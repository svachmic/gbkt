## What 11.2 Closed

SEED-014 visual gap at the codegen tier. The NEW-path tileset pipeline is now end-to-end:

1. **Authoring**: scene-level `tilesetPath` in DSL → ZoneIR (REQ-1 boundary preserved, IR unchanged).
2. **Metadata emission**: `GBDKPipelineV2.buildMetadataFile()` writes the `zoneTilesets` manifest to `game_metadata.json` (plan 01).
3. **PNG conversion**: `ConvertZoneTilesetsTask` Gradle task reads the manifest, invokes `png2asset` with locked flag set (`-map -spr8x8 -bpp 2 -noflip`, NO `-keep_palette_order` — plan 02 spike locked this), synthesizes `_zone_<sanitized>_tileset.h` with the `_zone_<id>_tileset` + `_zone_<id>_tileset_count` aliases (plan 03).
4. **Build wiring**: `GbktPlugin` registers `convertZoneTilesets`, with `dependsOn(generateC)` and `compileRom dependsOn convertZoneTilesets` (plan 04).
5. **Emission**: `SceneVisitor` zone-load block PREPENDS `set_bkg_data(0u, _zone_<id>_tileset_count, _zone_<id>_tileset)` BEFORE `_bkg_tiles_load_banked(...)` (plan 05).
6. **Include threading**: `GBDKPipelineV2` writes `#include "_zone_<sanitized>_tileset.h"` into the bank file's includes (plan 06).

The visible-frame gap between "tile-map indexes written" and "tile pixel bytes written" is now closed at the build tier — banks ROM (banks.gb, 64 KB) emits the ordered triple in `play_enter`:

```c
void play_enter(void) BANKED {
    set_bkg_data(0u, _zone_play_zone_tileset_count, _zone_play_zone_tileset);  // pixel bytes -> 0x8000-0x97FF
    _bkg_tiles_load_banked(2u, 0u, 0u, 20u, 18u, _zone_play_zone_tiles);        // tile-map indexes -> 0x9800-0x9BFF
    SHOW_BKG;
    SHOW_SPRITES;
}
```
