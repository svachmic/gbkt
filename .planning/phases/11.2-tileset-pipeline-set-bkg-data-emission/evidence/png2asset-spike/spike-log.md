# png2asset Spike — Flag + Shape Lock for Plan 03

Purpose: close RESEARCH §A3 Assumptions A1 (`-bpp 2` valid in `-map` mode) and A2 (`<stem>_tiles[N]` symbol shape). Plan 03 (`ConvertZoneTilesetsTask`) imports the locked flag set verbatim.

## Locked Flag Set

```
png2asset <input>.png -o <output>.c -map -spr8x8 -bpp 2 -noflip
```

**Deviation from RESEARCH §A3 proposal:** `-keep_palette_order` REMOVED. png2asset rejects it on RGB (non-indexed) PNGs with:
```
png2asset: Error: keep_palette_order only works with indexed png images (pngtype: 2, bits:8)
```
banks's `checker.png` is RGB (type 2, 8-bit) — and zone tilesets in general are unlikely to be authored as palette-indexed. The flag is preserved-for-sprites-only and dropped for zone backgrounds.

**RESEARCH-proposed flag set:** `<png> -o <outputC> -map -spr8x8 -bpp 2 -keep_palette_order -noflip` ← A1 also revealed `-keep_palette_order` incompatibility. Both assumptions now closed; flag set locked above.

## A1 Closure: `-bpp 2` valid in `-map` mode

**CONFIRMED.** Invocation 2 (`checker.png -o checker.c -map -spr8x8 -bpp 2 -noflip`) succeeded silently (exit 0, no stderr). `-bpp 2` is the documented GB tile encoding and works with `-map` mode without complaint.

## A2 Closure: `<stem>_tiles[N]` symbol shape

**CONFIRMED.** png2asset's `-map` mode emits the same `<stem>_tiles[N]` array shape as sprite mode, plus a header file with macros. Full inventory below.

### Emitted files (per png2asset invocation)

Two files: `<output>.c` AND `<output>.h`. Plan 03's synthesized `_zone_<id>_tileset.h` should `#include "checker.h"` (or whatever the per-zone stem-named header is) rather than redeclare the externs.

### `<stem>.c` shape (for `checker.c`)

```c
//AUTOGENERATED FILE FROM png2asset
// Conversion args: checker.png -o checker.c -map -spr8x8 -bpp 2 -noflip

#include <stdint.h>
#include <gbdk/platform.h>
#include <gbdk/metasprites.h>

BANKREF(checker)

const palette_color_t checker_palettes[4] = { ... };

const uint8_t checker_tiles[32] = { ... };   // 2 unique 8x8 tiles × 16 bytes

const unsigned char checker_map[4] = { ... }; // 2x2 tile indices
```

### `<stem>.h` shape (for `checker.h`)

```c
#define checker_TILE_ORIGIN       0
#define checker_TILE_W            8
#define checker_TILE_H            8
#define checker_WIDTH             16
#define checker_HEIGHT            16
#define checker_TILE_COUNT        2    // <-- count of unique tiles after dedup
#define checker_PALETTE_COUNT     1
#define checker_COLORS_PER_PALETTE 4
#define checker_TOTAL_COLORS      4
#define checker_MAP_ATTRIBUTES    0
extern const unsigned char checker_map[4];
#define checker_map_attributes    checker_map

BANKREF_EXTERN(checker)

extern const palette_color_t checker_palettes[4];
extern const uint8_t checker_tiles[32];
```

### Critical: tile dedup

png2asset **deduplicates identical 8×8 tiles** in `-map` mode. A 16×16 checker has 4 visual tiles but only 2 are unique → `checker_tiles[32]` (2 unique × 16 bytes), not `checker_tiles[64]`. A 256×256 all-gray PNG dedupes to 1 tile → `oversized_tiles[16]`. Plan 05's `set_bkg_data(0, <count>, <data>)` MUST use the dedup count (the macro `<stem>_TILE_COUNT`), not the visual tile count.

## Plan 03 Synthesized Header Shape

Per the locked flag set + emitted shape, Plan 03's `_zone_<sanitized>_tileset.h` should be:

```c
// AUTOGENERATED by ConvertZoneTilesetsTask — do not edit
#include "checker.h"   // or "<sanitized>.h" — whatever stem the task uses
#define _zone_<sanitized>_tileset       checker_tiles
#define _zone_<sanitized>_tileset_count checker_TILE_COUNT
```

This lets SceneVisitor (Plan 05) emit `set_bkg_data(0, _zone_<id>_tileset_count, _zone_<id>_tileset)` without knowing the PNG stem name.

## Failure Mode Characterization

| Scenario | stderr | exit | Plan 03 implication |
|----------|--------|------|---------------------|
| Missing PNG | `decoder error empty input buffer given to decoder. Maybe caused by non-existing file?` | **0** (success!) | **Exit code is NOT reliable.** Plan 03 MUST check that the output `.c` file was created AND non-empty. |
| Malformed PNG (4-byte garbage) | `decoder error PNG file is smaller than a PNG header` | **0** | Same as above — D-C4's Kotlin-side IHDR parse is the primary guard; png2asset's secondary guard is decoder error to stderr without nonzero exit. |
| Oversized PNG (256×256 RGB all-gray) | none — succeeds | 0 | png2asset has NO built-in size cap. Plan 03's IHDR pre-check is the only enforcement. After dedup, an all-uniform PNG of any size collapses to 1 tile; only worst-case (fully unique) tilesets hit the cap. |
| `-keep_palette_order` on RGB PNG | `png2asset: Error: keep_palette_order only works with indexed png images (pngtype: 2, bits:8)` | 0 | Already removed from locked flag set above. |

**Key invariant for Plan 03 error handling:** Treat any non-empty stderr OR missing output file as failure. Do NOT trust png2asset's exit code.
