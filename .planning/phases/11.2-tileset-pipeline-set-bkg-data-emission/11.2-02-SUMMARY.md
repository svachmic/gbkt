# Plan 11.2-02 Summary — png2asset Spike

## What was done

Manual spike against `gbkt-examples/banks/res/tiles/checker.png` to close RESEARCH §A3 assumptions A1 (`-bpp 2` valid in `-map` mode) and A2 (`<stem>_tiles[N]` symbol shape). Captured help text, success-path output, and three failure-mode invocations as evidence. Locked the png2asset flag set Plan 03 will consume verbatim.

## Key findings

- **A1: `-bpp 2` valid in `-map` mode** → CONFIRMED. Succeeds silently (exit 0, no stderr).
- **A2: emitted symbol shape** → `const uint8_t <stem>_tiles[N]` AND a `<stem>.h` header with macros (`<stem>_TILE_COUNT`, `<stem>_TILE_W`, etc.) — exact shape captured in `evidence/png2asset-spike/checker.c` + `checker.h`.
- **Deviation from RESEARCH proposal:** `-keep_palette_order` REMOVED. png2asset rejects it on RGB (non-indexed) PNGs. banks's `checker.png` is RGB type-2. The spike caught the assumption before plan 03 could ship broken.
- **Locked flag set for plan 03:** `png2asset <png> -o <out>.c -map -spr8x8 -bpp 2 -noflip`
- **Tile dedup caveat:** png2asset deduplicates identical 8×8 tiles. checker (16×16, 4 tiles visually) → 2 unique → `checker_tiles[32]`. Plan 05's `set_bkg_data(0, <count>, <data>)` MUST use the `<stem>_TILE_COUNT` macro, not visual tile count.
- **Error handling caveat:** png2asset returns exit 0 even on decoder errors. Plan 03 MUST check for non-empty stderr OR missing output file — D-C4's Kotlin-side IHDR parse is the primary guard.
