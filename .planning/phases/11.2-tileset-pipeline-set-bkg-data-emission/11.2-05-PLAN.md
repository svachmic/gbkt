<objective>
Extend `SceneVisitor.kt`'s existing zone-load block to PREPEND a `set_bkg_data(0, _zone_<id>_tileset_count, _zone_<id>_tileset)` call BEFORE the existing `_bkg_tiles_load_banked(...)` + `SHOW_BKG;` statements, ONLY when the zone has a non-null `tilesetPath`. This is the heart of REQ-3: pixel bytes reach VRAM (set_bkg_data writes the 0x8000-0x97FF tile-data area) BEFORE the tile-index map (_bkg_tiles_load_banked writes the 0x9800-0x9BFF tile-map area) references them. Without this ordering, the visible frame between writes shows zero-initialized VRAM — the SEED-014 visual gap.

Purpose: D-A3 symbolic count (no literal hardcoded N — the header `#define` couples size to the Gradle task output). D-claude-4 ordering (data before references-data). D-claude-2 sanitizer reuse inline. D-A1 no helper extraction. Tile-path filter mirrors Pitfall 6 — procedural zones (sport-racing's `_racing_<id>_tileset`) MUST NOT emit `set_bkg_data` referencing a Gradle-task-produced symbol; the LEGACY path emits its own `set_bkg_data` separately in SportVisitor.

Output: Banks `:generateC` produces a `bank1.c` whose `play_enter` body starts with the three-line ordered sequence. INV-7 (plan 07) will lock the shape; for now this plan verifies via grep against the regenerated C.
</objective>
