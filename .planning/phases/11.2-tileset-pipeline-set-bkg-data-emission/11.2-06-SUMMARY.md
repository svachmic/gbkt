# Phase 11.2 Plan 06: Bank File #include Directive Threading Summary

`GBDKPipelineV2.buildSceneFile()` now computes a `zoneTilesetIncludes: List<String>` after the existing `metaspriteInclude` block and appends it to the `CFile` includes argument, so `bank1.c` carries `#include "_zone_<sanitized>_tileset.h"` for every scene-bound zone with a non-null `tilesetPath` — closing the linker chain between plan 05's `set_bkg_data` CCall and plan 03/04's synthesized header.

## What Shipped

A 13-line additive block inside `buildSceneFile()` (lines 1473-1488 in the post-edit file), positioned immediately after the existing `metaspriteInclude = if (needsMetasprites) listOf("<gbdk/metasprites.h>") else emptyList()` declaration and BEFORE the `return CFile(...)` statement. The block:

```
val zoneTilesetIncludes =
    gameIR.scenes
        .flatMap { it.zoneRefs }
        .mapNotNull { zoneId -> gameIR.zones.firstOrNull { it.id == zoneId } }
        .filter { it.tilesetPath != null }
        .map { zone ->
            val sanitized = zone.id.replace('-', '_').replace(' ', '_')
            "\"_zone_${sanitized}_tileset.h\""
        }
        .distinct()
```

is preceded by a 6-line provenance comment naming `Phase 11.2 (D-B3, D-B4)` and cross-referencing plan 05's SceneVisitor call + plan 03's Gradle-task-synthesized header. The `CFile(...)` `includes = ...` argument is updated to append `+ zoneTilesetIncludes` after the existing `+ metaspriteInclude` term — single-token modification, no other CFile argument touched.

A new `ZoneTilesetIncludeTest` (248 lines, 5 `@Test` methods) locks the contract end-to-end against `GBDKPipelineV2().generate(game)` output:

1. **Positive** — `play_zone` (tilesetPath=tiles/checker.png) bound via `SceneIR.zoneRefs` → bank1.c includes `"_zone_play_zone_tileset.h"`.
2. **Sanitizer** — `boss-room area` zone id → bank1.c includes `"_zone_boss_room_area_tileset.h"` (both `-` and ` ` replaced with `_`).
3. **Distinct** — two scenes bind the same `shared_zone` → exactly ONE `#include "_zone_shared_zone_tileset.h"` line.
4. **Negative (procedural)** — `procedural_zone` (tilesetPath=null) bound to a scene → no include emitted.
5. **Negative (orphan)** — `orphan_zone` (tilesetPath set) exists in gameIR.zones but NO scene binds it via zoneRefs → no include emitted (locks `SceneIR.zoneRefs` as the include-driver, not `gameIR.zones` membership).

All five tests follow `Seed009BankIncludeTest`'s Pitfall 2 mitigation: 2-scene `build2SceneGame()` helper escapes `BankingAnalysisPass`'s single-scene HOME fast-path, with `assertNotNull(bank1)` firing BEFORE any include check so a fast-path collapse fails loudly against `main.c` rather than silently passing.
