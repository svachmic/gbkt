# Phase 11.2 Plan 01: zoneTilesets Manifest Emission Summary

One-liner: GBDKPipelineV2.buildMetadataFile() now emits a `zoneTilesets` JSON manifest in `game_metadata.json`, listing every ZoneIR with a non-null tilesetPath under `{id, path, sanitizedSymbol}` so ConvertZoneTilesetsTask (plan 03) can drive the PNG→2bpp pipeline from a single source of truth.

## What Shipped

A 17-line additive block inside `buildMetadataFile()` (inserted between the existing `tileDecoders` put and the closing `return json.toString(2)`) iterates `gameIR.zones`, skips any zone whose `tilesetPath` is null via `?: continue`, computes the sanitized symbol inline (`zone.id.replace('-', '_').replace(' ', '_')`), and appends a 3-key `JSONObject` (`id`, `path`, `sanitizedSymbol`) to a `JSONArray` that's finally `put` into the top-level metadata JSON under `"zoneTilesets"`. A provenance comment (`Phase 11.2 (D-A4): zone tilesets manifest consumed by ConvertZoneTilesetsTask. Filtered to NEW-path consumers (zone.tilesetPath != null); procedurally-authored sport-racing zones stay on LEGACY path.`) sits above the block.

A new `ZoneTilesetsMetadataTest` in the backend-gbdk test sourceset locks the shape:
- **Positive** `zoneTilesets manifest contains banks play_zone entry` — banks-shaped fixture (`id=play_zone`, `tilesetPath=tiles/checker.png`, `mapWidth=20`, `mapHeight=18`) emits exactly one entry whose three keys carry `play_zone`, `tiles/checker.png`, `play_zone` respectively.
- **Negative** `zoneTilesets omits zones without tilesetPath (procedural zones)` — a `tilesetPath=null` zone is filtered out, asserting `zoneTilesets.length() == 0`.
