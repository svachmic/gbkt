# Phase 11.2: tileset-pipeline-set-bkg-data-emission — Specification

**Created:** 2026-05-20
**Ambiguity score:** 0.16 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

Closing the SEED-014 visual gap surfaced by Phase 11.1 plan 08: when a scene binds a zone whose DSL declares `tileset(<png>)`, the generated bank file must emit a `set_bkg_data(0, N, _zone_<id>_tileset)` call alongside the existing `_bkg_tiles_load_banked(...)` + `SHOW_BKG;`, with the tile-pixel byte array produced from the PNG via a new `ConvertZoneTilesetsTask` (mirrors the existing `ConvertSpritesTask` png2asset pipeline). After this phase, banks renders the checker tilemap with real pixels rather than the all-zero VRAM default.

## Background

Phase 11.1 closed the codegen wiring for `_bkg_tiles_load_banked` (tile MAP indices → background) when a scene binds a zone, but never wired the corresponding `set_bkg_data` call (tile PIXEL graphics → VRAM). Concrete state at HEAD (post-11.1 plans 01–07):

- `SceneVisitor.kt:114-161` — emits `_bkg_tiles_load_banked(bank, 0, 0, mapW, mapH, _zone_<id>_tiles)` + `SHOW_BKG;` for `scene.zoneRefs.isNotEmpty()` (added in 11.1-05). Does NOT emit `set_bkg_data`.
- `GBDKPipelineV2.kt:720-746` (`buildZoneData()`) — emits `_zone_<id>_tiles[N]` (map indices) with a 1-byte placeholder `"0"` when `zone.tileData.isEmpty()`. No `_zone_<id>_tileset` (pixel bytes) array is authored anywhere.
- `WorldIR.kt:33-56` (`ZoneIR`) — has `tilesetPath: String?` and `tileData: List<Int>` (map indices). No field carries tile pixel bytes — they must come from outside the IR.
- `ConvertSpritesTask.kt:45` — existing Gradle task that invokes GBDK's `png2asset` against sprite PNGs and emits C headers. No equivalent task exists for zone tilesets.
- `SportVisitor.kt:498-525` — racing genre uses hand-coded inline 2bpp byte literals via `buildBuiltinTrackTilesetVarDecl()`. Two incompatible patterns currently coexist in the codebase.
- `BanksEmissionTest.kt` — INV-1..INV-6 sentinels lock the existing codegen surface; no INV locks `set_bkg_data` emission.
- `BanksUatTest.kt` (anchor 1 + anchor 2) — re-shoot in 11.1-08 produced PASSED at the JVM tier but PNGs stayed at 413 bytes (blank green screen) because VRAM tile slots were never populated.

The defect class is the exact one CLAUDE.md §"Verification Methodology — Visual Evidence Rule" was codified to prevent: JVM-tier codegen GREEN ≠ pixels on screen. This phase exists to close that gap for the banks/checker.png case before resuming `/gsd-execute-phase 11.1`.

## Requirements

1. **ZoneIR sources tile pixels from `tilesetPath`** — the IR boundary does not carry the byte array.
   - Current: `ZoneIR` has `tilesetPath: String?` and `tileData: List<Int>` (map indices). No pixel-byte field exists; no codegen layer consumes `tilesetPath` for pixel data.
   - Target: `tilesetPath` becomes the single source of truth for the pixel bytes. A new build-time step converts the referenced PNG into a C header that declares `extern const UINT8 _zone_<sanitized-id>_tileset[N]`. ZoneIR itself remains unchanged in pixel-byte shape (no new IR field).
   - Acceptance: Building banks emits a `_zone_play_zone_tileset.h` header alongside the generated bank files; `_zone_play_zone_tileset[N]` is declared with N matching the checker.png tile count × 16 bytes (e.g. 32 bytes for 2 tiles); ZoneIR has no `tilesetData`-shaped field in its source tree (`git diff WorldIR.kt` shows no new pixel-byte field).

2. **`ConvertZoneTilesetsTask` Gradle task** — invokes `png2asset` for each zone tileset PNG.
   - Current: `ConvertSpritesTask.kt:45` exists for sprite PNGs; no zone equivalent. Zone tileset PNGs are referenced via `tileset("checker.png")` in DSL but never converted.
   - Target: A new Gradle task `ConvertZoneTilesetsTask` discovers zone tileset PNGs from the generated game (via `ZoneIR.tilesetPath`), invokes the same `png2asset` binary that `ConvertSpritesTask` uses (same GBDK_HOME detection + error enhancement), and writes one `.c`/`.h` pair per zone tileset into `build/gbkt/generated/`. Task is wired into the build graph so `:gbkt-examples:banks:buildRom` produces the headers before `lcc` is invoked.
   - Acceptance: `./gradlew :gbkt-examples:banks:buildRom` from a clean state produces `build/gbkt/generated/_zone_play_zone_tileset.h` with `extern const UINT8 _zone_play_zone_tileset[];` (or sized equivalent) AND a matching `.c` file with the actual byte values; running on a missing PNG path produces a clear error message (NOT a silent skip).

3. **`SceneVisitor` emits `set_bkg_data` for zone-binding scenes** — paired with the existing `_bkg_tiles_load_banked` call.
   - Current: `SceneVisitor.kt:114-161` emits `_bkg_tiles_load_banked(...)` + `SHOW_BKG;` only.
   - Target: For each scene where `scene.zoneRefs.isNotEmpty()`, the visitor prepends `set_bkg_data(0, <numTiles>, _zone_<sanitized-id>_tileset);` BEFORE `_bkg_tiles_load_banked(...)`. `<numTiles>` is sourced from the zone's tileset metadata (header-declared size) rather than the map data. An `#include` directive for the generated `_zone_<id>_tileset.h` is emitted into the same generated bank `.c` file.
   - Acceptance: `cat gbkt-examples/banks/build/gbkt/generated/bank1.c | grep -A1 'play_enter'` shows `set_bkg_data(0, <N>, _zone_play_zone_tileset);` immediately before `_bkg_tiles_load_banked(2, 0, 0, 20, 18, _zone_play_zone_tiles);`. Generated `main.c` (or bank1.c, whichever houses the play scene) contains `#include "_zone_play_zone_tileset.h"`.

4. **INV-7 codegen-shape sentinel** — locks the `set_bkg_data` contract before any future change can silently regress it.
   - Current: `BanksEmissionTest.kt` has INV-1..INV-6. No invariant locks the `set_bkg_data` emission shape or its ordering relative to `_bkg_tiles_load_banked`.
   - Target: A new `@Test` (INV-7) in `BanksEmissionTest` asserts (a) the generated bank file contains exactly one `set_bkg_data(0, <N>, _zone_play_zone_tileset);` line within the `play_enter` body, AND (b) that line precedes any `_bkg_tiles_load_banked(...)` call in the same function, AND (c) an `#include "_zone_play_zone_tileset.h"` line exists in the same translation unit.
   - Acceptance: `./gradlew :gbkt-examples:banks:test --tests "*BanksEmissionTest.INV-7*"` passes against the post-Phase-11.2 codegen; reverting the SceneVisitor emission causes the test to fail (RED-then-GREEN bisect proves the sentinel).

5. **Anchor 1 + Anchor 2 PNGs visually show real pixels** — the visual-evidence binding criterion.
   - Current: `.planning/phases/11-port-banks-gbdk-example-to-gbkt/evidence/uat-screenshots/anchor1-play-scene.png` and `anchor2-tilemap.png` are 413 bytes each (blank DMG green; one pixel-color uniform screen).
   - Target: Re-running Phase 11.1 plan 11.1-08 Task 1 (after Phase 11.2 ships) overwrites both PNGs with files > 5 KB whose pixel content visually shows real tile graphics (anchor 1: play scene with sprite + checker background; anchor 2: checker tilemap pattern with alternating tiles). Phase 11 .md files remain untouched (CONTEXT D-10 boundary preserved).
   - Acceptance: After resuming `/gsd-execute-phase 11.1`, `stat -f%z anchor1-play-scene.png` returns > 5000 AND `stat -f%z anchor2-tilemap.png` returns > 5000; the user (or any human reviewer) opens both PNGs and confirms non-blank tile graphics; `git diff --stat .planning/phases/11-port-banks-gbdk-example-to-gbkt/` after the 11.1-08 reshoot lists ONLY the two `.png` files modified (no `.md` files touched).

## Boundaries

**In scope:**

- New Gradle task `ConvertZoneTilesetsTask` (mirrors `ConvertSpritesTask` shape, uses the same GBDK_HOME-detected `png2asset` binary).
- `SceneVisitor` emission of `set_bkg_data(0, N, _zone_<id>_tileset);` + `#include "_zone_<id>_tileset.h"` for any scene where `scene.zoneRefs.isNotEmpty()`.
- New `INV-7` codegen-shape sentinel in `BanksEmissionTest`.
- Visual closure of anchor 1 + anchor 2 PNGs via re-running `BanksUatTest` on the post-11.2 ROM.
- Cross-genre regression sweep at phase close: `./gradlew :gbkt-examples:banks:buildRom :gbkt-examples:dungeon:buildRom :gbkt-examples:explorer:buildRom :gbkt-examples:racer:buildRom --parallel` must all stay GREEN.

**Out of scope:**

- **Retrofitting `SportVisitor.buildBuiltinTrackTilesetVarDecl()`** — sport genre keeps its hand-coded inline 2bpp pattern for racing tracks. A future phase can unify the two paths; not blocking 11.2 (deferred).
- **Runtime tileset switching mid-scene** — calling `set_bkg_data` multiple times within a single `scene_enter`/`scene_frame` is NOT part of 11.2. One tileset per scene_enter only. (Deferred to a future phase if/when a game needs it.)
- **Compressed or banked tile data for tilesets exceeding ~192 tiles** — phase 11.2 targets small-to-medium tilesets that fit in a single VRAM bank. checker.png is 2 tiles. Larger tilesets requiring multi-bank tile data or compression are deferred.
- **GBC-mode per-tile palette attributes** — VRAM bank 1 attribute writes (`VBK_REG=1` + a second `set_bkg_tiles` for the attribute map) are NOT in 11.2. The explicit-slot palette DSL is Phase 13 territory.
- **DSL changes to `tileset(...)`, `zone(...)`, or `size(...)`** — the DSL surface that triggers the new emission already exists (added in 11.1-04 and 11.1-06). No `gbkt-lang` edits needed.
- **Cross-phase Phase 11 .md file writes** — per CONTEXT D-10 carried forward from 11.1, ONLY the two PNG files in Phase 11's `evidence/uat-screenshots/` directory may be modified. NO Phase 11 PLAN.md / CONTEXT.md / VERIFICATION.md edits.

## Constraints

- **Toolchain**: Must use the existing GBDK `png2asset` binary discovered via the same path-resolution logic `ConvertSpritesTask` uses (`gbkt { gbdkHome.set(...) }` → `GBDK_HOME` env → common install paths). No new external tool dependency.
- **Backward compatibility**: Any example whose scenes declare `zoneRefs` (today: only banks, via Phase 11.1) must still build and not regress. `:gbkt-examples:banks:buildRom` must produce a working `.gb` file after Phase 11.2 ships.
- **Compiler discipline**: Generated `set_bkg_data` call + `#include` header + `extern const UINT8 _zone_<id>_tileset[N];` declaration must compile clean under GBDK `lcc` with the standard `-Wa-l -Wl-m -Wl-j` flags. No implicit-int warnings, no const-mismatch warnings, no missing-declaration warnings.
- **ROM size cap**: `banks.gb` must remain within the existing 2× reference size cap measured by the `gbkt-build.properties` size invariant. Adding `set_bkg_data` + the checker tileset bytes (32 B for 2 tiles) will grow the ROM modestly — the existing cap must still hold.
