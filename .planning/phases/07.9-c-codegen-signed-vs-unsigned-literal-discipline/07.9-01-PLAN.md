<decision name="Architecture">
**Option C selected — `CIntLiteral(value: Int) : CExpr` as new sealed subtype, `CLiteral(value: Int)` unchanged.**

**Citation:** RESEARCH.md §4.6 Comparison Table row "Failure mode in NEW code": Option C is the **only option with explicit (loud-at-review) failure mode for future code paths** — Options B and E are silent, Option D is uniform but produces a wide regenerated-C diff (forces D-09 #3 reinterpretation per RESEARCH.md §6.3 / Pitfall 2), Option F is opt-in (default unchanged → same bug for un-tagged sites).

**Why specifically the additive split (preserve CLiteral default emission), not the flag variant or signed-default rename:**
- RESEARCH.md §4.2 documents two C variants: (i) split node, (ii) flag on existing CLiteral. The split node makes the difference loud at the visitor call site (`CIntLiteral(0)` vs `CLiteral(0)`) and forces every CEmitter `when` arm to remain exhaustive at compile time — the sealed-interface dispatch pattern is the project's V2 safety net per PATTERNS.md § Shared Patterns / Sealed-interface dispatch over CExpr.
- Default flavour bias: keep existing `CLiteral` emission semantics (signed-non-negative → `Nu`) so the ~120 currently-unsigned-typed sites are untouched. Only the 17–25 in-scope signed-comparison sites (D-04 bucket a) migrate to `CIntLiteral`. **This makes the Tier-3 surgical diff (D-09 #3) literally satisfiable without reinterpretation** — only signed-context call sites change in the regenerated C.
- Probes C and D confirm asm-byte-identical output for unsigned-typed targets — so keeping the default emission also incurs zero binary cost.

**Why Option C beats Option D for THIS phase:**
- D-09 #3 reads literally as "regenerated-C diff stays surgical — only signed-comparison call sites change". Option C produces this exact surgical diff natively. Option D produces a ~5000–10000 line text diff (every `Nu` → `N`) and forces the planner to reinterpret the criterion as "no asm-level change" (RESEARCH.md § Pitfall 2 / probes C & D). The user's locked CONTEXT.md decisions do not authorise such reinterpretation; Option C makes it unnecessary.

**Why Option C beats Options B/E for future contributors:**
- PATTERNS.md § Architecture-Dependency Summary table row "Robust to future contributors": Option C is YES (loud at review), Options B/E are NO (silent fallback). The user-memory feedback `feedback_route_to_proper_phase_when_blast_radius_is_wide.md` mandates structural fixes over inline conventions — sealed-interface exhaustiveness is the structural enforcement; visitor-site casts (E) and type-aware emitters (B) are conventions.

**Why Option C beats Option F:**
- Option F's nullable `CVar.type` defaults to null → un-tagged sites inherit the bug. Same risk surface as today, just with opt-in. Option C's `CIntLiteral` is positively-typed at construction.

**Trade-off accepted:** Wider call-site migration than Options B/D (17–25 sites per RESEARCH.md §4.2 + Section 5). That migration burden is the cost of robustness. Migration is bounded by D-03 scope (comparisons only) — non-comparison sites (D-04 bucket b) are deferred. The migration is the subject of Plan 02.
</decision>
