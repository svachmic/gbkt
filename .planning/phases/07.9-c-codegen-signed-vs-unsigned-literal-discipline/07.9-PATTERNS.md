## Pattern Assignments

### `gbkt-backend-gbdk/.../codegen/emit/CEmitter.kt` (codegen/pretty-printer, AST→text)

**Analog:** same file — Plan 07.4-34 landed `emitCastInner` at line 451 as the canonical
precedence-aware emission helper. The 07.9 fix lives in `emitExpr` → `is CLiteral` at
line 421 and must **compose with** (not duplicate or replace) the existing helper.

**Bug-site pattern at HEAD** (lines 419–432, must be preserved as a precedence-aware
exhaustive `when` over `CExpr`):
```kotlin
private fun emitExpr(expr: CExpr): String =
    when (expr) {
        is CLiteral -> if (expr.value >= 0) "${expr.value}u" else "${expr.value}"   // <-- BUG SITE (line 421)
        is CStringLiteral -> "\"${expr.value}\""
        is CVar -> expr.name
        is CBinaryExpr -> "${emitExpr(expr.left)} ${expr.op} ${emitExpr(expr.right)}"
        is CUnaryExpr -> "${expr.op}${emitExpr(expr.operand)}"
        is CCall -> "${expr.function}(${expr.args.joinToString(", ") { emitExpr(it) }})"
        is CTernary ->
            "(${emitExpr(expr.condition)}) ? ${emitExpr(expr.thenExpr)} : ${emitExpr(expr.elseExpr)}"
        is CArrayAccess -> "${emitExpr(expr.array)}[${emitExpr(expr.index)}]"
        is CCast -> "(${emitType(expr.type)})${emitCastInner(expr.expr)}"
        is CRawExpr -> expr.code
    }
```

**Layer-1 helper pattern to mirror or extend** (lines 433–455 — Plan 07.4-34 GREEN):
```kotlin
/**
 * Emit the inner expression of a [CCast], wrapping it in parentheses when its top-level
 * operator has lower precedence than the C cast operator. Without these parens C parses
 * `(UINT8)cond ? a : b` as `((UINT8)cond) ? a : b` — the cast binds only to the condition,
 * which broke GAP-CAMERA-NO-FOLLOW (Plan 07.4-32 → 07.4-34).
 * ...
 */
private fun emitCastInner(expr: CExpr): String =
    when (expr) {
        is CTernary, is CBinaryExpr, is CUnaryExpr -> "(${emitExpr(expr)})"
        else -> emitExpr(expr)
    }
```

**07.9 fix shape per architecture:**
- **Option B (type-aware):** add a `TypeContext` parameter threaded through `emitExpr` recursion. New private helper resolves `CVar.name` → `CType` via a symbol table populated at `emitFunction` entry. `is CLiteral` branch consults context for signed/unsigned bias.
- **Option D (drop default `u`):** change line 421 to a one-liner — `is CLiteral -> "${expr.value}"`. Touches only this line. **Tier-3 surgical diff is wide** (every `0u`/`1u`/`Nu` strips); per RESEARCH.md §6.3 the criterion needs explicit reinterpretation as "no asm-level change outside signed-comparison sites" (probes C/D justify).
- **Option F (`CVar.type` opt-in):** new private helper `emitCompareLiteral(literal, otherSide)` called from the `is CBinaryExpr` branch when `op in comparisonOps` and `otherSide is CVar` with `type` ∈ {CI8, CI16}. Mirrors the `emitCastInner` pattern structurally.
- **Option C (CIntLiteral split):** add a new `is CIntLiteral -> "${expr.value}"` arm to `emitExpr`. Existing `is CLiteral` arm untouched.
- **Option E (visitor-site cast):** **no change to CEmitter** — `emitCastInner` already handles the precedence correctly for `CCast(CI16, CLiteral(0))`.

**Invariant across all five options:** preserve `emitCastInner` semantics exactly as Plan
07.4-34 shipped. Tier-3 acceptance D-09 #3 fails if the camera-bounds clamp test
(`CameraBoundsClampPrecedenceTest`) regresses.

### `gbkt-backend-gbdk/.../codegen/ast/CExpr.kt` (codegen/AST data class)

**Analog:** same file. The existing shape (from RESEARCH.md and verified):
```kotlin

```

**07.9 fix shape per architecture:**
- **Option C — split node:**
  ```kotlin
  data class CLiteral(val value: Int) : CExpr      // signed-safe (no `u` suffix)
  data class CUIntLiteral(val value: Int) : CExpr  // explicit `u` suffix for the rare case
  ```
  OR (flag variant):
  ```kotlin
  data class CLiteral(val value: Int, val signed: Boolean = true) : CExpr
  ```
- **Option F — nullable `CVar.type`:**
  ```kotlin
  data class CVar(val name: String, val type: CType? = null) : CExpr
  ```
  Backward-compatible (default `null` keeps every existing visitor untouched).
- **Options B / D / E:** **no edits to CExpr.kt.**

**Invariant:** Adding new sealed subtypes forces every `CEmitter.emitExpr` `when` arm to
become exhaustive at compile time. This is the V2 architecture's primary safety feature
(see project CLAUDE.md "V2 Modular Architecture" → exhaustiveness via visitor / sealed).

### Sealed-interface dispatch over `CExpr`

**Source:** `gbkt-backend-gbdk/.../codegen/emit/CEmitter.kt:419-432` and `codegen/ast/CExpr.kt:17,24`
**Applies to:** Options C, F (any architecture that adds a new `CExpr` subtype or annotation)

**Pattern:** `sealed interface CExpr` + exhaustive `when` in `CEmitter.emitExpr` is the project's V2-architecture safety net. Any new sealed subtype (Option C's `CIntLiteral`, or a `signed: Boolean` flag) forces a compile-time error in `emitExpr` until the new arm is added. The compiler enforces exhaustiveness — bypass at your peril.

```kotlin
    when (expr) {
        is CLiteral -> …
        // every subtype enumerated
    }
```

### Single-place text emission

**Source:** project policy — `gbkt-backend-gbdk/CLAUDE.md` "Key Design Decisions"
> The `CEmitter` is the single point of text serialization, which enables source map collection.

**Applies to:** All architecture options.

**Pattern:** No new code path may concatenate C strings outside `CEmitter`. Options B / D / F that change emission must do so inside `CEmitter.emit*`; Option C adds a new AST node and lets the existing `CEmitter` dispatch on it; Option E uses `CCast` (already an AST node) and `emitCastInner` (already an emitter helper) — neither adds a new emission site. Any architecture that bypasses `CEmitter` regresses the source-map collector and breaks the contract.

### Multi-snapshot trajectory assertion (D-N-12 codified)

**Source:** `Round8CameraMonotonicityProbe.kt:18-62` (docstring) and lines 134–147
**Applies to:** Platformer probe (assertion-b friction monotonicity) and any future probe whose verdict depends on variable trajectory rather than single-point threshold.

**Pattern:** Capture variable at THREE (or more) snapshot points across a time window. Assert strict inequality between consecutive snapshots (e.g. `vx_10 > vx_5 > vx_0` for monotonic increase, `|vx_10| < |vx_5| < |vx_0|` for monotonic magnitude decrease). NEVER assert `var > threshold` against a single snapshot — round-7 false-positive of `_camera_y > 0` is the cautionary tale.
