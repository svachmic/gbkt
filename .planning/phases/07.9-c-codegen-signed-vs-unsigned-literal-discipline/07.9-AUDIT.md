## Bucket (b) Follow-up Candidates (DEFERRED — not fixed in 07.9)

These sites involve `CLiteral` in a non-comparison signed arithmetic context. They are catalogued for a future phase (Phase 07.6 RPG Codegen Audit or a dedicated follow-up sprint) per CONTEXT.md `<deferred>` note.

1. **`GBDKSystemVisitor.kt` — `rawX` initializer (approx line 151)**
   - Site: `CBinaryExpr(CCast(CI16, CVar("_${actorId}_x")), "-", CLiteral(80))`
   - Emitted C: `(INT16)_player_x - 80u`
   - Issue: Arithmetic operand `80u` in a `(INT16)x - N` subtraction. Under C's usual-arithmetic-conversions, both sides promote to `unsigned int`. For `_player_x` ≤ 160, the result stays in range (160 - 80 = 80, no wrap). But if an actor is at x=0, `(INT16)0 - 80u` = `0xFFB0` (unsigned), which then feeds into `INT16 rawX = (uint16_t)-80` = correct (since the result is stored in a signed type). **Currently works by accident** — the UINT8 range of actor positions bounds the subtraction.
   - Recommendation: Replace `CLiteral(80)` with `CIntLiteral(80)` in a follow-up to make intent explicit and eliminate SDCC's potential unsigned-promotion path.

2. **`GBDKSystemVisitor.kt` — `rawY` initializer (approx line 159)**
   - Site: `CBinaryExpr(CCast(CI16, CVar("_${actorId}_y")), "-", CLiteral(72))`
   - Same rationale as #1 for Y axis.
   - Recommendation: Same as #1.

3. **`ActorVisitor.kt` — smooth-movement velocity clamp upper bound (approx line 1119)**
   - Site: `CBinaryExpr(vxVar, ">", CVar(speedDef))` where `speedDef` is a CVar referencing a UINT8 config value
   - Note: This uses `CVar` RHS (not `CLiteral`), but the conceptual category is the same: signed `vx` compared against an unsigned-derived speed macro. This is a separate bug class to the CLiteral-specific fix. Tracked here for completeness.
   - Not a `CLiteral` site — out of scope for this audit. Listed for follow-up awareness.

4. **`ActorVisitor.kt` — smooth-movement velocity clamp negation (approx line 1124)**
   - Site: `CUnaryExpr("-", CVar(speedDef))` used as lower-bound in signed comparison
   - Note: Same as #3 — uses `CVar` not `CLiteral`. Tracked for follow-up.

5. **`RpgVisitor.kt` — `_char_*_exp` (CU16) in EXP delta arithmetic (various lines)**
   - The `_char_*_exp` variable is `CU16` (line 169: `CLiteral(0)` initializer with `CU16` type). EXP deltas and level-up thresholds use UINT16. No signed-context comparisons found in the audit. No bucket (b) sites in RpgVisitor.

**Summary:** 2 confirmed bucket-(b) sites in `GBDKSystemVisitor.kt` (rawX/rawY initializers). The `CUnaryExpr` negation sites in `ActorVisitor.kt` are `CVar`-based, not `CLiteral`-based — they are a related but separate concern.
