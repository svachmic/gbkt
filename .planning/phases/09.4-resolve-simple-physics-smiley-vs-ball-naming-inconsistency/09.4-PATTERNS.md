**Analog:** Self — the live file at `gbkt-examples/simple-physics/src/main/kotlin/io/github/gbkt/examples/simple_physics/SimplePhysics.kt`

**What to copy-adapt:** The property-delegate pattern drives the entire cross-tier rename automatically. The Kotlin property name IS the actor-ID; no magic string is involved (Project Rule #1 / `feedback_no_magic_strings`).

**Core rename sites** (from RESEARCH.md Q1, all confirmed):

```

L61  comment: `smiley sprite` → `ball sprite`
L64  DSL:     `val smiley by actor {` → `val ball by actor {`
L66  DSL:     `sprite(asset("sprites/smiley.png"))` → `sprite(asset("sprites/ball.png"))`
L124 DSL:     `smiley.moveTo(posX shr 4, posY shr 4)` → `ball.moveTo(posX shr 4, posY shr 4)`
```

**Current L64 pattern** (the load-bearing line — rename this and everything downstream propagates):

```kotlin
val smiley by actor {
    position(64, 64)
    sprite(asset("sprites/smiley.png")) {
        size(8, 8)
        hitbox(0, 0, 8, 8)
    }
}
```

Becomes:

```kotlin
val ball by actor {
    position(64, 64)
    sprite(asset("sprites/ball.png")) {
        size(8, 8)
        hitbox(0, 0, 8, 8)
    }
}
```

**Propagation chain (automatic — no manual edits needed):**
- IR actor-ID: `ActorDelegate.provideDelegate` derives `"ball"` from the property name
- Generated C: `GBDKPipelineV2` emits `_ball_x` / `_ball_y` / `move_sprite(0u, _ball_x + 8u, _ball_y + 16u)` from the IR actor-ID
- Sprite files: `ConvertSpritesTask` derives `ball.c`/`ball.h` from the `#include "sprites/ball.h"` in `main.c`
- Game metadata JSON: `GBDKPipelineV2.buildMetadataFile()` derives `"name": "ball"` from the IR actor-ID

## Shared Patterns

### Cross-tier rename propagation (apply to all 10 files)

**Source:** `gbkt-lang` `ActorDelegate.provideDelegate` mechanism (Project Rule #1 / `feedback_no_magic_strings`)

**Pattern:** The Kotlin property name is the single source of truth. Renaming the property at `SimplePhysics.kt:64` from `val smiley by actor` to `val ball by actor` propagates through:
- IR actor-ID → `"ball"`
- Generated C symbols → `_ball_x`, `_ball_y`
- Sprite asset file lookup → `sprites/ball.c`, `sprites/ball.h`
- Game metadata JSON → `"name": "ball"`, `"vars": {"x": "ball_x", "y": "ball_y"}`
- `.noi` linker symbol table → `__ball_x`, `__ball_y`

The only manual edits are: (1) the Kotlin property + asset path string, (2) test assertions that contain hardcoded `"smiley"` string literals, (3) documentation prose.

### Clean-before-build gate (apply to Wave 4 smoke gate)

**Source:** RESEARCH.md Q2, `.planning/verifier-gates.md`

**Pattern:** Always run `:clean` before `:buildRom` after an asset rename. Without `clean`, `build/gbkt/generated/sprites/smiley.c|h` persists from the prior build alongside the new `ball.c|h`, creating ghost symbols and potential linker conflicts. The mandatory command:

```bash
./gradlew :gbkt-examples:simple-physics:clean :gbkt-examples:simple-physics:buildRom
```

### Frozen-evidence convention (apply to evidence artifact production)

**Source:** Phase 09 / 09.1 / 09.3 precedent (CONTEXT.md §Canonical References)

**Pattern:** New evidence goes in a **fresh phase directory** (`.planning/phases/09.4-.../evidence/`). Prior phases' evidence directories are never overwritten. The `EVIDENCE_DIR` constant in `SimplePhysicsUatTest.kt` must be updated to the new phase path before re-running UAT, or the re-baseline will silently overwrite the frozen 09.3 evidence.

### `internal const val` naming convention (apply if test parameterization chosen)

**Source:** `SimplePhysics.kt:12-18` (established in Phase 09.3 Track 2)

```kotlin
internal const val CARTRIDGE_ROM_ONLY = "ROM_ONLY"
```

If the planner opts to parameterize actor-ID assertions, the pattern is `private const val ACTOR_ID = "ball"` in the test file's `companion object`. SCREAMING_SNAKE_CASE, `private` visibility (test-internal), placed at the top of the companion.
