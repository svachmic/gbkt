## Validation Dimensions (from RESEARCH.md § Validation Architecture)

### 1. JVM-tier assertions (post Wave 2)

`SimplePhysicsIRTest` (renamed):
- `"ball" == ir.actors.first().id`
- `ir.actors.first { it.id == "ball" }.position == PositionDef(64, 64)`
- `ir.actors.first { it.id == "ball" }.sprite != null`
- `setOf("ball") == ir.actors.map { it.id }.toSet()`

`SimplePhysicsEmissionTest` (unchanged — no actor-name assertions; still GREEN on both pre/post rename).

### 2. Generated-C assertions (post Wave 4 clean buildRom)

```bash
# Must be 0:
grep -c "smiley" gbkt-examples/simple-physics/build/gbkt/generated/main.c

# Must be > 0 (8 expected occurrences of _ball_* / ball-prefixed symbols):
grep -c "ball" gbkt-examples/simple-physics/build/gbkt/generated/main.c

# Sprite files: ball.c, ball.h must exist; smiley.c, smiley.h must NOT:
ls gbkt-examples/simple-physics/build/gbkt/generated/sprites/
```

### 3. ROM-level assertions

# Exit code must be 0:
