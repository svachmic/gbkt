## Summary

Phase 09.4 is a pure cross-tier rename (`smiley` → `ball`) of a single Kotlin DSL
property, the underlying 8×8 PNG asset, three test files, and three doc files. The
rename was performed mechanically and is internally consistent:

- DSL property: `val ball by actor` at `SimplePhysics.kt:64` (was `val smiley`).
- Sprite asset path: `sprites/ball.png` at `SimplePhysics.kt:66` (was `sprites/smiley.png`).
- `git mv` preserved history of `res/sprites/smiley.png` → `res/sprites/ball.png`.
- Generated `game_metadata.json` reflects `"name": "ball"` and `_ball_x` / `_ball_y` vars.
- IR test assertions migrated to `ir.actors.first { it.id == "ball" }` (4 sites).
- UAT test `EVIDENCE_DIR` redirected from the 09.3 path to the 09.4 phase path
  (intentional per the prompt — freezes 09.3 evidence as historical record).
- No orphan `smiley` symbols remain anywhere in the scoped tree EXCEPT the phase-dir
  path strings (which legitimately encode the phase title) — `grep -rn smiley`
  outside `build/` and `.planning/` returns only the three `EVIDENCE_DIR` substrings.
- No assertion VALUES were changed in any test (verified via `git diff`): only comments,
  string literals, and identifiers were touched. Behavior is preserved as designed.
- No naming collision: other examples (pong, breakout) also use `val ball by actor`,
  but each is scoped to its own `game { }` builder/DSL context, so there is no shared
  symbol space at risk.

No BLOCKER-tier defects. Two WARNINGs and three INFO items below cover stale
cross-references and inconsistencies that the rename touched but did not fix.

## Warnings

### WR-01: Stale "Bug B workaround" note in PLAYBOOK.md contradicts current source

**File:** `gbkt-examples/simple-physics/PLAYBOOK.md:43-48`
**Issue:** The "Known Quirks" entry asserts:

> `ActorRef.moveTo(Expr, Expr)` does not exist in the current DSL surface (`moveTo`
> only accepts `Int`). The port uses `ball.x set (posX shr 4)` and
> `ball.y set (posY shr 4)` via the `ActorPropertyRef` set-with-Expr API.

This is factually false at HEAD:

- `SimplePhysics.kt:124` actually calls `ball.moveTo(posX shr 4, posY shr 4)`.
- `SimplePhysics.kt:35-37` KDoc and `CLAUDE.md:56-58` both confirm the
  `ActorRef.moveTo(Expr, Expr)` overload was added in Phase 9.1 Plan 01 (SEED-002).

The PLAYBOOK quirk now describes a workaround that no longer exists in the source.
The rename touched these exact lines (4 `smiley → ball` edits at L43-48) without
correcting the stale claim. A reader following PLAYBOOK as the canonical
"Known Quirks" guide will be misinformed about the state of the DSL.

**Fix:** Either delete the quirk entirely (preferred — the workaround is gone)
or rewrite it as a historical note. Suggested replacement:

```markdown
- **Sub-pixel-to-pixel sync uses `ball.moveTo(Expr, Expr)`.** The
  `ActorRef.moveTo(Expr, Expr)` overload (added in Phase 9.1 Plan 01 — SEED-002)
  lowers to a single `SetPosition` op. The reference uses
  `move_sprite(0, SUBPIXELS_TO_PIXELS(PosX), ...)` inline; the gbkt port is
  functionally equivalent.
```

### WR-02: `resolveI16Address` re-parses the `.noi` file on every variable read

**File:** `gbkt-examples/simple-physics/src/test/kotlin/io/github/gbkt/examples/simple_physics/SimplePhysicsUatTest.kt:77-87`
**Issue:** Every `readI16(agent, name)` call invokes `resolveI16Address(name)`, which
in turn calls `noi.readLines()` and iterates with `pattern.matchEntire(line.trim())`.
In `behavior 1` alone this fires three times against the same `.noi` file
(once for the initial spdX read, once for spdXAt30, once for posXAt30, plus a fourth
for spdXAt64). The cost is small in absolute terms, but more importantly the function
silently treats a missing symbol as a fatal `error(...)` — combined with no caching,
a single typo (`readI16(agent, "spdx")` vs `"spdX"`) re-reads and re-fails the same
file every call site.

A subtler correctness risk: the regex anchors on `^DEF\s+__${name}\s+0x...`. If the
`.noi` file ever contains another symbol whose name happens to be `__${name}` for
unrelated reasons (e.g., a renamed actor or a stray static), the FIRST match is
returned. In Phase 09.4 the rename guarantees `__spdX`/`__spdY`/`__posX`/`__posY`
are unique INT16 vars (verified via `game_metadata.json`), but the helper is
defensive against neither (a) ambiguous matches nor (b) stale `.noi` files from
a previous build that still reference `__smiley_x` after the rename.

**Fix:** Cache the parsed symbol table in the companion or in the agent factory,
and ASSERT uniqueness when building it:

```kotlin
private val symbolTable: Map<String, Int> by lazy {
    val noi = File(ROM_FILE.parentFile, ROM_FILE.nameWithoutExtension + ".noi")
    check(noi.exists()) { ".noi not found at ${noi.absolutePath}" }
    val pattern = Regex("""^DEF\s+__(\w+)\s+0x([0-9A-Fa-f]+)\s*$""")
    val table = mutableMapOf<String, Int>()
    for (line in noi.readLines()) {
        val m = pattern.matchEntire(line.trim()) ?: continue
        val name = m.groupValues[1]
        val addr = m.groupValues[2].toInt(16)
        check(table.put(name, addr) == null) {
            "Duplicate symbol '$name' in .noi — refusing ambiguous resolution"
        }
    }
    table
}
private fun resolveI16Address(name: String): Int =
    symbolTable[name] ?: error("Symbol '$name' not found in .noi")
```

Also: if a stale `simple-physics.gb.noi` from a pre-rename build is on disk,
nothing in the test harness invalidates it. The phase already passes the ROM
smoke gate (`buildRom`), so this is latent, not active — but worth noting.

## Info

### IN-01: README "four-tier verification stack" uses class names that do not exist

**File:** `gbkt-examples/simple-physics/README.md:33-36`
**Issue:** The README claims:

> The four-tier verification stack covers `SimplePhysicsIRTest` (IR shape) →
> `SimplePhysicsEmissionTest` (codegen shape) → `GameTest` (JVM simulation) →
> `UatTest` (emulator playback against `PLAYBOOK.md`).

The actual class names on disk are `SimplePhysicsGameTest` and
`SimplePhysicsUatTest`. A reader who greps for `class GameTest` or `class UatTest`
will find nothing in this module. This is preexisting (not introduced by 09.4),
but the rename touched README L5 and is the natural place to also fix this.

**Fix:** Rewrite the line as
`...→ \`SimplePhysicsGameTest\` (JVM simulation) → \`SimplePhysicsUatTest\`
(emulator playback against \`PLAYBOOK.md\`)`.

### IN-02: KDoc class-comment paragraph in `SimplePhysics.kt` repeats `ActorRef.moveTo(Expr, Expr)` verbatim

**File:** `gbkt-examples/simple-physics/src/main/kotlin/io/github/gbkt/examples/simple_physics/SimplePhysics.kt:35-37`
**Issue:** The KDoc reads:

> Position sync uses `ActorRef.moveTo(Expr, Expr)` to teleport the ball actor to the
> sub-pixel-converted coordinate (the `ActorRef.moveTo(Expr, Expr)` overload added
> in Phase 9.1 Plan 01 — SEED-002 — lowers the call to a single SetPosition op).

The identifier `ActorRef.moveTo(Expr, Expr)` appears twice in the same sentence —
the parenthetical re-states what the leading clause just said. Phase 09.4 did
not introduce this, but it's a readability snag on the page that the reviewer
of a rename will land on.

**Fix:** Collapse to a single mention:

```
Position sync uses `ActorRef.moveTo(Expr, Expr)` (added in Phase 9.1 Plan 01 —
SEED-002) to teleport the ball actor to the sub-pixel-converted coordinate; the
overload lowers to a single SetPosition op.
```

### IN-03: `CARTRIDGE_ROM_ONLY` constant is module-level visibility but used in only one place

**Fix:** Either inline `cartridge = "ROM_ONLY"` (with a `// PHASE-13: typed
Cartridge.ROM_ONLY` comment) or actually exercise the constant from a test to
justify the `internal` visibility. No action required for this phase.
