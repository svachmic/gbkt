## Implementation Decisions

### Area 1 — Primary path: rename vs asset swap

- **D-A1-01 Path A (rename):** Rename `smiley` → `ball` across the entire footprint. Asset content stays the existing ball PNG. Smallest blast radius, zero visual pixel delta, fastest to ship. Aligns with the 09.3 "canonical showcase" framing — the example IS what it claims to render. Rejected alternatives: Path B (swap in real 8×8 smiley PNG; more work, requires UAT screenshot re-baseline against shifted pixels, no clear authoring win); Path A+ (rename + keep future-smiley intent in docs; clutters with non-committal future-intent, see D-A1-03).
- **D-A1-02 Asset filename plain `ball.png`:** Mirrors `gbkt-examples/breakout/res/sprites/ball.png` exactly. The example module dir is its own namespace; no `ball-8x8.png` / `physics-ball.png` disambiguator. simple-physics ships an independent copy of the bytes — cross-example asset-sharing is an incidental byte-equivalence, not a documented invariant.
- **D-A1-03 No future-smiley breadcrumb:** No `// TODO: smiley swap candidate` comment in source, no "smiley variant welcome as a contrib PR" line in CLAUDE.md / README. Clean rename. If a contributor later wants a smiley variant, they open an issue or a PR — neither the source nor the docs need a permanent aspirational-intent anchor. Rejected alternatives: CLAUDE.md one-liner (doc clutters with non-committal future-intent, sets a doc-as-issue-tracker precedent); source `TODO` / `PHASE-N` breadcrumb (09.3 reserves PHASE-N breadcrumbs for committed framework-primitive replacement sites only).

### Area 2 — UAT re-baseline policy

- **D-A2-01 Re-baseline behavior2 under fresh 09.4 evidence dir:** Re-run the UAT MCP behavior2 sequence on the post-rename ROM and capture both the screenshot and the JSON sidecar (now containing `_ball_x` / `_ball_y`) into `.planning/phases/09.4-…/evidence/`. The 09.3 evidence dir remains frozen as historical record. Honors the roadmap success criterion that pre-09.4 PNG remains untouched. Satisfies the Visual Evidence Rule even though no pixels moved — the "sprite is visible at expected pixel" truth is re-proven against the post-rename codegen and asset path. Rejected alternatives: skip re-baseline entirely (violates Visual Evidence Rule); JSON-sidecar-only without screenshot (half-measure — if the emulator is running anyway, the PNG capture is free).
- **D-A2-02 `rename-diff.md` verifier artifact:** Produce a side-by-side diff of `.planning/phases/09.3-…/evidence/post-09.3-main.c` vs the new `.planning/phases/09.4-…/evidence/post-09.4-main.c`. Demonstrates the rename is shape-preserving in generated C — identical bytes except the `_smiley_*` → `_ball_*` symbol tokens (and the `smiley`-prefixed tile-data array names). Mirrors the 09.3 pattern (refactor-diff.md, oracle-comparison-v2.md). Verifier-facing proof artifact; cheap to produce, high signal. Rejected alternative: rely solely on the JVM emission test (the parameterized assertion is necessary but the human-readable diff is what makes the shape-preservation visible to a reviewer in seconds).

### Area 3 — Docs sweep scope

- **D-A3-01 PLAYBOOK fully rewritten — 09.3 carve-out does NOT extend:** All 4 PLAYBOOK refs (L5, L11, L45, L48) get renamed `smiley` → `ball`. Rationale: 09.3's PLAYBOOK carve-out was specifically about NOT importing the showcase-reframing marketing tone into the test-agent contract. A name correction is fundamentally different — PLAYBOOK currently misnames the actor for the MCP agent reading it, which is a CORRECTNESS issue for the test contract. An MCP agent grepping `_smiley_x` post-rename to validate position would fail; PLAYBOOK must agree with the Kotlin DSL and the generated C. Rejected alternatives: PLAYBOOK as-is (stale relative to code, fails MCP test contract); surgical L5/L45/L48-only rename leaving the prose `smiley sprite` phrasing at L11 (partial-rename is more confusing than either extreme).
- **D-A3-02 Delete CLAUDE.md "Asset Source" section (L82-88):** Once the asset is `ball.png` and `val ball`, the "copied verbatim from `breakout/.../ball.png`" self-doc note is redundant — the asset IS what it claims to be, no aspirational future swap to document. Replace with nothing. The cross-example byte-equivalence with breakout is an incidental implementation detail, not a documented invariant; future divergence is acceptable. Rejected alternatives: rewrite to document the cross-example sharing as an intentional convention (over-documents an incidental detail; creates a false coupling invariant); delete the section AND drop any breakout cross-reference entirely from CLAUDE.md (this option is functionally identical to the chosen one — there are no other cross-references to drop).

In-source KDoc at `SimplePhysics.kt:35` and comment at `:61` are mechanical substitutions.
