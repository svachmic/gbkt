<objective>
Gap closure follow-up to Plan 03's D-10 root-cause fix. The user selected Option B on 2026-05-14 in 09.1-HUMAN-UAT.md: the project intent is a genuinely-MBC0 simple_physics ROM at runtime, not just at the build-metadata layer. Plan 03's zero-op filter only excludes scenes whose enterOps + frameOps + exitOps are ALL empty. Real simple_physics has ~30 non-trivial ops in its single scene and currently still lands in bank 1, which transitively forces the compiled ROM to MBC5 at the CompileRomTask layer (`bank1.c` always emits `#pragma bank 1`, `detectMaxBank` returns > 0, `readMbcType` upgrades).

This plan adds the analysis-layer half of the fix: extend BankingAnalysisPass with a single-scene-fits-HOME fast-path. When a GameIR has exactly one scene whose code volume fits within a conservative HOME-bank budget, the pass routes it to bank 0 (HOME) instead of bank 1+. The fast-path is statically gated by `scenes.size == 1` so multi-scene games (banked: rpg-lite, breakout, etc.) provably bypass it via the static guard.

This is Plan 1 of 2 for the gap closure (Plan 05 consumes this plan's bank-0 assignments to suppress bank1.c emission in GBDKPipelineV2 and adds the compiled-ROM byte verification + multi-example smoke regression).

Doctrine anchors per gap_closure_context:
- D-01 (batched surplus phase, but each plan stays atomic) — this plan is atomic on the analysis layer.
- D-03 (done signal = JVM-tier invariant) — the fast-path is locked by BankingAnalysisPassTest + MbcTypeProbeTest at the IR/analysis-pass output layer. No ROM rebuild needed for the contract; Plan 05 carries the build-time byte witness.
- D-04 (multi-example regression guard) — banked-game fixtures in MbcTypeProbeTest assert MBC5 behavior unchanged; the fast-path's `scenes.size == 1` guard makes the regression structurally impossible. Multi-example buildRom smoke regression is deferred to Plan 05 (where the bank1.c-suppression change actually risks regressing banked-game emission).
- D-10 (extended scope) — fast-path delivers the missing prong: single-scene games stay bank 0 cleanly without relying on the CompileRomTask belt-and-suspenders upgrade.
- D-12 (extended scope) — the per-example MBC-type probe now asserts the new bank-0 outcome for single-scene fixtures.

Purpose: without the analysis-layer fast-path, no downstream consumer (Plan 05's pipeline suppression, or any future emitter) has a clean signal that "this game is single-scene-bank-0 — emit it as HOME-only." Plumbing the decision into the analysis pass keeps the bin-packer pure and gives Plan 05 a localized, testable input contract.
