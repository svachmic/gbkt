### Fix 5 — `gbkt-analysis/.../passes/BankingAnalysisPass.kt` (D-10 root-cause)

**Root cause:** `findFirstFit` always starts scanning from bank 1 (`for (bank in 1 until maxBanks)`). For a single-scene game with zero ops, `estimatedBytes = 0`, which trivially fits in bank 1. The game then carries `bankSlot.bank = 1`, which triggers the MBC1/MBC5 path in `CompileRomTask.readMbcType()`.

**Current code to fix** (`BankingAnalysisPass.kt:155-173`):
```kotlin
private fun findFirstFit(
    bytes: Int,
    bankUsed: Map<Int, Int>,
    capacity: Int,
    preferredBank: Int?,
    maxBanks: Int,
): Int? {
    if (preferredBank != null && preferredBank in 1 until maxBanks) {
        val used = bankUsed[preferredBank] ?: 0
        if (used + bytes <= capacity) return preferredBank
    }
    // Fall back to first-fit scan (skip bank 0 — HOME)
    for (bank in 1 until maxBanks) {
        val used = bankUsed[bank] ?: 0
        if (used + bytes <= capacity) return bank
    }
    return null
}
```

**Fix direction (D-10):** In `buildCodeUnits`, skip scenes whose `estimatedBytes == 0` (no ops → no banking needed). Scenes with zero ops produce no banked functions, so they should not receive a `bankSlot` assignment. Alternatively, add an early-return guard in `run()`: if all `codeUnits` have `estimatedBytes == 0`, skip the pass entirely and return `PassResult.Success` with no `bankAssignments`.

**Analog for the test:** `BankingAnalysisPassTest.kt:43-55` (pattern to copy for new zero-ops test):
```kotlin

    assertNotNull(slot, "Expected 'gameplay' in bankAssignments")

}
```

**New test to add in `BankingAnalysisPassTest.kt`:**
```kotlin
@Test

    val scene = sceneWithOps("play", 0)  // zero ops → zero bytes
```

### Fix 6 — `gbkt-gradle-plugin/.../tasks/CompileRomTask.kt` `readMbcType()` (D-11 suggestion)

**Full function to modify** (`CompileRomTask.kt:259-279`):
```kotlin
private fun readMbcType(sourceDir: File): String {
    val propsFile = File(sourceDir, "gbkt-build.properties")
    if (propsFile.exists()) {
        val props = java.util.Properties()
        propsFile.inputStream().use { props.load(it) }
        val mbcType = props.getProperty("mbcType")
        if (mbcType != null) {
            // Banking requires at least MBC5 — upgrade ROM_ONLY automatically
            if (mbcType == "0x00") {
                val hasRam = ramBanks.getOrElse(0) > 0
                val upgraded = if (hasRam) "0x1B" else "0x19"
                logger.lifecycle("Cartridge upgraded from ROM_ONLY to MBC5 (banking detected)")
                return upgraded
            }
            return mbcType
        }
    }

    // Fallback: derive from RAM banks configuration
    val hasRam = ramBanks.getOrElse(0) > 0
    return if (hasRam) "0x1B" else "0x19" // MBC5+RAM+Battery or MBC5
}
```

**Fix (D-11):** Add suggestion line after the existing `logger.lifecycle(...)` call (surgical 1-line addition):
```kotlin
logger.lifecycle("Cartridge upgraded from ROM_ONLY to MBC5 (banking detected)")
logger.lifecycle("  Suggestion: add `config { cartridge(CartridgeType.ROM_MBC5) }` to silence this upgrade.")
```

The `logger.lifecycle()` pattern is already established in this function at line 270. The suggestion text mirrors `ErrorEnhancer` conventions — lifecycle log + actionable suggestion, not a build failure.
