## Phase Boundary

Phase 9.1 batches the surplus codegen defects and codegen-hygiene gaps surfaced during the Phase 9 simple_physics port that were not fixed under the per-port single-named-bug doctrine. By construction, 9.1 is a *surplus cleanup* phase — the single-named-bug doctrine (D-04 + D-05) is per-port and does not bind here; each fix is still atomic per plan.

**In scope:**
- **SEED-002** — add `ActorRef.moveTo(x: Expr, y: Expr)` overload to `gbkt-lang/.../ActorBuilder.kt`; lock the lowering to a single `SetPosition(id, x, y)` op with a JVM-tier IR-level assertion; migrate simple_physics port in the same plan from the workaround (`smiley.x set ...; smiley.y set ...`) to the new overload.
- **DEFERRED-09-01** — fix all 4 SDCC scaffolding warnings (codes 84, 85×2, 126) in `GBDKPipelineV2.kt`: initialize `delay_frames._d`, silence `show_sprites_range` unref-params with `(void)`, drop `main()`'s trailing `return;` after the infinite loop. Four independent JVM-tier invariant tests, one per warning code.
- **DEFERRED-09-02** — root-cause fix to `BankingConfig` defaults so single-scene games stay in bank 0 (HOME); keep the `CompileRomTask` upgrade guard as belt-and-suspenders fallback (still upgrades + emits a lifecycle log when banking IS detected, with a suggestion nudging the user to declare `cartridge(CartridgeType.ROM_MBC5)` explicitly). Lock per-example MBC type assertion: single-scene games → MBC 0x00 (ROM_ONLY); banked games (LabyrinthOfTheDragon, RPG-Lite, etc.) → MBC5 unchanged.
- Build-only smoke regression across **all** gbkt examples after each infrastructure plan (DEFERRED-09-01 and -02): `buildRom` success on every example, zero new SDCC warnings.

**Out of scope:**
- Adding a family of `Expr` overloads (`position(Expr,Expr)`, `moveBy(Expr,Expr)`, etc.) speculatively — anti-overfitting rail 1 (no DSL features just to make a port pretty). Wait for real-port telemetry before expanding.
- Removing the `show_sprites_range` stub entirely (caller audit deferred to a future hygiene phase).
- Redesigning the `BankingConfig` / banking-analysis surface beyond the default change — Phase 11 (banks port) is where banking primitives are properly exercised.
- Full emulator UAT on examples beyond simple_physics — build smoke is sufficient at this tier.
- Re-running Phase 9's 3 D-01 behaviors as a regression contract (the JVM-tier invariants already lock the codegen surface).
- Phase 10/11/12 methodology refinements (INT16-read UAT helper, MCP wiring docs, decel-aware UAT trace) — those belong in Phase 10's discuss/plan, not in 9.1.
- Spinning 9.2/9.3 sub-phases per item — batched-surplus decision means all three items live in 9.1, each as its own plan.

<decisions>
## Implementation Decisions

### Scope cap (doctrine application)
- **D-01:** **Batched surplus phase.** Single-named-bug doctrine (D-04 + D-05 from Phase 9) was *per-port*. Phase 9.1 is by design the surplus catch-all; the doctrine does not bind here. Bundle SEED-002 + both deferreds in one phase, each fix as its own atomic plan.
- **D-02:** **All three items in scope.** SEED-002 + DEFERRED-09-01 + DEFERRED-09-02. No 9.2/9.3 split.
- **D-03:** **Done signal per fix = JVM-tier invariant** mirroring D-11 from Phase 9. Each plan lands a JVM-tier emission/lowering test that locks the codegen contract. No ROM rebuild required for the contract; runtime is downstream.
- **D-04:** **Multi-example regression = build-only smoke.** After each infrastructure plan (the two deferreds; SEED-002 is DSL-only and only touches `simple_physics`), run `buildRom` on every gbkt example. Pass = build success + zero new SDCC warnings. No emulator UAT for examples beyond simple_physics.

### SEED-002 (moveTo Expr overload)
- **D-05:** **Scope = single `moveTo(x: Expr, y: Expr)` overload only.** Matches the seed exactly. No speculative family of `Expr` overloads (`position`, `moveBy`, etc.). Adjacent overloads wait for real-port telemetry per the seed's own "Trigger conditions".
- **D-06:** **Migrate simple_physics in the same plan as the overload.** Acts as integration proof — the overload is exercised end-to-end, and the C-diff appendix from Phase 9 evolves from 2 `SetActorProperty` ops to 1 `SetPosition` op for the position-sync glue. Reinforces the oracle-comparison narrative.
- **D-07:** **JVM-tier test shape = IR-level assertion.** Test asserts the recorded `ScriptOp` is a single `SetPosition(id, x, y)`, not two `SetActorProperty` ops. Locks the contract at the IR layer, independent of C emission. Fastest test, smallest surface. No C-level grep required (the existing pipeline emission for `SetPosition` is already covered).

### DEFERRED-09-01 (SDCC scaffolding warnings)
- **D-08:** **Fix all 4 warnings.** Mechanical, additive, low-risk. Unlocks the "zero SDCC warnings across the example suite" bar.
  - **84 (delay_frames):** emit `UINT8 _d = 0u;` instead of `UINT8 _d;`.
  - **85×2 (show_sprites_range):** silence with `(void)from; (void)to;` — lowest blast radius. Stub-removal explicitly NOT in scope (caller audit defers to a future hygiene phase).
  - **126 (main):** drop the trailing `return;` after the infinite `while(1)` loop.
- **D-09:** **Test shape = four independent JVM-tier invariant tests**, one per SDCC code, each naming the code in its assertion message. Failure attribution is unambiguous when a regression breaks one but not the others. No combined "scaffolding clean" test; no SDCC-invocation integration test (the latter would gate CI on a GBDK install).

### DEFERRED-09-02 (MBC5 auto-upgrade for single-scene games)
- **D-10:** **Two-pronged fix — BankingConfig default + CompileRomTask guard.**
  1. **Root-cause:** `BankingConfig` default changes from "all scene code to bank 1" to "bank 0 (HOME) until banking is actually needed". The analysis pass decides when to spill to bank 1+ (existing mechanism). Single-scene games end up MBC 0x00 (ROM_ONLY) cleanly.
  2. **Belt-and-suspenders:** `CompileRomTask.readMbcType()` upgrade guard stays — still upgrades ROM_ONLY → MBC5 if banking IS detected by the analysis. Defends against future regressions that re-introduce spurious bank usage.
- **D-11:** **Upgrade feedback level = lifecycle log + suggestion.** When the `CompileRomTask` guard fires (the user configured `ROM_ONLY` but the game actually uses bank N), keep the current `lifecycle("Cartridge upgraded ...")` log AND add a suggestion line: *"Configure `config { cartridge(CartridgeType.ROM_MBC5) }` to silence this upgrade."* Friendly default behavior; nudges the user to make the cartridge type explicit. NOT a build failure (compile-time-over-runtime principle 2 considered and rejected here — the current auto-upgrade is a documented friendly default, and breaking existing build.gradle.kts files is wider blast radius than the win).
- **D-12:** **Regression contract = per-example MBC type assertion.** Add a small probe that builds each gbkt example and asserts the final MBC type:
  - simple_physics, simple Pong (if it fits bank 0) → MBC 0x00 (ROM_ONLY).
  - Breakout, Explorer, Shmup, LabyrinthOfTheDragon, RPG-Lite, etc. → MBC5 (unchanged from current behavior).
  Locks the contract explicitly per example; failures point at the right example. NOT just "build success + size delta" — size delta won't catch a silent MBC downgrade.

### Claude's Discretion
- **Plan ordering across the three items.** Suggested by risk-and-blast-radius: Plan 1 = SEED-002 (smallest, DSL-only, no infra change). Plan 2 = DEFERRED-09-01 (4 fixes, pipeline scaffolding only, no behavior change). Plan 3 = DEFERRED-09-02 (widest blast radius — touches `BankingConfig` defaults + per-example MBC assertion probe). Planner decides final order; this is a recommendation, not a constraint.
- **Test placement.** JVM tests for SEED-002 live in `gbkt-backend-gbdk/src/test/.../codegen/` (or `gbkt-lang/src/test/` if IR-level — planner picks). DEFERRED-09-01 invariants live alongside existing `GBDKPipelineV2` tests in `gbkt-backend-gbdk/src/test/.../pipeline/`. DEFERRED-09-02 MBC-type assertion probe location is open — likely a new test in `gbkt-gradle-plugin/src/test/` since it's a build-task-level concern.
- **simple_physics C-diff appendix update.** Phase 9's `evidence/c-diff.md` mentioned the Bug B workaround in a "longer regions" row. After SEED-002 migration, that row should be retracted (or updated to "equal" / "shorter") in a closing note. Planner may treat this as a 4th tiny plan or fold it into the SEED-002 plan; both are fine.
