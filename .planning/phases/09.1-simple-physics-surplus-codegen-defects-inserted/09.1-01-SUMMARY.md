## Implementation Details

### Task 1: ActorRef.moveTo(Expr, Expr) overload (ActorBuilder.kt)

Added immediately after the existing `moveTo(Int, Int)` at line 334:

```kotlin
fun ActorRef.moveTo(x: Expr, y: Expr) {
    ScriptBuilderContext.current?.setPosition(id, x, y)
        ?: error("moveTo() called outside a ScriptBuilder block")
}
```

Key design decision: `x` and `y` are passed through unchanged — NO `Literal()` wrapping. The underlying `ScriptBuilder.setPosition(id, x: Expr, y: Expr)` already exists and emits `SetPosition(actorId, x, y, ...)`. The overload is purely additive — zero visitor sites changed, zero existing tests affected.

### Task 1: MoveToExprOverloadTest.kt (RED→GREEN TDD)

- **RED gate:** Test failed to compile before the overload existed (`Argument type mismatch: actual type is 'Expr', but 'Int' was expected`)
- **GREEN gate:** Test compiles and passes after overload is added
- Primary test: `moveTo(Expr, Expr) emits exactly one SetPosition op` — asserts `ops.size == 1` with D-07 citation, `assertIs<SetPosition>(ops[0])`, reference equality for `x` and `y` Expr instances
- Negative control: `moveTo(Int, Int) still emits exactly one SetPosition op with Literal x and y` — guards against signature collision

### Task 2: SimplePhysics.kt migration

Before:
