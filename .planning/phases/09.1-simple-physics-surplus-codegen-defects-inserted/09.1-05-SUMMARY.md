# Phase 09.1 Plan 05: Pipeline bank1.c-Omission for Single-Scene-HOME Games Summary

Pipeline-layer gap closure (G-01 fully closed): GBDKPipelineV2.buildCFiles() now suppresses bank1.c for single-scene-fits-HOME games via `allScenesInHome` predicate, folding scene functions into main.c; compiled simple-physics.gb byte 0x0147 flipped 0x19 → 0x00.

## What Was Built

### Pipeline source edit (GBDKPipelineV2.kt lines 495-542, +37 lines)

Single addition to `buildCFiles()` function body (buildSceneFile body is byte-identical, per Strategy B):

1. **`allScenesInHome` predicate** (lines 520-521):
   ```kotlin
   val allScenesInHome = gameIR.scenes.isNotEmpty() &&
       gameIR.scenes.all { (it.bankSlot?.bank ?: 1) == 0 }
   ```
   Uses `all { ... }` (not `first { ... }.bank`) so mixed-bank GameIR cannot accidentally enter the fold path.

2. **Fast-path branch** (lines 523-541) when `allScenesInHome` fires:
   - Builds `mergedHome` by appending sceneFile.functions + defines + includes to homeFile
   - Passes empty sentinel sceneFile to `buildHeaderFile` so scene prototypes appear under `homeFunctionPrototypes` (non-BANKED) rather than `sceneFunctionPrototypes` (BANKED)
   - Returns `listOf(mergedHome, headerFile) + tilemapBankFiles` — NO sceneFile, so bank1.c absent from output

3. **Else branch** (default banked-game path): unchanged `listOf(homeFile, sceneFile, headerFile) + tilemapBankFiles`

KDoc in the guard cites: Plan 09.1-05, gap-closure 2026-05-14, Plan 04 analysis-layer fast-path, D-04 anti-overfitting rationale.

Key discovery during implementation: **no `stripBanked` helper was needed**. `SceneVisitor.kt` line 77 already handles this:
```kotlin
val sceneBanked = sceneBank == null || sceneBank > 0
```
When `bankSlot.bank == 0`, `sceneBanked = false` and `isBanked = false` is set on the CFunction. Functions folded into main.c are already correctly NOT BANKED.

## Deviations from Plan

### Observations (not deviations)

**1. No stripBanked helper needed**
- The plan anticipated needing a `stripBanked` helper to clear `isBanked = true` on folded functions
- Investigation found SceneVisitor.kt line 77 already handles this: `val sceneBanked = sceneBank == null || sceneBank > 0`
- When `bankSlot.bank == 0`, `sceneBanked = false` → `isBanked = false` is set at CFunction construction
- Result: simplified implementation (~5 fewer lines than planned)

**2. RED test required stricter assertion than plan spec**
- Plan spec allowed the OR condition: `output["bank1.c"] == null OR !output["bank1.c"]!!.contains("#pragma bank 1")`
- After Plan 04, the pipeline already emits bank1.c with `bank = 0` (no `#pragma bank 1`), so the second arm of the OR was already true
- The test had to assert `output["bank1.c"] == null` (strict) to be genuinely RED
- Additionally asserted `void play_enter` in main.c (function definition, not just a call) to prove folding direction

**3. pong remains at 0x19**
- Plan noted "pong MAY flip to 0x00" as uncertain
- Confirmed: real pong DSL is 3-scene; allScenesInHome does NOT fire; 0x19 is correct
- The pong-like JVM fixture is a single-scene TEST SHAPE (not the real game structure)

None of these required architectural deviation per Rule 4.
