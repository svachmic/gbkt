# Phase 09.1 Plan 04: Single-Scene-Fits-HOME Fast-Path Summary

Analysis-layer gap closure for G-01: BankingAnalysisPass now routes single-scene games fitting a 4 KB HOME budget to bank 0, preventing spurious MBC5 upgrade in simple_physics-class ROMs.

## What Was Built

### Root-cause source edit (BankingAnalysisPass.kt lines 54-69, +83-91)

Two additions to `BankingAnalysisPass.kt` (total: ~19 lines of new source + KDoc):

1. **`HOME_BANK_SCENE_BUDGET = 4_096` constant** added to the `private companion object`. KDoc cites 09.1-04, gap-closure date 2026-05-14, Option B decision, and the anti-overfitting rationale (static value, no backend coupling).

2. **Single-scene fast-path branch** inserted in `run()` after `buildCodeUnits()` and before `buildTransitionGraph()`:
   ```
   if (codeUnits.size == 1 && codeUnits[0].estimatedBytes <= HOME_BANK_SCENE_BUDGET) {
       val unit = codeUnits[0]
       val assignments = mapOf(unit.id to BankSlot(bank = 0))
       return PassResult.Success(context.copy(bankAssignments = context.bankAssignments + assignments))
   }
   ```
   - `findFirstFit` body: unchanged (byte-identical to pre-fix — verified via `git diff`)
   - Multi-scene games bypass the fast-path via the `codeUnits.size == 1` guard
   - Correctly composes with the D-10 zero-op filter: zero-op scenes produce empty `codeUnits`, so `size != 1`, fast-path skips, assignments empty (Plan 03 contract preserved)
