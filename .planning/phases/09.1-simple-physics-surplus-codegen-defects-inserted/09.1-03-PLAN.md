<objective>
Root-cause fix for DEFERRED-09-02: single-scene games (like simple_physics) currently force MBC5 upgrade because BankingAnalysisPass assigns zero-op scenes to bank 1, which triggers the CompileRomTask.readMbcType() upgrade guard. Two prongs per D-10:

1. Root cause: Make BankingAnalysisPass skip zero-op code units before bin-packing — zero-byte scenes do not need bank assignments.
2. Belt-and-suspenders: Keep the CompileRomTask upgrade guard unchanged in behavior; add a lifecycle() suggestion (D-11) nudging users to declare cartridge(CartridgeType.ROM_MBC5) explicitly.

The regression contract (D-12) is a per-example MBC-type assertion probe that runs BankingAnalysisPass over each example's GameIR shape and asserts the expected outcome (ROM_ONLY for zero-op single-scene; MBC5 for banked).

Purpose: Without the root-cause fix, every minimal gbkt game silently upgrades to MBC5 — a 64KB+ cartridge format for what should be a 32KB ROM. The fix lets minimal games stay in MBC 0x00 cleanly, while preserving friendly auto-upgrade for genuinely-banked games.

Output:
- 1 source edit in BankingAnalysisPass.kt (filter zero-op code units).
- 1 new test case in BankingAnalysisPassTest.kt (zero-op scene -> no bank assignment).
- 1 source edit in CompileRomTask.kt (1-line suggestion).
- 1 new test file MbcTypeProbeTest.kt (per-example MBC-type assertions).
- Multi-example smoke regression.
</objective>
