## Root-Cause Source Edit (D-10)

**File:** `gbkt-analysis/src/main/kotlin/io/github/gbkt/analysis/passes/BankingAnalysisPass.kt`
**Function:** `buildCodeUnits()` (line ~113)
**Change:** Added `.filter { it.estimatedBytes > 0 }` at the end of the map chain

```kotlin
// BEFORE
game.scenes.map { scene ->
    val opCount = scene.enterOps.size + scene.frameOps.size + scene.exitOps.size
    CodeUnit(id = scene.id, estimatedBytes = opCount * bytesPerStatement)
}

// AFTER
game.scenes
    .map { scene ->
        val opCount = scene.enterOps.size + scene.frameOps.size + scene.exitOps.size
        CodeUnit(id = scene.id, estimatedBytes = opCount * bytesPerStatement)
    }
    .filter { it.estimatedBytes > 0 } // D-10: skip zero-op scenes; they need no bank assignment
```

`findFirstFit` body is byte-identical to pre-fix version — the bin-packer is pure; the fix is at the input boundary.

## New Test Cases

### BankingAnalysisPassTest.kt — zero-op scene test (RED/GREEN)

Added adjacent to existing "single scene fits in bank 1" test:
```kotlin
@Test
fun `single scene with zero ops gets no bank assignment (ROM_ONLY stays bank 0)`() {
    val scene = sceneWithOps("play", 0)  // zero ops → zero bytes
    val game = GameIR(name = "SimplePhysicsLike", scenes = listOf(scene))
    val result = pass.run(makeContext(game, maxBanks = 2))
    assertIs<PassResult.Success>(result)
    val slot = result.context.bankAssignments["play"]
    assertTrue(slot == null || slot.bank == 0,
        "Per D-10: zero-op scene must NOT receive a bank-1+ slot (causes spurious MBC5 upgrade). Got slot=$slot")
}
```

## Pre-Existing Build Failures (D-04 Triage)

Three examples fail with SDCC error 91 ("extern definition mismatches with declaration") for RPG character stat variables (`_char_*_hp`, `_char_*_sp`, `_char_*_atk`, etc.). These are pre-existing failures unrelated to this plan's changes:

- Root cause: SDCC type mismatch between `game.h` extern declarations and `main.c` definitions for character stats (likely a `UINT8` vs `INT8` or `UINT16` mismatch in the RPG genre codegen)
- Affected: dungeon, explorer, rpg-lite (all use `gbkt-genre-rpg`)
- These failures existed before this plan; confirmed by checking that the same error appears in other non-genre-rpg examples' base behavior is unaffected

**Action:** Logged to `deferred-items.md` in this phase directory for future RPG codegen fix phase.
