# Phase 06.8 Plan 03: Multi-Currency System Summary

Multi-currency system for `gbkt-genre-rpg` using type-safe `CurrencyRef` objects, `CurrencyBuilder` delegate pattern, merchant/monster-drop integration, and GBDK codegen emitting per-currency globals and arithmetic helpers with PO localization key comments.

## What Was Built

### Task 1: CurrencyDef Domain Types, CurrencyBuilder, DSL Tests (committed in plan 05)

**Files created/modified:**
- `CurrencyDef.kt` — `CurrencyDef(id, max=9999, exchanges)`, `CurrencyExchange(toId, rate)`, `CurrencyRef(id)` data classes
- `CurrencyBuilder.kt` — `CurrencyBuilder(id)` with `max(Int)` and `exchange(to: CurrencyRef, rate: Int)`; `CurrencyDelegate` with `provideDelegate`
- `RpgExtensions.kt` — `GameBuilder.currency(id, block)` and `GameBuilder.currency(block): CurrencyDelegate` extensions
- `CurrencyTest.kt` — 8 DSL tests: registration, multiple coexistence, exchange rates, CurrencyRef equality, monster drops, merchant per-item currency, backward compat, default max=9999

**Critical discovery:** Kotlin's `provideDelegate` pattern works ONLY for class-level properties, not local `val` inside lambdas. Tests use explicit-ID form `currency("gold") { max(9999) }` instead.

### Task 2: MerchantDef/MonsterDef per-item/per-drop Currency (committed in plan 05)

**Files modified:**
- `MonsterDef.kt` — `DropEntry` gains `currencyRef: CurrencyRef?` and `amount: Int` fields (backward-compatible defaults)
- `MerchantDef.kt` — `ShopItem` gains `currencyRef: CurrencyRef?`; `MerchantDef` gains `currencyRef: CurrencyRef?` alongside legacy `currencyName: String = "Gold"`
- `MonsterBuilder.kt` — `DropListBuilder.dropCurrency(currency: CurrencyRef, amount: Int, chance: Int = 100)`
- `MerchantBuilder.kt` — `ShopItemBuilder.currency(ref: CurrencyRef)` and `MerchantBuilder.currency(ref: CurrencyRef)` overloads

### Task 3: Multi-Currency Codegen (this session)

**Files modified:**
- `RpgVisitor.kt` — `generateCurrencyFunctions(system)` emitting `add_{id}(UINT16 amount)`, `sub_{id}(UINT16 amount)`, `exchange_{from}_{to}(UINT16 amount)` C functions; `generateCurrencyVarDecls(system)` emitting `_currency_{id}` and `_currency_{id}_max` globals; PO localization comment marker `str_currency_{id}` in `add_{id}` body
- `GBDKSystemVisitor.kt` — `"rpg_currency" -> RpgVisitor(gameIR).generateCurrencyFunctions(system)` dispatch
- `GBDKPipelineV2.kt` — `generateCurrencyVarDecls()` wired in `buildSystemGlobalVars()` GenericSystem block
- `RpgCodegenTest.kt` — 3 codegen tests: per-currency globals/functions, exchange function generation, PO localization key comment

**Generated C example (gold currency, max 9999):**
```c
UINT16 _currency_gold = 0;
const UINT16 _currency_gold_max = 9999;

void add_gold(UINT16 amount) {
    // str_currency_gold — PO localization key for currency display name
    _currency_gold += amount;
    if (_currency_gold > 9999) { _currency_gold = 9999; }
}

void sub_gold(UINT16 amount) {
    if (_currency_gold >= amount) { _currency_gold -= amount; }
    else { _currency_gold = 0; }
}

// (when exchange rate defined: 1 gem = 100 gold)
void exchange_gems_gold(UINT16 amount) {
    sub_gems(amount);
    add_gold(amount * 100);
}
```

### Auto-fixed Issues

**1. [Rule 1 - Bug] Currency tests inside wrong class**

- **Found during:** Task 3
- **Issue:** `Edit` appended currency tests inside `ActionRpgCodegenTest` class (end of file) instead of `RpgCodegenTest`. The Kotlin compiler compiled them into `ActionRpgCodegenTest.class`, so `RpgCodegenTest` XML results showed only 56 tests (not 59).
- **Fix:** Moved tests from `ActionRpgCodegenTest` to correct location inside `RpgCodegenTest` (before its closing `}`).
- **Files modified:** `RpgCodegenTest.kt`
- **Commit:** `8a1ee75`

**2. [Rule 3 - Blocking] Gradle incremental compilation served stale class files**

- **Found during:** Task 3 verification
- **Issue:** After editing `RpgCodegenTest.kt`, Gradle's incremental compilation cache kept reporting `compileTestKotlin UP-TO-DATE` and using stale `.class` files. Even `clean` and `--no-build-cache` didn't fix it.
- **Fix:** Removed `executionHistory.bin` to force full task re-evaluation, then used `--rerun-tasks` for reliable recompilation.
- **Impact:** No source files changed — build infrastructure deviation only.

### Delegate Pattern Constraint (Plan Design)

- **Found:** Kotlin `provideDelegate` only works for class-level properties (not `val` inside lambdas)
- **Impact:** All `CurrencyTest.kt` tests use `currency("gold") { }` instead of `val gold by currency { }`
- **Decision:** Both forms work (`currency("gold") {}` for lambda context, `val gold by currency {}` for class context). Tests cover the lambda form since that's the common use case.
