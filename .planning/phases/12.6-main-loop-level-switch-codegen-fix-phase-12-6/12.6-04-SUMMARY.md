## Property-name capture mechanism (Project Rule #1)

The delegate's `provideDelegate(thisRef, property: KProperty<*>)` operator
captures `property.name` as the scene id without requiring any explicit
string parameter from the user:

```kotlin
operator fun provideDelegate(
    thisRef: Any?,
    property: KProperty<*>,
): ReadOnlyProperty<Any?, SceneRef> {
    val gb = GameBuilderContext.current
        ?: error("levelCardScene {} must be called inside a game {} block")
    val builder = LevelCardSceneBuilder(property.name).apply(block)
    ref = builder.materialize(gb)
    return this
}
```

`property.name` is `"nextLevelScene"` when the user writes `val nextLevelScene by levelCardScene { ... }`.
The lowercased form `"nextlevelscene"` matches the widened gate landed by Plan 12.6-02
(`lower.contains("nextlevel")`), so the main-loop substrate continues to
emit SCENE_NEXTLEVEL references.

## Decisions Made

- **Reuse `gb.scene(name) { ... }` instead of introducing a new IR node.** The
  card-scene lifecycle is fully expressible as a regular scene with a
  `frame { whenever(buttons.start.pressed) { cEmit("setup_current_level();"); navigate(gameplay) } }`
  body. Adding an IR node would force changes across `gbkt-ir`,
  `ExprVisitorI`/`ScriptOpVisitorI`, and every backend — out of scope for
  a DSL-tier fix.
- **Hoist `sceneBuilderBlocks` into a local val before entering the inner
  `gb.scene { ... }` lambda.** Required because `SceneBuilder` is annotated
  `@GbktDsl`, which forbids implicit outer-receiver lookups across DSL
  scopes. Without this, the compiler errors with `'val sceneBuilderBlocks ...'
  cannot be called in this context with an implicit receiver`.
- **Omit PLAN's optional Test 4 (outside-game-block error path).** The
  factory function `fun GameBuilder.levelCardScene(...)` is a typed
  extension on `GameBuilder`. Without a `GameBuilder` receiver, the factory
  cannot be referenced at all — the Kotlin COMPILER raises a
  receiver-mismatch error, which is a stronger guarantee than a runtime
  error. PLAN acceptance criteria explicitly accept this (12.6-04-PLAN.md:171).

## Issues Encountered

- **@GbktDsl scope error on `sceneBuilderBlocks`.** First compile attempt
  of `LevelCardSceneBuilder.materialize` failed with the
  `cannot be called in this context with an implicit receiver` error. Root
  cause: `SceneBuilder` is annotated `@GbktDsl` (a `@DslMarker`), which
  blocks implicit outer-receiver lookups across DSL scopes. Resolution:
  hoist `sceneBuilderBlocks` into a `val userBlocks` local before entering
  the inner lambda — no behavioral change, just a 1-line addition with an
  explanatory comment.
