# Phase 12.6 Plan 07: Platformer-template migration + anchor-5 tighten + UAT re-shoot Summary

delegate + zone-level spawn), tightens anchor5LevelSwitch assertions, and
re-shoots anchor-5 evidence. Originally a 3-task plan; the human-verify gate

### Task 2 — Tighten anchor5LevelSwitch + re-shoot evidence (commit b98f8595)

### Debug Cycle 1 — RC-A camera reset (commit baea851b)

- Root cause: `setup_current_level()` reset `_playerX`/`_playerY` but not
  `_camera_x`/`_old_camera_x`. After level switch, player spawned at x=40px
  but camera retained level-1 scroll value (113), producing screen_x = -73
  (off-screen). Reference `main.c:63` does `camera_x = 0`.
- Fix: emit `_camera_x = 0; _old_camera_x = 0;` in every switch case of
  `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded()`.
- JVM regression: new D-07 assertion in `LevelSwitchEmissionTest`.
- Verification: MCP frame 1208 shows `_camera_x=0`, player sprite visible on-screen.

### Debug Cycle 2 — RC-B card draw (commit d3672ebd)

- Root cause: `LevelCardSceneBuilder.materialize()` did not synthesize the
  card-draw sequence. The Cycle 1 attempt `move_bkg(0u, 0u)` only zeroed BG
  scroll; the actual card art was never painted.
- Investigation revealed the SceneBuilder.zone() lowering does not emit
  set_bkg_data/set_bkg_tiles for level-card-style scenes — the materialize()
  helper must synthesize the GBDK ShowCentered() equivalent itself.
- Fix: append an `enter` block in materialize() emitting
  `hide_sprites_range(0u, MAX_HARDWARE_SPRITES); fill_bkg_rect(0u, 0u, DEVICE_SCREEN_WIDTH, DEVICE_SCREEN_HEIGHT, 0u); _bkg_tiles_load_banked(2u, (20-W)/2, (18-H)/2, W, H, tilemap); DISPLAY_ON;`.
- Failed attempt rolled back: direct `SWITCH_ROM(2u)` from BANKED bank-1 code
  hangs the GB; reverted to the safer HOME-bank helper that wraps SWITCH_ROM.
- Verification: MCP frame 1150 shows `current_scene=nextLevelScene`,
  `sprites=[]`, bgText with centered card glyphs at rows 7-9 — byte-identical
  to the reference's frame-1139 pattern.

### Debug Cycle 3 — RC-C tilemap wraparound (commit b06bf4d1)

- Root cause: setup_current_level emitted
  `_bkg_tiles_load_banked(2u, 0u, 0u, ZONE_WIDTH, ZONE_HEIGHT, tilemap)`
  with ZONE_WIDTH=60. GBDK's `set_bkg_tiles` wraps at the 32-cell BG map
  boundary, so columns 32..59 overwrote columns 0..27 — producing the
  level-1-leftover chimera the user observed.
- Reference uses `SetCurrentLevelSubmap(0, 0, DEVICE_SCREEN_WIDTH+1, DEVICE_SCREEN_HEIGHT)` =
  21x18 cells, no wrap because 21 < 32.
- Fix: swap the wide-write for
  `_bkg_set_level_submap_banked(0u, 0u, 21u, 18u)` — reuses the existing
  HOME-bank helper that was already wired by `platformer_camera_update` for
  column-scroll. Internally calls `set_bkg_submap` with a stride argument so
  no wrap occurs.
- JVM regression: new D-08 assertion in `LevelSwitchEmissionTest` (positive
  shape + forbidden old shape + per-case count).
- Verification: MCP frame 1233 shows level-2 bgText byte-identical to
  reference world1-area2 first-screen (no `&'`/`./`/`0`/`67676767` patterns
  from level 1).

- Player metasprite eye area renders with inverted palette.

Root family: `ConvertSpritesTask` / `ConvertZoneTilesetsTask` (gbkt-gradle-plugin)
palette index mapping when targeting GBC_COMPATIBLE running on DMG. Routes
to NEW Phase 12.9 (`palette-inversion-asset-pipeline`).

  not post-enter — caused Cycle 2's false `RESOLVED` verdict.

  D-08 windowed-write fix reduced wraparound-induced walking-right BG variation

  (human-verify) is the primary closure signal — proceed to checkpoint for
  duck-art approval`. Soft gate, threshold retune needed.

Both route to NEW Phase 12.10 (`uat-test-harness-capture-timing`).
