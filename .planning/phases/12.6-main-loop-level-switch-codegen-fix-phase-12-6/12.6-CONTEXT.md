# Phase 12.6: main-loop-level-switch-codegen-fix - Context

**Gathered:** 2026-05-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 12.6 is a **terminal, narrowly-scoped codegen fix** for the two main()-loop
level-switch defects surfaced by Plan 12-23 round-2 (commit `91d028d3`). It
closes **Gate G1** of the four Phase-12-close visual gates documented in
Plan 12-27 SUMMARY.

**In scope (DEFECT-1 + DEFECT-2 only):**

1. **DEFECT-1** — Same-frame VRAM stomp in the main-loop level-switch guard.
   `GBDKPipelineV2.buildMainLoopLevelSwitchGuardIfNeeded`
   (`gbkt-backend-gbdk/.../codegen/pipeline/GBDKPipelineV2.kt:2546–2567`)
   currently emits `navigate_to_scene(SCENE_NEXTLEVEL)` immediately followed
   by `setup_current_level()`. Both run in a single main-loop iteration with
   no vblank between them — the new level's tilemap overwrites the NextLevel
   card art before the LCD can render it. Symptom: `02-nextlevel-card.png`
   shows world1-area2 instead of the card.

2. **DEFECT-2** — `_playerX` preserved across level switch, causing same-frame
   level-end trigger re-fire. The level-end trigger in
   `PlatformerVisitor.buildPhysicsUpdateFunction`
   (`gbkt-genre-platformer/.../codegen/PlatformerVisitor.kt:1110–1126`) reads
   `player_real_x` at start-of-frame; after the level-switch the player is
   still at `_playerX=449` (right edge of level 1), so the trigger fires
   again on the first gameplay frame, advancing `_next_level` past level 2.
   Symptom: `03-level-2.png` shows world2-area1 (level 3), not world1-area2
   (level 2).

**Out of scope (routed to NEW sibling phases at 12.6 close):**

- **Gate G2** — Player metasprite levitating above tilemap floor
  (`SEED-PHASE-12-PLAYER-LEVITATING-NOT-GROUNDED`). PlatformerVisitor
  5-point AABB probe / ground-snap defect. Different module
  (`PlatformerVisitor.build5PointProbe`), different blast radius. → **NEW
  Phase 12.7** to be inserted at 12.6 close.

- **Gates G3 + G4** — Grass tilemap white-pixel render artifacts on
  world1-tileset.png (`SEED-PHASE-12-GRASS-TILEMAP-WHITE-PIXELS`) +
  conditional anchor-1 re-verify after G3. png2asset / palette diagnostic
  on `ConvertZoneTilesetsTask`. Different module entirely
  (`gbkt-gradle-plugin`). → **NEW Phase 12.8** to be inserted at 12.6 close.

**Rationale for tight scope:** Per `feedback_many_small_plans_terminal_subphase`,
sub-phases must close their defect cluster in one shot (no 12.6.1 follow-ups).
Per `feedback_route_to_proper_phase_when_blast_radius_is_wide`, three
independent defect clusters spanning three codegen modules earn three
separate phases, not one mega-phase.

**Phase 12 close gating:** `phase.complete 12` STAYS DEFERRED until G2 + G3 +
G4 also ship via sibling phases 12.7 + 12.8. Phase 12.6 closes G1 only.

  integer parent `12` (NOT `12.6`) so the new phases land as siblings 12.7
  and 12.8, not as 12.6.1 / 12.6.2.

### DEFECT-1 fix — new `levelCardScene()` DSL helper

- **D-02:** Fix shape — **Hybrid (Option A + dedicated lifecycle helper)**.
  Remove `setup_current_level()` from the main-loop guard so the guard emits
  ONLY `navigate_to_scene(SCENE_NEXTLEVEL)`. Introduce a new platformer-genre
  DSL helper that owns the card-show → wait-for-Start → setup_current_level
  → navigate-to-gameplay lifecycle. This is the reference behavior in
  `platformer_template/src/player.c:44–82`.

- **D-03:** Helper shape — **Scene-block helper** in
  `gbkt-genre-platformer/src/main/kotlin/io/github/gbkt/genre/platformer/dsl/PlatformerExtensions.kt`.
  Surface: `val nextLevelScene by levelCardScene { showText(...); onStartPress(gameplayScene) }`
  (delegate pattern — no magic string ID per Project Rule #1; name inferred
  from the property delegate, see established pattern for `scene()`,
  `actor()`, etc.). The helper produces a `SceneRef` and emits codegen that:
  (a) on enter — paints card visuals (no `setup_current_level` call); (b) on
  frame — listens for `buttons.start.pressed`; (c) on Start-press — calls
  `setup_current_level()` THEN `navigate_to_scene(gameplayScene)`. Card
  renders for N frames (until Start), then new-level VRAM writes happen
  IMMEDIATELY BEFORE the gameplay scene takes over — no inter-frame stomp.

- **D-04:** Main-loop guard update — `GBDKPipelineV2.buildMainLoopLevelSwitchGuardIfNeeded`
  (kt:2546–2567) returns the same `CIf(_next_level != _current_level, ...)`
  block but the `thenBody` contains ONLY the `navigate_to_scene(SCENE_NEXTLEVEL)`
  call. The `setup_current_level()` call is removed from this site.

- **D-05:** Reference accuracy gate — the new `levelCardScene` codegen must
  emit `setup_current_level()` AS A SUBSTRING reachable from the Start-press
  path; the existing emission-invariant test for `setup_current_level` (see
  `GBDKPipelineV2.kt:2536–2546` doc comments) must be re-pointed at the new
  emission site, not the guard.

### DEFECT-2 fix — per-level spawn position

- **D-06:** Fix shape — **Option A: per-level spawn position written by
  `setup_current_level()`**. Each platformer zone declares its spawn
  position; `setup_current_level()` (generated by GBDKPipelineV2) reads a
  generated `_level_spawn_x[N]` / `_level_spawn_y[N]` table inside its
  per-level `switch` cases and writes `_playerX` / `_playerY` (and
  `_playerVx = 0` / `_playerVy = 0` for safety) before returning. This fixes
  the root cause: position MUST be set by the level, not preserved across
  switches.

- **D-07:** DSL surface — `spawn(x: UByte, y: UByte)` added to existing
  `ZoneBuilder` in
  `gbkt-lang/src/main/kotlin/io/github/gbkt/core/dsl/WorldBuilders.kt:65`.
  Numeric coords only — no new magic strings. Default if omitted: a
  sensible spawn (e.g., `(16, 120)`) with a build-time warning so users
  know to declare explicitly.

- **D-08:** Per-game migration — `gbkt-examples/platformer-template/.../PlatformerTemplate.kt`
  zone declarations (`world1Area1`, `world1Area2`, `world2Area1`) gain
  `spawn(x, y)` calls. Reference values: derive from
  `/Users/michalsvacha/gbdk/examples/cross-platform/platformer_template/src/player.c:91–122`
  (the reference per-level spawn logic).

- **D-09:** Tightened regression assertion — the existing JVM-tier
  `anchor5LevelSwitch` test tightens its tolerant
  `assertVariable("_current_level", >= 1)` to
  `assertVariable("_current_level", == 1)` after the level switch (proves
  DEFECT-2 no longer re-fires the trigger same-frame).

## Deferred Ideas

### `zone(id: String)` magic-string violation — Project Rule #1 (HIGH PRIORITY)

The existing `zone(id: String, block: ZoneBuilder.() -> Unit): ZoneRef`
signature in
`gbkt-lang/src/main/kotlin/io/github/gbkt/core/dsl/GameBuilder.kt:480`
takes a magic string ID. This violates `feedback_no_magic_strings`
(Project Rule #1: "No magic strings — DSL must reflect names from property
delegates / lambda params, never duplicate as String params, unless the
string is a path to a file"). The fix is to convert to delegate-pattern
`val world1Area1 by zone { ... }` mirroring `actor()`, `scene()`, etc. via
a `ZoneDelegate.provideDelegate`.

**OUT OF SCOPE for Phase 12.6** — substrate refactor across `gbkt-lang`
(builder + delegate), `gbkt-engine` (IR Zone), every game using `zone()`
(at least: dungeon, explorer, rpg-lite, banks, racer, platformer-template,
+ test fixtures). Blast radius is wide — needs its own phase per
`feedback_route_to_proper_phase_when_blast_radius_is_wide`.

**Routing (seed already captured):** see
`.planning/seeds/SEED-ZONE-MAGIC-STRING-DELEGATE-MIGRATION.md` (created
during this discuss-phase, 2026-05-25). Routed to Phase 13
(framework-primitives-surfaced-by-example-ports-rolling) since `zone()`
is a substrate DSL primitive that Phase 13 already covers. Phase 12.6
does not act on this seed; only `spawn(x, y)` (numeric coords) is added
to the existing `ZoneBuilder` by 12.6.
