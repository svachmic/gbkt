# Phase 12.6 Plan 05: emit-per-level-spawn-tables-and-writes Summary

DEFECT-2 substrate-tier closure: extended `buildSetupCurrentLevelFunctionIfNeeded`'s per-zone
case body with four new C lines (spawn-X write, spawn-Y write, vx reset, vy reset) using the
cross-visitor symbol-resolution pattern from `PlatformerVisitor.kt:549-558`; added a new
internal method `buildLevelSpawnTablesIfNeeded(gameIR)` that emits the `_level_spawn_x[]` /
`_level_spawn_y[]` const UINT8 arrays in HOME bank gated on `gameUsesTilemapCollision`; wired
the new arrays into `buildHomeFile`'s raw-section list BEFORE the consumer function. After
this lands, every level switch writes the player to the per-level spawn position before the
first gameplay frame, so the level-end trigger no longer re-fires same-frame because
`_playerX = spawn_x[N] << 4` is far from the right-edge threshold. This closes the DEFECT-2
substrate; the levelCardScene helper (Plan 12.6-06) and platformer-template migration
(Plan 12.6-07) will land the user-facing surface and the runtime verification respectively.

## New method signature

```kotlin
internal fun buildLevelSpawnTablesIfNeeded(gameIR: GameIR): String?
```

- **Gate:** Returns `null` when `gameUsesTilemapCollision(gameIR) == false` OR when there are
  zero gameplay zones — preserves D-14 byte-identity for non-platformer games.
- **Zone filter:** Identical to the filter inside `buildSetupCurrentLevelFunctionIfNeeded`
  (excludes ids containing `title`, `nextlevel`, or `next_level`) so the array indices match
  the switch cases one-to-one.
- **Default fallback (D-07):** When a gameplay zone has `spawnX == null`, substitutes `16`
  and emits a build-time WARNING to stderr. `spawnY == null` defaults to `120` silently
  (paired sentinel — the spawnX warning covers the case). Plan 12.6-07 migrates
  platformer-template to `spawn(40u, 120u)` so the warning does not fire on the production
  path.

## Four new C lines per case (emitted with platformer-template symbols, idx=0)

```c
// Phase 12.6 D-06 — per-level spawn position (closes DEFECT-2).
// Spawn coords are pixels in the DSL; <<4 shift converts to subpixel form (mirrors
// reference SetupPlayer() at platformer_template/src/player.c:101-103). The write
// happens AFTER `_bkg_tiles_load_banked` so the order mirrors the reference's
// SetupCurrentLevel() → SetupPlayer() sequence (see Pitfall 1 in 12.6-RESEARCH.md).
// Velocity reset is part of the contract (Pitfall 3): without it, the player would
// carry level-N momentum into level-N+1, causing same-frame level-end-trigger re-fire.
_playerX = ((INT16)_level_spawn_x[0u]) << 4;
_playerY = ((INT16)_level_spawn_y[0u]) << 4;
_playerVx = 0;
_playerVy = 0;
```

In the gbkt-backend-gbdk test fixture (default `tilemap_collision` config — no rebinds), the
emitted symbols are `_player_x` / `_player_y` / `_player_vx` / `_player_vy`. The platformer-template
production path will emit `_playerX` / `_playerY` / `_playerVx` / `_playerVy` because
`PlatformerTemplate.kt` rebinds via the `tilemap_collision` system config. The hoisted
symbol-resolution block (mirroring `PlatformerVisitor.kt:549-558`) makes the codegen pick up
either binding without further change.

## Wiring sequence in buildHomeFile (line 1217-1234)

Order matters: the arrays are forward-declarations the `setup_current_level()` function
reads, so they must appear FIRST in main.c.
