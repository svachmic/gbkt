<domain>
## Phase Boundary

Remove the delegate-ceremony tax and the hand-rolled variable/frame-logic
patterns surfaced by the four reference-port audits. This is the **second**
sub-phase of the 13.x family and the one that unblocks the rest — Req #12 ships
first because it deletes the `@Suppress` ceremony every later sub-phase's
call-site migration would otherwise have to carry.

**Owns exactly five requirements (full citations in ROADMAP.md §"Phase 13"
catalog) + one carried-in review item:**
- **Req #12** — delegate-unused-warning fix for `val/var by …` (ships first).
- **Req #2** — single-frame `if` / `unless` conditional primitive (replaces
  nested `whenever` used as a clamp).
- **Req #3** — fixed-point sub-pixel abstraction (`i16FixedVar` / `subpixel { }`)
  hiding the manual `shr 4` and the magic `1024` / `shl 4`.
- **Req #8** — `damp()` / `easeToZero()` decay primitive (replaces the
  ease-toward-zero ladder).
- **Req #9** — wrap/cycle primitive for `u8Var` / `i8Var` (replaces hand-rolled
  modulo / `& 0xF` wrap and makes the Pitfall-6 folklore unrepresentable).
- **WR-06 (carried-in from 13.1 code review)** — `SaveDataDelegate` single-use
  guard. Folded here because it lives on the same delegate surface as the Req #12
  fix; auto-closes when 13.2 completes (`resolves_phase: 13.2`).

**Out of scope (explicit):**
- WR-07 ref-registry validation (typed-ref validation, NOT delegate ergonomics) —
  stays a standalone todo for a future ref-resolution phase (per ROADMAP).
- Full `whenever` → `runIf` replacement sweep — only nested single-frame sites
  migrate this phase; the broader unification is tracked as a Tier-3 follow-up
  (see Deferred Ideas), not done here.
- Any DSL change NOT surfaced by the four reference-port audits (simple-physics,
  metasprites, banks, platformer-template).
- Metasprite/sprite/color (Req #4-7 → 13.3), zone/scene (Req #10/13/14 → 13.4),
  graphics/level codegen (Req #15/17/18 → 13.5).

**Sequencing constraint:** Req #12 (+ WR-06, same delegate surface) lands before
the variable/control-flow primitives, so the new `i16FixedVar` / `u8Var(wrapAt=)`
declarations and migrated call sites never re-introduce `@Suppress` ceremony.

<decisions>
## Implementation Decisions

### Req #12 — delegate-unused-warning fix
- **D-01:** **Zero call-site ceremony is the target.** An author writes
  `var x by u8Var(0)` with NO annotation at all. The fix is mechanism-based
  (e.g. `provideDelegate` return shape / an idiom the compiler treats as used,
  or a compiler-plugin-free equivalent — researcher determines feasibility).
- **D-02 (fallback, bounded):** If Kotlin genuinely cannot suppress a never-read
  *local-property* warning purely via the delegate mechanism, the accepted
  fallback is **ONE `@file:Suppress("UNUSED_VARIABLE")` per example file** —
  **never per-site**. The success-criterion "zero `@Suppress` annotations on
  delegate-bound properties" is interpreted as *zero per-site* suppress on
  delegate properties; a single file-level suppress is the sanctioned escape
  hatch only if the mechanism path fails.
- **D-03:** This fix removes the **temporary `@Suppress` D-09 introduced in
  Phase 13.1** on the `by saveData { }` delegate, plus the 16 instances in
  `PlatformerTemplate.kt`, 2 in `Banks.kt`, and any others on delegate-bound
  properties across the examples.

### WR-06 — SaveDataDelegate single-use guard (carried-in)
- **D-04:** **Uniform single-use guard across ALL delegate types**, not just
  `SaveDataDelegate`. Since Req #12 reworks the shared delegate surface, add the
  "throw if `provideDelegate` is called a second time on the same delegate
  instance" guard to the shared `VarDelegate` base + every delegate type
  (Var/Array/Save/Metasprite/Actor/etc. as applicable). Misuse (delegate-instance
  reuse → silent double-registration) fails loudly at build time everywhere.
- **D-05:** Document each delegate instance as single-use (KDoc on the base /
  factory functions). This satisfies the carried-in success criterion
  ("`SaveDataDelegate` fails loudly on misuse … a second `provideDelegate`
  throws") generalised to the whole surface.

### Req #2 — single-frame if / unless
- **D-06:** User-facing names are **`runIf(cond) { }` / `unless(cond) { }` /
  chained `.orElse { }`**. No bare `if` (Kotlin-reserved) and no backticked
  `` `if` `` (ugly source). These **alias/rename the existing internal
  `ifOp` / `elseOp`** in `ScriptBuilder` — same `IfOp` lowering, new ergonomic
  names.
- **D-07:** **`whenever` coexists** and is NOT `@Deprecated` this phase. It stays
  the idiom for top-level reactive triggers (its pervasive current use across all
  8 examples). A literal `@Deprecated` would flood the many un-migrated, legit
  reactive sites with warnings — directly fighting this phase's clean-build /
  zero-ceremony gate. Instead the "don't forget" durability is provided by a
  Tier-3 roadmap follow-up + pending todo (see Deferred) **and** a KDoc signpost
  on `whenever` steering authors to `runIf` for single-frame logic.
- **D-08:** Migration scope for Req #2 = **nested single-frame `whenever` sites
  only** (e.g. `SimplePhysics.kt:93-120` inner clamps). Non-nested top-level
  `whenever` calls are left as-is.

### Req #3 — fixed-point sub-pixel
- **D-09:** **Ship both forms** — the declarative type `i16FixedVar` (delegate,
  parallel to `i16Var`) AND the `subpixel { }` scope block. The **declarative
  type is the primary migration form** (it's what the simple-physics oracle
  migrates to); `subpixel { }` is the alternative for grouped arithmetic.
- **D-10:** **Fractional bits are configurable, default 4** (e.g.
  `i16FixedVar(initialPixels, fractionalBits = 4)`). 12.4 is the default and the
  only format any current example uses. The configurable knob future-proofs other
  fixed-point ratios but the **default-4 path is the one all examples migrate to**.
- **D-11:** **Construct in whole pixels, extract via `.toPixel()`.**
  `i16FixedVar(80)` hides the `shl 4`; `posX.toPixel()` returns an `Expr` for
  `ball.moveTo(posX.toPixel(), posY.toPixel())`. No shift literal (`shl 4` /
  `shr 4`) and no magic `1024` ever leak into user code. (`moveTo` is NOT taught
  to auto-convert a fixed ref — explicit `.toPixel()` keeps the conversion
  visible.)
- **D-12 (hard constraint, not a re-decision):** simple-physics is the **codegen
  oracle** — `SimplePhysicsEmissionTest` pins the generated C shape. The
  default-4 `i16FixedVar` path MUST lower to **byte-identical** C: same int16
  `posX += spdX` integration, same `>> 4` pixel extraction. Any shape divergence
  fails the oracle. Verify via clean `:gbkt-examples:simple-physics:buildRom` +
  the emission test (per CLAUDE.md ROM-build smoke-test rule).

### Req #8 — decay primitive
- **D-13:** Canonical form is the **method `v.easeToZero(by = 1)`** on the
  variable; `by` (per-frame decay step) defaults to 1 (the only value used today).
  Lowers to the same two-branch ladder
  (`if v < 0 → v++` / `if v > 0 → v--`) — same generated C. Reads as an operation
  on the variable, IDE-discoverable. (No separate free-fn `damp()` alias unless
  the planner finds a strong reason; the method is the single canonical surface.)

### Req #9 — wrap / cycle primitive
- **D-14:** **Declarative type param** — `var idx by u8Var(0, wrapAt = N)`. The
  wrap invariant lives in the variable's declaration; mutations auto-wrap, making
  out-of-wrap states unrepresentable (subsumes the Pitfall-6 `u8Var`-not-`i8Var`
  folklore). ROADMAP-preferred and consistent with the 13.1 declarative
  precedent. Not the fluent `.cycle(N)` form (invariant wouldn't be in the type;
  author could forget to call it).
- **D-15:** **Single smart `wrapAt = N` param** covering both current flavors.
  Codegen auto-selects: emit `& (N-1)` when N is a power of two (matches `rot`'s
  `and 0xF` byte-for-byte) else compare-reset `if v >= N → v = 0` (matches
  `idx`'s current `whenever(idx isAtLeast NUM_FRAMES){ idx set 0 }` C). One
  concept; the mask-vs-modulo distinction is hidden.
- **D-16 (researcher must verify):** "Mutations auto-wrap" — the wrap guard is
  emitted after mutating ops on the wrapped var. Researcher confirms the
  generated-C shape stays **same-or-smaller** vs the hand-rolled per-frame wrap
  (the SC bar). Primary migration targets (`idx`, `rot` in Metasprites.kt) are
  `u8Var`; `i8Var` wrap semantics are the researcher's call but no current call
  site needs them.

### Migration / deprecation policy (cross-cutting)
- **D-17:** **Hard-replace, no `@Deprecated` aliases** for the new primitives —
  same precedent as Phase 13.1 D-11. The "old forms" for #3/#8/#9 are hand-rolled
  *patterns* (raw `i16Var` + `shl 4`, manual decay ladders, manual wrap), not
  deprecatable DSL functions, so migration = rewrite the example call sites and
  delete the `PHASE-13` markers. The ONE deliberate exception is `whenever`
  (D-07): kept un-deprecated and tracked via roadmap/todo, not a code annotation.
- **D-18:** Migration sweep covers the four audited reference ports
  (simple-physics, metasprites, banks, platformer-template) plus any other active
  example carrying the relevant patterns or delegate-bound `@Suppress`. Per-req:
  #12/WR-06 → all delegate-bound `@Suppress` sites; #2 → nested-whenever clamp
  sites; #3 → simple-physics + platformer-template subpixel sites; #8 →
  metasprites + simple-physics decay ladders; #9 → metasprites `idx`/`rot`.
  Regression sweep targets (per ROADMAP): pong, breakout, simple-physics,
  metasprites, metasprites-stress, banks, racer.
- **D-19:** New primitives documented in **DSL_REFERENCE.md** with worked
  examples (success criterion).

### Claude's Discretion
- The exact Kotlin mechanism for D-01 (zero-ceremony unused-warning suppression)
  vs the D-02 file-level fallback — researcher/planner pick based on what the
  Kotlin compiler actually permits for never-read local delegated properties.
- Whether `subpixel { }` (D-09) shares the configurable-bits config of the
  `i16FixedVar` type or carries its own — researcher decides the interplay.
- Whether a free-fn `damp()` alias is worth shipping alongside
  `easeToZero()` (D-13) — default is method-only.
- Exact codegen mechanism for the smart `wrapAt` power-of-two detection (D-15)
  and the auto-wrap emission point (D-16).

### Folded Todos
- **`savedatadelegate-single-use-guard` (WR-06)** — carried-in from
  `13.1-REVIEW.md`; `resolves_phase: 13.2`. `SaveDataDelegate` stored its `ref`
  as a nullable populated in `provideDelegate`; reusing one instance across two
  `val`s double-registers under the last property name and silently drops the
  first. **Fit:** generalised in D-04/D-05 to a uniform single-use guard across
  all delegates (same surface as the Req #12 rework). Auto-closes on phase
  completion.

<code_context>
## Existing Code Insights

### Reusable Assets
- **`VarDelegate` base class** (`VariableBuilders.kt:346`): single
  `provideDelegate` + `getValue`/`setValue` shared by all four numeric delegate
  types. Adding the WR-06 single-use guard (D-04) and the Req #9 `wrapAt` plumbing
  here propagates to every delegate at once. `i16FixedVar` (D-09) is a new
  subclass parallel to `I16VarDelegate`.
- **`ifOp` / `elseOp` in `ScriptBuilder`** (`ScriptBuilder.kt:140-160`): the
  single-frame conditional ALREADY EXISTS and lowers to `IfOp`. Req #2 is
  primarily an ergonomic rename/alias (`runIf`/`unless`/`.orElse`) + a `whenever`
  KDoc signpost — not a new codegen path.
- **`whenever`** (`ScriptBuilder.kt:197`): a one-armed `IfOp`; identical lowering
  to a single-armed `runIf`. Confirms #2 is naming/surfacing, not new behavior.
- **`ActorRef.moveTo(Expr, Expr)`** (Phase 9.1 / SEED-002): already accepts an
  `Expr`, so `ball.moveTo(posX.toPixel(), posY.toPixel())` (D-11) needs only the
  `.toPixel()` Expr accessor, not a new `moveTo` overload.

### Established Patterns
- **Delegate side-effect registration via `GameBuilderContext` thread-local**
  (`VariableBuilders.kt:359-370`): `provideDelegate` registers the `VariableDef`
  as a side effect and returns `this`. The unused-warning (Req #12) arises
  because the resulting local property is never read — the warning is about the
  property name, NOT the delegate internals (informs D-01 feasibility analysis).
- **`MetaspriteDelegate` / `ActorDelegate` name-from-property inference**: same
  `provideDelegate` idiom; any uniform guard (D-04) must respect their existing
  contracts.
- **12.4 fixed-point convention** (`SimplePhysics.kt` / its CLAUDE.md): high 12
  bits = pixel, low 4 = sub-pixel; `shr 4` extracts pixel; `1024` = 64px×16. The
  default-4 `i16FixedVar` (D-10) encodes exactly this.

### Integration Points
- DSL delegates/builders (`VariableBuilders`, `ScriptBuilder`) → IR
  (`IfOp`, `VariableDef`, i16 ops) → GBDK codegen → all migrated example call
  sites → emission tests (`SimplePhysicsEmissionTest`) + regression ROM builds.
- The new primitives must reuse the existing `i16Var` / `IfOp` lowering so
  generated C is byte-identical (D-12) or smaller — no new codegen branches that
  change the C shape.

<specifics>
## Specific Ideas

- "Zero ceremony" for Req #12 is the explicit bar — the delegate exists to remove
  ceremony, so the fix must not add a new annotation at the call site. A single
  per-file suppress is the only sanctioned fallback (D-01/D-02).
- The user wants `whenever` kept but flagged for a future unification — durability
  via a tracked roadmap/todo item, NOT a noisy `@Deprecated` that would fight the
  clean-build gate (D-07).
- The user wants the wrap invariant in the *type* (`u8Var(wrapAt=N)`), and a
  single smart `wrapAt` that hides whether the lowering is a mask or a
  compare-reset (D-14/D-15).
- Sub-pixel: construct in pixels, never expose `shl 4`/`shr 4`/`1024`; explicit
  `.toPixel()` keeps the conversion visible rather than auto-magic in `moveTo`
  (D-11).

</specifics>
