Required emission (verbatim from reference, parameterized by metaspriteId):
```c
{
    uint8_t hiwater = 0u;
    uint8_t subpal = _rot >> 2;
    switch (_rot & 0x3u) {
        case 1:
            hiwater += move_metasprite_flipy(sprite_metasprites[_idx], 0, subpal, hiwater,
                                              DEVICE_SPRITE_PX_OFFSET_X + (_posX >> 4),
                                              DEVICE_SPRITE_PX_OFFSET_Y + (_posY >> 4));
            break;
        case 2:
            hiwater += move_metasprite_flipxy(sprite_metasprites[_idx], 0, subpal, hiwater,
                                              DEVICE_SPRITE_PX_OFFSET_X + (_posX >> 4),
                                              DEVICE_SPRITE_PX_OFFSET_Y + (_posY >> 4));
            break;
        case 3:
            hiwater += move_metasprite_flipx(sprite_metasprites[_idx], 0, subpal, hiwater,
                                              DEVICE_SPRITE_PX_OFFSET_X + (_posX >> 4),
                                              DEVICE_SPRITE_PX_OFFSET_Y + (_posY >> 4));
            break;
        default:
            hiwater += move_metasprite_ex(sprite_metasprites[_idx], 0, subpal, hiwater,
                                          DEVICE_SPRITE_PX_OFFSET_X + (_posX >> 4),
                                          DEVICE_SPRITE_PX_OFFSET_Y + (_posY >> 4));
            break;
    }
    hide_sprites_range(hiwater, MAX_HARDWARE_SPRITES);
}
```

CRITICAL ID-resolution decision: the variable names referenced in the switch (`_rot`, `_idx`, `_posX`, `_posY`) are USER-DEFINED in the port assembly (Plan 13). The visitor must use the variable names the port declares. Two viable approaches:
(a) Hardcode names `_rot`, `_idx`, `_posX`, `_posY` and require the port to use those exact names (constrains the port — acceptable for Phase 10 since reference uses those exact names).
(b) Look up by convention — `_${metaspriteId}_idx`, `_${metaspriteId}_rot`, etc. (more general but the port assembly must conform).
Recommendation: approach (a) for Phase 10 — the port assembly (Plan 13) declares variables with the canonical names `idx`, `rot`, `posX`, `posY` (lowering to `_idx`, `_rot`, `_posX`, `_posY`). Document the constraint in the visitor's KDoc.

Use `CRawCode(...)` for the entire block — typed C AST does not have native switch-with-arbitrary-rhs support that beats raw emission, and the literal-emission convention is for individual literal nodes, not for fully-formed C blocks. Note Phase 07.9 convention still applies for any standalone `CLiteral` outputs.
