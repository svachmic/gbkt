## Warnings

### WR-01: `CIntLiteral(0)` used for UINT8 `groundedSym` comparison — deviates from Phase 07.9 convention without a comment at the new call site

**File:** `gbkt-genre-platformer/src/main/kotlin/io/github/gbkt/genre/platformer/codegen/PlatformerVisitor.kt:1222`

**Issue:** The H3 fix emits `CBinaryExpr(CVar(groundedSym), "!=", CIntLiteral(0))`. Per the Phase 07.9 Literal Emission Convention (`gbkt-backend-gbdk/CLAUDE.md` §"Literal Emission Convention"), `CIntLiteral` is reserved for signed-context comparisons (INT8/INT16 LHS). `groundedSym` resolves to a UINT8 variable (`_grounded` initialized via `CLiteral(0)` at line 172, set to `CLiteral(1)` at line 1381). The correct choice for a UINT8 comparison RHS is `CLiteral(0)` (emits `0u`), not `CIntLiteral(0)` (emits bare `0`).

The existing code at lines 1028 and 1090 makes the same choice (`CIntLiteral(0)` for `groundedSym`) and is justified by a local-scope convention comment at lines 1075-1081: "UINT8 actually permits CLiteral, but matching the local-scope convention keeps the tilemap-physics branch internally consistent." However, the new H3 fix at line 1222 adds a **third** such site without citing this rationale. A reader scanning the fix diff sees `CIntLiteral(0)` for a UINT8 operand with no visible justification.

Functionally, `_grounded != 0` and `_grounded != 0u` produce identical code in SDCC for a UINT8 operand (both branches are unsigned-context, so the literal suffix does not change promotion behavior). This is NOT a runtime bug. But the omission of a justifying comment at the new call site is a maintainability hazard: a future auditor may flag it as a Phase 07.9 violation and "fix" it to `CLiteral(0)`, creating a spurious diff. It also prevents the established audit (`07.9-AUDIT.md`) from being mechanically complete.

**Fix:** Either (a) add a comment at line 1222 mirroring the one at lines 1075-1081, or (b) change to `CLiteral(0)` to match the convention. Option (a) preserves the existing local-scope discipline; option (b) strictly follows Phase 07.9.

Option (a) — preferred (keeps lines 1028, 1090, and 1222 consistent under the same documented exception):
```kotlin
// groundedSym is UINT8; CIntLiteral(0) is used (not CLiteral) to match the
// local-scope convention at lines 1028+1090 (per comment at lines 1075-1081).
CBinaryExpr(
    CVar(groundedSym),
    "!=",
    CIntLiteral(0),  // see lines 1075-1081 for convention rationale
),
```

Option (b) — strictly Phase 07.9 compliant:
```kotlin
CBinaryExpr(
    CVar(groundedSym),
    "!=",
    CLiteral(0),  // UINT8 unsigned-context — emits 0u per Phase 07.9 convention
),
```

## Info

### IN-01: Test `EVIDENCE_DIR` companion `val` is eagerly initialized at class-load time

**File:** `gbkt-genre-platformer/src/test/kotlin/io/github/gbkt/genre/platformer/codegen/LevelEndTriggerGroundedGuardEmissionTest.kt:79-85`

**Issue:** `EVIDENCE_DIR` is declared as a plain `val` in the `companion object`, so the `File(System.getProperty("user.dir")).resolve(...)` chain executes at class-load time regardless of whether the test actually runs. In the common case this is harmless, but it means `user.dir` is captured before the JUnit test runner can override the working directory. If the test is run in a context where `user.dir` differs from `<repo-root>/gbkt-genre-platformer` (e.g., IDE run configurations that set the project root as `user.dir`), the evidence path would be miscalculated at class-load time with no warning.

The sibling test `PlatformerPhysicsSnapToTileTopEmissionTest` uses the same pattern (line 100-105), so this is an established project convention — not a new defect introduced by this change. The finding is informational.

**Fix:** Convert to a `val` with `by lazy { ... }` delegate to defer resolution until first access (when the test method body runs, guaranteeing `user.dir` is stabilized by the runner). This is consistent with how the sibling test is expected to behave.
```kotlin
val EVIDENCE_DIR by lazy {
    File(System.getProperty("user.dir"))
        .resolve("../.planning/phases/12.7-player-levitating-physics-codegen/evidence/tier1-shape")
        .normalize()
}
```

### IN-02: Trigger-region walk has no guard for the case where the CIf is emitted with no braces (single-statement form)

**File:** `gbkt-genre-platformer/src/test/kotlin/io/github/gbkt/genre/platformer/codegen/LevelEndTriggerGroundedGuardEmissionTest.kt:244-258`

**Issue:** The forward-walk loop that bounds the trigger CIf region relies on brace counting (`{` increments `depth`, `}` decrements). If the CEmitter were ever to emit the thenBody without braces (bare single-statement form, e.g., `if (...) ++_next_level;`), `started` would never be set to true and the loop would run to the end of `snapshotLines` — collecting all remaining lines from the comment to the end of the extracted function body rather than just the trigger block. The `_grounded` primary assertion would still pass (the token would be present somewhere), but the `++_next_level` regression-guard assertion would also pass, masking a potential emit-shape regression.

In practice `CEmitter.emitStatement` always wraps `CIf.thenBody` in braces (the emitter always emits `{ ... }`) — so this scenario cannot currently occur. The finding is informational.

**Fix:** Add an assertion after the walk that `started` is true, guaranteeing a brace was found and the region is bounded:
```kotlin
assertTrue(
    started,
    "Level-end trigger CIf region must contain at least one `{` — " +
        "expected braced thenBody from CEmitter. triggerRegionStr:\n$triggerRegionStr"
)
```
