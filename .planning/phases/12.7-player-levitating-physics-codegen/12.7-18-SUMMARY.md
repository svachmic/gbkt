## Decisions Made

- **Three assertions, not one compound check.** The `<action>` Step 3 listed three sub-checks (name, value, final-shift). Splitting them into three separate `assertTrue` calls (R5a, R5b, R5c) instead of a single compound expression gives W13's debugger named failure modes. When W13 emits the fix, R5a flips first (name appears in the snap block), then R5b (value appears). If W13 accidentally drops the final `<< 4` shift while extending the formula, R5c catches that as a NAMED separate failure rather than burying it in a compound boolean.
- **Sub-region slice via comment-marker + assignment-token (option a, not option b).** Plan 12.7-18 <action> Step 3 offered two slicing strategies. Option (a) anchors on the `Snap to tile-top` comment marker — a column-stable, semantic anchor unique to this block. Option (b) anchors on `foot_tile_row` + `_player_y = ` — token-based. Option (a) is more semantic ("the snap block IS the region between this comment and that assignment") and more drift-resistant (a future refactor that renames or reorders intermediate vars wouldn't break the slice).
- **Either-of acceptance for both name AND value.** The diagnostic Section 5 names two equivalent fix shapes (Option A explicit `pivot_adjust = 2u`, Option B folded `height_plus_pivot = 26u`). Locking to ONE would force W13's hand. Accepting EITHER lets W13 author pick the cleaner shape at fix time. The invariant being locked is semantic ("the 2-px correction is encoded in the snap block"), not syntactic.
- **Evidence-before-assert preserved.** The test writes the snap-block to `evidence/tier1-shape/platformer_physics_update_snap_block.c` BEFORE the new R5 assertions fire. On a RED run, the evidence file still lands on disk — a reviewer can see WHAT was emitted without re-running. Mirrors the sibling TilemapCollisionEmissionTest INV-1..4 pattern. The existing `platformer_physics_update.c` evidence write (line 241) was preserved unchanged.
