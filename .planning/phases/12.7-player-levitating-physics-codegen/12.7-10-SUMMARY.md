# Phase 12.7 Plan 10: Strengthen R-05 Invariant Test for Precedence-Class Bug Summary

One-liner: Add two new JVM-tier assertions (`foot_pixel_top`, `foot_pixel_anchor`) that lock the precedence-immune intermediate-vars emission shape; RED at this commit against the broken Plan 12.7-04 inlined snap, GREEN once Plan 12.7-11 lands.

## Result

R-05 invariant strengthened. The test
`PlatformerPhysicsSnapToTileTopEmissionTest.platformer_physics_update emits snap-to-tile-top
assignment inside foot-probe block` is **RED at this commit** (assertion 4 fails at line
327 — `foot_pixel_top` token absent from Plan 12.7-04 emission). Existing assertions 1-3
still pass; the failure is specifically at the new precedence-class assertion. All other

The strengthening is the upstream miss that allowed the C-precedence bug to ship through
Plan 12.7-04's GREEN verdict. Plan 12.7-11 codegen rewrite to intermediate-vars form
will flip this RED → GREEN.

## What the bug class is

C operator precedence: `+`/`-` (C11 §6.5.6) binds **tighter** than `<<`/`>>` (C11 §6.5.7).

The Plan 12.7-04 emission inlined the snap algebra into a single expression
(evidence/tier1-shape/platformer_physics_update.c:25):

```c
// Snap to tile-top: deterministic single-assignment snap...
UINT16 foot_tile_row = player_real_y + 24u >> 3u;
_player_y = foot_tile_row << 3u - 24u << 4u;            // BROKEN
```

The second line **parses as** `foot_tile_row << (3u - 24u) << 4u`. Unsigned underflow
(`3u - 24u` → very large `UINT`) produces a garbage `_player_y` — observable at runtime
as the player sprite glued to the top of the screen (user UAT 2026-05-26).

## What the upstream printer does

`CEmitter.kt:426` emits `CBinaryExpr` as `"${left} ${op} ${right}"` with **no
precedence-aware parens**. The C AST has **no `CParenExpr` node** today; adding one is
AST surgery that is out of scope for Phase 12.7 (see
`SEED-PHASE-X-CPAREN-EXPR-IN-C-AST.md` dropped by Plan 12.7-16).

The Plan 12.7-04 SUMMARY claim _"printer encodes intended left-to-right grouping"_ is
**incorrect**. The erratum is recorded by Plan 12.7-16 SUMMARY's Round-4 close section —
this plan does **not** mutate `12.7-04-SUMMARY.md`.

## Why the original substring assertions were insufficient

The W2 R-05 gates assert `physicsBody.contains("foot_tile_row")` and
`physicsBody.contains("_player_y")`. Both substrings co-exist with the broken
inlined expression — the tokens are present, but the adjacent operator algebra is
semantically wrong. Substring presence is not a precedence contract.

## What this plan adds

Two new assertions appended to the assertion block of the single `@Test` method:

### Assertion 4 — `foot_pixel_top`

```kotlin
assertTrue(
    physicsBody.contains("foot_pixel_top"),
    "platformer_physics_update body must contain `foot_pixel_top` " +
        "intermediate var (Plan 12.7-11 precedence-immune snap shape). ..."
)
```

Forces the codegen to emit `foot_pixel_top = foot_tile_row << 3` as its own
`CVarDecl` line — one binary-op class only — making `<< 3` precedence-immune.

### Assertion 5 — `foot_pixel_anchor`

```kotlin
assertTrue(
    physicsBody.contains("foot_pixel_anchor"),
    "platformer_physics_update body must contain `foot_pixel_anchor` " +
        "intermediate var (Plan 12.7-11 precedence-immune snap shape). ..."
)
```

Forces the codegen to emit `foot_pixel_anchor = foot_pixel_top - height` as its
own `CVarDecl` line — isolating the subtract from the trailing `<< 4` shift so C
precedence cannot reorder.

Both failure messages include `physicsBody.take(4000)` so a RED-run review surfaces
the broken emission shape on disk.

## Fix shape (Plan 12.7-11 GREEN companion)

```c
UINT16 foot_tile_row     = (player_real_y + height) >> 3;   // one >> per line
UINT16 foot_pixel_top    = foot_tile_row << 3;              // one <<
UINT16 foot_pixel_anchor = foot_pixel_top - height;         // one -
posYSym                  = foot_pixel_anchor << 4;          // one <<
```

Each line carries at most one binary-op class, making the algebra precedence-immune
regardless of `CEmitter.kt:426`'s no-paren printer.
