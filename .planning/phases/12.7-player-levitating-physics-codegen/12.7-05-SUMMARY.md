# Phase 12.7 Plan 05: D-03 Defensive Tightening (Stuck-Resolve Guard) Summary

Wrapped the stuck-in-ground resolve while-loop in `if (groundedSym == 0)` so the
loop only runs when the player is not grounded — preserves defense-in-depth for
spawn-inside-floor and head-probe inverse-drift edges while skipping the
redundant fall-collision case Plan 12.7-04's snap-to-tile-top now handles
deterministically. One-line conceptual change; one file modified at one site.

## One-liner

`add(CWhile(...))` at the stuck-resolve site at PlatformerVisitor.kt:883-911 is
now `add(CIf(condition = CBinaryExpr(CVar(groundedSym), "==", CIntLiteral(0)),
thenBody = listOf(CWhile(...))))` — purely additive AST wrap; CWhile's condition
and body are unchanged.

## Behavior Analysis

| Frame state | Before this plan | After this plan |
|-------------|-------------------|------------------|
| `grounded=1` (just landed, snap fired) | While-loop checks `is_tile_solid` → false → no-op (1 condition eval) | While-loop skipped entirely (0 condition evals) |
| `grounded=1` + somehow stuck (spawn-in-floor BEFORE first frame) | Loop iterates, pops player up | Loop SKIPPED — initial-frame stuck state is a separate concern (see below) |
| `grounded=0` (airborne) | Loop checks `is_tile_solid` → false on clean air → no-op | IDENTICAL — guard true, loop checked |
| `grounded=0` + head-probe inverse-drift edge | Loop pops player out of ceiling-poke | IDENTICAL — guard true, loop fires |

**Spawn-inside-floor caveat:** D-03 CONTEXT notes the loop also serves
defense-in-depth for the spawn-inside-floor case. The new guard means a player
who spawns INSIDE a floor with `grounded` initialized to `1` (the platformer
template defaults this) will not be pulled out on frame 1 by the stuck-resolve
loop alone. However, the snap-to-tile-top from Plan 04 (W3 Plan B) handles this
deterministically on the very first frame where the foot-probe fires (the snap
is unconditional in the foot-probe gate, runs even when `grounded` was already
`1`), so the spawn-in-floor scenario is now resolved by snap, not by loop —
which is the strictly-stronger fix D-03 + W3 collectively delivers.
