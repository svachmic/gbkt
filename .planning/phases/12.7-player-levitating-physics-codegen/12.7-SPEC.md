## Goal

The platformer-template player metasprite is visibly pinned to the underlying solid tile-row with zero pixel gap each frame when not in a jump arc, as observed in re-shot Anchor 2 and Anchor 5 PNGs and locked by a JVM-tier emission invariant on `platformer_physics_update`.

## Background

Phase 12.6 closed Gate G1 (main()-loop level-switch codegen — DEFECT-1 + DEFECT-2). Gate G2 (player levitating above floor) was inserted into ROADMAP.md as Phase 12.7 per `feedback_route_to_proper_phase_when_blast_radius_is_wide.md` and the seed `SEED-PHASE-12-PLAYER-LEVITATING-NOT-GROUNDED.md`.

**Current state on `feat/d_and_d_gaps` (post-12.6 SHIP):**

- `PlatformerVisitor.buildVerticalFootProbe()` (`gbkt-genre-platformer/src/main/kotlin/io/github/gbkt/genre/platformer/codegen/PlatformerVisitor.kt:1222`) emits a 2-point foot AABB probe that zeroes `_playerVy` and sets `_grounded = 1` on hit. **It does NOT emit a snap-to-tile-top correction** — the player's `_playerY` is left at the integrated position, which can be several sub-pixels above the tile top (visible as a stable hover).
- A "stuck-in-ground" while-loop (PlatformerVisitor:879) pops the player UP 1 pixel at a time only when `is_tile_solid(x, y + heightMinus1)` is true — it does NOT pull the player DOWN to the tile top when the foot is above with no overlap.
- Probe + integration order (PlatformerVisitor:838 vertical-probe → 1054 velocity-integration) places probes BEFORE integration; reference `platformer_template/src/player.c` integrates first then probes. This ordering may compound the hover.
- Phase 12 evidence PNGs at `.planning/phases/12-port-platformer-template-gbdk-example-to-gbkt/evidence/uat-screenshots/anchor-2/{01-grounded.png, 03-landed.png}` and `.../anchor-5/01-near-end.png` show the player visibly hovering 3–5 px above the ground tile row.
- The substrate is intact: `is_tile_solid()` (PlatformerVisitor / GBDKPipelineV2:2273) is correctly emitted; 5-point probe coverage is correct; `_grounded` flag flips correctly. The defect is specifically the missing snap-to-tile-top step and possibly the probe/integration ordering.

This is a **Visual Evidence Rule** case (CLAUDE.md §"Verification Methodology"): `assertVariable("_playerVy", 0)` would falsely report "grounded" because vy IS zeroed by collision; only a screenshot can prove the visual outcome. The bug class is exactly the one the Visual Evidence Rule was codified to catch (Phase 07.4 history).

Phase 12 close (Plan 12-27 administrative state) stays partial until G2 (this phase) + G3 + G4 (Phase 12.8) ship. Per `feedback_decimal_phase_pitstop_resume_target.md`, the resume target after 12.7 SHIPS is Phase 12 itself (waiting on 12.8), NOT Phase 13.
