    ```markdown
    # SEED: Add `CParenExpr` to C AST + precedence-aware `CBinaryExpr` printer

    **Origin:** Phase 12.7 gap-closure (Plan 12.7-16). Surfaced by the C-operator-precedence
    bug in Plan 12.7-04's snap emission (`_player_y = foot_tile_row << 3u - 24u << 4u;`
    which C parses as `foot_tile_row << (3u - 24u) << 4u`).

    **Status:** OPEN. Route to a new sibling phase via `gsd-phase --insert 12 cparen-expr-c-ast-surgery`
    OR to a Phase 13+ slot — your call when the time comes.

    ## Problem

    The C AST at `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/ast/CExpr.kt`
    has no `CParenExpr` node. The `CBinaryExpr` printer at
    `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/emit/CEmitter.kt:426`
    emits binary ops as:
    `${emitExpr(expr.left)} ${expr.op} ${emitExpr(expr.right)}`
    with NO precedence-aware parens.

    Any visitor that nests `CBinaryExpr` instances inherits C's default operator precedence
    at emit time — regardless of what the Kotlin tree structure intended. The Kotlin AST
    `CBinaryExpr(CBinaryExpr(a, "<<", b), "-", c)` and `CBinaryExpr(a, "<<", CBinaryExpr(b, "-", c))`
    BOTH emit `a << b - c`, but they have DIFFERENT C semantics.

    Phase 12.7 found this the hard way: Plan 12.7-04's snap emission shipped through
    Plan 12.7-02's substring-only JVM test as GREEN, but the runtime ROM was broken because
    the emitted expression's C-precedence parse did not match the Kotlin AST's grouping.

    ## Workaround that Phase 12.7 shipped

    Plan 12.7-11 restructured `PlatformerVisitor.buildVerticalFootProbe`'s snap emission to
    use intermediate `CVarDecl` locals (`foot_pixel_top`, `foot_pixel_anchor`), splitting the
    algebra across multiple lines so each emitted line has at most one binary-op class.
    This is precedence-immune by construction but COSTS:
    - 3 extra `UINT16` locals per snap-emission site
    - Visitor authors must remember to NEVER nest `CBinaryExpr` with mixed precedence classes
    - No JVM-tier enforcement of the rule (Plan 12.7-10's test locks ONE site only)

    ## Proper fix (this seed's scope)

    1. **Add `CParenExpr` to the C AST** at
       `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/ast/CExpr.kt`.
       Sealed-interface dispatch (the file is `sealed interface CExpr`) means `CEmitter`'s
       `when` matcher gains exhaustiveness for the new variant.

    2. **Rewrite `CBinaryExpr` printer in `CEmitter.kt:426`** to insert precedence-aware
       parens when needed. Reference C11 §6.5 precedence table:
       - 6.5.6 multiplicative: `*` `/` `%` (precedence 13)
       - 6.5.5 additive: `+` `-` (precedence 12)
       - 6.5.7 shift: `<<` `>>` (precedence 11)
       - 6.5.8 relational: `<` `<=` `>` `>=` (precedence 10)
       - 6.5.9 equality: `==` `!=` (precedence 9)
       - 6.5.10 bitwise AND: `&` (precedence 8)
       - 6.5.11 bitwise XOR: `^` (precedence 7)
       - 6.5.12 bitwise OR: `|` (precedence 6)
       - 6.5.13 logical AND: `&&` (precedence 5)
       - 6.5.14 logical OR: `||` (precedence 4)
       Algorithm: when emitting `CBinaryExpr(left, op, right)`:
         - if `left` is a `CBinaryExpr` AND its op has lower precedence than the outer op,
           wrap `left` in parens.
         - if `right` is a `CBinaryExpr` AND its op has lower-or-equal precedence than the
           outer op (for left-associative ops), wrap `right` in parens.
         - left-associativity matters; reference C11 §6.5 associativity rules.

    3. **Compose with `CEmitter.emitCastInner`** at lines 443-457 (the existing precedence-
       aware cast emission from Plan 07.4-34). The new printer convention should NOT
       conflict — `emitCastInner` wraps `CCast` inners that are `CBinaryExpr` / `CUnaryExpr`
       / `CTernary` in parens; the new printer adds parens for SUBTREES of `CBinaryExpr`.
       The two helpers should compose cleanly.

    4. **Regression sweep** — the new printer can alter ANY visitor's emitted output. Run
       the 8-target sweep (per `12.7-PATTERNS.md` §"gradlew single-command regression sweep")
       and accept that several ROMs will have intentional byte-changes. Document each
       intentional change with a code-comment-level rationale + visual-runtime check.

    5. **JVM test** — add `CBinaryExprPrecedenceParenEmissionTest` under
       `gbkt-backend-gbdk/src/test/.../codegen/emit/` with at least 8 cases covering:
       - mixed-precedence nesting (the Phase 12.7 bug class — `a << (b - c)` and `(a - b) << c`)
       - same-precedence left-associative nesting (`a + b + c` MUST NOT add parens)
       - same-precedence right-associative (assignment chains)
       - parens around `CUnaryExpr` (sometimes needed; sometimes not)
       - the `CCast` interaction (compose-with-`emitCastInner`)
       - relational + logical nesting (`a < b && c == d`)
       - bitwise + shift nesting (`(a & b) << c`)
       - the original Phase 12.7 snap shape (regression guard for the bug class that opened this seed)

    6. **Update visitor authors' contract** — document in
    ```
