## Math Identity (D-02 unchanged at algebra layer)

Let `r = player_real_y`, `h = height`.

```
foot_tile_row     = (r + h) >> 3
foot_pixel_top    = foot_tile_row << 3 = ((r+h) >> 3) << 3
foot_pixel_anchor = foot_pixel_top - h
posYSym           = foot_pixel_anchor << 4
                  = (foot_pixel_top - h) << 4
                  = ((foot_tile_row << 3) - h) << 4    -- the locked D-02 formula
```

## Round-trip verification (spawn_y=120, h=24)

```
foot_tile_row     = (120 + 24) >> 3 = 144 >> 3 = 18
foot_pixel_top    = 18 << 3 = 144
foot_pixel_anchor = 144 - 24 = 120
posYSym           = 120 << 4 = 1920
player_real_y (next frame, _player_y >> 4) = 1920 >> 4 = 120
gap = 120 - 120 = 0 pixels   ✓ (player's foot lands exactly on tile-row top at pixel 144)
```

## Decisions Made

- **Path A (intermediate-vars), NOT Path B (CParenExpr AST surgery), for 12.7 scope.** Path B requires adding `CParenExpr` to `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/ast/CExpr.kt` AND rewriting every `CBinaryExpr` printer site in `CEmitter` to insert precedence-aware parens. That is a backend-wide change affecting every visitor's emission shape AND every existing tier1-shape evidence file across all phases — a blast radius far beyond Phase 12.7's scope. Per project rule `feedback_route_to_proper_phase_when_blast_radius_is_wide`, the correct routing is a dedicated phase initiated via a SEED. Plan 12.7-16 will drop `SEED-PHASE-X-CPAREN-EXPR-IN-C-AST.md` — NOT this plan.
- **CLiteral throughout, no CIntLiteral.** All four CVarDecl initializers and the final RHS are unsigned-context UINT16 sub-pixel arithmetic per `gbkt-backend-gbdk/CLAUDE.md` §"Literal Emission Convention". CIntLiteral is reserved for signed-comparison RHS only (Plan 05's `groundedSym == 0` guard).
- **Correct Plan 12.7-04's misclaim.** The Plan 12.7-04 SUMMARY asserted "the printer encodes intended left-to-right grouping" — this is incorrect. `CEmitter.emitExpr` emits `CBinaryExpr` as bare `${left} ${op} ${right}` with NO precedence-aware parens (the C AST has no `CParenExpr` today). This SUMMARY documents the correction.
