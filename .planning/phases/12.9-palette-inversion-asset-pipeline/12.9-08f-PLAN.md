- **D1 (0F-in-flip):** `SceneVisitor.kt` (~line 299) appends an inline `CRawCode("DISPLAY_ON;")` as
  the last zone-load item, BEFORE the user-authored `LevelCardSceneBuilder` clear, so the GBC PPU
  composites a flip frame with un-cleared world1 cols 20–31 (the `0F` tile). Fix: gate/omit the
  inline `DISPLAY_ON` when the scene's `enterOps` already end with a `DISPLAY_ON` (trailing-
  `DISPLAY_ON` heuristic — no `ZoneIR` field). Result: `bank1.c` `nextLevelScene_enter()` clears the
  BG BEFORE the single final `DISPLAY_ON;`.
- **D2a (player box — THE blocker):** `ConvertSpritesTask.buildPng2AssetArgs` omits
  `-keep_palette_order`, so png2asset re-sorts the indexed source palette and the sprite-sheet's
  orange background lands at index 2 (opaque) instead of the source's index 0 (transparent). Fix:
  append `-keep_palette_order` when the source PNG is indexed (reuse / mirror `isIndexedPng` from
  ConvertZoneTilesetsTask). This matches the proven reference Makefile. On GBC, OBJ index 0 is
  hardware-transparent, so the box disappears.
- **D2b (character colors):** the metasprite's generated `<name>_palettes` array is never uploaded
  (`set_sprite_palette` count = 0), so the character renders under the GBDK default grayscale OBJ
  palette. Fix: in `GBDKPipelineV2`'s sprite-VRAM loader (~line 4852, where metasprite
  `set_sprite_data` is emitted), also emit a GBC-gated `set_sprite_palette(<slot>, <count>,
  <name>_palettes)` for each metasprite, symmetric to the BG palette path. Determine the palette
  symbol/count from the metasprite's png2asset output (`<name>_palettes` + its palette count macro).
- **D3 (walk-through):** `PlatformerVisitor.buildHorizontalProbe()` (~line 1276) uses
  `CLiteral(halfW)` (halfW = hitbox.width/2 = 4) vs the reference HALF_WIDTH = 5. Fix:
  `CLiteral(halfW)` → `CLiteral(halfW + 1)` so probes read `player_real_x + 5u` / `- 5u`.
- **D4 (level-2 sunk):** `setup_current_level()` resets `$vySym = 0` per level but NOT the grounded
  symbol, which carries `1` from the prior level's level-end trigger → gravity suppressed → the
  collision snap never fires → the player freezes at raw spawn y (sunk). Fix: in
  `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded` (~line 2529), reset the grounded symbol to
  0 alongside the `$vySym = 0` line. Resolve the grounded symbol the same way `posXSym`/`vySym` are
  resolved from the `tilemap_collision` GenericSystem config (look for a `groundedVar` key; the
  generated symbol is `_grounded`). NOT a `PlatformerTemplate.kt` spawn_y change — the spawn tables
  stay `{40,40,40}/{120,120,120}`.
