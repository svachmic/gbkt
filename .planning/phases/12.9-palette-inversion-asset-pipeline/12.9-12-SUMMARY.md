# Phase 12.9 Plan 12: Code-Review Gap-Closure 12.9-12 Summary

**One-liner:** Five code-review findings resolved — unconditional sprite/zone palette externs, exact DISPLAY_ON match with card-overdraw tilemap skip, consistent halfW=5 probe base, and self-contained zone tileset header.

## What Was Built

Executed the gap-closure bundle from `12.9-REVIEW.md` fixing 5 items across 3 modules:

### FIX 1 — CR-01: Sprite palette extern unconditional (ConvertSpritesTask)

`generateSpriteHeader` previously gated both `#include <gb/cgb.h>` and
`extern const palette_color_t <stem>_palettes[]` on `isIndexed`. But png2asset always emits
the `_palettes` array for every sprite PNG (no `-no_palettes` flag is used;
`-keep_palette_order` only affects palette ORDER). A non-indexed (RGB) metasprite PNG
therefore produced a missing extern → SDCC "Undefined identifier" when `set_sprite_palette()`
in main.c referenced it.

**Fix:** Removed both `if (isIndexed)` gates. Both the `<gb/cgb.h>` include and the palette
extern are now emitted unconditionally. `generateSpriteHeader` promoted to `internal` top-level
(mirrors `buildPng2AssetArgs` pattern) for direct test access.

**Test:** `ConvertSpritesHeaderPaletteExternTest` — RED→GREEN for non-indexed PNG fixture.

### FIX 2 — CR-02: False positive (no code change)

The review claimed `synthesizeHeader` gated the palette extern on indexedness. In fact,
`synthesizeZoneTilesetHeader` (formerly `synthesizeHeader`) already declared the
`_zone_<id>_tileset_palettes` extern **unconditionally**. Status updated to `false-positive`
in `12.9-REVIEW.md`.

### FIX 3 — WR-01 + Polish: Exact DISPLAY_ON match + card-overdraw tilemap skip (SceneVisitor)

Two improvements to `SceneVisitor`'s zone-load prelude:

1. **WR-01 exact match**: `it.code.contains("DISPLAY_ON")` → `it.code.trim() == "DISPLAY_ON;"`.
   A comment mentioning `DISPLAY_ON` or a macro named `DISPLAY_ONCE` can no longer accidentally
   suppress the inline LCD re-enable.

2. **Polish (card-overdraw skip)**: When the scene's enterOps contain the card-scene full-clear
   signal `fill_bkg_rect(0u, 0u, 32u, 32u, 0u)`, the `_bkg_tiles_load_banked(bank, 0, 0, ...)`
   tilemap-place statement is skipped. The card clear immediately overwrites this (0,0) placement
   and redraws centered — keeping the (0,0) place produced a brief top-left flash. Tile DATA load
   (`pixelLoad = set_bkg_data`) and `set_bkg_palette` are both kept.

**Test:** `LevelCardSceneEmissionTest` tests 8+9 — card enter lacks (0,0) place; normal scene still has it.

### FIX 4 — WR-02: Consistent halfW=5 base in PlatformerVisitor

The D3 fix patched `CLiteral(halfW + 1)` at one call site in `buildHorizontalProbe` while
leaving `halfW = hitbox.width / 2 = 4` uncorrected. Foot/head probes used `halfWMinus2 = 2`
(one pixel narrower than the reference `HALF_WIDTH - 2 = 3`).

**Fix:** Set `halfW = hitbox.width / 2 + 1 = 5` at the derivation site; revert
`CLiteral(halfW + 1)` → `CLiteral(halfW)` in `buildHorizontalProbe`. Result:
- horizontal probes: `player_real_x ± 5u` (unchanged — G3-approved behavior preserved)
- foot/head probes: `player_real_x ± 3u` (was 2u — now consistent with reference)

**Test:** `TilemapCollisionEmissionTest` WR-02 test — RED→GREEN.

### FIX 5 — WR-03: `<gb/cgb.h>` in zone tileset header (ConvertZoneTilesetsTask)

`synthesizeZoneTilesetHeader` emitted `extern const palette_color_t _zone_<id>_tileset_palettes[...]`
without including `<gb/cgb.h>` — the header providing the `palette_color_t` typedef. The sibling
`generateSpriteHeader` already included it; the zone header was inconsistent and relied on transitive
includes.

**Fix:** Added `appendLine("#include <gb/cgb.h>")` alongside the existing `<stdint.h>` and
`<gbdk/platform.h>`. `synthesizeHeader` promoted to `internal` top-level `synthesizeZoneTilesetHeader`
for direct test access.

**Test:** `ConvertZoneTilesetsHeaderCgbIncludeTest` GREEN.

## Deviations from Plan

### Structural refactoring (Rule 2 — correctness prerequisite for testing)

Both `generateSpriteHeader` (ConvertSpritesTask) and `synthesizeHeader` (ConvertZoneTilesetsTask)
were promoted from `private` class methods to `internal` top-level functions. This mirrors the
existing `buildPng2AssetArgs` and `injectBankPragma` patterns. Without this, RED→GREEN unit tests
could only verify behavior through GBDK-requiring integration paths.

The `synthesizeHeader` in ConvertZoneTilesetsTask was renamed to `synthesizeZoneTilesetHeader` to
avoid ambiguity with the class-level delegation wrapper.
