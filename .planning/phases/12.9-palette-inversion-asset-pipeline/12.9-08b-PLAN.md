pipeline-generated `setup_current_level()` function, which W5's `SceneVisitor` palette fix never
touched (gameplay scene has empty `scene.zoneRefs` — Pitfall 7). The fix is a single addition to the

`set_bkg_palette` call after each zone's `set_bkg_data` line. The `_zone_<id>_tileset_PALETTE_COUNT`
macro, the `_zone_<id>_tileset_palettes` extern, and the `<gb/cgb.h>` include chain are ALL already
present in `main.c` from W4 — no header or include work.

RC-1d, `main()` calls `cgb_compatibility()` which makes `set_bkg_palette` a no-op on DMG, and the
existing `_gbkt_default_bg_pal` upload at `main.c:~698` is emitted unconditionally for this reason —
so the new per-zone call may also be emitted unconditionally. The executor should match whichever
gating shape the existing `setup_current_level` / default-palette emission uses so DMG safety is
preserved without redundant `#ifdef` noise.

jump FIRES (the G3 "dead jump" was a wrong-button J_B + metadata-gap false alarm). In that case 08b's
RC-2 deliverable is DOCUMENTATION ONLY — a PLAYBOOK.md note that jump = A or UP (not B) and that the
gameplay metadata `controls` omits jump because it is a `RawOp`-injected function. ONLY if 08a proved
jump genuinely broken does 08b touch `PlatformerVisitor.buildTilemapPhysicsUpdateFunction()`.

`feedback_no_parallel_gradle_clean`).
