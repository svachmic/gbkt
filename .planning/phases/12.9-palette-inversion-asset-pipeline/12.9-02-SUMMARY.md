## Reframe Verdict (D-10)

**R-03 (nextLevel BG-clear gap) + R-04 (0F artifact) = SAME ROOT CAUSE.**

Both defects are caused by `fill_bkg_rect(0u, 0u, DEVICE_SCREEN_WIDTH=20, DEVICE_SCREEN_HEIGHT=18, 0u)` clearing only the 20x18 visible viewport while the GBC BG hardware plane is 32x32 tiles. When gameplay scrolls the camera right, world1Area1 tile data (including 0x0E/0x0F indices) occupies columns 20-31. When `nextLevelScene_enter` calls `move_bkg(0u, 0u)`, those columns become visible — producing the "0F" artifact.

## D-12 Disposition: NO Seed File

Per D-12: since the 0F artifact is PRE-EXISTING and is in the palette-wiring blast radius (same fix target as R-03), it is resolved by Phase 12.9 W6. No seed file created. R-04 acceptance criterion becomes "anchor-5 re-shoot post-fix shows no 0F in any quadrant."

## Verdict

**R-03+R-04 BUNDLED. Single fix lands in W6. NO seed.**

Fix: `fill_bkg_rect(0u, 0u, 32u, 32u, 0u)` (covers full 32x32 GBC BG hardware-addressable tile area, LCDC.3) in `PlatformerExtensions.kt:860-862`.
