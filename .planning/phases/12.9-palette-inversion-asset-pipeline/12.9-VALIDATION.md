## Validation Tier Map (Nyquist)

- **Codegen-shape tier (JVM unit/integration):** R-01, R-02, R-08 — locks generated C contract one level below visual outcomes. Per `CLAUDE.md § Verification Methodology — Visual Evidence Rule`, variable assertion is sufficient when the test locks the GENERATED C SHAPE.
- **Runtime-visual tier (MCP screenshot):** R-03, R-04 — visual SCs require runtime PNG via `gbkt-emulator` MCP. Per `feedback_visual_evidence_for_visual_truths`: "when the goal is visual, codegen GREEN is necessary but never sufficient."
- **User-verdict tier (binding gate):** R-05, R-06 — explicit user APPROVED/BLOCKED verdict on PNG evidence committed to `evidence/`.
- **Binary tier (ROM hash):** R-07 — `shasum -a 256` against post-build `*.gb` artifacts; pre/post comparison via 7-target manifest.
- **Admin tier:** R-09 — git log + `phase.complete 12` CLI invocation evidence captured to `evidence/phase-complete-12-invocation.txt`.
