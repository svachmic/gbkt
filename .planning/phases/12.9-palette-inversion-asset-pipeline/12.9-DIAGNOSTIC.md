### nextLevelScene_enter — Quoted Body (bank1.c:72-81)

```c
void nextLevelScene_enter(void) BANKED {
    set_bkg_data(0u, _zone_nextLevelZone_tileset_count, _zone_nextLevelZone_tileset);
    _bkg_tiles_load_banked(2u, 0u, 0u, _zone_nextLevelZone_tilemap_WIDTH, _zone_nextLevelZone_tilemap_HEIGHT, _zone_nextLevelZone_tilemap);
    DISPLAY_ON;
    hide_sprites_range(0u, MAX_HARDWARE_SPRITES);
    move_bkg(0u, 0u);
    fill_bkg_rect(0u, 0u, DEVICE_SCREEN_WIDTH, DEVICE_SCREEN_HEIGHT, 0u);
    _bkg_tiles_load_banked(2u, (DEVICE_SCREEN_WIDTH - _zone_nextLevelZone_tilemap_WIDTH) / 2u, (DEVICE_SCREEN_HEIGHT - _zone_nextLevelZone_tilemap_HEIGHT) / 2u, _zone_nextLevelZone_tilemap_WIDTH, _zone_nextLevelZone_tilemap_HEIGHT, _zone_nextLevelZone_tilemap);
    DISPLAY_ON;
}
```

### 4-Point Findings

1. **SceneVisitor zone-load prelude fires first.** The first three statements (`set_bkg_data` + `_bkg_tiles_load_banked` + `DISPLAY_ON`) come from `SceneVisitor`'s zone-load flatMap, placing the nextLevel tileset at BG tile index 0, map position (0,0). This runs before any `LevelCardSceneBuilder.materialize()` code.

2. **`LevelCardSceneBuilder.materialize()` then runs with `fill_bkg_rect(20x18)`.** After the zone-load prelude, the materialized card-scene logic executes: `hide_sprites_range + move_bkg(0, 0) + fill_bkg_rect(0u, 0u, DEVICE_SCREEN_WIDTH, DEVICE_SCREEN_HEIGHT, 0u) + centered _bkg_tiles_load_banked + DISPLAY_ON`. The critical defect is in the `fill_bkg_rect` arguments: `DEVICE_SCREEN_WIDTH = 20` and `DEVICE_SCREEN_HEIGHT = 18` match the 20x18 visible viewport only.

3. **Only the 20x18 visible viewport is cleared; the GBC BG hardware plane is 32x32 tiles.** When gameplay has scrolled the camera (`_camera_x > 0`), BG tile indices at columns 20-31 remain in VRAM with world1Area1 tilemap data — including `0x0E`/`0x0F` grass/ground tile indices. When the nextLevel scene resets scroll via `move_bkg(0u, 0u)`, the residual tile data at columns 20-31 is no longer scrolled off-screen and becomes visible in the bottom-right quadrant as the "0F" text artifact.

4. **D-06 MCP runtime trace is OPTIONAL — codegen shape is already the defect surface.** The quoted C body proves the defect conclusively: `fill_bkg_rect(0u, 0u, DEVICE_SCREEN_WIDTH, DEVICE_SCREEN_HEIGHT, 0u)` covers only 20x18 tiles. The fix (`fill_bkg_rect(0u, 0u, 32u, 32u, 0u)`) covers the full 32x32 GBC BG hardware-addressable tile area (LCDC.3 = 256x256 pixels = 32x32 tiles). No runtime probe is needed to confirm the diagnosis.

**Verdict:** CODEGEN-IS-THE-DEFECT. D-11 fix lands in W6 (PlatformerExtensions.kt:859-862 → 32u, 32u).

### Reframe Verdict (D-10)

**0F artifact = PRE-EXISTING.** The "0F" text artifact appears in Phase 12.7 anchor-5 captures (`02-nextlevel-card.png`) which were committed 2026-05-26 — prior to Phase 12.8 W3 conditional `-keep_palette_order` activation (2026-05-27). **Root cause (D-10 reframe):** `0x0E` and `0x0F` are real BG tile indices in `_zone_world1Area1Zone_tilemap` (confirmed: 6 grep hits in the gameplay tilemap C array). The visible "0F"/"F" text in anchor-5/01-02 captures is residual gameplay BG tilemap data persisting through the nextLevel scene transition. There is NO runtime `printf`/`gotoxy` involved — those are BG tile cells with the wrong content surviving from world1Area1 because `fill_bkg_rect(0u, 0u, DEVICE_SCREEN_WIDTH=20, DEVICE_SCREEN_HEIGHT=18, 0u)` only clears the 20×18 visible viewport while the GBC BG hardware plane is 32×32 tiles. When `nextLevelScene_enter` calls `move_bkg(0u, 0u)` and resets scroll to (0,0), those columns are no longer scrolled off-screen and become visible in the viewport as the "0F" tile artifact.

**R-03 (nextLevel transition BG-clear gap) + R-04 (0F text artifact) collapse into ONE defect class.** Both are caused by the same `fill_bkg_rect` 20×18 undercoverage. A single fix — `fill_bkg_rect(0u, 0u, 32u, 32u, 0u)` covering the full GBC BG hardware-addressable tile area (LCDC.3: 256×256 pixels = 32×32 tiles) — resolves both.

**D-12 disposition:** Because the 0F artifact is in the palette-wiring blast radius (same root cause, same fix target), it is fixed in Phase 12.9 per the D-12 rule. **NO seed file drop required.** R-04 acceptance becomes "anchor-5 re-shoot post-fix shows no 0F text artifact in any quadrant."
