    - `gbkt-engine/build.gradle.kts` — should depend on `gbkt-ir` and `gbkt-lang`
    - `gbkt-world/build.gradle.kts` — should depend on `gbkt-ir`, `gbkt-lang`, `gbkt-engine`

    **Enforce the layering** by adding Gradle `configurations` constraints to lower-level modules:

    For `gbkt-ir/build.gradle.kts`:
    ```kotlin
    configurations.all {
        // gbkt-ir is the lowest layer — must not depend on higher-level modules
        exclude(group = project.group.toString(), module = "gbkt-lang")
        exclude(group = project.group.toString(), module = "gbkt-engine")
        exclude(group = project.group.toString(), module = "gbkt-world")
        exclude(group = project.group.toString(), module = "gbkt-core")
    }
    ```

    For `gbkt-lang/build.gradle.kts`:
    ```kotlin
    configurations.all {
        // gbkt-lang depends on gbkt-ir only — must not pull in engine or world
        exclude(group = project.group.toString(), module = "gbkt-engine")
        exclude(group = project.group.toString(), module = "gbkt-world")
    }
    ```

    **IMPORTANT:** The exact Gradle API depends on whether these are published modules or project dependencies. If the `configurations.all { ... }` approach causes issues, fall back to a custom validation task:

    ```kotlin
    tasks.register("validateDependencies") {
        doLast {
            val forbidden = setOf("gbkt-lang", "gbkt-engine", "gbkt-world", "gbkt-core")
            configurations["compileClasspath"].resolvedConfiguration.firstLevelModuleDependencies.forEach {
                require(it.moduleName !in forbidden) {
                    "Module ${project.name} must not depend on ${it.moduleName}"
                }
            }
        }
    }
    tasks.named("check") { dependsOn("validateDependencies") }
    ```

    **Verify:** Run `./gradlew build -x spotlessCheck` to confirm no existing dependencies are broken.
