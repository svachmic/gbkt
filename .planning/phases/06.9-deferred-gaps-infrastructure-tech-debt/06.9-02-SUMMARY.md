# Phase 06.9 Plan 02: Collection Simulation in ScriptOpInterpreter Summary

Implemented in-memory simulation for four collection operation families (hashtable, pool, ring buffer, fixed slots) in ScriptOpInterpreter, closing J10. Collection operations now maintain correct state in the JVM test runner instead of returning 0 stubs, enabling unit testing of collection-heavy game logic without a ROM or emulator.

## What Was Built

### Task 1: Collection State and Dispatch

Added three new state fields to `ScriptOpInterpreter`:

```kotlin
private val hashTables: MutableMap<String, MutableMap<Long, Long>> = mutableMapOf()
private val ringBuffers: MutableMap<String, ArrayDeque<Long>> = mutableMapOf()
private val fixedSlots: MutableMap<String, MutableMap<Int, Long>> = mutableMapOf()
```

Replaced the `evaluateCallExpr` `when(fn)` dispatch with a condition-guard `when` block that matches function name patterns:

- `ht_{name}_insert/get/contains/remove/size/clear` — hash table operations
- `ring_{name}_push/pop/peek/size/clear` — ring buffer operations (FIFO via `ArrayDeque`)
- `pool_{name}_alloc/free/active_count` — pool operations (backed by hashTables with `__pool_` prefix)
- `slot_{name}_set/get/clear` — fixed slot operations

Replaced the `CallOp` no-op stub with `executeCallOp()` which constructs a synthetic `CallExpr` to reuse the same dispatch logic for side-effecting calls.

### Task 2: CollectionSimulationTest

Created 40 tests covering:

- **Hash table**: insert/get round-trip, contains true/false, remove, size tracking, clear, overwrite existing key, CallOp dispatch
- **Ring buffer**: push/peek FIFO order, push/pop FIFO order, pop on empty returns 0, size tracking, pop decreases size, clear, CallOp dispatch
- **Pool**: alloc returns 0/1/2 indices, active_count tracking, free decreases count, CallOp dispatch, alloc-free-alloc reuses lowest freed index, free on nonexistent pool is no-op, double-free is idempotent, alloc after free-all returns 0, active_count after alloc-free-alloc cycle
- **Fixed slot**: set/get, get on unset returns 0, overwrite, clear, multiple independent indices, CallOp dispatch
- **Collection isolation**: different names have independent state
- **Unknown functions**: return 0 without throwing (backward compatible)

## Decisions Made

1. **Synthetic CallExpr in executeCallOp**: Rather than duplicating the dispatch logic, `executeCallOp` constructs a `CallExpr(op.function, op.args)` and calls `evaluateCallExpr`. This shares all collection logic between the expression and statement call paths.

2. **Pool backed by hashTables with prefix**: Pool collections use the existing `hashTables` map with a `__pool_` prefix (e.g., `__pool_bullets`). This avoids adding a fourth collection type for a simple alloc/free tracker while keeping namespaces separate from user-defined hash tables.

3. **evaluateCallExpr refactored to condition-guard when**: Changed from `when(expr.function) { ... }` to `when { fn.startsWith(...) && fn.endsWith(...) -> ... }` to support the compound prefix+suffix matching required by collection naming conventions.
