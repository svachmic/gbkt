    **1. Create CombatVisitor.kt** in `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/visitor/`:

    Class: `CombatVisitor(private val gameIR: GameIR)` — generates C functions for a CombatEngineSystem.

    Method `fun generateCombatFunctions(system: CombatEngineSystem): List<CFunction>` returns these C functions:

    **a) `combat_request_state_<id>(UINT8 s)`** — sets `_pending_state_<id> = s`
    - Single CExprStatement assigning parameter to pending global
    - Uses typed C AST: `CExprStatement(CBinaryExpr("=", CVar("_pending_state_${id}"), CVar("s")))`

    **b) `update_combat_<id>(void)`** — main per-frame update function:
    - First block: deferred transition application:
      ```
      if (_pending_state_<id> != 0xFF) {
          _combat_state_<id> = _pending_state_<id>;
          _pending_state_<id> = 0xFF;
      }
      ```
      Use `CIf` with `CBinaryExpr("!=", CVar("_pending_state_${id}"), CLiteral(0xFF))`.
    - Second block: declarative condition checking (before the switch):
      - If `system.onVictoryCondition` is non-empty: emit `if (<condition_ops>) { combat_request_state_<id>(3u); }` — checks victory predicate each frame, auto-transitions to VICTORY when true
      - If `system.onDefeatCondition` is non-empty: emit `if (<condition_ops>) { combat_request_state_<id>(4u); }` — checks defeat predicate each frame, auto-transitions to DEFEAT when true
      - Condition ops are converted to C expressions via ExprVisitor (same pattern as `whenever()` conditions in scene codegen)
    - Third block: `CSwitch` on `_combat_state_<id>` with cases:
      - Case 0 (INIT): `_combat_state_<id> = 1u; break;` — auto-advance to PLAYER_TURN
      - Case 1 (PLAYER_TURN):
        - TURN_BASED: `if (button_pressed(J_A)) { combat_request_state_<id>(2u); }` then break
        - REAL_TIME: no J_A check — player logic runs every frame, then request transition to ENEMY_TURN
      - Case 2 (ENEMY_TURN): `combat_request_state_<id>(1u); break;` — simple back-to-player
      - Case 3 (VICTORY): emit `onVictoryOps` via ScriptOpVisitor, then break
      - Case 4 (DEFEAT): emit `onDefeatOps` via ScriptOpVisitor, then break
      - Cases 5+ (customStates): empty body with comment `/* custom: <stateId> */`, then break
      - Sub-state cases: for each entry in `system.stateHierarchy`, generate child state cases with a nested switch or flat case numbering (implementation: assign child states sequential IDs after custom states, e.g. parent PLAYER_TURN=1 has children at IDs 64+). Include a comment `/* sub-state of <parentId>: <childId> */` for readability
    - Use `CSwitchCase` for each case. Use `ScriptOpVisitor.visit()` to convert onVictory/onDefeat ScriptOp lists to CStatement lists.
    - Follow C89 rules: no variable declarations after statements inside cases.

    **c) `combat_is_in_state_<id>(UINT8 state)`** — returns `_combat_state_<id> == state`
    - Return type: CU8 (UINT8 for boolean result on Game Boy)
    - Body: `CReturn(CBinaryExpr("==", CVar("_combat_state_${id}"), CVar("state")))`

    **d) `combat_parent_state_<id>(UINT8 state)`** — returns the parent state ID for a given state (only generated when `stateHierarchy` is non-empty):
    - Returns the parent state ID via switch: each child state maps to its parent ID
    - For top-level states, returns the state itself
    - Enables RPG/game code to check "am I in any sub-state of PLAYER_TURN?" via `combat_parent_state_<id>(current) == 1u`

    **e) `trigger_<id>(void)`** — resets combat to INIT and clears pending:
    - `_combat_state_<id> = 0u;`
    - `_pending_state_<id> = 0xFFu;`

    **f) `damage_<id>(UINT8 src, UINT8 tgt, UINT8 amount)`** — damage formula dispatcher (only generated when `damageFormula != null`):
    - If `system.damageFormula` is non-null, emit a function that calls the user-provided C function by name:
      ```c
      UINT8 damage_<id>(UINT8 src, UINT8 tgt, UINT8 amount) {
          return <damageFormula.functionName>(src, tgt, amount);
      }
      ```
    - If `system.damageFormula` is null, skip — no damage function generated
    - The referenced function is a user-defined extern C function. Add a forward declaration: `extern UINT8 <functionName>(UINT8 src, UINT8 tgt, UINT8 amount);` to the header file output
    - Uses CReturn with CCall node. The user provides the formula implementation; engine just dispatches to it.

    Add MPL-2.0 license header. Import ScriptOpVisitor and ExprVisitor from same codegen/visitor package for op conversion.

    **2. Update GBDKSystemVisitor.kt** — replace the stub `visitCombatEngineSystem`:
    - Replace `emptyList()` stub with: `CombatVisitor(gameIR).generateCombatFunctions(system)`
    - Add import for CombatVisitor
    - Keep existing `buildSimpleBattleFunctions()` untouched — add comment: `// TODO 06.5: migrate simpleBattle to CombatEngineSystem`

    **3. Update GBDKPipelineV2.kt** `buildSystemGlobalVars()`:
    - Find where `simple_battle` generates `_combat_state_<id>` global. Use `mcp__serena__search_for_pattern("_combat_state")` to find the exact location.
    - Add a parallel block: when system is `CombatEngineSystem`, emit:
      - `CVarDecl("_combat_state_${id}", CU8, init=CLiteral(0))` — INIT state
      - `CVarDecl("_pending_state_${id}", CU8, init=CLiteral(0xFF))` — no pending transition sentinel
    - Also add combat globals to `buildHeaderFile()` as extern declarations so banked scene functions can read state.

    **Key C89 considerations:**
    - All loop variables declared before use (CVarDecl before CFor with init=null)
    - unsigned literal suffix: CLiteral(0xFF) emits as "255u" per CEmitter convention
    - No function pointers — all dispatch via switch (project convention)
