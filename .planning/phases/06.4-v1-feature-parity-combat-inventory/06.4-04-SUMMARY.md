## Decisions Made

- Delegate tests use explicit-id variants (`combatEngine("combat", block)`) instead of property delegate syntax (`val combat by combatEngine { }`) — Kotlin's `provideDelegate` operator is only called for class-level property delegates, not for local variables inside lambdas. Since tests are methods (not class properties), `provideDelegate` is never called and `getValue` throws. Using explicit-id avoids false failures without changing production code.
- Menu InventoryDataSource `printf` format changed from `%s` to `%u` — item IDs are `UINT8` integers, not strings; `%s` would cause undefined behavior in C.
- gbkt-bom and gbkt-all confirmed adequate — `gbkt-engine` constraint and `api(project(":gbkt-engine"))` already cover all combat/inventory engine types; no new module entries needed.
