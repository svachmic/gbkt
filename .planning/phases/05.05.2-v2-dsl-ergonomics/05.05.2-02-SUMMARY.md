# Phase 05.05.2 Plan 02: Example Game Migration + API Deprecation Summary

All three example games migrated from assembly-style assign/varRef/literal DSL to Kotlin-idiomatic delegate operators, actor property access, and bracket array syntax; old API deprecated with DeprecationLevel.WARNING.

## What Was Built

### Task 1: Migrate All Three Example Games

**PongV2.kt:** Fully migrated to Kotlin-idiomatic syntax.
- `assign("ballDx", literal(1))` → `ballDx set 1`
- `assign("ball.x", varRef("ball.x") + varRef("ballDx"))` → `ball.x += ballDx`
- `varRef("paddle1.y") isAbove literal(16)` → `paddle1.y isAbove 16`
- `setPosition(ball.id, 80, 72)` → `ball.moveTo(80, 72)`
- `varRef("p1Score")` in print → `p1Score.toExpr()`
- `@Suppress("UNUSED_VARIABLE")` removed from all variable declarations
- All 4 variables now use clean `var score by u8Var(0)` form

**BreakoutV2.kt:** Fully migrated including complex array and bitwise patterns.
- `BinaryExpr(varRef("ball.x") - literal(40), BinaryOp.SHR, literal(3))` → `(ball.x - 40) shr 3`
- `arrayAssign("bricks", varRef("bidx"), literal(0))` → `bricks[bidx] = 0`
- `arrayRef("bricks", varRef("bidx")) isEqualTo literal(1)` → `bricks[bidx] isEqualTo 1`
- `BinaryExpr`/`BinaryOp` imports removed from game file
- Brick initialization changed from `forOp("bi", ...)` to `whileOp + bidx` (see Deviations)
- `lives -= 1` replaces `assign("lives", varRef("lives") + literal(-1))`
- `ballDy *= -1` replaces `assign("ballDy", varRef("ballDy") * literal(-1))`

**ExplorerV2.kt:** Fully migrated including bitwise torch logic and combat scene.
- `(varRef("stepCount") and literal(3)) isEqualTo literal(0)` → `(stepCount and 3) isEqualTo 0`
- `ifOp(varRef("hp") isAbove literal(3)) { assign("hp", ...) }` → `ifOp(hp isAbove 3) { hp -= 3 }`
- `varRef("hp")` in print → `hp.toExpr()`
- Combat scene: assign/varRef → set/compound ops

**ExprBuilder.kt missing overloads added (Rule 2 auto-fixes):**
- `Expr.shr(Int)` and `Expr.shl(Int)` — for `(ball.x - 40) shr 3` pattern
- `Expr.plus/minus/times/div/rem(AssignableVar)` and `(ActorPropertyRef)` — for `brow * 10 + bc`
- `Expr.isAbove/isBelow/isAtLeast/isAtMost/isEqualTo/isNotEqualTo(AssignableVar)` and `(ActorPropertyRef)` — for cross-type conditions

**ActorBuilder.kt missing overloads added (Rule 2 auto-fixes):**
- `ActorPropertyRef.isAbove/isBelow/isAtLeast/isAtMost/isEqualTo/isNotEqualTo(ActorPropertyRef)` — for `ball.y isAtLeast paddle.y` pattern

### Task 2: Deprecate Old API + Update Tests + Update Docs

**ScriptBuilder.kt deprecations (DeprecationLevel.WARNING):**
- `assign()` — message: "Use variable delegate operators: `score set 0`, `score += 1`, `ball.x += ballDx`"
- `arrayAssign()` — message: "Use array bracket syntax: `arr[i] = value`"
- `arrayRef()` — message: "Use array bracket syntax: `arr[i]`"
- `raw()` — message: "raw() is an escape hatch for C code. Consider adding DSL support instead."

**ExprBuilder.kt deprecations (DeprecationLevel.WARNING):**
- `literal()` — message: "Integer literals are auto-wrapped. Use the raw Int value directly."
- `varRef()` — message: "Use variable delegates directly: `var score by u8Var(0)` then use `score`."

**ScriptBuilderTest.kt:** Added `@Suppress("DEPRECATION")` to class declaration — these tests verify the internal ScriptBuilder contract, not the public DSL surface.

**CLAUDE.md Quick DSL Examples section:** Completely rewritten to show v2 syntax:
- Variable delegate pattern with all assignment operators
- Actor property access (`ball.x += ballDx`, `ball.moveTo(80, 72)`)
- Array bracket syntax (`bricks[bidx] = 0`, `bricks[bidx]`)
- Cross-type comparisons (`ball.y isAtLeast paddle.y`)
- Increment/decrement (`score++`, `--lives`)
- NOTE at end marking old API as deprecated

**context/DSL_REFERENCE.md:** Added/updated sections:
- Variables section rewritten with all operator forms and DEPRECATED note
- New "Arrays" section with bracket read/write, exists(), size
- New "Actors (v2 DSL)" section with ActorRef.x/y/visible, moveTo(), collides()
- Readable Comparisons section updated with cross-type examples and logicalAnd/logicalOr

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Overloads] Added Expr/ActorPropertyRef cross-type comparison and arithmetic overloads**
- **Found during:** Task 1 compilation of PongV2.kt and BreakoutV2.kt
- **Issue:** `(paddle2.y + 8) isAbove ball.y` failed — `Expr.isAbove(ActorPropertyRef)` did not exist. `brow * 10 + bc` failed — `Expr.plus(AssignableVar)` did not exist. `Expr.shr(Int)` did not exist.
- **Fix:** Added all missing overloads to ExprBuilder.kt and ActorBuilder.kt covering all arithmetic and comparison combinations between Expr, AssignableVar, and ActorPropertyRef
- **Files modified:** `ExprBuilder.kt`, `ActorBuilder.kt`
- **Commit:** 97bd5c5

**2. [Rule 1 - Design Constraint] Replaced forOp("bi",...) with whileOp + bidx for brick initialization**
- **Found during:** Task 1 — plan said `bricks[bi] = 1` but `bi` is a for-loop string variable, not an `AssignableVar` delegate
- **Issue:** forOp creates a C `uint8_t bi` loop variable with no `AssignableVar` handle; inside the body, only `varRef("bi")` (deprecated) could reference it
- **Fix:** Changed initialization to `whileOp(bidx isBelow bricks.size) { bricks[bidx] = 1; bidx += 1 }` using the already-declared `bidx` variable
- **Files modified:** `BreakoutV2.kt`
- **Commit:** 97bd5c5

### Out-of-Scope Issues (Pre-existing, Not Fixed)

The `gbkt-core:test` suite has a pre-existing compilation failure in `IRHierarchyTest.kt` — `ScriptOpDescriber` does not implement `visitGotoXYOp`. This was documented in Plan 01 SUMMARY and is unrelated to Phase 05.05.2 changes. All other modules build and their tests pass.
