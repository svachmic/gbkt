  <action>
    Read each example game file fully to understand its structure before migrating. Apply these transformations systematically:

    **Universal transformations (all 3 games):**

    1. **Remove `@Suppress("UNUSED_VARIABLE")`** from variable declarations — delegates are now used directly, so the suppression is no longer needed.

    2. **`assign("name", expr)` → delegate operator:**
       - `assign("score", literal(0))` → `score set 0`
       - `assign("score", varRef("score") + literal(1))` → `score += 1`
       - `assign("ball.x", varRef("ball.x") + varRef("ballDx"))` → `ball.x += ballDx`
       - `assign("ball.y", literal(80))` → `ball.y set 80`
       - For compound operations: identify the AssignOp and use the matching operator (+=, -=, *=)

    3. **`varRef("name")` → delegate reference:**
       - `varRef("score")` → `score` (the AssignableVar itself, calls toExpr() implicitly via operator overloads)
       - `varRef("ball.x")` → `ball.x` (the ActorPropertyRef, calls toExpr() implicitly)

    4. **`literal(N)` → raw Int:**
       - `literal(5)` → `5` (works because all operators accept Int overloads)
       - In comparison operators: `varRef("score") isAtLeast literal(5)` → `score isAtLeast 5`
       - In `setPosition`: `setPosition("ball", literal(80), literal(72))` → `ball.moveTo(80, 72)`

    5. **`forOp("var", literal(N), literal(M))` → `forOp("var", N, M)`:**
       - Use the new Int-accepting overload added in Plan 01

    **PongV2.kt specific:**
    - Replace all `assign("ballDx", ...)`, `assign("ball.x", ...)` etc. with delegate ops
    - `setPosition("ball", ...)` → `ball.moveTo(80, 72)` (if applicable) or keep as actor property sets
    - All `varRef("p1Score")`, `varRef("p2Score")` → `p1Score`, `p2Score`
    - All `whenever(varRef(...) isAbove literal(...))` → `whenever(ball.x isAbove 160)`

    **BreakoutV2.kt specific:**
    - `u8Array("bricks", 30)` → `u8Array(30)` (name inferred from property name `bricks`)
    - `arrayAssign("bricks", varRef("bi"), literal(1))` → `bricks[bi] = 1` (where `bi` is `AssignableVar`)
    - `arrayRef("bricks", varRef("bidx"))` → `bricks[bidx]`
    - `BinaryExpr(varRef("ball.x") - literal(40), BinaryOp.SHR, literal(3))` → `(ball.x - 40) shr 3` (using existing `shr` infix on Expr + ActorPropertyRef.minus(Int) returning Expr)
    - Remove direct `BinaryExpr`/`BinaryOp` imports — these are IR types that should not appear in game code

    **ExplorerV2.kt specific:**
    - Same variable/literal/assign transformations
    - `varRef("hp") isAbove literal(0)` → `hp isAbove 0`
    - Explorer uses `logicalAnd`/bitwise `and` — these should work with AssignableVar extensions
    - Combat scene `assign`/`varRef` calls migrated to delegate ops
    - `dpadAny()` and `delay(N)` calls remain unchanged (they are ScriptBuilder methods, not affected)

    **Verification approach for each game:**
    1. Before migrating, run `./gradlew :gbkt-examples:pong:generateC` and save the C output for comparison
    2. After migrating, run `./gradlew :gbkt-examples:pong:generateC` and verify the C output is functionally equivalent (structural differences are acceptable per CONTEXT.md, but variable names and logic flow must match)

    **WARNING:** Do NOT change any ScriptBuilder method calls that are NOT in the transformation list (e.g., `navigate()`, `showDialog()`, `playSound()`, `fade()`, `delay()`, `raw()` if any remain). Only change the five patterns: assign→delegate, varRef→delegate, literal→Int, arrayAssign→bracket, arrayRef→bracket.
