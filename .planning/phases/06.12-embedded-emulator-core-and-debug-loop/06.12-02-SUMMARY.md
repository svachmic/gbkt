## Decisions Made

- **registerTickListener vs manual tick wrap:** Used `gameboy.registerTickListener(Runnable)` instead of calling `onTick?.invoke()` after each `gameboy.tick()` call manually. Coffee-GB's `registerTickListener` fires from inside `tick()` which is cleaner and correct.
- **EventBus.NULL_EVENT_BUS:** Headless mode uses the null event bus. Frame completion is detected via `gameboy.tick()` returning `true` — no need to subscribe to `DmgFrameReadyEvent`. The pixel buffer is updated by Coffee-GB's `Display` class internally.
- **GameboyType.DMG + BootstrapMode.SKIP:** Fastest startup for tests. SKIP bypasses Nintendo logo validation, making minimal 32KB test ROMs work without embedding the real logo bytes.
- **Minimal test ROM strategy:** A 32KB ByteArray with cartridge type 0x00 (ROM ONLY), zeroed body, and correct header checksum satisfies Coffee-GB's `Rom` parser. No real game needed for lifecycle tests.

## Issues Encountered

- **Coffee-GB Display pixel API is package-private:** `putDmgPixel` and `putColorPixel` on `Display` are package-private in Java, so we cannot subclass or override them from Kotlin. Frame data is instead captured by subscribing to the EventBus `DmgFrameReadyEvent` or via `tick()` returning true and using the internal buffer state. For headless operation, `EventBus.NULL_EVENT_BUS` is used and frame buffer updates are managed internally by Coffee-GB — the `Display` class writes pixels to its internal `int[]` buffer, and `frameIsReady()` fires an event. Since we use NULL_EVENT_BUS, we detect frame completion from `tick()` returning `true` rather than from events.
