## Decisions Made
- Used `() -> MemoryAccess?` provider lambda instead of storing a direct reference — allows safe null return when emulator is stopped mid-session
- Exposed `HexViewTab.buildDump()` as `internal fun` for unit testing without needing Swing repaint
- Default hex view starts at 0xC000 WRAM since that is where GBDK global variables (score, lives, etc.) are allocated
- SEPARATOR constant in HexViewTab was hardcoded as a string literal (Rule 1 auto-fix: `String.padEnd()` is not a Kotlin compile-time constant)
