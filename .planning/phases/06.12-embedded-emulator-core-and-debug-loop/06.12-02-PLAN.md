<objective>
Implement `CoffeeGbEmulator` — the headless core that wraps Coffee-GB's `Gameboy` class. This is the engine that all other features (display, debug log, Gradle tasks) build on.

Purpose: Provides a working headless emulator that can load and run Game Boy ROMs on the JVM. Headless-first design ensures CI and automated testing work before any GUI is added.
Output: `CoffeeGbEmulator` class that starts/stops/pauses/resumes/steps ROMs, captures frame buffer, manages emulator thread lifecycle.

CRITICAL DESIGN DECISION: The emulator MUST use a custom `tick()` loop on the daemon thread — NOT `gameboy.run()`. Three downstream features depend on tick-level control:
1. EMU_printf interception (Plan 03) — must check opcode after each instruction
2. Speed multiplier — must adjust sleep duration between frame completions
3. stepFrame() — must run tick() until one frame completes, then stop

Using `gameboy.run()` would block the thread with no way to intercept individual ticks, breaking all three features.
</objective>

1. **Constructor:** Takes `EmulatorConfig`. Stores config, initializes empty debug log.

2. **start():**
   - Load ROM via `Rom.of(config.romFile)` (Coffee-GB's ROM loader)
   - Build `GameboyConfiguration` with ROM
   - Create `Gameboy(configuration)`
   - Create an `EventBusImpl` for frame events
   - Implement Coffee-GB's `Display` interface to capture pixel data into an `IntArray(160 * 144)`. The `putDmgPixel` and `putColorPixel` methods write RGB data to a pixel buffer. `frameIsReady()` copies the buffer to the public frame buffer (double-buffered to avoid tearing) and invokes `onFrameReady` callback.
   - Call `gameboy.init(eventBus, NullSerialEndpoint, NullConsole)` — these are no-ops for headless
   - Note: Coffee-GB may not have `NullSerialEndpoint` and `NullConsole` — check the API. If not available, create minimal no-op implementations.
   - Launch the **custom tick loop** on a daemon thread named "gbkt-emulator" (see step 2a)
   - Set `running = true`
   - This method is NON-BLOCKING — it returns immediately after launching the thread

2a. **Custom tick loop (CRITICAL — do NOT use gameboy.run()):**
   The daemon thread runs this loop instead of `gameboy.run()`:
   ```kotlin
   private fun emulatorLoop() {
       val targetFrameNanos = 16_742_706L  // ~59.7 FPS (1 second / 59.7275)
       var lastFrameTime = System.nanoTime()

       while (running) {
           if (paused) {
               Thread.sleep(10)  // Yield while paused
               lastFrameTime = System.nanoTime()  // Reset timing on unpause
               continue
           }

           // Run one micro-op tick
           val frameDone = gameboy.tick()

           // After each tick, invoke the per-tick callback (Plan 03 hooks here)
           onTick?.invoke()

           if (frameDone) {
               // Frame complete — notify listeners
               onFrameReady?.invoke(getFrameBuffer())

               // Speed control: sleep to maintain target frame rate
               val now = System.nanoTime()
               val elapsed = now - lastFrameTime
               val targetNanos = (targetFrameNanos / speedMultiplier).toLong()
               val sleepNanos = targetNanos - elapsed
               if (sleepNanos > 0) {
                   Thread.sleep(sleepNanos / 1_000_000, (sleepNanos % 1_000_000).toInt())
               }
               lastFrameTime = System.nanoTime()
           }
       }
   }
   ```
   Key points:
   - `tick()` runs one micro-op, NOT one full instruction. A single Game Boy instruction takes 1-6 micro-ops. One frame = ~69,905 T-cycles.
   - `onTick` is a nullable callback that Plan 03 (EmuPrintfInterceptor) will wire to check for the ld d,d trap. It fires after every tick, so the interceptor must be fast (quick-reject on opcode != 0x52).
   - Speed control: at 1x, sleep to maintain 59.7 FPS. At 2x, halve the sleep. At 4x, quarter it. At speeds >= 4x, there's effectively no sleep (CPU-bound).
   - `paused` is a volatile boolean checked each iteration.

3. **stop():**
   - Set `running = false`
   - Join emulator thread with 2-second timeout
   - Call `gameboy.close()` (flushes battery saves)

4. **pause()/resume():**
   - Set/clear the `paused` volatile boolean
   - Do NOT delegate to `gameboy.pause()` / `gameboy.resume()` — we own the pause logic in our tick loop

5. **stepFrame():**
   - Only valid when `paused` is true (caller must pause first — enforced by toolbar disabling the Step button when running)
   - Run `gameboy.tick()` in a tight loop until it returns true (one full frame)
   - After each tick, invoke `onTick` callback (so EMU_printf interceptor still works during stepping)
   - After frame completes, invoke `onFrameReady` callback
   ```kotlin
   override fun stepFrame() {
       check(paused) { "stepFrame() requires the emulator to be paused" }
       do {
           val frameDone = gameboy.tick()
           onTick?.invoke()
       } while (!frameDone)
       onFrameReady?.invoke(getFrameBuffer())
   }
   ```

6. **setSpeed(multiplier: Float):**
   - Store in a `@Volatile var speedMultiplier: Float = 1.0f`
   - The custom tick loop reads this value on each frame completion to calculate sleep duration
   - Values: 1.0 = normal (59.7 FPS), 2.0 = double speed, 4.0 = quad speed
   - No upper bound enforcement needed — the loop simply skips sleeping at high multipliers

7. **getFrameBuffer():**
   - Return a copy of the current pixel buffer (160*144 IntArray)
   - Use `synchronized(frameBufferLock)` for the copy to avoid tearing

8. **getMemory():**
   - Return a `MemoryAccess` implementation that delegates to Coffee-GB's `AddressSpace`
   - `readByte(address)` -> `addressSpace.getByte(address)` (mask to 0xFF)
   - `writeByte(address, value)` -> `addressSpace.setByte(address, value)`
   - If the emulator is not started, throw `IllegalStateException("Emulator not started")`

9. **getDebugLog():**
   - Return `debugLog.toList()` (thread-safe copy)
   - The debug log is populated by `EmuPrintfInterceptor` (Plan 03) via `addDebugEntry`

10. **isRunning() / isHeadless:**
    - `isRunning()` returns the `running` volatile boolean
    - `isHeadless` returns `config.headless`

11. **Thread safety:**
    - `@Volatile` for `running`, `paused`, and `speedMultiplier`
    - Frame buffer: `synchronized(frameBufferLock)` for double-buffer swap
    - Debug log: use a `ConcurrentLinkedDeque` or synchronized list with bounded size

12. **Callback hooks (for Plan 03 and Plan 09 to wire):**
    ```kotlin
    var onTick: (() -> Unit)? = null           // Plan 03: EMU_printf check per tick
    var onFrameReady: ((IntArray) -> Unit)? = null  // Plan 09: display update
    var onDebugEntry: ((DebugLogEntry) -> Unit)? = null  // Plan 09: log routing
    ```

13. **addDebugEntry(entry: DebugLogEntry):**
    - Internal method (not on interface) for the interceptor to call
    - Adds to in-memory bounded list (drop oldest if > maxLogEntries)
    - Invokes `onDebugEntry` callback
    - If `config.logFile` is set, append to file with auto-flush

IMPORTANT: Do NOT implement the `ld d,d` trap detection in this class. That belongs in Plan 03 (EmuPrintfInterceptor). This class provides the `onTick` callback hook and `addDebugEntry` method for Plan 03 to use.

IMPORTANT: Coffee-GB's exact API may differ slightly from research. Read the actual imported classes to determine correct constructor/method signatures. The research was verified from GitHub source but the Maven artifact may have minor differences.
