# Phase 06.12 Plan 05: GbDisplayPanel and InputHandler Summary

**One-liner:** Swing framebuffer panel with nearest-neighbor 4x scaling + EventBus keyboard input handler for 8 Game Boy buttons.

## What Was Built

### GbDisplayPanel

A `JPanel` subclass that accepts `IntArray` framebuffer snapshots from the emulator and renders them at 4x scale (640x576 default). Key design points:

- Thread-safe: `onFrame()` copies pixel data under a lock, then schedules `repaint()` on EDT via `SwingUtilities.invokeLater`. No UI calls from the emulator thread.
- Nearest-neighbor interpolation via `RenderingHints.VALUE_INTERPOLATION_NEAREST_NEIGHBOR` — pixel art stays crisp at any scale factor.
- Aspect-ratio preservation: computes `minOf(panelW / 160.0, panelH / 144.0)` and centers the image with black bars.
- Wires into `CoffeeGbEmulator.onFrameReady` callback.

### InputHandler

A `KeyListener` that maps 8 keyboard keys to Coffee-GB joypad events:

| Key       | Game Boy Button |
|-----------|-----------------|
| Arrow Up  | UP              |
| Arrow Down | DOWN           |
| Arrow Left | LEFT           |
| Arrow Right | RIGHT         |
| Z         | A               |
| X         | B               |
| Enter     | START           |
| Backspace | SELECT          |

Posts `ButtonPressEvent`/`ButtonReleaseEvent` to the shared `EventBus`. Coffee-GB's `Joypad` class subscribes to these events and updates hardware registers + fires interrupt $60.

`mapKey()` is `internal` to enable direct unit testing without constructing `KeyEvent` objects.

### InputHandlerTest

16 tests covering:
- All 8 key-to-button mappings via `mapKey(keyCode)`
- 3 unmapped keys returning `null` (Q, Escape, Space)
- `keyPressed()` / `keyReleased()` posting correct `ButtonPressEvent` / `ButtonReleaseEvent` for all 8 buttons
- Unmapped keys posting no events
- Rapid press accumulation preserving order

Uses a recording `EventBus` stub — no Swing headful environment or real Coffee-GB instance needed.
