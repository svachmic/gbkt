# Phase 06.12 Plan 06: EmulatorWindow and EmulatorToolbar Summary

**One-liner:** Swing JFrame shell composing GbDisplayPanel + developer toolbar with pause/step/speed/log/memory controls and per-second FPS title bar updates.

## Objective

Build the main developer-facing emulator window (JFrame) and a discoverable toolbar with pause/resume, step frame, speed 1x/2x/4x, log viewer toggle, and memory inspector toggle buttons.

## What Was Built

### EmulatorToolbar.kt

Non-floatable `JToolBar` with:
- **Pause/Resume button** — calls `emulator.pause()` or `emulator.resume()`, updates button text, enables/disables Step
- **Step button** — calls `emulator.stepFrame()`, starts disabled (only active when paused)
- **Speed toggle group** — `1x` / `2x` / `4x` buttons in a `ButtonGroup` (mutually exclusive), default 1x; each calls `emulator.setSpeed(multiplier)`
- **Log toggle** — fires `onLogViewerToggle` callback (nullable lambda) on state change
- **Memory toggle** — fires `onMemoryInspectorToggle` callback on state change
- **`updatePauseState(paused: Boolean)`** — external sync from keyboard shortcuts, dispatches to EDT via `SwingUtilities.invokeLater`

### EmulatorWindow.kt

Main `JFrame` with:
- `BorderLayout` composing `EmulatorToolbar` (NORTH), `GbDisplayPanel` (CENTER), `JLabel` status bar (SOUTH)
- Title: `"gbkt - {romName} | 0.0 FPS | Frame 0"` updated every second via `javax.swing.Timer`
- `defaultCloseOperation = DO_NOTHING_ON_CLOSE` + `WindowAdapter.windowClosing` → calls `fpsTimer.stop()`, `emulator.stop()`, `dispose()`
- Global keyboard shortcuts via `KeyboardFocusManager.addKeyEventDispatcher`: Space (pause/resume), F10 (step when paused)
- `startFpsTimer()` — activates the 1s title bar update loop
- `onFrameReady(frameData)` — increments frame counter and delegates to `displayPanel.onFrame()`
- `setStatus(text)` — updates status bar from any thread
- `toolbar` and `displayPanel` exposed as public `val` for callers to wire input and callbacks

### EmulatorToolbarTest.kt

18 unit tests covering:
- Initial button states (Pause text, Step disabled, 1x selected)
- Pause → button shows Resume, step becomes enabled
- Resume → button shows Pause, step becomes disabled
- Step button click calls `emulator.stepFrame()`
- Speed buttons call `emulator.setSpeed()` with correct float
- Memory and Log toggle callbacks fire with correct boolean values
- `updatePauseState(true/false)` syncs button state with EDT pump

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing security/correctness] InputHandler not wired in EmulatorWindow constructor**

- **Found during:** Task 2 implementation
- **Issue:** Plan's action code had `addKeyListener(InputHandler(/* controller from emulator */))` placeholder. `InputHandler` requires an `EventBus` which is not exposed on the `GbEmulator` interface — the window has no way to construct it.
- **Fix:** `EmulatorWindow` sets `isFocusable = true` so callers can add `KeyListener` externally with their `EventBus`. This is the correct design since the caller constructs both the emulator and input handler.
- **Files modified:** `EmulatorWindow.kt`
