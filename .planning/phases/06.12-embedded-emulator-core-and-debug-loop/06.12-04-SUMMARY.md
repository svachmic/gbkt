# Phase 06.12 Plan 04: Source Map Resolution and Debug Log Writing Summary

Source map resolution and real-time debug log file writing using .gbkt.map JSON files and auto-flushed PrintWriter.

## What Was Built

**SourceMapResolver** (`gbkt-emulator/src/main/kotlin/io/github/gbkt/emulator/debug/SourceMapResolver.kt`)
- Loads all `.gbkt.map` JSON files from a configured directory at construction time
- Builds an in-memory `Map<Int, SourceLocation>` from C line numbers to Kotlin DSL locations
- `resolve(cLine: Int)` returns `SourceLocation?` with file, line, symbol, and context fields
- Handles null/missing directories, empty directories, malformed JSON, and non-map files gracefully
- Used by `CoffeeGbEmulator.addDebugEntry()` to enrich entries before they reach the in-memory log

**DebugLogWriter** (`gbkt-emulator/src/main/kotlin/io/github/gbkt/emulator/debug/DebugLogWriter.kt`)
- Wraps `PrintWriter(BufferedWriter(FileWriter(logFile, false)), true)` — overwrite mode with autoFlush
- Creates parent directories automatically (enables `build/gbkt/logs/` to not pre-exist)
- Each `write(entry)` calls `entry.formatted()` and then `flush()` for guaranteed real-time visibility
- Implements `Closeable` for use in try-with-resources / Kotlin `use {}` blocks

**CoffeeGbEmulator wiring:**
- Added `SourceMapResolver` field initialized from `config.sourceMapsDir`
- Replaced raw `bufferedWriter()` with `DebugLogWriter` for `config.logFile`
- `addDebugEntry()` now enriches entries: when `cLine` is set and `kotlinFile` is null, resolves location and calls `entry.copy()` with the Kotlin file, line, and context
- `stop()` now calls `logWriter?.close()` (DebugLogWriter.close() handles flush internally)

## Test Coverage

**SourceMapResolverTest** (9 tests):
- `resolve` returns correct Kotlin location for mapped C line
- `resolve` returns null for unmapped C line (999, 0, -1)
- Optional fields (symbol, snippet) default to empty string when absent
- Null sourceMapsDir — all resolves return null
- Non-existent directory — all resolves return null
- Empty directory — all resolves return null
- Multiple .gbkt.map files are all loaded (entries from both files resolvable)
- Non-.gbkt.map files in directory are ignored
- Malformed JSON files are silently skipped (valid files still loaded)

**DebugLogWriterTest** (10 tests):
- Correct format with full source map info (file:line, context, message, timestamp)
- Correct format without source map info (no .kt: prefix)
- Correct format with context but no source map
- Multiple writes produce multiple lines
- New DebugLogWriter overwrites existing file content (fresh per run)
- Parent directories created automatically
- close() flushes remaining data to disk
- use block closes writer automatically
- Timestamp format [MM:SS.mmm] for 90500ms → [01:30.500]
- Zero timestamp formats as [00:00.000]
