    **PongGameTest.kt (new file, 2-3 scenarios):**

    Test structure:
    - Build `GameIR` from `pongV2` DSL once per class (companion object or `@BeforeAll`)
    - Create fresh `SimulationContextV2(ir)` per test method
    - Each test enters the "game" scene, sets up initial state via `setVar()`, advances frames, and asserts outcomes

    Scenarios (choose based on actual PongV2 game logic — read the DSL first):
    1. **Ball bounces off wall** — Set ball near top/bottom wall, set velocity toward wall, advance 1-2 frames, verify velocity direction reversed
    2. **Score increments when ball exits** — Set ball near screen edge (left or right), advance frames until it crosses boundary, verify correct player's score incremented
    3. **Win condition triggers scene change** — Set score to just below win threshold, trigger the scoring event, verify scene changes to gameover

    Guidelines per pitfall 5 (5-second budget):
    - Keep frame counts to 1-30 per scenario
    - `build()` called once per test class, not per test
    - Use `setVar()` to force initial conditions rather than simulating many frames to reach them

    **BreakoutGameTest.kt (new file, 2-3 scenarios):**

    Same structure — build from `breakoutV2` DSL.

    Scenarios (choose based on actual BreakoutV2 game logic — read the DSL first):
    1. **Ball bounces off paddle** — Position ball near paddle, set downward velocity, advance frames, verify upward velocity after bounce
    2. **Score updates on brick hit** — Position ball near brick zone with appropriate velocity, advance frames, verify score incremented or bricksLeft decremented
    3. **Ball reset when exiting bottom** — Position ball below paddle, advance frames, verify ball position resets to center or lives decremented

    Guidelines:
    - Use standard JUnit 5 `assertEquals` alongside `sim.assertVar()` (locked decision: both work out of the box)
    - Enable tracing on at least one test to verify trace log works: `sim.enableTracing()` at start, `sim.getTraceLog()` assertion at end
