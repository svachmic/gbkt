    **ProcessAssetsTask.kt — replace stub with real processing:**

    Replace `processSprite()` stub (currently writes `.processed` marker files) with real processing logic:

    1. **PNG processing** (`processSprite` or `processPng` method):
       - Read PNG via `javax.imageio.ImageIO.read(file)` (already used in AssetPipeline.kt)
       - Extract palette using `AssetPipeline.extractPalette()` (auto-quantize mode by default per locked decision)
       - Convert image to tile data via `AssetPipeline.convertImage()`
       - Deduplicate tiles via `TileDeduplicator.deduplicate()`
       - Write raw 2bpp tile data to output directory as `.2bpp` file
       - Compute sprite sheet frame metadata: `frameCount = (sheetWidth / frameWidth) * (sheetHeight / frameHeight)` where frame dimensions come from the image dimensions or default to 8x8
       - Build `SpriteEntry` for manifest with tileCount, uniqueTileCount, widthInTiles, heightInTiles, palette, frameWidth, frameHeight, frameCount
       - On failure: throw `GradleException("Asset validation failed: $filePath — $errorDetail")` per locked decision (fail on first invalid asset)

    2. **TMX processing** (`processTmx` method):
       - Parse via `TiledParser.parse(file)` (pass `File` directly — TiledParser has a `parse(File): TiledMap` overload)
       - Do NOT call `TiledParser.parse(file.readText())` — the `parse(String)` overload interprets the string as a file path, not content
       - Detect collision layers via `layer.isCollisionLayer` (uses `gbkt_collision=true` custom property from Plan 03-01)
       - Extract tile data and collision mask
       - Build `TilemapEntry` for manifest with width, height, hasCollision, tilesetPath

    3. **LDtk processing** (`processLdtk` method):
       - Parse via `LdtkParser.parse(file.readText())`
       - Detect collision layers via `layer.isCollision`
       - Build `TilemapEntry` for manifest

    4. **Manifest writing:**
       - After processing all assets (incremental or full), build `AssetManifest` from collected entries
       - Write via `manifest.toJson()` to `manifestFile` property (which points to `build/generated/assets/asset-manifest.json`)
       - For incremental builds: load existing manifest, update/add/remove entries for changed files, write back

    5. **Incremental build support** (already uses `@Incremental`/`InputChanges`):
       - `processIncrementally()`: for ADDED/MODIFIED → process file and update manifest entry; for REMOVED → remove manifest entry and delete output file
       - `processAll()`: process every file in asset directory, build fresh manifest
       - Keep the existing `@CacheableTask` and `@Incremental` annotations

    6. **File routing by extension:**
       - `.png` → `processPng()`
       - `.tmx`, `.json` (Tiled JSON) → `processTmx()`
       - `.ldtk` → `processLdtk()`
       - Other extensions → skip with warning

    **Dependency verification (before implementation):**
    - Verify `gbkt-gradle-plugin/build.gradle.kts` has `implementation` dependency on `gbkt-core` (needed for AssetPipeline, TileDeduplicator, TiledParser, LdtkParser, AssetManifest imports)
    - If missing, add: `implementation("io.github.gbkt:gbkt-core:$gbktVersion-SNAPSHOT")` to dependencies block
