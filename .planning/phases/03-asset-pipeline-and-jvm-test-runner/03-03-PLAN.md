    **ScriptOpInterpreter (new file in existing test package):**
    Create `ScriptOpInterpreter` class in `gbkt-core/src/main/kotlin/io/github/gbkt/core/test/`:

    **State management:**
    - `variables: MutableMap<String, Long>` — game variables, initialized from `GameIR.variables` (VariableDef.initialValue)
    - `actorPositions: MutableMap<String, Pair<Int, Int>>` — initialized from `GameIR.actors[].position`
    - Actor positions also accessible as variables: `"<actorId>.x"` and `"<actorId>.y"` (per PongV2 usage pattern where `varRef("ball.x")` reads actor position)
    - `currentSceneId: String` — initialized from `GameIR.startScene ?: game.scenes.first().id`
    - `frameCount: Int` — total frames executed
    - `joypad: Int` — current frame input bitmask (D-pad and buttons)
    - `joypadPrev: Int` — previous frame input (for edge detection: pressed = current & !prev)
    - `tracingEnabled: Boolean` — when true, append state changes to trace log
    - `traceLog: MutableList<String>` — frame-by-frame trace entries

    **Core execution:**
    - `executeFrame()`: get current scene from `game.scenes`, execute `scene.frameOps` sequentially, update `joypadPrev = joypad`, increment `frameCount`
    - `enterScene(sceneId: String)`: set `currentSceneId`, execute `scene.enterOps`
    - `executeOp(op: ScriptOp)`: exhaustive `when(op)` with NO `else` branch — compiler enforces all 24 subtypes handled

    **ScriptOp handlers (implement fully for core ops, no-op stub for hardware ops):**
    - `Assign` → update `variables[target]` with evaluated expression value
    - `ArrayAssign` → no-op stub (arrays not used in example games)
    - `IfOp` → evaluate `condition` Expr, if truthy execute `thenOps`, else execute `elseOps`
    - `WhileOp` → evaluate `condition`, loop while truthy executing `bodyOps` (cap at 10000 iterations to prevent infinite loops in tests)
    - `ForOp` → ranged loop: set `variables[variable]` = `evaluateExpr(from)`, iterate while <= `evaluateExpr(to)`, execute `body` ops, then increment variable by 1 each iteration (cap at 10000 iterations)
    - `SetPosition` → update `actorPositions[actorId]` and sync to variables `"<actorId>.x"` / `"<actorId>.y"`
    - `MoveBy` → add offset to `actorPositions[actorId]` and sync to variables
    - `NavigateTo` → call `enterScene(sceneId)` (run exit ops of old scene, enter ops of new scene)
    - `WaitFrames` → no-op in simulation (per research recommendation)
    - `PlaySound`, `ShowDialog`, `ShowMenu`, `PrintOp`, `FadeOp`, `SetVisible`, `SpawnActor`, `DestroyActor`, `AnimateOp`, `CameraOp` → no-op stubs (hardware-dependent, per locked decision)
    - `CallOp`, `ReturnOp` → no-op stubs
    - `MathOp` → execute math operation (abs, min, max, clamp)
    - `RawOp` → no-op stub (raw C code not simulatable)
    - `TriggerSystem` → no-op stub (per locked decision for hardware features)

    **Expr evaluator:**
    - `evaluateExpr(expr: Expr): Long` — exhaustive `when(expr)` on all 9 Expr sealed subtypes (NO `else` branch):
      - `Literal` → `value.toLong()`
      - `VarRef` → `variables[name] ?: 0L`
      - `StringLiteral` → 0L (numeric context)
      - `BinaryExpr` → evaluate `left` and `right`, then dispatch on `BinaryOp` enum:
        - Arithmetic: ADD(+), SUB(-), MUL(*), DIV(/), MOD(%)
        - Bitwise: AND(&), OR(|), XOR(^), SHL(<<), SHR(>>)
        - Comparison: EQ(==), NEQ(!=), LT(<), LTE(<=), GT(>), GTE(>=) → return 1L or 0L
        - Logical: LOGICAL_AND(&&), LOGICAL_OR(||) → short-circuit evaluation
      - `UnaryExpr` → evaluate `operand`, dispatch on `UnaryOp` enum: NEGATE(-), BITWISE_NOT(~), LOGICAL_NOT(if 0 then 1 else 0)
      - `TernaryExpr` → evaluate `condition`; if != 0L return `evaluateExpr(thenExpr)` else return `evaluateExpr(elseExpr)`
      - `PropertyAccessExpr` → look up `actorPositions[objectId]`; if `property == "x"` return `.first.toLong()`, if `"y"` return `.second.toLong()`, else return `variables["$objectId.$property"] ?: 0L`
      - `ArrayAccessExpr` → 0L (no-op stub)
      - `CallExpr` → 0L (no-op stub)

    **Collision detection (bounding box):**
    - `checkCollision(actorA: String, actorB: String): Boolean` — use actor positions and hitbox dimensions from `GameIR.actors[].sprite.hitbox` (or default 8x8)
    - Integrate collision check into `IfOp` evaluation when the condition references a collision expression (CollidesWith comparison via actor IDs)

    **Tracing:**
    - When `tracingEnabled`, log variable assignments, scene changes, and collision events to `traceLog` with format: `"frame=$frameCount: $event"`
    - Example: `"frame=5: ball.x = 82"`, `"frame=10: scene -> gameover"`

    Create `SimulationContextV2` class wrapping `ScriptOpInterpreter`:

    ```kotlin
    class SimulationContextV2(game: GameIR) {
        private val interpreter = ScriptOpInterpreter(game)
    ```

    **Frame advancing (per locked decision):**
    - `advanceFrames(count: Int)` — execute `count` frames sequentially
    - `runUntil(maxFrames: Int = 600, predicate: SimulationContextV2.() -> Boolean)` — advance frames until predicate returns true or maxFrames reached; throw if maxFrames exceeded without predicate satisfaction

    **Input simulation (per locked decision — both low-level and high-level):**
    - Low-level: `press(button: Int)`, `release(button: Int)` — set/clear joypad bits
    - High-level: `tap(button: GameBoyButton)` — press for 1 frame, advance 1 frame, release
    - High-level: `holdDpad(direction: DpadDirection, frames: Int)` — hold direction for N frames
    - `GameBoyButton` enum: A, B, START, SELECT
    - `DpadDirection` enum: UP, DOWN, LEFT, RIGHT
    - Button bitmask constants matching GBDK: A=0x01, B=0x02, SELECT=0x04, START=0x08, RIGHT=0x10, LEFT=0x20, UP=0x40, DOWN=0x80

    **State inspection (per locked decision):**
    - `getVar(name: String): Int` — read variable value from interpreter
    - `setVar(name: String, value: Int)` — directly set variable (for test setup)
    - `assertVar(name: String, expected: Int)` — assert variable equals expected value; throw AssertionError with descriptive message including variable name, expected, and actual values
    - `val currentScene: String` — delegate to interpreter.currentSceneId
    - `val frameCount: Int` — delegate to interpreter.frameCount

    **Scene control:**
    - `enterScene(sceneId: String)` — set current scene and run its enter ops (for test setup to jump to specific scene)

    **Tracing (per locked decision):**
    - `enableTracing()` — enable frame trace log on interpreter
    - `getTraceLog(): List<String>` — return current trace entries
    - On test failure (when used with JUnit): trace log is available for debugging
