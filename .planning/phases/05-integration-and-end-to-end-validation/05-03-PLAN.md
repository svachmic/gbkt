**Step 3: If `compileRom` fails with lcc errors** — diagnose and fix. Breakout has additional complexity over Pong that may expose new codegen gaps:

a. **Sound effects:** BreakoutV2 uses `soundEffect()` which registers a `GenericSystem` with type `"sound"`. Check whether `GBDKPipelineV2` handles `GenericSystem` in the system list. If the pipeline generates a function call to a sound system function, verify the function is declared.

c. **Collision detection:** `collidesWith` expressions between actors must generate valid C. Check `ExprVisitor` handles `CollisionCheck` expression (may fall through to TODO).

d. **Score display / printf:** If Breakout uses `showDialog` or text rendering, verify the generated C calls are correct.

**Step 4: Apply lessons from Pong (05-02-SUMMARY.md).** Any fixes made to codegen for Pong should already apply to Breakout since they share the same codegen pipeline. Check whether Pong fixes resolved Breakout issues too.

**Step 5: Iterate** — fix codegen source code (not generated C), re-run `buildRom` until it succeeds.

**Step 6: Verify ROM file.** Check `breakout.gb` exists with non-zero size.
