<objective>
Wire v2 GameBuilder bridge in Gradle plugin so that v2 games (PongV2, BreakoutV2, ExplorerV2) route through the `generateV2(GameIR)` pipeline instead of failing with "argument type mismatch".

Purpose: This is the single dominant gap blocking all four INTG requirements. The Gradle plugin receives a `GameBuilder` from v2 games but tries to pass it to v1 `backend.generate(Game)` which expects `Game`, not `GameBuilder`. The fix adds a detection bridge: if `rawGame` is a `GameBuilder`, call `.build()` to get `GameIR`, then route to `backend.generateV2(gameIR)`.

Output: `./gradlew :gbkt-examples:pong:generateC` succeeds and produces C files via v2 pipeline. `./gradlew :gbkt-examples:pong:budgetReport` prints the budget report.
</objective>

**Detection pattern** (use reflection — worker runs with user's classloader):
```kotlin
val gameBuilderClass = try {
    Class.forName("io.github.gbkt.core.dsl.v2.GameBuilder")
} catch (_: ClassNotFoundException) { null }
```

**If `gameBuilderClass != null && gameBuilderClass.isInstance(rawGame)`** — v2 path:
1. Call `rawGame.javaClass.getMethod("build").invoke(rawGame)` to get `GameIR`
2. Call `BackendReflection.findBackendForTarget(target)` to get the backend
3. If backend is null, throw GradleException("No backend found for target '$target'")
4. Print `"Using backend: ${BackendReflection.getBackendDisplayName(backend)}"`
5. Call `backend.javaClass.getMethod("generateV2", Class.forName("io.github.gbkt.core.ir.v2.GameIR")).invoke(backend, gameIR)` to get a `GenerationResult`
6. Extract files from the result: call `result.javaClass.getMethod("getFiles").invoke(result)` to get `Map<String, GeneratedFile>`
7. For each file, call `generatedFile.javaClass.getMethod("getContent").invoke(generatedFile)` to get the String content
8. Write each file to `outputDir`
9. **Skip** source map generation (the v1 `GBDKCodeGenerator` cannot handle `GameIR`). Print `"WARNING: Source maps not yet available for v2 pipeline games."` and `"WARNING: Compiler errors will reference C line numbers, not Kotlin source."` **Note:** The locked decision requires source-map error mapping. V2 source map support is deferred to a gap-closure plan after Phase 5 core integration — the v1 `GBDKCodeGenerator` is architecturally incompatible with `GameIR`, so v2 source maps require a new implementation in `GBDKPipelineV2`. This deferral is acknowledged, not silently dropped.
10. Call `writeBuildMetadata(gameIR, outputDir)` — this may fail for v2 objects; wrap in try-catch and skip gracefully
11. Skip asset optimization for v2 games (it expects a v1 `Game` object)

**Else** — v1 path: leave existing code completely unchanged.

The key structural change is to insert an `if/else` branch right after `rawGame` is obtained (after the `getter.invoke(null)` call), splitting into v2 and v1 code paths. The v1 path contains all existing code (asset processing, generateWithBackendRegistry, source maps, metadata, optimization). The v2 path is the new code.

Do NOT modify `generateWithBackendRegistry()` — it stays as-is for v1 games.

**Part A — Fix `resolveGameIR()` in BudgetReportTask.kt:**

The current code tries `game.javaClass.getMethod("getIr").invoke(game)` which fails for `GameBuilder` (no `getIr()` method). Fix by trying `build()` first:

```kotlin
private fun resolveGameIR(game: Any): Any? {
    val gameIrClass = try {
        Class.forName("io.github.gbkt.core.ir.v2.GameIR")
    } catch (e: ClassNotFoundException) {
        return null
    }

    return when {
        gameIrClass.isInstance(game) -> game
        else -> {
            // Try GameBuilder.build() first (v2 DSL)
            try {
                game.javaClass.getMethod("build").invoke(game)
            } catch (_: NoSuchMethodException) {
                // Fall back to getIr() (legacy accessor)
                try {
                    game.javaClass.getMethod("getIr").invoke(game)
                } catch (_: NoSuchMethodException) {
                    null
                }
            }
        }
    }
}
```
