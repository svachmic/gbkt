Note: gbkt's cartridge upgrades to MBC5 (banking detected — `play_enter` and `play_frame`
land in bank 1, all scaffolding/trampolines in HOME). The reference is a single-bank
ROM_ONLY cartridge. `l__CODE` aggregates `l__CODE_0 + l__CODE_1` and is the canonical
"total code size" signal both projects report.

## Comparison table

| Metric    | Reference | gbkt port | Delta  | Verdict                            |
|-----------|-----------|-----------|--------|------------------------------------|
| File size | 32768     | 32768     | 0      | within 2× ✓ (32 KB cartridge pad)  |
| l__CODE   | 574       | 588       | +14    | within 2× (≤1148) ✓                |
| l__HOME   | 187       | 319       | +132   | informational                      |
| l__DATA   | 26        | 17        | -9     | informational                      |

`l__CODE` delta (+14 bytes / +2.4 %) is the load-bearing signal for D-09 part 2 — gbkt
emits a hair more code for the simple_physics behaviour than hand-written C. The
`l__HOME` delta (+132 bytes) reflects gbkt's scene-trampoline scaffolding
(`play_enter_trampoline`, `play_frame_trampoline`, `navigate_to_scene`, sprite/sound
helpers) plus joypad-edge-detection helpers that the bare-bones reference does not
have. The `l__DATA` saving (-9 bytes) reflects gbkt initialising globals where the
reference uses static initialisers.

## D-09 Verdict (codegen quality, part 2 — ROM size)

**PASS** — gbkt port `l__CODE` is 588 bytes; 2× reference cap is 1148 bytes (574 × 2).
gbkt is within 1.025× of the reference, far inside the 2× envelope demanded by
ROADMAP success criterion 1.

## Notes

- The build succeeded warning-free with respect to **the two simple_physics-specific
  signals the plan calls out**: SDCC warning 94 (Bug A regression — Plan 04's named
  fix) is absent, and SDCC warning 158 (Risk 3 i16→u8 narrowing) is absent. The Plan
  04 ExprVisitor fix held: signed-comparison RHS lowers to bare `CIntLiteral`, and the
  i16→u8 narrowing site (`smiley.x set (posX shr 4)`) compiles without truncation
  warnings.

- Four pre-existing gbkt scaffolding warnings (SDCC `84`, `85`, `85`, `126`) fire on
  every gbkt example build (verified against `gbkt-examples:pong:buildRom` as
  control). They arise from gbkt-emitted helper functions (`delay_frames`,
  `show_sprites_range`, the post-`while(1)` `return;`) and are NOT introduced by Phase
  09 work. Per the deviation-rules SCOPE BOUNDARY, these are out of scope for Plan 05
  and have been logged to `deferred-items.md` for a future codegen-hygiene phase.

- The MBC5 upgrade ("Cartridge upgraded from ROM_ONLY to MBC5 (banking detected)") is
  informational — gbkt defaults route scene code to bank 1, which forces MBC5. A
  future tuning pass could place such a trivial single-scene game entirely in HOME for
  a small further code-size win, but it is not required for D-09 PASS and is out of
  scope for Phase 09.
