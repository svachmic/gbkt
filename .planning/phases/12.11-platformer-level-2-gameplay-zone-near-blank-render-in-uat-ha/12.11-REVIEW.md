## Warnings

### WR-01: Stale KDoc in `buildMainLoopLevelSwitchGuardIfNeeded` describes the wrong generated-C shape

**File:** `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/GBDKPipelineV2.kt:2649-2689`

**Issue:** The KDoc block for `buildMainLoopLevelSwitchGuardIfNeeded` (lines 2649-2689) contains
two inconsistencies with the actual generated code:

1. The documented "Shape" example at lines 2651-2655 shows the guard body as:
   ```c
   if (_next_level != _current_level) {
       navigate_to_scene(SCENE_NEXTLEVEL);
       setup_current_level();             // ← shown in doc, NOT emitted
   }
   ```
   The actual implementation (lines 2710-2722) emits only `navigate_to_scene(sceneEnumConstant)`
   in the `thenBody`. `setup_current_level()` was removed from the guard in Phase 12.6 and now
   lives in the `levelCardScene` Start-press path — but the KDoc shape was never updated.

2. The contract assertions at lines 2687-2689 state:
   > - main() body MUST contain `setup_current_level()` AS A SUBSTRING.

   This assertion is false as a statement about what `buildMainLoopLevelSwitchGuardIfNeeded`
   emits. The guard body no longer contains `setup_current_level()`. This creates a contradictory
   document: the function's own KDoc says it emits a call it does not actually emit.

**Why this is a Warning, not Info:** A future maintainer reading only the KDoc to understand what
the guard emits will implement an emission test asserting that the guard body contains
`setup_current_level()`. That test will incorrectly pass (because `setup_current_level()` does
appear elsewhere in main.c — in the `gameplay_enter` call path — and a file-level grep would
satisfy it). The KDoc is actively misleading in the presence of an out-of-scope grep, exactly the
failure mode that CLAUDE.md §"Scope-level grep gates (corollary)" warns about.

**Fix:** Update the KDoc shape example and contract assertions to reflect the actual Phase 12.11
guard body:
```kotlin
 * **Shape** (post-Phase 12.6 / Phase 12.11 guard, mirrors reference main.c lines 44-82):
 * ```c
 * // Phase 12.11 — level-switch guard with SCENE_NEXTLEVELSCENE exclusion
 * if (_next_level != _current_level && current_scene != SCENE_NEXTLEVELSCENE) {
 *     navigate_to_scene(SCENE_NEXTLEVEL);
 * }
 * ```
 *
 * `setup_current_level()` is NOT emitted here — it lives in the levelCardScene
 * Start-press path (PlatformerExtensions.kt materialize, Plan 12.6-04).
 *
 * **Contract for anchor 5 emission tests:**
 * - main() body MUST contain `if (_next_level != _current_level && current_scene != SCENE_NEXTLEVELSCENE)` (or equivalent).
 * - main() body MUST contain `navigate_to_scene(SCENE_NEXTLEVEL)` AS A SUBSTRING.
 * - main() body MUST NOT contain `setup_current_level()` inside the guard's then-body
 *   (setup_current_level lives in levelCardScene frame, not in the guard).
```

### IN-02: Test 1 fixture (`buildTilemapCollisionGame`) does not exercise the new guard condition

**File:** `gbkt-backend-gbdk/src/test/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/SetupCurrentLevelDisplayGateEmissionTest.kt:114-135`

**Issue:** The `buildTilemapCollisionGame` fixture used in Tests 1 and 3 includes scenes
`["title", "gameplay"]` — no scene ID matches `nextlevel` or `next_level`. As a result,
`buildMainLoopLevelSwitchGuardIfNeeded` returns `emptyList()` for this fixture, and the Failure A
guard extension (`&& current_scene != SCENE_NEXTLEVELSCENE`) is not exercised by any test in this
file. The A-site guard is only tested indirectly through the re-armed UAT in
`PlatformerTemplateUatTest.anchor5LevelSwitch`, which requires a built ROM (skipped when absent).

This is intentional per the test's stated scope (the class header explicitly notes Tests 1 and 3
target the B-site, Test 2 targets the A-site with the DSL fixture). However, there is no emission
test in this file that verifies the generated guard condition string contains
`current_scene != SCENE_NEXTLEVELSCENE`, leaving the Failure A fix without a JVM-tier RED→GREEN
guard. The UAT is the only binding gate, and it skips when no ROM is present.

**Fix:** Add a Test 4 using the `buildLevelCardSceneGameDsl()` fixture (already available in the
file) that brace-walks `void main(` body from `main.c` and asserts the guard condition string
contains both `_next_level != _current_level` AND `current_scene != SCENE_NEXTLEVELSCENE`,
similar to the `LevelCardSceneEmissionTest` pattern. Example:
```kotlin
@Test
fun `main loop guard contains current_scene != SCENE_NEXTLEVELSCENE exclusion (Failure A fix token, RED pre-fix)`() {
    val gameIR = buildLevelCardSceneGameDsl()
    val mainC = pipeline.generate(gameIR).files["main.c"] ?: error("main.c not generated")
    val mainBody = extractFunctionBody(mainC, "void main(")
    assertTrue(
        mainBody.contains("current_scene != SCENE_NEXTLEVELSCENE"),
        "main() guard must contain 'current_scene != SCENE_NEXTLEVELSCENE' " +
            "(Failure A fix — prevents nextLevelScene_enter() firing every frame). " +
            "body:\n\${mainBody.take(4000)}"
    )
}
```
