<decisions>
## Implementation Decisions

### Diagnosis structure
- **D-01:** **Diagnose BOTH A and B before any fix lands.** A and B are entangled — disabling
  or reordering one reveals the other, and the SEED lists competing/falsifiable hypotheses for
  each. A DIAGNOSE plan must root-cause both (codegen-read + runtime/MCP probe) and write a
  DIAGNOSTIC.md verdict; only then do fix plans land. Mirrors the 12.9 `08e→08f`
  diagnose→fix cluster shape. Rejected: per-defect diagnose→fix pairs (the entanglement
  masking effect — fixing A changes what B looks like — and prior false-hypothesis history in
  12.8/12.9 make split-vertical-slices risky).

### Failure A — fix locus
- **D-02:** **Failure A must be fixed in codegen/runtime ONLY.** The harness START-press cadence
  in `anchor5LevelSwitch()` is treated as correct ground-truth and MUST NOT be loosened to make
  A pass. The fix lands in generated C / DSL codegen — the candidate site is the
  `levelCardScene` Start-press handler `whenever(buttons.start.pressed){ setup_current_level(); navigate(gameplay) }`
  (`PlatformerExtensions.kt:911-916`) and/or its `button_pressed(J_START)` rising-edge emission /
  frame-handler composition. This honors the 12.10 (harness) vs 12.11 (codegen) split and gives
  the strongest regression guarantee. Rejected: permitting a test-cadence adjustment as a last
  resort (blurs the 12.10/12.11 boundary).

### Failure B — fix locus
- **D-03:** **Reproduce/explain the MCP-vs-harness divergence FIRST, before choosing a codegen
  site.** The load-bearing clue is that MCP renders level-2 but the scripted harness produces a
  STABLE near-blank frame (12.10 proved it is NOT a settle/capture race). Diagnosis must pin WHY
  the harness diverges (frame cadence / DISPLAY_ON / SHOW_BKG / bank state at the exact harness
  frame) before changing the level-2 `setup_current_level` case
  (`GBDKPipelineV2.kt:2466-2530`: `set_bkg_data` + `set_bkg_palette` + windowed
  `_bkg_set_level_submap_banked(0u,0u,21u,18u)` — candidate causes: submap dims vs a wider
  level-2 tilemap, `_current_area_bank`, SHOW_BKG, DISPLAY_ON ordering). Fixing the VRAM path
  blind risks fixing a non-cause. Rejected: auditing the upload path directly with the
  MCP-renders-fine result as secondary.

### JVM emission guard — scope
- **D-04:** **The RED→GREEN JVM-tier guard covers BOTH the A and B emission sites.** It must
  pin, in generated C: (1) the corrected `levelCardScene` Start-press navigate/`setup_current_level`
  emission (A), AND (2) the level-2 `setup_current_level` case body (B). RED on the pre-fix
  generator, GREEN post-fix. May be one test or two; lives in the platformer-template or
  gbkt-backend-gbdk test tier. Per the CLAUDE.md scope-grep corollary it MUST grep WITHIN
  function scope (brace-walk / awk extraction), NOT file-level `grep -c` counts — a file-level
  count cannot distinguish the level-2 case from level-1 or another scene's emission. Rejected:
  greping only the single site that turns out to be the genuine codegen change.

### Claude's Discretion
- Concrete diagnostic instrumentation (which globals/VRAM regions to probe, MCP vs read_memory
  for the divergence repro), exact fix-plan count and wave layout, and the precise grep anchors
  for the emission test are left to the researcher/planner — provided D-01..D-04 hold.

</decisions>
