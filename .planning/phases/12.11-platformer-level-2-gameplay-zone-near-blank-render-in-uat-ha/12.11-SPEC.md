# Phase 12.11: platformer level-2 gameplay-zone level-switch + near-blank render (UAT harness) — Specification

**Created:** 2026-06-02
**Ambiguity score:** 0.13 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

The `PlatformerTemplateUatTest.anchor5LevelSwitch()` UAT harness test goes GREEN with its
`@Disabled` annotation removed and the `assertScreenshotIsNonUniform(..., "anchor5-level-2")`
assertion re-armed — meaning the level-1 → nextLevel-card → level-2 switch **completes in
the harness** (`_current_level` reaches 1) **and** the level-2 (`world2Area1Zone`) gameplay
BG tilemap **renders non-blank** (dominant-colour ratio < 0.95) in the same scripted run.

## Background

`anchor5LevelSwitch()` (`gbkt-examples/platformer-template/src/test/kotlin/.../PlatformerTemplateUatTest.kt:856-870`)
is currently `@Disabled`, routed out of Phase 12.10 (test-infrastructure-only) into this
sibling phase. It is deterministically RED across 3/3 isolated reruns and surfaces **two
distinct, entangled defects** — disabling/reordering one only reveals the other:

- **Failure A (logic):** the card → gameplay (level-2) switch never completes in the harness.
  Across 3/3 reruns: `final_current_level: 0`, `post_release_scene: nextLevelScene`,
  `mid_level_2_scene: nextLevelScene`. The scene stays on the nextLevelScene card; the
  START-press → gameplay navigation never fires under the harness's frame/button cadence.
  Test asserts `_current_level == 1` at `PlatformerTemplateUatTest.kt:1157`.

- **Failure B (render):** when the switch *does* reach level-2 (observed in an earlier run
  with `current_level: 1`), the captured `03-level-2.png` is a 661-byte near-blank frame —
  one colour over 98.3% of the 160×144 screen (`0.983` dominant ratio at
  `PlatformerTemplateUatTest.kt:220` / `:1094`).

Phase 12.10 evidence (decisive):
1. **Pre-existing, NOT a 12.10 regression** — the platformer-template ROM is byte-identical
   to pre-12.10; 12.10 changed only test-infra files.
2. **NOT a capture-timing race** — inserting `StepAgent.settle()` before the level-2 capture
   reaches a STABLE frame that IS near-blank (so the 12.10 settle primitive does not fix it).
3. **Logic state correct, framebuffer blank** — in the reaching-level-2 run, state machine
   arrived (`grounded: 1`, `playerY: 1920`) but the BG plane was not on screen.
4. **Deterministic** across 3 isolated reruns (same 0.983 ratio).
5. **Regressed since Phase 12.7** — committed 12.7 `03-level-2.png` evidence is 1606 bytes
   (non-blank); sibling anchor5 frames (00/01/02) are still non-blank. Only `03-level-2.png`
   collapsed.
6. **12.9 approved level-2 via direct MCP capture, NOT this harness** — so the harness
   level-2 frame may have been near-blank since the 12.9 codegen bundle landed while the MCP
   capture showed a good frame (an MCP-vs-harness divergence this phase must close).

The `setup_current_level()` codegen path that owns level loading already exists
(`GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded`, `GBDKPipelineV2.kt:2410+`): each
gameplay zone emits a `case` with `set_bkg_palette`, `_bkg_tiles_load_banked`, windowed
`_bkg_set_level_submap_banked(0u, 0u, 21u, 18u)`, and per-level spawn writes. The defect is
therefore in this path's behaviour for the SECOND level (and/or the card→gameplay START-press
navigation that drives into it under the harness), not in the absence of the path.

This is a **codegen/runtime defect-fix phase**, not a test-harness phase (that was 12.10).
