## Root Cause Verdicts

### Failure A: `_current_level` stuck at 0 in harness

**Root cause: Frame-boundary VBlank collision.**

The main-loop guard calls `navigate_to_scene(SCENE_NEXTLEVELSCENE)` → `nextLevelScene_enter()` EVERY FRAME while `_next_level != _current_level` (true on the card scene: `1 != 0`). `nextLevelScene_enter()` contains `fill_bkg_rect(32,32)` + `_bkg_tiles_load_banked(...)` — tile-map writes that consume VBlank. When VBlank fires during these writes, Coffee-GB's `stepFrame()` returns with the ROM paused inside `nextLevelScene_enter()`, after `update_joypad()` already ran for that iteration. The next `step(setOf(Button.START))` call resumes from there, completes the enter call, hits VBlank again — `update_joypad()` is never called with START in `Joypad.buttons`. `__joypad = 0x00`, `button_pressed(J_START)` evaluates to 0, the card navigation never fires.

Research hypotheses assessment:
- H-A1 (`display_off` stall): NOT the primary Failure A cause (though display IS ON per probe)
- H-A2 (guard override): FALSIFIED
- H-A3 (Coffee-GB joypad strobe): REFINED — the issue is frame-boundary collision, not P1 strobe

### Failure B: Near-blank level-2 BG in harness

**Root cause: `_bkg_set_level_submap_banked()` called with `LCDC.7 = 1` (display ON).**

`setup_current_level()` wraps `_bkg_set_level_submap_banked(0u, 0u, 21u, 18u)` with no DISPLAY_OFF/ON. `set_bkg_submap` writes to VRAM BG map area (0x9800-0x9BFF), accessible only during H-blank/V-blank. With display ON (confirmed: `LCDC_REG = 0xC7`), the write is dropped or corrupted in Coffee-GB, producing a 98.3% near-blank frame. The GBDK reference wraps the equivalent call in explicit `DISPLAY_OFF`/`DISPLAY_ON` (verified: `/Users/michalsvacha/gbdk/examples/cross-platform/platformer_template/src/main.c:58-71`).

### MCP-vs-harness divergence

Phase 12.9's G3 approval used direct MCP capture that bypassed the card scene. In the MCP single-call path, `gameplay_enter()` → `setup_current_level()` runs once; Coffee-GB's timing may allow this single VRAM write to succeed. The harness ALWAYS goes through the card scene (D-02 ground-truth), which: (a) produces the VBlank collision preventing Failure A from resolving, and (b) if Failure A were fixed, the display-ON VRAM write would cause Failure B. Both defects entangled, as the SEED documented.
