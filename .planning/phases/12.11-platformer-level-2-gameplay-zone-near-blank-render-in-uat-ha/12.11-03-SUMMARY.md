## Fix Details

### Fix Site 1 — Failure B (buildSetupCurrentLevelFunctionIfNeeded)

The raw-C template string for `void setup_current_level(void) NONBANKED` was modified to insert:
- `DISPLAY_OFF;` on its own line immediately after `_current_level = _next_level;` (before the switch)
- `DISPLAY_ON;` on its own line immediately after the switch's closing `}` (before the function's closing `}`)

Generated `main.c` brace-walk confirms the correct token order:
```
void setup_current_level(void) NONBANKED {
    _current_level = _next_level;
    DISPLAY_OFF;                     ← present, before switch
    switch (_current_level % 3u) {
    case 0: ... _bkg_set_level_submap_banked(0u, 0u, 21u, 18u); ... break;
    case 1: ... _bkg_set_level_submap_banked(0u, 0u, 21u, 18u); ... break;
    case 2: ... _bkg_set_level_submap_banked(0u, 0u, 21u, 18u); ... break;
    default: break;
    }
    DISPLAY_ON;                      ← present, after switch
}
```

`DISPLAY_OFF` at index < `switch (_current_level` at index < `DISPLAY_ON` — ordering constraint satisfied.

### Fix Site 2 — Failure A (buildMainLoopLevelSwitchGuardIfNeeded)

The `CIf` condition was extended from `_next_level != _current_level` to a nested `CBinaryExpr`:

```
CBinaryExpr(
    CBinaryExpr(CVar("_next_level"), "!=", CVar("_current_level")),
    "&&",
    CBinaryExpr(CVar("current_scene"), "!=", CVar(sceneEnumConstant)),
)
```

Generated `main.c` confirms:
```c
if (_next_level != _current_level && current_scene != SCENE_NEXTLEVELSCENE) {
    navigate_to_scene(SCENE_NEXTLEVELSCENE);
}
```

This prevents `nextLevelScene_enter()` from being called EVERY frame while already on the card scene, stopping the VBlank-consuming VRAM writes from displacing `update_joypad()` from the frame boundary.

## Deviations from Plan

### Diagnostic-Revised Failure-A Fix Site (recorded as required by plan's critical_deviation_note)

**Context:** The plan's prose (written before the DIAGNOSTIC) assumed the DISPLAY_OFF/ON wrap alone would make the Failure-A double-call "benign." The `12.11-DIAGNOSTIC.md` Wave 1 analysis REVISED this:

- **Original theory:** DISPLAY_OFF/ON in setup_current_level() makes the double-call from the card path safe.
- **Diagnostic verdict (Fix Site 2):** Failure A is a FRAME-BOUNDARY VBLANK COLLISION — the main-loop guard fires `navigate_to_scene(SCENE_NEXTLEVELSCENE)` EVERY FRAME while `_next_level != _current_level`, calling `nextLevelScene_enter()` which contains `fill_bkg_rect(32,32)` + `_bkg_tiles_load_banked(...)`. These VRAM writes span VBlank; Coffee-GB's `stepFrame()` returns mid-enter, leaving the ROM paused inside `nextLevelScene_enter()`. The next `step(setOf(Button.START))` resumes from there, never reaching `update_joypad()` for the START-pressed frame.

**Resolution:** Both fix sites applied as DIAGNOSTIC.md prescribes:
1. Failure B: `buildSetupCurrentLevelFunctionIfNeeded` — DISPLAY_OFF/ON wrap (per plan body AND diagnostic)
2. Failure A: `buildMainLoopLevelSwitchGuardIfNeeded` — `&& current_scene != SCENE_NEXTLEVELSCENE` guard (diagnostic-only site, not in original plan prose)

Both are within the declared file scope (`GBDKPipelineV2.kt`) and within `gameUsesTilemapCollision`-gated functions (SPEC-REQ-5 preserved).
