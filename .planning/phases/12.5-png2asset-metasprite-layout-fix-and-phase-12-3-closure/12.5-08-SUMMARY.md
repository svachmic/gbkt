# Phase 12.5 Plan 08: 5-Game DSL Migration to mode/pivot/frameSize — Summary

Migrated metasprites and metasprites-stress to declare mode/pivot/frameSize in their metasprite sprite() blocks. Fixed a Rule 1 bug in GBDKPipelineV2 that broke actor sprite conversion for 8x8 sprites. Refreshed byte-identity baselines atomically. All 5 game ROMs build GREEN.

## Gate Scope Decision: Actor Sprites vs Metasprites

**Decision:** `validateMetaspriteSpritePaths()` in GenerateCTask.kt:780 iterates only `gameIR.getMetasprites()` — it does NOT check actor sprites (`gameIR.actors[].sprite`). Therefore:

- **Pong** (3 actor sprites: paddle.png×2, ball.png): NO migration needed — outside gate scope
- **Breakout** (2 actor sprites: paddle.png, ball.png): NO migration needed — outside gate scope
- **Simple-Physics** (1 actor sprite: ball.png): NO migration needed — outside gate scope
- **Banks**: zero sprite blocks confirmed by grep — excluded per RESEARCH Pitfall 2

These 4 games have NO DSL changes. They are documented as "no flags required (actor sprite, not a metasprite)".

## Rule 1 Bug Fix: Actor Sprite Sidecar Cutting Flags

**Found during:** Task 1 buildRom verification for simple-physics

**Issue:** `GBDKPipelineV2.buildMetadataFile()` emitted actor sprite sidecar entries WITHOUT cutting flags (spriteMode/pivotX/pivotY/frameWidth/frameHeight). `ConvertSpritesTask` defaulted to `spriteMode=SPR8x16, frameHeight=8`. For simple-physics's 8×8 ball.png, `buildPng2AssetArgs` passed `-sw 8 -sh 8` without `-spr8x8` → png2asset failed: "Image size 8 x 8 isn't an even multiple of tile size 8 x 16".

**Fix:** `GBDKPipelineV2.buildMetadataFile()` now derives cutting flags from `actor.sprite.size`:
- `spriteMode`: `SPR8x8` when `size.height <= 8`, else `SPR8x16`
- `frameWidth/frameHeight`: from `sprite.size.width` / `sprite.size.height`
- `pivotX/pivotY`: always `0, 0` (actor sprites have no DSL pivot declaration)

**Files modified:** `gbkt-backend-gbdk/.../GBDKPipelineV2.kt`
**Commit:** 9c2f5912

## Baseline Refresh (Pitfall 4)

Adding explicit `-spr8x8 -px 0 -py 0 -sw 64 -sh 48` changes png2asset output because the old baselines were generated with just `-noflip` (no frame-slicing flags). The new flags enable explicit frame-slicing at 64×48px per frame.

| Baseline | Old size (bytes) | New size (bytes) | Change reason |
|----------|-----------------|-----------------|---------------|
| metasprites/elephant.c.baseline | 14,xxx (960 tile bytes in array) | 10,453 (768 tile bytes) | Explicit -sh 48 slices to 5 exact frames; -spr8x8 mode changes tile packing |
| metasprites-stress/elephant.c.baseline | same as above | 10,469 | Same conversion, BANKREF differs slightly due to output file path |
| metasprites-stress/tiger.c.baseline | same as above | 10,421 | Same PNG content, different symbol names |

Baselines refreshed atomically in the same commit as the DSL changes (Task 2 commit 945670e1).
