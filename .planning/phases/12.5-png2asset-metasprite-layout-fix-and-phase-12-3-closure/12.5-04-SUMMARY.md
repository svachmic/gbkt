# Phase 12.5 Plan 04: Sidecar Emitter — 5 Sprite Cutting-Flag Fields Summary

**One-liner:** Emitter in `buildMetadataFile()` now writes `spriteMode/pivotX/pivotY/frameWidth/frameHeight` into each metasprite `sprites[]` entry of `game_metadata.json`, with null-coalescing defaults; actor-sprite entries remain unchanged per D-05.

## What Was Built

Extended `GBDKPipelineV2.buildMetadataFile()` to include the 5 png2asset cutting-flag fields in each metasprite `sprites[]` JSON entry. These fields are read by `ConvertSpritesTask` (Plan 05) to build the png2asset command-line arguments.

### Changes

**`GBDKPipelineV2.kt`:**
- Added `import io.github.gbkt.core.ir.SpriteMode`
- Appended 5 chained `.put(...)` calls to the metasprite sprites[] emitter block (lines 367-371):
  - `"spriteMode"` → `ms.spriteMode?.name ?: SpriteMode.SPR8x16.name` (null → `"SPR8x16"`)
  - `"pivotX"` → `ms.pivotX ?: 0`
  - `"pivotY"` → `ms.pivotY ?: 0`
  - `"frameWidth"` → `ms.frameWidth ?: 8`
  - `"frameHeight"` → `ms.frameHeight ?: 8`
- Added `// Phase 12.5 D-05 — png2asset cutting flags in sidecar` comment
- Added `// Actor sprite entries do NOT carry cutting flags (D-05); only id/spritePath/includePath/mirrorDedup.` comment to actor-sprite block

**`GBDKPipelineV2MetadataSpritesTest.kt`:**
- Added `import io.github.gbkt.core.ir.SpriteMode`
- Added Test 5: `emits_sprite_cutting_flags_in_sprites_array` — asserts all 5 fields for a fully-specified `MetaspriteIR` (SPR8x16, pivotX=12, pivotY=6, frameWidth=24, frameHeight=32)
- Added Test 6: `emits_defensive_defaults_when_cutting_flags_are_null` — asserts null IR fields emit safe defaults
