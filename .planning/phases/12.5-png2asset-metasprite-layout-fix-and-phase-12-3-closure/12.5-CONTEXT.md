prevented the platformer-template player from rendering as recognizable duck art in the

### DSL surface — typed flag builders on `sprite()`

- **D-04: `sprite(AssetRef)` gains a typed builder block exposing png2asset cutting
  flags. Required (NOT optional) for every metasprite.** The new DSL surface:
  ```kotlin
  val player by metasprite {
      sprite(asset("graphics/player-character-gbapduck-sprites.png")) {
          mode(SpriteMode.SPR8x16)   // -spr8x16 (or -spr8x8 if 8px tall)
          pivot(12, 6)               // -px 12 -py 6
          frameSize(24, 32)          // -sw 24 -sh 32
          // mirrorDedup() already exists per Phase 10.1-16 / Phase 12.4 D-02
      }
      // ... existing posX/posY/rot/idx binders ...
      // ... frames with tile(relX, relY, baseId) ...
  }
  ```
  - **Why typed builder, not raw flag string:** Captures each png2asset concept as a
    typed Kotlin method — compile-time validation, IDE autocomplete, no magic
    strings (per `feedback_no_magic_strings.md`). Raw-flag-string option was
    rejected: a raw `"-spr8x16 -px 12 -py 6 -sw 24 -sh 32"` reintroduces the magic-
    string anti-pattern the rest of the DSL avoids.
  - **Why required, not optional with defaults:** Per user direction —
    "explicit > implicit at the cost of migration churn." Aligns with Phase 12.4
    D-01's `sprite()` mandatory stance and the project's "Declarative Over
    Imperative" principle (`PROJECT.md §Core Principles`). The CURRENT behavior
    (no -px/-py/-sw/-sh passed) is exactly the bug Phase 12.5 fixes — making
    these optional would let the bug recur silently in future games.
  - **Why builder block on `sprite()`, not a sibling `spriteConfig()`:** Co-located
    config keeps the DSL block readable; the cutting flags are properties OF the
    asset binding, not a parallel concern. The sibling-block option remains
    available as a future refactor if config grows beyond ~5 methods.
  - **Researcher MUST scout:** the existing `MetaspriteBuilder.posX(v: AssignableVar)`
    binder shape (Plan 10.1-05) and Phase 12.4 D-01a's `sprite(asset: AssetRef)`
    shape — the new builder methods are structurally siblings.

- **D-04a: Builder method signatures locked.**
  - `fun mode(m: SpriteMode)` — `SpriteMode.SPR8x16` or `SpriteMode.SPR8x8` (enum
    already implied by current `spriteModeFromHeight` heuristic).
  - `fun pivot(x: Int, y: Int)` — maps to `-px <x> -py <y>`.
  - `fun frameSize(w: Int, h: Int)` — maps to `-sw <w> -sh <h>`. Planner picks
    whether to validate (e.g., `w % 8 == 0`, `h % 8 == 0`) at DSL time or defer to
    ConvertSpritesTask.
  - Existing `mirrorDedup(opt: Boolean = true)` keeps current Phase 10.1-16 / 12.4
    D-02 semantics — captured in the sidecar as today.
  - **Future flag extension** (NOT in 12.5 scope): if png2asset gains `-keep_palette_order`,
    `-bpp 2`, or other flags relevant to a later game, add a sibling typed method.
    The DSL is open for additive extension.

- **D-04b: IR fields are additive on `MetaspriteIR`.**
  ```kotlin
  data class MetaspriteIR(
      // ... existing fields ...
      val spritePath: String? = null,           // Phase 12.4 D-01b
      val mirrorDedup: Boolean = false,         // Phase 10.1-16
      // NEW in 12.5:
      val spriteMode: SpriteMode? = null,       // SPR8x16 / SPR8x8 / null = legacy
      val pivotX: Int? = null,
      val pivotY: Int? = null,
      val frameWidth: Int? = null,
      val frameHeight: Int? = null,
  )
  ```
  Additive only — keeps `gbkt-ir` a leaf module; no breaking change to JVM tests
  of MetaspriteIR construction. At codegen / validation boundary, throw if any of
  the 5 new fields is null (mirrors Phase 12.4 D-01b's spritePath null-check
  pattern). Planner picks: extend the existing `GenerateCTask` validation hook
  added in Plan 12.4-05.

### ConvertSpritesTask — refactor to flag-builder driven by sidecar

- **D-06: `ConvertSpritesTask.convertSprite()` builds the png2asset command from
  sidecar fields, not hardcoded `-spr8x8/-noflip` heuristics.**
  Current invocation at `ConvertSpritesTask.kt:237-244`:
  ```kotlin
  val args = mutableListOf(pngFile.absolutePath, "-o", outputC.absolutePath)
  when (spriteMode) { SpriteMode.SPR8x8 -> args.add("-spr8x8"); SPR8x16 -> {} }
  if (!mirrorDedup) args.add("-noflip")
  ```
  New invocation:
  ```kotlin
  val args = mutableListOf(pngFile.absolutePath, "-o", outputC.absolutePath)
  when (sidecarEntry.spriteMode) {
      SpriteMode.SPR8x8 -> args.add("-spr8x8")
      SpriteMode.SPR8x16 -> { /* default */ }
  }
  args.addAll(listOf("-px", "${sidecarEntry.pivotX}", "-py", "${sidecarEntry.pivotY}"))
  args.addAll(listOf("-sw", "${sidecarEntry.frameWidth}", "-sh", "${sidecarEntry.frameHeight}"))
  if (!sidecarEntry.mirrorDedup) args.add("-noflip")
  ```
  - **Remove** the `spriteModeFromHeight(pngFile)` height-heuristic (line ~236) —
    sidecar's `spriteMode` is authoritative; height-inference is dead code after
    migration.
  - **Tests:** Extend `ConvertSpritesTaskSidecarTest` (Phase 12.4 Plan 12.4-03)
    with assertions for each new flag's command-line position. Optionally add a
    `ConvertSpritesTaskFlagBuilderTest` per-flag focus.
