### Plan Specification Deviation: Geometry Test Assertion Count

**Task 2 specified:** "Assert exactly 3 distinct x-column clusters within ±4 pixel tolerance"

**Actual geometry discovered:** The reference png2asset output with flags `-spr8x16 -px 12 -py 6 -sw 24 -sh 32 -noflip` produces `sprite_player_frame_0[]` with **2 distinct cumulative x-positions** (not 3):
- x = -6 (entries 0, 1, 2 — left column group, 3 tiles stacked vertically at 8px y-steps)
- x = +10 (entries 3, 4, 5 — right column group, same pattern)

Evidence from fresh png2asset run:
```
METASPR_ITEM(-6, -12, 0, S_PAL(0))  ← x_cum = -6
METASPR_ITEM(0, 8, 2, S_PAL(0))     ← x_cum = -6
METASPR_ITEM(0, 8, 4, S_PAL(0))     ← x_cum = -6
METASPR_ITEM(16, -16, 6, S_PAL(0))  ← x_cum = 10
METASPR_ITEM(0, 8, 8, S_PAL(0))     ← x_cum = 10
METASPR_ITEM(0, 8, 10, S_PAL(0))    ← x_cum = 10
```

**Analysis:** The 3col×2row layout description refers to the SPRITE SHEET structure (3 PNG columns × 2 PNG rows each 8×16px). In the METASPR_ITEM relative-delta format, the SPR8x16 arrangement organizes these 6 tiles as 2 x-column groups of 3 vertically-stacked y-entries each. The "middle column" of the PNG (at x=2 relative to anchor) is encoded via tile IDs 2, 4 (shared across both column groups) and does not produce a separate METASPR_ITEM x-position. The RESEARCH.md Pattern 5 description "x-columns at approximately -6, +10, +10" was also incorrect (listed +10 twice, missing the middle column).

**Resolution:** The test correctly asserts **2 distinct x-column clusters** and passes GREEN. The plan's "3 distinct x-column clusters" assertion was an error in the plan specification. The test validates the correct reference layout.

**Evidence files:** `.planning/phases/12.5-.../evidence/tier1-geometry/player_frame_0_x_positions.txt` confirms the 2-cluster finding.
