## What Was Built

`validateMetaspriteSpritePaths()` in `GenerateCTask.kt` (the Plan 12.4-05 gate at ~line 780) was extended with 3 new check blocks after the existing `spritePath` null-check:

1. **mode check** — `getSpriteMode().invoke(ms) == null` → `GradleException("Metasprite '$id' missing mode() — declare mode(SpriteMode.SPR8x16) or mode(SpriteMode.SPR8x8) inside sprite() { ... } block. (Phase 12.5 D-04b)")`

2. **pivot check** — `getPivotX().invoke(ms) == null || getPivotY().invoke(ms) == null` → `GradleException("Metasprite '$id' missing pivot() — declare pivot(x, y) inside sprite() { ... } block. (Phase 12.5 D-04b)")`

3. **frameSize check** — `getFrameWidth().invoke(ms) == null || getFrameHeight().invoke(ms) == null` → `GradleException("Metasprite '$id' missing frameSize() — declare frameSize(w, h) inside sprite() { ... } block. (Phase 12.5 D-04b)")`

All 3 use `invoke(ms) != null` pattern (NOT type-cast) per Pitfall 3 — classloader isolation in Gradle worker context makes casting `Object` to `SpriteMode?` or `Int?` unsafe.
