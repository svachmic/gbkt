### Free-text user direction (re-shaped Area 2):

> "Just to put this out there - maybe png2asset is in general not a tool that can be fully automated. Maybe it strictly needs a human to say - this is how I designed my sprites and you need to cut them as such. I can be wrong, just saying that meybe the approach rather than encoding into the codebase should be to expose the parameters/arguments through the gradle plugin, which is called then manually based on some kind gradle kts file with configuration (for reproducibility). **Claude's reflection + finding:** Verified against `ConvertSpritesTask.kt:237-244` — gbkt currently passes only `-spr8x8` (height heuristic) and `-noflip` (mirrorDedup). The pivot (-px/-py), frame size (-sw/-sh), and explicit mode (-spr8x16) flags documented in `res/README.md` are NEVER passed. User's intuition was the smoking gun. This collapsed the diagnostic into a confirmation step and shifted the phase shape toward DSL flag exposure.
