## Nyquist Waiver — Wave 0 Co-Creation (TDD)

Wave 0 is waived; the two NEW test files (`ZoneBuilderTilemapTest.kt` and `BankingAnalysisPassTilemapOverflowTest.kt`) are co-created with their corresponding production code in TDD-style plans (12.2-01 Task 2 and 12.2-08 Task 2 respectively). Each task lists the test file in `<read_first>` and writes the failing test stub BEFORE the production-code step, then verifies it goes GREEN. This is functionally equivalent to a preceding Wave 0 plan and is the project's accepted pattern for unit-test-only additions at the same module boundary.

Rationale for the waiver (not creating a separate Wave 0 plan):

1. **Same module, same boundary.** Both NEW test files live in the same Gradle module as the production code they exercise (`gbkt-lang` for ZoneBuilder; `gbkt-analysis` for BankingAnalysisPass). A separate Wave 0 plan would split a single TDD cycle across two plans for no behavioral benefit — only added orchestration overhead.

2. **TDD discipline preserved.** Both Task 2 blocks (in Plans 01 and 08) carry `tdd="true"` and a `<behavior>` block listing the expected test cases BEFORE the action steps. The executor writes the failing test FIRST (RED), then the production code (GREEN), then verifies via `./gradlew :<module>:test --tests "<TestClass>"`. The Nyquist sampling-frequency intent is satisfied: feedback latency is < 30s per task, no 3 consecutive tasks without automated verify.

3. **No downstream consumer ambiguity.** Neither new test file is referenced as a `<read_first>` dependency by any other plan's task. The test files are leaf nodes — they exist solely to lock the new behavior introduced in their respective parent plans.

4. **Co-creation is the established project pattern** for new unit-test-only additions at the same module boundary (confirmed by reviewing prior phase plans across Phases 11.x and 12.x).
