    # SEED: Phase 12 — Per-Zone Tilemap Bank Allocation

    **Created:** <today> (Phase 12.2 close)
    **Source:** Phase 12.2 SPEC §"Out of scope"

    ## Context

    Phase 12.2 emits all `_zone_<id>_tilemap.c` files with `#pragma bank 2` (shared bank), and
    BankingAnalysisPass guards against cumulative overflow at 14336 bytes (16 KB minus 2 KB
    safety margin). Phase 12's 5 zones sum to ~6480 bytes — well under the threshold.

    Adding more or larger zones could trigger the overflow. The current behavior is to fail
    the build with a clear error naming each zone's contribution.

    ## What's Deferred

    Implement per-zone tilemap bank allocation, mirroring the existing
    `GBDKPipelineV2.allocateZoneBanks` bin-packing logic for tileset data. Each zone's tilemap
    would land in its own bank (or a small bank-group), with the `#pragma bank N` set per-zone.

    Tile-coordinate-system changes may be required if the bank-switching cost on tilemap access
    becomes a runtime concern (typically not — tilemaps are loaded once via `_bkg_tiles_load_banked`).

    ## Revival Condition

    `BankingAnalysisPass.checkTilemapBankOverflow` fires with `cumulative > 14336 bytes`. The
    error message explicitly cites this SEED.

    ## Related

    - `gbkt-analysis/.../BankingAnalysisPass.kt` (Phase 12.2 Plan 08)
    - `gbkt-backend-gbdk/.../GBDKPipelineV2.kt` `allocateZoneBanks` (the tileset analogue)
