## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug-in-must_have] Ground-tile set corrected from `{0x00..0x05}` to `{0x08..0x0d}` to match deterministic png2asset output**

- **Found during:** Task 1, first test run (BUILD FAILED).
- **Issue:** The plan's `must_haves.truths` line 15 and `<acceptance_criteria>` line 220 both cited the ground-tile set as `{0x00, 0x01, 0x02, 0x03, 0x04, 0x05}`. The first test run produced `row31[0..19] = [8, 9, 10, 11, 12, 9, 10, 11, 12, 9, 10, 11, 12, 9, 10, 11, 12, 9, 10, 11]` — values in `{0x08..0x0d}`, not `{0x00..0x05}`. The plan author appears to have predicted png2asset's tile allocation order without measuring it.
- **Empirical verification:** Direct png2asset invocation in `/tmp/12.2-05-probe` with the exact command the production code uses (`png2asset world1-area1.png -c probe.c -noflip -map -maps_only -source_tileset world1-tileset.png`) confirmed the row 31 byte pattern is `0x08, 0x09, 0x0a, 0x0b, 0x0c, 0x0d` (ground tiles) followed by `0x1a` (right-side fill beyond the ground portion). Rows 29 + 30 + 31 all carry the same pattern (the ground "wall" extends across the bottom three rows in `world1-area1.png`). The probe directory was cleaned after measurement.
- **Fix:** Changed the test's `groundTiles` set to `setOf(0x08, 0x09, 0x0a, 0x0b, 0x0c, 0x0d)`. Updated the assertion failure message to reference `{0x08..0x0d}`. Added a class-level header comment explaining the correction and an inline comment at the assertion site pointing to the header.
- **Why this is still REQ-2-conformant:** The plan's AC5 structural intent is "row 31 contains ground-tile values distinct from the 0x11 sky" — the concrete set is an instance of that intent. The corrected `{0x08..0x0d}` set is the same structural assertion with the empirically-measured values. A modulo-tiled grid (Defect 7) would still fail all three assertions: (a) size ≠ 1920, OR (b) row 0 wouldn't be uniform 0x11, OR (c) row 31 wouldn't carry the specific ground-tile values that emerge from straight-copy png2asset output.
- **Files modified:** `gbkt-gradle-plugin/src/test/kotlin/io/github/gbkt/gradle/tasks/ConvertZoneTilesetsTaskTest.kt` (groundTiles set + 3 comment blocks).
- **Commit:** `e5e7d24d` (single task commit — the test went through one RED iteration before turning GREEN with this correction).
