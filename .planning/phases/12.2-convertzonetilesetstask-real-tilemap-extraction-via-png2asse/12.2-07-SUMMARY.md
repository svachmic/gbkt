## Decisions Made

- **Loose-parent `assertFailsWith<Exception>` over strict `<IllegalArgumentException>`.** Production code throws `IllegalArgumentException` today (Kotlin `require()` semantics). The plan-text's `<interfaces>` guidance prefers loose parent because Gradle task execution sometimes wraps exceptions across versions, and the message-based assertion is the load-bearing structural lock. The loose form keeps the test resilient to Gradle drift; the message-based contract is the actual contract.
- **Keyword set `{"tilemap", "missing", "not found"}`.** Plan-text spec. The production message contains `tilemap` AND `not found`, so all three of the assertion's accept conditions match. Future regressions that:
  * change the message to say "asset missing" (drop "tilemap") would still pass — guarded by "missing" (currently absent from production but accepted by the lock).
  * drop both "tilemap" and "not found" but say "Zone play_zone has no map data" would FAIL — message contains "play_zone" but no member of the keyword set.
  This is the intended structural tolerance: lock the load-bearing diagnostic content without over-constraining the wording.
- **Test placed BETWEEN Plan 06's last test and the MAX_ZONE_TILESET_TILES sanity test.** Plan 05 placed its REQ-2 test before the sanity check; Plan 06 placed its REQ-3 test before the sanity check; Plan 07 continues that convention. Reading order: happy paths → guards → emission invariants (Plans 05+06) → fail-fast diagnostics (this plan + the existing D-C2/D-C4/D-C3 set) → sanity check. The new test is grouped with the *other* fail-fast tests (D-C2 at line 242, D-C4 at line 291, D-C3 at line 340, D-01-missing-bank at line 489) only by intent — by line position it lands right before the sanity check, matching Plans 05/06.
- **Reused `play_zone` zone id from plan-text.** Distinct from the existing missing-tileset test's `absent_zone` id, so when scanning the test-suite stdout one can tell at a glance which fail-fast guard fired (D-C2 missing tileset vs REQ-4 missing tilemap).
- **`gbdkHome.set(File(tempDir, "fake-gbdk").apply { mkdirs() }.absolutePath)`** — same pattern as the existing D-C2 test (line 274). The task's `GbdkToolchain.find` resolves a structurally-valid path; the executable is never invoked because the `require()` fires first. Empirically verified by the 8 ms wall time (vs ~440 ms for the full happy-path png2asset invocation in Test 1).
- **No spotless reconciliation attempted.** Same SCOPE BOUNDARY reasoning as Plans 12.2-01, 12.2-03, 12.2-04, 12.2-05, 12.2-06: the gradle-plugin module has pre-existing spotless drift across ~9 unrelated files; running `spotlessApply` would balloon this commit with unrelated reformatting.
