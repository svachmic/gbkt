## Back-compat for tilemap()-less zones

| Option | Description | Selected |
|--------|-------------|----------|
| Skip tilemap emission entirely | Emit no `_zone_<id>_tilemap.c`; drop extern and WIDTH/HEIGHT defines. Cleanest but requires verifying GBDKPipelineV2's setup_current_level doesn't emit `BANK(_zone_play_zone_tilemap)` for banks. | |
| Emit a 1-byte stub tilemap | `const uint8_t _zone_<id>_tilemap[1] = {0};` with `WIDTH=1/HEIGHT=1`. Trivial dead bytes; weird semantics. | |
| Hard-fail with DSL-migration diagnostic | Per SPEC Requirement 4 literal text. Forces edit to Banks.kt despite SPEC out-of-scope clause. | |
| Reuse first-pass `_tileset_map[]` as tilemap | When `tilemap()` absent, emit tilemap.c populated with raw `_tileset_map[]` from first png2asset invocation. Banks gets a 2×2 tilemap (correct checker). `size(W,H)` ignored. No second invocation. | ✓ (chosen via Claude ultrathink) |

**User's choice:** "Ultrathink about this as a senior gbdk/kotlin engineer and propose the best solution to future-proof this and avoid recurring bugs."

**Notes:** Claude analyzed all four options and recommended option (4) — reuse first-pass `_tileset_map[]` — captured in CONTEXT.md as **D-01 (Path A)**. Rationale:

1. Maps 1:1 to png2asset's two real modes (single-PNG vs two-PNG); DSL becomes faithful surface over the tool.
2. Defect 7 cannot recur — synthesizer is DELETED, not reached-but-empty.
3. Banks gets correct output with zero DSL edits (`checker.png` 16×16 → real 2×2 tilemap; `size(20,18)` becomes harmless vestigial).
4. Backward compat is real, not a stub. Output structurally identical to GBDK's reference `TitleScreen.c`/`NextLevel.c`.
5. No SPEC migration error needed. Hard-fail still applies for genuinely-broken case (tilemap() set but file missing).
6. WIDTH/HEIGHT always from real PNG dims; SPEC Requirement 3 satisfied without special-casing.

**SPEC literal-text deviation flagged for verifier:** SPEC Requirement 1's acceptance criterion says "PlatformerTemplate.kt's 5 zones each call `tilemap(asset("graphics/<zone>.png"))`". D-01 tightens this to 3 zones (the `world*-area*` ones); `titleZone` and `nextLevelZone` remain `tileset()`-only. Observable behavior is identical; DSL is semantically clearer. Planner records the deviation in per-plan SUMMARY.md and 12.2-VERIFICATION.md.

## png2asset output processing strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Parse-and-re-emit (matches 11.2 pattern) | Run png2asset → read .c → regex-parse `<Stem>_map[N]` → emit fresh `_zone_<id>_tilemap.c` with our header. Robust; matches Phase 11.2's existing parser. | ✓ |
| -bin mode + emit ourselves | Run png2asset with `-bin` → raw bytes → emit C array. Requires verifying `-bin` shape; most isolated. | |
| In-place pragma injection + symbol rename | Read .c → prepend header + rewrite symbol inline. Fewest moving parts. Risk: auxiliary symbols flow through verbatim. | |
| Accept .c file as-is + alias via header | Inject `#pragma bank N` at top + alias `_zone_<id>_tilemap` to `<Stem>_map` in header. Symbol indirection obscures byte array from grep tests. | |

**User's choice:** Parse-and-re-emit
**Notes:** Captured as **D-02**. Matches Phase 11.2's existing `synthesizeScreenTilemap` parser (ConvertZoneTilesetsTask.kt:393-430). Tightest control; reuses proven pattern. Path A's one-invocation case (D-01) also uses parse-and-re-emit against the first png2asset output's `_tileset_map[]`; the two paths share the parser, differing only in which png2asset invocation's output gets read.

## DSL signature for tilemap()

| Option | Description | Selected |
|--------|-------------|----------|
| AssetRef only (typed) | `fun tilemap(ref: AssetRef)`. Matches modern typed-ref convention (no magic strings). Simpler API surface. | ✓ |
| Both String and AssetRef (matches tileset) | Two overloads mirroring `tileset()`. Symmetric with existing pattern; slightly larger API surface. | |
| AssetRef only + later add String if asked | Ship AssetRef-only; add String later if needed. Smallest surface; preserves option to expand. | |

**User's choice:** AssetRef only (typed)
**Notes:** Captured as **D-03**. Enforces `feedback_no_magic_strings.md` rule. `tileset()`'s dual-surface (`String` + `AssetRef`) is itself a candidate for future cleanup — deferred to a future phase, not in 12.2 scope.
