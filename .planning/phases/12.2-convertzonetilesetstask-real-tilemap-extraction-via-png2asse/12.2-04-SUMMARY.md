## Decisions Made

- **`synthesizeHeader` does the ImageIO.read, not `convertOneTileset`.** The plan-text gave two options (read in caller and pass dims; read inside header). Chose the header-internal read because it's where the WIDTH/HEIGHT macros are emitted — keeps the IHDR → macro pipeline in one place and makes future tests that lock per-zone WIDTH/HEIGHT shape against PNG dims easier to express.
- **Multiple-of-8 require-guard inside `synthesizeHeader`.** The caller (`convertOneTileset`) already validates the tileset PNG's IHDR for multiple-of-8 (existing D-C4 guard), but it does NOT validate the optional tilemap PNG. Re-checking inside `synthesizeHeader` for `tilemapPng` covers both paths (one-invocation = re-check tileset PNG, two-invocation = first-time check on the tilemap PNG). Cheap defensive guard with a clear error message.
- **`convertOneTileset` unused params kept.** Plan-text directive: removing `screenMapWidth/screenMapHeight` from the function signature cascades into `convertZoneTilesets`' read of `entry.getInt("mapWidth")` / `("mapHeight")` and the metadata-emission code in GBDKPipelineV2.buildMetadataFile. Out of scope per terminal-subphase rule. Added `@Suppress("UNUSED_PARAMETER")` + KDoc to make the deprecation explicit.
