# Phase 12.8 Plan 03: W3 Absorb-Path Codegen Fix — Conditional `-keep_palette_order` (Re-Scoped)

W3 codegen fix per the W2 ABSORB verdict, RE-SCOPED after the orchestrator surfaced a wider blast radius than the initial plan captured. The fix is now a RUNTIME-CONDITIONAL flag-pass-through: `-keep_palette_order` is appended to the png2asset invocation iff the PNG's IHDR color-type byte is `3` (indexed/colormap). RGB and RGBA PNGs — including `banks/res/tiles/checker.png`, `platformer-template/res/graphics/title-screen.png`, and `platformer-template/res/graphics/next-level.png` — see the original 8-arg flag set, exactly as pre-12.8, and continue to compile cleanly.

This re-scope preserves both load-bearing W3 doctrines:
- **W2 ABSORB verdict** — the fix lands in one production file (`ConvertZoneTilesetsTask.kt`), not multiple, so the routing decision stands.
- **Reference Makefile alignment** — line 82 of `platformer_template/Makefile` passes `-keep_palette_order` for the indexed `world1-tileset.png`; our conditional emission lines up with that authoritative oracle.

## Deviations from Plan

### 1. [Round 1 — superseded by Round 2] Unconditional flag pin broke RGB fixture tests

- **Was a Rule 4 architectural deviation in round 1** (commit `16ddf5ce`): unconditional `"-keep_palette_order"` element appended to args list broke 4 `ConvertZoneTilesetsTaskTest` tests (checker.png + title-screen.png RGB fixtures) because png2asset rejects the flag on RGB inputs.
- **Resolved by Round 2 (commit `13037c9b`):** conditional `isIndexedPng` guard suppresses the flag for RGB inputs. The 4 previously-failing tests now PASS. Truth #5 from the must_haves is satisfied.

### 2. [Round 1 — Worktree mechanics #3099] Initial edits leaked to main repo via absolute-path drift

- Documented in the round-1 commit and retained here for the orchestrator audit trail.
- **No data lost; main repo HEAD untouched.** Used the sanctioned `git checkout -- <single-file>` recovery (per `destructive_git_prohibition`) and re-applied via worktree-prefixed absolute paths.

### 3. [Round 2 — Scope expansion, user-approved] New sibling test file `IsIndexedPngTest.kt`

- The round-1 `<critical_scope_rules>` said "ONLY modify ConvertZoneTilesetsTask.kt". The round-2 user instruction explicitly authorized adding a sibling test class for the new helper.
- Chose to add `IsIndexedPngTest.kt` as a NEW sibling test file (not edits to `ConvertZoneTilesetsTaskTest.kt`) to keep the round-1 cleanup minimal and to follow the existing per-feature emission-test naming convention seen elsewhere in `gbkt-gradle-plugin/src/test/.../tasks/`.
- 5 test methods (instructed minimum was 2). The 3 extra cover structural guards (missing file, truncated header, signature mismatch) that the caller relies on for the `false ⇒ do NOT pass flag` safety contract — these are not stylistic; they prevent the helper from accidentally returning `true` on malformed input and re-introducing the original png2asset exit=1 failure mode.

### 4. [Visibility change — necessary for test access] `isIndexedPng` raised from `private` to `internal`

- The helper needs to be callable from the sibling test class to exercise both branches without reflection. Marked `internal` (Kotlin's package-private analog scoped to the compilation module) and documented inline. Documentation block in the helper notes the visibility rationale so future readers don't widen further on speculation.

## Threat Surface Scan

No new threat surface introduced. The conditional shape is BETTER than the unconditional shape from a Tampering perspective:

- **T-12.8-01 (Flag change affects byte output of OTHER zone tilesets):** Now strictly scoped to indexed PNGs. RGB tilesets (banks/checker, title-screen, next-level) see byte-identical png2asset output to pre-12.8 (the args list shape is preserved); only indexed tilesets see the flag impact.

- **T-12.8-W3 (Edit accidentally touches second-invocation args list):** Continued mitigation — the second-invocation `tilemapArgs` listOf at kt:373-383 is byte-identical to its pre-edit shape; only the leading comment was reworded in round 1, not the args list itself.
