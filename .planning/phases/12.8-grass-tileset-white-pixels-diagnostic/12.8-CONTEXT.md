## Specific Ideas

- **Reference Makefile line numbers `84-86`** — D-01 names this exact range
  for cross-check. Worth confirming the line numbers match the current
  GBDK 2020 release the user has installed; if not, search the Makefile
  for `world1-tileset.png` and grep the surrounding png2asset invocation.
- **The "white pixels" symptom is most likely DMG palette index 0
  manifesting as LCD transparent** — per seed Hypothesis 1. The diagnostic
  evidence should explicitly call out which color in `world1-tileset.png`
  maps to index 0 in the post-png2asset palette. If it's an unintentional
  background color, fix; if it's the intended grass shade, the bug is in
  palette assignment ordering (`-keep_palette_order` was REMOVED at the
  spike per `ConvertZoneTilesetsTask.kt:55`, which may need re-evaluation).
- **`-keep_palette_order` re-evaluation** — the comment at line 51-57 says
  png2asset rejected the flag on RGB (non-indexed) PNGs at the Plan 02
  spike. If world1-tileset.png is actually INDEXED (not RGB), the flag may
  work and SHOULD be added. W1 diagnostic verifies the PNG color mode.
- **0F/F text rendering hint** — `0F` and `F` in the nextlevel-card text
  corruption look like ASCII chars 0x46 (`F`) being rendered with a corrupt
  font tile. This is consistent with palette-index-0 mapping to white,
  which means the font's foreground pixels (intended as DMG dark-grey)
  render as white — D-10's "same flag may fix both" hypothesis derives
  from this.
- **The 1-2 px sink (D-09) is suspiciously consistent with a tile-edge
  rounding error** — if the grass tilemap row has its top edge encoded one
  pixel below where the AABB collision expects it, the player's
  visually-grounded foot would render 1-2 px below the visual surface.
  This connects D-09 to D-07 (char-sunk) as plausibly same-root-cause.

The png2asset binary is consumed at `${GBDK_HOME}/bin/png2asset` —
whatever the user has installed. If a future png2asset version changes
output format silently, D-13's JVM test catches it but only at test-run
time. A `gbkt-gradle-plugin` task that pins png2asset version + hash would
be a stronger guarantee. Out of scope for 12.8.

genre-platformer expansion. Capture as seed if 12.8 diagnostic confirms
the issue is structural rather than a flag delta.
