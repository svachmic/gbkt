Make zone and scene declarations **no-magic-string and safe-by-default**, the third
of five Phase-13 framework-primitive sub-phases. Owns exactly Req #10/#13/#14:

Phase 13.5 (titleZone/nextLevelZone migrated to `by zone` here will be re-migrated to

<decisions>
## Implementation Decisions

### Req #14 — PNG-derived safe `size` default

- **D-01: Derivation runs in the gradle task, NOT in the DSL.** `gbkt-lang` has **zero**
  filesystem/ImageIO usage (re-confirmed) and must keep that boundary (same reason
  13.3 D-07 deferred png2asset's frame count to a gradle task). `ZoneBuilder.build()`
  emits an **"auto" sentinel** for `mapWidth`/`mapHeight` when `size()` is omitted;
  `ConvertZoneTilesetsTask` (already reads the PNG via ImageIO and already consumes
  `mapWidth`/`mapHeight` from `game_metadata.json`) derives the tile dims and back-fills.
  Do NOT introduce ImageIO/File reads into `gbkt-lang`/`ZoneBuilder`.
- **D-02: A pure `resolveZoneSize(explicit?, derivedPngTileDims?)` function holds the
  deterministic fallback chain.** Lives in a JVM-unit-testable location (`gbkt-lang` or
  `gbkt-core`); takes resolved inputs (no file IO) and returns the final `(w, h)`. The
  gradle task supplies `derivedPngTileDims` by reading the PNG. This satisfies Req #14's
  "JVM test asserts derived dims" acceptance at the **policy** tier (pure fn:
  derived→derived, derived=null→20×18, explicit→explicit), while the **PNG read** is
  proven end-to-end by the `banks` `:buildRom` smoke. Do NOT put the policy test in
  `gbkt-gradle-plugin` against a fixture PNG (heavier, couples policy to file IO).
- **D-03: Disambiguation rule — `tilemap()` presence drives derivation.**
  - `tilemap(asset)` present → derive size from the **tilemap PNG**'s tile dimensions.
  - tileset-only (no `tilemap()`) → fall back to **20×18** (the tileset PNG is treated
    purely as a tile source, NEVER as map dimensions).
  - explicit `size(w, h)` **always wins**.
  - the literal **32×32** default is eliminated; no path yields it.
  Rationale: banks' checker (tileset-only, ~2×2 tiles) and platformer's titleZone
  (tileset-only full-screen banner) are **structurally indistinguishable in the IR** —
  there is no "repeating vs full-image" flag. Deriving from a tileset-only PNG would
  emit a broken 2×2 banks zone, so we must never do it; 20×18 (full GB screen) is the
  safe default and `size()` is the override. No image-sniffing/threshold heuristic
  (against gbkt's determinism value).
- **D-04: banner zones (titleZone/nextLevelZone) get explicit `size(20, 9)` in 13.4.**
  They are 160×72px = **20×9-tile** tileset-only banners; the 20×18 fallback would pad
  9 rows of garbage. Explicit `size(20, 9)` (explicit always wins → D-03) makes them
  emit correctly NOW; the explicit size is **removed when they become `screen()` in
  13.5** (which derives 20×9 from the full-image PNG). This is "good defaults, full
  control" (13.1 D-05): 20×18 fallback is for true full-screens; non-standard banners
  declare their size. Do NOT ship the visually-wrong 20×18 form (quality/visual-evidence
  rule).
- **D-05: platformer world zones (60×32) derive from their tilemap PNG.** They are
  `tileset + tilemap(world-areaN.png)` where the tilemap is 480×256px = **60×32 tiles**
  — today truncated to the magic 32×32 (actively losing half the level). Deriving 60×32
  is a **correctness fix** that **grows** the emitted tilemap; this is legitimate per
  Req #14's intent and `platformer-template` is NOT in the 7-target byte-identity
  regression sweep (it only needs to build GREEN). **Researcher/planner verification
  item:** confirm the grown 60×32 tilemap does not overflow its bank in
  `platformer-template:buildRom`.
- **D-06: banks drops its explicit `size(20, 18)`.** Falls through to the tileset-only
  20×18 fallback (D-03) → must emit a byte-identical-or-smaller zone tilemap (Req #14
  acceptance; banks IS in the regression sweep).

### Req #13 — `navigate(...)` / `start` ref-only

- **D-07: Incremental migrate-then-delete (suite GREEN every commit).** First migrate
  all callers to `navigate(sceneRef)` / `start = sceneRef` while BOTH the string and ref
  forms still compile (16 test files + 2 example mains + any `start = "..."` fixtures),
  keeping `./gradlew test` GREEN at every commit. THEN a final plan deletes the
  `navigate(String)` overload and the `start`-String path once nothing references them.
  No giant atomic breaking commit; aligns with the "many small plans, each GREEN"
  feedback. NOT an atomic delete-and-fix-all sweep.
- **D-08: `start` becomes `SceneRef?`; validation preserved on the SceneRef path.**
  `var start: String? = null` → `var start: SceneRef? = null`. The build-time validation
  (start-not-null; start references a registered scene; "Did you mean?" suggestion) is
  rewired off `SceneRef.id`. The error message changes from `start = "sceneId"` to the
  ref form. `start` stays nullable (the not-null check still fires at `build()`). Req #13
  acceptance: the start-scene validation (unset / unknown scene) still fails in a JVM
  test via the `SceneRef` path.
- **D-09: No `@Deprecated` shim** for `navigate(String)` or the `start`-String path —
  hard-remove (13.1 D-11 / 13.2 D-17 / 13.3 D-16 precedent). After the final delete,
  `grep -rn 'navigate("'` and `grep -rn 'start = "'` (excl. archive/build) return zero
  non-comment hits; KDoc examples updated to ref form.

### Req #10 — `by zone { }` delegate + `zone(String)` hard-remove

- **D-10: `ZoneDelegate` mirrors `MetaspriteDelegate` exactly.** Single-use guard
  (reuse/double-bind throws `IllegalStateException`), `GameBuilderContext.current` lookup
  (errors if used outside a `game { }` block), `property.name → ZoneRef.id`, returns a
  `ZoneRef` usable everywhere the string form's `ZoneRef` is used today. Factory:
  `fun zone(block: ZoneBuilder.() -> Unit): ZoneDelegate` (mirrors
  `MetaspriteBuilder.kt:524`). A JVM test asserts the registered `ZoneRef.id` equals the
  property name and that reuse is rejected.
- **D-11: Full delegate-only hard-remove of `zone(String, block)`** (the declaration
  form), matching the metasprite blueprint (metasprite is delegate-ONLY — there is no
  `metasprite("id")` factory). The user chose maximal no-magic-strings symmetry over the
  SPEC's literal "add only" scope. The `zone(ref: ZoneRef)` **load** overload (used in
  scene-enter, e.g. `zone(playZone)`) is a DIFFERENT API and is **preserved** — only the
  String-id **declaration** form is removed.
- **D-12: `ZonePlatformerPhysicsTest`'s 4 method-form `gb.zone("z1") {}` calls are
  restructured into a `game { val z1 by zone {} }` block.** These use an explicit
  receiver outside any `game { }` block, so they cannot use the delegate as-is (it needs
  `GameBuilderContext.current`). Restructure them rather than keep an escape-hatch factory
  — true delegate-only, no permanent string footgun. (This was the alternative the user
  rejected; recorded for honesty.)
- **D-13: Unwire `LabyrinthOfTheDragon-port` from the build** — comment out
  `include("LabyrinthOfTheDragon-port")` in `settings.gradle.kts:66`, deferring the port
  to the next milestone. This is REQUIRED for D-11: Labyrinth's 8 floor files use
  `zone("floorN")` and are a compiled subproject, so hard-removing `zone(String)` would
  break their Kotlin compilation and fail `./gradlew test`. Unwiring is consistent with
  the port's existing deferred `:buildRom` debt (it already cannot build —
  `project_rpg_char_codegen_debt`). Capture a deferred idea: "re-wire + migrate Labyrinth
  to `by zone` in the next milestone."
- **D-14: Migration blast radius (post-unwire) ≈ 32 in-repo callers**, all framework
  test/example code: ~18 `gbkt-backend-gbdk` pipeline tests
  (`LevelCardSceneEmissionTest`, `LevelSwitchEmissionTest`,
  `TilemapCollisionPathCEmissionTest`, `SetupCurrentLevelDisplayGateEmissionTest`,
  `TitleSceneEmissionTest`), 6 `gbkt-genre-platformer` tests (`PlatformerInputDslTest` +
  the 4 restructured `ZonePlatformerPhysicsTest` calls), 1 `gbkt-core`
  `WorldBuilderTest`, plus `banks` (1) and `platformer-template` (5). KDoc/comment
  examples (`GameBuilder.kt:470`, `SceneBuilder.kt:148`, `PlatformerExtensions.kt:265,410`,
  `PickupBuilder.kt:99,187,223`) updated to the `by zone` form for doc honesty. **Researcher
  MUST enumerate the full post-unwire caller set before planning.**

<specifics>
## Specific Ideas

- A zone should read as `val playZone by zone { tileset(asset("tiles/checker.png")) }` —
  no duplicated `"play_zone"` string, no `size(20, 18)` ceremony (derived/defaulted),
  matching the `val elephant by metasprite { }` headline shape from 13.3.
- Navigation should read as `navigate(titleScene)` / `start = titleScene` — never
  `navigate("title")` / `start = titleScene.id`. The `.id` accessor and string literals
  disappear from author code.
- The size default should be **invisible when correct and loud when wrong**: omit `size()`
  and get the right dims (derived from `tilemap()`) or a safe 20×18 — never a silent 32×32
  that truncates a 60-wide level (the exact bug Req #14 kills, visible in platformer's
  world zones).
- The user explicitly chose **maximal no-magic-strings symmetry** for zones (full
  `zone(String)` hard-remove) over the SPEC's narrower "add the delegate" scope, accepting
  the Labyrinth-unwire cost — consistent with the 13.3 "wider blast radius for a single
  clean surface" appetite (13.3 D-13 Color sweep).

</specifics>
