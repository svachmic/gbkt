# Phase 13.4 Plan 08: Migrate banks + platformer-template to by zone, navigate(ref), startScene Summary

**One-liner:** Banks + platformer-template (5 zones) migrated to `by zone` delegate with D-03/D-04/D-05/D-06 size policy; `navigate(ref)` + `startScene = ref` across both examples; both generateC GREEN.

## What Was Built

Migrated the two zone-bearing example mains to the new Wave 1 primitives:

**banks (D-06 + D-07):**
- `val playZone = zone("play_zone") { ...; size(20, 18) }` → `val playZone by zone { tileset(...) }` — drops the explicit `size(20, 18)`, falling through to the tileset-only 20×18 fallback in `resolveZoneSize` (byte-identical output)
- `navigate("play")` / `navigate("play")` → `navigate(playSceneRef)` / `navigate(playScene)` using `sceneRef("play")` forward-ref
- `start = "title"` → `startScene = titleScene` (Plan 13.4-03 migration target)
- `import io.github.gbkt.core.dsl.zone` added (disambiguation of member vs top-level)

**platformer-template (D-04 + D-05 + D-07):**
- 3 world zones (`world1Area1Zone`, `world1Area2Zone`, `world2Area1Zone`): `val ... = zone("...") {}` → `val ... by zone {}` with `tilemap(asset(...))` and NO explicit `size()` — `resolveZoneSize` derives 60×32 from the tilemap PNG (D-05 correctness fix; previously silently truncated to 32×32)
- 2 banner zones (`titleZone`, `nextLevelZone`): `val ... = zone("...") {}` → `val ... by zone { ...; size(20, 9) }` — explicit `size(20, 9)` preserved (D-04; 20×9-tile banners must NOT use the 20×18 fallback)
- `zone(titleZone)` / `zone(nextLevelZone)` LOAD calls in scene blocks preserved (D-11 Pitfall 1)
- `navigate("gameplay")` → `navigate(SceneRef("gameplay"))` forward-ref (data class ctor usable from ScriptBuilder scope)
- `start = titleScene.id` → `startScene = titleScene`
- `import io.github.gbkt.core.dsl.zone` added

## Key Design Decisions

- `import io.github.gbkt.core.dsl.zone` is REQUIRED in both files — the `by zone` property delegate uses the top-level `fun zone(block): ZoneDelegate` factory from `WorldBuilders.kt`, but inside a `game { }` block the member `GameBuilder.zone(String, block)` shadows it (Kotlin receiver resolution prefers the member). Wave context documented this GOTCHA; the explicit import resolves the ambiguity.
- `sceneRef("play")` used as `playSceneRef` for the `pauseScene` forward-ref in Banks.kt — `sceneRef()` is a `GameBuilder` member, accessible from inside the game lambda. The `SceneRef("gameplay")` data class constructor is used inside a `whenever()` block in platformer-template because `sceneRef()` is not accessible from `ScriptBuilder` scope.
- `frames(6)` replaces the 6 procedural `frame { tile(...) }` blocks (Rule 1 auto-fix) — the D-08 exactly-one guard (Plan 13.3-06) rejects the mixed asset-driven + procedural form. The asset-driven path (`sprite(asset(...))` + `mode/pivot/frameSize`) handles sprite data loading; `frames(6)` declares the frame count.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] PlatformerTemplate.kt player metasprite mixed asset-driven + procedural frame{} form rejected by D-08 exactly-one guard**

- **Found during:** Task 2 — `generateC` failed with `IllegalArgumentException: metasprite "player": cannot use both sprite(asset(...)) and frame{}`
- **Issue:** The D-08 exactly-one guard (Plan 13.3-06 `31c3c15b`) was added during Phase 13.3 to enforce that metasprites use EITHER the asset-driven path (`sprite(asset(...))`) OR the procedural path (`frame { tile(...) }`), never both. PlatformerTemplate.kt was never migrated — it had `sprite(asset(...)) { mode/pivot/frameSize }` (asset-driven) PLUS 6 `frame { tile(...) }` blocks (procedural).
- **Root cause:** Pre-existing; the guard was introduced after the platformer-template was authored. The `generateC` was silently failing before Plan 13.4-08 even touched the file.
- **Fix:** Removed the 6 procedural `frame { tile(...) }` blocks; replaced with `frames(6)` to declare the frame count for the asset-driven path. The `sprite(asset(...))` with `mode(SpriteMode.SPR8x16)`, `pivot(12, 6)`, and `frameSize(24, 32)` provide the geometry to `png2asset`; `ConvertSpritesTask` derives the sprite layout from the PNG.
- **Files modified:** `PlatformerTemplate.kt`
- **Commit:** 90cbe856

**2. [Rule 1 - Bug] sceneRef() not accessible from ScriptBuilder scope in platformer-template**

- **Found during:** Task 2 compilation — `sceneRef("gameplay")` inside `whenever()` block failed: "'fun sceneRef(id: String): SceneRef' cannot be called in this context with an implicit receiver"
- **Issue:** `sceneRef()` is a `GameBuilder` member function; the `whenever()` block lambda has a `ScriptBuilder` receiver, which does not inherit `GameBuilder` scope
- **Fix:** Used `SceneRef("gameplay")` (data class constructor, publicly importable via `io.github.gbkt.core.dsl.*`) as the forward reference — identical semantics, no implicit receiver required
- **Files modified:** `PlatformerTemplate.kt`
- **Commit:** 90cbe856
