<objective>
Introduce the SceneRef-typed start surface (Req #13b / D-08) so authors write `startScene =
titleScene` with no `.id` and no string literal, and rewire the build-time start validation
(not-null, registered-scene, "Did you mean?") off `SceneRef.id`. Because flipping `var start`
to `SceneRef?` has a ~69-file compile blast radius and a String literal CANNOT be intercepted
by any `fun` once the property type is `SceneRef?`, this plan uses the ONLY assignment-compatible
Kotlin-valid bridge: it KEEPS the public `var start: String? = null` alive during the migration
wave and adds a SEPARATE temporary PUBLIC `var startScene: SceneRef? = null` (PUBLIC because migrated callers assign it from OTHER Gradle modules — gbkt-core/genre/backend/examples — where an `internal` member of gbkt-lang would be inaccessible; mirrors why the existing `var start: String?` is public). Migrated callers
(plans 04–08) assign `startScene = <ref>`; unmigrated `start = "..."` fixtures keep compiling
against `start: String?`. `build()` resolves `startRef = startScene ?: start?.let { SceneRef(it) }`
and validates off `startRef.id`. The terminal plan 13.4-09 then DELETES `start: String?` and
RENAMES `startScene`→`start`, so the END-STATE public surface is exactly `var start: SceneRef?`
(D-08) with no string path and no @Deprecated shim (D-09/D-15). Migrate the `GameBuilderTest`
start-validation tests to the `startScene = SceneRef(...)` form so validation coverage moves to
the new path.

Purpose: Unlock the SceneRef start surface and the staged 69-file migration while keeping
`./gradlew test` GREEN at every commit (D-07) with a mechanism Kotlin actually permits.
Output: PUBLIC `var startScene: SceneRef?` + rewired validation off startRef.id + retained
`var start: String?` bridge; migrated GameBuilderTest.
</objective>
