## Key Design Decisions

1. **Explicit `import io.github.gbkt.core.dsl.zone` required for all 5 declaration-bearing files.** Inside a `game { }` block, the `GameBuilder.zone(id: String, block)` member function has resolution priority over the top-level `zone(block): ZoneDelegate` factory. Without the explicit import, Kotlin resolves `val x by zone { }` to the member function and errors with "No value passed for parameter 'id'". The explicit import makes the top-level function visible and Kotlin correctly prefers it for the `by` delegation syntax.

2. **`SceneRef(id)` constructor used for forward-reference navigate targets.** All the pipeline tests have scene graphs with navigation cycles (title→gameplay→nextLevel→gameplay) or forward references (title scene navigates to gameplay before gameplay is declared). Since `whenever { ... }` lambdas execute immediately during DSL recording, `navigate(gameplayScene)` would trigger a "Variable must be initialized before use" error for forward references. Using `navigate(SceneRef("gameplay"))` is semantically identical (both produce `NavigateTo("gameplay")` in the IR) and avoids the forward reference.

3. **Captured `val sceneX = scene(...)` used for backward-reference navigate targets.** Where the navigate target is already declared before the navigating scene (e.g., `scene("gameplay")` navigates back to `titleScene` which was declared first), the captured val is used directly: `navigate(titleScene)`.

4. **Zone LOAD calls preserved.** `zone(gameplayZone1)` calls inside `scene { }` blocks are the `zone(ref: ZoneRef)` load overload and were NOT migrated — these remain exactly as before (D-11 preserved).

**2. [Rule 1 - Bug] Forward-reference problem in navigate(sceneRef) for cyclic scene graphs**
- **Found during:** Task 2 analysis
- **Issue:** Pipeline tests have scenes that navigate to other scenes declared later (forward reference). `whenever { navigate(targetScene) }` executes immediately during DSL recording; accessing `targetScene` before `val targetScene = scene(...)` completes would cause `UninitializedPropertyAccessException`
- **Fix:** Used `navigate(SceneRef("id"))` constructor directly for forward references, preserving identical semantics (both produce `NavigateTo(id)` in the IR). Backward references (scenes already declared) use the captured val
- **Files modified:** LevelCardSceneEmissionTest.kt, LevelSwitchEmissionTest.kt, TilemapCollisionPathCEmissionTest.kt, SetupCurrentLevelDisplayGateEmissionTest.kt, TitleSceneEmissionTest.kt (for navigate calls), CrossBankZoneTilemapAccessTest.kt (for raceScene capture)
