# Phase 13.4: framework primitives — zone & scene ergonomics — Specification

**Created:** 2026-06-04
**Ambiguity score:** 0.16 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

Make zone and scene declarations no-magic-string and safe-by-default: introduce a `by zone { }` property delegate (Req #10), hard-remove the string forms of `navigate(...)` and `start` in favor of `SceneRef` (Req #13), and replace the dangerous `size(32, 32)` zone default with a PNG-derived (else 20×18) safe default (Req #14) — then migrate every active caller across examples and tests so the framework compiles and all ROMs build GREEN with same-or-smaller generated C.

## Background

Grounded in the current codebase (2026-06-04, branch `feat/d_and_d_gaps`):

- **Req #10 — no `ZoneDelegate`.** `GameBuilder.zone(id: String, block)` (`gbkt-lang/.../GameBuilder.kt:482`) is string-form only. The analog already exists: `MetaspriteDelegate.provideDelegate` (`gbkt-lang/.../MetaspriteBuilder.kt:461`) captures the Kotlin property name via `by` — a direct blueprint. Active string-form zone call sites: `Banks.kt:56` (1 zone) and `PlatformerTemplate.kt:261,266,271,302,305` (5 zones). Archive `dungeon`/`explorer` are inactive (`gbkt-examples/.archive/`) and out of scope.

- **Req #13 — string/ref split.** Both `navigate(String)` (`ScriptBuilder.kt:283`) and `navigate(SceneRef)` (`ScriptBuilder.kt:288`) exist; neither is deprecated. `GameBuilder.start: String? = null` (`GameBuilder.kt:98`) is String-only, forcing `start = titleScene.id`. Real (non-comment) string-form callers: `PlatformerTemplate.kt:408`, `Banks.kt:69,95`, `Banks.kt:98` (`start = "title"`), plus **16 test files** that build game IR with `navigate("...")` (across `gbkt-backend-gbdk`, `gbkt-lang`, `gbkt-core`, `gbkt-genre-rpg`, `gbkt-gradle-plugin`). ~12 builder/genre **KDoc comment** blocks also show `navigate("...")` examples (cosmetic — won't break compilation).

- **Req #14 — magic 32×32.** `ZoneBuilder` defaults `mapWidth/mapHeight = 32` (`WorldBuilders.kt:69-70`); `size(w,h)` (`WorldBuilders.kt:123`) merely overwrites them. Per PATTERNS gotcha #6 the 32×32 default writes 1024 tile indices over a smaller tile array (e.g. the 4-byte checker), so every author must hand-write `size(20, 18)` (`Banks.kt`). The post-12.2 Path A pipeline already knows a zone PNG's tile dimensions.

This phase is the third of five Phase-13 subsystem sub-phases (13.1, 13.2, 13.3 complete). It owns Req #10/#13/#14 only; the codegen-heavy Req #15/#17/#18 belong to Phase 13.5.

## Requirements

1. **`by zone { }` delegate (Req #10)**: Zones can be declared via the property delegate so the zone ID is inferred from the Kotlin property name — no duplicated magic string.
   - Current: only `zone("id") { }` exists; no `ZoneDelegate`. `val play = zone("play_zone") { }` duplicates the name as a string.
   - Target: `val playZone by zone { }` registers a zone whose ID is the property name (`"playZone"`), mirroring `MetaspriteDelegate`; returns a `ZoneRef` usable everywhere the string form's `ZoneRef` is used today. The delegate must reject reuse/double-binding the same way `MetaspriteDelegate` does.
   - Acceptance: a `by zone { }` JVM test asserts the registered `ZoneRef.id` equals the property name; `banks` and `platformer-template` declare all zones via `by zone` with zero `zone("...")` string literals; generated C for those ROMs is byte-identical-or-smaller vs the pre-migration baseline.

2. **Hard-remove string `navigate(...)` (Req #13a)**: The string overload `navigate(String)` is deleted — only `navigate(SceneRef)` remains.
   - Current: `navigate(String)` and `navigate(SceneRef)` coexist; authors mix both forms (Banks.kt:69/95 string, others ref).
   - Target: `navigate(String)` is removed from `ScriptBuilder`; any `navigate("x")` call is a **compile error**. All real callers (2 example mains + 16 test files) migrate to `navigate(sceneRef)`. KDoc examples in builders/genres are updated to the ref form for doc honesty.
   - Acceptance: `grep -rn 'navigate("' --include=*.kt` over the repo (excluding `.archive/` and `build/`) returns **zero** non-comment hits; the full `./gradlew test` (all modules) compiles and is GREEN; no `@Deprecated` shim for `navigate(String)` remains.

3. **`start` accepts `SceneRef`, string form removed (Req #13b)**: `start` is assigned a `SceneRef` directly — no `.id`, no string.
   - Current: `var start: String? = null` requires `start = titleScene.id` (or raw `start = "title"`).
   - Target: `start` accepts a `SceneRef` (`start = titleScene`); the String-typed assignment path is removed so `start = "title"` and `start = titleScene.id`-as-the-only-option no longer apply. All examples set `start = <sceneRef>`. Build-time validation (start-not-null, start-references-a-registered-scene) is preserved through the `SceneRef` path.
   - Acceptance: every active example sets `start = <sceneRef>` (no `.id` accessor, no string literal); `grep -rn 'start = "' --include=*.kt` (excl. archive/build) returns zero non-comment hits; the start-scene validation error still fires for an unset/unknown start in a JVM test.

4. **PNG-derived safe `size(...)` default (Req #14)**: Omitting `size()` no longer yields a magic 32×32; the default is derived safely.
   - Current: `ZoneBuilder` defaults to 32×32, silently overwriting smaller tile arrays; authors must write explicit `size(20, 18)`.
   - Target: when `size()` is omitted, the zone dimensions are derived from the zone's tilemap/full-image PNG tile dimensions (Path A) when one is present; when only a small repeating `tileset(...)` exists with no derivable map PNG, the default falls back to the Game Boy screen size **20×18**; explicit `size(w, h)` always overrides; the literal **32×32** default is eliminated. `banks` drops its explicit `size(20, 18)` (now derived/defaulted) without changing the emitted tilemap.
   - Acceptance: a JVM test asserts (a) a zone with a derivable PNG yields that PNG's tile dimensions, (b) a zone with only a repeating tileset and no explicit size yields 20×18, (c) explicit `size()` still wins; `banks` builds GREEN with byte-identical-or-smaller generated zone tilemap after removing its explicit `size(20, 18)`.

5. **Call-site migration + docs (Req #10/#13/#14 cross-cut)**: Every active caller is migrated and the new primitives are documented.
   - Current: `banks` and `platformer-template` use string-form zone/navigate/start; 16 test files use `navigate("...")`; DSL_REFERENCE.md documents only the string/`.id` forms.
   - Target: all active examples and all test fixtures use the new primitives; DSL_REFERENCE.md gains worked examples for `by zone { }`, `navigate(sceneRef)` / `start = sceneRef`, and the smart `size` default. The 7-target regression sweep (pong, breakout, simple-physics, metasprites, metasprites-stress, banks, racer) plus `platformer-template` build GREEN.
   - Acceptance: clean `:buildRom` for `banks` and `platformer-template` EXIT 0; 7-target regression sweep all EXIT 0 (pong may PASS\* per known toolchain non-determinism); full `./gradlew test` GREEN; DSL_REFERENCE.md contains the three worked examples.

## Boundaries

**In scope:**
- `ZoneDelegate` + `by zone { }` factory in `gbkt-lang` (mirrors `MetaspriteDelegate`).
- Hard removal of `navigate(String)` from `ScriptBuilder`; `navigate(SceneRef)`-only.
- `GameBuilder.start` accepts `SceneRef` (string path removed); validation preserved.
- PNG-derived → 20×18-fallback zone `size` default; explicit `size()` override retained.
- Migration of all **active** examples: `banks`, `platformer-template` (incl. its `titleZone` & `nextLevelZone` — migrated to `by zone` now).
- Migration of all **16 test files** that use `navigate("...")` and any `start = "..."` test fixtures so the suite compiles.
- KDoc comment examples in builder/genre files updated to ref form.
- DSL_REFERENCE.md worked examples for the three primitives.
- Regression sweep across the 7 named targets + `platformer-template`.

**Out of scope:**
- Req #15 (auto-emit `*_exit` BANKED), Req #17 (typed `bindCurrentLevel()`/`loadLevel()`), Req #18 (`screen()`/`image()` primitive) — owned by Phase 13.5; the `titleZone`/`nextLevelZone` migrated to `by zone` here will be **re-migrated to `screen()` in 13.5** (intentional, documented hand-off).
- Req #11 (auto-sized `romBanks`/`ramBanks`), Req #12 (`@Suppress("UNUSED_VARIABLE")` fix), Req #16 (typed `triggerSystem(ref)`) — not in this sub-phase's owned set.
- Archive examples (`gbkt-examples/.archive/dungeon`, `.archive/explorer`) — inactive, not built, not migrated.
- Any DSL change not surfaced by Req #10/#13/#14 — no speculative polish (Phase 13 umbrella out-of-scope rule).
- Changing the runtime *meaning* of navigation or zone tilemaps — this is an API-shape + safe-default change, not a behavior change; generated C shape must not change except where a smaller/derived size legitimately shrinks it.

## Constraints

- **Generated C unchanged in shape or smaller.** No codegen regressions; the byte-identity baselines for the regression-sweep targets must hold (or shrink only where the derived `size` legitimately reduces tilemap bytes — e.g. banks 20×18 vs 32×32).
- **All ROMs build GREEN** with same-or-smaller byte sizes; `:buildRom` smoke for `banks` + `platformer-template` is mandatory (per `feedback_rom_build_smoke_test_for_codegen_phases` — JVM tests cannot see staleness in `build/gbkt/generated/`).
- **Full test suite must compile and pass.** Hard-removing `navigate(String)` breaks 16 test files at compile time; migrating them is a gating part of this phase, not optional cleanup. (Known pre-existing IntegrationTest baseline reds inherited from 11.1-04 are tracked separately and are not introduced by this phase.)
- **`size` fallback chain is deterministic:** PNG-derived → else 20×18 → never 32×32; explicit `size()` always wins. (Inferred decision — flagged below; planner may revisit in discuss-phase.)
- **No magic strings** (Project Rule #1): zone/scene IDs flow from property delegates and typed refs, never duplicated as String literals.
