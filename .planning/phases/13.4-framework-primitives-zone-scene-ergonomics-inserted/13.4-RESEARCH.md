## Summary

Phase 13.4 is a pure API-shape + safe-default change across three primitives in `gbkt-lang`. The implementation is principally a Kotlin DSL refactor with no new runtime semantics: `ZoneDelegate` is a clone of the well-proven `MetaspriteDelegate`; `navigate`/`start` string forms are hard-removed after an incremental migrate-then-delete sweep; the zone size default is replaced with a deterministic fallback chain whose "auto" sentinel is carried through the existing `ZoneIR → game_metadata.json → ConvertZoneTilesetsTask` pipeline.

The largest planning risk is the **Req #13b blast radius**: changing `GameBuilder.start` from `String?` to `SceneRef?` breaks **69 files** (real code), not just the 2 example mains mentioned in the SPEC overview. This is separate from the 16 navigate-test files. The planner must batch the `start` migration carefully, likely using a temporary internal-overload bridge to keep the suite GREEN at each commit during the wave.

The **Req #10 zone-declaration-form blast radius** is 37 real call sites across 8 test files + 2 example files (post-unwire). The D-12 `ZonePlatformerPhysicsTest` restructuring is a known complication: its 4 `gb.zone("z"){}` calls use an explicit receiver outside any `game{}` block and must be restructured into `game { val z by zone {} }` DSL blocks.

**Primary recommendation:** Implement Wave 0 new-primitive additions (ZoneDelegate, SceneRef start, resolveZoneSize) in gbkt-lang/gbkt-ir with full JVM tests GREEN; then execute the migrate-then-delete sweep in module-batched plans (each plan migrates one module cluster and stays GREEN); close with a clean `:buildRom` smoke + byte-identity sweep.

### Pattern 1: ZoneDelegate — mirror of MetaspriteDelegate

**What:** Property delegate that captures `property.name` at `by`-binding time, registers a `ZoneIR` with the active `GameBuilder`, returns a `ZoneRef`.
**When to use:** All zone declarations in `game { }` blocks.

```kotlin
// Source: gbkt-lang/MetaspriteBuilder.kt:461-503 (verbatim blueprint)
class ZoneDelegate(private val block: ZoneBuilder.() -> Unit) :
    ReadOnlyProperty<Any?, ZoneRef> {
    private var ref: ZoneRef? = null
    private var delegateUsed: Boolean = false

    operator fun provideDelegate(
        thisRef: Any?,
        property: KProperty<*>,
    ): ReadOnlyProperty<Any?, ZoneRef> {
        check(!delegateUsed) {
            "ZoneDelegate instance reused: was already bound to '${ref?.id ?: "<unknown>"}'. " +
                "Each 'val x by zone { }' must use its own delegate instance."
        }
        delegateUsed = true
        val name = property.name
        val gameBuilder =
            GameBuilderContext.current
                ?: error("zone {} must be called inside a game {} block")
        val builder = ZoneBuilder(name)
        builder.block()
        val ir = builder.build()
        gameBuilder.registerZone(ir)  // mirrors registerMetasprite() at line 496
        ref = ZoneRef(name)
        return this
    }

    override fun getValue(thisRef: Any?, property: KProperty<*>): ZoneRef =
        ref ?: error("ZoneDelegate not initialized — was provideDelegate called?")
}

// Factory function — mirrors metasprite() at MetaspriteBuilder.kt:524
fun zone(block: ZoneBuilder.() -> Unit): ZoneDelegate = ZoneDelegate(block)

// Usage (target DSL shape):
val playZone by zone {
    tileset(asset("tiles/checker.png"))
    // size(20, 18) omitted → 20×18 fallback (tileset-only zone)
}
```

**Note:** `GameBuilder.registerZone(ir: ZoneIR)` is the internal method to expose (mirrors `registerMetasprite`). Check `GameBuilder` for the `_zones += zone` pattern at line :486 — expose as `internal fun registerZone(ir: ZoneIR) { _zones += ir }`.

### Pattern 2: `resolveZoneSize` — pure deterministic fallback chain

**What:** Pure function (no file I/O) encoding the D-03 fallback chain.
**When to use:** Called by `ConvertZoneTilesetsTask` after reading the PNG; also directly unit-tested.

```kotlin
// Source: D-02 decision (CONTEXT.md) — to be authored in Wave 0
// Recommended location: companion object in WorldBuilders.kt or a top-level fun in gbkt-lang
// (NOT in gbkt-gradle-plugin — pure fn goes in DSL module for JVM testability)

/**
 * Resolves the final zone tile dimensions from the D-03 fallback chain.
 *
 * Priority:
 * 1. explicit – author called size(w, h) → return explicit pair.
 * 2. derivedPngTileDims – tilemap PNG present → return PNG-derived dims.
 * 3. default → return (20, 18) — Game Boy safe full-screen size.
 *
 * Never returns (32, 32). That default is eliminated.
 */
fun resolveZoneSize(
    explicit: Pair<Int, Int>?,
    derivedPngTileDims: Pair<Int, Int>?,
): Pair<Int, Int> = when {
    explicit != null -> explicit
    derivedPngTileDims != null -> derivedPngTileDims
    else -> 20 to 18
}
```

### Pattern 3: ZoneIR "auto" sentinel encoding — recommended: `Int? = null`

**What:** Change `ZoneIR.mapWidth: Int = 32` to `ZoneIR.mapWidth: Int? = null` (sentinel = null).
**Why null over -1 or marker type:** `ZoneIR.bankOverride` already uses `Int? = null` as sentinel (WorldIR.kt:60); consistent precedent. `GameIRSerializer` already uses `JSONObject.NULL` / `optInt` pattern for nullable Int on `SceneIR.mapWidth` (GameIRSerializer.kt:207,233) — same pattern reusable.

**Metadata JSON flow:**
- `GBDKPipelineV2.buildMetadataFile()` at :335: emit `null` → `JSONObject.NULL` when mapWidth is null.
- `ConvertZoneTilesetsTask` at :150-153: currently `require(entry.has("mapWidth")...)`. Update to: if null sentinel, derive from PNG; if explicit, use value. The `@Suppress("UNUSED_PARAMETER")` at :237 already confirms mapWidth/mapHeight passed to `convertOneTileset` are unused (since Phase 12.2, `synthesizeZoneTilesetHeader` derives dims from PNG IHDR directly). So the flow is clean: null sentinel → derive in `ConvertZoneTilesetsTask`; explicit value → pass through (but still derived from PNG for the header — the explicit value is only used by `resolveZoneSize` for tilemap-count validation).

**Key clarification on tile-count computation:** `synthesizeZoneTilesetHeader` ALREADY derives `tilemapW/H` from the PNG IHDR at lines :627-638 — it does NOT use the passed `screenMapWidth`/`screenMapHeight` parameters (hence `@Suppress("UNUSED_PARAMETER")`). The sentinel only needs to flow correctly for the `require()` check at :150-153; after that, the actual dimensions come from PNG always.

**Recommended sentinel update in ConvertZoneTilesetsTask:** Replace the `require(entry.has("mapWidth")...)` hard failure with: read value, if null/missing then proceed (dimensions will be PNG-derived); if explicit, store for `resolveZoneSize`. This decouples the sentinel check from the PNG-read path.

### Pattern 4: `start = SceneRef` migration — incremental via temporary internal bridge

**What:** D-08 changes `var start: String? = null` to `var start: SceneRef? = null`. To satisfy D-07 (both forms compile during migration), add a temporary **unlisted** property overload bridge:

```kotlin
// Temporary bridge (NOT @Deprecated — internal scaffolding only; removed in final plan)

// This is NOT the same as a @Deprecated shim (D-09) — it's a migration scaffold.
@Suppress("UNUSED")

}
```

Or more practically: add a String-accepting overloaded setter via a companion extension temporarily. The exact mechanism is Claude's discretion (D-07). **Critical insight:** the planner must account for the **69-file blast radius** for `start = "..."` vs the 16-file blast radius for `navigate("...")`. These are independent migration sweeps.

### Anti-Patterns to Avoid

- **Starting with the hard-remove before all callers are migrated.** D-07 mandates migrate-then-delete. If `navigate(String)` is removed before the 16 test files are updated, the test suite fails to compile — not just fails, but won't compile. This would require a revert.
- **Using `start = sceneRef.id` as the migration target.** The acceptance criterion says `no .id accessor` on start (for active examples). The migration target is `start = sceneRef` directly. This means the type change from `String?` to `SceneRef?` must happen BEFORE migrating callers that use `.id`.
- **Changing `zone(ref: ZoneRef)` load overload.** D-11 explicitly preserves it. Only the `zone(id: String, block)` DECLARATION form is removed. Confusing these will break scene-enter zone loading.
- **Introducing ImageIO into `gbkt-lang`.** D-01 forbids it. The sentinel must be a pure data value; the PNG read stays in the gradle task.
- **Deriving zone size from a tileset-only PNG.** D-03 explicitly forbids this — banks' checker PNG is ~2×2 tiles; deriving dims from it would emit a broken tilemap. Only `tilemap()` presence drives PNG derivation.

## D-05 Bank Overflow Verification: platformer-template 60×32 Tilemaps

**Question:** Does the grown 60×32 tilemap for 3 world zones risk bank overflow in `platformer-template`?

**Analysis (verified via source code):**

`BankingAnalysisPass.checkTilemapBankOverflow()` (BankingAnalysisPass.kt:295-325) computes a **cumulative** sum of all zone tilemap byte counts against `TILEMAP_BANK_THRESHOLD = 14_336` bytes. The check reads the tilemap PNG IHDR directly via ImageIO and computes `(width/8) * (height/8)`.

**Byte accounting for platformer-template post-D-05:**

| Zone | PNG path | Dimensions | Tile dims | Byte count |
|------|----------|-----------|-----------|------------|
| world1Area1Zone | `graphics/world1-area1.png` | 480×256px | 60×32 | 1,920 bytes |
| world1Area2Zone | `graphics/world1-area2.png` | 480×256px | 60×32 | 1,920 bytes |
| world2Area1Zone | `graphics/world2-area1.png` | 480×256px | 60×32 | 1,920 bytes |
| titleZone | `graphics/title-screen.png` | 160×72px | 20×9 | 180 bytes |
| nextLevelZone | `graphics/next-level.png` | 160×72px | 20×9 | 180 bytes |
| **Total** | | | | **6,120 bytes** |

**Threshold check:** 6,120 bytes << 14,336 bytes threshold. **No bank overflow risk.** [VERIFIED: source code analysis]

**Per-bank check:** `allocateZoneBanks()` uses first-fit bin-packing with 16,384 bytes per bank. Each individual zone tilemap is at most 1,920 bytes — well under 16,384. Multiple zones will fit in bank 2 with headroom.

**Concrete verification mechanism for the planner:**
1. After `./gradlew :gbkt-examples:platformer-template:generateC` completes, check `BankingAnalysisPass` output — no `ANLZ-12` error means cumulative check passed.
2. After `./gradlew :gbkt-examples:platformer-template:buildRom` completes, check the `.noi` file at `build/gbkt/output/platformer-template.noi`: look for `DEF l__CODE_2` through `DEF l__CODE_N` hex sizes; none should exceed `0x4000` (16384 = 16KB).
3. The build EXIT 0 is the primary gate (per D-16). The `.noi` check is a secondary audit.

**Note on old 32×32 vs new 60×32:** The old world zones used the magic 32×32 default (1024 bytes each), actively truncating the 60-tile-wide level maps. The new 60×32 (1920 bytes each) is a **correctness fix** — platformer-template is explicitly excluded from the byte-identity regression sweep.

## Common Pitfalls

### Pitfall 1: Removing `zone(ref: ZoneRef)` load overload by mistake

**What goes wrong:** There are TWO `zone(...)` signatures: `zone(id: String, block)` in `GameBuilder` (REMOVE) and `zone(zoneRef: ZoneRef)` in `SceneBuilder` (KEEP). Removing both would break scene-enter zone loading.
**Why it happens:** grep hits on `zone(` match both; a global find-and-remove would catch both.
**How to avoid:** Only remove `fun zone(id: String, block: ZoneBuilder.() -> Unit)` at `GameBuilder.kt:482`. The `fun zone(zoneRef: ZoneRef)` at `SceneBuilder.kt:151` stays untouched.
**Warning signs:** Tests that test `scene { zone(playZone) }` (load call) fail to compile after migration.

### Pitfall 2: `ZonePlatformerPhysicsTest` D-12 restructuring complexity

**What goes wrong:** The 4 `gb.zone("z1") {}` calls use `val gb = GameBuilder("test")` as an explicit receiver WITHOUT a `game {}` context. `ZoneDelegate.provideDelegate` requires `GameBuilderContext.current` to be set. Calling `val z1 by zone {}` on a bare `GameBuilder` instance (not via `game {}`) will throw "zone {} must be called inside a game {} block."
**How to avoid:** Restructure the tests to use `game("test") { val z1 by zone {} }`; read back zones via `ir.zones` after `.build()` instead of `gb.currentZones()`. The `.currentZones()` accessor may still work mid-`game {}` if called via a closure, but post-`build()` via `ir.zones` is cleaner.
**Warning signs:** `ZonePlatformerPhysicsTest` throws `IllegalStateException` at test runtime (not compile time).

### Pitfall 3: `start` blast radius larger than `navigate` blast radius

**What goes wrong:** Planning waves that batch `navigate` migration (16 test files) and assume the `start` migration is similarly scoped (it's not). The `start` blast radius is ~69 files.
**Why it happens:** The SPEC overview mentions "2 example mains + 16 test files" for navigate; the start = "..." footprint is scattered across many more test files that use it as boilerplate DSL setup.
**How to avoid:** Batch `start` migration separately from `navigate` migration, with dedicated plans per module cluster. Use the full file list in section 3 above.
**Warning signs:** After changing `var start: String?` to `var start: SceneRef?`, the compile fails in unexpected modules like `gbkt-genre-sport` tests, `gbkt-lang` metasprite tests, etc.

### Pitfall 4: Changing `mapWidth/mapHeight` default at wrong layer

**What goes wrong:** Changing the default value in `ZoneIR` to `null` without updating `ConvertZoneTilesetsTask`'s `require(entry.has("mapWidth"))` check at :150-153. This causes a hard failure during `:buildRom` for all zones.
**How to avoid:** Update `ConvertZoneTilesetsTask` in the SAME plan as the `ZoneIR` sentinel change. The `require()` check must become: handle null/missing as "auto-derive from PNG" rather than fatal error.
**Warning signs:** `ConvertZoneTilesetsTask` throws "re-run :generateC to refresh metadata" during buildRom after the ZoneIR change.

### Pitfall 5: `BanksEmissionTest` assertion drift after banks drops `size(20, 18)`

**What goes wrong:** `BanksEmissionTest.kt` may have assertions tied to the exact zone metadata (mapWidth=20, mapHeight=18). After D-06 changes banks to use the auto-derived 20×18 (same final value), these assertions should pass. But if the test asserts on the sentinel value in metadata JSON rather than the final output, it could fail.
**How to avoid:** Check `BanksEmissionTest` for any JSON-level mapWidth assertions. The byte-identity sweep is the canonical gate, not metadata JSON assertions.

### ZoneDelegate complete implementation

```kotlin
// Source: Clone of MetaspriteBuilder.kt:461-503 with type substitutions
// Location: gbkt-lang/src/main/kotlin/io/github/gbkt/core/dsl/WorldBuilders.kt (append after ZoneRef)

class ZoneDelegate(private val block: ZoneBuilder.() -> Unit) :
    ReadOnlyProperty<Any?, ZoneRef> {
    private var ref: ZoneRef? = null
    private var delegateUsed: Boolean = false

    operator fun provideDelegate(
        thisRef: Any?,
        property: KProperty<*>,
    ): ReadOnlyProperty<Any?, ZoneRef> {
        check(!delegateUsed) {
            "ZoneDelegate instance reused: was already bound to '${ref?.id ?: "<unknown>"}'. " +
                "Each 'val x by zone { }' must use its own delegate instance."
        }
        delegateUsed = true
        val name = property.name
        val gameBuilder =
            GameBuilderContext.current
                ?: error("zone {} must be called inside a game {} block")
        val builder = ZoneBuilder(name)
        builder.block()
        val ir = builder.build()
        gameBuilder.registerZone(ir)
        ref = ZoneRef(name)
        return this
    }

    override fun getValue(thisRef: Any?, property: KProperty<*>): ZoneRef =
        ref ?: error("ZoneDelegate not initialized — was provideDelegate called?")
}

fun zone(block: ZoneBuilder.() -> Unit): ZoneDelegate = ZoneDelegate(block)
```
