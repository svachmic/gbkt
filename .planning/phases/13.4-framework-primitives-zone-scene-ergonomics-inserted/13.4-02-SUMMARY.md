# Phase 13.4 Plan 02: resolveZoneSize + null sentinel + PNG back-fill Summary

**One-liner:** Pure `resolveZoneSize` fn + `ZoneIR` null sentinel replace dangerous `Int=32` default; `ConvertZoneTilesetsTask` derives dims from tilemap PNG and calls `resolveZoneSize`.

## What Was Built

Replaced the dangerous magic `size(32, 32)` zone default (which caused silent level truncation) with a deterministic PNG-derived→20×18-fallback chain. `ZoneIR.mapWidth`/`mapHeight` are now `Int?=null` (auto sentinels). A pure `resolveZoneSize(explicit?, derivedPngTileDims?)` function holds the fallback policy (D-03: explicit wins, else PNG-derived, else 20×18; never returns 32×32). `ConvertZoneTilesetsTask` reads the sentinel-aware metadata and back-fills dims from the tilemap PNG. DSL (gbkt-lang) stays filesystem-free — no ImageIO/File added.

## Key Design Decisions

- `ZoneIR.mapWidth`/`mapHeight` changed from `Int = 32` to `Int? = null` — mirrors `bankOverride: Int? = null` sentinel pattern already in the data class.
- `resolveZoneSize` is a top-level Kotlin function in `WorldBuilders.kt` (package `io.github.gbkt.core.dsl`). Zero imports from `javax.imageio` or `java.io.File` — gbkt-lang stays filesystem-free per D-01.
- `ZoneBuilder.build()` passes `if (explicitSizeSet) mapWidth else null` — the `explicitSizeSet` boolean flag is set only when `size(w, h)` is called explicitly.
- `GBDKPipelineV2` uses `zone.mapWidth ?: org.json.JSONObject.NULL` for both mapWidth and mapHeight — mirrors the tilemapPath JSONObject.NULL idiom at line 333, ensuring keys are present in JSON even when null.
- `ConvertZoneTilesetsTask` derives dims from the **tilemap PNG only** — `tilemapPngFile` (never the tileset PNG). For tileset-only zones (no tilemap PNG), `derivedDims` is null and `resolveZoneSize` returns the 20×18 fallback.
- Legacy-path visitors (`SceneVisitor` legacy branch, `GBDKSystemVisitor`) use `?: 20` / `?: 18` fallback — consistent with D-03.
