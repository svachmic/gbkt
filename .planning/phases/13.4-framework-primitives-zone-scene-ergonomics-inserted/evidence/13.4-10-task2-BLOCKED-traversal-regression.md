## Diagnosis (orchestrator, evidence-based)
- **13.4 did NOT modify platformer collision/physics codegen.** Across all 13.4 commits,
  the only `gbkt-genre-platformer/src/main/**` change is KDoc cleanup in 13.4-09
  (`PlatformerExtensions.kt`); no change to `PlatformerVisitor` / horizontal probe / collision.
- **The behavioral change is the world-zone dimension: 32×32 → 60×32.** Pre-13.4 the world
  zones used the magic `size(32, 32)` default (truncated). 13.4-02 (`resolveZoneSize` +
  null-sentinel, magic-32 removal) + 13.4-08 (`by zone` migration dropping the implicit
  default) cause the world zones to derive **60×32** from the tilemap PNG.
  - Current generated constants: `_zone_world1Area1Zone_tilemap_WIDTH = 60`, `_HEIGHT = 32`;
    tilemap array `[1920]` = 60×32 (matches the GBDK reference oracle `World1Area1_map[1920]`).
  - `_current_level_width_in_tiles` is now 60 (was 32); collision indexes the tilemap with
    `WIDTH` as row-stride, so the dimension change altered the data/extent the unchanged
    collision logic runs against.
- **Hypothesis to confirm in diagnose phase:** the player hard-stops at a single obstacle
  early in the now-60-wide real level. Candidates: (a) tilemap-stride / row-major layout
  mismatch between the 60-wide submap load and the collision index; (b) the real PNG layout
  content at that column is genuinely impassable vs the GBDK reference (possible residue of
  the Phase-12 Defect-7 synthetic-tilemap class — confirm whether `world1Area1Zone_tilemap`
  is the real PNG layout or a synthesized ramp extended to 60×32); (c) metasprite-frame /
  hitbox change interacting with the horizontal probe half-width (12.9 `HALF_WIDTH=5`).
