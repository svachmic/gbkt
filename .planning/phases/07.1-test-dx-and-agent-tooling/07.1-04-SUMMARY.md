# Phase 07.1 Plan 04: MCP Server Tool Expansion Summary

Expanded the gbkt MCP server from 11 to 16 tools, adding save/load state, batch assertions, playbook access, game discovery, and convention-based game-name start.

## What Was Built

### McpEmulatorSession — 6 new methods

| Method | Description |
|--------|-------------|
| `startByName(gameName, gbcMode)` | Convention-based start via `GameDiscovery.configForGame()` |
| `saveState(label)` | Saves WRAM+OAM+HRAM to `build/gbkt/savestates/<label>.gbst` |
| `loadState(label)` | Restores savestate, steps one frame to refresh observation |
| `batchAssert(checks)` | Validates 6 assertion types against current observation |
| `getPlaybook()` | Reads PLAYBOOK.md relative to ROM file's project directory |
| `listGames()` | Scans project for built ROMs via `GameDiscovery.scanForBuiltRoms()` |

### ToolHandlers.kt — 5 new handlers + enhanced emulator_start

| Handler | Tool |
|---------|------|
| `handleSaveState` | `emulator_save_state` |
| `handleLoadState` | `emulator_load_state` |
| `handleAssert` | `emulator_assert` |
| `handleGetPlaybook` | `emulator_get_playbook` |
| `handleListGames` | `emulator_list_games` |

`handleStart` enhanced: accepts `game` string parameter for convention-based discovery when `romFile` is absent.

### batchAssert Check Types

| Type | Args | Description |
|------|------|-------------|
| `variable_equals` | `name`, `expected` | Exact variable match |
| `variable_in_range` | `name`, `min`, `max` | Inclusive range check |
| `scene_is` | `scene` | Current scene name |
| `text_on_screen` | `text` | Substring on either tilemap layer |
| `actor_visible` | `name` | Actor in observation actors list |
| `sprite_count` | `expected` | Total visible OAM sprite count |

### StepAgent — 2 new methods

Added `saveState(file)` and `loadState(file)` delegating to `AgentDebugSession` to expose savestate capability without leaking the private session field.

### Build Changes

Added `implementation(project(":gbkt-test"))` to `gbkt-mcp-server/build.gradle.kts` for `GameDiscovery` access.

## Decisions Made

1. **StepAgent saveState delegation**: The plan referenced `agent.emulator` (private), so saveState/loadState were added to StepAgent delegating to the existing `AgentDebugSession.saveState(file)` / `loadState(file)` methods. This is cleaner than exposing the internal emulator.

2. **emulator_start required fields**: Changed `required = listOf("romFile")` to `required = emptyList()` to allow game-name-only invocation. Validation moved into the handler logic — returns error if neither `game` nor `romFile` is provided.

3. **batchAssert uses cached observation**: To avoid unintended frame advancement during assertion, `batchAssert` uses `lastObservation` (or steps one frame only if none cached). This keeps assertions non-destructive.

4. **getPlaybook path resolution**: ROM is at `<project>/build/gbkt/output/<name>.gb` — walk 4 levels up (output → gbkt → build → project) to find the project directory. Also checks working directory root as fallback.
