## Decisions Made

- **JUnit5 as compileOnly:** Consumers (game test modules) bring their own JUnit5 version via their own `testImplementation` block. This avoids version conflicts.
- **Assertion functions top-level + extension:** Plan specified extension functions on `GbktTestExtension`, but the test cases call `assertScene(obs, "title")` directly (no receiver). Both APIs provided — top-level for direct use, extension functions for receiver-context usage.
- **No org.json dependency:** The `org.json` library is an `implementation` detail of `gbkt-emulator` (not exposed as `api`), so it is not on gbkt-test's compile classpath. Failure JSON is built manually with `StringBuilder` to avoid adding a transitive dependency.
- **AssertionError not kotlin.test:** `kotlin.test` assertions (`assertEquals`, `assertTrue`) are only available in test source sets. Main source uses `throw AssertionError(...)` directly.

**2. [Rule 1 - Bug] Glob patterns in KDoc/comments trigger Kotlin lexer comment parsing**
- **Found during:** Task 2 (compileKotlin main source)
- **Issue:** `output/*.gb` in KDoc is parsed as `/*` (block comment open) followed by `.gb`, causing "Missing `}`" and "Unclosed comment" compiler errors. This is a Kotlin K2 compiler sensitivity to `/*` sequences in comments.
- **Fix:** Replaced glob patterns in all KDoc and inline comments with descriptive text (e.g., `NAME.gb` instead of `*.gb`)
- **Files modified:** `GameDiscovery.kt`
- **Verification:** `compileKotlin` succeeds
- **Committed in:** `09b860e`
