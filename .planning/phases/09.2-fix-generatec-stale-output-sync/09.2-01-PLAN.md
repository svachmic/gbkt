| test process → @TempDir | `@TempDir`-isolated; no cross-test contamination |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09.2-01 | Tampering | syncOutputDir helper deletes the wrong file → silent data loss | mitigate | D-S-02 whitelist (3 explicit sidecar names) + dotfile exemption (`.gitkeep`, `.DS_Store`, IDE markers survive) + `.gbkt.map`-suffix pattern exemption; idempotency test (R-04 case 4) ensures repeated invocation is safe; locked-file test (case 5) ensures permission failures fall back to WARNING-and-skip (NOT silent delete-failure-with-empty-stdout) |
| T-09.2-01a | Tampering | syncOutputDir recurses into subdirectories → deletes processed-assets tree | mitigate | Helper uses `outputDir.listFiles()` (top-level only), explicitly filters `it.isFile`; per RESEARCH §Don't Hand-Roll, `walk().toList()` is rejected because it recurses |
| T-09.2-02 | DoS | Tmpdir leak across tests if @TempDir cleanup fails on setWritable(false) | mitigate | Test 5 uses `try { ... } finally { outputDir.setWritable(true) }` to guarantee restore before JUnit @TempDir cleanup |
| T-09.2-SC | Tampering | npm/pip/cargo installs | accept | RESEARCH §Package Legitimacy Audit confirms ZERO new external packages; only JDK `java.io.File`, existing `org.junit.jupiter.api`. No slopcheck applies. |
