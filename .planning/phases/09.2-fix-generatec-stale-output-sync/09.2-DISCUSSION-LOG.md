## Sync mechanism

### Mechanism (S-01)

| Option | Description | Selected |
|--------|-------------|----------|
| Diff-and-delete | Enumerate outputDir, compute emittedSet, delete the difference. Doesn't fight Gradle's @OutputDirectory tracking. | ✓ |
| Wipe-then-write | Delete outputDir at task start, write everything fresh. Simplest but worse incrementality. | |
| Per-file @OutputFile | Statically declare every possible bank file. Pure declarative but file set is dynamic. | |

**User's choice:** Diff-and-delete (recommended).

### Protected set (S-02)

| Option | Description | Selected |
|--------|-------------|----------|
| Whitelist only | Pipeline files + known sidecars (*.gbkt.map, gbkt-build.properties, game_metadata.json). | |
| Whitelist + dotfile exemption | Same as above plus skip anything starting with `.` (defensive against .gitkeep, IDE markers). | ✓ |
| Only delete *.c and *.h | Narrow sweep to the actual link-error vector. Doesn't fix general staleness. | |

**User's choice:** Whitelist + dotfile exemption.

### Sync site (S-03)

| Option | Description | Selected |
|--------|-------------|----------|
| Shared helper, end-of-task in both paths | Extract syncOutputDir() once, invoke at end of executeV2Path() AND v1 path. | ✓ |
| Beginning-of-task wipe + write | Sync BEFORE writing. Equivalent end-state, reversed order. | |
| v2 path only, defer v1 fix | Apply sync only to v2 path. Smaller blast radius; creates contract drift. | |

**User's choice:** Shared helper, end-of-task in both paths.

### Logging (S-04)

| Option | Description | Selected |
|--------|-------------|----------|
| Log per deletion at lifecycle | `println("Removed stale: $name")` matching existing `Generated:` format. | ✓ |
| Log summary line only | One line: `Removed N stale files` (when N > 0). | |
| Silent | No log. Fix is invisible. Increases regression-masking risk. | |

**User's choice:** Log per deletion at lifecycle.
