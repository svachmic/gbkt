## Decisions Made

- **D-S-03 (sync call sites at end of both paths):** Both call sites placed AFTER all file writes complete and AFTER metadata writing (v1 also after asset optimization). This ensures `files.keys` reflects the complete emission set before reconciliation.
- **D-S-04 (lifecycle log):** Helper's existing `println("Removed stale: <name>")` (Plan 1) is the structural signal; verified live by operator probe — `Removed stale: bank1.c` observed during `--rerun-tasks` on the real `:simple-physics` example.
- **D-R-01 / D-R-02 (integration test design — diverged from plan):** The original test design pre-staged a stale `bank1.c` before `generateC`. This DOES NOT work because Gradle's `@CacheableTask` stale-output cleanup deletes files in `@OutputDirectory` that were NOT in the previous run's snapshot BEFORE the task action runs. Replaced with a two-step probe: Step 1 establishes `bank1.c` as a legitimate output (two-scene game routes through bank 1); Step 2 switches to a single-scene game that triggers BankingAnalysisPass HOME fast-path, dropping `bank1.c` from the emission set, so `syncOutputDir` (and only `syncOutputDir`) deletes it.
- **W2 Option A (split manual smoke into checkpoint task):** Honors CLAUDE.md `rom_build_smoke_test_for_codegen_phases` memory rule — conscious operator sign-off rather than fold-into-autonomous `<verify>`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test design was structurally unable to reach syncOutputDir under Gradle `@CacheableTask` stale-output cleanup**
- **Found during:** Task 2 (GREEN gate iteration) — wired helper, but test still FAILED because `bank1.c` was deleted by Gradle's own pre-task cleanup, not by `syncOutputDir` (no `Removed stale:` log line emitted).
- **Issue:** Original PLAN's test pre-staged `bank1.c` before the FIRST `generateC` run. Gradle's `@CacheableTask` machinery treats files in `@OutputDirectory` that were NOT in the previous run's snapshot as "stale outputs from a removed task" and deletes them BEFORE the task action executes. The pre-staged file was therefore destroyed before `syncOutputDir` had a chance to act on it.
- **Fix:** Redesigned the test as a TWO-STEP probe — Step 1 uses `createTwoSceneGameFixture()` (two scenes bypass the BankingAnalysisPass single-scene HOME fast-path, so `bank1.c` IS emitted and Gradle snapshots it as a legitimate output); Step 2 switches to `createMinimalGameFixture()` (single scene fits HOME, `bank1.c` no longer in emission set), and only `syncOutputDir` can delete the now-stale `bank1.c`. Added `createTwoSceneGameFixture()` helper to support Step 1.
- **Files modified:** `IntegrationTest.kt` (test body + new helper)
- **Verification:** Test passes GREEN. Operator's live probe on real `:simple-physics` confirms `syncOutputDir` IS firing in production (`Removed stale: bank1.c` and `Removed stale: optimization-report.json` observed during `--rerun-tasks`).
- **Committed in:** `2d50c096` (Task 2 commit)

**2. [Rule 3 - Blocking] Stale `~/.m2` `gbkt-analysis` snapshot pre-dated Phase 09.1 BankingAnalysisPass HOME fast-path fix**
- **Found during:** Task 2 (root-causing why even single-scene games still emitted `bank1.c`)
- **Issue:** Local `~/.m2` snapshot of `gbkt-analysis` was dated March 23, 2026 — BEFORE the Phase 09.1-04 `BankingAnalysisPass.kt:91` single-scene-fits-HOME fast-path landed (May 14, 2026). TestKit's Gradle workers resolved against the stale snapshot, so single-scene games still routed via bank 1 (bank1.c emitted), masking the fast-path dependency the test relied on.
- **Fix:** Ran `./gradlew publishToMavenLocal` for the full transitive chain (`:gbkt-ir`, `:gbkt-lang`, `:gbkt-engine`, `:gbkt-world`, `:gbkt-core`, `:gbkt-backend-api`, `:gbkt-analysis`, `:gbkt-backend-gbdk`) and `./gradlew --stop` to flush the Gradle daemon. After republish, single-scene games correctly route through HOME and `bank1.c` is omitted.
- **Files modified:** None (artifact-cache refresh only)
- **Verification:** Two-step staleness regression GREEN; `:simple-physics:buildRom` smoke GREEN.
- **Committed in:** N/A (no source changes; surfaced and tracked here per Rule 3 documentation requirement)
