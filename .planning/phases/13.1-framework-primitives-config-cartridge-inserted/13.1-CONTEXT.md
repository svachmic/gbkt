<domain>
## Phase Boundary

Replace string-typed and hand-computed `config { }`-block values with typed,
analysis-derived primitives. Lowest-risk slice of the 13.x family — config-block
scoped, no frame-logic or codegen-shape risk.

**Owns exactly three requirements (full citations in ROADMAP.md Phase 13 catalog):**
- **Req #1** — type-safe `Cartridge` enum replacing the `"ROM_ONLY"` / `"MBC1"` /
  `"MBC5_RAM_BATTERY"` magic strings.
- **Req #11** — auto-sized `romBanks` from `BankingAnalysisPass` + `ramBanks`
  propagation to `gbkt-build.properties` (eliminate the duplicate `ramBanks`
  between DSL and `build.gradle.kts`).
- **Req #16** — typed `triggerSystem(systemRef)` + the `val saves by saveData { }`
  delegate collapse.

**Out of scope (explicit):**
- Auto-derived `saveData` slot sizing — ROADMAP marks this a Tier-3 candidate;
  `ramBanks` here is *propagation only*, not derivation.
- The delegate-unused-warning fix (Req #12) — owned by Phase 13.2. 13.1 carries a
  temporary `@Suppress("UNUSED_VARIABLE")` on the new `by saveData` delegate that
  13.2 removes globally.
- `navigate(scene)` string-vs-ref unification (Req #13) — owned by Phase 13.4.
  13.1 sets the precedent (typed-ref + hard-replace) that 13.4 should stay
  consistent with.
- Any DSL change NOT surfaced by the four reference-port audits.

</domain>

<decisions>
## Implementation Decisions

### Cartridge type (Req #1)
- **D-01:** Cartridge is a **flat enum** — `enum class Cartridge { ROM_ONLY,
  MBC1, MBC1_RAM, MBC1_RAM_BATTERY, MBC3_TIMER_BATTERY, MBC5, MBC5_RAM_BATTERY }`.
  1:1 with the current 7-entry `CARTRIDGE_MBC_MAP`. NOT a composed builder
  (`mbc5 { ram(); battery() }`) — a composed form would admit illegal combos and
  is too much surface for the lowest-risk phase.
- **D-02:** Assigned via a **method**, `cartridge(Cartridge.MBC5_RAM_BATTERY)`,
  mirroring the existing `target(GbcTarget)` setter in the same `ConfigBuilder`.
  NOT field assignment and NOT both-forms — single consistent style.
- **D-03:** **The enum owns its MBC hardware byte** (e.g.
  `MBC5_RAM_BATTERY(0x1B)`). `CARTRIDGE_MBC_MAP` in `GenerateCTask.kt` is
  **deleted**; the enum is the single source of truth and lowers directly with no
  runtime string parsing. Enum lives in `gbkt-ir` (next to `CartridgeConfig`).
- **D-04 (constraint, not a re-decision):** The gradle plugin reads the game
  config **reflectively** (`config::class.java.getMethod("getCartridge")` →
  `.toString()` → local-map lookup, `GenerateCTask.kt:507-516`). "Enum owns the
  byte" lowers cleanly by exposing a reflectively-accessible byte accessor
  (e.g. `getMbcByte()`) that the plugin calls instead of the map lookup, OR by
  resolving the byte in the IR serializer and writing it to
  `gbkt-build.properties`. The byte resolution moves to where the enum is defined
  (gbkt-ir); the plugin consumes the already-resolved value. Researcher picks the
  exact mechanism.

### Auto-sized banks (Req #11)
- **D-05:** **Omitting `romBanks` ⇒ derive** the count from `BankingAnalysisPass`.
  An explicit `romBanks = N` remains as an advanced-user **override** (PROJECT
  principle #5 "Good Defaults, Full Control"). NOT fully-automatic-no-override.
- **D-06:** When an explicit `romBanks` is set **below** the analysis-derived
  need, the build **fails with a hard compile error** (actionable message, e.g.
  "romBanks=4 too small; banking analysis needs 6"). PROJECT principle #2
  ("compile-time over runtime"). This is *stricter* than the existing cartridge
  ROM_ONLY→MBC5 auto-upgrade precedent — chosen deliberately. The override can
  therefore only raise the count (margin), never silently undersize. Validation
  happens at analysis/build time (JVM), before C generation.
- **D-07:** `ramBanks` single source of truth = **DSL `config { }`**.
  `GenerateCTask` reads `config.ramBanks` reflectively (as it already does for
  `cartridge`) and writes it to `gbkt-build.properties`; `CompileRomTask` reads
  it from there. The gradle `gbkt { ramBanks }` extension becomes redundant →
  **deprecated**. Keeps config in "write Kotlin, ship a cartridge".

### Typed triggerSystem + saveData ref (Req #16)
- **D-08:** Ship the **full `val saves by saveData { }` delegate now** — id
  inferred from the property name, fully eliminating the `"saves"` magic string
  (satisfies Req #16 + Project Rule #1). Mirrors the existing `MetaspriteDelegate`
  / `ActorDelegate` `provideDelegate` pattern. NOT the partial "return-value ref,
  delegate-in-13.2" path (that would keep the `"saves"` magic string this phase).
- **D-09:** The delegate carries a **temporary `@Suppress("UNUSED_VARIABLE")`**
  until Phase 13.2's Req #12 removes it for all delegates at once. Known,
  accepted, sequenced debt — not a regression.
- **D-10:** `saveData` returns a `SaveDataRef` that implements a **general
  `SystemRef`**; `triggerSystem(ref: SystemRef)` accepts any system kind. Keeps
  `triggerSystem` open for future system kinds without a second overload. NOT a
  save-specific-only ref.

### Migration / deprecation policy (cross-cutting)
- **D-11:** **Hard-replace, no `@Deprecated` aliases.** Delete the old forms
  (`cartridge: String`, hand-set `romBanks`, `triggerSystem(String)`,
  `saveData(String)`) outright and migrate every call site in-phase. Project is
  pre-1.0 with no external users; a clean break prevents new magic strings from
  sneaking back and keeps the "zero string-typed values" gate unambiguous (no
  deprecated-internal-use carve-outs).
- **D-12:** Migration sweep touches **all 8 examples that set config values**
  (banks, breakout, metasprites, metasprites-stress, platformer-template, pong,
  racer, simple-physics) + `banks/build.gradle.kts` (`ramBanks` removal) +
  banks' `saveData`/`triggerSystem` call sites. Regression sweep targets per
  ROADMAP: pong, breakout, simple-physics, metasprites, metasprites-stress,
  banks, racer.
- **D-13:** **Reconcile** `CompileRomTask`'s string-based ROM_ONLY→MBC5
  auto-upgrade (`CompileRomTask.kt:256-282`) with the typed enum +
  banking-derived `romBanks` path — fold into 13.1 (keep / move to analysis-time
  / remove; researcher decides, but it must not parse free cartridge strings any
  more).
- **D-14:** **`GameIRSerializer` keeps the wire string** — the cartridge enum
  serializes by `.name` to the existing `"cartridge"` JSON field
  (`GameIRSerializer.kt:558,566`). The wire string is a serialization impl
  detail, NOT a user-facing magic string, so it does not violate Rule #1. In
  scope to update the (de)serializer to map name↔enum.

### Claude's Discretion
- Exact reflective vs serializer-resolved mechanism for D-04 (lowering the MBC
  byte) — researcher/planner pick based on classpath/classloader constraints.
- Exact `CompileRomTask` auto-upgrade disposition under D-13.
- Whether `BankingAnalysisPass` exposes its derived count via a new accessor or
  an existing one for the D-05/D-06 derive+validate path.

</decisions>

## Existing Code Insights

### Reusable Assets
- **`GbcTarget` enum + `target(GbcTarget)` method** (`Types.kt`,
  `SystemBuilders.kt:560`): the exact precedent for D-01/D-02. The new `Cartridge`
  enum + `cartridge(Cartridge)` method should mirror it line-for-line.
- **`MetaspriteDelegate` / `ActorDelegate` `provideDelegate`**: precedent for the
  `by saveData { }` delegate (D-08). Name-from-property inference already exists
  in the codebase.
- **`refRegistry.register(id, RefKind.SYSTEM)`** (`GameBuilder.kt:339`): the
  registration hook the `SaveDataRef` should flow through.
- **`BankingAnalysisPass`** (`gbkt-analysis`): already computes bank needs;
  D-05/D-06 derive+validate read its output rather than recomputing.

### Established Patterns
- **Reflective config extraction in the gradle plugin** (`GenerateCTask.kt`): the
  plugin does NOT hard-link the game IR types — it invokes getters by name and
  reads `.toString()`. Any enum byte accessor added for D-04 must be reachable
  the same reflective way.
- **`gbkt-build.properties` as the DSL→build handoff**: cartridge byte, gbcMode
  already flow through it; `ramBanks` (D-07) and possibly the derived `romBanks`
  (D-05) join the same channel.

### Integration Points
- DSL (`ConfigBuilder`, `ScriptBuilder`, `GameBuilder`) → IR (`CartridgeConfig`,
  new `Cartridge` enum, `TriggerSystem`, `SystemRef`) → serializer
  (`GameIRSerializer`) → gradle plugin (`GenerateCTask` write,
  `CompileRomTask` read) → all 8 example call sites.

</code_context>

<specifics>
## Specific Ideas

- Mirror `GbcTarget`/`target()` exactly for `Cartridge`/`cartridge()` — the user
  wants stylistic consistency within `ConfigBuilder`, not a third config style.
- Hard error (not warn) on undersized `romBanks` override — the user explicitly
  chose the stricter compile-time gate over the softer auto-upgrade precedent.
- The wire format staying a string (enum `.name`) is fine — the user
  distinguishes serialization strings from user-facing magic strings.

</specifics>
