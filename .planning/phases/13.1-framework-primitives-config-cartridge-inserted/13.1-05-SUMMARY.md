### Implementation Details (from commit d642d0d7)

The `fromCartridgeConfig` method in `AnalysisConfig.kt` now reads:

```kotlin
fun fromCartridgeConfig(config: CartridgeConfig): AnalysisConfig {
    val typeMax = when (config.cartridge) {
        Cartridge.ROM_ONLY -> 2
        Cartridge.MBC1, Cartridge.MBC1_RAM,
        Cartridge.MBC1_RAM_BATTERY -> 32
        Cartridge.MBC3_TIMER_BATTERY -> 128
        Cartridge.MBC5, Cartridge.MBC5_RAM_BATTERY -> 256
    }
    val effectiveMax = minOf(typeMax, config.romBanks ?: typeMax)
    return AnalysisConfig(maxBanks = effectiveMax)
}
```

Mapping behavior verified matches plan spec:
- `ROM_ONLY` → typeMax 2
- `MBC1` family (MBC1, MBC1_RAM, MBC1_RAM_BATTERY) → typeMax 32
- `MBC3_TIMER_BATTERY` → typeMax 128
- `MBC5` family (MBC5, MBC5_RAM_BATTERY) → typeMax 256
- `romBanks == null` → effectiveMax == typeMax (no artificial cap, derive sentinel)
- `romBanks = N` → effectiveMax == minOf(typeMax, N)

The when block covers all 7 Cartridge enum entries exhaustively with no `else` branch — Pitfall 5 compile-time exhaustiveness guard is in effect.
