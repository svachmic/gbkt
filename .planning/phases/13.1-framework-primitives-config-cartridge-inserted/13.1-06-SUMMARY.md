## What Was Built

### GBDKBackend.kt — D-05 derive block

Before constructing `AnalysisConfig`, `generateV2()` now evaluates `gameIR.config.romBanks`:

- **`null` (D-05 omitted):** Runs a probe `DefaultPipeline.execute()` with `outputDirectory=null` (Pitfall 1 guard), reads `bankAssignments.values.maxOfOrNull { it.bank } ?: 0`, computes `effectiveRomBanks = maxOf(2, nextPowerOfTwo(maxBank + 1))`. The real `AnalysisConfig` and `PassContext` are constructed with the derived count.

- **explicit value (e.g. `romBanks=4`):** Used as-is. D-06 validation occurs inside `BankingAnalysisPass.bankOverflowError()` when the explicit value is too small.

The probe context uses `outputDirectory = null` so `BudgetAuditPass` does not write `optimization-report.json` during the probe run (Pitfall 1 from RESEARCH.md).

### BankingAnalysisPass.kt — D-06 diagnostic

`bankOverflowError()` was refactored to accept the `PassContext`. When bank overflow occurs AND `context.game.config.romBanks` is non-null (explicitly set by the author), the method:

1. Runs an internal probe with `typeMax` banks (unconstrained) and `outputDirectory=null`
2. Computes `derived = maxOf(2, nextPowerOfTwo(maxAssigned + 1))`
3. Returns `PassResult.Failed` with the D-06 message:
   `"romBanks=$declared too small; banking analysis needs $derived. Set romBanks >= $derived or remove romBanks to auto-derive."`

This satisfies `RomBanksValidationTest` which calls `DefaultPipeline.create().execute(ctx)` directly (bypassing GBDKBackend).

## Deviations from Plan

### 1. [Rule 1 - Architecture] D-06 message placed in BankingAnalysisPass, not GBDKBackend

**Found during:** Task 1 implementation

**Issue:** The plan acceptance criterion states `GBDKBackend.kt contains the string 'too small'`. However, `RomBanksValidationTest` runs `DefaultPipeline.create().execute(ctx)` directly without going through `GBDKBackend`. For the test to be GREEN, the D-06 message must appear in the analysis pipeline's diagnostics — not as an exception thrown by `GBDKBackend`.

**Fix:** The D-06 diagnostic is emitted from `BankingAnalysisPass.bankOverflowError()` when it detects `context.game.config.romBanks` is non-null (explicit) and caused the overflow. `GBDKBackend` does NOT throw a separate exception for the `else` branch — the analysis pass handles it.

**Impact:** The D-06 contract is correctly locked by the test. The deviation from the plan's acceptance criterion text (where the message should be in GBDKBackend) is a documentation inaccuracy in the plan — the architecture constraint (test bypasses GBDKBackend) requires the diagnostic to originate in the analysis layer.

**Files modified:** `gbkt-analysis/.../BankingAnalysisPass.kt` (bankOverflowError adds context parameter and D-06 branch)
