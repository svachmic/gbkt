In sell function: `if (_shop_<id>_sell_override[slot_idx] != 0xFF) { price = _shop_<id>_sell_override[slot_idx]; } else { price = base_price * sell_ratio / 100; }`. Add currency, remove item.

    2. **Add party management codegen** to RpgVisitor:
       - `generatePartyFunctions(system: GenericSystem): List<CFunction>`:
         - Emit `_party_active[N]` array (character IDs), `_party_active_count`
         - If reserve enabled: `_party_reserve[N]`, `_party_reserve_count`
         - Emit `add_to_party(char_id)`, `remove_from_party(char_id)`, `swap_party_member(active_idx, reserve_idx)`
         - **GAP-4 (guest party member codegen):** Emit `_party_is_guest[N]` UINT8 array (1=guest, 0=regular). Emit helper functions:
           - `is_guest(char_idx)` — returns `_party_is_guest[char_idx]`
           - `remove_guest(char_id)` — removes guest member by character ID (used as script action triggered by flag check)
           - Modify `equip_item_<slot>()` codegen to add guest lock guard: `if (is_guest(active_char_idx)) { return; }` — guests cannot change equipment
           - Modify PLAYER_TURN state in combat: skip guests (they are AI-controlled). In ENEMY_TURN phase, guest party members use monster-style AI dispatch via `update_ai_guest_<charId>()` that generates basic attack or a predefined ability list.
         - If row formation: `_party_row[N]` (0=front, 1=back), `set_row(char_idx, row)`

    3. **Add RPG save codegen** to RpgVisitor:
       - `generateRpgSaveFunctions(system: GenericSystem): List<CFunction>`:
         - Emit `save_rpg_state(slot)`: serialize character stats, inventory, party, flags to SRAM
           - **GAP-11 (save checksum):** After serializing all fields, emit `compute_save_checksum(slot)` that XOR-folds all save bytes into a UINT16 checksum and writes it to the last 2 bytes of the save slot. Formula: iterate all bytes in save slot region, XOR each byte into a running UINT16 accumulator with rotation (`checksum = (checksum << 1) ^ byte`).
         - Emit `load_rpg_state(slot)`: deserialize from SRAM
           - **GAP-11 (save checksum validation):** Before deserializing, emit `validate_save_checksum(slot)` that recomputes the checksum from save data and compares it against the stored checksum. On mismatch: set `_save_corrupt` UINT8 flag = 1 and return early without loading (prevents loading corrupted data). Emit `_save_corrupt` as a global UINT8 that the game scene can check to show a warning.
         - If auto-save: emit `auto_save_rpg()` trigger function
         - If NG+: emit `new_game_plus()` with carry-over rules
         - Extends existing SaveSystem pattern — RPG save wraps engine save with additional RPG state fields

    4. **Add ability learning codegen** to RpgVisitor:
       - `generateAbilityLearningFunctions(system: GenericSystem): List<CFunction>`:

         - Skill points: emit `_skill_points[N]` globals, `spend_skill_points(char_id, ability_id, cost)`

         - If mastery: emit `_ability_mastery[N]` counters, `gain_mastery(ability_id)` increment + evolution check

    5. **Add player flee and in-battle item use to CombatVisitor PLAYER_TURN state** (via RpgVisitor helper functions):
       - `player_flee_<id>()`: generates flee attempt logic — base flee chance (configurable, default 50%), modified by monster speed vs party speed. On success, transition to COMBAT_STATE_FLED (new custom state registered by RpgVisitor). On failure, skip player turn and transition to ENEMY_TURN.
       - `use_item_in_battle_<id>(item_id)`: generates in-battle item use — calls the item's onUseOps (from ItemDef) within combat context, deducts item from inventory (calls `remove_item(item_id, 1)`), then transitions to ENEMY_TURN. Targets the active combatant by default; healing items target party member.
       - Wire both into the PLAYER_TURN state machine: add `_combat_<id>_selected_action` UINT8 global (ACTION_ATTACK=0, ACTION_ABILITY=1, ACTION_ITEM=2, ACTION_FLEE=3). The PLAYER_TURN state dispatches based on this value to basicAttack, dispatch_ability, use_item_in_battle, or player_flee respectively.
       - This is the critical wiring that connects RPG actions to the engine combat state machine (SC-5).
