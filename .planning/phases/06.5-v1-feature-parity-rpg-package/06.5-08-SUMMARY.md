## Decisions Made
- **encounterConfig over new typed fields**: Added `encounterConfig: Map<String, Any>? = null` to `CombatEngineSystem` rather than adding `partyIds`, `encounterData`, etc. as first-class fields. Keeps the sealed IR node lean while allowing simpleBattle data to flow through to codegen if needed. The null default is backward-compatible with all existing non-RPG usages.
- **Remove buildSimpleBattleFunctions() entirely**: The method generated a simple stub combat loop. Now that `CombatVisitor.generateCombatFunctions()` handles `TURN_BASED`, there is no need for a parallel implementation. Removed cleanly.
- **party(String) overload added to SimpleBattleBuilder**: Integration test and ExplorerV2 use string-based party IDs. Added alongside the `party(CharacterDef)` overload for API completeness.
