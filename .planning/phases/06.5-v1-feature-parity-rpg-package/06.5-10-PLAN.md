       ```kotlin
       class CombatHookBuilder {
           private val hooks = mutableMapOf<CombatHookPoint, MutableList<ScriptOp>>()

           fun beforeAction(block: ScriptBuilder.() -> Unit) {
               hooks.getOrPut(CombatHookPoint.BEFORE_ACTION) { mutableListOf() }
                   .addAll(recordStatements(block))
           }
           fun afterAction(block: ScriptBuilder.() -> Unit) { ... }
           fun afterDamage(block: ScriptBuilder.() -> Unit) { ... }
           fun beforeTurn(block: ScriptBuilder.() -> Unit) { ... }
           fun afterTurn(block: ScriptBuilder.() -> Unit) { ... }
           fun onVictory(block: ScriptBuilder.() -> Unit) { ... }
           fun onDefeat(block: ScriptBuilder.() -> Unit) { ... }

           fun build(): Map<CombatHookPoint, List<ScriptOp>> = hooks.mapValues { it.value.toList() }
       }
       ```

    1. **Add hook injection to CombatVisitor**: In `buildStateMachineSwitch()` and related methods, emit hook call sites at each CombatHookPoint location:
       - **BEFORE_TURN:** At the start of turn processing (before PLAYER_TURN/ENEMY_TURN dispatch)
       - **AFTER_TURN:** At the end of turn processing (after both player and enemy have acted)
       - **BEFORE_ACTION:** Before each action dispatch (in both PLAYER_TURN and ENEMY_TURN handlers)
       - **AFTER_ACTION:** After each action completes (after ability/attack/item execution returns)
       - **AFTER_DAMAGE:** After any damage calculation writes to HP (after `_combat_<id>_hp[target] -= damage` line)
       - **ON_VICTORY:** In the VICTORY state handler, before any onVictoryOps — hooks run first, then user-defined victory ops
       - **ON_DEFEAT:** In the DEFEAT state handler, before any onDefeatOps — hooks run first, then user-defined defeat ops

       Implementation pattern — for each hook point, emit:
       ```c
       /* Hook: BEFORE_ACTION */
       if (_combat_<id>_hooks_enabled) {
           hook_before_action_<id>();
       }
       ```
       Where `hook_<point>_<id>()` is a generated C function containing the ScriptOps for that hook point. Only emit the hook function and call site if combatHooks contains ops for that point (no-op for empty hooks — zero overhead when hooks are unused).

    2. **Emit hook functions**: For each non-empty hook point in combatHooks, generate:
       - `void hook_<point>_<id>(void)` C function containing the ScriptOps
       - Use ScriptOpVisitor to generate C from the ScriptOps (same pattern as onVictoryOps)
       - Emit `_combat_<id>_hooks_enabled` UINT8 global (default 1) — allows runtime hook disable for performance

       - `onVictory hook runs before user onVictoryOps`
       - `empty combatHooks produces no hook functions (zero overhead)`
       - `multiple hook points each generate separate functions`
       - `hooks_enabled global emitted when any hook is present`
       - `zero CRawCode in hook codegen`
