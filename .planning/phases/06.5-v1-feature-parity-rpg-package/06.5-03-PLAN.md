    1. **Create BehaviorTree.kt**: Sealed hierarchy of behavior tree node types:
       ```kotlin
       sealed interface BehaviorNode
       data class SelectorNode(val children: List<BehaviorNode>) : BehaviorNode   // OR — first success wins
       data class SequenceNode(val children: List<BehaviorNode>) : BehaviorNode   // AND — all must succeed
       data class ConditionNode(val predicate: MonsterCondition) : BehaviorNode   // leaf condition check
       data class ActionNode(val action: MonsterAction) : BehaviorNode            // leaf action to execute
       data class PhaseThresholdNode(val hpPercent: Int, val tree: BehaviorNode) : BehaviorNode  // HP-threshold boss phase
       data class CooldownNode(val abilityId: String, val cooldownTurns: Int, val child: BehaviorNode) : BehaviorNode  // cooldown gate
       ```
       Supporting types:
       ```kotlin
       sealed interface MonsterCondition
       data class HpBelow(val percent: Int) : MonsterCondition
       data class HpAbove(val percent: Int) : MonsterCondition
       data class AllyHpBelow(val role: MonsterRole?, val percent: Int) : MonsterCondition
       data class TurnCountAbove(val count: Int) : MonsterCondition
       data object Always : MonsterCondition

       sealed interface MonsterAction
       data class UseAbility(val abilityId: String) : MonsterAction
       data class BasicAttack(val targetStrategy: TargetStrategy = TargetStrategy.RANDOM) : MonsterAction
       data class Flee(val chance: Int = 100) : MonsterAction
       data class Summon(val monsterId: String, val count: Int = 1) : MonsterAction
       data class ChargeAction(val abilityId: String, val chargeTurns: Int) : MonsterAction

       enum class TargetStrategy { RANDOM, LOWEST_HP, HIGHEST_THREAT, BY_ROLE }
       enum class MonsterRole { TANK, HEALER, DPS, SUPPORT }
       enum class AwarenessLevel { SELF_ONLY, TARGET_AWARE, FULL_CONTEXT }
       enum class DifficultyTier { EASY, NORMAL, HARD }
       ```

    1. **Expand RpgVisitor** with ability and status effect codegen methods:
       - `generateAbilityFunctions(system: GenericSystem): List<CFunction>` — for each AbilityDef:
         - Emit `use_ability_<id>()` C function with: SP cost check + deduction, targeting resolution switch, execute ops via ScriptOpVisitor, status effect application with chance
         - Use typed C AST: CIf for SP check, CSwitch for targeting, CVarDecl for locals — zero CRawCode
       - `generateStatusEffectFunctions(system: GenericSystem): List<CFunction>` — for each StatusEffectDef:
         - Emit `apply_effect_<id>()`: apply chance check, stack handling, duration set
           - **GAP-5 (stat-based resist):** When resistType=STAT_CONTEST, emit `chance = applyChance - (target_<resistStat> - caster_matk)` before the apply check instead of using flat applyChance. When resistType=FLAT, use applyChance directly (existing behavior).
           - **GAP-6 (per-effect immunity):** Before applying, check BOTH `immuneCategories` (existing) AND `immuneToEffects`. Emit `if (_char_<target>_immune_to_<effectId>)` guard that short-circuits application. The immunity set is emitted as a bitmask or const array per character.
         - Emit `tick_effect_<id>()`: per-turn damage/heal, duration decrement, remove-on-expire
           - **GAP-7 (per-stack scaling):** When stackMode=INTENSITY and perStackScaling=true, emit `damage = damagePerTurn * _effect_<id>_stacks` instead of flat damagePerTurn. When perStackScaling=false (default), use flat damagePerTurn.
         - Emit `cleanse_effects(category)`: remove all effects matching category
         - **GAP-8 (full cleansing API):** Additionally emit:
           - `remove_effect_<id>()`: clears `_effect_<id>_active`, resets `_effect_<id>_duration` and `_effect_<id>_stacks` to 0. For removing a specific effect by ID.
           - `dispel_buffs(target_idx)`: iterates all registered effects where category==BUFF and calls `remove_effect_<id>()` for each active buff on the target. For stripping all buffs from an enemy.
         - Use UINT8 arrays for effect tracking: `_effect_<id>_active`, `_effect_<id>_duration`, `_effect_<id>_stacks`
         - If stackMode == INTENSITY and onStackAppliedOps is non-empty: emit callback invocation inside `apply_effect_<id>()` after incrementing stacks
         - If stackMode == INTENSITY and onStackRemovedOps is non-empty: emit callback invocation inside `tick_effect_<id>()` when decrementing/removing stacks

    2. **Add monster AI codegen** to RpgVisitor:
       - `generateMonsterAIFunctions(system: GenericSystem): List<CFunction>` — for each MonsterDef with a behavior tree:
         - Emit `update_ai_<id>()` C function that evaluates the behavior tree
         - **CRITICAL: Iterative evaluation, not recursive** — flatten the tree into sequential if/else chains at codegen time. Walk the tree depth-first, emit CIf/CBlock for conditions, CCall for actions. The tree structure determines the nesting of C if statements.
         - PhaseThresholdNode: emit `if (_mon_<id>_hp_pct < threshold)` check
         - CooldownNode: emit `if (_mon_<id>_cd_<abilityId> == 0)` check, decrement in AI function header
         - SelectorNode: emit children as sequential `if (...) { ... } else if (...) { ... }` — first match wins
         - SequenceNode: emit children as sequential statements — all must execute
         - ActionNode: emit CCall to appropriate action function (use_ability, basic_attack, flee, summon)
       - If `MonsterDef.allowGlobalRepeatPrevention == true`: emit `_mon_<id>_last_action` UINT8 global, add `if (_mon_<id>_last_action != <action_id>) { ... }` guard at the start of each action branch in `update_ai_<id>()`, and update `_mon_<id>_last_action = <action_id>` after executing an action
       - **GAP-3 (difficulty tier modifies AI targeting):** Emit `_combat_difficulty` UINT8 global. In `update_ai_<id>()`, generate difficulty-branched target selection:
         - When `difficulty == EASY`: Override all TargetStrategy to RANDOM regardless of behavior tree specification (dumb targeting)
         - When `difficulty == NORMAL`: Use behavior tree's specified TargetStrategy as-is (default behavior)
         - When `difficulty == HARD`: Override TargetStrategy fallback to LOWEST_HP (smart targeting — targets weakest party member). Also enables ability selection preference for highest-damage abilities when multiple options are available.
         - Emit as CIf chain at the top of target resolution: `if (_combat_difficulty == 0) { /* EASY: random */ } else if (_combat_difficulty == 2) { /* HARD: lowest HP */ } else { /* NORMAL: tree default */ }`
       - All behavior tree evaluation code is FLAT C (no function pointer arrays, no stack-based BT runtime) — tree is compiled away at codegen time

    2b. **Wire ability dispatch into combat state machine**: The `use_ability_<id>()` functions generated by `generateAbilityFunctions()` must be callable from the CombatVisitor PLAYER_TURN and ENEMY_TURN states. Add a dispatch mechanism:

This function is called from the combat state machine's PLAYER_TURN (for player-selected abilities) and from `update_ai_<id>()` (for AI-selected abilities via `UseAbility` action nodes).
       - Add `_combat_<id>_selected_ability` UINT8 global for the currently selected ability in PLAYER_TURN.
       - This wiring goes in RpgVisitor and is emitted alongside the ability functions.
