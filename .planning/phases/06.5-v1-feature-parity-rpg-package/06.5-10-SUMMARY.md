## Decisions Made
- CombatHookPoint lives in gbkt-ir (not gbkt-rpg) because it's a direct field type on CombatEngineSystem which is sealed in gbkt-ir — Kotlin sealed constraint requires all implementations and field types to be in the same module
- AFTER_DAMAGE call site placed in ENEMY_TURN case after action dispatch, as there is no explicit HP deduction operation in the base turn-based state machine — this is the semantically closest injection point
- hooks() DSL extension uses setCombatHooks() setter pattern to bridge gbkt-rpg (extension module) to gbkt-lang (core builder module)
