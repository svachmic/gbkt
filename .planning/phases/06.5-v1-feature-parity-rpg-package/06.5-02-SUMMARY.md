## Decisions Made
- AbilityDef and StatusEffectDef are plain data classes (not sealed IR subtypes) — maintains design constraint from Plan 01 RPG package pattern
- `isDebuff` is a derived `val` property using `get()` rather than a constructor param — derived from `category` field
- Delegate tests use explicit-id form since `provideDelegate` is not called for local `val` inside lambdas — matches CombatInventoryBuilderTest pattern and comment
- `recordStatements()` is `internal` to gbkt-lang; RPG module instantiates `ScriptBuilder()` directly for op recording — same pattern as existing `SimpleBattleBuilder`
