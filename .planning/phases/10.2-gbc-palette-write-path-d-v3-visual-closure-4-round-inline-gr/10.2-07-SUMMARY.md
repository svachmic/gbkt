## Named Cause

**Source:** GBDKPipelineV2.kt mainBody buildList, lines ~3826–3835 (commit 0976e08b, Plan 10.1-22)

**Mechanism:** LCDC.4=1 (shared $8000–$97FF VRAM region, enabled by Plan 20's LCDC reorder) means `set_bkg_data(0, 1, _checkerboard_bg_pattern)` and `set_sprite_data(0u, 48u, elephant_tiles)` both write to VRAM starting at tile 0 ($8000). Plan 22's emission order:
1. `set_sprite_data(0u, 48u, elephant_tiles)` — writes elephant tiles to $8000+
2. `set_bkg_data(0, 1, _checkerboard_bg_pattern)` — OVERWRITES tile 0 with checker bytes

Last write wins. Sprite tile 0 contains checker bytes when DISPLAY_ON fires. Combined with `set_bkg_palette` committing BG-palette-aware PPU state, Coffee-GB's PPU decodes sprite tile 0 using BG palette colors (gray) instead of OAM palette slot 2 (cyan_pal).

**OCPD slot 2 = `[0x7FFF, 0x7FEA, 0x56A0, 0x2940]` (cyan_pal) is CORRECT in palette RAM throughout — the palette write path is NOT broken. The defect is in VRAM tile data ordering.**

## Fix Shape: Option B (Order-Tweaked)

Swap the two `addAll()` calls in `buildMainFunction()` mainBody buildList:

```
BEFORE (Plan 22 / broken):
    addAll(allSpriteDataLoads)
    addAll(hoistedBgFillCheckerboardStatements)

AFTER (Plan 08 fix):
    addAll(hoistedBgFillCheckerboardStatements)
    addAll(allSpriteDataLoads)
```

Writing bgFillCheckerboard FIRST means elephant tile data is the LAST write to tile 0 — sprite tile 0 contains correct elephant pixel data when DISPLAY_ON fires.
