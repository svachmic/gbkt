<objective>
Add the SEED-012 MCP tool PAIR — `emulator_read_memory(address, count)` AND `emulator_write_memory(address, value)` — to `gbkt-mcp-server`, with session-layer + StepAgent-layer pass-through wrappers. This is the diagnostic-tool prerequisite that unlocks every subsequent bisect-probe palette-RAM dump and the post-fix UAT re-shoot's BCPD/OCPD verification.

**Why the pair (user decision 2026-05-19):** The original SEED-012 was read-only. But D-07 requires a full 16-byte (slots 0..7 first-color) — and ideally a full 64-byte (slots 0..7 × 4 colors × 2 bytes) — BCPD/OCPD dump per probe. The GBC hardware BCPS/OCPS port pair uses index-write + data-read indirect addressing: you write the index byte to 0xFF68 (BCPS) / 0xFF6A (OCPS), then read the corresponding byte from 0xFF69 (BCPD) / 0xFF6B (OCPD). Without a `writeMemory` tool, the orchestrator cannot drive the index register, so the dump reduces to a 1-byte sentinel. The user just rejected scope reduction (revision 1) and authorized extending SEED-012 with the write companion to RESTORE the D-07 evidence contract.

Purpose: Without this PAIR, every bisect probe (Plans 03/04/05) and the closure-verdict (Plan 09) can only get behavior3 PNG bytes plus 1-byte BCPD/OCPD signals — not the full per-slot palette RAM state that the Coffee-GB `ColorPalette.java` source-dive (10.1 finding-v2) names as the binding signal.

Output: Two additive `addTool(...)` registrations + two `handleX` handler methods + two `McpEmulatorSession` wrapper methods + one new `StepAgent.writeMemory` method. Zero changes to gbkt-emulator semantics (writeByte already exists in MemoryAccess); zero changes to the existing 16 tools.
</objective>
