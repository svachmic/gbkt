```kotlin
private fun extractFunctionBodyForDv3V3(source: String, signature: String): String? {
    val sigIdx = source.indexOf(signature)
    if (sigIdx == -1) return null
    val openIdx = source.indexOf('{', sigIdx + signature.length)
    if (openIdx == -1) return null
    var depth = 0
    var i = openIdx
    while (i < source.length) {
        when (source[i]) {
            '{' -> depth++
            '}' -> {
                depth--
                if (depth == 0) return source.substring(openIdx + 1, i)
            }
        }
        i++
    }
    return null
}
```

## Shared Patterns

### GBC-conditional emission gate (D-11 binding for any new emission)

**Source:** `GBDKPipelineV2.kt:1014`, `:3780`, `:3798` (three identical sites).
**Apply to:** Any new register write, palette write, or hoist in Wave 5's fix.

```kotlin
if (gameIR.config.gbcTarget != GbcTarget.DMG) {
    // GBC-only emission — DMG codegen is unaffected
}
```

**Negative-of-DMG gate semantics:** future enum additions (hypothetical `SGB`) default to emitting the gated content — safer than silent drop on the GBC visual path. Plan 22 uses this exact spelling.

### Awk brace-walk before grep (D-18 binding for any new RED test)

**Source:** All 5 currently-locked tests — `DV3GbcPaletteWriteDiagnosticTest.kt:72-90`, `DV3VisualV2DiagnosticTest.kt:65-83`, and 3 more.
**Apply to:** Every new @Test method in `DV3VisualV3DiagnosticTest.kt`.

The shared 18-line helper (rename per file to avoid same-package symbol clash — `extractFunctionBodyFor<Test-name>`). File-level grep is forbidden — `mainC.contains("set_bkg_palette")` would pass even if the call lives in `play_enter()`. Always brace-walk to the function body first.

### Duplication-not-relocation hoist (Plan 20 + 22 pattern)

**Source:** `GBDKPipelineV2.kt:3737-3743` (sprite-palette hoist) + `:3762-3768` (bgFillCheckerboard hoist).
**Apply to:** Any fix-shape that needs to move an emission earlier in the bootstrap sequence.

The hoist FILTERS-AND-MAPS the start scene's `enterOps` — it does NOT remove them from the source. The original emission stays in `{start}_enter()`, the hoisted copy lands in `main()`. Palette/VRAM writes are idempotent so duplication is runtime-neutral, but the locked `BgCheckerboardEmissionTest` (which asserts on `play_enter` body) stays GREEN because the original RawOp is untouched.

### MCP-tool registration shape (16 existing tools in `ToolHandlers.kt:338-807`)

**Source:** Every `addTool(...)` block in `Server.registerEmulatorTools()`.
**Apply to:** The new `emulator_read_memory` registration.

Uniform shape: `addTool(name, description, inputSchema = ToolSchema(properties, required)) { request -> withContext(Dispatchers.IO) { try { ToolHandlerLogic.handle<X>(...) } catch (e: Exception) { System.err.println("MCP [<name>] error: $e"); errorResult("...") } } }`. The `System.err.println` (not stdout) is critical — stdout is the MCP transport.

### Plan 21→22 diagnostic→fix decoupling (D-19 binding for Wave 4 → Wave 5)

**Source:** Phase 10.1 `10.1-21-SUMMARY.md` (diagnostic plan committed `DV3VisualV2DiagnosticTest` RED + finding writeup) and `10.1-22-SUMMARY.md` (1-task atomic fix that flipped the test RED → GREEN).
**Apply to:** Wave 4 (named-cause finding plan) MUST commit `DV3VisualV3DiagnosticTest` RED. Wave 5's fix is a 1-task atomic execution.
