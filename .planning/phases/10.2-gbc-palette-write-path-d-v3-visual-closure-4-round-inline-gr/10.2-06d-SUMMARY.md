## Mechanism Hypothesis (refined from sub-narrow)

- `set_bkg_palette(0u, 1u, _gbkt_default_bg_pal)` writes to BCPD slot 0 (BG palette RAM) before DISPLAY_ON
- `set_bkg_data(0, 1, _checkerboard_bg_pattern)` writes checker tile data into BG VRAM tile slot 0, which in GBC mode with LCDC.4=1 shares the $8000–$97FF region with sprite VRAM
- This combination overwrites elephant sprite tile data OR corrupts OAM attribute bytes (subpal selection bits) before the first composited frame
- Result: sprite renders with wrong subpalette (gray slot 0 instead of cyan slot 2)
