# Phase 10.2 Plan 08: Atomic addAll order-swap fix — bgFillCheckerboard before allSpriteDataLoads Summary

**One-liner:** Order-Tweaked addAll swap in GBDKPipelineV2.kt mainBody puts bgFillCheckerboard before allSpriteDataLoads — VRAM tile-0 last-write-wins restores elephant sprite pixel integrity at DISPLAY_ON.

## What Was Done

Applied the verbatim fix from `evidence/d-v3-visual-finding-v3.md` Section 5 to
`GBDKPipelineV2.kt`. The fix swaps two `addAll()` calls in `buildMainFunction()`'s `mainBody`
buildList, resolving the 5th-layer VRAM collision identified by the Phase 10.2 bisect chain
(Plans 03–06d, 7 probes).

**Root cause recap (from finding-v3.md Section 2):**
With `LCDC.4=1` (shared `$8000-$97FF` region for both BG and sprite tile data), Plan 22's
emission order was:
1. `set_sprite_data(0u, 48u, elephant_tiles)` → writes elephant bytes to VRAM tile 0
2. `set_bkg_data(0, 1, _checkerboard_bg_pattern)` → OVERWRITES tile 0 with checker bytes

Last write wins: elephant sprite tile 0 contained checker bytes at DISPLAY_ON → gray sprite.

**Fix:**
Move `addAll(hoistedBgFillCheckerboardStatements)` to BEFORE `addAll(allSpriteDataLoads)`.
BG tile data writes first; then `set_sprite_data` overwrites with elephant data → sprite tile 0
has correct elephant pixel data when `DISPLAY_ON` fires.
