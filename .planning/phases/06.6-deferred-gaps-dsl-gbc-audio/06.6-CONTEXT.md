# Phase 06.6: Deferred Gaps — DSL Ergonomics, GBC Support & Audio - Context

**Gathered:** 2026-02-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Close three categories of deferred framework gaps before example games showcase the framework:
1. **DSL Ergonomics** — Input released event, dpad axis helpers, safe array access, generic typed collections, struct element types, old API removal
2. **GBC Color Support** — RGB/hex color helpers, palette builder DSL, preset library, hardware validation
3. **Audio System** — hUGEDriver integration, priority-based SFX mixing, music lifecycle management, .uge asset pipeline

Deferred item traceability: A1-A6 (DSL), B1-B3 (GBC), C1-C3 (Audio) from roadmap.

</domain>

<decisions>
## Implementation Decisions

### Old API Removal (A6)
- **Delete outright** — `assign()`, `varRef()`, `literal()` removed entirely, no deprecation ceremony (pre-v1 release)
- **Full sweep + compiler** — grep sweep to proactively find all call sites in tests/examples, then compiler verifies zero remain
- **raw() renamed** — keep as escape hatch, rename to signal danger (e.g., `unsafeRaw()` or `cEmit()`), emit build WARNING when used

### Input Enhancements (A1, A2)
- **InputRef.released** — edge-triggered (true for one frame on release), matching `.pressed` semantics
- **dpad.x / dpad.y** — return full `Expr` values (-1/0/+1) composable with arithmetic: `player.x += dpad.x * speed`

### Array Safety (A3)
- **Compile-time bounds checking only** — when index is a literal, validate at DSL record time; zero runtime overhead in generated C
- **Best DX philosophy** — proactively help the developer catch mistakes without GB CPU cost

### Struct Types (A5)
- **DSL construct** — `struct("TileHashEntry") { field("key", u16); field("value", u8) }` — explicit definition mapping to C struct
- **Reusable** — define once, use in hashtable, pool, ring buffer, fixed slots, and standalone variables
- **Dot syntax for field access** — `entry.key set 5` / `whenever(entry.key isAbove 10)` via proxy objects
- **Flat fields only** — struct fields are primitives (u8, u16, i8, i16, bool); nested structs deferred

### Generic Collections (A4)
- **Reified generics** — `val cache by hashtable<TileEntry>(64)` with compile-time type checking and IDE autocomplete
- **Method-based access** — `cache.put(key, entry)` / `cache.get(key)` / `cache.remove(key)` — clear intent, consistent verb style
- **All four collection types** support struct elements from the start (hashtable, pool, ring buffer, fixed slots)
- **forEach iteration** — `entityPool.forEach { entity -> entity.x += entity.dx }` generates C for-loop
- **RAM validation** — RAMPlanningPass calculates total collection memory; build error if total exceeds WRAM budget
- **Pool acquire** — returns null proxy + `exists` check when full: `val bullet = pool.acquire(); whenever(bullet.exists) { ... }`
- **Ring buffer** — full API: push/pop/peek, overwrite-oldest on full
- **Fixed slots** — both index access (`inv[3]`) and named keys (`equip.slot("weapon")`)

### GBC Color Helpers (B1, B2)
- **Multiple input formats** — `gbc(r,g,b)` with 0-31 range, `gbcHex("#FF8800")` from 24-bit, and named constants; all compile to RGB555
- **Lossy conversion warning** — build warning with preview: `'#FF8800' maps to GBC (31,17,0)` showing original vs actual
- **Explicit GBC opt-in** — `config { target(GBC) }` or `config { target(GBC_COMPATIBLE) }` matching GBDK compiler flag distinction

### GBC Palette System (B3)
- **Builder DSL** — `val forest by palette { color0(gbc(0,20,5)); color1(gbc(10,25,8)); ... }` auto-validates 4-color limit
- **Curated preset library** — ~15-20 presets: classic GB green, nature, fire/ice, ocean, dungeon, UI
- **Scene-level default + actor override** — `scene { palette(GbcPalette.NATURE) }` with per-actor `palette(GbcPalette.FIRE)` override
- **Hardware validation** — build error if scene uses more than 8 BG or 8 OBJ palettes (via analysis pass)

### Audio Driver (C1, C2, C3)
- **hUGEDriver** — native .uge format, GBDK built-in support, active community
- **Asset-based music** — `val theme by music(asset("music/dungeon.uge"))` with asset pipeline conversion
- **Gradle asset pipeline** — .uge to C conversion in processAssets task alongside PNG/TMX
- **Priority-based SFX mixing** — HIGH/MEDIUM/LOW per sound; high-priority SFX temporarily steal music channels, auto-resume
- **Fade transitions** — `play(battleTheme, fadeIn = 30)` / `stopMusic(fadeOut = 15)` for smooth track changes
- **Music resume** — opt-in: `play(dungeonTheme, resume = true)` remembers position for RPG dungeon-to-battle pattern
- **Scene auto-manage** — `scene { music(dungeonTheme) }` auto-plays on enter, auto-stops on exit; explicit play()/stop() can override

### Claude's Discretion
- Exact rename for `raw()` (unsafeRaw / cEmit / rawC — pick what reads best)
- Specific palette preset names and color values in the curated library
- Internal priority scheduling algorithm for audio channel management
- C code generation patterns for struct field access proxies
- hUGEDriver integration details (exact API calls, bank placement for music data)

</decisions>

<specifics>
## Specific Ideas

- Pool acquire syntax with `exists` check: `val bullet = pool.acquire(); whenever(bullet.exists) { bullet.x set player.x }`
- Palette builder syntax: `val forest by palette { color0(gbc(0, 20, 5)); color1(gbc(10, 25, 8)); ... }`
- Music in scenes: `scene("dungeon") { enter { play(dungeonTheme) } }` — scene auto-manages lifecycle
- SFX priority: `val swordHit by sfx { channel(PULSE_1); priority(HIGH) }` — high steals from music
- Fixed slots with named keys: `equip.slot("weapon").item set ironSwordId`
- forEach on collections: `entityPool.forEach { entity -> entity.x += entity.dx }`
- Axis helpers composable: `player.x += dpad.x * speed`

</specifics>
