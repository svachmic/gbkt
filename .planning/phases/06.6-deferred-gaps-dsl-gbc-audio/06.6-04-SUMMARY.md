# Phase 06.6 Plan 04: Struct Types and Generic Collections Summary

**One-liner:** StructDef IR node with CollElementType sealed interface replaces VarType in all collection nodes, enabling struct-typed collections with generic DSL delegates and typedef struct C codegen.

## What Was Built

### Task 1: StructDef IR node, CollElementType sealed interface, and struct builder DSL

**StructIR.kt** — new file with three types:
- `StructFieldDef(name, type: VarType)` — single struct field with `byteSize`
- `StructDef(name, fields, sourceLocation?)` — flat primitive struct with `byteSize`, `field()` lookup, and validation (no empty/duplicate fields)
- `CollElementType` — sealed interface replacing `VarType` in all collection IR nodes:
  - `CollElementType.Primitive(varType)` — wraps VarType; `cTypeName` returns GBDK alias ("UINT8", "INT16", etc.)
  - `CollElementType.Struct(structDef)` — wraps StructDef; `cTypeName` returns struct name

**CollectionsIR.kt** — all four collection types updated:
- `IRCollHashTable.keyType/valueType: CollElementType` (was `VarType`)
- `IRCollPool.elementType: CollElementType`
- `IRCollRingBuffer.elementType: CollElementType`
- `IRCollFixedSlots.elementType: CollElementType`

**GameIR.kt** — added `val structs: List<StructDef> = emptyList()`

**StructBuilder.kt** — DSL extension:
```kotlin
val tileEntry = struct("TileHashEntry") {
    field("key", u16)
    field("value", u8)
}
// tileEntry.byteSize == 3
```

**StructVar** proxy for dot-syntax field access:
```kotlin
val proxy = StructVar("slot", tileEntry)
val keyRef = proxy["key"]  // AssignableVar("slot.key")
```

**GameBuilder.kt** — added `registerStruct()`, `findStructByName()`, `_structs` list, and `structs = _structs.toList()` in `build()`.

**Tests:** StructIRTest.kt (14 tests) — StructFieldDef byteSize, StructDef validation, field lookup, CollElementType byteSize/cTypeName, collection sizeBytes integration.

### Task 2: Generic collection delegates and struct codegen

**CollectionBuilders.kt** — new file with four delegate types and factory functions:
- `HashTableDelegate`, `PoolDelegate`, `RingBufferDelegate`, `FixedSlotsDelegate`
- Each registers the IR node in GameBuilder via `GameBuilderContext.current?.registerHashTable(...)` in `provideDelegate`
- Three overload forms for each: `CollElementType`, `StructDef`, and `VarType`
- Reified generic forms: `hashtable<TileHashEntry>(64)`, `pool<Entity>(8)`, etc.

DSL usage:
```kotlin
// Explicit struct form
val cache by hashtable(tileEntry, 64)

// Explicit primitive form
val scores by hashtable(VarType.U8, VarType.U16, 16)

// Reified generic form (resolves by T::class.simpleName)
val cache by hashtable<TileHashEntry>(64)
```

**GameBuilder.kt** — added:
- `_hashTables`, `_pools`, `_ringBuffers`, `_fixedSlots` mutable lists
- `registerHashTable()`, `registerPool()`, `registerRingBuffer()`, `registerFixedSlots()` methods
- Wired into `build()` as `hashTables = _hashTables.toList()`, etc.

**GBDKPipelineV2.kt** — added `buildStructTypedefs()`:
```kotlin
// Emits: typedef struct { UINT16 key; UINT8 value; } TileHashEntry;
private fun buildStructTypedefs(structs: List<StructDef>): List<CTypedef>
```
Added `typedefs = structTypedefs` to the `CFile` constructor in `buildHomeFile()`.

**Tests:** StructCollectionTest.kt (17 tests) + 3 new pipeline integration tests in GBDKCollectionCodegenTest.kt.
