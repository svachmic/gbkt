# Phase 06.6 Plan 01: DSL Ergonomics — Input Released, Axis Helpers, Array Bounds, API Deletion Summary

**InputRef.released for falling-edge input, dpad.x/y axis helpers, compile-time array bounds check via require(), and removal of literal()/varRef() deprecated functions**

## Performance

- **Started:** 2026-02-24
- **Completed:** 2026-02-24

- **Files modified:** 8

## Accomplishments

- Added `InputRef.released` property (falling-edge detection) to all 8 inputs: dpad.up/down/left/right and buttons.a/b/start/select via new 4th `releasedFn` constructor parameter
- Added `dpad.x` and `dpad.y` axis helpers returning -1/0/+1 `TernaryExpr` for smooth directional movement
- Added `button_released` and `dpad_released` C helper functions to `GBDKPipelineV2.buildInputHelperFunctions()` using `(~__joypad & mask) & (__joypad_prev & mask)` logic
- Added compile-time `require()` bounds check to `ArrayVar.get(Int)` and `set(Int,...)` — throws `IllegalArgumentException("Array bounds error: index $i out of bounds for array '$name' (size=$n)")` at DSL record time
- Deleted `literal()` and `varRef()` deprecated factory functions from `ExprBuilder.kt`
- Rewrote `ScriptBuilderTest` in `gbkt-core` to use `game{}.build()` pattern instead of internal `ScriptBuilderContext` (which is inaccessible from `gbkt-core`)
- Updated `GameBuilderTest` and `ArrayVarHelpersTest` to use modern API (`buttons.start.pressed`, `dpad.up.held`, `AssignableVar.set`)

## Decisions Made

- `ScriptBuilderContext` is `internal` to `gbkt-lang`. The `ScriptBuilderTest` in `gbkt-core` previously used internal context via `@Suppress("DEPRECATION")`. After deleting deprecated public methods, the test needed to use `game{}.build()` pattern to establish context without accessing internal types. The two-helper approach (`buildScript` for direct ops, `buildGameScript` for context-needing ops) keeps all tests in the existing file location while being correct.
- `button_released` and `dpad_released` use identical logic (both check `(~__joypad & mask) & (__joypad_prev & mask)`) since both are "was pressed last frame, not pressed this frame" semantics — the mask determines which buttons/directions are checked.
