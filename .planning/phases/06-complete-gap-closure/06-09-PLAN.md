<task type="auto">
  <name>Task 1: Source map viewer with bidirectional scrolling and asset ref inspections</name>
  <files>
    gbkt-intellij-plugin/src/main/kotlin/io/github/gbkt/intellij/preview/CCodePreviewPanel.kt
    gbkt-intellij-plugin/src/main/kotlin/io/github/gbkt/intellij/services/GbktCodegenService.kt
    gbkt-intellij-plugin/src/main/kotlin/io/github/gbkt/intellij/inspections/GbktAssetRefInspection.kt
    gbkt-intellij-plugin/src/main/kotlin/io/github/gbkt/intellij/inspections/GbktCreateAssetPlaceholderQuickFix.kt
    gbkt-intellij-plugin/src/main/resources/META-INF/plugin.xml
  </files>
  <action>
    Use Serena MCP tools for code exploration.

    **I1 — Source map viewer (C→DSL direction):**
    1. Read CCodePreviewPanel.kt — per Research: DSL→C direction already works via `setupDslCaretListener()` and `scrollToMatchingCLine()`. The gap is C→DSL reverse direction.
    2. Add a caret listener on the C code editor (right panel) that:
       - Gets the current C line number relative to the current file (using `fileLineOffsets` to map combined doc line → per-file line)
       - Looks up the SourceLocation for that C line from the loaded source map
       - If found, scrolls the DSL editor (left panel) to the corresponding Kotlin file:line
       - Highlights the matching DSL line
    3. In GbktCodegenService, add `findKotlinLocationForCLine(cFile: String, cLine: Int): SourceLocation?` method that reverse-maps from C line to Kotlin source. This iterates the source map entries for the given file and finds the entry matching the C line.
    4. Add visual feedback: highlight the matched line in both editors with a semi-transparent background color.

    **I2 — Asset reference inspections:**
    5. Create `GbktAssetRefInspection.kt` extending `LocalInspectionTool`.
    6. In `buildVisitor()`, visit PsiElements that represent `asset("path/to/file.png")` calls.
    7. For each asset reference string:
       - Resolve the path relative to the project's asset directory (typically `src/main/resources/` or `src/main/assets/`)
       - Check if the file exists on disk
       - If missing, register a `ProblemHighlightType.ERROR` with the string literal element
    8. Create `GbktCreateAssetPlaceholderQuickFix.kt`:
       - Implements `LocalQuickFix`
       - Creates a minimal 1x1 transparent PNG at the referenced path
       - Uses Java ImageIO to create the PNG: `BufferedImage(1, 1, TYPE_INT_ARGB)` → write to file
    9. Register the inspection in `plugin.xml`:
       ```xml
       <localInspection
           implementationClass="io.github.gbkt.intellij.inspections.GbktAssetRefInspection"
           displayName="Missing asset reference"
           groupName="gbkt"
           enabledByDefault="true"
           level="ERROR" />
       ```

    **Plugin compilation:**
    10. Check the plugin's `build.gradle.kts` for the IntelliJ platform target version. Use only stable APIs. Add any new dependencies (e.g., for image creation — java.awt is available in IntelliJ runtime).
  </action>
  <verify>
    IntelliJ plugin compiles: `./gradlew :gbkt-intellij-plugin:buildPlugin` (or equivalent).
    GbktAssetRefInspection registered in plugin.xml.
    No deprecated IntelliJ API warnings.
  </verify>
  <done>Source map viewer has bidirectional C↔DSL scrolling. Asset reference inspection validates file existence. Quick-fix creates placeholder PNG.</done>
</task>
