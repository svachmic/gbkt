    **A1 — SoundEffectDef in GameIR:**
    1. Create `SoundEffectDef` data class in Types.kt (or new file) with fields:
       - `id: String`, `channel: Channel`, `registers: SoundRegisters`
       - Channel enum: PULSE1, PULSE2, WAVE, NOISE
       - SoundRegisters: sweep, duty, envelope, frequency, length, trigger, lengthEnable, waveform
       Reference existing `Sound.kt` in gbkt-core (at `io.github.gbkt.core.Sound`) for field types and preset data.
    2. Add `soundEffects: List<SoundEffectDef> = emptyList()` to GameIR (mirrors variables/arrays pattern).
    3. In GameBuilder, add `registerSoundEffect()` method and wire `soundEffect {}` DSL to register into GameIR.soundEffects.

    **A1 — Real NRxx register writes:**
    4. Rewrite `buildSoundWrapperFunction()` in GBDKPipelineV2.kt:
       - Look up SoundEffectDef from gameIR.soundEffects by id
       - Map channel type to correct NRxx register set:
         - PULSE1: NR10 (sweep), NR11 (duty+length), NR12 (envelope), NR13 (freq low), NR14 (freq high+trigger)
         - PULSE2: NR21, NR22, NR23, NR24 (no sweep)
         - WAVE: NR30, NR31, NR32, NR33, NR34
         - NOISE: NR41, NR42, NR43, NR44
       - Bit-pack according to Pan Docs register layouts (see Research code example A1):
         - NR10: `(sweepTime << 4) | (sweepDir << 3) | sweepShift`
         - NR11: `(dutyBits << 6) | (length & 0x3F)`
         - NR12: `(envVol << 4) | (envDir << 3) | envPace`
         - NR13: `freq & 0xFF`
         - NR14: `(trigger << 7) | (lengthEnable << 6) | ((freq >> 8) & 0x07)`
       - Emit CRawCode with hex-formatted register writes: `NR10_REG = 0xXXu;`

    **A3 — Custom waveform export:**
    5. When SoundEffectDef.channel == WAVE and registers.waveform is non-null (16 bytes), generate:
       `const UINT8 wave_data_<id>[] = { 0x.., 0x.., ... };` (16 bytes of wave RAM data)
       Before triggering CH3, emit wave RAM load sequence.

    **A4 — SoundSystem visitor wiring:**
    6. In `buildSystemFunctions()`, replace `filterIsInstance<GenericSystem>()` with a full dispatch that also handles SoundSystem. When SoundSystem is present, generate sound driver init function and ensure `sound_driver_update()` is called per frame. (Note: The full GBDKSystemVisitor for all system types is in Plan 05. This step only ensures SoundSystem is no longer silently ignored — either via the visitor pattern from Plan 05, or a local SoundSystem check if Plan 05 hasn't run yet.)

    **Tests:**
    7. Write unit tests verifying:
       - BEEP preset generates correct NR11/NR12/NR13/NR14 register values
       - HIT preset generates correct values (NOISE channel → NR41-NR44)
       - WAVE channel preset generates wave_data array + wave RAM load
       - SoundSystem is handled in buildSystemFunctions (not silently dropped)
