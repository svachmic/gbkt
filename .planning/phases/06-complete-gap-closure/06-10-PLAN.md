**Important context:** The v2 architecture is fundamentally different from v1. In v2, scene/entity/input/graphics concepts live in gbkt-ir (data classes: SceneIR, ActorIR, SpriteDef) and gbkt-lang (builders: SceneBuilder, ActorBuilder, InputBuilders with dpad/buttons singletons). There are no standalone "engine" runtime types. gbkt-engine's role is to provide the public-facing engine API surface that consumers import.

Create four Kotlin files replacing the package-info.kt placeholders:

**1. `gbkt-engine/.../scene/SceneTypes.kt`** (package `io.github.gbkt.core.scene`):
- `typealias SceneId = String` — scene identifier type
- `interface SceneLifecycle` with `fun onEnter()`, `fun onFrame()`, `fun onExit()` — lifecycle contract for scene implementations
- `data class SceneTransitionRequest(val targetSceneId: SceneId, val fadeType: FadeType = FadeType.NONE)`
- `enum class FadeType { NONE, FADE_BLACK, FADE_WHITE }` — transition fade options
- KDoc explaining these are v2 engine foundations; actual scene recording uses SceneBuilder in gbkt-lang

**2. `gbkt-engine/.../entity/EntityTypes.kt`** (package `io.github.gbkt.core.entity`):
- `interface Positionable { val x: Int; val y: Int }` — position contract
- `interface Movable : Positionable { fun moveTo(x: Int, y: Int); fun moveBy(dx: Int, dy: Int) }`
- `data class Hitbox(val x: Int, val y: Int, val width: Int, val height: Int)` — AABB collision box
- `data class EntityState(val visible: Boolean = true, val active: Boolean = true)` — runtime entity state
- KDoc explaining these are v2 engine interfaces; actor IR uses ActorIR in gbkt-ir

**3. `gbkt-engine/.../input/InputTypes.kt`** (package `io.github.gbkt.core.input`):
- `enum class Button { A, B, START, SELECT }` — button enum
- `enum class DpadDirection { UP, DOWN, LEFT, RIGHT }` — direction enum
- `interface InputState { fun isHeld(button: Button): Boolean; fun isPressed(button: Button): Boolean; fun isDpadHeld(direction: DpadDirection): Boolean; fun isDpadPressed(direction: DpadDirection): Boolean }`
- KDoc explaining these are v2 engine types; DSL input uses dpad/buttons singletons in gbkt-lang

**4. `gbkt-engine/.../graphics/GraphicsTypes.kt`** (package `io.github.gbkt.core.graphics`):
- `data class SpriteSize(val width: Int, val height: Int)` — sprite dimensions
- `data class AnimationFrame(val tileIndex: Int, val duration: Int)` — single animation frame
- `data class AnimationDef(val frames: List<AnimationFrame>, val loop: Boolean = true)` — animation definition
- `data class PaletteIndex(val index: Int)` — palette slot reference (0-7 for GBC)
- KDoc explaining these are v2 engine types; sprite data uses SpriteDef in gbkt-ir/ActorIR

**5. `gbkt-bom/build.gradle.kts`** — Add `api(project(":gbkt-rpg"))` constraint between the gbkt-backend-gbdk and gbkt-analysis entries. Add comment: "// RPG genre package -- combat, stats, abilities, monsters".

Delete the 4 package-info.kt files after creating the replacement type files (they become redundant since each new file declares the same package).
