# Phase 06.11: LabyrinthOfTheDragon Port - Context

**Gathered:** 2026-02-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Port the LabyrinthOfTheDragon (LotD) original C game to gbkt V2 Kotlin DSL as the flagship reference implementation. Same game content (8 dungeon floors, 12 monsters, 4 character classes, 24 abilities, items, dialog, save system) expressed in idiomatic V2 DSL. Includes PO-based localization with English and Czech. Generated C compiles with GBDK. Gameplay validation deferred to Phase 07 (UAT).

**Terminology (important):**
- **LotD Original** = hand-written C game in `LabyrinthOfTheDragon/src/` (24K lines, 56 files)
- **LotD V1 Port** = previous gbkt V1 attempt in `LabyrinthOfTheDragon-port/` (build config + assets remain, Kotlin source incomplete)
- **LotD V2 Port** = this phase — new V2 Kotlin DSL code in `LabyrinthOfTheDragon-port/`

</domain>

<decisions>
## Implementation Decisions

### Porting Fidelity
- The LotD Original is the **absolute source of truth** for game mechanics, feel, and specs
- **Case-by-case** for internal structure: gameplay-visible behavior must match the Original; internal structure (banks, memory layout, codegen patterns) can use V2 improvements
- **Fix obvious bugs** found during porting (off-by-ones, impossible conditions) but preserve intentional quirks. Use judgment, document fixes
- **Port debug facilities** (test floors, stat overrides from test.c/test.h) — useful for Phase 07 UAT

### Localization
- **Full PO localization** for all user-visible strings (~356+ strings). Audit existing en.po against Original strings.h to close gaps
- **Clean strings in PO, framework auto-pads** — do NOT pad strings in PO msgstr values. Add framework auto-padding support for fixed-width menu alignment. Document this as a framework feature
- **English + Czech** — two languages. Czech chosen to stress-test diacritics (ě, š, č, ř, ž, ý, á, í, é, ú, ů, ď, ť, ň — 14 extra font tiles needed)
- **Compile-time language flag** — build separate ROMs per language (labyrinth_en.gb, labyrinth_cs.gb). No runtime language switching
- **Extend Original font** with Czech diacritic tiles. Preserve the Original's visual style
- **Czech translation:** Claude drafts cs.po, user reviews and corrects

### Code Organization
- **Mirror V1 port file structure:** scenes/, rpg/, rpg/abilities/, world/, world/floors/ packages
- **One file per floor** (Floor1Entrance.kt through Floor8DragonLair.kt)
- **One file per class abilities** (FighterAbilities.kt, SorcererAbilities.kt, MonkAbilities.kt, DruidAbilities.kt)
- **Object-based entry point:** `object LabyrinthOfTheDragon { fun create() = gbGame(...) { ... } }` instead of top-level function
- **Reference-grade documentation:** KDoc on every file header, every monster definition, cross-references to Original C. Full tutorial quality
- **Zero magic strings — HARD CONSTRAINT.** All scene IDs, monster names, state names, flag names must use type-safe references. If a framework API currently requires a raw string, **fix the framework API first** to accept typed refs
- **No LotD-specific framework hacks.** Every framework change must be generic and reusable for "the next game after LotD." The port is a consumer of the framework, not a co-designer
- **Single Gradle module:** Keep `LabyrinthOfTheDragon-port/` directory. Reuse build.gradle.kts and assets selectively — only parts verified as correct
- **Clean canonical asset layout:** Deduplicate res/ directory. One canonical location per asset type: sprites/ for all sprites, tiles/ for tilesets, tilemaps/ for maps, strings/ for PO. Remove duplicates, audit against Original
- **Audit Original Node.js tools** (png2bin, color2bin, colorhex2c, strings2c, tables2c) against V2 Gradle plugin pipeline. Verify all tool functionality is covered. Fix gaps before writing game code
- **Fix validation to pass clean.** No skipValidation=true. Fix OAM usage and add missing assets so the reference game validates without workarounds

### DSL Gap Handling
- **Extend framework — no raw() escape hatches.** Every Original C pattern gets proper DSL support (new IR nodes, DSL builders, codegen visitors as needed)
- **DSL abstracts hardware.** Game code never references GBDK APIs directly. The DSL hides hardware behind high-level concepts (loadTileset(), setSprite()). Codegen emits the right GBDK calls
- **Separate framework tasks** for significant gaps. Framework extensions become their own plans, not inline with porting plans. Port plans depend on framework plans
- **Text system: best of both.** Use V2's architecture but ensure it can express everything the Original's text_writer.c/textbox.c does (character-by-character animation, line breaks, cursor positioning)
- **Banking: verify auto matches Original.** Let V2's auto-banking analysis run, then compare output bank layout to the Original's manual bank assignment. Investigate divergences
- **V2 save system.** Use V2's save DSL, no need to match Original's exact SRAM layout (no cross-compatibility requirement)

### Planning Granularity — HARD CONSTRAINT
- **Quality over speed.** Completeness and correctness are the priority
- **Small, self-contained plans.** Each plan should deliver a clearly bounded piece of value that can be verified independently. Prefer many focused plans over fewer large ones
- **Every plan must be complete within its scope.** No "we'll wire this up later" — each plan's deliverable should work end-to-end for the slice it covers
- **Full coverage required.** The sum of all plans must deliver the complete phase scope. No content left behind, no "nice to have" that gets silently dropped
- **Framework gaps get their own plans.** Don't bundle a framework extension with a porting task — separate concerns, separate plans, explicit dependencies between them

### Claude's Discretion
- Exact file-level decomposition beyond the established package structure
- Test strategy (IR tests, simulation tests, build verification) — follow conventions from Phase 06.10 example games
- Order of porting (which subsystem first — floors, monsters, battle, etc.)
- Internal naming conventions for constants and helper functions

</decisions>

<specifics>
## Specific Ideas

- "The original is the absolute source of truth when it comes to mechanics, feel and specs"
- "No magic strings, ever. I want to drum this in all developers as much as necessary"
- "I don't want [the framework] to be strongly biased towards the original LotD. Yes, LotD might need certain functionality, but it must be done in a way that gives the functionality to the next game after LotD"
- "Take the best parts out [of the V1 port] and reuse them. But beware — I could never make the actual gameplay work. So only take those parts you are sure are useful"
- Czech localization serves dual purpose: proves multi-language PO system and provides diacritics stress test

</specifics>

<deferred>
## Deferred Ideas

- Runtime language selector on title screen — could be added later but compile-time flag is sufficient for reference
- Save file compatibility with Original — not needed, V2 save format is independent
- Additional languages beyond English and Czech — framework supports it, just add more .po files

</deferred>
