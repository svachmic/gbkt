  <action>
Extend the Original font tileset with 14 Czech diacritic character tiles.

**Czech characters needed (14 tiles):**
- Lowercase with háček: ě, š, č, ř, ž, ď, ť, ň (8 tiles)
- Lowercase with čárka: ý, á, í, é, ú (5 tiles)
- Lowercase with kroužek: ů (1 tile)

**Design approach:**

1. **Inspect the Original font.png** — Determine tile size (expected 8x8 pixels), total tile count (expected 128), layout (likely 16 tiles per row × 8 rows), and visual style (pixel density, baseline, weight).

2. **Create diacritic tiles** — Each diacritic tile is the base Latin character (already in the font) with the appropriate diacritical mark added:
   - Háček (ˇ): small inverted circumflex above the letter (ě=e+ˇ, š=s+ˇ, č=c+ˇ, ř=r+ˇ, ž=z+ˇ, ď=d+ˇ, ť=t+ˇ, ň=n+ˇ)
   - Čárka (´): acute accent above the letter (á=a+´, é=e+´, í=i+´, ú=u+´, ý=y+´)
   - Kroužek (°): ring above the letter (ů=u+°)
   - In an 8x8 tile, the diacritical mark typically occupies the top 2-3 rows, with the letter body shifted down or compressed. Match the Original font's weight and style.

3. **Append to font.png** — Add the 14 new tiles after the existing 128 tiles. If the layout is 16 tiles/row, this means adding one partial row (14 tiles in a new row). The extended font will be 142 tiles total.

4. **Tile index assignment** — Document the tile indices for each diacritic:
   - Tile 128 = ě, 129 = š, 130 = č, 131 = ř, 132 = ž, 133 = ý, 134 = á, 135 = í, 136 = é, 137 = ú, 138 = ů, 139 = ď, 140 = ť, 141 = ň
   - (Exact order can vary; the mapping just needs to be consistent with the character map in Task 2.)

**Tooling:** Use Python PIL/Pillow or ImageMagick to programmatically generate the tiles, OR hand-draw them. The key requirement is visual consistency with the Original font.

**VRAM budget check:** 142 tiles × 16 bytes/tile = 2272 bytes. VRAM tile bank holds 256 tiles (4096 bytes). Original uses FONT_OFFSET = 0x80 (tile 128 start), meaning font tiles occupy 0x80-0xFF (tiles 128-255). 142 total font tiles would occupy 0x80 through 0x80+141 = 0x80+0x8D = tile 0x10D... this exceeds the 0xFF limit. **Alternative:** If FONT_OFFSET maps font tile 0 to VRAM tile 128, then 142 font tiles need VRAM tiles 128-269, which overflows. **Resolution options:**
- Use a lower FONT_OFFSET to make room (e.g., FONT_OFFSET = 0x72 → tiles 114-255 = 142 tiles, leaving 0x00-0x71 for dungeon tiles)
- Or keep FONT_OFFSET = 0x80 and only load diacritics when in Czech locale (compile-time selection means only one font variant is compiled)

Document the chosen VRAM layout.
