## Decisions Made

- **tables.c as static data:** The Original's `tables.c` (~9.5KB, 48 lookup arrays × 99 levels covering player/monster HP/ATK/DEF/AGL/DMG/SP/HEAL at each power tier) is the backbone of the combat system. Rather than building a new V2 framework feature for tier-scaled stat generation, port the tables as static game data. These tables represent the Original author's game balance decisions — they are game content, not framework infrastructure.

- **GAP-06 is the largest framework gap:** The zone object system (chests with scripted callbacks, sconces with multi-state lighting puzzles, NPCs with level-gated behavior, doors with lock states) has no V2 equivalent. A full ZoneObjectBuilder DSL must be designed and implemented before any floor porting begins. This is a significant but well-bounded framework feature.

- **Priority ordering for framework fix plans:** FP-01 (tables.c) → FP-02 (Zone Object DSL) → FP-03 (encounter tables) are the 3 prerequisites that block the most porting plans. FP-04/FP-05/FP-06/FP-07/FP-08 can be done in waves alongside porting.

- **19 patterns confirmed NOT gaps:** The dungeon exploration preset, torch gauge, magic key counter, zone transitions, save system, global flags, behavior trees, simpleBattle, status effects, abilities, dialog/HUD, GBC palettes, scene navigation, and input APIs are all fully supported — these cover the majority of LotD's game logic.
