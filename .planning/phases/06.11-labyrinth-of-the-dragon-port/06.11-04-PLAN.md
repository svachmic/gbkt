  <action>
Implement auto-padding as a framework feature in the PO string processing pipeline.

**Requirements (from CONTEXT.md):**
- PO msgstr values should be clean (no trailing spaces)
- Framework auto-pads strings to fixed width based on msgctxt namespace
- Different widths per context: ability names = 13 chars, item short names = 6 chars, etc.
- Width configuration must be extensible (game specifies padding rules, not hardcoded per LotD)

**Design:**

1. **Padding configuration** — Create a `PaddingConfig` data class or DSL:
   ```kotlin
   // In localization configuration
   localization {
       padding {
           context("ability") { width(13) }
           context("misc_item_short") { width(6) }
       }
   }
   ```
   Or simpler: a `Map<String, Int>` mapping msgctxt prefixes to target widths.

2. **Processing integration** — Find the existing PO file parser (in gbkt-core or gbkt-backend-gbdk localization pipeline). Add a post-processing step that pads msgstr values according to the configuration.

3. **Padding behavior:**
   - Right-pad with spaces to reach target width
   - If string already meets or exceeds width, do NOT truncate (warn instead)
   - Only pad entries whose msgctxt matches a configured context
   - Entries without a matching context are left unchanged

4. **Use Serena** to find the existing PO parser:
   - `mcp__serena__search_for_pattern` for "msgctxt", "msgstr", "PoParser", "po.*parse"
   - `mcp__serena__find_symbol` for any LocalizationConfig or StringsConfig classes

5. **Tests:** Create tests that verify:
   - A string shorter than width gets padded: "Fire" → "Fire         " (13 chars)
   - A string at width stays unchanged: "Melee Attack!" (13 chars exactly)
   - A string longer than width is NOT truncated but generates a warning
   - Entries without matching context are unmodified
  </action>

Add locale selection support to the Gradle plugin for building language-specific ROMs.

**Requirements (from CONTEXT.md):**
- Compile-time language flag: build separate ROMs per language
- `labyrinth_en.gb` and `labyrinth_cs.gb` as separate outputs
- No runtime language switching

**Implementation:**

1. **GbktExtension property** — Add `locale` property:
   ```kotlin
   // In GbktExtension
   val locale: Property<String> = objects.property(String::class.java).convention("en")
   ```

2. **Gradle project property** — Read from `-Pgbkt.locale=cs`:
   ```kotlin
   // In plugin apply()
   val localeFromProp = project.findProperty("gbkt.locale") as? String
   if (localeFromProp != null) extension.locale.set(localeFromProp)
   ```

3. **PO file selection** — In the localization pipeline task, select `res/strings/{locale}.po` based on the locale property instead of hardcoded `en.po`.

4. **Output naming** — When locale is set and outputName contains no locale suffix, auto-append: `labyrinth` → `labyrinth_en` or `labyrinth_cs`.

5. **Use Serena** to find:
   - `GbktExtension` class and its existing properties
   - The task that processes PO files
   - The task that sets output ROM filename

6. **Do NOT** add multi-variant builds (building both en and cs in one `./gradlew buildRom` invocation). That's a future enhancement. Each invocation builds one locale.
