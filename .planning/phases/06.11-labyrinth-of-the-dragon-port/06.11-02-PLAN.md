  <action>
Systematically examine each Original C pattern category and verify V2 framework support. For each category, read the Original C source and then check the V2 DSL/IR/codegen for equivalent support.

**Categories to audit (from RESEARCH.md potential gaps):**

1. **Chest scripted callbacks** — Original `floor*.c` has `chests[]` arrays with function pointer callbacks (`chest_add_torch`, `chest_add_magic_key`). Check if V2 `zone.onInteract {}` can express per-chest typed callbacks with flag gating, item granting, and custom logic.

2. **Exit condition gates** — Original `exits[]` have bidirectional tile transitions. Some are gated by flags (boss door). Check if V2 zone transitions support conditional blocking via flag state.

3. **Progressive encounter tables** — Original encounter tables are level-gated (same floor shows different monsters at different levels). Check if V2 `zone.encounters { entry() }` supports level/flag-weighted entries or conditional groups.

4. **Object interaction types** — Original `objects[]` distinguishes sign/lever/sconce/chest by type with different interaction logic. Check if V2 `tryInteractWithObject` can differentiate object types.

5. **Multi-monster encounters** — Original encounters can have 1-3 monsters per battle. Check if `simpleBattle()` supports multiple simultaneous enemies.

6. **Class-based ability learning** — Original characters unlock abilities at specific levels. Check if V2 character DSL supports level-gated ability lists.

7. **Monster AI special attacks** — Original monsters have conditional AI (deathknight revives, beholder multi-attack, will-o-wisp phasing). Check if `MonsterBuilder.ai {}` supports these patterns.

8. **Combat state typed refs** — Audit all combat state strings (COMBAT_STATE_VICTORY, etc.). Check if `CombatEngineSystem` exposes typed refs or requires raw strings.

9. **Flag typed access** — Audit `flags.getFlag("name")` pattern. Check if V2 provides `FlagRef` typed references that eliminate string literals.

10. **Window-layer text system** — Original `text_writer.c` has character-by-character animation. Check if V2 dialog system supports this or is instant-display only.

11. **PO auto-padding** — Verify the auto-padding feature does NOT exist anywhere in codebase (confirmed in research, but double-check).

12. **Compile-time locale flag** — Verify `GbktExtension` has no locale property (confirmed in research, but double-check).

13. **Node.js build tools coverage** — Original uses `tools/` scripts (png2bin, color2bin, colorhex2c, strings2c, tables2c, hash.js, common.js) to generate C from assets at build time. Verify V2 Gradle plugin pipeline covers ALL of this functionality. Check each tool's purpose and map to V2 equivalent. Flag any tools with no V2 coverage.

14. **tables.c level-scaled data tables** — Original `tables.c` (~8KB, auto-generated by tables2c from `data/tables.csv`) contains: `exp_by_level[99]`, `monster_exp[4][99]` (per tier), `agl[4][99]` stat growth tables. Verify whether V2's RPG framework generates equivalent data from DSL definitions (e.g., `expCurve = ExpCurve.STANDARD`) or if these tables must be ported as explicit game data. If the V2 framework does NOT auto-generate, this is a BLOCKING gap.

**For each gap, document:**
- Gap ID (e.g., GAP-CHEST-CALLBACK)
- Severity: BLOCKING (prevents porting), DEGRADING (can work around but loses fidelity), COSMETIC
- Original C pattern (with file:line reference)
- V2 current status (supported / partial / missing)
- Recommended fix approach
- Affected porting plans (which game content needs this)

**Use Serena MCP tools** to inspect V2 API surfaces:
- `mcp__serena__get_symbols_overview` on ZoneBuilder.kt, CombatEngineSystem, MonsterBuilder.kt, etc.
- `mcp__serena__find_symbol` for specific methods like `encounters`, `onInteract`, `ai`
- `mcp__serena__search_for_pattern` for combat state string patterns

Write the complete audit to `06.11-GAP-AUDIT.md`.
