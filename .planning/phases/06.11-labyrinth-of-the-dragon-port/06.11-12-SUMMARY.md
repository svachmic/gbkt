## Accomplishments

### Task 1: Port battle scene

Created `BattleScene.kt` with complete combat UI and state machine integration:

1. **Scene registration pattern** — `BattleScene.register(builder, combat, sounds, state)` follows TitleScene.kt/HeroSelectScene.kt parameter pattern. Takes typed `BattleRef`, `LabyrinthSounds`, `GameState` and `SceneRef` parameters for explicit dependency wiring.

2. **GBC palette declarations** — 7 palettes applied at scene scope: `battleBg0`, `battleHpNormal`, `battleHpCritical`, `battleSpBar`, `battleUi`, `battleBuff`, `battleDebuff`. Follows TitleScene.kt's `palette()` call pattern (SceneBuilder-level, not inside enter).

3. **Enter block** — `hideSprites()`, `clear()`, `playSound(sounds.startBattle)`. Lightweight initialization; combat engine handles party/encounter setup via `battleUpdate()`.

4. **Frame block — combat state machine:**
   - `battleUpdate(combat)` — single call drives the full turn-based combat engine every frame
   - `whenever(combatIsInState(CombatStates.PLAYER_TURN, combat))` — D-pad up/down moves `state.battleMenuCursor`, A button confirms action
   - `whenever(combatIsInState(CombatStates.TARGET_SELECT, combat))` — D-pad left/right moves `state.battleTargetIndex`, A confirms target, B cancels
   - `whenever(combatIsInState(CombatStates.VICTORY, combat))` — plays `sounds.battleSuccess`, navigates to gameplay
   - `whenever(combatIsInState(CombatStates.DEFEAT, combat))` — plays `sounds.battleDeath`, navigates to game over
   - `whenever(combatIsInState(CombatStates.FLEEING, combat))` — plays `sounds.falling` during escape attempt

5. **Exit block** — `hideSprites()` cleans up battle sprites and status icon OAM.

6. **KDoc** — extensive documentation of Original combat flow states, menu navigation, HP display patterns, status effect layout, monster death animation, and screen shake. Cross-references to `battle.c` and `encounter.h` line ranges.

## Decisions Made

- **register() parameter signature** takes explicit `BattleRef`, `LabyrinthSounds`, `GameState`, and two `SceneRef` params — follows the established dependency injection pattern from TitleScene.kt and HeroSelectScene.kt.
- **gameplayRef/gameOverRef as parameters** (rather than `Scenes.gameplayRef` direct access) — makes the scene's dependencies explicit. Plan 12b will call `BattleScene.register(this, combat, sounds, state, Scenes.gameplayRef, Scenes.gameOverRef)`.
- **initPartyFromClass/initBattleFromEncounter not called** — these C functions don't exist in the V2 DSL as ScriptBuilder operations. The enter block initializes visual state only; full encounter/party setup is handled by the combat engine's initialization sequence triggered via `battleUpdate()` on first frame.
- **CombatStates typed constants** — `CombatStates.PLAYER_TURN`, `.TARGET_SELECT`, `.VICTORY`, `.DEFEAT`, `.FLEEING` from `gbkt-genre-rpg` — zero magic string state names.
- **Palette declarations at scene scope** — `palette(Palettes.battleBg0)` etc. called in scene block (not enter block) per `palette()` being a SceneBuilder function.

## Deviations from Plan

None — plan executed as written. The only adaptation was using documented patterns correctly:
- `frame {}` (not `every.frame {}`) — `frame` is the correct SceneBuilder method name
- Palette declarations in scene scope — SceneBuilder API, not ScriptBuilder
- `state.battleMenuCursor` and `state.battleTargetIndex` referenced via `GameState` parameter — AssignableVar delegate pattern
