**Flag variable naming convention (CONFIRMED):**
The C variable name is `_flag_{flagName}` where `flagName` is the raw flag name from `FlagPageIR.flags`.
The page name (`FlagPageIR.name`) is NOT included in the variable name — it is only used for SRAM byte grouping.
Evidence: `setFlag(flagName)` emits `Assign("_flag_$flagName", ...)` in ScriptBuilder.kt line 613.
All visitor code (`GBDKSystemVisitor`, `RpgVisitor`) uses `_flag_${flagId}` where flagId is the raw flag name.

**map_textbox origin (CONFIRMED):**
`callOp("map_textbox", StringLiteral("str_key"))` in floor DSL emits `map_textbox(str_key);` via ScriptOpVisitor.visitCallOp() (line 973) which produces CCall(op.function, op.args). No visitor defines this function — it is a raw C call with no corresponding generated definition.
In the Original C, `map_textbox` is an inline function in map.h that sets `map_state = MAP_STATE_TEXTBOX_OPEN` and `textbox_message = text`. The V2 codegen must generate an equivalent helper.

**NPC boss trigger functions (CONFIRMED):**
`callOp("start_mini_boss_f8", ...)` etc. in Floor8DragonLair.kt emit raw C function calls. These function names do NOT exist in the Original C — they are port-specific helpers. The callOp mechanism produces `CCall(op.function, op.args)` which emits a bare function call. The pipeline must generate matching function definitions OR the port must use a different DSL pattern (e.g., inline the battle setup in onTalk handlers).

C AST types needed:
- CVarDecl(name, type, initializer, isConst=false) — global variable
- CDefine(name, value) — #define constant
- CU8, CU16, CArray(elementType, size) — types
- CLiteral(value) — integer literal
