**128-tile ASCII font extended to 142 tiles with Czech diacritics (ě š č ř ž ý á í é ú ů ď ť ň); generic FontCharacterMapping class encodes diacritic strings to tile byte sequences for C codegen**

## Accomplishments
- Extended font.png from 128x64 (128 tiles) to 128x72 (144 tiles) with 14 Czech diacritic tiles appended
- Each diacritic tile visually matches the Original font: same 8x8 grid, same stroke weight, mark in rows 0-1 with glyph body in rows 3-7
- Created `FontCharacterMapping` in `gbkt-core` — generic framework class (not LotD-specific) mapping `Char → tileIndex`
- Czech factory maps all 14 diacritics to tiles 128-141 with correct hex encoding (ě→`\x80`, š→`\x81`, ..., ň→`\x8D`)
- 37 tests covering: all 14 Czech chars, ASCII passthrough, unmapped char warnings, generic design, tile uniqueness

## Decisions Made
- **FONT_OFFSET recommendation:** Use `FONT_OFFSET = 0x72` (tile 114) for Czech locale builds so 142 font tiles fit without overflowing VRAM (256 - 114 = 142). English builds can keep `FONT_OFFSET = 0x80`.
- **font.png dimensions:** 128x72 px (144 tiles) rather than exactly 142 tiles because 16-per-row layout requires rows to be complete; tiles 142-143 are padding.
- **FontCharacterMapping location:** Placed in `gbkt-core` (not `gbkt-backend-gbdk`) so all games can use it without pulling in the backend module. The backend uses it when creating `CStringLiteral` values containing diacritics.
- **Diacritical mark placement:** Rows 0-1 for the mark (háček=inverted V, čárka=acute diagonal, kroužek=ring), row 2 as gap, rows 3-7 for letter body. For tall letters with ascenders (ď, ť), letter is shifted down 1px to make room for the mark in row 0.
- **Replacement tile:** Default replacement for unmapped characters is `0x3F` (the `?` tile) with a warning — no silent data corruption.
