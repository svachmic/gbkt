## Decisions Made

- **Sealed vs non-sealed ZoneObjectIR**: Used sealed because zone objects are a closed domain in one module; this enables exhaustive `when()` dispatch in codegen with compile-time safety
- **zone_check_edges vs inline in zone_transition**: The condition flag check goes in a separate auto-generated `zone_check_edges_()` function rather than in `zone_transition_()` — because `zone_transition` is a generic low-level function; the edge check is the high-level decision point
- **_player_level convention**: Used a convention-based `_player_level` global for encounter level range checks; ExplorationSystem has no party reference — developer must sync this variable to the party leader level
- **Accumulator always advances**: In encounter checks, `acc += entry.weight` runs even when level/flag gates prevent the entry from firing — preserving correct weight distribution across entries
