# Phase 06.11 Plan 09: Combat System Configuration Summary

**simpleBattle("combat") configured with 4 character classes, 12 monsters, and 27 weighted encounter groups ported from Original's battle.c/encounter tables**

## What Was Built

### `CombatSystem.kt`

Complete combat system configuration for Labyrinth of the Dragon. The file defines:

1. **`LabyrinthCombatSystem` data class** — typed holder for the `BattleRef` returned by `simpleBattle("combat")`, passed to battle scene plans for zero-string combat system access.

2. **`GameBuilder.registerCombat()` extension** — takes `LabyrinthCharacters` and `Monsters` typed parameters and configures:
   - `party()` for all 4 character classes (druid/fighter/monk/sorcerer)
   - 29 `encounter {}` groups across all 4 floor tiers
   - `onVictory {}` and `onDefeat {}` (empty — navigation delegated to battle scene plan)

3. **29 encounter groups** weighted by floor tier:
   - **Common (floors 1-2):** kobold/goblin/zombie single + multi-monster groups (weight 8-30)
   - **Uncommon (floors 3-4):** bugbear/owlbear/gelatinous cube groups (weight 7-20)
   - **Rare (floors 5-6):** displacer beast/will-o-wisp/deathknight groups (weight 5-12)
   - **Boss/Elite (floors 7-8):** mindflayer/beholder/dragon with BOSS tier (weight 2-5)

4. **Comprehensive KDoc** documenting Original combat mechanics:
   - Battle state machine flow (battle.h BattleState enum)
   - Damage formulas (`calc_damage(d16_roll, base_dmg)` from stats.c line 80)
   - Status effect turn tick (poison_hp, regen_hp, paralyzed_roll, etc.)
   - AGL-based escape mechanic (`roll_flee()` from stats.c line 107)
   - Item usage in combat (POTION/ETHER/REMEDY/ELIXIR effects)

## Deviations from Plan

### Auto-adapted: Plan Template Uses Non-Existent DSL Methods

**Found during:** Task 1 — reading SimpleBattleBuilder.kt source

**Issue:** The plan template showed `maxPartySize()`, `maxEnemies()`, `turnOrder(TurnOrderStrategy.SPEED_BASED)`, `onState(CombatState.VICTORY) { awardExp(); awardDrops() }`, and `onTurnStart {}` methods that do not exist in `SimpleBattleBuilder`. Additionally, `awardExp()` and `awardDrops()` are only template strings in the IntelliJ plugin — not actual DSL functions. `CombatState` is `CombatStates` (object with `CombatStateId` properties).

**Fix:** Implemented using only the actual available DSL methods (`party()`, `encounter()`, `onVictory()`, `onDefeat()`). Combat mechanics that the plan intended to configure (turn order, party size, status ticks) are handled by the V2 combat engine runtime — they are documented in KDoc rather than re-declared in DSL config.

**Files modified:** `CombatSystem.kt` (design adjusted — no deviations from available API)

**Classification:** [Rule 1 - Bug] Wrong DSL usage in plan template. Fixed automatically by using actual available API.
