## Files Created/Modified

- `LabyrinthOfTheDragon-port/src/main/kotlin/io/github/gbkt/examples/labyrinth/rpg/Monsters.kt` — 12 monster definitions with stats, tier, exp, AI behavior trees; `Monsters` data class; `GameBuilder.registerMonsters()` extension

## Decisions Made

- `registerMonsters()` is a `GameBuilder` extension (not standalone `object`) because `monster()` DSL requires `GameBuilder` context to register `GenericSystem` IR nodes — calling outside game block would be impossible
- `Monsters` data class returned as holder for typed `MonsterDef` references — encounter tables use `+monsters.kobold` without raw string IDs
- Stats use flat baseline values from `tables.c` stat arrays at typical encounter level per tier, not the Original's dynamic `get_monster_hp(level, tier)` formula — DSL uses fixed stats
- `ELITE` tier from Original (mind flayer on floor 7) maps to `BOSS` in DSL `MonsterTier` — only COMMON/UNCOMMON/RARE/BOSS available
- `Deathknight` mapped to `RARE` (floors 5-7) per Original `CLAUDE.md` tier table
- Sprite references omitted: `MonsterBuilder` has no `sprite()` method in current DSL

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing DSL Capability] Sprite references not possible in MonsterBuilder**
- **Found during:** Task 1
- **Issue:** Plan spec requires `sprite()` with `asset()` reference for each monster, but `MonsterBuilder` DSL has no `sprite()` method — the builder only supports `name()`, `tier()`, `stats()`, `exp()`, `ai()`, `drops()`, `cooldown()`, `role()`, etc.
- **Fix:** Omitted sprite references from monster definitions. Added note in KDoc header that MonsterBuilder has no sprite() in current DSL. Sprite-to-monster association would require a separate `SpriteRegistry` or extension to `MonsterDef`.
- **Files modified:** Monsters.kt (omission — no sprite blocks)
- **Verification:** Compile passes without sprite() calls
- **Committed in:** `962c009`
