**RpgExtensions.kt** — Extension functions on GameBuilder:
```kotlin
// These are the user-facing DSL entry points.
// They extend GameBuilder (from gbkt-core dsl/v2) with RPG constructs.

fun GameBuilder.character(id: String, block: CharacterBuilder.() -> Unit): CharacterDef {
    val builder = CharacterBuilder(id)
    builder.block()
    val def = builder.build()
    // Store in a registry accessible from other RPG builders
    rpgRegistry.registerCharacter(def)
    return def
}

fun GameBuilder.monster(id: String, block: MonsterBuilder.() -> Unit): MonsterDef {
    val builder = MonsterBuilder(id)
    builder.block()
    val def = builder.build()
    rpgRegistry.registerMonster(def)
    return def
}

fun GameBuilder.simpleBattle(id: String, block: SimpleBattleBuilder.() -> Unit) {
    val builder = SimpleBattleBuilder(id, scriptBuilderFactory = { ScriptBuilder(/* ... */) })
    builder.block()
    val battleDef = builder.build()

    // Produce a core SystemIR.GenericSystem — NOT a new sealed IR subtype
    val config = mapOf(
        "type" to "simple_battle",
        "partyIds" to battleDef.partyIds,
        "encounterData" to battleDef.encounters,
        "onVictoryOps" to battleDef.onVictoryOps,
        "onDefeatOps" to battleDef.onDefeatOps
    )
    registerSystem(SystemIR.GenericSystem(id = id, config = config))
}
```

**RpgRegistry** — Internal helper for tracking RPG definitions during DSL execution:
- `class RpgRegistry` with `registerCharacter(def)`, `registerMonster(def)`, `getCharacter(id)`, `getMonster(id)`
- Stored as an extension property or companion-level registry on GameBuilder (use a thread-local or WeakHashMap pattern similar to how GameBuilder's RefRegistry works)
- Alternatively, store directly as a property map on GameBuilder if it supports extension data (check the actual GameBuilder API from Plan 01-02). If GameBuilder does not have a generic extension mechanism, use a companion-object-level `ThreadLocal<RpgRegistry>` that is initialized when the first RPG extension function is called and cleared when `build()` completes.
