## Decisions Made

- **Verbatim mirror of frame-splice helpers, no abstraction.** Considered factoring `(collect*Ops, add*Ops)` into a generic phase-aware splice helper (e.g. `addGenrePhaseOps(functions, sceneId, phase, ops)` where `phase ∈ {ENTER, FRAME, EXIT}`). Rejected: only 2 phases exist today, the named-helper pair is more discoverable in IDE call-hierarchy navigation, and the structural mirror is itself a soft contract — readers can compare frame and enter splices side-by-side without chasing an abstraction.
- **`addGenreEnterOps` runs BEFORE `addTilesetGuardToEnterFunction` in `buildSceneFile`.** Both helpers prepend to the same `<sceneId>_enter` body via `fn.copy(body = statements + fn.body)`. Call order determines final head position. Choosing genre→guard yields final body `[guard, genre, user]` — the guard's `if (_current_tileset_id != TILESET_ID_<scene>)` runs first so the right tileset is active when the genre's tileset/tilemap DMA runs, and user enter ops run last with all setup complete. The alternative (guard→genre yielding `[genre, guard, user]`) would run pool spawn / zone DMA against a possibly-wrong tileset on cross-scene transitions.
- **Test uses reflection on the private helper, not a fixture GenreSystemVisitor.** ServiceLoader registration is global per JVM — a fixture visitor registered via `META-INF/services/io.github.gbkt.backend.api.GenreSystemVisitor` would leak across the test classpath and contaminate sibling tests (e.g. `PongPipelineTest`). Reflection on the private helper is isolated and exercises the exact splice contract the pipeline relies on. The `collectGenreEnterOps` helper is a verbatim mirror of `collectGenreFrameOps` and inherits its proven correctness — its ServiceLoader walk is identical apart from the field name read.
