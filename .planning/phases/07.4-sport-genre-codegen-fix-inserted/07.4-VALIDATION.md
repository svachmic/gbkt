## Validation Tiers (Nyquist)

Three tiers, in order of cost. Every Success Criterion and every D-XX decision
must be claimed by at least one tier.

### Tier 1 — JVM codegen tests (cheapest, fastest)

Modules: `gbkt-genre-sport/src/test/`, `gbkt-backend-gbdk/src/test/`.

Asserts on the generated C output of a synthesized racing() phase:

- `RacingTickEmissionTest` — `race_frame()` calls `racing_tick_<id>()` once per
  frame and `racing_tick_<id>()` calls `update_camera_<id>()` (covers SC #3 + D-06).
- `RacingMovementMathTest` — `racing_tick_<id>()` integrates throttle/friction/
  handling against per-vehicle state (`_vehicle_<id>_vx/vy/heading`); higher
  speed stat → strictly larger position delta on the same frame budget
  (covers SC #2 + D-07/D-09).
- `RacingPolygonRasterTest` — synthesized `_zone_<id>_tiles[]` is non-trivial
  (>0 drivable bytes, >0 wall bytes), enclosed corridor matches polygon, dims
  match `mapWidth × mapHeight` (covers SC #4 + D-10/D-11/D-17 enclosure invariant).
- `RacingPoolSynthesisTest` — `aiOpponents(carAi, count = N)` synthesizes an
  ActorPoolIR with N instances; pool id == vehicle property name; OAM allocator
  patterns from 07.3 are present (covers SC #1 + D-13/D-14).
- `RacingLapBitmapTest` — `racing_check_finish_<id>()` uses an in-order visited
  bitmap and refuses to advance lap on out-of-order checkpoint touches; lap
  increments only on first-checkpoint crossing AFTER the bitmap is full (covers
  SC #5 + D-15/D-16/D-17).
- `RacingGenericContractTest` — declare→synthesize→spawn AI→move player→complete
  lap on a fixture racing() call independent of `Racer.kt`. Validates the engine
  contract holds for any racing/sport game (covers D-02/D-09 reusability + D-18 item 2).
- `RacingNoMagicStringsTest` — for a fixture using `val track1 by racing { … }`,
  every emitted C symbol containing the track id uses `track1` (covers D-04).
- **`GenreVisitorResultTest` (revision 2 / Plan 09)** — locks the additive
  `enterOps` field on the API surface (covers GAP-A/B/D wiring half).
- **`GenreEnterOpsSpliceTest` (revision 2 / Plan 10)** — locks the
  `addGenreEnterOps` prepend semantics in GBDKPipelineV2 (covers GAP-A/B/D
  pipeline half).
- **`RacingEnterOpsEmissionTest` (revision 2 / Plan 11)** — asserts SportVisitor
  emits pool-spawn / set_bkg_data + set_bkg_tiles / `_camera_target` ops into
  `enterOps` (covers GAP-A, GAP-B, GAP-D at codegen tier).
- **`RacingCollisionGuardTest` (revision 2 / Plan 12)** — asserts the wall
  collision + INT16 bounds guard wraps both player and AI position write-back
  (covers GAP-C at codegen tier; D-09 same-physics-path invariant preserved).

### Tier 3 — MCP play-through (end-to-end runtime evidence)

Module: `gbkt-examples/racer/`.

Driven by the agent through the `gbkt-emulator` MCP server. Re-runs
`UAT-racer.md` (the failure baseline) and flips it from `status: failed` to
`status: passed`. Goldens captured 2026-05-07 are torn up and regenerated.

Required playbook checkpoints (covered by D-19, all six Success Criteria):

1. `emulator_start gbkt-examples/racer/build/gbkt/output/racer.gb`
2. `emulator_wait_for_scene "race"` — confirms enter scene (SC #6)
3. `emulator_screenshot` — visible track tilemap on BG layer (SC #4)
4. `emulator_assert "rival actor visible"` — AI car renders via pool (SC #1)
5. `emulator_press dpad.right held=N` then `emulator_read_variable
   "_camera_x"` over time — camera scrolls with player (SC #3)
6. `emulator_read_variable "_vehicle_carPlayer_vx"` shows ramp-up while held
   then friction decay on release — stats drive movement (SC #2)
7. `emulator_step` until lap 1 complete — confirm `_racing_lap_track1 == 1`
   only after the in-order bitmap completed (SC #5)
8. **Negative test:** ping-pong oscillation across the start/finish line — must
   NOT increment lap counter (D-17 binding constraint, "a lap means a real lap")
9. Race ends after 3 laps — `_racing_lap_track1 == 3` and victory transition fires (SC #6)

The MCP playbook lives at `gbkt-examples/racer/PLAYBOOK.md` (rewritten in this
phase).
