# Phase 07.4 Plan 31: DialogVisitor Loop Counter Initialisation (DEFERRED-07.4-27-01 Closure)

**One-liner:** Closed DEFERRED-07.4-27-01 by initialising all 8 CVarDecl loop-counter call sites in DialogVisitor.kt from `null` to `CLiteral(0)`, backed by a 4-test JVM RED→GREEN gate.

## Objective

Fix the uninitialised loop counter bug in `_win_print_at`, `_win_clear_region`, `_win_fill_screen`, and `_vwf_print_at` helpers emitted by `DialogVisitor.kt`. The bug caused SDCC to place an uninitialised `UINT8` on the stack; the for-loop condition read stack garbage, producing wrong text rendering or partial clear regions on larger games. SDCC was "lucky" with stack slot 0 on small fixtures — real undefined behaviour.

## Remaining Deferred Work

**`_win_clear_region` inner-loop rx-reset bug (still DEFERRED):** The inner `for` loop in `_win_clear_region` never resets `rx` to 0 between outer iterations. This means after the first row is cleared, `rx` stays at `w` for all subsequent rows — only one row is actually cleared on repeated calls. This requires a structural change (adding a `CExprStatement(CBinaryExpr(CVar("rx"), "=", CLiteral(0)))` inside the outer loop body before the inner loop), not a one-line initializer change. Out of scope for Plan 31 per the STRIDE threat register T-07.4-31-02 (disposition: accept). Filed in `deferred-items.md`.
