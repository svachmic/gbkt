## Decisions Made

- **VRAM read surface for the runtime probe.** The runtime tilemap value lives in three places at race_enter+30: (1) const ROM array at absolute address 0x24000 (would need bank switching via emulator MBC state), (2) RAM-shadow of the array if the codegen copies it, or (3) VRAM BG tile-map at 0x9800 + y * 32 + x where `set_bkg_tiles` actually writes. Chose (3) because it is exactly what the LCD reads when rendering — zero indirection between the assertion and the rendered shape. Confirmed by the boot sequence Round6WramCorruptionProbe uses and the `readMemory` API on `StepAgent`.
- **Inline expected grid duplicated across two test fixtures + one evidence file.** The expected 19x19 corridor lives in three places: the Kotlin literal `expectedGridAscii` in `TrackSynthesizerCircuitShapeTest.kt`, the identical literal in `Round8TrackTilemapShapeProbe.kt`, and the ASCII art in `07-expected-circuit-tilemap-ascii-art.txt`. Two test fixtures keep each tier independent; the evidence file is the reviewer-readable single source-of-truth. Drift is structurally controlled by tracked-evidence review (any change to the contract requires editing all three).
- **MAX_MISMATCH_FOR_PASS = 18 (~5% of 361 cells).** Tight enough to fail decisively against the HEAD baseline (mismatch=55) but loose enough to allow Plan 35 latitude on corridor-width edge cells (1-tile shifts on the polygon perimeter). Identical threshold at both tiers so the JVM and runtime contracts move in lockstep.
- **Bug-surface diagnosis recorded but no production change.** The runtime VRAM matches the JVM synthesizer output byte-for-byte. This is a load-bearing finding for Plan 35: the entire fix surface is in `TrackSynthesizer.kt`'s `scanlineFill` + `composeTiles` passes. Recorded in this SUMMARY's accomplishments + commit-3 message for Plan 35 to consume — but Plan 33 made no production change. The diagnostic comes for free from the two RED probes producing the same mismatch count.

Solution: read VRAM (post-`set_bkg_tiles` copy) instead of the source array. VRAM is the rendered surface, so this is actually a stricter read than reading the source array would be.
