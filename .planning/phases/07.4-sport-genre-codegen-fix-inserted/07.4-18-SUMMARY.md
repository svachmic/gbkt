# Phase 07.4 Plan 18: 4-Corner Wall-Collision Sample Summary

4-corner OR-accept wall-collision guard replaces single-center tile sample in `buildPositionWriteBackWithCollision`, closing the NAVIGABILITY-PLAYER-CORNER-TRAP gap identified in Plan 14 UAT evidence.

## What Was Built

`SportVisitor.buildFourCornerWallSampleAccept` — new `internal` helper that emits an inline C expression checking all four pixel corners of a sprite's bounding box (NW, NE, SW, SE) against the zone tile array. A move is accepted iff at least one corner lands on a non-WALL tile within map bounds. `buildPositionWriteBackWithCollision` was updated to call this helper for both player and AI write-backs (D-09 uniform physics path).

`RacingPlayerTraversabilityTest` — 4 `@Test` methods verifying corner-trap freedom and full-loop navigability at the JVM tier via a pure-Kotlin simulation of the emitted C semantics.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] RacingCollisionGuardTest assertions incompatible with 4-corner C shape**
- **Found during:** Task 2 (GREEN phase)
- **Issue:** `tick_body_rejects_wall_tile()` checked for named variable `tile != 0u`; `bounds_check_present()` checked for `tileCol`/`tileRow` variable names; `ai_body_uses_same_collision_guard()` expected >= 2 tile samples. All three assertions broke because the 4-corner helper emits inline expressions without named intermediaries.
- **Fix:** Updated assertions to check for `!= 0u` (inline comparison present), `>> 3)` (bit-shift for tile-coord present), and counts updated to >= 8 (4 corners x player + 4 corners x AI). Updated KDoc in the test to explain Plan 07.4-18 change.
- **Files modified:** `gbkt-genre-sport/src/test/kotlin/io/github/gbkt/genre/sport/codegen/RacingCollisionGuardTest.kt`
- **Commit:** af930533

**2. [Rule 1 - Bug] Test sequences from plan geometrically incorrect for racer fixture topology**
- **Found during:** Task 2 (GREEN phase, first pass)
- **Issue:** The plan specified test sequences (e.g., UP×30 + LEFT×30 + DOWN×30) that did not produce the expected corner-trap or full-loop results because the racer fixture has GRASS (tile 2, drivable) in the center, not walls. The corridor runs around the perimeter only; spawn at (80,80) is in the center grass. `UP×30` from (80,80) stops near y=26 (hits perimeter wall), and subsequent LEFT, DOWN, RIGHT sequences did not thread the corridor correctly at the frame counts from the plan text.
- **Fix:** Empirically derived correct frame counts via a debug simulation tool (`TrackDebugTest.kt`, deleted before final commit). Redesigned all 4 tests with calibrated sequences that are clearly RED with single-center sampling and clearly GREEN with 4-corner sampling. Key insight: RIGHT×14 (not RIGHT×60) keeps the player in the right corridor at cols 13-14, allowing DOWN×15 to reach CP-2 territory.
- **Files modified:** `gbkt-genre-sport/src/test/kotlin/io/github/gbkt/genre/sport/codegen/RacingPlayerTraversabilityTest.kt`
- **Commit:** e45519a3
