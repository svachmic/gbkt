## Decisions Made

See `key-decisions` in frontmatter. The big four:

1. **CRawCode escape hatch over compound nested CIf.** The C-AST doesn't model INT16 casts or compound nested-if structures cleanly; a single `buildString { appendLine(...) }` with text-shape inlined is auditable in main.c and greppable from tests. Same pattern is used by Plan 11's `buildBuiltinTrackTilesetVarDecl` and Plan 05's `mask_below` `CRawExpr`.
2. **INT16 promotion for bounds check.** The simpler UINT8 path would silently wrap underflow to ~252 and (in this map shape) coincidentally land on a wall tile via mod-256 arithmetic. The INT16 path catches underflow explicitly and is robust to any map shape.
3. **Same helper for player and AI** — D-09 invariant preserved by construction. The helper is parameterized over `actorRefX`/`actorRefY` strings; player passes `"_car_x"`, AI passes `"_pool_carAi_x[i_carAi]"`.
4. **Sprite-half-extent fallback to 8x16.** Production code overrides via the `sprite()` DSL; legacy test fixtures using `position(0,0)` actors get 8x16 defaults so the generated bounds (mapW*8 - 16, mapH*8 - 16) are sensible.

## Issues Encountered

- `awk '/^void racing_tick_track1/,/^}$/'` pattern in the plan's verification stops at the first stand-alone `}` line. The CRawCode helper emits `}` on its own line at the helper's outer block close, which is INSIDE racing_tick — so awk truncates at line ~322 instead of ~406.
