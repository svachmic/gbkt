## Decisions Made

- **Asserting at the emitted-text layer, not just the AST** — see `key-decisions[0]`. The plan's `<behavior>` for Task 1 described an AST-shape assertion (`CCast.expr must be a CTernary instance`). Code inspection showed the AST at HEAD is already shaped correctly. The actual bug lives in `CEmitter.kt:430` where the cast is rendered as `(UINT8)<expr>` with no outer parentheses around the inner ternary. The test was adapted to assert against the emitted C text (where the contract is actually violated), with an additional AST-tier diagnostic kept in place to document the AST status — preserving the spirit of the plan's two-tier contract. This is consistent with the precedent set by `CameraBoundsUnderflowTest` (Plan 07.4-21), which also asserts against `emitCameraBody`.
- **Variable name without underscore** — `VariableInspector.readNamed("car_y")` not `("_car_y")`; the inspector strips the C underscore prefix. Round6WramCorruptionProbe (the explicit precedent the plan referenced) demonstrates this.
- **Evidence file written before assertion** — runtime probe flushes evidence to disk before invoking the JUnit `assertTrue`, so the file lands even when the assertion (intentionally) fails.
