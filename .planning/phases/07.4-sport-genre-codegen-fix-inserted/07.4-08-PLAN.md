```kotlin
// the vehicle declares the racing stats (speed, acceleration, handling).
val car by actor {
    position(80, 80)
    sprite(asset("sprites/car.png")) { size(8, 16); hitbox(0, 0, 8, 16) }

val rival by actor {
    sprite(asset("sprites/rival.png")) { size(8, 16); hitbox(0, 0, 8, 16) }

val carPlayer by vehicle {
    actor(car)
    stats { speed(200); acceleration(160); handling(180) }
}
val carAi by vehicle {
    actor(rival)
    stats { speed(180); acceleration(150); handling(200) }
}

//  - a synthesized BG zone with id == property name (e.g., track1)

//  - per-frame physics tick (racing_tick_<id>) wired into the scene's frame block
val track1 by racing {
    laps(3)
    player(carPlayer)
    aiOpponents(carAi)
    track {
        waypoint(x = 5, y = 5, checkpoint = true)
        waypoint(x = 15, y = 5)
        waypoint(x = 15, y = 15, checkpoint = true)
        waypoint(x = 5, y = 15)
    }
}
```

```markdown
## Codegen Contract (Phase 07.4)

Every `racing { }` declaration generates the following C artifacts. All identifiers come from the property delegate name (Project Rule #1, D-04).

| Artifact | Generated by | Purpose |
|----------|--------------|---------|
| `racing_tick_<id>(void)` | SportVisitor.visitRacing | Per-frame loop: input → throttle/steer → speed_cur ramp → cardinal heading → delta = speed_cur >> 5 → vx/vy → write-back to bound actor → camera update → checkpoint advance → maybe-increment lap |
| `_vehicle_<playerId>_speed_cur` | SportVisitor varDecls | Player scalar speed (capped by stats.speed) |
| `_vehicle_<playerId>_heading` | SportVisitor varDecls | Cardinal: 0=N, 1=E, 2=S, 3=W |
| `_racing_visited_<id>` | SportVisitor varDecls | Bitmap; bit K = checkpoint K visited this lap |
| `_racing_lap_count_<id>` | SportVisitor varDecls | Player laps completed |
| `_racing_cp_x_<id>[]` / `_racing_cp_y_<id>[]` | SportVisitor varDecls | Checkpoint pixel coords (only `isCheckpoint = true` waypoints) |
| `_racing_wp_x_<id>[]` / `_racing_wp_y_<id>[]` | SportVisitor varDecls | Full waypoint loop coords (for AI pathing) |
| `_zone_<id>_tiles[]` | TrackSynthesizer + GBDKPipelineV2.buildZoneData | Polygon-to-tilemap synthesis: 0=wall, 1=drivable, 2=grass |
| `update_camera_camera(void)` | GBDKSystemVisitor.visitCameraSystem (consumed unchanged) | Bounded INT16 follow of bound player actor |
| `_pool_<aiId>_x[N]`, `_y[N]`, `_active[N]`, `_oam[N]` | ActorPool engine (07.3, consumed unchanged) | Per-instance AI position + active flag + OAM slot |
| `_pool_<aiId>_wp_idx[N]` | SportVisitor varDecls | Per-AI-instance next-waypoint index |
| `_pool_<aiId>_speed_cur[N]` / `_heading[N]` | SportVisitor varDecls | Per-AI-instance physics state (same math as player, D-09) |

### Lap Rule (D-15..D-17)

Lap completion uses an in-order checkpoint bitmap, not a wrap-around mod-N counter. The player must:

1. Touch checkpoint K only after touching all checkpoints 0..K-1 (in DSL declaration order). Out-of-order touches do NOT set the bit.
2. Lap completes when the player crosses checkpoint 0 again AFTER all checkpoint bits are set.

This makes ping-pong oscillation against a single edge structurally incapable of advancing the lap counter — D-17 "a lap means a real lap" is honored by construction.

### Engine Reusability (D-02)

No game-specific patterns. The codegen above works for any racing/sport game built on `racing { }`. The Racer example exercises every artifact; future games (rally, ball sports, tournaments) reuse the same engine without new visitor code.

See `.planning/phases/07.4-sport-genre-codegen-fix-inserted/07.4-CONTEXT.md` for the full D-01..D-19 decision log.
```
