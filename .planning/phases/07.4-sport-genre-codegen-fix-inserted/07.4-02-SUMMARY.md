## Accomplishments

- `Vehicle` data class added (id, actorRef: ActorRef, stats: VehicleStats). Wraps an `ActorRef` so codegen can resolve the bound on-screen actor without magic strings (D-04, D-05). Init block rejects blank id.
- `VehicleRef` data class added (id, actorId). Lightweight reference returned by the `vehicle { }` property delegate, parallel in shape to `ActorRef` and `ActorPoolRef`. Init block rejects blank id and blank actorId.
- `AiVehicleSlot` data class added (vehicleId, count). Models one `aiOpponents(carAi, count = N)` declaration (D-13); each slot maps to one `ActorPoolIR` at codegen time (D-14). Init block rejects blank vehicleId and `count < 1`.
- `RacingConfig.playerVehicleId: String? = null` field added — populated by the upcoming Plan 03 `RacingDelegate.provideDelegate` so codegen knows which vehicle the camera + physics tick + lap counter are wired to.
- `RacingConfig.aiVehicles: List<AiVehicleSlot> = emptyList()` field added — populated by `RacingBuilder.aiOpponents()` in Plan 03; one slot per call.
- `TrackDef.zoneId` relaxed to `String?` with default `null`. Plan 03's `RacingDelegate` will auto-derive the zone id from the racing() property name when the user doesn't supply one (D-04, D-12). Init block keeps the "if non-null, must not be blank" semantic so the existing `TrackDef(zoneId = "")` rejection test still passes.
- `VehicleDef` preserved with a doc note explaining it's the legacy domain type kept for `SportCodegenTest` / `SportDomainTest` / `SportBuildersTest` fixtures; Plan 03 will phase fixtures over to the new `Vehicle` at its own pace.
- `import io.github.gbkt.core.dsl.ActorRef` added at the top of the file. The `gbkt-core` aggregator re-exports `gbkt-lang` so this import resolves without changing `gbkt-genre-sport`'s direct deps.

## Decisions Made

1. **TrackDef.zoneId nullability relaxation preserves blank-rejection.** The init block changed from `require(zoneId.isNotBlank())` to `require(zoneId == null || zoneId.isNotBlank())`. This satisfies both the plan (allow null for auto-derive) and the existing `SportDomainTest` test that asserts `TrackDef(zoneId = "")` throws.
2. **VehicleDef preserved without `@Deprecated`.** Plan instruction allowed deprecation only "if it can stay compilable for SportCodegenTest.kt fixtures"; deprecation would cascade warnings through every fixture callsite. Cleaner to add a doc note explaining `VehicleDef` is the legacy type and `Vehicle` is the new path. Plan 03 owns the fixture migration timing.
3. **New types clustered after VehicleDef, before RacingAIConfig.** Keeps all vehicle-related declarations (legacy + new) together for readability; puts AiVehicleSlot adjacent to RacingAIConfig since both describe AI-side configuration.
