## Decisions Made

1. **Reading B (corridor erosion)** chosen over Reading A (filled polygon). Per RESEARCH.md A1, Reading B matches a real-world racing-game shape (closed loop) — the only one that makes lap-detection meaningful when the player is constrained to a corridor near the polygon boundary.
2. **Tile-index constants pinned at file scope** as `private const val TILE_WALL/DRIVABLE/GRASS`. SportVisitor (Plan 05) will reference the same numerical values; locking now avoids a magic-number drift later.
3. **Degenerate-polygon contract = throw IllegalArgumentException** per Plan 01 SUMMARY § Decision 1. The synthesizer is strict because RacingValidationPass (ANLZ-RACING-01) catches the same cases earlier; defense-in-depth, not silent fallback.
4. **`Math.floorDiv` for x-intersection arithmetic** — Kotlin's `/` truncates toward zero, which produces wrong floor values for negative dividends; `Math.floorDiv` yields true floor division. Polygon vertices in valid waypoint coordinates are non-negative today, but the algorithm must be correct across signs.
5. **Double-precision distance computation** — the cell center is at (x+0.5, y+0.5), so Int arithmetic would lose the half-pixel offset that makes corridor-width thresholds land on exact tile boundaries. Compile-time-only cost (~16K ops for max 32×32 map × 16 edges); negligible.
