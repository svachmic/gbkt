## Area 1 — Player–Car Binding & Camera Auto-Wire

### Round 1 (rejected — magic strings)

| Option | Description | Selected |
|--------|-------------|----------|
| Explicit binding via DSL (`vehicle("car_player") { actor(car) }`) | racing() reads bound ActorRef; auto-wires camera follow + input + lap checks | |
| Convention by id (`val car_player by actor { }` matched against `vehicle("car_player")`) | Codegen looks up actor by id == "car_player" | |
| racing() owns the actor (`vehicle("car_player") { sprite(...); position(...); stats { ... } }`) | racing() generates the actor; no separate `val car by actor { }` | |

**User's choice:** None — rejected all options.
**Notes:** "No magic strings" (Project Rule #1). All three options leaked string ids into the DSL. Re-asked.

### Round 2 (selected)

| Option | Description | Selected |
|--------|-------------|----------|
| Vehicle wraps an actor (`val car by actor { }; val carPlayer by vehicle { actor(car); stats { } }; val track1 by racing { player(carPlayer); aiOpponents(carAi); track { waypoint(...) } }`) | Vehicle wraps a separately-declared actor. All ids from delegates. racing() takes vehicle refs and auto-wires camera follow against the bound actor. | ✓ |
| Vehicle owns its actor (`val carPlayer by vehicle { sprite(...); position(...); stats { } }`) | Tighter DSL but loses ability to customize the actor with movement{}, animationStates{}, custom props | |
| Actor IS the vehicle (drop `vehicle { }`, add `vehicleStats { }` directly on actor) | Most concise; removes the vehicle domain type | |

**User's choice:** Vehicle wraps an actor (Recommended).
**Rationale captured in D-05:** Keeps the on-screen actor a separate, customizable entity. racing() takes vehicle refs, not actor refs. Camera follow auto-emitted from `player(carPlayer)` per D-06.
