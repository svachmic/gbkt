# Phase 07.4 Plan 17: TILESET-VISUAL-CONTRAST closure (Wave 14) Summary

**One-liner:** SportVisitor's 48-byte builtin track tileset is now derived from 3 logical 8x8 palette-index matrices via a new `tilePatternToBytes` helper; tiles render as solid black wall, solid light-gray road, and dark-gray/white checkerboard grass — pairwise distinct in byte sequence with visible texture on GRASS. 11 lock tests in RacingTilesetContrastTest GREEN.

## What was built

### Change A — `tilePatternToBytes` helper (new)

`SportVisitor` now declares an `internal fun tilePatternToBytes(matrix: List<List<Int>>): List<Int>` that converts an 8x8 palette-index matrix (cells in 0..3) to 16 GBDK 2bpp interleaved bytes per the Game Boy programming reference:

- For row r in 0..7: `byte[2r]` holds the LOW bit of each pixel in that row; `byte[2r+1]` holds the HIGH bit.
- Pixel at (col, row) occupies bit (7-col) of each byte (MSB = leftmost pixel).
- Combined: palette = (high_bit << 1) | low_bit.

Validation: `IllegalArgumentException` for non-8x8 input or any cell outside 0..3.

The helper makes the byte derivation auditable — instead of a hand-tuned 48-int literal, the 3-tile builtin is now generated from 3 visible logical matrices, and the helper itself is round-trip tested at JVM tier (solid-3, solid-1, solid-2 all verified).

### Change B — `builtinTrackTilesetBytes()` rewritten

`builtinTrackTilesetBytes()` is now `internal` (was `private`) and calls `tilePatternToBytes` three times to produce the 48-byte output:

```kotlin
internal fun builtinTrackTilesetBytes(): List<Int> {
    val wall = tilePatternToBytes(List(8) { List(8) { 3 } })
    val drivable = tilePatternToBytes(List(8) { List(8) { 1 } })
    val grass = tilePatternToBytes(
        List(8) { row -> List(8) { col -> if ((col + row) % 2 == 0) 2 else 0 } }
    )
    return wall + drivable + grass
}
```

The visibility bump from `private` to `internal` is the round-2 plan-checker WARNING 6 LOCKED decision: the helpers ARE the contract for the visual-contrast claim, so they get a tested visibility marker rather than a reflection escape hatch.

### Change C — RacingTilesetContrastTest (new file, 11 assertions)

`gbkt-genre-sport/src/test/kotlin/io/github/gbkt/genre/sport/codegen/RacingTilesetContrastTest.kt` (176 lines) calls the helpers directly via `SportVisitor()` and asserts:

| # | Test | What it locks |
|---|------|---------------|
| 1 | `wall tile is uniform palette 3` | Every decoded pixel of tile 0 has palette index 3. |
| 2 | `wall tile is solid 0xFF (regression-safe)` | All 16 bytes of tile 0 equal 0xFF (Plan 11 invariant). |
| 3 | `drivable tile is uniform palette 1` | Every decoded pixel of tile 1 has palette index 1. |
| 4 | `grass tile has visible texture (at least 2 distinct palette indices)` | Tile 2 has >= 2 distinct palette indices in its 64-pixel grid. |
| 5 | `three tile byte sequences are pairwise distinct` | wall != drivable, wall != grass, drivable != grass. |
| 6 | `total tileset is 48 bytes (Plan 11 invariant preserved)` | `builtinTrackTilesetBytes().size == 48`. |
| 7 | `tilePatternToBytes round-trip solid palette 3` | Returns 16 bytes of 0xFF. |
| 8 | `tilePatternToBytes round-trip solid palette 1` | Returns row pairs (0xFF, 0x00) x 8. |
| 9 | `tilePatternToBytes round-trip solid palette 2` | Returns row pairs (0x00, 0xFF) x 8. |
| 10 | `tilePatternToBytes validates 8x8 size` | 7x8 and 8x7 input both throw IllegalArgumentException. |
| 11 | `tilePatternToBytes validates palette range` | Cell value 4 throws IllegalArgumentException. |

A private `bytesToMatrix(bytes: List<Int>): List<List<Int>>` helper inverts the 2bpp encoding so per-tile pattern assertions can decode bytes back to a pixel matrix and inspect palette indices directly.

- The plan's example test method name `grass tile has visible texture (>= 2 distinct palette indices)` contained the literal `>` character which is illegal inside Kotlin backtick-quoted identifiers.
