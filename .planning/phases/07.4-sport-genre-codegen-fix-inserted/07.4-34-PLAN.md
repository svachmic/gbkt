<objective>
Close GAP-CAMERA-NO-FOLLOW by fixing the C-precedence bug in the camera-bounds clamp emission. The current visitor emits `CCast(CU8, clampX)` correctly in Kotlin AST form, but the emitted C is `_camera_x = (UINT8)(rawX < 0u) ? 0u : (rawX > 0u) ? 0u : rawX;` — the cast binds tighter than the ternary. The fix is to ensure parentheses surround the entire ternary at emission time.

Two possible fix surfaces (diagnose during Task 1):
1. **AST shape** — if `CCast.expr` is `CBinaryExpr` instead of `CTernary` (i.e., the Kotlin source is structured wrong), fix the visitor's expression construction so CCast wraps the OUTER CTernary node, not the inner comparison.
2. **Emitter shape** — if the AST is correct (CCast contains CTernary) but the emitter outputs `(TYPE)(comparison) ? ... : ...` without parentheses around the ternary, fix CEmitter to always parenthesise CCast's inner expression when that inner expression is a CTernary or CBinaryExpr.

The diagnosis: read GBDKSystemVisitor.kt line 184 — `CCast(CU8, clampX)` where `clampX` is a CTernary. So the AST IS correct. The bug is at emission time. Fix surface = CEmitter (or whatever node renders CCast). Confirm by walking the emitter and reading how CCast.expr is serialised.

Per D-N-05 the fix lives in gbkt-backend-gbdk (visitor or emitter layer); reusable across all CameraSystem consumers (Explorer, Dungeon, RPG-Lite — every game with bounded camera follow inherits the fix).
</objective>
