## Accomplishments

### Production code

- **`SportVisitor.visitRacing` is now a two-path dispatcher.** `visitRacingNew` runs when the GenericSystem config carries `playerVehicle: Vehicle` (Plan 03 delegate-driven path); `visitRacingLegacy` runs when only the legacy `RacingConfig` is present (SportCodegenTest direct-construction fixtures). The two paths are mutually exclusive — no double-emission risk.
- **`racing_tick_<id>(void)` is emitted as a single CFunction in the HOME bank** via GenreVisitorResult.functions. Body sections in declared order:
  - **C.1 — Throttle/steer ramp** using player VehicleStats (accel, speed cap, brake = `(accel * 2).coerceAtMost(255)`, friction = 1). dpad input via `dpad_held(J_UP)` / `dpad_held(J_DOWN)`.
  - **C.2 — Cardinal heading update** via `dpad_pressed(J_LEFT)` / `dpad_pressed(J_RIGHT)`. Heading kept in [0..3] via `& 3` mask.
  - **C.3 — Delta = `_vehicle_<vehId>_speed_cur >> 5`**, four-case `CSwitch` on heading to compute vx/vy, then `_<actor>_x += (UINT8)vx; _<actor>_y += (UINT8)vy;` write-back. (D-07 — racing() owns position write-back.)
  - **C.4 — `update_camera_<cameraId>()` invocation** (D-06). cameraId discovered from `gameIR.systems.firstOrNull { it is CameraSystem }?.id` with `"camera"` fallback.
  - **C.5 — Checkpoint state machine** using `_racing_visited_<id>` UINT8 bitmap, `mask_below = (1u << _racing_checkpoint_idx_<id>) - 1u` order check, lap-completion guard (`visited == all_set AND proximity-to-CP-0`), and post-completion reset to `1u` (CP 0 bit kept) — D-15, D-17 ping-pong loophole eliminated by construction.
  - **C.6 — One C-AST for-loop per AiVehicleSlot.** Inner body: active-slot guard (`if (!_pool_<aiId>_active[i]) continue;`), waypoint-follower input source (largest |Δx| vs |Δy| selects cardinal heading toward next waypoint), throttle ramp identical to player C.1 with optional rubber-band boost, integration `_pool_<aiId>_speed_cur[i] >> 5` (IDENTICAL `>> 5` shape — D-09), four-case CSwitch on `_pool_<aiId>_heading[i]`, position write-back to `_pool_<aiId>_x[i]` / `_pool_<aiId>_y[i]`, waypoint-cursor advance when within 8px of target.
