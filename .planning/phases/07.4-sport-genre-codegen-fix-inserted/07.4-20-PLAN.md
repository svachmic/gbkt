<objective>
Land **Path C** (user-locked decision): reframe `clear()` and `print()` as scene-aware so they cannot wipe a loaded BG tilemap. Flip Plan 19's RED tests to GREEN.

Purpose: Honor the project's window-layer-UI architectural rule (CLAUDE.md) at the codegen tier — the DSL author should never have to reason about which layer their print writes to. The codegen knows whether a scene has a BG tilemap (via `tilesetRef` or genre enterOps splice) and lowers `clear()` and `print()` accordingly.

This is the principled fix per D-02 (no game-specific special cases) and D-03 (IR exposes no hardware ops; we route the existing `ScreenClear` IR through the existing `visitScreenClear` hook — no new IR node). The fix surface spans `gbkt-lang` (one-line DSL routing) + `gbkt-backend-gbdk` (scene-aware lowering); no new IR shapes, no DSL surface changes from the user's perspective.

**Two-part fix (revision — closes B-1, B-2, B-3):**

**Part 1 (DSL routing — one-line change in gbkt-lang):**
At HEAD, `ScriptBuilder.clear()` emits `RawOp("cls();")` directly (gbkt-lang/src/main/kotlin/io/github/gbkt/core/dsl/ScriptBuilder.kt:432). This bypasses `visitScreenClear` entirely — making the visitor scene-aware would have no effect on the racer's actual code path. **Fix:** change the body of `clear()` to `ops += ScreenClear(sourceLocation = captureV2Location())`. Now the DSL routes through the existing `ScreenClear` IR node, and `visitScreenClear` becomes the codegen hook.

**Part 2 (codegen — scene-aware lowering in gbkt-backend-gbdk):**
- `ScriptOpVisitor.visitScreenClear` becomes scene-aware: emits `cls()` when the current scene has no BG tilemap; otherwise emits a non-destructive screen-clear (`HIDE_SPRITES;` macro + `_win_clear_region(0, 0, 20, 18)` — keeps BG intact).
- `ScriptOpVisitor.visitPrintOp` becomes scene-aware: emits `_win_print_at(...)` when the current scene has a BG tilemap; otherwise preserves the existing `gotoxy(...)` + `printf(...)` lowering for back-compat (per the revised back-compat decision below).

## Back-compat strategy for print() in non-BG scenes (Plan 19 Test #3) — REVISED

Two options were on the table:
- (a) **Scene-aware PrintOp**: keep `gotoxy + printf` for non-BG scenes (title, results, gameover); swap to `_win_print_at` for BG scenes.
- (b) Universally lower `PrintOp` → `_win_print_at` (the original Plan 20 choice).

**Choice: (a) Scene-aware PrintOp** — REVISED from the original (b) per checker B-3.

**Rationale for revision:**
1. **`sprintf` IS available in GBDK-2020** (confirmed: `/Users/michalsvacha/gbdk/include/stdio.h:55` declares `void sprintf(char *str, const char *format, ...);`). So the universal `_win_print_at` path (b) is technically feasible — sprintf-into-stack-buffer would compile.
2. **HOWEVER**, the universal-swap path requires every existing `print(...)` call site in the 5 non-racer example games (shmup, platformer, platformer-gbc, dungeon, explorer) to work correctly through a NEW codegen path (sprintf-into-buffer + _win_print_at) that has not been previously exercised. The risk class is regression-by-untested-rewrite across 5 ROMs.
3. The original Plan 20 acknowledged this risk by adding a "FIXME(07.4-20-FOLLOWUP)" escape hatch for the case where sprintf might fail at link time — that escape would have shipped literal format strings (`"SCORE: %d"`) on screen across 5 games. That violates `feedback_quality_over_shortcuts.md` ("no smoke and mirrors").
4. The CLAUDE.md "Window-Layer UI" rule applies most stringently to scenes WITH a custom BG tilemap (which is where text on the BG layer would corrupt graphics). For BG-less scenes (title, results, gameover), `gotoxy + printf` writes to the BG tile layer but the BG is empty — there's nothing to corrupt. The architectural-purity argument for (b) is real but the regression-risk-vs-purity tradeoff favors (a) for this phase.

**Net for Plan 20:**
- BG scenes (race scene; any scene with `tilesetRef` or genre BG splice) — `print(...)` lowers to `_win_print_at(...)`. Window-layer UI honored where it matters most.
- Non-BG scenes (title, results, gameover) — `print(...)` keeps the existing `gotoxy + printf` lowering. Zero behavioral change for the 5 non-racer example games.

For `ScreenClear`, the discriminator is also scene-aware: `cls()` for non-BG scenes, non-destructive form for BG scenes. Same shape as PrintOp; consistent codegen contract.

**Future direction (NOT this plan):** A follow-up phase can pursue universal `_win_print_at` lowering after the dynamic-print path (sprintf-into-buffer with formatted args) is exercised across all 5 games' actual `print(format, ...args)` shapes. That work is out of scope for 07.4. This decision is recorded in the SUMMARY.

## Discriminator predicate

```kotlin
private fun sceneHasBgTilemap(
    sceneId: String,
    gameIR: GameIR,
    genreEnterOps: Map<String, List<ScriptOp>>,
): Boolean {
    val scene = gameIR.scenes.firstOrNull { it.id == sceneId } ?: return false
    if (scene.tilesetRef != null) return true
    // Genre enterOps splice paints the BG via set_bkg_tiles — detect by op shape.
    val sceneGenreOps = genreEnterOps[sceneId] ?: return false
    return sceneGenreOps.any { op ->
        op is RawOp && (op.code.contains("set_bkg_tiles") || op.code.contains("set_bkg_data"))
    }
    // Future direction: when a structured LoadBackgroundTilemap ScriptOp lands, replace the
    // RawOp text-match with a typed check. JVM-tier ScreenClearSceneAwareTest will surface
    // a regression if the predicate stops detecting the genre splice.
}
```
