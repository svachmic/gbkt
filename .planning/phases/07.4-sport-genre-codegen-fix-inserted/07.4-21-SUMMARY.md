# Phase 07.4 Plan 21: Camera Bounds Underflow Fix Summary

**Two-line `kotlin.math.max(0, ...)` clamp in `visitCameraSystem` closes the UINT8-underflow class for all sub-screen `CameraSystem`s, locked by a 5-test JVM regression net.**

## Performance

- **Duration:** ~10 min
- **Started:** 2026-05-11
- **Completed:** 2026-05-11
- **Tasks:** 3
- **Files modified:** 3 (1 created, 2 edited)

## Accomplishments
- Eliminated the underflow class for all `CameraSystem`s whose zone is smaller than the GB screen (160x144). Sub-screen zones now lock the camera at the origin instead of producing `SCX/SCY = 248` (or similar wraparound) and pushing the BG off-screen.
- Added `CameraBoundsUnderflowTest` (5 tests) that locks the invariant per-axis: sub-screen X (boundsWidth=152, maxX must be 0 not -8), sub-screen Y (boundsHeight=100, maxY must be 0 not -44 — W-4 closure), exact-screen, supra-screen, no-bounds.
- Spot-checked racer's generated `update_camera_camera`: X axis now emits `(rawX > 0u) ? 0u : rawX` (post-fix) instead of the previous `> -8` literal that wrapped via UINT8. Y axis remains `(rawY > 8u) ? 8u : rawY` because racer's bounds happen to be 152×152, so maxY = +8 is positive and the fix is a no-op there.
- Updated and renamed the racer's `driving steers and accelerates so camera_x changes` test to assert the correct post-fix invariant (`camera_x stays at 0` for sub-screen zones). The prior assertion was only satisfied because of the underflow bug.

## Decisions Made
- **Generic codegen fix**, not a racing-genre patch — D-02 mandates no game-specific special cases. The fix benefits every `CameraSystem` regardless of genre.
- **`kotlin.math.max(0, ...)`** chosen over a `coerceAtLeast(0)` extension — explicit, no extension import needed, idiomatic in arithmetic contexts.
- **W-4 closure for Test #2:** racer's actual bounds (152×152) are NOT genuinely negative on the Y axis (maxY = +8). To make the Y-axis assertion truly RED at HEAD the test uses `boundsHeight = 100` so maxY = -44 is negative. This proves the fix applies to BOTH axes independently rather than accidentally only on X.
- **Updated racer test rather than deleting it.** The original test name and assertion captured the *bug*'s observable behavior (apparent camera "movement" via UINT8 wraparound), not the contract. Renaming it to `driving keeps camera_x clamped at zero for sub-screen zone` and asserting `assertEquals(0, camEnd, ...)` preserves regression coverage for the post-fix contract while removing the false signal.
