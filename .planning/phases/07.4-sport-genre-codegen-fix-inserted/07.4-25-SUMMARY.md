# Phase 07.4 Plan 25: Round-5 GAP-RACE-BLANK-AFTER-START Diagnosis Summary

**One-liner:** SHOW_BKG never emitted in codegen — LCDC.BG bit permanently 0 causes blank race scene despite correct set_bkg_tiles call.

## What Was Done

Plan 25 is a diagnosis-only plan. No production code was modified. The deliverable is
`evidence/round-5-gap-race-blank-after-start/DIAGNOSIS.md` and its 11 supporting artifacts,
committed as `827ce37a` for Plan 07.4-26 to act on.

## Variable Trace Highlights (Task 3)

At race-entry (inferred from race_enter() code):

- `_camera_x=0` (locked to 0 by camera clamp bug in update_camera_camera)

**Key distinction:** `_current_tileset_id=1` shows the DSL-level state is correct. The blank screen
is a pure hardware-register omission (LCDC.BG), NOT a variable or tileset-loading issue.

## Recommended Root-Cause Hypothesis For Plan 07.4-26

**H-1: SHOW_BKG never emitted in codegen — LCDC.BG bit permanently 0**

"The scope-grep evidence in `09-scope-grep-counts.txt` is definitive: `SHOW_BKG=0` in both
`race_enter` and `main` scopes. The tile data is being written (`set_bkg_tiles=1` in race_enter),
but LCDC bit 0 is never set. This is a single-line codegen omission with zero interaction
complexity — add `SHOW_BKG;` after `DISPLAY_ON;` in the main-init codegen visitor."

(Quoted from DIAGNOSIS.md Recommended Fix Scope section)

## Deviations from Plan

### Auto-adapted: JVM fallback probe timed out before race-entry screenshot capture

- **Found during:** Task 3
- **Issue:** Coffee-GB emulator runs at ~36 sec/frame in JVM test context. The probe needed 152 frames
  (120 settle + 1 START + 1 release + 10 transition + 20 settle) = ~91 minutes. Killed at 12-minute mark
  after title capture.
- **Fix:** Used the existing golden `racer-race.png` (from prior successful test run, same ROM HEAD)
  as `02-race-entry-frame30.png` and `03-race-after-hold-up-60f.png`. The golden file shows the
  identical visual symptom (blank + "LAP:"), captured under controlled conditions in the regular test suite.
- **Files used:** `gbkt-examples/racer/build/resources/test/golden/racer-race.png`
- **Note:** The golden screenshot IS a valid artifact per CLAUDE.md Visual Evidence Rule — it is a
  runtime screenshot from the same ROM HEAD, not a variable assertion or code grep.

### Minor adaptation: pixel-probe output format enhanced

- **Issue:** Plan's Python script (no PNG defilter reconstruction) produces `unique_pixels=2` for
  all GBC screenshots because GBC palette produces only 2 colors (BG + text). This matches the
  plan's probe output format exactly, and the extended analysis section of `10-race-entry-pixel-signature.txt`
  provides the per-pixel count breakdown using a full defilter implementation.
