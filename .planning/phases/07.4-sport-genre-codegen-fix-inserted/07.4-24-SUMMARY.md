## What Got Built

### Task 1 — gbkt-genre-sport/CLAUDE.md gains "Scene-Aware clear() and print() Contract (Plan 07.4-20)" section (commit `25b67546`)

A new section appended after the existing "Wall-Collision Sample (Plan 07.4-18)" section, BEFORE "## Testing", covering:

- **Part 1 (DSL routing):** `ScriptBuilder.clear()` now emits `ScreenClear` IR (vs. previously `RawOp("cls();")`). One-line gbkt-lang change at `gbkt-lang/src/main/kotlin/io/github/gbkt/core/dsl/ScriptBuilder.kt:432`.
- **Part 2 (scene-aware codegen):** Two tables show the lowering choice for `ScreenClear` and `PrintOp` based on scene shape:
  - Has BG tilemap → `HIDE_SPRITES; _win_clear_region(0,0,20,18);` and `_win_print_at(...)` (non-destructive).
  - No BG tilemap → `cls()` and `gotoxy(); printf();` (back-compat preserves 5 non-racer example games byte-for-byte).
- **What this means for `racing { }` authors:** No "use `_win_*` in racing scenes" rule for DSL authors — the codegen handles the layer choice.
- **What this means for `gbkt-genre-sport` maintainers:** The `sceneHasBgTilemap(...)` predicate detects BG via `scene.tilesetRef != null` OR a `RawOp` containing `set_bkg_tiles`/`set_bkg_data`. If `racing { }` ever stops emitting `set_bkg_tiles` as a `RawOp`, update the predicate.
- **Why this matters (lessons learned):** Cross-references the Plan 14 false positive (`_current_tileset_id=1` variable evidence vs. `cls()` wiping the painted tilemap moments later).

### Task 2 — Project root CLAUDE.md gains "Verification Methodology — Visual Evidence Rule" section (commit `c1f93514`)

A new section inserted between "## Documentation Index" and "## Common Tasks Routing", covering:

- **The rule:** Visual truths ("X is visible on screen") MUST include a runtime screenshot, not a variable-state assertion alone.
- **When this rule applies:** GSD verifier runs against visual SCs, MCP play-throughs, UAT verdicts.
- **When variable evidence is sufficient:** Internal state truths ("counter incremented", "save written"), JVM-tier codegen tests that lock the generated C shape.
- **How to satisfy the rule:** MCP `gbkt-emulator.emulator_screenshot(path)` writes PNG to phase `evidence/` directory.
- **Scope-level grep gates (corollary):** File-level `grep -c cls() bank1.c` cannot distinguish race_enter from title_enter — use awk brace-walk extraction (Plan 07.4-23 Task 1 step 3 demonstrates this).
- **History:** Pointer to the Phase 07.4 round-2 → round-4 incident as the proof point.

The GSD verifier reads CLAUDE.md before constructing test plans, so this section reaches the verifier role at the same time as the rest of the project's instructions.

The Plan 14 evidence screenshot (`evidence/racer_14_race_entry_frame129.png`) showed the IDENTICAL state the user reported in round-4 UAT — the bug was present at round 2; the verifier did not look at the screenshot pixels.
