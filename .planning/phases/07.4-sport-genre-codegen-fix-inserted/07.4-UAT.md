## Diagnosis Summary

**Single root cause for tests 2, 3, 5, 6:** `clear()` in `raceScene.enter` (Racer.kt:137) lowers to GBDK `cls()` and runs AFTER the racing genre's BG-paint splice (`set_bkg_data` + `set_bkg_tiles` for `_zone_track1_tiles`), wiping the freshly-painted track tilemap. `print("LAP:", ...)` in the same enter block lowers to BG-layer `gotoxy`/`printf` (not the window-layer `_win_*` helpers), violating the project's window-layer-UI architectural rule. Genre `enterOps` are prepended in `GBDKPipelineV2.addGenreEnterOps:1479`; user enter ops always run after.

**This is NOT a regression from Plans 15–18.** The Plan 14 round-2 evidence screenshot (`evidence/racer_14_race_entry_frame129.png`) shows the identical dark-BG / two-stacked-cars / "LAP:"-top-left view. Round-2 SC-4 verification confirmed via `_current_tileset_id=1` variable assignment (proves splice ran) without visually validating BG pixels rendered the track. The bug has been present throughout the phase; the JVM-tier evidence is correct, but the runtime ROM has never actually shown the track to a human player.

**Two secondary issues compound (revealed once primary fix lands):**
1. **Camera bounds < screen size.** Zone is 19×19 tiles (152×152 px) < 160×144 screen. `update_camera_camera` in main.c:252-256 computes `maxX = boundsWidth - 160 = -8`, then UINT8 clamps to 248 — wildly mis-scrolled. Need racing genre to either synthesize a zone ≥ 160×144 px or guard the bounds calc against `bounds < screen`.
2. **Cross-bank const data access.** `_zone_track1_tiles` lives in `#pragma bank 2` but `set_bkg_tiles` is called from bank 1 without `SWITCH_ROM(2)` first. May surface as still-blank BG even after primary fix.

**Suggested fix paths (planner to choose):**
- **A. Patch the racer DSL example.** Remove `clear()` from `raceScene.enter`; switch `print("LAP:", …)` to a window-layer call. Smallest blast radius. Unblocks SC-5/SC-6 MCP play-through.
- **B. Defensive `SportVisitor.enterOps`.** Append re-paint after user ops, OR detect downstream `ScreenClear` and reorder. Generalises for future racing games.
- **C. Reframe `clear()` as scene-aware** — deprecate or lower differently when a BG tilemap is loaded. Principled fix per project architectural rule (window-layer UI; no `gotoxy`/`printf` on BG).

Audits for the two secondary issues should be scheduled regardless of which path is taken.

**Debug session:** `.planning/debug/racer-bg-tilemap-not-rendered.md`
