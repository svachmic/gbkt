## Decisions Made

1. **Reflection over compile-time dep.** The plan body's `<action>` block listed direct imports of `RacingConfig` / `WaypointDef` / `AiVehicleSlot` etc. from `gbkt-genre-sport.domain`. Direct imports would create the module cycle `gbkt-analysis -> gbkt-genre-sport -> gbkt-backend-gbdk -> gbkt-analysis`. The parallel-execution prompt explicitly flagged this constraint (`gbkt-analysis main must not depend on gbkt-genre-sport`). Java reflection on the data-class generated `getX()` accessors keeps the pass resilient to additive field changes in gbkt-genre-sport while honoring the module-graph constraint. The same map-typed pattern is already used by `SemanticValidationPass.kt:checkFadeWithoutAudioMixer` (`it.config["type"] == "audio_mixer"`).
2. **Test-only dep on gbkt-genre-sport.** Adding `testImplementation(project(":gbkt-genre-sport"))` lets the test sourceset import `RacingConfig` / `Vehicle` / `WaypointDef` / `VehicleStats` / `TrackDef` directly to build expressive fixtures. Gradle's DAG remains acyclic because at test-compile time, gbkt-genre-sport main is already on the classpath (compiled against gbkt-analysis main; this is the test classpath, not the main classpath).
3. **Per-scene de-dup of ANLZ-RACING-04.** Multiple hand-coded writes to the bound player actor in a single frame block emit ONE warning per scene (keyed by `scene.id`). The fix-it suggestion already covers all writes ("Remove direct moveBy / SetPosition / _<player>_x|y writes from the scene's frame block"). One warning per scene is the right granularity.
4. **Direct-actor-write detection by var-name convention.** ScriptOp does not have a typed `AssignActorProperty` op — the DSL lowers `actor.x = …` to a plain `Assign` with `target = "_<actorId>_x"`. The pass matches `Assign.target == "_${playerActorId}_x"` / `"_${playerActorId}_y"`, which mirrors the sport-codegen output convention. This stays aligned with what Plan 05's SportVisitor reads from the IR.
5. **Polygon-degeneracy math in Long arithmetic.** The shoelace formula multiplies tile coords; on a 32x32-tile dungeon, individual products fit Int but accumulating across many waypoints could push the sum out of range. Long is defensive and fast on x86/ARM. The collinearity test uses cross-product `(b - a) × (c - a) == 0`, also in Long for the same reason.
6. **Pass position: between SemanticValidationPass and ResourceInventoryPass.** This guarantees actor / scene IDs already resolved before the racing pass walks them (so `playerActorId in actorIds` is meaningful), and that racing-binding ERRORs short-circuit before resource counting (avoiding spurious budget warnings on a game that wouldn't compile anyway).
