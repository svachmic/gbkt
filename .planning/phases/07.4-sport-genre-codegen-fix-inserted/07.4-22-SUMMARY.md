## Fix Detail

After Task 2, racer's `bank1.c` contains:

```c
void race_enter(void) BANKED {
    _camera_target = 0u;
    set_bkg_data(0, 3, _racing_track1_tileset);
    SWITCH_ROM(2);                                              // <-- Plan 22 added
    set_bkg_tiles(0, 0, 19u, 19u, _zone_track1_tiles);
    _current_tileset_id = 1u;
    pool_carAi_spawn(80u, 96u);
    {
        HIDE_SPRITES;
        _win_clear_region(0u, 0u, 20u, 18u);                    // (Plan 20)
    }
    SHOW_SPRITES;
    _raceTime = 0u;
    _position = 1u;
    _win_print_at(1u, 1u, "LAP:", 4u);                          // (Plan 20)
}
```

The `SWITCH_ROM(2)` is emitted by the new `guardCrossBankBgTilemapAccess` private helper in `GBDKPipelineV2`, which prepends a `SWITCH_ROM(<bank>)` RawOp before any genre enter op matching the canonical shape `set_bkg_tiles(..., _zone_<id>_tiles)` whose referenced zone is allocated to a non-current ROM bank (`bankAllocation[zoneId] > 1`).

**Why no SWITCH_ROM restore (e.g., SWITCH_ROM(1) after the call):** the dungeon zone-load convention DOES emit a restore in `main.c` because that path is called from the HOME bank (bank 0) and switches back. The race_enter splice runs entirely inside bank 1; subsequent ops in race_enter (`pool_carAi_spawn`, `_win_clear_region`, `_win_print_at`) do not depend on the bank register pointing at bank 1 (they call into HOME-resident helpers that auto-switch via BANKED calling convention). When the next user-bank function is called, the BANKED trampoline switches the bank register on entry. Adding a defensive `SWITCH_ROM(1)` after the read would be cosmetic, not load-bearing — and Plan 22 followed feedback_quality_over_shortcuts.md by NOT adding cosmetic ops.
