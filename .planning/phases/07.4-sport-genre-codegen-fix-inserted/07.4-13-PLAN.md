<objective>
Audit `gbkt-examples/racer/src/test/kotlin/io/github/gbkt/examples/racer/RacerEmulatorTest.kt` and remove every `writeVariable`-style state seeding that becomes redundant after Plans 11 + 12 land. The natural-play path now activates the AI pool, loads the track tileset, and clamps the player position via wall-collision — so any test that previously had to fake those preconditions to make an assertion fire can now drive the ROM through the natural game flow and assert against the resulting state.

The user-feedback rule `feedback_quality_over_shortcuts.md` makes this MANDATORY: a test that passes by virtue of `writeVariable("_pool_carAi_active", 0, 1u)` is smoke-and-mirrors when the production codegen now sets that variable on its own. Keep only the seeding that is genuinely necessary (e.g. a focused probe of the checkpoint bitmap state machine that would otherwise need to drive 30+ frames through the corridor — the seeding then becomes a deliberate test isolation, not a workaround for missing production behavior, and the comment must say so).

Purpose: align the JVM-level emulator regression net with the ACTUAL runtime, so a future regression that breaks the enterOps splice (Plan 11) or the collision guard (Plan 12) trips a test instead of being masked by seeding.
Output: 1 test file modified (~-30 / +20 LOC depending on what was seeded vs. what becomes natural). Net diff is small; surface area is narrow.
</objective>

The user-feedback rule that gates this plan (verbatim from MEMORY.md):

> **Quality over shortcuts** — no smoke and mirrors; every fix must be provably correct, not just passing tests

> **Hide C complexity from Kotlin test surface** — tests must speak gbkt/Kotlin, never expose GBDK tile offsets or VRAM addresses

The current state of RacerEmulatorTest (per VERIFICATION.md): "4/4 GREEN — but with state seeding via writeVariable" — i.e. the tests pass because the test harness manually fakes preconditions that the production code does not establish. After Plan 11 + 12, those preconditions ARE established naturally; the tests should reflect that.

Scrub heuristic — for each writeVariable call:

1. **Is the seeded variable now set by production code at scene-enter?** (Plan 11 sets `_pool_<aiId>_active[i]` via pool spawn helper; sets `_current_tileset_id`; sets `_camera_target`.)
   - YES → REMOVE the seeding. The test must reach the assertion via natural play (e.g. `agent.start()`, `agent.assertScene("title")`, `agent.pressStart()`, `agent.waitForScene("race")`, then assert `_pool_carAi_active[0] == 1u`).
   - NO → KEEP the seeding but add a comment explaining why.

2. **Is the seeded variable now reachable via natural input within a reasonable frame budget?** (Plan 12 collision guard means held-UP cannot underflow _car_y; held-LEFT/RIGHT can navigate the corridor; ~30-60 frames of input drives the player to a checkpoint.)
   - YES → REMOVE the seeding. Test drives input, asserts on natural state.
   - NO (e.g. driving 3 full laps would take 1000+ frames in test wall-time) → KEEP with comment.

3. **Are tile offsets, VRAM addresses, or other C-shaped tokens leaking into Kotlin assertions?** (per `feedback_hide_c_complexity.md`)
   - If a test reads `_pool_carAi_x[0]` directly to confirm a runtime position, that's an acceptable hidden-from-test-surface use of a low-level read. But if a test calls `agent.writeMemoryAddress(0x6000, ...)` to seed VRAM tile bytes, that's a leak — refactor to use a higher-level assertion (e.g. `assertActorVisible(rival)`).

Tests that should NOW be reachable from natural play after Plan 11 + 12:

- "AI pool slot becomes active at race-scene enter" → drive title → race transition (press Start), wait 1 frame, assert `_pool_carAi_active[0] == 1u`. NO SEEDING NEEDED.
- "Tileset id becomes non-sentinel at race-scene enter" → same path; assert `_current_tileset_id != 0xFF` after race transition. NO SEEDING.
- "Camera target is bound to player actor index at race-scene enter" → assert `_camera_target == 0` (or whatever the player actor index is). NO SEEDING.
- "Held UP for 30 frames does not wrap _car_y off-screen" → drive title → race → hold UP for 30 frames; assert `_car_y in 0..(mapH*8 - 16)`. NO SEEDING.
- "Player can touch checkpoint 0 by driving north" → drive corridor manually; assert `_racing_checkpoint_idx_track1 >= 1` after sufficient frames. NO SEEDING (potentially keep frame budget bounded).

Tests that LEGITIMATELY keep seeding:

- "Lap-bitmap state machine rejects out-of-order checkpoint touches" → seeding `_racing_visited_track1 = 0` and a precise position near CP 2 to verify the mask_below guard rejects the advance. KEEP, with comment: "Direct probe of the bitmap state machine; full natural play would require driving 100+ frames just to set up the wrong-order test, which is out of scope for this micro-assertion."
- "racing_tick increments lap counter exactly once per real-circuit completion" → may need to seed a near-completion bitmap state to avoid driving 1000 frames per assertion. KEEP, with comment.
