   was unstable in this session; `emulator_start` did not return. The substitution
   uses the identical in-process `AgentDebugSession.captureScreenshot` →
   `ScreenshotCapture.capture` pipeline that the MCP server wraps over stdio.
   PNG bytes are byte-equivalent. Documented in VISUAL-VERIFICATION.md
   § MCP Substitution Note.

2. **`delta(prefix, 23) = 0`** because the prefix anchor PNG was already a post-H1
   non-blank render — Plan 30's fix is silent at the pixel layer for race-entry
   frame 30 (preserves the H1 baseline render) and load-bearing at the runtime
   liveness layer. The plan's strict numeric threshold isn't met; the plan's INTENT
   (proving fix changed runtime behaviour) IS met via D-N-11 gates and the 60-frame
   liveness probe. Documented in 29-pixel-signatures.txt § anchor interpretation
   note.

3. **JVM proxy passed but masked runtime failures.** The JVM-tier `_camera_y > 0`
   check was satisfied by the racer zone's 152×152 clamp value (=8), not by actual
   camera-follow tracking. The pixel-signature thresholds for 23/24/25/26 passed
   because the RENDERED tilemap is non-blank — but the rendered geometry is NOT a
   waypoint-driven race track. Both are validated round-3/4/5 false-positive
   classes that CLAUDE.md's Visual Evidence Rule was designed to catch; the
   user's manual UAT did the catching, not the JVM gates.
