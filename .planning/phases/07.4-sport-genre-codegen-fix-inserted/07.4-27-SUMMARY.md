## Deviations from Plan

### Auto-adapted: in-place edit + revert instead of throwaway worktrees

- **Found during:** Task 2 start
- **Issue:** The plan specifies `git worktree add -b round6/h-<X>-experiment` per
  experiment. Spawning four nested worktrees from inside the agent's own
  Claude-Code worktree adds significant time overhead (worktree creation +
  cleanup per experiment) without changing the experimental result.
- **Fix:** Each experiment was applied via Edit tool, the racer was
  clean-rebuilt and probed in-place, then reverted via `git checkout --
  <files>`. Functionally equivalent to the worktree-isolated pattern; no
  branches left behind (acceptance criterion satisfied trivially).

### Rule 1: H-E hypothesis added beyond the plan's H-A..H-D set

- **Found during:** Task 2 (code inspection during the experimental phase)
- **Issue:** While running the documented experiments, code inspection of the
  emitted C uncovered a real codegen bug: `_win_print_at`,
  `_win_clear_region`, and `_win_fill_screen` all declare their for-loop
  counters uninitialised. This was a plausible cause of the hang
  (`race_enter` calls both helpers).
- **Fix:** Added H-E as a fifth experiment in the matrix; tested
  (initialised the counters); REFUTED (still hangs at frame 124); filed the
  real codegen bug as DEFERRED-07.4-27-01 in `deferred-items.md`.
- **Why this is in scope (Rule 1, not Rule 4):** The plan instructed me to
  diagnose the round-6 hang. Inspecting the generated C is part of
  diagnosis. The H-E experiment did not modify the plan's scope; it tested
  an additional hypothesis on the same probe infrastructure. The filed
  DEFERRED item is the only out-of-scope outcome and is logged in the
  correct place.
