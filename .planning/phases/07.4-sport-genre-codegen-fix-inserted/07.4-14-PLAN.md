```markdown
### Scene-Enter Splice (Phase 07.4 closure)

`SportVisitor.visitRacingNew` populates `GenreVisitorResult.enterOps` (added in Phase 07.4-09) for the bound race scene with three op groups:

1. Camera target bind — `_camera_target = <playerActorIdx>u;` so the auto-emitted CameraSystem variable is non-sentinel at runtime.
2. Track tileset + tilemap load — `set_bkg_data(0, 3, _racing_<id>_tileset)` then `set_bkg_tiles(0, 0, mapW, mapH, _zone_<id>_tiles)` then `_current_tileset_id = 1u;`. The 3-tile builtin tileset (wall/road/grass) is emitted as `_racing_<id>_tileset[48]` and consumed by these ops.
3. AI pool spawn — `pool_<aiId>_spawn(<rivalX>u, <rivalY>u);` per AI vehicle slot, sourced from the rival actor's `position(...)` declaration.

The pipeline `GBDKPipelineV2.collectGenreEnterOps` + `addGenreEnterOps` (Phase 07.4-10) prepends these ops at the head of `<sceneId>_enter`'s body, mirroring the existing `frameOps` splice for the per-frame loop.

Covered by `RacingEnterOpsEmissionTest` (multiple test methods, GAP-A / GAP-B / GAP-D closure evidence) and the GBDKPipelineV2 `GenreEnterOpsSpliceTest`.

### Wall-collision Position Write-Back (Phase 07.4-12)

`buildPositionWriteBackWithCollision` wraps the player and AI position update in an INT16 bounds check + tile sample against `_zone_<id>_tiles`. If the proposed tile is 0 (wall, per the TrackSynthesizer constants from Plan 07.4-04) or the proposed position is out of world bounds, the move is rejected. This upholds D-17 by construction — player cannot drive across walls, cannot wrap off-screen via UINT8 underflow, and must traverse the corridor to touch checkpoints in declared order.

Covered by `RacingCollisionGuardTest` (multiple test methods, GAP-C closure evidence).

### Waypoint-Neighborhood Force + 3-Level Wall-Aware AI Heading (Phase 07.4-16, round-2 closure)

After polygon rasterization + perimeter-walls, `TrackSynthesizer` runs a `forceWaypointNeighborhoodsToDrivable` post-pass that overwrites every declared waypoint cell AND its 3x3 tile neighborhood (`WAYPOINT_FORCE_RADIUS = 1`) to `TILE_DRIVABLE`. This guarantees the AI's sample-center heuristic accepts every waypoint position, closing TRACK-NAVIGABILITY's "waypoint-on-wall" failure mode. The perimeter-walls invariant is preserved on cells away from waypoints; if a waypoint sits on the perimeter, the waypoint wins (D-17 — the polygon vertex must be reachable).

`SportVisitor.buildAiPoolBodyStatements` emits a 3-LEVEL wall-aware heading pick via `buildAiHeadingPickWithFallback`:
1. **Primary** — largest-axis cardinal toward the target waypoint.
2. **Fallback** — perpendicular cardinal toward the target.
3. **Tertiary** — first unblocked of {0=N, 1=E, 2=S, 3=W} (skipping primary/fallback). If all four are blocked, the AI keeps its current heading (stays put — a stable degenerate state bounded by the 3x3 force radius around any waypoint).

The probe at each level reuses the same sprite-sample-and-tile-lookup as the player's wall-collision-guard (D-09 uniform physics path — only the heading pick gets a wall-aware fallback; the write-back is unchanged).

Covered by `RacingTrackNavigabilityTest` (10 test methods, TRACK-NAVIGABILITY closure evidence — racer / generic / triangle / pentagon fixtures + AI-simulation full-lap contract).

### High-Contrast 3-Tile Builtin Tileset (Phase 07.4-17, round-2 closure)

`SportVisitor.tilePatternToBytes(matrix: List<List<Int>>): List<Int>` (visibility: `internal`) converts an 8x8 palette-index matrix to GBDK 2bpp interleaved bytes. `SportVisitor.builtinTrackTilesetBytes()` (visibility: `internal`) is rewritten to derive 48 bytes from 3 logical pixel matrices instead of hand-tuned literals:
- WALL: solid palette index 3 (black) — all 16 bytes 0xFF.
- DRIVABLE: solid palette index 1 (light gray) — alternating row pairs (0xFF, 0x00).
- GRASS: checkerboard of palette index 2 (dark gray) and palette index 0 (white) — visible per-pixel texture.

The three tiles produce pairwise-distinct byte sequences and the GRASS tile carries visible texture (>= 2 distinct palette indices), closing TILESET-VISUAL-CONTRAST's "uniform-toned BG layer" failure mode under the default DMG palette.

Covered by `RacingTilesetContrastTest` (11+ test methods asserting byte-sequence pairwise inequality, per-tile palette uniformity for WALL/DRIVABLE, visible texture for GRASS, and round-trip correctness of `tilePatternToBytes` for solid palettes 1/2/3 + size + range validation).
```
