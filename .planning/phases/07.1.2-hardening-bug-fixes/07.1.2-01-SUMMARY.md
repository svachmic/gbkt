# Phase 07.1.2 Plan 01: Analysis Pass Bug Fixes and Audit Summary

Fix F-075 (BankAllocator silent overflow) and F-077 (checkPalettePrecision false positives) using TDD, then audit all 11 analysis passes for the same four bug classes.

## What Was Built

**F-075 fix — BankAllocator hard error on overflow:**
`BankAllocator.allocateForStrings()` previously silently assigned an overflowing namespace to `maxBanks` regardless of capacity, with a warning string that no caller would check. The overflow path now throws `IllegalStateException("Game content exceeds ROM capacity. ...")` — a truly unignorable hard error per D-05.

**F-077 fix — checkPalettePrecision false positive elimination:**
The body of `checkPalettePrecision()` in `SemanticValidationPass` was replaced with a no-op comment. The root cause: `GBCColor` stores rgb555 (already quantized values). The biased expansion formula (`shl 3 | shr 2`) used to recover rgb888 produces values that never round-trip back to the original rgb555 values, generating false-positive precision warnings for valid colors like WHITE (0x7FFF). Precision loss detection must happen at DSL construction time via `gbcHex()`, not at analysis time on already-quantized data.

**Analysis pass audit — all 11 passes:**
All 11 analysis passes were read and audited for 4 bug classes. All clean — no additional fixes required.

**Detailed findings:**

**Bug Class 1 (incomplete operations):** No pass updates one data structure without its sibling. BankingAnalysisPass correctly updates both `bankUsed` and `assignments` atomically. VRAMLayoutPass updates both per-scene and per-actor `vramAssignments` maps. All consistent.

**Bug Class 2 (missing state cleanup):** `ConstantFoldingPass` resets `foldCount = 0` and `foldDetails.clear()` at the top of `run()`. `BitwiseOptimizationPass` calls `rewriteDiagnostics.clear()` and `rewriteDetails.clear()` at the top of `run()`. `DeadCodeEliminationPass` is advisory — it does NOT remove scenes, only emits INFO diagnostics, so no dangling reference cleanup is needed.

**Bug Class 3 (single-pass algorithms):** `ConstantFoldingPass` uses bottom-up recursive folding (`foldBinaryExpr` folds children before evaluating the parent), so nested constant expressions converge in one pass. No multi-pass issue.

**Bug Class 4 (silent overflow/fallback):** `BankingAnalysisPass` returns `PassResult.Failed` on overflow. `OAMAllocationPass` returns `PassResult.Failed` on hard overflow. `VRAMLayoutPass` emits ERROR diagnostics and returns `PassResult.Failed` if any exist. `RAMPlanningPass` returns `PassResult.Failed` on WRAM overflow. All overflows are hard errors.
