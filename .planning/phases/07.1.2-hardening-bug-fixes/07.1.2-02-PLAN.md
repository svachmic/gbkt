    **F-034 fix (PuzzleVisitor.kt, buildCheckMatch method, lines 212-401):**

    CRITICAL: The original plan's approach (clear when `run >= minMatch` inside the scan loop) is algorithmically wrong. It breaks detection of runs longer than `minMatch` because clearing cells mid-scan corrupts the comparison for the next cell. For example, with grid `[A, A, A, A, B]` and minMatch=3: at c=2, run=3, cells 0-2 are cleared; at c=3, cur=A but grid[2]=0, so A!=0 resets the run -- the 4th A is never cleared.

    The correct approach detects **end-of-run** (when `cur != prev` OR at the end of the row/col), THEN checks `run >= minMatch` and clears from `run_start` to the end of the run. This is a fundamentally different loop structure.

    **Horizontal scan restructure:**
    1. Add CVarDecl for `run_start` (CU8 type, initialized to 0) at the top of the function body alongside existing `run`, `cur`, `found` declarations
    2. The horizontal scan's inner CFor loop (c from 1 to width) must be restructured:
       - At each iteration, load `cur = grid[r * width + c]`
       - Compare `cur` with `grid[r * width + (c-1)]` (the previous cell)
       - If `cur == prev`:
         - `run++` (same as current code)
       - If `cur != prev` (run ended):
         - **Before resetting:** check `if (run >= minMatch)` and if so, emit a clearing loop: `for (int k = run_start; k < run_start + run; k++) { grid[r * width + k] = 0; }` and set `found = 1`
         - Then reset: `run = 1; run_start = c;`
       - **After the inner loop ends** (end of row): check again `if (run >= minMatch)` and clear, because the last run in a row has no "next different cell" to trigger end-of-run detection

    3. Express the clearing loop as a CFor:
       ```kotlin
       CFor(
           init = CVarDecl("k", CU8, initializer = CVar("run_start")),
           condition = CBinaryExpr(CVar("k"), "<", CBinaryExpr(CVar("run_start"), "+", CVar("run"))),
           increment = CUnaryExpr("++", CVar("k")),
           body = listOf(
               CExprStatement(
                   CBinaryExpr(
                       CArrayAccess(CVar("_puzzle_grid_$id"),
                           CBinaryExpr(CBinaryExpr(CVar("r"), "*", CLiteral(width)), "+", CVar("k"))),
                       "=",
                       CLiteral(0)
                   )
               )
           )
       )
       ```

    4. The end-of-row check is a separate CIf after the inner CFor loop completes:
       ```kotlin
       CIf(
           condition = CBinaryExpr(CVar("run"), ">=", CLiteral(minMatch)),
           thenBody = listOf(
               // same clearing CFor as above
               CExprStatement(CBinaryExpr(CVar("found"), "=", CLiteral(1)))
           )
       )
       ```

    **Vertical scan restructure:**
    Apply the identical end-of-run pattern to the vertical scan (c2/r2 loops). The clearing loop iterates over rows:
    `for (int k = run_start; k < run_start + run; k++) { grid[k * width + c2] = 0; }`
    The end-of-column check is a separate CIf after the inner CFor loop completes.

    **New semantics per RESEARCH.md Pitfall 5:** `puzzle_check_match_$id()` now returns 1 if matches were found AND clears them, returns 0 if no matches. The previous behavior (returns 1 forever without clearing) was already broken -- this is the correct fix.
