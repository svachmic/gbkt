<objective>
Close REVIEW CR-01 (BLOCKER) by bracketing the SRAM write loop in
`SavestateManager.load()` with explicit MBC5 ENABLE_RAM / DISABLE_RAM writes so
that SRAM bytes actually land in real cartridge SRAM (not just in the
IntArray-backed test mock).

Purpose: Without this bracket, every SRAM write through `memory.writeByte(addr,
value)` for `addr in 0xA000 until 0xBFFF` is silently dropped by the MBC5
`ramWriteEnabled` gate after any game's `save_game_saves` routine runs
`ENABLE_RAM; ... DISABLE_RAM;`. The mock-backed `SavestateManagerTest` cannot
catch this because its `MemoryAccess` is a flat `IntArray` with no MBC. CR-01
demonstrates the Anchor 4 UAT test passes spuriously because both the
mid-mutation `writeMemory(0xA000, 99)` AND every `loadState()` SRAM write are
dropped by the same gate — `pre == post == 0xFF`.

Output: Updated `SavestateManager.load()` with ENABLE_RAM bracket immediately
before the SRAM read+write loop and DISABLE_RAM restore immediately after.
KDoc updated.

This plan does NOT touch `BanksUatTest` (Plan 11) or
`SavestateManagerTest` (Plan 12) — those are dedicated follow-up plans.
</objective>
