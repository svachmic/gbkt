## Summary

Phase 11.1 closes three seeded codegen defects + one deferred UAT anchor. Research has **fully located** the root causes of all three seeds and surveyed the regression set:

- **SEED-014 (WIDE):** `_bkg_tiles_load_banked` helper is currently gated behind `hasSportRacing && bankAllocation.values.any { it > 1 }`. The helper is ONLY referenced by `SportVisitor.race_enter` today; no other call site exists. Banks needs a NEW call site emitted from `play_enter` (BANKED, in bank1.c). The DSL gap is closed by a minimal scene-to-zone binder. **D-03's "two coexisting emission paths" is structurally sound**: the existing `visitExplorationSystem` path emits `zone_load_X` into HOME with inline `SWITCH_ROM(N)/set_bkg_tiles/SWITCH_ROM(1)` (HOME→HOME is safe); the new banks path emits a call to the HOME helper from a BANKED scene_enter (planner D-claude-2 option (b) is unconditionally correct — the helper is HOME-resident and CFunction.bank=0).

- **SEED-015 (LOCAL):** The root cause is **not** the trampoline filter at `GBDKPipelineV2.kt:2186-2189`, which already correctly skips HOME-resident scenes. The bug lives in `FunctionDeduplicationPass`. When `pause_enter`/`title_enter` (BANKED) have byte-identical bodies, the pass replaces `title_enter` with `/* Deduplicated: see pause_enter */` and then **rewrites every callsite via the regex `\b{name}\s*\(`** — which over-matches into the trampoline's section comment text (`// Trampoline: title_enter (bank 1)` → `// Trampoline: pause_enter (bank 1)`) AND into the trampoline body (`title_enter();` → `pause_enter();`). The fix is to either (a) make the dedup callsite-rewrite regex tighter (don't match inside comments / on whitespace), or (b) opt scene lifecycle functions out of dedup, or (c) make the rewrite skip comment lines. Two RED-by-design sentinel candidates are identified.

- **SEED-016 (UNKNOWN-until-executed → KNOWN):** `SavestateManager.kt` currently captures **only WRAM (0xC000–0xDFFF), OAM (0xFE00–0xFE9F), and HRAM (0xFF80–0xFFFE)** — explicitly NOT SRAM (0xA000–0xBFFF). The 11-UAT.md Anchor 4 recipe explicitly anticipates this (RESEARCH §Pitfall 3) and uses `emulator_save_state` + `emulator_load_state` as the round-trip mechanism. Since `SavestateManager` does NOT include SRAM, the GBST round-trip will currently **NOT preserve** SRAM bytes — the round-trip assertion `pre_bytes == post_bytes` will FAIL unless SRAM happens to be all zeros (which it would be, since `load` overwrites WRAM only and SRAM remains at whatever value it had pre-load — but the load() never touches SRAM at all, so it stays untouched, which means pre == post by accident; details in §SEED-016). **The D-06 outcome-2 NARROW fix is the right route**: extend `SavestateManager` to also capture/restore 0xA000–0xBFFF (8 KB ramBank-0 only suffices for banks; a follow-up seed handles multi-RAM-bank games).

**Primary recommendation:** Adopt D-claude-1 option (i) (scene-block `zone(playZone)` method), D-claude-2 option (b) (reuse existing helper, call from BANKED scene_enter), D-claude-3 fix the FunctionDeduplicationPass callsite-rewrite regex (smallest correct change), D-claude-6 SEED-016 outcome attribution = outcome 2 NARROW (extend SavestateManager to include SRAM region 0xA000–0xBFFF). Plan count: 9 plans (refinement of D-13's 10-step frame, see §Wave Frame).

### Pattern 4: FunctionDeduplicationPass callsite-rewrite-skip-comments (SEED-015 fix)

**What:** Modify `FunctionDeduplicationPass.optimize()`'s call-site rewrite step to NOT rewrite text inside comments.

**Current bug** (`FunctionDeduplicationPass.kt:128-135`):

```kotlin
for ((dupName, canonicalName) in callSiteRedirects) {
    val callPattern = Regex("""\b${Regex.escape(dupName)}\s*\(""")
    result = callPattern.replace(result) { matchResult ->
        matchResult.value.replace(dupName, canonicalName)
    }
}
```

The regex `\bname\s*\(` matches `// Trampoline: title_enter (bank 1)` because `\s*` matches the space and `\(` matches the `(` from `(bank 1)`. Result: the comment text is silently rewritten.

**Fix** — line-by-line filter, skip lines that begin with `//` (single-line comments). The remaining edge case (`/* ... */` multi-line block comments containing function-name-followed-by-space-then-paren) is rare in generated C — the codegen does not emit multi-line C block comments via section comments, and the existing `/* Deduplicated: see X */` comment is itself a single line that does NOT contain a `(`. So the line-prefix filter is sufficient.

```kotlin
for ((dupName, canonicalName) in callSiteRedirects) {
    val callPattern = Regex("""\b${Regex.escape(dupName)}\s*\(""")
    result = result.lines().joinToString("\n") { line ->
        val trimmed = line.trimStart()
        if (trimmed.startsWith("//") || trimmed.startsWith("/*") || trimmed.startsWith("*")) {
            line  // Skip: don't rewrite inside comments
        } else {
            callPattern.replace(line) { m -> m.value.replace(dupName, canonicalName) }
        }
    }
}
```

**Alternative fix (TIGHTER regex)** — drop the `\s*`:

```kotlin
val callPattern = Regex("""\b${Regex.escape(dupName)}\(""")
```

This is a SMALLER diff but it changes the behavior for legitimate C calls of the form `foo (x)` (with whitespace). Existing codegen does NOT emit such calls (the C AST emitter writes `foo(x)` without whitespace, confirmed in `CEmitter.emitExpr`). So this fix is also safe. **Recommend the skip-comments variant** because it is more conservative and preserves the original regex semantics for code lines.

- (i) **Bump magic to "GBST2"** — older files explicitly rejected. Cleanest.
- (ii) **Keep magic, document new format** — older files silently misinterpret. Risky.

**Recommend (i)** for D-06 NARROW fix; document in `SavestateManager.kt` KDoc with a backwards-compatibility note (or accept that .gbst files are session-scoped and never long-lived).

### Anti-Patterns to Avoid

- **Adding zone-load emission inside `visitExplorationSystem`.** Per D-03, do NOT touch this visitor. Banks does NOT have an ExplorationSystem; the new emission path lives in `SceneVisitor`.
- **Auto-binding by analysis pass (D-claude-1 option iii).** Magic; rejected per CONTEXT.md `<deferred>`.
- **Tightening dedup regex to `\b{name}\b\(`** — `\b` between `(` and a preceding char is technically valid but the existing `\s*\(` is needed for legibility. The fix is to skip comments, not to invent fragile regex flag combinations.

- **Extending SavestateManager beyond SRAM bank 0** — multi-bank RAM (`SWITCH_RAM(N)` for N>0) is a Phase 13 / future-emulator concern; route as a new seed if SEED-016 surfaces it.

## Common Pitfalls

### Pitfall 1: Forgetting `SceneIR.equals/hashCode` when adding `zoneRefs`

**What goes wrong:** The data class default `equals`/`hashCode` work for typical use, but `SceneIR.kt:48-79` manually overrides both because `collisionData: ByteArray?` needs `contentEquals`. Adding `zoneRefs` to the data class WITHOUT updating the manual override → two `SceneIR` instances with different `zoneRefs` are considered equal in IR-shape tests.

**Why it happens:** Override exists for `ByteArray` semantics, gets stale when fields are added.

**How to avoid:** Plan-checker MUST require any plan touching `SceneIR` to update BOTH `equals` (line ~60) AND `hashCode` (line ~70). Add a 2-line assertion in the Plan-Phase-11.1 plan-checker prompt if necessary.

**Warning signs:** `BanksIRTest > scene equality` GREEN with `zoneRefs` differing — that's the indicator.

### Pitfall 2: `SceneVisitor.visit` callers not threading `zoneBankAllocation` + `zones`

**What goes wrong:** SceneVisitor.visit gains new optional params. The default-empty path silently emits NOTHING for the zone-load — banks generates with no `_bkg_tiles_load_banked` call in `play_enter` → INV-2 stays RED post-fix.

**Why it happens:** Default parameters preserve compile-time backwards compatibility but silently allow callers to skip the wiring.

**How to avoid:** Make `SceneVisitor.visit` REQUIRE the new params (no defaults) if `scene.zoneRefs.isNotEmpty()`. Alternative: emit a `check(zoneBankAllocation.containsKey(zoneId)) { ... }` runtime guard inside the visitor.

**Warning signs:** banks INV-2 RED post-fix when JVM emission test runs; bank1.c does not contain the helper call.

The current codebase does NOT emit such calls (CEmitter writes `foo(x)`), so the alternative is safe. But the skip-comments variant is safer because it preserves the regex unchanged for code lines.

**Why it happens:** Aesthetic preference for tighter regex; comments-are-data oversight.

**How to avoid:** Recommended fix = skip-comments variant. Adds an explicit `line.trimStart().startsWith("//")` filter. Plan should include a JVM-tier sentinel that:
1. RED: asserts banks `main.c` does NOT contain `// Trampoline: pause_enter (bank 1)` for the title trampoline section comment (or, less brittle: `assertFalse(mainC.contains("title_enter_trampoline"))`).
2. GREEN after the fix: no `title_enter_trampoline` symbol at all (because dedup correctly skips the section comment text; the trampoline filter `slot.bank > 0` already excludes title since title is now in bank 0 — actually, banks's title scene IS in bank 1 per `BankingAnalysisPass` FFD ordering: title, pause, play all sized small enough to fit in bank 1. Let me re-verify).

### Pitfall 4: SavestateManager file-format change breaks existing `.gbst` files

**What goes wrong:** Older `.gbst` files (8483 bytes, magic="GBST") get re-read by the new SavestateManager which expects 16675 bytes. The read overruns to EOF; SRAM bytes silently become 0xFF or 0x00.

**Why it happens:** SRAM is appended to the binary format; magic unchanged; no version field.

**How to avoid:** Either bump magic to "GBST2" (recommended) OR add a 1-byte version field after magic. NOT a backwards-compat shim — `.gbst` files are session-scoped per test run, so a hard incompat is acceptable for D-06's NARROW fix.

**Warning signs:** `SavestateManagerTest` (in `gbkt-emulator/.../SavestateManagerTest.kt`) fails when reading a pre-fix file.

### Pitfall 5: Anchor 4 SRAM byte may be all zeros at first read

**What goes wrong:** Banks's SRAM `saveFlag` defaults to 0 (`var saveFlag by u8Var(0)`). On first Select press, `save_game_saves(0u)` writes `_saveFlag` (=0) to SRAM[0]. Sentinel byte (171=0xAB) is written to SRAM[1]. Pre-roundtrip `read(0xA000, 4)` = `[0, 0xAB, 0, 0]` (slot 0 + 0-init slot 1). Post-roundtrip same. Assertion `pre == post` passes EVEN IF SavestateManager doesn't capture SRAM, because both pre and post read uninitialized SRAM (Coffee-GB MemoryBattery defaults).

**Why it happens:** The "saved" value is 0, indistinguishable from default. Reading SRAM after save_state+load_state shows the ACTUAL SRAM in the emulator's RAM (which load_state didn't touch). If load_state doesn't preserve SRAM, the SRAM stays at its post-save value = pre value. Test passes by accident.

**How to avoid:** Before saving, write a non-zero value into `saveFlag` (e.g., via DSL: change `var saveFlag by u8Var(42)`, or change the test to step a frame that triggers a save with a non-zero value). Alternatively, the test should:
1. Press Select → write 0 (default saveFlag) → SRAM[0]=0, SRAM[1]=0xAB
2. **Write a different value via `agent.writeMemory(0xC000+saveFlagOffset, 99)` BEFORE second Select** — ensures the second save writes a distinct value.
3. Press Select again → SRAM[0]=99, SRAM[1]=0xAB
4. save_state → load_state → SRAM[0] MUST still be 99 (proves SRAM round-trip works).
5. Without SavestateManager extension, post-load SRAM[0] = ??? — actually, since load_state DOESN'T TOUCH SRAM, the SRAM[0]=99 stays at 99. The test STILL PASSES.

Wait — this is exactly the SEED-016 RESEARCH §Pitfall 3 dilemma. Per the 11-UAT.md Anchor 4 recipe: GBST save_state/load_state is the "reboot substitute" because emulator_stop+emulator_start would re-init SRAM. But save_state+load_state doesn't actually exercise SRAM persistence (it just doesn't TOUCH SRAM, which is also what an in-process MemoryBattery does).

**The Anchor 4 spec is actually testing the wrong thing.** It tests that the SaveDataBuilder write path produces a write to SRAM — which is what INV-4 (codegen tier) already locks. The "round-trip" via GBST doesn't add information beyond "the write persists across an in-process save+load cycle that doesn't touch SRAM".

**For D-06 outcome attribution:**

- If the planner adopts the **broad interpretation** of Anchor 4 — "post-roundtrip SRAM byte equals pre-roundtrip SRAM byte" — then the test trivially passes today (because neither pre nor post SRAM is mutated by save_state+load_state). The SavestateManager extension is unnecessary. Outcome **(1) codegen-tier only** lands: Anchor 4 ships GREEN with the @Test as written.
- If the planner adopts the **strict interpretation** — "save_state+load_state must SNAPSHOT the SRAM state at save time and RESTORE that snapshot at load time, such that any mutation between save and load is REVERTED by load" — then SavestateManager MUST include SRAM. Outcome **(2) narrow SavestateManager fix** lands.

**Recommendation for the planner:** Adopt the STRICT interpretation (per Anchor 4's literal spec: "the SRAM bytes at 0xA000 contain the saved value [pre] ... STILL contain the same value [post]"). The strict interpretation is what users actually care about; trivial-pass is a hollow GREEN. Therefore route SEED-016 to outcome (2) — NARROW SavestateManager extension. This is what the user's CONTEXT.md D-06 anticipates by mentioning the "NARROW extend SRAM 0xA000–0xBFFF" route as a first-class outcome.

The Anchor 4 @Test must therefore include a write-between-save-and-load step:

```kotlin
@Test fun `anchor 4 SRAM persistence via GBST round-trip`() {
    newAgent().use { agent ->
        agent.stepN(10)
        agent.waitForScene("play", maxFrames = 120)
        agent.step(setOf(Button.SELECT))          // trigger save (writes _saveFlag=0 to SRAM[0])
        agent.stepN(2)
        val preBytes = agent.readMemory(0xA000, 4)   // [0, 0xAB, ?, ?]
        agent.saveState("anchor4-pre")
        // Mutate SRAM mid-roundtrip — proves load_state RESTORES the snapshot.
        agent.writeMemory(0xA000, 99)             // SRAM[0] := 99
        agent.loadState("anchor4-pre")
        val postBytes = agent.readMemory(0xA000, 4)  // MUST be [0, 0xAB, ?, ?] post-load (SRAM restored from snapshot)
        assertEquals(preBytes.toList(), postBytes.toList(),
            "SRAM round-trip MUST preserve byte values (D-06 NARROW SavestateManager fix). " +
            "pre=$preBytes post=$postBytes")
    }
}
```

If SavestateManager does NOT include SRAM, this test FAILS (post is `[99, 0xAB, ?, ?]`). If SavestateManager DOES include SRAM (post-fix), this test PASSES (post is `[0, 0xAB, ?, ?]`). Clean RED→GREEN cycle.

**Warning signs:** If the test author writes the simpler "trivial roundtrip" recipe from 11-UAT.md verbatim, the test will pass today and obscure the SavestateManager gap. Plan-checker MUST surface this and require the mutate-between-save-load variant.

for ((dupName, canonicalName) in callSiteRedirects) {

## Technical Approaches (Claude's Discretion Resolutions)

### D-claude-1 (DSL surface): Option (i) — scene-block `zone(playZone)` method

**Decision:** Option (i).

**Rationale:**
- Matches existing scene-builder DSL idioms (`tileset()`, `palette()`, `music()`, `collisionData()` all live as builder methods on `SceneBuilder`).
- Discoverable via IDE autocomplete; user writes `scene("play") { zone(<Ctrl-Space>) }` and gets the list of declared ZoneRefs.
- IR change is minimal (`SceneIR.zoneRefs: List<String>`); the field-by-id pattern mirrors `SceneIR.actorIds: List<String>` (already present, line 38).
- No magic-string violations: `zone(playZone)` takes a `ZoneRef`, which is created at the property-delegate site (`val playZone = zone("play_zone") { ... }`). The `ZoneRef.id` carries the property-derived name. Compliant with `feedback_no_magic_strings`.
- Option (ii) (`playZone.loadInScene(playScene)`) requires a forward-resolved `SceneRef`, which is brittle (banks declares scenes in reverse order to satisfy SceneRef.id resolution — pause first, then play with `navigate(pauseScene)`). The binder side would force re-ordering.
- Option (iii) (auto-bind by analysis pass) is rejected per CONTEXT `<deferred>` ("too magical").

**Concrete syntax (banks edit):**

```kotlin
// Banks.kt:88 — current:
scene("play") {
    enter { showSprites() }
    frame { ... }
    exit { hideSprites() }
}

// Banks.kt:88 — post-fix:
scene("play") {
    zone(playZone)             // NEW (D-claude-1 option i)
    enter { showSprites() }
    frame { ... }
    exit { hideSprites() }
}
```

The `zone()` call accumulates into the scene's `zoneRefs`; if called multiple times in one scene, the IR holds multiple zone IDs (planner may want to add a `require(zoneRefs.size <= 1)` guard for 11.1 since multi-zone is deferred — recommend doing so to fail-fast on accidental multi-zone usage).

### D-claude-4 (Anchor 4 test method assertion shape)

**Decision:** Mutate-between-save-and-load recipe (§Pitfall 5).

**Rationale:** A trivial roundtrip (read-save-load-read) passes today because SavestateManager doesn't touch SRAM — pre and post both reflect the un-mutated SRAM state. To genuinely exercise the round-trip, the test must mutate SRAM AFTER save_state and BEFORE load_state, then assert load_state restored the original.

**Concrete @Test (verified against existing `BanksUatTest` style; uses `agent.writeMemory(addr, byte)` — verify this method exists on StepAgent at plan time; if not, use direct `agent.session.emulator.getMemory().writeByte(...)`):**

```kotlin
@Test
fun `anchor 4 SRAM persistence via GBST round-trip`() {
    newAgent().use { agent ->
        agent.stepN(10)
        agent.waitForScene("play", maxFrames = 120)

        // First save: writes default _saveFlag (=0) to SRAM[0]; sentinel 0xAB to SRAM[1].
        agent.step(setOf(Button.SELECT))
        agent.stepN(2)
        val preBytes = agent.readMemory(0xA000, 4)
        agent.saveState("anchor4-pre")

        // Mutate SRAM[0] between save and load — without SavestateManager SRAM extension,
        // load_state will NOT restore SRAM, so post != pre.
        agent.writeMemory(0xA000, 99)
        agent.loadState("anchor4-pre")
        val postBytes = agent.readMemory(0xA000, 4)

        File(EVIDENCE_DIR, "anchor4-sram-persistence.txt").writeText(
            "pre: ${preBytes.toList()}\npost: ${postBytes.toList()}\nmatch: ${preBytes.contentEquals(postBytes)}\n"
        )
        assertContentEquals(preBytes, postBytes,
            "SRAM round-trip MUST preserve byte values mid-cycle mutation. " +
            "pre=${preBytes.toList()} post=${postBytes.toList()}. " +
            "Root cause if FAIL: SavestateManager does NOT capture 0xA000-0xBFFF (D-06 narrow fix)."
        )
    }
}
```
