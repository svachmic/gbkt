- **Provenance — pre-existing:**
  - Identical failure documented in `.planning/phases/11.2-tileset-pipeline-set-bkg-data-emission/deferred-items.md` §"Pre-existing RPG character codegen extern/declaration mismatch", verified at pre-Phase-11.2 base commit `dfe52566`.
  - Identical failure documented in user memory `project_rpg_char_codegen_debt.md` (2026-05-20).
  - Phase 11.1 changes (plans 01–08) touched zone-tilemap codegen (`SceneIR`, `SceneBuilder`, `GBDKPipelineV2`, `SceneVisitor`, postprocess passes), `SavestateManager.kt`, and `Banks.kt`. NONE of these paths emit `_char_*` symbols.
- **Why not auto-fixed (Rule 4 not Rule 1/2/3):** Per memory `feedback_route_to_proper_phase_when_blast_radius_is_wide.md`, system-wide codegen / type-system changes must NOT be inline-patched. The defect affects `gbkt-genre-rpg` character codegen + `gbkt-backend-gbdk` character visitor + `Character` DSL builder. The fix requires a discuss-phase to decide which side is authoritative (extern in `.c` vs declaration in `.h`) and what type RPG stats are (`UINT8`?).
- **Absorption per CONTEXT D-14 + Plan 09 `<behavior>`:** The plan's own `<behavior>` block explicitly authorizes this path: "If the failure is genuinely outside the seed cluster, capture as a new seed file in `.planning/seeds/` bound for Phase 13 / a future emulator phase." Per CONTEXT D-14, no Phase 11.1.1 escalation is permitted; absorption via seed-capture is the documented path.

### 2. [Rule 3 — Blocking] Switched sweep invocation from `--parallel` to `--continue`

- **Found during:** Initial Task 1 invocation with the plan's literal command line `./gradlew ... --parallel`.
- **Issue:** Gradle's `--parallel` mode aborts the entire build on the first task failure. The first run produced `BUILD FAILED` at `:gbkt-examples:dungeon:compileRom` and never executed `:gbkt-examples:racer:clean :gbkt-examples:racer:buildRom`. This masked the racer GREEN result and prevented honest per-game accounting.
- **Fix:** Re-ran the sweep with `--continue` (instead of `--parallel`). `--continue` allows independent tasks to continue executing after a failure, producing per-game pass/fail for all 4 games. This is consistent with the plan's `<behavior>` intent ("Inspect the log tail for `BUILD SUCCESSFUL` vs `BUILD FAILED`. If FAILED, follow CONTEXT D-14 absorption rule") — we need per-game accounting to apply the absorption rule per-game.
- **Files modified:** `evidence/regression-sweep-buildrom.log` (now reflects the `--continue` run, not the `--parallel` run).
- **Commit:** `fd655183` (Task 1)
