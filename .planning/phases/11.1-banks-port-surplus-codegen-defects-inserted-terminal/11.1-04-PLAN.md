<interfaces>
Per CONTEXT D-01 (scoped DSL exception, cites Phase 10.1 D-13 precedent) and D-02 (no automatic Phase 13 follow-up):

The new `zone()` DSL method takes a typed `ZoneRef` — created at the property-delegate site (e.g., `val playZone by zone("play_zone") { tileset(asset("tiles/checker.png")) }`). `ZoneRef.id` carries the property-derived name (no magic strings, per memory `feedback_no_magic_strings`). DSL takes typed `ZoneRef`; IR stores `String` (zoneRef.id). This asymmetry matches the existing `actorIds: List<String>` convention on SceneIR.

`SceneIR.zoneRefs: List<String> = emptyList()` — default empty preserves backwards compatibility for all 4 zone-having games' existing scenes (dungeon, explorer, racer use the ExplorationSystem path per D-03 and need no opt-in).

SceneBuilder accumulator pattern follows the existing `music(musicRef: MusicRef)` / `paletteOps` shape: private `mutableListOf<String>()`, populated by `zone()` calls during DSL recording, propagated to `SceneIR(...)` constructor at `build()` time.
</interfaces>
