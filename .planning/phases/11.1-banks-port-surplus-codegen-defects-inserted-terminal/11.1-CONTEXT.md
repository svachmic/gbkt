Phase 11 (banks port). It closes 3 seeds (SEED-014, SEED-015, SEED-016) and executes
the deferred Phase 11 Anchor 4 UAT, then re-shoots Phase 11's Anchor 1 + Anchor 2
visual evidence into Phase 11's own evidence directory (cross-phase coupling per

follow-up subphase is permitted. Surplus discoveries inside the seed cluster are
ABSORBED by splitting a plan or inserting a plan; surplus genuinely outside the
cluster routes to NEW seeds bound for Phase 13.

The fix shape locked by this CONTEXT is a deliberate SCOPED EXCEPTION to the Phase 9 /
Phase 10 / Phase 11 anti-overfitting D-overfitting-1 "no new DSL features" cap. SEED-014
requires a small NEW DSL surface (a scene-to-zone binder; exact syntax planner discretion)
that lets a game declare zone tilemap loading without forcing it to import an
`ExplorationSystem`. The exception is justified the same way Phase 10.1 D-13 justified
`MoveMetasprite` var-ref IR fields: it is the smallest surface that allows the seed to
close honestly, AND it removes a structural coupling that would re-surface in every
future port that has zones but no genre system (Phase 12 platformer_template is the next
likely consumer).

## Implementation Decisions

### Anti-overfitting doctrine (inherited from Phase 9 / 10 / 11 — overarching guardrail)

- **D-overfitting-1 (inherited):** Do not add DSL features just to make THIS port
  pretty. RE-EMPHASIZED here: the scene-to-zone binder DSL (D-01) is a SCOPED
  EXCEPTION justified by SEED-014 honesty, not a license for further DSL surface.
- **D-overfitting-2 (inherited):** Do not tune codegen visitors to banks's shape.
  SEED-014 fix must work for any game with zones + no genre system, not just banks.
- **D-overfitting-3 (inherited):** Do not let GBDK reference style become THE gbkt
  style. The SEED-014 fix is about gbkt's own internal coupling (zone-load tied to
  ExplorationSystem), not about matching reference's banking shape.

### SEED-014 fix architecture (THE wide-blast-radius decision)

- **D-01: Add minimal scene-to-zone binder DSL surface.** SCOPED EXCEPTION to
  D-overfitting-1, justified by Phase 10.1 D-13 precedent (`MoveMetasprite` var-ref
  fields). The surface lets a game declare which scene(s) load which zone(s) on
  enter, without forcing the game to declare an `ExplorationSystem`. Exact syntax is
  planner discretion (D-claude-1) — plausible shapes: `scene("play") { zone(playZone) }`
  inside the scene block, OR `playZone.loadInScene(playScene)` as a binder, OR a new
  IR field on `SceneIR.zoneRefs: List<ZoneRef>`. Smallest surface that closes SEED-014
  honestly. The hook is recorded in IR; the backend uses it to emit
  `_bkg_tiles_load_banked(bank, ...)` (or inline `SWITCH_ROM(N)` + `set_bkg_tiles` +
  `SWITCH_ROM(1)`) from the scene's `enter` C function. The existing
  `_bkg_tiles_load_banked` helper is un-gated from `hasSportRacing && bank > 1` to
  "any game with the new DSL hook AND a zone allocated to bank > 0".
- **D-02: Hook ships in 11.1 as scoped exception; no automatic Phase 13 follow-up
  requirement.** Phase 13's requirement list is NOT pre-edited for this hook. If
  Phase 12 (platformer_template) consumption surfaces a need to generalize (e.g.,
  multi-zone-per-scene, zone-transition declarations), route to Phase 13 via
  `/gsd-phase --edit 13` at THAT time, not now. The hook in 11.1 is the
  minimum-viable surface — the LEAST DSL the seed cluster needs to close.
- **D-03: Zone-load decoupling — DO NOT move `zone_load_X` / `zone_transition_X`
  out of `GBDKSystemVisitor.visitExplorationSystem` wholesale.** Such a refactor
  would have a much wider blast radius (touching dungeon / explorer / racer / rpg-lite
  ExplorationSystem codegen). Instead: emit a SEPARATE, minimal scene-enter
  tile-load wrapper for the new hook path, leaving the existing exploration-driven
  `zone_load_X` / `zone_transition_X` emissions untouched. Two paths coexist:
  - Games WITH ExplorationSystem: existing path (visitExplorationSystem emits
    `zone_load_X` with full tileset-reuse guard / onEnter / safeZone bookkeeping;
    transitions drive when it fires).
  - Games WITHOUT ExplorationSystem but WITH the new scene-zone binder: new path
    (lightweight `SWITCH_ROM(N)` + `set_bkg_tiles` + `SWITCH_ROM(1)` emission at the
    bound scene's enter, no tileset-reuse guard needed because banks loads exactly
    one zone). Whether this lands as a new helper in main.c (HOME-resident) or as
    inline code inside scene_enter is planner discretion (D-claude-2) — driven by
    BANKED scene_enter NOT being able to safely call `set_bkg_tiles` for non-HOME
    bank data without HOME-resident SWITCH_ROM (per Plan 07.4-30 rationale).

### SEED-015 trampoline body inheritance fix

- **D-04: Post-fix output = NO trampoline emitted for HOME-resident scenes.** The
  existing filter at `GBDKPipelineV2.kt:2186-2189` (`slot != null && slot.bank > 0`)
  already encodes this intent. The bug is somewhere DOWNSTREAM of the filter — the
  buggy `title_enter_trampoline() { pause_enter(); }` indicates either a post-process
  dedup that's rewriting bodies, a section-comment carry-over, or a wave-emission
  state leak. Researcher locates root cause; planner picks the smallest correct fix
  that preserves the "no trampoline for HOME scenes" invariant. The fix path is NOT
  "emit a no-op stub" (which would add dead code for every HOME-resident scene
  across all example games); it IS "make the existing filter actually catch the
  scenes it claims to catch".
- **D-05: SEED-015 fix includes a RED→GREEN JVM-tier sentinel test.** Asserts banks
  main.c does NOT contain `title_enter_trampoline` (or any HOME-resident scene's
  `*_trampoline` symbol). Test goes RED before fix, GREEN after. Lives in
  `gbkt-examples/banks/src/test/kotlin/.../BanksEmissionTest.kt` next to INV-1..INV-4.

### Claude's Discretion

- **D-claude-1: Exact DSL surface for the scene-to-zone binder.** Plausible shapes:
  - Option (i): `scene("play") { zone(playZone); enter { } frame { } }` — DSL
    method call inside scene block. Closest to existing scene-builder patterns.
  - Option (ii): `playZone.loadInScene(playScene)` — binder on the zone side. May
    be cleaner if we want multi-zone-per-scene later, but adds a Phase 13 churn risk.
  - Option (iii): IR-only field on `SceneIR.zoneRefs: List<ZoneRef>` with
    auto-binding driven by an analysis pass (e.g., "if a game has 1 zone and 1
    play-like scene, bind them automatically"). Too magical; rejected unless
    researcher surfaces a compelling reason.
  - Planner picks. Default recommendation: option (i) — explicit, scene-local,
    matches existing scene-builder DSL idioms.
- **D-claude-2: Backend emission shape for the scene-zone load.** Two paths
  reasonable:
  - Option (a): Emit a new HOME-resident wrapper function (e.g., `scene_play_load_zones()`)
    that contains the `SWITCH_ROM(N)` + `set_bkg_tiles` + `SWITCH_ROM(1)` sequence;
    BANKED `play_enter()` calls this wrapper.
  - Option (b): Reuse the existing `_bkg_tiles_load_banked(bank, x, y, w, h, tiles)`
    helper; BANKED `play_enter()` calls `_bkg_tiles_load_banked(2u, 0u, 0u, ...)`.
  - Planner picks. Option (b) is preferred (DRY with sport-racing's existing call
    pattern, smaller diff). Option (a) is fallback if helper signature doesn't fit.
- **D-claude-3: SEED-015 root cause hunt strategy.** Planner picks the diagnostic
  approach (binary-search the trampoline emission loop, grep for `pause_enter`
  attribution, check for any post-process visitor that rewrites trampoline bodies).
  Researcher likely surfaces the root cause; planner translates to plan steps.
- **D-claude-4: Anchor 4 test method's specific assertion shape.** Planner picks
  based on what the MCP emulator surface supports today. Plausible:
  `emulator_save_state` → `emulator_stop` → `emulator_start` (with saved state) →
  `emulator_read_memory(0xA000, 1)`. The exact API call sequence is planner
  discretion; the contract is "post-reboot SRAM byte equals pre-reboot SRAM byte".
- **D-claude-5: Regression-set smoke test invocation pattern.** Single
  `./gradlew :gbkt-examples:banks:buildRom :gbkt-examples:dungeon:buildRom
  :gbkt-examples:explorer:buildRom :gbkt-examples:racer:buildRom`, OR parallel
  Gradle worker invocations. Planner picks based on CI loop speed.
- **D-claude-6: SEED-016 Anchor 4 outcome attribution.** When the test runs, the
  planner / executor identifies whether the failure mode (if any) maps to
  outcome (1) codegen / outcome (2) SavestateManager narrow / outcome (3) wider
  emulator concern, and routes per D-06. The judgment call (especially between
  outcome 2 narrow and outcome 3 wide) is documented in the plan summary.
