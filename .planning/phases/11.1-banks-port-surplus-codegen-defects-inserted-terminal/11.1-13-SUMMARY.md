## 5 New Sentinel Test Names + Assertion Summary

1. `cross-file rewriter rewrites actual call site`
   — Asserts `foo()` in bank1.c IS rewritten to `bar()` when foo is deduped into bar via cross-file redirect. Primary contract.

2. `cross-file rewriter rewrites identifier inside string literal observed behaviour lock`
   — OBSERVED BEHAVIOUR: `printf("foo(x) called")` in bank1.c IS rewritten to `printf("bar(x) called")`. The regex `\bfoo\s*\(` matches `foo(` inside the string literal (the `(` satisfies `\s*\(`). Assertion locks current behaviour at parity with FunctionDeduplicationPass; string-literal safety is deferred (WR-01/02/03).

3. `cross-file rewriter rewrites identifier inside inline block comment observed behaviour lock`
   — OBSERVED BEHAVIOUR: `int x = 5; /* foo(y) note */ stuff;` in bank1.c IS rewritten to contain `bar(y) note`. The line does NOT start with `//`, `/*`, or `*`, so the line-prefix filter does not protect it; the regex matches `foo(` inside the comment. Locks current behaviour.

4. `cross-file rewriter identifier substring overlap is NOT rewritten as a call`
   — Asserts `foo_helper()` is PRESERVED verbatim. The `\b` word-boundary prevents `foo` from matching inside `foo_helper` because `_` is a word character. The `foo()` call on the same line IS rewritten.

5. `cross-file rewriter leading-comment-prefix line is skipped SEED-015 defense-in-depth`
   — Asserts `// Trampoline: foo (bank 1)` line is PRESERVED verbatim. The line-prefix filter (SEED-015 fix, COutputOptimizer lines 102-108) skips `//`-prefixed lines regardless of the regex change.

## Decisions Made

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Kotlin nested block comment bug in KDoc**
- **Found during:** Task 1 (compiling the test file)
- **Issue:** KDoc for sentinel 2 contained the literal text `/*` (as a backtick-quoted code example), which Kotlin treated as opening a nested block comment inside the `/** */` KDoc. This caused the KDoc to be unclosed at EOF, producing "Syntax error: Unclosed comment" at line 722.
- **Fix:** Replaced `/*` reference in the KDoc text with the plain English phrase "block-comment-start" to avoid the nested comment issue.
- **Files modified:** `COutputOptimizerTest.kt`
- **Verification:** `./gradlew :gbkt-backend-gbdk:compileTestKotlin` returned BUILD SUCCESSFUL
- **Committed in:** 84567f03 (part of task commit)

**2. [Rule 1 - Bug] assertContains 3-argument form unavailable for CharSequence**
- **Found during:** Task 1 (test compilation)
- **Issue:** `assertContains(charSequence, substring, message)` does not exist in the Kotlin test library. The 3-parameter form is only available for collections, arrays, and ranges.
- **Fix:** Changed to `assertTrue(string.contains(substring), message)` for the two affected assertions.
- **Files modified:** `COutputOptimizerTest.kt`
- **Verification:** BUILD SUCCESSFUL
- **Committed in:** 84567f03 (part of task commit)
