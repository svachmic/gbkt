# Phase 11.1 Plan 08: Anchor 1+2 Re-shoot Execution Summary

BanksUatTest anchor 1 + anchor 2 @Tests ran against the post-Plan-06 banks ROM. Both tests PASS at the JVM tier. However, both PNG screenshots remain at 413 bytes (blank DMG green screen) — the acceptance criterion of > 5000 bytes is NOT met. Root cause: SEED-014 implementation (Plans 02–06) added `set_bkg_tiles` (tile map index writing) but NOT `set_bkg_data` (tile pixel graphics loading into VRAM). Without `set_bkg_data`, tile slot 0 in VRAM is all-zeros = all-white, producing a monochrome screen regardless of tile map content.

## What Was Found

**Anchor 1 test result:**
- Test: PASSED (skipped=0, failures=0, time=0.231s)
- JSON sidecar: `current_scene: 1` (SCENE_PLAY) — scene navigation IS working
- PNG: 413 bytes — one color (230, 248, 218) = DMG green = blank screen
- Reason blank: `play_enter` emits `SHOW_BKG` + tile map write, but NO `set_bkg_data` loads tile graphics into VRAM

**Anchor 2 test result:**
- Test: PASSED (skipped=0, failures=0, time=0.297s)
- PNG: 413 bytes — same blank screen
- Reason blank: `_bkg_tiles_load_banked` calls `set_bkg_tiles` (tile map indices = `{0}` placeholder), but VRAM tile slot 0 is all-zeros = white; checker pattern requires non-zero tile pixel data

**Pre/post sizes:**
- anchor1-play-scene.png: 413 bytes (pre) → 413 bytes (post, timestamp updated)
- anchor2-tilemap.png: 413 bytes (pre) → 413 bytes (post, timestamp updated)
- Neither PNG crossed the 5000-byte threshold

**Root cause (architectural):**
The SEED-014 implementation emits the zone tile MAP load path (`set_bkg_tiles` via `_bkg_tiles_load_banked`), but does NOT emit the zone tile GRAPHICS load path (`set_bkg_data`). The `SportVisitor` pattern for racer (Plan 07.4) emits both: `set_bkg_data(0, 3, _racing_<id>_tileset)` then `_bkg_tiles_load_banked(...)`. The new SceneVisitor zone-load path (Plan 05) emits only the tile MAP call, not the tile GRAPHICS call.

Additionally, `_zone_play_zone_tiles` is `[1] = { 0 }` (1-byte placeholder, not 360 bytes of checker map), so even if `set_bkg_data` were added, the tile map would show all tile-0 everywhere (solid fill, not checker pattern).

**Two missing items for checker pattern to appear:**
1. `_zone_play_zone_tiles[360]` — 20×18 checker map with alternating 0,1 indices
2. `set_bkg_data(0, 2, checkerTileData)` — load black/white tile pixel graphics into VRAM before `set_bkg_tiles`

**What IS working (post-Plan-06):**
- `_bkg_tiles_load_banked` helper present in main.c (INV-2 GREEN)
- `play_enter` calls `_bkg_tiles_load_banked(2u, 0u, 0u, 20u, 18u, _zone_play_zone_tiles)` + `SHOW_BKG` (INV-6 GREEN)
- Cross-bank scene navigation works (anchor 1 variable evidence GREEN: `current_scene=1`)
- BANKED trampoline fires without MBC5 trap

## Deviations from Plan

**[Rule 4 — Architectural] Missing `set_bkg_data` emission in SEED-014 SceneVisitor zone-load path**

- **Found during:** Task 1 post-reshoot PNG analysis
- **Issue:** The plan expected post-Plan-06 ROM to render visible tiles (> 5KB screenshot). Actual result: 413-byte blank screen. Root cause: SceneVisitor zone-load prepend (Plans 05+06) emits `set_bkg_tiles` (tile map) but NOT `set_bkg_data` (tile graphics). Without tile graphics in VRAM, all tiles appear as the DMG background color (monochrome white).
- **Impact:** Both PNG acceptance criteria (> 5000 bytes) FAIL. Task 2 (human-verify visual content) cannot be completed until this is fixed.
- **Architectural decision required:** Adding `set_bkg_data` for zone tilesets requires:
  1. Zone tile PIXEL DATA (2bpp GBDK format) embedded in the zone bank C file alongside the tile map
  2. `set_bkg_data` emission in `SceneVisitor` before `_bkg_tiles_load_banked`
  3. Data source: either hardcoded builtin (SportVisitor pattern) for checker, or general tileset PNG→2bpp pipeline
- **Status:** BLOCKED — returned to human per CLAUDE.md Rule 4 (user decision required)
