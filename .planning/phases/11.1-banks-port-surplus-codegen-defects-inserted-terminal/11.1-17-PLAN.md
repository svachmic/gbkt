<objective>
Close ANCHOR-1+2-RESHOOT (the residual gap left open by Plan 15's CONTINGENCY (a))
by wiring the png2asset-generated tilemap data into the runtime `set_bkg_tiles`
arg in Banks's `play_enter`. The current symptom is that `set_bkg_data` correctly
populates VRAM tile slots 0 + 1 with the checker tile pixel bytes, but the
companion tile-index array (`_zone_play_zone_tiles[]`) passed to
`_bkg_tiles_load_banked` is a 1-byte `{0}` stub — so the runtime fills all
20×18 = 360 BG positions with tile index 0 (the all-white tile), and the
perceptual check at Plan 14 correctly rejects the uniform-white screenshot.

Purpose: Per Plan 15 SUMMARY's root-cause analysis, `png2asset -map` emits a
small 2×2 source-PNG map (`_zone_play_zone_tileset_map[4] = {0x00,0x01,0x01,0x00}`)
in the generated `.c` file, but this value is NOT exposed to gbkt codegen and is
NOT tiled across the zone's screen-tile grid. Phase 11.2 fixed the pixel-data
emission gap (set_bkg_data); this plan fixes the companion tile-index emission
gap by synthesizing a screen-sized tile-index array in the Gradle task pipeline
(where the PNG and dimensions are available together) and routing
`SceneVisitor`'s `_bkg_tiles_load_banked` arg through it.

Decision: option (b) — the Gradle task (`ConvertZoneTilesetsTask`) synthesizes a
**new symbol** `_zone_<id>_screen_tiles[mapWidth*mapHeight]` by tiling the
png2asset map across the zone's screen-tile dimensions; the codegen pipeline is
the consumer. NOT option (a) — pure extern reference would require the codegen
to know the source-PNG tile-grid dimensions to expand the tiling at C-emit
time, but the Kotlin codegen module has no asset-root access (`GBDKPipelineV2`
operates on IR, not files on disk). Plumbing PNG dimensions through IR or
re-reading the PNG from the backend module both inflate scope past "narrow
fix". The Gradle task already opens the PNG via `ImageIO.read(pngFile)` for
the D-C4 dimension guard at lines 182-191 — extending it to compute the
screen-tiling array is the smallest mechanically correct path.

Output: A working Banks ROM that renders the 2×2 checker pattern tiled across
the full 20×18 BG layer when `play_enter` runs. Anchor 1+2 PNGs re-shot post-fix
will be non-blank (≥ 4 distinct colours per Plan 14's perceptual helper). This
plan does NOT re-shoot the PNGs — the orchestrator re-runs Plan 15's anchor
re-shoot path after Plan 17 lands.
