<objective>
Close REVIEW CR-02 (BLOCKER) by aligning the cross-file rewriter regex in
`COutputOptimizer` with the intra-file rewriter regex in
`FunctionDeduplicationPass` — both use the call-site-shape `\b<name>\s*\(`
trailer — and adding a JVM-tier sentinel test that locks the over-match guards
(string literal occurrences, inline block comments, identifier substring
overlap) against future drift.

Purpose: Per CR-02, COutputOptimizer.kt:100 uses `\b<dupName>\b` (no `\s*\(`
trailer). This diverges from FunctionDeduplicationPass.kt:130 which uses
`\b<name>\s*\(`. The cross-file rewriter over-matches function names in C
string literals, inline block comments, multi-line block comment middles, and
forward-declaration prototypes. INV-5 is GREEN today because Banks's specific
output doesn't trigger any of those cases — but the divergence is a quiet
maintenance defect that will surface as soon as a visitor emits a function name
inside a string literal (e.g. a debug `printf` with the function name in the
format string). The line-prefix comment-skip filter at COutputOptimizer.kt:103-107
only catches `//`-prefixed and `/*`-prefixed line starts; inline block comments
and string literals remain unprotected.

Output: COutputOptimizer.kt rewriter aligned to `\b<dupName>\s*\(`. A new
sentinel test in `COutputOptimizerTest.kt` (or a new file if one doesn't exist
— verify in read_first) that asserts the three over-match guards.

This plan is independent of CR-01 work (Plans 10/11/12) and lands in Wave 7.
The fix is regex-only; the comment-skip filter at lines 103-107 stays as a
secondary defense-in-depth.
</objective>
