## Accomplishments

- Created 4 domain wrapper classes (`HashTableCollection`, `CollectionPool`, `RingBufferCollection`, `FixedSlotsCollection`) each exposing typed operation methods that emit IRColl* statements via `RecordingContext.require().emit()`
- Created `CollectionDelegates.kt` with 4 property delegate classes and 4 DSL factory functions — mirrors `U8ArrayDelegate` pattern from `Variables.kt`
- Each delegate auto-registers the IRColl* descriptor with `GameScopeContext.current` on first access (idempotent — same instance on repeat access)
- 9 tests in `CollectionDelegatesTest.kt` covering: delegate registration (4 types), idempotency (2 types), and domain class IR emission (3 types) — all pass, zero regressions across 1761 tests

## Decisions Made

- `Expr.ir` used to access underlying `IRExpression` (not `.unwrap()`) — ExpressionWrapper.kt uses `open val ir: IRExpression` as the backing field property
- Unnamed Kotlin local variables (`val _ = expr`) avoided in tests — experimental language feature; used `val accessed = ...` instead
- `buildForTest()` helper created in test file using `internal` visibility — registers dummy scenes so `GameBuilder.build()` doesn't throw, enables inspecting collection lists without full game setup
- Spotless formatting applied before commit — reformats constructor parameter lists to single-line when short enough
