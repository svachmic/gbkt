# Phase 3.1 Plan 03: GBDK Collection Codegen Summary

**GBDK backend generates fully static C code (no heap) for all 4 collection types (hash table, pool, ring buffer, fixed slots) with correct dispatch wiring in StatementCodegen, ExpressionCodegen, and GBDKCodeGenerator.generate()**

## Accomplishments

- Created `CollectionsCodegen.kt` with `generateCollectionData()`, `generateCollectionFunctions()`, `generateCollectionStatement()`, and `generateCollectionExpr()` entry points
- HashTable: linear probing with static UINT16/UINT8 arrays, `_hash()`, `_insert()`, `_lookup()`, `_clear()` functions
- CollPool: free-list bitmap with `_init()`, `_alloc()` returning INT8, `_free_slot()` functions
- RingBuffer: head/tail indices with `_push()`, `_pop()`, `_peek()` functions
- FixedSlots: bitfield active tracking (UINT8 for count<=8, UINT16 for 9-16) with `_claim()`, `_release()`, `_is_active()` functions
- All generated C uses static arrays only — zero heap allocation
- Wired `generateCollectionStatement()` into `generateDelegatedStatement()` dispatch chain
- Wired `generateCollectionExpr()` into `generateExprWithPrecedence()` else-branch delegation
- Added `generateCollectionData()` call after `generateVariables()` in `generate()`
- Added `generateCollectionFunctions()` call after `generatePoolFunctions()` in `generate()`
- 14 integration tests covering static array declarations, runtime function generation, bitfield sizing, no-heap verification, and statement codegen

## Decisions Made

- ExpressionCodegen uses `else -> generateCollectionExpr()` delegation pattern (not explicit when branches) — consistent with how mixer expressions are handled, avoids adding 7 import+branch pairs to the already-large when block
- Collection data position: immediately after `generateVariables()` — arrays must be declared before helper functions reference them
- Collection functions position: after `generatePoolFunctions()`, before scene functions — same logical grouping as other runtime helper systems
- All generated C uses GBDK C89 style: loop variables declared at top of block, `UINT8 i` for loop counters
