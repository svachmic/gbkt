**1. Expand visitExplorationSystem** in GBDKSystemVisitor.kt:

The current method generates only `exploration_move_<id>()`. Expand to generate:

a) **exploration_move_<id>()** — Keep existing d-pad movement logic. After the `_map_collision(nx, ny)` check and before updating `_player_x/_player_y`, add a TODO comment for entity obstacle detection (Plan 03 will fill this in). After position update, add a call to `exploration_step_<id>()`.

b) **exploration_step_<id>()** — NEW function. Body:
   - Increment `_exploration_step_count`
   - For each gauge in system.gauges: decrement `_gauge_<id>` by decrementPerStep. If onLowThreshold set: `if (_gauge_<id> <= threshold)` → emit onLowStatements via ScriptOpVisitor. If `_gauge_<id> == 0` → emit onDepletedStatements.
   - Emit system.stepStatements via ScriptOpVisitor (the onStep callback)
   - Call `_encounter_check_<id>()` if system has any zones with encounter tables

c) **exploration_encounter_check_<id>()** — NEW function. Body:
   - Check safe zone flag: `if (_current_zone_safe) return;`
   - If `_exploration_step_count < _encounter_safe_steps` → return (safe steps not exhausted)
   - Roll random: `rand() % totalWeight` via CCall("rand") + CBinaryExpr modulo
   - Walk encounter entries with accumulated weights to determine which encounter fires
   - For conditional entries: check the condition flag via CIf before adding to weight accumulation
   - If encounter fires: emit generic combat trigger — `_encounter_triggered = 1; _encounter_id = entryIndex;`

d) **exploration_interact_<id>()** — NEW function. Body:
   - Emit system.interactStatements via ScriptOpVisitor (the onInteract callback)
   - This function is called from the scene frame loop when the player presses the interact button (A button)
   - If interactStatements is empty, generate an empty function body (no-op)

e) **zone_load_<id>(zone_id)** — NEW function. Body:
   - Tileset reuse guard: `if (_current_tileset_id != zone_tileset) { set_bkg_data(...); _current_tileset_id = zone_tileset; }`
   - Load tilemap: `set_bkg_tiles(0, 0, mapWidth, mapHeight, _zone_<id>_tiles)`
   - Load collision data: copy zone collision into `_map_collision_data[]`
   - Execute zone onEnter callbacks via ScriptOpVisitor

f) **zone_transition_<id>(target_zone_id, edge, entry_x, entry_y)** — NEW function (Gap 7+8 from CONTEXT.md). Body:
   - **onExit callback (Gap 8)**: Before loading the new zone, execute the CURRENT zone's onExit statements via ScriptOpVisitor. Use `_current_zone_id` to look up the current zone's exit callback. Generate a switch on `_current_zone_id` that emits each zone's onExit statements.
   - **Player position mapping (Gap 7)**: After onExit, calculate entry position based on transition type:
     - If `entry_x` and `entry_y` are provided (non-0xFF sentinel): set `_player_x = entry_x; _player_y = entry_y;` directly
     - If `edge` is provided (edge-based auto-mapping): calculate from exit edge:
       - Exit EAST → `_player_x = 0; _player_y` stays same
       - Exit WEST → `_player_x = mapWidth - 1; _player_y` stays same
       - Exit NORTH → `_player_y = mapHeight - 1; _player_x` stays same
       - Exit SOUTH → `_player_y = 0; _player_x` stays same
     - Generate a CSwitch on `edge` parameter for the 4 directions
   - **Load new zone**: Call `zone_load_<id>(target_zone_id)` which handles tileset, tilemap, collision, and onEnter
   - The sequence is: onExit(current) → set player position → zone_load(new) → onEnter(new)

Use CCall, CIf, CFor, CBinaryExpr, CVarDecl, CReturn — typed C AST throughout. Use CRawCode only for GBDK hardware macros (`set_bkg_data`, `set_bkg_tiles` — these are function calls expressible as CCall).

**Important cross-module smart cast pattern**: Capture ExplorationSystem fields into local vals at the top of visitExplorationSystem (e.g., `val tileSize = system.tileSize`, `val gauges = system.gauges`). This avoids Kotlin cross-module smart cast issues documented in STATE.md.

- For each gauge in system.gauges: `_gauge_<id>` (UINT8, init gauge.initial)

Call `buildZoneData()` from `buildHomeFile()` and inject results into the main.c file after existing collision arrays (follow the `collisionArrays`/`collisionFunctions` pattern).
