## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Entity Obstacle Detection (Directive G3)
- **Blocking feedback**: Bump feedback on blocked movement (short sound/visual nudge), not silent
- **Per-entity collision modes**: Configurable per entity — block, passthrough, blockAndTrigger, overlapTrigger
  - blockAndTrigger: player stops on adjacent tile, trigger fires (entity remains wall)
  - overlapTrigger: player moves onto entity tile, trigger fires (floor trigger / pressure plate)
- **Entity-aware callbacks**: onBlocked receives the blocking entity reference — game can react differently per NPC
- **Player-only collision**: Only the player checks entity collisions. NPC-to-NPC collision is not supported
- **Runtime changeable modes**: Collision mode set at definition time by default, but a runtime setter is available for dynamic cases (e.g., doors that unlock)
- **Dual collision shapes**: Both tile-based (full grid tile) and pixel-based (hitbox) available — programmer chooses per entity
- **Auto-clear on remove**: Removing/destroying an entity automatically clears its collision
- **Multi-tile entities**: Entities can occupy multiple tiles (e.g., 2x2 boulders)
- **Pushable entities**: Included in this phase as a collision mode
  - Push direction is configurable per entity (any direction, horizontal-only, specific directions)
  - onPushed callback fires with entity reference and push direction — enables puzzle mechanics
  - Push only succeeds if destination tile is free

#### AudioMixer Implementation (Directive A5)
- **Channel groups**: Predefined defaults (music, sfx, ui) plus custom group definitions
- **Volume control**: Both mute/unmute (quick toggle) and gradual volume (0-100%) supported
- **Master volume**: Global master volume control that scales all group volumes
- **Configurable channel mapping**: DSL lets game author assign Game Boy's 4 channels (CH1/CH2/CH3/CH4) to groups
- **Built-in fade support**: fadeGroup(group, targetVolume, frames) generates per-frame interpolation
- **Persistable state**: Audio settings saveable/restorable as part of game save data
- **Priority system**: Each sound has a priority level. Higher priority can interrupt lower when channels are full
- **Auto-ducking**: Music volume automatically reduces during important SFX or dialog playback

#### Zone Transitions
- **Configurable transition style**: Per-zone transition type (cut, fade, scroll) — not one global style
- **Auto tileset reuse detection**: Engine compares tileset IDs and skips VRAM reload when adjacent zones share the same tileset. Invisible to DSL author
- **Player position mapping**: Edge-based auto-mapping as default, with override to named entry points when needed
- **Zone lifecycle callbacks**: Both onEnter and onExit callbacks available

#### Encounter System
- **Rate model**: Safe steps + random range (N guaranteed safe steps, then random chance within a range) — classic JRPG model
- **Per-zone rates**: Each zone has its own encounter configuration
- **Explicit safe zone flag**: Zones can be marked as encounter-free with a dedicated flag
- **Conditional encounter entries**: Encounter table entries can have conditions (story flags)

#### Engine/RPG Architecture Boundary
- **Interface pattern throughout**: All extension points use pluggable interfaces
- **Generic combat trigger**: Encounters fire a generic 'start combat' event. Engine doesn't know about RPG systems
- **Encounter data as interfaces**: Encounter entries define contracts, not concrete types
- **Standalone world system**: Works independently without RPG package
- **Pluggable movement**: Movement style is an interface. Grid movement is default
- **Separated state ownership**: Engine owns world state. RPG owns party/inventory/quests
- **Fully pluggable save/load**: Save system is fully interface-based
- **Presets with overrides**: World system provides preset configurations as starting points

### Claude's Discretion
- Exact bump sound/animation implementation for entity blocking
- Internal grid-to-pixel collision resolution details
- Fade interpolation algorithm (linear vs eased)
- GBDK NRxx register manipulation details for audio
- Zone transition frame budgets
- Encounter random number generation approach
- Interface naming conventions and Kotlin sealed/open hierarchy choices

### Deferred Ideas (OUT OF SCOPE)
- NPC-to-NPC collision — could be a future enhancement if pathfinding is added
- Smooth/free movement implementation — interface exists in 06.3, concrete smooth impl is a future feature
- Advanced puzzle mechanics beyond pushables (switches, pressure plates, timed blocks) — could be its own phase

## Summary

Phase 06.3 builds from a well-established V2 pipeline. The world/dungeon subsystems (world, exploration, entity) currently exist only as CLAUDE.md documentation stubs — the directories contain no Kotlin source files. The `ExplorationSystem` IR node exists but is a bare skeleton with no fields. `ExplorationBuilder` exists with minimal properties and a build() method that drops all configured data. 3. **Entity obstacle detection (G3) + AudioMixer real implementation (A5)** — add entity collision IR to gbkt-ir, extend ExplorationSystem codegen with entity grid tracking, replace AudioMixer stubs with NRxx channel-state logic

**Primary recommendation:** Follow the exact phase 06.2 pattern: IR types in gbkt-ir, DSL builders in gbkt-lang, codegen in GBDKSystemVisitor / GBDKPipelineV2. Add to GameIR the new world fields (zones, flags). Keep zero CRawCode by using CBinaryExpr for register assignments (same pattern as NR10-NR44 sound registers) and CRawCode only for GBDK hardware macros that are lvalue expansions.

## Architecture Patterns

### Pattern 1: SystemIR Extension

The `ExplorationSystem` data class in `gbkt-ir/SystemIR.kt` is currently a bare stub with only the standard `id`/`sourceLocation`/`bankSlot`/`vramRange`/`oamSlot` fields. ### Pattern 4: DSL Builder Pattern

- Builder class annotated `@GbktDsl`

### Pattern 7: AudioMixer Real Implementation (A5)

Current state: `buildAudioMixerStubs` (GBDKSystemVisitor.kt lines 625-672) generates 4 stub functions with body comments only.

Target state: Replace with real NR register manipulation following the exact `buildNRxxRegisterWrites` pattern already established:

```kotlin
// CBinaryExpr for hardware register writes — NOT CRawCode
fun nrWrite(register: String, value: CExpr): CExprStatement =
    CExprStatement(CBinaryExpr(CVar(register), "=", value))
```

Game Boy audio channel group volume control maps to:
- `NR50_REG` (master volume: bits 6:4 = left vol, bits 2:0 = right vol)
- `NR51_REG` (channel panning: bit 7-4 = L-CH4,CH3,CH2,CH1; bit 3-0 = R-CH4,CH3,CH2,CH1)
- Per-channel: NR12/NR22 (pulse envelope = volume), NR32 (wave output level)

The real implementation stores channel group mappings as global arrays and manipulates NR50/NR51 for mute/unmute:
```kotlin
// Global state (added to buildSystemGlobalVars when audio_mixer present)
// UINT8 _mixer_group_vol[3] — volume per group (0-7 maps to hardware range)
// UINT8 _mixer_master_vol = 7 — master volume (0-7)
// UINT8 _mixer_group_muted[3] — mute state per group

// set_group_volume(group, vol): scales by master, writes NR50/NR51
// mute_group(group): clears relevant NR51 bits
// unmute_group(group): restores NR51 bits from channel mapping
// fadeGroup interpolation: per-frame loop via CWhile
```

### Pattern 8: Entity Obstacle Detection (G3)

Current state: `exploration_move` in `visitExplorationSystem` has a TODO comment at line 550: `"TODO: entity obstacle detection (entity system completion)"`.

Target state: Add entity collision table after the tile collision check:
```c
// Entity collision grid (added as HOME-bank globals)
// UINT8 _entity_grid[32*32 / 8] — bit-packed entity presence
// UINT8 _entity_grid_ids[max_entities] — entity ID at each occupied cell

// In exploration_move():
// After: if (_map_collision(nx, ny)) return;
// Add:   entity_id = _entity_check_collision(nx, ny);
//        if (entity_id != 0xFF) {
//            _entity_handle_block(entity_id, nx, ny);
//            return;
//        }
```

The entity collision grid is separate from the tile collision system (which uses `_map_collision_<scene>(x,y)` switch dispatch). Entity collision uses a flat grid bitmap updated whenever entities move.

Collision mode enum values map to codegen behavior:
- `BLOCK` → return immediately (same as tile collision)
- `PASSTHROUGH` → skip entity check entirely (filtered at DSL layer)
- `BLOCK_AND_TRIGGER` → return + emit onBlocked callback with entity ref
- `OVERLAP_TRIGGER` → don't return, emit trigger callback, continue movement
- `PUSH` → check if destination tile of push is free, move entity, continue player movement

### Anti-Patterns to Avoid

- **CRawCode for register writes**: The NRxx register writes use `CBinaryExpr(CVar("NR10_REG"), "=", ...)` — NOT CRawCode. This is the established pattern. Follow it for AudioMixer NR50/NR51.
- **Dropping builder data**: The current `ExplorationBuilder.build()` returns `ExplorationSystem(id = id)` discarding all configured properties. This is the exact gap to fix — all builder fields must flow through to the IR.
- **Missing GenericSystem audio_mixer IR**: The AudioMixer is currently `GenericSystem(type="audio_mixer")` and routes to `buildAudioMixerStubs`. The fix is replacing the stubs with real logic within `buildAudioMixerStubs` (renamed to `buildAudioMixerFunctions`) — no new SystemIR type needed; GenericSystem with type config is the established extensibility pattern.
- **World codegen directory that doesn't exist**: The world CLAUDE.md references `gbkt-backend-gbdk/.../codegen/world/` but this directory is absent. World codegen goes either into new methods on GBDKPipelineV2 or a helper class — not a world/ subdirectory unless explicitly created.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Recording callbacks (onStep, onBlocked) | Custom callback capture | `recordStatements { block }` via ScriptBuilder+StatementRecorder | Established DSL recording pattern |
| Hex-format literals | `CRawCode("0x77")` | `CRawExpr("0x77u")` for hex unsigned | CEmitter pattern for hex values |
| Entity grid bit manipulation | Float/byte slice custom logic | Standard bit packing via CLiteral + bitwise CBinaryExpr | Game Boy has no stdlib |
| Random encounter RNG | Custom LFSR | `rand() % totalWeight` via CCall("rand") + CLiteral | GBDK provides rand() in stdlib.h |
| Zone tileset reuse detection | Per-frame tileset comparison | Extend existing `_current_tileset_id` guard (already in GBDKPipelineV2) | Pattern already established for scenes |

## Common Pitfalls

### Pitfall 1: ExplorationSystem Has No Fields Yet
**What goes wrong:** You attempt to read `system.tileSize` from an `ExplorationSystem` and get a compile error because the field doesn't exist.
**Why it happens:** `ExplorationSystem` was added as a skeleton in a prior phase. The build() in ExplorationBuilder drops all configured data.
**How to avoid:** First task: expand `ExplorationSystem` in `gbkt-ir/SystemIR.kt` AND update `ExplorationBuilder.build()` in `gbkt-lang/SystemBuilders.kt` in the same change.
**Warning signs:** `ExplorationBuilder.build()` currently returns `ExplorationSystem(id = id)` with nothing else — this is the signal.

### Pitfall 2: GameIR Has No Zone Fields
**What goes wrong:** Zones defined via `zone { }` in GameBuilder are never passed to codegen — the `GameIR.zones` field doesn't exist yet.
**Why it happens:** The CLAUDE.md stubs describe the design but nothing was implemented.
**How to avoid:** Add `zones: List<ZoneIR> = emptyList()` and `flags: List<GlobalFlagsIR> = emptyList()` to GameIR before writing any zone codegen.
**Warning signs:** All zone-related codegen receiving an empty list at runtime.

### Pitfall 3: AudioMixer Stubs Pass Tests But Do Nothing
**What goes wrong:** Existing MusicCodegenTest tests assert that stub functions EXIST. If you replace stubs with real implementations, you may inadvertently break tests that check for stub comment content.
**Why it happens:** Phase 06 intentionally generated stubs; tests were written to verify stub generation.
**How to avoid:** Update the AudioMixer tests in `MusicCodegenTest.kt` to assert real behavior (NR50/NR51 writes) instead of stub comments. The 3 existing tests (lines 206-268) need to be rewritten.
**Warning signs:** Tests checking for `"AudioMixer stub"` comment strings.

### Pitfall 4: Entity Grid Globals Not in buildSystemGlobalVars
**What goes wrong:** Entity collision grid arrays (`_entity_grid[]`) are referenced in `exploration_move` C code but never declared as globals.
**Why it happens:** `buildSystemGlobalVars` must be extended for the ExplorationSystem case when entity obstacle detection is enabled.
**How to avoid:** Entity grid variables follow the established `buildSystemGlobalVars` pattern — add them alongside `_player_x`, `_player_y`, `_current_floor` when any entity has a non-passthrough collision mode.

### Pitfall 5: Zone Tilemap Bank Overflow (Known Pattern)
**What goes wrong:** Zone tilemap data placed in wrong bank causes overflow (documented in project MEMORY.md as critical pitfall from LabyrinthOfTheDragon port).
**Why it happens:** `setBank(N)` must end with explicit `setBank()` not `returnToHome()` — bank state leaks.
**How to avoid:** For phase 06.3 in the V2 typed AST pipeline, assign `bank` field on `CFile` directly rather than using any bank state tracking. Zone tilemap data goes in banked C files, not main.c.
**Warning signs:** Banked .c files absorbing functions that should be in HOME bank.

### Pitfall 6: Cross-Module Smart Cast (Kotlin Compiler Limitation)
**What goes wrong:** Code like `if (system is ExplorationSystem) { val x = system.tileSize }` fails in a different module with "Smart cast to 'ExplorationSystem' is impossible".
**Why it happens:** Kotlin cannot smart cast public API properties from external modules (known project pattern — documented in STATE.md as [Phase 06.1-01] and [Phase 06.1-03]).
**How to avoid:** Capture nullable ExplorationSystem fields into local vals before use:
```kotlin
val tileSize = system.tileSize  // local val — smart cast works
val gauges = system.gauges       // local val
```

### Real AudioMixer NR50/NR51 codegen

```kotlin
// In: GBDKSystemVisitor.kt — replace buildAudioMixerStubs
// NR50_REG: bits 6:4 = L master vol, bits 2:0 = R master vol
// NR51_REG: bit routing — which channels go to L/R outputs
// Pattern matches existing buildNRxxRegisterWrites nrWrite() helper:
val setGroupVolume = CFunction(
    name = "set_group_volume",
    returnType = CVoid,
    params = listOf(CParam("group", CU8), CParam("vol", CU8)),
    body = buildList {
        // Store volume: _mixer_group_vol[group] = vol;
        add(CExprStatement(CBinaryExpr(
            CArrayAccess(CVar("_mixer_group_vol"), CVar("group")),
            "=", CVar("vol")
        )))
        // Update NR50 master volume if not muted
        add(CComment("Recalculate NR50 from master + group volumes"))
        add(CExprStatement(CBinaryExpr(CVar("NR50_REG"), "=",
            CBinaryExpr(CVar("_mixer_master_vol"), "|",
                CBinaryExpr(CVar("_mixer_master_vol"), "<<", CLiteral(4)))
        )))
    },
    sectionComment = "AudioMixer: set channel group volume",
)
```

### Entity collision check in exploration_move

```kotlin
// After tile collision check in visitExplorationSystem, add entity grid check:
```

## Open Questions

1. **Zone tilemap data format**
   - What we know: World CLAUDE.md mentions `tileset("dungeon.png")` and `size(32, 32)` in zone maps. The V2 pipeline already handles `_current_tileset_id` for scene tileset reuse.
   - What's unclear: Exact binary format for zone tilemap data (are tile indices 1 byte or 2 bytes? Is this raw arrays like `map_<scene>_collision[]`?).
   - Recommendation: Use `const UINT8 _zone_<id>_tiles[]` with 1 byte per tile (0-255 tile index range for GB), same format as the collision data arrays. Zone dimensions fit in UINT8 (max 32 tiles = 256 pixels).

2. **AudioMixer channel group IR representation**
   - What we know: `GenericSystem(type="audio_mixer")` carries `config: Map<String, Any>`. The channel group definitions (music=CH1+CH2, sfx=CH3, etc.) need to be in that config map.
   - What's unclear: Whether to define a rich `AudioMixerIR` type or keep `GenericSystem` with structured config map.
   - Recommendation: Keep `GenericSystem` approach but add a typed `AudioMixerConfig` data class as the config value — `config = mapOf("type" to "audio_mixer", "mixer" to AudioMixerConfig(...))`. Avoids adding a new SystemIR subtype and SystemIRVisitorI method, which would require updating all visitors.

3. **Encounter RNG approach**
   - What we know: Game Boy has no stdlib rand() in GBDK without including stdlib.h. The encounter check needs a pseudo-random number.
   - What's unclear: Whether to use GBDK's `rand()` (from stdlib.h) or a custom LFSR inline.
   - Recommendation: Use `rand()` from `<stdlib.h>` — GBDK includes it and it's a single C function call expressible as `CCall("rand", emptyList())`. The modulo pattern `rand() % totalWeight` is `CBinaryExpr(CCall("rand", ...), "%", CLiteral(totalWeight))`.

4. **Where does zone tilemap bank allocation happen?**
   - What we know: Zone tilemaps are large data arrays that must be banked. The V2 pipeline uses CFile.bank for bank assignment.
   - What's unclear: Whether zone tilemap data goes in the same bank as the zone's scenes or in dedicated data banks.
   - Recommendation: For Phase 06.3 simplicity, emit zone tilemap data as `const UINT8` arrays in main.c (HOME bank, bank 0) for small games. Add bank annotation support as a follow-up when LabyrinthOfTheDragon is ported in Phase 06.7.
