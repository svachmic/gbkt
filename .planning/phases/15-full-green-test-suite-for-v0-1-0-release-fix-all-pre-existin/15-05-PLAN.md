and labels it a trivial correction. Research (Pitfall 1) and a direct source read
(`gbkt-examples/platformer-template/build/gbkt/generated/sprites/player.c:143`;
`main.c:70` comment) prove this is insufficient. The real correction is four-part:
(a) SOURCE — read on-disk `build/gbkt/generated/sprites/player.c`, not in-JVM
`pipelineOutput.files["main.c"]`; (b) SYMBOL — target `player_metasprite0` (the
per-frame array), NOT `player_metasprites` (the pointer table) and NOT
`sprite_player_frame_0`; (c) PARSER — match `METASPR_ITEM(dy, dx, tile, S_PAL(..))`
macros, not `{int,int,int}` braces; (d) ASSET ACQUISITION — the file is a Gradle
build artifact, so the test must obtain it (wire `tasks.test` to depend on the
sprite-generation task, skip gracefully if genuinely absent). This deviation from
D-04 is honored because D-04 is provably under-scoped, not because the planner judged
it inconvenient; it is recorded in the diagnosis ledger.
