# Phase 13.6 — REQ-6 regression: byte-identity guard broken by non-deterministic permute temp name

**Found by:** execute-phase regression gate, 2026-06-05 (after plans 01–06 + binding sign-off).
**Severity:** blocking for REQ-6 (byte-identity regression oracle). NOT a visual/runtime
regression — the elephant tile data is byte-identical and renders correctly (Task 2/3 APPROVED).
**Disposition:** routed to gap-closure plan **13.6-07** (user decision). Phase 13.6 NOT complete.

## Symptom

`:gbkt-examples:metasprites-stress:test` and `:gbkt-examples:metasprites:test` fail their
`*GeneratedSpriteByteIdentityTest` cases with `IllegalStateException` (the test's own
`error()` on byte mismatch) on a clean rebuild:

```
MetaspritesStressGeneratedSpriteByteIdentityTest > generated elephant_tiles ... FAILED
MetaspritesStressGeneratedSpriteByteIdentityTest > generated tiger_tiles ... FAILED
```

Plan 05 captured the baselines once and they passed in that session; they do NOT survive a
clean `:convertSprites` rerun.

## Root cause

The diff between each re-pinned baseline and a freshly generated `<sprite>.c` is **exactly one
line** — the png2asset "Conversion args" comment, which echoes the input PNG path:

```
< // Conversion args: /gbkt_permuted_11371562937861264601.png -o /elephant.c -spr8x8 -px 0 -py 0 -sw 64 -sh 48 -noflip -keep_palette_order
> // Conversion args: /gbkt_permuted_9285651522261017614.png  -o /elephant.c -spr8x8 -px 0 -py 0 -sw 64 -sh 48 -noflip -keep_palette_order
```

`prePermuteIndexedPng` (Plan 13.6-03, `gbkt-gradle-plugin/.../tasks/PngUtils.kt`) creates the
permuted PNG with a **random** temp filename (`File.createTempFile("gbkt_permuted_", ".png")`
or equivalent). png2asset records that random path in a comment in the generated C, so the
generated C is non-deterministic across rebuilds. All sprite tile DATA is byte-identical;
only the comment differs.

Confirmed for all three re-pinned baselines:
- `gbkt-examples/metasprites/src/test/resources/baseline/elephant.c.baseline` (px 32 py 24)
- `gbkt-examples/metasprites-stress/src/test/resources/baseline/elephant.c.baseline` (px 0 py 0)
- `gbkt-examples/metasprites-stress/src/test/resources/baseline/tiger.c.baseline` (px 0 py 0)

## Recommended fix (for 13.6-07)

Make the permute temp filename **deterministic and unique per sprite** so the generated C is
reproducible (a real reproducible-build property, not a test workaround):

- In `prePermuteIndexedPng` / its `ConvertSpritesTask` call site, name the permuted file from
  the source sprite base name (e.g. `<buildTmp>/gbkt_permuted_<spriteBaseName>.png`) instead
  of a random `createTempFile`. Unique per sprite → no elephant/tiger collision; stable across
  runs → the "Conversion args" comment is reproducible.
- Re-pin all three baselines from the now-stable output.
- Re-run `:gbkt-examples:metasprites:test` + `:gbkt-examples:metasprites-stress:test` → GREEN.
- Re-run a clean `:gbkt-examples:metasprites:buildRom` (and metasprites-stress) → EXIT 0.

This fix also reduces the temp-leak window flagged in 13.6-REVIEW.md (WR-01 / WR-04): a
deterministic build-dir path is easier to clean up reliably than a root-TMPDIR random file.
