## Open Question 2 / Pitfall 7 — CLOSED

**S_PAL(0) descriptor count after permutation: 161 (not 149 as estimated)**

The plan specified 149 S_PAL(0) descriptors (matching the pre-fix committed baseline). After Plan 03's permutation landed, the actual generated output has **161** S_PAL(0) descriptors.

**Why the count changed (correct behavior, not a regression):**
- Pre-permutation: 256-entry PLTE (sparse), png2asset deduplicates tiles using all 256 palette entries as identity. Some tiles assigned S_PAL(1) (different sub-palette group). `remapMetaspriteSubPalette` rewrites these to S_PAL(0) → 149 total.
- Post-permutation: compact 4-entry PLTE (dense, all used). Different palette layout changes png2asset's tile deduplication key → 5 frames × 32-33 METASPR_ITEM each = 161 entries. All directly assigned S_PAL(0) by png2asset (no S_PAL(1) exists). `remapMetaspriteSubPalette` runs and finds 0 entries to rewrite.

**Implication for Plan 05:** The byte-identity baseline re-pin (Plan 05) must use **161** S_PAL(0) as the validated anchor, NOT 149.

`MetaspritesGeneratedSpriteByteIdentityTest` fails with the current pre-fix baseline — this is **expected** and will be resolved in Plan 05's baseline re-pin.
