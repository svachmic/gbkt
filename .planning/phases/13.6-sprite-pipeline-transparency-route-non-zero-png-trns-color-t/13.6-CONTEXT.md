# Phase 13.6: sprite-pipeline transparency — route non-zero PNG tRNS color to GB OBJ index 0 - Context

**Gathered:** 2026-06-05
**Status:** Ready for planning

<domain>
## Phase Boundary

The sprite asset pipeline routes a PNG's declared transparent color (tRNS) to Game Boy
2bpp OBJ index 0 regardless of source palette order, so a normally-authored indexed
sprite (transparent on a non-zero index) renders with all visible colors intact. Default
behavior auto-corrects with a build WARNING; an opt-in strict mode hard-fails the mismatch
instead. Sprite-OBJ-only — BG/world palette inversion and zone-tileset tRNS are explicitly
out of scope (routed to Phase 13.7).

</domain>

**In scope (from SPEC.md):**

- Auto-routing the tRNS color to GB OBJ index 0 in the sprite conversion path (`ConvertSpritesTask` / `buildPng2AssetArgs` / png2asset invocation), preserving visible-color relative order.
- Build-time WARNING naming each auto-corrected sprite.
- Opt-in strict-mode `gbkt {}` extension knob that hard-fails the mismatch.
- OBJ palette overflow guard (fail on >3 used visible colors after routing).
- Baseline re-pin for `metasprites` + `metasprites-stress` (elephant + tiger).
- D-17 7-target buildRom regression sweep + binding human Visual Evidence sign-off via MCP reshoot.

**Out of scope (from SPEC.md):**
- BG/tilemap/world palette inversion (platformer world + player background) — routed to **Phase 13.7** (diagnose-first); 13.6 is sprite-OBJ-only.
- `ConvertZoneTilesetsTask` / zone-tileset tRNS handling — behavior change is sprite-scoped (parse code MAY be shared, but no zone-tileset behavior changes here).
- Reverting/altering the 13.3-22/24 ascending-ramp polarity fix or the 12.9 D2a `-keep_palette_order` behavior for index-0 sprites — regression oracles, not targets.
- Editing the authored PNG assets to pre-canonicalize them — framework-side fix only (user decision 2026-06-04).
- Actively dropping/renumbering unused palette colors as a *feature* — "reorder transparent→0 only"; unused entries are merely excluded from the overflow count, not rewritten.

<decisions>
## Implementation Decisions

### Strict-mode knob shape (DSL surface)
- **D-01:** The opt-in strict knob lives in a **new `sprites { }` sub-extension** of `gbkt {}`:
  `gbkt { sprites { strictTransparency.set(true) } }`. This mirrors the existing
  `emulator`/`web`/`output`/`optimization` sub-extension pattern (see `GbktExtension.kt`),
  gives sprite-pipeline config a cohesive home with room to grow, and keeps the property name
  inferred (no magic strings). Default OFF (auto-correct), per SPEC.
- **D-02:** Planner adds a `SpritesExtension` class + a `fun sprites(action: Action<SpritesExtension>)`
  method on `GbktExtension`, and wires the convention default (`strictTransparency = false`) in
  `GbktPlugin.apply()`, then threads the flag into `ConvertSpritesTask`. Follow the precedent of
  the other sub-extensions exactly.

### Repo/example strict posture
- **D-03:** The FRAMEWORK default stays OFF (SPEC-locked). Separately, turn strict mode **ON for
  index-0-correct example(s)** — specifically the **platformer** example (player background is
  already index-0-correct via 12.9 D2a) — as a standing regression guard so no future asset
  silently breaks the index-0 invariant there.
- **D-04:** `metasprites`/`metasprites-stress` (elephant) stay on **default auto-correct** — the
  elephant IS the auto-correction demo; strict would break it. Strict + overflow hard-fail paths
  are proven by the JVM fixture tests the SPEC already mandates, not by example builds.
- **⚠ Planner gate (blocking for D-03):** Before flipping `strictTransparency = true` in the
  platformer example, the planner MUST verify that **every** sprite PNG in that example is
  index-0-correct (tRNS at index 0 or no tRNS). If any platformer sprite is tRNS-on-nonzero,
  enabling strict would hard-fail its build — in that case do NOT flip the knob there; pick a
  different verified-index-0 example or skip D-03's example-posture change and note it. This must
  not turn the D-17 platformer/simple-physics sweep targets RED.

### Unused-slot feedback
- **D-05:** On auto-route, the framework stays **silent about declared-but-unused palette slots**
  (e.g. the elephant's 0-pixel bright-green). Only the tRNS reorder WARNING (D-06) is emitted.
  Keeps build output focused. The existing opt-in `gbkt { optimization { detectPaletteWaste } }`
  is the proper home for waste reporting — do NOT duplicate or extend it from the convert task in
  this phase. Unused entries are excluded from the overflow count only (per SPEC Req 5).

### Warning wording & level
- **D-06:** Canonical auto-correction warning, emitted at **WARN level** (visible by default):
  > `sprite <name> declares transparent color at palette index N≠0; framework routed it to GB OBJ index 0 (enable strict mode to fail instead)`
  Substitute the real sprite name and the detected index N. The `(enable strict mode to fail
  instead)` hint makes the strict knob (D-01) discoverable. Exactly one such warning per
  auto-corrected sprite; building a canonical index-0 sprite prints none (SPEC Req 3).

### Claude's Discretion
- Mechanism (pre-permute palette vs png2asset transparent-color flag × `-keep_palette_order`
  interaction) is **deferred to research** per SPEC constraint — NOT decided here. Run
  `/gsd-plan-phase 13.6` WITH research.
- tRNS/PLTE parse-code placement (extend `PngUtils.kt` vs new file) is planner's call (SPEC says
  placement-agnostic). Reusing/extending `PngUtils.kt` is the natural home — it already owns the
  shared PNG-header parse (`isIndexedPngShared`).
- Exact `SpritesExtension` property type (`Property<Boolean>`) and naming follow existing
  sub-extension conventions.

</decisions>

## Existing Code Insights

- `OptimizationExtension.detectPaletteWaste` — existing palette-waste reporting home; D-05 keeps unused-slot reporting OUT of the convert task and defers to this opt-in surface.

### Established Patterns
- `ConvertSpritesTask.buildPng2AssetArgs` is `internal` file-scope specifically so the sidecar test can call it without a subprocess — keep the new logic testable the same way.
- Convention defaults set in `GbktPlugin.apply()`; tasks read extension via wired Provider — follow for the strict flag.

### Integration Points
- New tRNS parse (PngUtils) → consumed by `buildPng2AssetArgs`/conversion path → drives auto-route (Req 2), WARNING (Req 3, D-06), strict gate (Req 4, D-01), overflow guard (Req 5).
- `SpritesExtension.strictTransparency` flows `GbktExtension` → `GbktPlugin` → `ConvertSpritesTask`.
