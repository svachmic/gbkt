# Phase 13.6: sprite-pipeline transparency — route non-zero PNG tRNS color to GB OBJ index 0 — Specification

**Created:** 2026-06-05
**Ambiguity score:** 0.14 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

The sprite asset pipeline routes a PNG's declared transparent color (tRNS) to Game Boy 2bpp OBJ index 0 regardless of the source palette order, so a normally-authored indexed sprite (transparent on a non-zero index) renders with all visible colors intact — by default automatically (with a build warning), and with an opt-in strict mode that hard-fails the mismatch instead.

## Background

Game Boy hardware forces 2bpp OBJ index 0 to be the transparent slot. `ConvertSpritesTask.buildPng2AssetArgs()` (`gbkt-gradle-plugin/.../tasks/ConvertSpritesTask.kt:749-751`) appends `-keep_palette_order` to png2asset for **every** indexed PNG (added Phase 12.9 D2a, gated on `isIndexedPngShared`). That flag carries an unstated invariant: the source PNG's palette index 0 must already be the transparent/background color.

`metasprites/res/sprites/elephant.png` violates the invariant — it is a 64×240 indexed PNG with `tRNS = 4` (white background) but the **outline color (7,24,33 dark teal) at index 0**. `-keep_palette_order` faithfully preserves the wrong order: the outline stays at GB index 0 (the transparent slot) and renders see-through → the elephant loses its outline/border (visible through the ear and body). This was PROVEN by reordering a temp copy so transparent→index 0: the ~14–18% outline pixels move out of the transparent index into a visible index 1 (`.planning/seeds/SEED-PHASE-13-SPRITE-OUTLINE-LOST-NONZERO-TRNS-INDEX.md`).

Current PNG parsing (`PngUtils.kt`) reads **only** the IHDR color-type byte (indexed yes/no) — there is no PLTE or tRNS chunk parsing anywhere in the plugin. png2asset's default auto-sort is also unreliable (Phase 12.9 noted it moved the platformer player's orange background off index 0), so neither the current `-keep_palette_order` path nor a no-flag path is correct for a tRNS-on-nonzero PNG.

The fix is framework-side (the core value prop is "the framework manages GB hardware, not the author"), must NOT revert the 13.3-22/24 ascending-ramp palette-polarity fix, and must NOT regress the 12.9 D2a `-keep_palette_order` transparency fix for index-0 sprites (the platformer player). The separate BG/world palette inversion is **not** this phase — it is routed to Phase 13.7.

## Requirements

1. **tRNS transparent-index detection**: The pipeline determines the declared transparent palette index of an indexed sprite PNG by parsing its tRNS/PLTE chunks.
   - Current: `PngUtils.kt` parses only the IHDR color-type byte; no tRNS/PLTE chunk parsing exists.
   - Target: A function returns the transparent palette index of an indexed PNG (the index referenced by the tRNS chunk), or a "none" sentinel when no tRNS chunk is present or the PNG is not indexed.
   - Acceptance: For `elephant.png` the function returns `4`; for the platformer-template player sprite (transparent at index 0) it returns `0`; for a non-indexed or no-tRNS PNG it returns the "none" sentinel.

2. **Auto-route transparent → GB OBJ index 0 (default behavior)**: When an indexed sprite declares tRNS on a non-zero index, the pipeline routes that color to GB 2bpp index 0 while preserving the relative order of the visible colors. Index-0-transparent sprites are unchanged.
   - Current: `buildPng2AssetArgs` adds `-keep_palette_order` unconditionally for indexed PNGs → tRNS-on-nonzero PNGs keep their wrong order; the elephant outline (src idx 0) collapses into the transparent slot.
   - Target: After conversion, the elephant's white tRNS color lands at GB index 0 and the outline color (7,24,33) lands at a non-zero GB index; the platformer player's index-0 background stays at GB index 0.
   - Acceptance: 2bpp decode of the generated elephant tiles shows **0% outline-color pixels at GB index 0** and the outline color present at a non-zero index (≈17.9% of pixels, per the seed proof); the platformer-template player tiles are unchanged versus the pre-13.6 baseline.

3. **Build WARNING on auto-correction**: When the pipeline auto-routes a non-zero tRNS index, `ConvertSpritesTask` logs a build-time warning naming the corrected sprite and the index.
   - Current: No warning surface — the silent wrong-order conversion is invisible to the developer.
   - Target: For each auto-corrected sprite, `convertSprites` logs a WARNING of the form "sprite `<name>` declares transparent color at palette index N≠0; framework routed it to GB index 0".
   - Acceptance: Building `metasprites` prints exactly one such warning naming `elephant.png`; building a canonical index-0-transparent sprite prints no such warning.

4. **Opt-in strict mode (hard-fail the mismatch)**: A `gbkt {}` extension knob makes an index-0 ≠ tRNS mismatch a build failure instead of an auto-correction. Default (off) auto-corrects per Requirement 2.
   - Current: No such knob exists; the only behavior is the (broken) unconditional `-keep_palette_order`.
   - Target: With strict mode enabled, an indexed sprite whose index-0 ≠ tRNS color fails `convertSprites` with a non-zero exit and a clear, actionable message naming the sprite and the tRNS index; with strict mode off/default, the same sprite auto-corrects and builds successfully.
   - Acceptance: With the knob ON, building `metasprites` (elephant) fails with non-zero exit and a message naming the sprite + index; with the knob OFF/default, the same build succeeds and auto-corrects.

5. **OBJ palette overflow guard**: After routing transparent→index 0, if a sprite needs more than 3 **used** (non-zero-pixel) visible colors, the build fails fast with a clear "too many OBJ colors" error. Unused (zero-pixel) declared palette entries do NOT count toward the limit.
   - Current: No overflow check; a >4-color sprite silently mis-renders or truncates via png2asset.
   - Target: `convertSprites` fails fast, naming the sprite and the used-visible-color count, when transparent + >3 used visible colors cannot fit the 4-entry GB OBJ palette. The elephant (3 used visible after the 0-pixel bright-green) passes.
   - Acceptance: A fixture indexed sprite with 4 used visible colors + transparent fails `convertSprites` with the overflow message; `elephant.png` (3 used visible) passes. (Reconciliation: overflow is judged by **used** color count — counting the elephant's 4 *declared* visible colors would wrongly fail the phase's own primary target; see Interview Log.)

6. **Preserve prior fixes (regression oracle)**: The change must not revert the 13.3-22/24 ascending-ramp palette-polarity fix nor the 12.9 D2a `-keep_palette_order` transparency fix for index-0 sprites.
   - Current: gbkt sprite palettes are ascending (13.3-22/24); the platformer player (index-0 bg) is transparent-correct via `-keep_palette_order`.
   - Target: The player sprite conversion stays correct; gbkt sprite palette ramps stay ascending; `metasprites-stress` elephant + `tiger.png` baselines re-pinned (tiger likely shares the same tRNS-on-nonzero authoring).
   - Acceptance: Platformer-template player tiles unchanged; `MetaspritesGrayPaletteEmissionTest` GREEN; `elephant.c` baselines re-pinned for `metasprites` AND `metasprites-stress`, `tiger.png` checked/re-pinned; D-17 7-target buildRom sweep EXIT 0.

## Boundaries

**In scope:**
- tRNS/PLTE PNG-chunk parsing to find the declared transparent index (code home left to the planner).
- Auto-routing the tRNS color to GB OBJ index 0 in the sprite conversion path (`ConvertSpritesTask` / `buildPng2AssetArgs` / png2asset invocation), preserving visible-color relative order.
- Build-time WARNING naming each auto-corrected sprite.
- Opt-in strict-mode `gbkt {}` extension knob that hard-fails the mismatch.
- OBJ palette overflow guard (fail on >3 used visible colors after routing).
- Baseline re-pin for `metasprites` + `metasprites-stress` (elephant + tiger).
- D-17 7-target buildRom regression sweep + binding human Visual Evidence sign-off via MCP reshoot.

**Out of scope:**
- BG/tilemap/world palette inversion (platformer world + player background) — routed to **Phase 13.7** (diagnose-first); 13.6 is sprite-OBJ-only.
- `ConvertZoneTilesetsTask` / zone-tileset tRNS handling — the behavior change is sprite-scoped (parse code MAY be shared, but no zone-tileset behavior changes here).
- Reverting or altering the 13.3-22/24 ascending-ramp polarity fix or the 12.9 D2a `-keep_palette_order` behavior for index-0 sprites — those are regression oracles, not targets.
- Editing the authored PNG assets to pre-canonicalize them — this is a framework-side fix (per user decision 2026-06-04).
- Actively dropping/renumbering unused palette colors as a *feature* — the chosen behavior is "reorder transparent→0 only"; unused entries are merely excluded from the overflow count, not rewritten.

## Constraints

- Must NOT revert 13.3-22/24 (ascending sprite-palette ramps) or 12.9 D2a (`-keep_palette_order` for index-0-transparent sprites). Both are explicit regression oracles.
- png2asset transparent-color flag semantics × `-keep_palette_order` interaction must be researched before committing to the mechanism (pre-permute palette vs png2asset transparent flag) → run `/gsd-plan-phase 13.6` **WITH research**.
- GB OBJ palette holds exactly 4 entries: index 0 (transparent) + 3 visible.
- CLAUDE.md Visual Evidence Rule applies: "outline is visible / renders solid" is a visual truth — closure REQUIRES a runtime MCP screenshot, not just a 2bpp-decode/variable assertion (the decode test is necessary but not sufficient).
- Blast radius MEDIUM-HIGH — affects every indexed sprite; the platformer player sprite is the standing regression oracle for every change.

## Acceptance Criteria

- [ ] tRNS-index detection returns: `elephant.png` → 4, platformer player sprite → 0, non-indexed/no-tRNS → "none" sentinel.
- [ ] Generated `elephant` 2bpp tiles: 0% outline-color pixels at GB index 0; outline color present at a non-zero index (≈17.9%).
- [ ] Platformer-template player sprite tiles byte-identical to the pre-13.6 baseline (no `-keep_palette_order` regression).
- [ ] Building `metasprites` prints exactly one auto-correction WARNING naming `elephant.png`; a canonical index-0 sprite prints none.
- [ ] Strict-mode knob ON → `convertSprites` fails (non-zero exit) with a message naming the sprite + tRNS index; OFF/default → auto-corrects and succeeds.
- [ ] A >3-used-visible-color sprite fixture fails `convertSprites` with a clear overflow error; `elephant.png` (3 used) passes.
- [ ] `elephant.c` baseline re-pinned for `metasprites` AND `metasprites-stress`; `tiger.png` checked/re-pinned.
- [ ] `MetaspritesGrayPaletteEmissionTest` GREEN (13.3-22/24 ascending ramps preserved).
- [ ] D-17 7-target buildRom sweep (pong/breakout/simple-physics/metasprites/metasprites-stress/banks/racer) EXIT 0 (pong PASS\*).
- [ ] MCP reshoot: elephant outline renders solid at rot=0 (gray) AND across the pink/cyan/green cycle, zero see-through through body/ear — binding human Visual Evidence sign-off.

**Overflow reconciliation (Req 5):** Q2's literal "keep all declared entries, fail if >3 visible remain" would fail the elephant itself (4 *declared* visible colors: outline, green-midtone, unused bright-green, body). Locked accordingly; unused declared entries are excluded from the count but not actively rewritten ("reorder only").
