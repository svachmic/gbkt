## REQ-6: Deterministic Temp Name — Scheme and Directory

**Problem (gap source):** `prePermuteIndexedPng` created the permuted PNG via `File.createTempFile("gbkt_permuted_", ".png", file.parentFile)`, which produced a random numeric suffix (e.g. `gbkt_permuted_11371562937861264601.png`). `png2asset` echoes the input path into a "Conversion args" comment in the generated C, so the generated sprite C was non-deterministic across rebuilds. All tile DATA was byte-identical; only the one comment line differed — but the byte-identity oracles in the example modules (outside `pluginTest`) failed on clean rebuild.

**Fix:** Replace `File.createTempFile(...)` with:
```
File(buildTempDir, "gbkt_permuted_${file.nameWithoutExtension}.png")
```
where `buildTempDir = File(sourceDir, "sprites/tmp")` is created with `mkdirs()` at the call site in `convertSprite`.

- **Directory:** `<cSourceDir>/sprites/tmp/` — a stable build-tree location (not TMPDIR, not adjacent to source asset)
- **Filename scheme:** `gbkt_permuted_elephant.png`, `gbkt_permuted_tiger.png` — unique per sprite, deterministic across runs
- **Stale cleanup:** `temp.delete()` called before `ImageIO.write` so reruns overwrite cleanly

**Result in generated C:**
```c
// Conversion args: /gbkt_permuted_elephant.png -o /elephant.c -spr8x8 -px 32 -py 24 ...
```
(same string on every clean rebuild — the comment is now reproducible)

## WR Code-Review Fixes

### WR-01: ImageIO.write guard (PngUtils.kt)

`prePermuteIndexedPng` now wraps `ImageIO.write` in `try/catch`:
- If the write throws (disk full, encoder failure), the temp file is deleted before rethrowing
- Eliminates the orphaned-file scenario documented in 13.6-REVIEW.md WR-01

### WR-02: countUsedVisibleColors try/catch (PngUtils.kt)

`countUsedVisibleColors` body wrapped in `try { ... } catch (_: Exception) { 0 }`:
- Honors the KDoc contract "0 if the file cannot be read or is not an indexed PNG"
- Matches `getTransparentIndexShared`'s discipline (which already had try/catch)
- A malformed/truncated PNG now returns 0 instead of propagating raw IOException

### WR-04: Single try/finally for full temp lifetime (ConvertSpritesTask.kt)

`convertSprite` now wraps `buildPng2AssetArgs` + exec in a single `try { ... } finally { tempFile?.delete() }`:
- No throwing statement between `prePermuteIndexedPng` returning and the cleanup scope
- `lastArgs` variable initialized to `emptyList()` before the try block so the exit-nonzero error message can still include `Flags:` (required by `ConvertSpritesTaskFailFastTest`)

### WR-05: ASCII messages (ConvertSpritesTask.kt)

Both user-facing messages replaced U+2260 (`≠`) with ASCII:
- Strict-mode GradleException: `"$transparentIdx (index != 0, strict mode enabled)"` 
- D-06 auto-route warning: `"$transparentIdx (index != 0); framework routed it to GB OBJ index 0 (enable strict mode to fail instead)"`
- Semantically identical to D-06 canonical wording; `(enable strict mode to fail instead)` hint preserved
