## Findings

### Warnings (3)

**WR-01:** Missing-PNG GradleException in ConvertSpritesTask.kt formats "Resolved path" as `"${assetDir}/${spritePath}"` (string interpolation) instead of `pngFile.absolutePath`. On Windows, this produces mixed backslash/forward-slash separators. Functionally correct on macOS/Linux. Accepted for Phase 12.4; fix in a future cross-platform cleanup.

**WR-02:** `JSONObject(metaFile.readText())` at ConvertSpritesTask.kt:94 throws `org.json.JSONException` on malformed sidecar — not wrapped in a `GradleException` with diagnostic context. Same pattern exists in ConvertZoneTilesetsTask. Accepted as a shared DX issue; route to a future error-experience improvement plan.

**WR-03 (Recommended for fix before phase close):** `GBDKPipelineV2MetadataSpritesTest` covers only metasprite entries in `sprites[]`. The Plan 12.4-13 regression fix that re-added actor sprites to the sidecar manifest has no JVM-tier regression guard. The fix was validated by ROM smoke test only. Adding one test method to the existing test class would lock this contract.

### Info (4)

**IR-01:** ConvertSpritesTaskSidecarTest only exercises the `includePath` fallback path (field absent). No test exercises the forward path where `includePath` differs from the spritePath stem (the metasprite case). Low priority — the fallback covers the actor-sprite case which is the more common path in tests.

**IR-02:** `entry.getString("id")`, `entry.getString("spritePath")`, `entry.getBoolean("mirrorDedup")` are strict getters — they throw `JSONException` on missing keys. Safe for machine-generated sidecar. Recommend documenting this requirement in the class KDoc.

**IR-03:** `validateMetaspriteSpritePaths` function name could more explicitly state the predicate (non-null check vs path validity). KDoc is clear; rename is cosmetic.

**IR-04:** Internal field `spriteAssetPath` vs IR field `spritePath` two-name mapping is intentional and explicit in `build()`. No action needed.
