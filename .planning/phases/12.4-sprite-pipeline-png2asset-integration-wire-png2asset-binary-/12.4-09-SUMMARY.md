# Phase 12.4 Plan 09: Multi-Tile Player Metasprite Composition Summary

**One-liner:** Replaced 6 single-tile placeholder `frame { tile(0,0,N) }` blocks with 36 multi-tile `tile(dx,dy,baseId)` calls from the Plan 12.4-08 png2asset evidence table, and added `sprite(asset("graphics/player-character-gbapduck-sprites.png"))` binder.

## What Was Built

Single edit to `PlatformerTemplate.kt`'s `val player by metasprite { }` block:

1. **`sprite()` binder added** — `sprite(asset("graphics/player-character-gbapduck-sprites.png"))` inserted as the first statement inside the block (D-05). The `game_metadata.json` output now records `"spritePath": "graphics/player-character-gbapduck-sprites.png"`.

2. **36 tile() calls authored** — 6 frames × 6 tile entries each (D-03 + D-14). Layout per frame: 3 columns × 2 8x16-pair rows, using dx/dy/baseId values verbatim from the Plan 12.4-08 captured evidence table:
   - Frame 0 (idle): baseIds 0, 2, 4, 6, 8, 10
   - Frame 1 (walk1): baseIds 12, 2, 4, 14, 16, 18
   - Frame 2 (walk2): baseIds 12, 2, 4, 20, 22, 24
   - Frame 3 (walk3): baseIds 26, 28, 30, 32, 34, 36
   - Frame 4 (jump-up): baseIds 38, 40, 42, 44, 46, 48
   - Frame 5 (jump-fall): baseIds 50, 52, 54, 56, 58, 60

3. **Obsolete comment removed** — The 4-line "PHASE-12 GAP: MetaspriteBuilder.sprite() is not yet implemented" block (pre-12.4 state) was deleted and replaced with a Phase 12.4 D-03/D-14 context note.
