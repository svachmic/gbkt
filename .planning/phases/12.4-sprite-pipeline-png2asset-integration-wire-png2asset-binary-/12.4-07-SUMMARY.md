### Task 2 (regression tests)

Two test files with 3 total test methods:

- `MetaspritesGeneratedSpriteByteIdentityTest.kt` (metasprites project):
  - `generated elephant_tiles c file is byte-identical to pre-12-4 baseline` — PASS
- `MetaspritesStressGeneratedSpriteByteIdentityTest.kt` (metasprites-stress project):
  - `generated elephant_tiles c file is byte-identical to pre-12-4 baseline` — PASS
  - `generated tiger_tiles c file is byte-identical to pre-12-4 baseline` — PASS

Test design:
- Skip gracefully via `assumeTrue(generatedFile.exists())` when `:convertSprites` has not been run (CI-safe, no GBDK required)
- Load baseline from classloader `getResourceAsStream("baseline/<name>.c.baseline")` (works in both Gradle and IDE)
- On failure: emits diff-friendly message with first 5 differing byte offsets, size mismatch, and explanation of likely causes
- `assertContentEquals(baselineBytes, actualBytes)` for the assertion itself

**[Rule 1 - Bug] Removed GbdkToolchain dependency from test files**

- **Found during:** Task 2 test compilation
- **Issue:** Initial test drafts imported `io.github.gbkt.gradle.internal.GbdkToolchain` (from `gbkt-gradle-plugin`). The example projects do NOT have `testImplementation(project(":gbkt-gradle-plugin"))` in their build.gradle.kts — compilation failed.
- **Fix:** Removed the `GbdkToolchain.find()` check entirely. The generated file's existence IS the GBDK availability signal — if `build/gbkt/generated/sprites/elephant.c` doesn't exist, the test skips via `assumeTrue`. This is simpler and equivalent.
