# Phase 12.4 Plan 05: D-01b spritePath Null-Check Gate in GenerateCTask

Pre-codegen validation gate that throws `GradleException` when any `MetaspriteIR` has `spritePath == null`, surfacing the error before backend codegen runs with an actionable fix message.

## What Was Built

Added `validateMetaspriteSpritePaths(gameIR: Any)` — an `internal` package-level function in `GenerateCTask.kt` that iterates the metasprites list via reflection and throws `GradleException` on the first metasprite missing a `sprite(asset(...))` binding. Called from `executeV2Path()` after `GameBuilder.build()` returns but before the backend lookup.

## Tasks Completed

### Task 1: D-01b null-check in GenerateCTask (feat)

**Commit:** `c6a0173c`

Inserted the validation gate in `executeV2Path()` at the correct boundary point: after `gameIR` is constructed (line 362) and before `BackendReflection.findBackendForTarget(target)` (the next line). Added `validateMetaspriteSpritePaths(gameIR)` call and the full implementation as a package-level `internal fun` at the bottom of `GenerateCTask.kt`.

Implementation details:
- Uses `javaClass.getMethod("getMetasprites")` to access `GameIR.metasprites` — mirrors the file's existing reflection idiom (consistent with lines 362, 373, 374, etc.)
- Uses `javaClass.getMethod("getSpritePath")` and `getMethod("getId")` on each metasprite
- Graceful fallback: `NoSuchMethodException` is caught and silently skips validation for older IR versions (migration window safety)
- Throws first failure encountered — user fixes one at a time (matches Behavior 4 in plan)
- Error message format: `"Metasprite '<id>' is missing sprite(asset(...)) — add sprite(asset(\"<path/to/sprite.png>\")) to your metasprite { } block. ... (Phase 12.4 D-01b)"`
- No new analysis pass introduced (honors RESEARCH Scout Target 4c)

**Discovery: Worktree Gradle runs against worktree gradlew, not parent repo**

The worktree has its own complete `gradlew`. Running `./gradlew` from the parent repo
(`/Users/michalsvacha/GitHub/personal/gbkt`) routes `:gbkt-gradle-plugin:compileTestKotlin`
to the **parent repo's** `gbkt-gradle-plugin/` sources, so the worktree test file was
invisible. Running `./gradlew` from the worktree root correctly compiled the new test.

The mavenLocal `gbkt-ir-0.1.0-SNAPSHOT.jar` was stale — it did not contain
`MetaspriteIR`/`MetaspriteFrame`/`MetaspriteTile` classes. Had to run
`./gradlew :gbkt-ir:publishToMavenLocal` from the worktree to refresh the jar.
This was a setup prerequisite, not a code change.
