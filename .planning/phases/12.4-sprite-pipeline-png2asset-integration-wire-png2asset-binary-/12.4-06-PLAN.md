<objective>
Migrate the 2 metasprite-using example games (`metasprites`, `metasprites-stress`) to carry the
mandatory `sprite(asset(...))` binding per CONTEXT D-01 + D-05. Covers SPEC REQ-3 (`sprite()` DSL
adoption) and REQ-4 (asset path convention applied uniformly across in-tree games).

Purpose: After Plan 12.4-05's validation gate lands, any metasprite without `sprite()` fails the
build. This plan migrates the 2 games whose metasprites currently rely on the deleted implicit
`<assetDir>/sprites/<stem>.png` convention so they pass the gate AND so the new sidecar path
(Plans 12.4-02 → 12.4-03) drives their png2asset invocation deterministically. Generated sprite C
MUST be byte-identical pre/post-12.4 (back-compat invariant from SPEC § Constraints) — Plan 12.4-07
adds the byte-identity regression test that locks this contract.

Per RESEARCH § Key Finding #1, only these 2 games have `metasprite { }` blocks (pong/breakout/banks/
simple-physics use `actor { sprite(...) }` and do NOT need migration).

Output: 3 one-line DSL additions across 2 files. Mechanical edits. NO byte-data changes.
</objective>
