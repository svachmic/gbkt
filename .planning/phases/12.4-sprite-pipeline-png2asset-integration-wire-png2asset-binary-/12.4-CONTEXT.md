<decisions>
## Implementation Decisions

### DSL surface — `sprite(asset(...))` binder

- **D-01: `sprite(AssetRef)` is MANDATORY on every metasprite block — no
  convention fallback.** The 5 existing sprite-using games (`pong`, `breakout`,
  `banks`, `simple-physics`, `metasprites`, `metasprites-stress`) MUST be
  migrated to add `sprite(asset("sprites/<existing-name>.png"))` to their
  `metasprite { }` blocks. The previous implicit convention
  (`res/sprites/<metasprite-id>.png` derived from the include stem) is REMOVED.
  Rationale:
  - **No magic strings** (user memory `feedback_no_magic_strings.md`):
    `parseSpriteIncludes()` deriving stems from `#include "sprites/<stem>.h"` in
    `main.c` is a magic-string convention; explicit `sprite(asset(...))` flows
    the path through `AssetRef` (which carries `path: String`).
  - **Explicit > implicit:** future artists/devs can grep for the actual PNG path
    in DSL; no need to know the `_<id>` → file convention.
  - **Migration cost is bounded:** ~6 lines × 6 games = 6 mechanical edits, all
    in `gbkt-examples/<game>/src/main/kotlin/.../Game.kt`; back-compat covered
    by byte-identity test on generated sprite C.
  - **Researcher MUST scout:** Plan 12-15 / 12.3-01 `tilemap(asset(...))` +
    `tileset(asset(...))` binder pattern (ZoneBuilder), and Plan 10.1-05's
    `MetaspriteBuilder.posX()` AssignableVar binder pattern. The `sprite()`
    binder is structurally `posX()`-shape but takes `AssetRef` instead of
    `AssignableVar`.

- **D-01a: Builder method signature locked.** `fun sprite(asset: AssetRef)`
  on `MetaspriteBuilder`. Captures `asset.path` into a new
  `MetaspriteIR.spritePath: String?` field (additive, optional only for the
  migration window — see D-01b). Planner picks whether to validate the path
  at DSL time (e.g., must end with `.png`, must not contain `..`) or defer to
  ConvertSpritesTask's resolver.

- **D-01b: IR field is OPTIONAL during migration; REQUIRED at codegen.** Add
  `MetaspriteIR.spritePath: String? = null` (additive — keeps `gbkt-ir` a leaf
  module; no breaking change to JVM tests of MetaspriteIR construction). At
  codegen time, the GenerateCTask validation pass throws if any metasprite has
  `spritePath == null` (mirrors the "fail-fast at the pipeline boundary"
  pattern from D-04). Researcher: confirm whether the existing
  `ValidationPass.kt` in gbkt-analysis has an analogous null-check shape that
  this can mirror.

### ConvertSpritesTask plumbing — sidecar in game_metadata.json

- **D-02: `game_metadata.json` gains a `sprites[]` section; ConvertSpritesTask
  reads the sidecar instead of parsing `main.c` includes.**
  ```json
  // game_metadata.json (additive section)
  "sprites": [
    { "id": "player",   "spritePath": "graphics/player-character-gbapduck-sprites.png", "mirrorDedup": false },
    { "id": "elephant", "spritePath": "sprites/elephant.png", "mirrorDedup": false },
    ...
  ]
  ```
  - **Emitter:** `GBDKPipelineV2.buildMetadataFile()`
    (`gbkt-backend-gbdk/.../GBDKPipelineV2.kt:204`) — already builds the JSON
    with `actors[]` + `scenes{}`; add a `sprites[]` JSONArray iterating
    `gameIR.metasprites`, emitting `{id, spritePath, mirrorDedup}` per IR
    record.
  - **Reader:** `ConvertSpritesTask` gains an `@get:InputFile metadataFile:
    RegularFileProperty` (mirrors `ConvertZoneTilesetsTask.metadataFile` per
    Phase 12.2 D-A2). The `convertSprites` @TaskAction parses the JSON,
    iterates the `sprites[]` array, and for each entry resolves
    `{assetDir}/{spritePath}` → PNG file → png2asset. `parseSpriteIncludes()`,
    `isMetaspriteBound()`, and `isMirrorDedupOptIn()` companion-object helpers
    are DELETED (their main.c-grep semantics are subsumed by the sidecar's
    explicit `id` + `mirrorDedup` fields).
  - **Mirror-dedup migration:** the existing `MetaspriteIR.mirrorDedup`
    boolean (Plan 10.1-16) flows directly into the sidecar — no behavior
    change for the per-metasprite mirror-dedup opt-in.
  - **Output `.c` / `.h` file naming:** preserved — output stays at
    `build/gbkt/generated/sprites/<id>.c` + `.h`. The `_tiles[]` native array
    name remains `${stemName}_tiles` (derived from PNG file basename,
    matching png2asset's convention). The path-based alias remains
    `sprites_<id>_tiles` (derived from include path, matching the
    GBDKPipelineV2 `set_sprite_data()` call site).
  - **Plumbing in GbktPlugin.kt:** `convertSprites.metadataFile` wired from
    `generateC.flatMap { it.outputDir }.map { it.file("game_metadata.json") }`
    — same shape as `convertZoneTilesets.metadataFile` (line ~376).

### Frame composition source — DSL owns layout

- **D-03: User DSL `tile(relX, relY, baseId)` calls are AUTHORITATIVE; png2asset
  only provides the `_tiles[]` byte array.** MetaspriteVisitor continues to
  emit its own `sprite_<id>_frame_N[]` `metasprite_t` tables from the DSL
  `frame { tile(...) }` entries (Phase 10.1 behavior). The DSL `tile()` calls
  are NOT validated against png2asset's auto-generated metasprite_t tables;
  png2asset's metasprite output is IGNORED at codegen time (only `_tiles[]`
  byte array is consumed).
  - **Acceptance for Req 2 (multi-tile per frame):** in
    `PlatformerTemplate.kt`'s `val player by metasprite { }`, each of the 6
    frames declares ~6 `tile(relX, relY, baseId)` calls per frame (3 cols × 2
    8×16 pairs = 6 entries; per `res/README.md`'s `-spr8x16 -px 12 -py 6 -sw
    24 -sh 32` flags). Approximate total: 6 frames × 6 tiles = ~36 tile entries.
    Planner picks exact baseId values from png2asset's `_tiles[]` ordering
    (researcher scouts: run png2asset against the player PNG and capture the
    tile ordering before planning).
  - **Back-compat (metasprites + metasprites-stress):** their existing
    `tile()` calls (manually transcribed from upstream `-noflip` id space)
    stay verbatim. Generated `sprite_<id>_frame_N[]` arrays are byte-identical
    to pre-12.4 baseline. SPEC § Constraints test asserts this.
  - **Why not png2asset-owned (option A):** would require MetaspriteVisitor
    to reference png2asset's auto-symbol names (e.g.,
    `player_metasprites[][]`), creating a tight coupling between
    PlatformerVisitor / MetaspriteVisitor and png2asset's output shape. Phase
    10.1 explicitly authored the DSL-owned model; reversing it now would
    break byte-identity for metasprites/metasprites-stress.
  - **Why not DSL helper macro (option C):** premature abstraction —
    `sheet8x16(cols=3, rows=2)` is one phase's worth of DSL design + tests
    on its own. Defer to a future phase if multi-game pattern repetition
    emerges.

### Synthesis-fallback policy — all paths fail-fast

- **D-04: All 4 silent-stub paths in ConvertSpritesTask escalate to
  `GradleException` — `generateStubCFile()` + `generateStubHeader()` DELETED.**
  Mirrors Phase 12.2 Defect 7 full-delete pattern (the
  `ConvertZoneTilesetsTask.synthesizeScreenTilemap()` removal).
  - **Path 1 — Missing PNG** (`ConvertSpritesTask.kt:119-124`):
    ```kotlin
    if (!pngFile.exists()) {
        throw GradleException(
            "Sprite PNG not found: ${pngFile.absolutePath} (for metasprite '${id}')\n" +
            "  Declared at: sprite(asset(\"${spritePath}\"))\n" +
            "  Resolved path: ${assetDir}/${spritePath}"
        )
    }
    ```
  - **Path 2 — png2asset exit != 0** (`ConvertSpritesTask.kt:236-240`):
    throw with `pngFile.absolutePath` + `result.exitValue` + flags passed.
  - **Path 3 — png2asset exception** (`ConvertSpritesTask.kt:245-248`):
    throw with `pngFile.absolutePath` + caught exception message (rewrap).
  - **Path 4 — Zero-size array** (`ConvertSpritesTask.kt:358-372`):
    throw with `pngFile.absolutePath` + diagnostic "png2asset produced empty
    tile array (PNG may be all-transparent or 0×0)".
  - **NOT changed:** the `png2asset binary missing` warn-and-skip at
    `ConvertSpritesTask.kt:92-97` (SPEC § Constraints explicitly preserves
    this as the "toolchain optional" gate).
  - **Test:** `ConvertSpritesTaskFailFastTest` (was named
    `ConvertSpritesTaskSynthesisAuditTest` in SPEC) — 4 unit-level cases
    asserting each path throws GradleException with the expected message
    fragments. Existing `ConvertSpritesTaskMetaspriteDefaultTest` +
    `ConvertSpritesTaskMirrorDedupOptInTest` are DELETED (their semantics
    move into the sidecar — `isMetaspriteBound` + `isMirrorDedupOptIn`
    companion helpers are removed per D-02).
  - **SEED resolution:** `SEED-PHASE-12-CONVERTSPRITESTASK-AUDIT.md`
    frontmatter `status` → `resolved`; body amended with
    "Resolution: all 4 silent-stub paths replaced with fail-fast Gradle
    exceptions in Phase 12.4."
