<objective>
Run the D-09 ROM-build smoke sweep: clean `:buildRom` for all 6 sprite-using games (pong, breakout,
banks, simple-physics, metasprites, metasprites-stress) + platformer-template (the test target).
Capture per-game results in an evidence file. Covers SPEC § Constraints (back-compat: all 6
sprite-using ROMs must build clean), CONTEXT D-09, and the memory rule
`feedback_rom_build_smoke_test_for_codegen_phases.md` (codegen phases need a ROM-build smoke gate
before close).

Purpose: JVM-tier tests prove Kotlin code compiles + generated C matches expectations, but they
CANNOT see staleness in `build/gbkt/generated/`. The ROM-build smoke test runs the full pipeline
(generateC → convertSprites → convertZoneTilesets → compileRom → lcc) and confirms each step
succeeds end-to-end. Without this gate, a regression in the new sidecar plumbing (e.g., a
GradleException raised for a perfectly valid game) would only surface when a developer tries
`:buildRom` later — past the phase close.

This plan is a CHECKPOINT (autonomous: false) because the developer must have GBDK installed to
execute it AND because the resume-signal carries evidence the verifier needs to gate phase close.

Output: One evidence file documenting per-game pass/fail + key metrics. No source changes.
</objective>

       for GAME in pong breakout banks simple-physics metasprites metasprites-stress platformer-template; do
