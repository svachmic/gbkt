## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Actor sprites missing from ConvertSpritesTask sidecar**
- **Found during:** Initial :buildRom run for pong (first game)
- **Issue:** Phase 12.4-03 refactored ConvertSpritesTask from scanning `main.c` (parseSpriteIncludes) to reading `sprites[]` from `game_metadata.json`. The sidecar only tracked metasprites. Actor sprites (pong paddle/ball, breakout paddle/ball, simple-physics ball) still generate `#include "sprites/<stem>.h"` in main.c via `actorSpriteIncludes` code path, but no corresponding `.h` files were ever produced.
- **Fix:** `GBDKPipelineV2.buildMetadataFile()` — add actor sprites (via `gameIR.actors.mapNotNull { actor -> actor.sprite?.assetRef?.path }.distinct()`) to the `sprites[]` JSON array with `mirrorDedup=false`.
- **Files modified:** `GBDKPipelineV2.kt`
- **Commit:** 562ced65 (included with evidence commit)

**2. [Rule 1 - Bug] ConvertSpritesTask output filename derived from PNG stem, not include path stem**
- **Found during:** platformer-template :buildRom (after actor sprite fix)
- **Issue:** `convertSprite()` used `pngFile.nameWithoutExtension` as the output file stem. For platformer-template, the PNG is `player-character-gbapduck-sprites.png`, so the output was `sprites/player-character-gbapduck-sprites.h`. But main.c includes `"sprites/player.h"` (from `metaspriteSpriteIncludes` which uses `ms.id = "player"`). Also, `pathBasedArrayName` was derived from `pngRelPath`, producing `graphics_player_character_gbapduck_sprites_tiles` instead of the expected `sprites_player_tiles`.
- **Fix:** (a) Add `"includePath"` field to each sidecar entry in `buildMetadataFile()` (metasprites: `"sprites/<id>.h"`, actor sprites: path-derived). (b) `ConvertSpritesTask`: read `includePath` from sidecar; use its stem as the output file stem; derive `pathBasedArrayName` from `includePath` not `pngRelPath`.
- **Files modified:** `GBDKPipelineV2.kt`, `ConvertSpritesTask.kt`
- **Commit:** 562ced65
