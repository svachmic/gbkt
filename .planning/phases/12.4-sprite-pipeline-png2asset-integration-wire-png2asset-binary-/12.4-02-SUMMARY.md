## What Was Built

### GBDKPipelineV2.kt — sprites[] emit block

Inserted a new `sprites[]` JSONArray emit block inside `buildMetadataFile()` immediately after `json.put("zoneTilesets", zoneTilesets)` and before `return json.toString(2)`. The block mirrors the existing `zoneTilesets[]` loop shape:

- Iterates `gameIR.metasprites`
- Skips entries with `spritePath == null` via `?: continue` (migration window D-01b)
- Emits `{id, spritePath, mirrorDedup}` per lowerCamelCase D-11 keys
- Always emits `json.put("sprites", sprites)` regardless of list size — empty list produces `"sprites":[]`

### GBDKPipelineV2MetadataSpritesTest.kt — 4 test cases

New sibling test class in `io.github.gbkt.backend.gbdk.codegen.pipeline` package:

1. `emits_sprites_array_with_explicit_spritePath` — entry present with correct field values
2. `skips_metasprite_with_null_spritePath` — sprites[] length == 0 when path is null
3. `emits_mirror_dedup_true_when_set` — mirrorDedup=true reflected faithfully
4. `emits_empty_array_when_no_metasprites` — key present, array empty (not missing key)
