## Area 1 — Resolver precedence (convention vs sprite())

### Question 1: Precedence when sprite() AND convention both exist

| Option | Description | Selected |
|--------|-------------|----------|
| sprite() always wins; convention is fallback (Recommended) | If sprite() is set, use that AssetRef path. If not set, fall back to res/sprites/<id>.png. Preserves back-compat for 5 existing games (zero DSL touch). | |
| sprite() is required when convention would not match | Convention is primary; sprite() is required only for non-conforming layouts (e.g. platformer-template). | |
| sprite() is mandatory for ALL metasprites | Remove convention entirely. Every metasprite MUST call sprite(asset(...)). All 6 games migrate (~6 lines × 6 games). | ✓ |

**User's choice:** sprite() is mandatory for ALL metasprites
**Notes:** Captured as D-01. No magic-string convention. All 6 active sprite-using games (pong, breakout, banks, simple-physics, metasprites, metasprites-stress) gain one line of `sprite(asset(...))` DSL each. Migration cost (~6 lines × 6 games) accepted as bounded.

## Area 2 — Frame composition source

### Question 2: Who owns per-frame tile arrangement?

| Option | Description | Selected |
|--------|-------------|----------|
| png2asset owns; DSL frame {} count is the contract | png2asset's auto-generated metasprite_t tables drive layout. MetaspriteVisitor stops emitting its own tables. DSL frame() calls become count-only validators. | |
| DSL owns; tile() calls are authoritative (Recommended) | User declares tile(relX, relY, baseId) explicitly. MetaspriteVisitor emits sprite_<id>_frame_N[] from DSL. png2asset only contributes _tiles[] byte array. Preserves byte-identical generated C for metasprites/metasprites-stress. | ✓ |

**Notes:** Captured as D-03. Preserves SPEC § Constraints (byte-identical metasprite C for metasprites + metasprites-stress). PlatformerTemplate.kt gains ~36 explicit tile() calls (6 frames × ~6 tiles each at -spr8x16 -px 12 -py 6 -sw 24 -sh 32). Helper macro deferred.
