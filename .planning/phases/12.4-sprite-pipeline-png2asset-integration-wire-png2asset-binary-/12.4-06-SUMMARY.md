# Phase 12.4 Plan 06: Migrate metasprite examples to mandatory sprite(asset(...)) binding

**One-liner:** Added `sprite(asset(...))` binder to 3 metasprite blocks (elephant in metasprites, elephant+tiger in metasprites-stress) so the D-01b validation gate passes and ConvertSpritesTask can resolve PNG paths via game_metadata.json sidecar.

## What Was Built

- **Task 1:** In `Metasprites.kt`, the `val elephant by metasprite { }` block now opens with `sprite(asset("sprites/elephant.png"))` as its first line. The obsolete PHASE-13 comment "MetaspriteBuilder.sprite() not yet implemented" was removed and replaced with a Phase 12.4 D-01 note. The KDoc's gap item for `MetaspriteBuilder.sprite()` was also removed since Plan 12.4-01 resolved it.

- **Task 2:** In `MetaspritesStress.kt`, both `val elephant by metasprite { }` and `val tiger by metasprite { }` blocks now open with their respective `sprite(asset(...))` binders. The player actor's `sprite(asset("sprites/player.png"))` (on `ActorBuilder`) was correctly left untouched. The KDoc CR-03 comment had no reference to sprite()-less binding, so no KDoc update was needed.
