<objective>
Refactor `ConvertSpritesTask` to read from the `game_metadata.json` `sprites[]` sidecar emitted by
Plan 12.4-02 instead of grepping `main.c` includes. Delete the 3 companion-object helpers
(`parseSpriteIncludes`, `isMetaspriteBound`, `isMirrorDedupOptIn`) and the 2 orphaned test files
they back. Wire `convertSprites.metadataFile` in `GbktPlugin.kt` (mirrors `convertZoneTilesets`
plumbing at line 372). Covers CONTEXT D-02 reader side + supports SPEC REQ-1 (PNG path resolution
via sidecar) and REQ-4 (no magic strings — sidecar carries explicit `{id, spritePath, mirrorDedup}`).

Purpose: Closes the no-magic-strings gap. After this plan, ConvertSpritesTask no longer needs to
know about main.c grep conventions or comment-marker sentinels — the explicit `sprite(asset(...))`
DSL binding flows through MetaspriteIR → game_metadata.json → ConvertSpritesTask deterministically.

NOTE: This plan does NOT yet add the 4 fail-fast paths or delete `generateStubCFile`/`generateStubHeader`
— that belongs in Plan 12.4-04 (separate concern, easier review). Plan 03 keeps the existing
warn-and-continue stub paths in place; Plan 04 replaces them all with `throw GradleException(...)`.
</objective>

| Sidecar JSON → file-system resolver | `spritePath` strings from `sprites[]` flow to `assetDir.resolve(spritePath)`. An attacker who can write `game_metadata.json` could attempt path traversal (`../../etc/passwd`). |
| png2asset exec | External GBDK binary invocation — already a trust boundary in the existing code (warn-and-skip if absent). |
