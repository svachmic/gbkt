#### 7c. Tile math from png2asset flags

From `res/README.md`: player PNG uses `-spr8x16 -px 12 -py 6 -sw 24 -sh 32`.
- `-sw 24 -sh 32` = 24×32 pixel sprite frame = 3 columns × 4 rows of 8×8 tiles
- In `-spr8x16` mode (pairs of 8×8 tiles treated as one 8×16 tile), 3 columns × 2 "tile-pairs" per column = 6 `metasprite_t` entries per frame
- 6 frames × 6 entries = ~36 `tile()` DSL calls in total for the `player` metasprite

**The planner cannot fill in exact baseId values without running png2asset.** D-14 leaves this to the planner: "researcher asks the researcher to embed the expected baseId table in RESEARCH.md before planning the PlatformerTemplate DSL edit plan." 1. Runs `./gradlew :gbkt-examples:platformer-template:convertSprites` after the D-02 sidecar reader is in place
2. Inspects `build/gbkt/generated/sprites/player.c` for the `player_character_gbapduck_sprites_tiles[]` array ordering
3. Records the tile count and maps baseIds 0..N to their x/y positions in the 24×32 frame atlas
4. Only then writes the 36 `tile()` calls in `PlatformerTemplate.kt`

This first-run-capture step is a DEPENDENCY for the PlatformerTemplate DSL edit plan (see Open Questions #1).

**Planner use:** "`MetaspriteFrameBuilder` supports multiple `tile()` calls (no upper bound); 6 frames × ~6 tiles each. Schedule 'first-run png2asset capture' plan BEFORE the PlatformerTemplate DSL edit plan."

   - **Option C:** Always pass `-spr8x8` for all sidecar-driven metasprite PNGs (historically forced by `isMetaspriteBound`), add `-px -py -sw -sh` flags from a new sidecar field. But these flags aren't in the CONTEXT D-02 sidecar schema.
