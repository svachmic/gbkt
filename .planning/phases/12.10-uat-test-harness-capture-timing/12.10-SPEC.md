# Phase 12.10: uat-test-harness-capture-timing — Specification

**Created:** 2026-06-02
**Ambiguity score:** 0.19 (gate: ≤ 0.20)
**Requirements:** 5 locked

## Goal

The UAT test-harness gains a reusable settle-before-capture primitive so post-scene-transition screenshots latch the rendered frame instead of stale/blank PPU state, AND the `anchor4MetaspriteAnimation` pixel-diff threshold is recalibrated from the wrap-corruption-inflated `>10%` to a value the real ~6.60% facing-right/facing-left diff clears deterministically while still proving hflip.

## Background

This phase was spun out of the Phase 12.6 debug cycles (STATE.md lines 125–132) and bundles two surfaced UAT-harness defects:

1. **Capture-timing unreliability.** `ScreenshotCapture.capture()` (`gbkt-emulator/.../agent/ScreenshotCapture.kt:66`) renders whatever `getFrameBuffer()` holds at the instant `StepAgent.captureScreenshot()` (`StepAgent.kt:190`) is called. Immediately after a scene transition, the PPU/VRAM has not yet latched the new scene, so harness PNGs come out stale or blank — the 413-byte blank PNGs in Plan 11.1-08, and the reason Phase 12.6 fell back to *direct MCP capture* and recorded "Coffee-GB capture timing is unreliable" (STATE.md line 131, debug Cycle 2 lesson). There is no settle/wait-for-stable-frame capture path today.

2. **anchor4 threshold miscalibration.** `anchor4MetaspriteAnimation()` (`gbkt-examples/platformer-template/.../PlatformerTemplateUatTest.kt:484`) asserts a full-frame facing-right vs facing-left pixel diff `> 10%` via `VisualDiff.compare(tolerance = 0.10)` (line 593). The `>10%` bar was calibrated against buggy wrap-corruption output that inflated background-tilemap variation during the right-hold scroll. Phase 12.6 fixed the wrap corruption (windowed submap write `_bkg_set_level_submap_banked`), removing the inflation, so the genuine diff is now **6.60%** and the test soft-fails (STATE.md line 132). The 24×32 duck metasprite occupies ~3.3% of the 160×144 frame, so the hflip-only signal cannot reach 10% without the (now-removed) BG inflation.

Phase 12.10 does NOT touch codegen — it is a test-harness / emulator-tooling phase only.

## Requirements

1. **Settle-before-capture primitive**: A reusable capture path in the shared harness layer waits for the emulator frame to stabilize before reading the frame buffer, so post-transition captures are not stale/blank.
   - Current: No settle/stable-frame capture API exists; `captureScreenshot()` reads `getFrameBuffer()` immediately, and `ScreenshotCapture.capture()` serializes whatever is there
   - Target: A reusable primitive (in the shared `StepAgent` / `ScreenshotCapture` / `UatRunner` layer) captures a screenshot only after the frame buffer has settled (e.g., stepped to a stable/rendered frame), available to ALL UAT tests, not just anchor4
   - Acceptance: The primitive is a public/shared harness API exercised by ≥1 UAT test; calling it after a scene transition yields a non-blank, fully-rendered PNG

2. **Capture-timing RED→GREEN proof**: A regression test reproduces the stale/blank post-transition capture and proves the settle primitive fixes it.
   - Current: No test reproduces the blank-PNG / stale-capture failure mode; the bug was only observed manually (11.1-08 413-byte PNGs)
   - Target: A JVM-tier test in `gbkt-emulator` that captures immediately after a transition (demonstrates the stale/blank failure) and via the settle primitive (demonstrates a rendered frame), asserting the difference
   - Acceptance: The test fails (RED) without the settle primitive and passes (GREEN) with it; committed in the `gbkt-emulator` suite

3. **anchor4 threshold retune (integrity preserved)**: `anchor4MetaspriteAnimation` passes deterministically while remaining a meaningful hflip/animation gate.
   - Current: `VisualDiff.compare(tolerance = 0.10)` asserts `>10%` diff; real diff is 6.60% → soft-fail; threshold reflects deleted wrap-corruption inflation
   - Target: Threshold recalibrated to a value the genuine ~6.60% facing-right/facing-left diff clears with margin, AND the gate still proves the hflip occurred (NOT lowered to a trivially-passing no-op; sprite-region re-method is acceptable if it keeps the signal meaningful)
   - Acceptance: `anchor4MetaspriteAnimation` passes GREEN across repeated runs (deterministic); the retuned threshold/method still fails if the hflip is removed (integrity check), with the calibration rationale documented in the test

4. **Harness + example suites GREEN**: The change does not regress existing emulator or platformer-template tests.
   - Current: `:gbkt-emulator` and `:gbkt-examples:platformer-template` suites are GREEN except the known-14 IntegrationTest baseline (inherited 11.1-04) and the anchor4 soft-fail being fixed here
   - Target: Full `:gbkt-emulator` test suite and full `:gbkt-examples:platformer-template` test suite GREEN (modulo the pre-existing inherited-14 baseline), with anchor4 now GREEN
   - Acceptance: `./gradlew :gbkt-emulator:test` and `./gradlew :gbkt-examples:platformer-template:test` pass with no new failures beyond the documented inherited baseline

5. **Defensive ROM regression sweep (no codegen drift)**: The 7-target byte-identical ROM sweep confirms this phase introduced no generated-C change.
   - Current: 7-target sweep is the project regression contract (5 strict byte-identical + pong PASS\* + platformer-template); this phase should touch zero codegen
   - Target: Run the standard 7-target ROM sweep; all strict targets remain byte-identical to their pre-phase ROMs (no codegen drift), pong PASS\* per its documented non-determinism
   - Acceptance: Sweep manifest captured to phase evidence; 5 strict targets byte-identical, pong PASS\*, platformer-template byte-identical (no codegen change expected)

## Boundaries

**In scope:**
- A reusable settle/wait-for-stable-frame capture primitive in the shared harness layer (`StepAgent` / `ScreenshotCapture` / `UatRunner`)
- A RED→GREEN JVM-tier regression test in `gbkt-emulator` reproducing and fixing the stale/blank post-transition capture
- Recalibration of the `anchor4MetaspriteAnimation` pixel-diff threshold (and/or comparison method) to deterministic GREEN with preserved hflip integrity
- Defensive 7-target ROM regression sweep to prove no codegen drift

**Out of scope:**
- Re-shooting / retrofitting the existing platformer-template anchors 1–5 onto the new primitive — only anchor4 consumes it this phase; the other anchors stay as-is to keep blast radius small
- Replacing the direct-MCP capture workflow as the source-of-truth for user-gated visual SCs — direct MCP remains primary per CLAUDE.md Visual Evidence Rule; the harness primitive serves automated regression only (decision: "Harness fixed but MCP stays primary")
- Any codegen / generated-C / IR / DSL change — this is a test-harness-only phase
- Fixing the inherited-14 IntegrationTest baseline (tracked separately, NOT this phase)
- Any change to the MCP server screenshot path (`gbkt-mcp-server`)

## Constraints

- Zero codegen change: no edits under `gbkt-backend-gbdk`, `gbkt-ir`, `gbkt-lang`, genre modules, or any generated-C path. Proven by Requirement 5's byte-identical sweep.
- The anchor4 retune must preserve test integrity: the gate must still FAIL if the hflip/animation is removed — it may not be lowered to a value any frame trivially passes.
- The settle primitive must be deterministic and headless-safe (runs in CI without a display), consistent with the existing `GbktTestExtension` auto-skip-on-missing-ROM convention.
- Determinism: anchor4 and the new timing test must pass repeatably, not flakily.

- [ ] `anchor4MetaspriteAnimation` passes GREEN deterministically (repeated runs) with the retuned threshold/method
- [ ] The retuned anchor4 gate still FAILS when the hflip is removed (integrity preserved — not a no-op)
- [ ] `./gradlew :gbkt-emulator:test` GREEN (no new failures beyond inherited-14 baseline)
- [ ] `./gradlew :gbkt-examples:platformer-template:test` GREEN including anchor4
- [ ] 7-target ROM sweep: 5 strict targets byte-identical, pong PASS\*, platformer-template byte-identical (no codegen drift); manifest in phase evidence
- [ ] No files changed under any codegen/IR/DSL/genre module
