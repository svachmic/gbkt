**`StepAgent.settle()` / `captureScreenshotSettled()` — a 2-consecutive-identical / cap=30 / best-effort frame-buffer stability primitive that eliminates the stale/blank post-transition capture class, proven by a stub-driven ROM-free RED→GREEN regression.**

## Accomplishments
- Added `StepAgent.settle(): IntArray` — advances frames via `session.runFrames(1)` until 2 consecutive `getFrameBuffer()` snapshots are pixel-identical (cap=30, best-effort on cap, never throws). Held buttons preserved (loop never calls `step()`/`stepN()` and never touches `heldButtons`).
- Added `StepAgent.captureScreenshotSettled(label: String): File` — settles then delegates to `session.captureScreenshot(label)`, preserving the existing PNG + variable-snapshot JSON sidecar path.
- Exposed `SETTLE_STABLE_FRAMES=2` / `SETTLE_FRAME_CAP=30` as named companion constants (no magic numbers).
- Created `SettleCaptureTest` — stub-driven, no ROM, no `assumeTrue`, CI-safe; 3 GREEN tests proving the RED→GREEN capture-timing fix, the best-effort cap contract, and content-not-identity comparison.

## RED→GREEN Transition (R-02)

The capture-timing regression is **conceptually RED against pre-Task-1 code**: `SettleCaptureTest` references the `StepAgent.settle()` symbol (and `StepAgent.SETTLE_FRAME_CAP`), neither of which existed before Task 1 — so the test would fail to compile (the strongest RED). After Task 1 lands the primitive, all 3 tests pass GREEN:
- `settleLatchesRenderedFrameNotStaleFrame` — `immediate.captureFrameBuffer()` grabs the first stale (mid-render) frame; `settle()` returns the rendered frame; asserts `!immediate.contentEquals(settled)` AND `settled.contentEquals(renderedFill)`. This is the direct RED→GREEN proof on raw IntArrays (no PNG round-trip).
- `settleReturnsLastFrameWhenNeverStable` — a never-stabilizing stub → `settle()` returns the last (cap-th) frame and does not throw (D-02 best-effort).
- `settleComparesContentNotIdentity` — rendered frames are fresh instances each call; `settle()` latches by content, not identity (Pitfall 3).

## Decisions Made
- None beyond the locked CONTEXT.md decisions. Method names kept as D-05 suggestions (`settle` / `captureScreenshotSettled`) — they are intent-derived, not magic strings.
- Trimmed an over-specified `assertNotSame` premise in `settleComparesContentNotIdentity` during Task 2: `settle()` returns the exact instance it last read, which equaled the *last* captured rendered instance. Re-anchored the assertion to the *first* rendered instance (captured only once), which is genuinely a different object from the one `settle()` latches — preserving the content-not-identity proof. This is a test-authoring correction, not a deviation from the primitive contract.

## Deviations from Plan

None — plan executed exactly as written. (The `assertNotSame` re-anchoring above is intra-Task-2 test calibration to make the content-vs-identity assertion correct, not unplanned scope.)

## Issues Encountered
- Initial `settleComparesContentNotIdentity` failed: `assertNotSame(firstRendered, settled)` because `firstRendered` was reassigned on every stub call and ended up being the same instance `settle()` returned. Resolved by capturing `firstRendered` only on the first rendered call (`if (firstRendered == null)`), so it is a distinct earlier instance from the one `settle()` latches. Test now GREEN.
