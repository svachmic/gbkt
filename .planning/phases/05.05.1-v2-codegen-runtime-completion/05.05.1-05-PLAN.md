<task type="auto">
  <name>Task 1: Prepare sprite assets and generate+compile all three ROMs</name>
  <files>
    gbkt-examples/pong/src/main/resources/sprites/
    gbkt-examples/breakout/src/main/resources/sprites/
    gbkt-examples/explorer/src/main/resources/sprites/
    gbkt-examples/pong/src/main/kotlin/PongV2.kt
    gbkt-examples/breakout/src/main/kotlin/BreakoutV2.kt
    gbkt-examples/explorer/src/main/kotlin/ExplorerV2.kt
    gbkt-gradle-plugin/src/main/kotlin/io/github/gbkt/gradle/tasks/GenerateCWorkAction.kt
  </files>
  <action>
    1. **Ensure sprite PNG assets exist** in each example project's resources:
       - `pong/src/main/resources/sprites/paddle.png` (4x16 paddle sprite)
       - `pong/src/main/resources/sprites/ball.png` (4x4 or 8x8 ball sprite)
       - `breakout/src/main/resources/sprites/paddle.png`, `ball.png`, `brick.png`
       - `explorer/src/main/resources/sprites/player.png` (8x16 or 16x16 player)
       - If sprites don't exist, create simple placeholder PNGs using GBDK-compatible 4-shade palette (white/light gray/dark gray/black). These can be minimal — even 1-tile sprites are sufficient for visibility testing.

    2. **Verify DSL definitions reference correct sprite assets:**
       - Check PongV2.kt actors have `sprite(asset("sprites/paddle.png")) { size = 4 x 16 }` etc.
       - Check BreakoutV2.kt and ExplorerV2.kt similarly
       - If sprite asset references are missing or use placeholder names, update them to match actual file paths

    3. **Wire png2asset into the build pipeline** (REQUIRED — do not skip even if partially done):
       - In GenerateCWorkAction or the Gradle plugin, ensure `png2asset` is invoked for each .png in the sprites/ directory before lcc compilation
       - png2asset command: `${gbdkHome}/bin/png2asset sprites/paddle.png -o build/gbkt/generated/sprites/paddle.c -sw 8 -sh 8` (adjust -sw/-sh per sprite size)
       - Ensure the generated .c/.h files are passed to lcc compilation alongside main.c/bank1.c
       - **Verify sprite .h files exist** after png2asset runs: check that `build/gbkt/generated/sprites/*.h` files are present for every sprite PNG referenced by actors in the DSL. If any .h file is missing, the subsequent lcc compilation will fail with "undefined identifier" errors on sprite data arrays. This is the critical link between Plan 03's `#include` directives and actual sprite data.

    4. **Generate C for all three examples:**
       ```bash
       ./gradlew :gbkt-examples:pong:generateC
       ./gradlew :gbkt-examples:breakout:generateC
       ./gradlew :gbkt-examples:explorer:generateC
       ```

    5. **Inspect generated C output** for each game:
       - Verify `update_sprites()` function exists with `move_sprite()` calls
       - Verify `set_sprite_data()` calls in main()
       - Verify `SHOW_SPRITES;` in main()
       - Verify no `/* TODO:` comments remain
       - For Breakout: verify `play_sound_*()` functions exist
       - For Explorer: verify `show_dialog()` and menu functions exist

    6. **Compile ROMs** (requires GBDK installed):
       ```bash
       ./gradlew :gbkt-examples:pong:buildRom
       ./gradlew :gbkt-examples:breakout:buildRom
       ./gradlew :gbkt-examples:explorer:buildRom
       ```

    7. **Fix any compilation errors** by updating the codegen. Common issues:
       - Undeclared function prototypes → add to game.h
       - Type mismatches → check CType usage in visitor
       - Missing includes → add to buildHomeFile()
       - BANKED function calls from HOME → move function to HOME or add trampoline
       - Bank overflow → check generated code size

    8. **Run all tests to verify no regressions:**
       ```bash
       ./gradlew :gbkt-core:test :gbkt-backend-gbdk:test
       ```
  </action>
  <verify>

    - `gbkt-examples/explorer/build/gbkt/output/explorer.gb` exists
    `./gradlew :gbkt-core:test :gbkt-backend-gbdk:test` passes.
  </verify>
  <done>
    All three example ROMs compile successfully. Generated C contains complete game logic with sprite rendering, sound effects, and all ScriptOp implementations. No compilation errors.
  </done>
