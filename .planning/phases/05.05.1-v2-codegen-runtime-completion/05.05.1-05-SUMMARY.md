# Phase 05.05.1 Plan 05: End-to-End ROM Compilation & Human Verification

**One-liner:** All three example ROMs compile, run, and pass human gameplay verification — with raw() escape hatches flagged as gaps needing native DSL support.

## What Was Built

### Task 1 (Complete): Compile all three ROMs

Found and fixed 5 build/codegen bugs (OAM slot collision, missing sprite headers, zero-size arrays, missing trigger functions, missing sound prototypes). All 3 ROMs compile to 32 KB .gb files.

### Task 2 (Complete): Human gameplay verification in mGBA

All three games tested iteratively with the user. Found and fixed 12+ gameplay bugs:

**Pong (Approved):**
- Fixed blank screen: added buildOAMInitStatements() for set_sprite_tile() calls
- Created visible paddle.png (was all-transparent placeholder)
- Fixed collision: nested whenever for both X zone AND Y overlap
- Fixed AI: tracks paddle center at 2px/frame (was tracking top edge at 1px)
- Added centered text, live score HUD, scoring flash with 30-frame delay
- Separated paddle collision zones from scoring zones

**Breakout (Approved with reserves):**
- Rewrote entire game: visible brick rows via printf("##########")
- Positional brick collision using static C array (raw() escape hatch)
- HUD with SCORE/LIVES, "BALL LOST!" animation, proper win/gameover
- Fixed paddle sprite: 24x8 PNG with 3 unique tiles to prevent png2asset dedup
- Fixed ScriptOpVisitor.visitPrintOp to pass format args to printf

**Explorer (Approved with reserves):**
- Fixed step counter (was never incrementing)
- Added combat sequence with text-based auto-battle
- Added compact single-line HUD: "HP:%d L:%d T:%d"
- Fixed variable resets (only on new game from title, not combat/pause return)
- Added torch depletion with game-over on torch-out
- Fixed text centering/overflow for 20-column screen

## Identified Gaps (raw() escape hatches)

8 raw() usages across 3 games that need native DSL support:

| # | Game | Usage | Needed Feature |
|---|------|-------|----------------|
| 1-2 | Pong | Delay loops (30 frames ×2) | `delay(frames)` ScriptOp |
| 3 | Breakout | Delay loop (40 frames) | `delay(frames)` ScriptOp |
| 4 | Breakout | Brick collision array (static UINT8[30], positional read/write) | `u8Array()` + `arrayRef()` |
| 5 | Explorer | Any-dpad-direction check | `dpadAny()` expression |
| 6 | Explorer | Compound condition (&&, &, == 0) | `Expr.logicalAnd()` combinator |
| 7 | Explorer | Delay loop (60 frames) | `delay(frames)` ScriptOp |
| 8 | Explorer | Combat sequence (prints + delays + if/else) | `delay(frames)` (rest works) |

**5 features needed to close all gaps:**
1. `delay(frames)` — Blocking busy-wait (distinct from state-machine `waitFrames`)
2. `dpadAny()` — Any-direction-held expression
3. `Expr.logicalAnd()` / `Expr.logicalOr()` — Compound condition combinators
4. `u8Array(name, size)` — Array variable declaration at game level
5. `arrayRef(name, index)` — Read array elements in expressions
