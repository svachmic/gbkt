  <name>Task 1: Unseal IR interfaces and create visitor interfaces</name>
  <files>
    gbkt-core/src/main/kotlin/io/github/gbkt/core/ir/v2/ScriptOp.kt
    gbkt-core/src/main/kotlin/io/github/gbkt/core/ir/v2/Expr.kt
    gbkt-core/src/main/kotlin/io/github/gbkt/core/ir/v2/SystemIR.kt
    gbkt-core/src/main/kotlin/io/github/gbkt/core/ir/v2/ScriptOpVisitorI.kt
    gbkt-core/src/main/kotlin/io/github/gbkt/core/ir/v2/ExprVisitorI.kt
    gbkt-core/src/main/kotlin/io/github/gbkt/core/ir/v2/SystemIRVisitorI.kt
  </files>
  <action>
    1. **Unseal the three IR interfaces.** In ScriptOp.kt, Expr.kt, and SystemIR.kt, change `sealed interface` to `interface`. Keep all existing data class subtypes in the same files.

    2. **Add `accept()` to each interface:**
       ```kotlin
       interface ScriptOp {
           val sourceLocation: SourceLocation?
           fun <T> accept(visitor: ScriptOpVisitorI<T>): T
       }
       ```
       Do the same for `Expr` and `SystemIR`.

    3. **Add `accept()` override to each data class subtype.** Each of the 24 ScriptOp subtypes, 9 Expr subtypes, and 6 SystemIR subtypes needs:
       ```kotlin
       data class Assign(...) : ScriptOp {
           override fun <T> accept(visitor: ScriptOpVisitorI<T>): T = visitor.visitAssign(this)
       }
       ```
       Use `visit{ClassName}` naming convention (e.g., `visitAssign`, `visitIfOp`, `visitWhileOp`, `visitLiteral`, `visitVarRef`, `visitDialogSystem`, `visitGenericSystem`).

    4. **Create ScriptOpVisitorI.kt** with one `visit*` method per ScriptOp subtype (24 methods). All methods return `T`:
       ```kotlin
       interface ScriptOpVisitorI<T> {
           fun visitAssign(op: Assign): T
           fun visitArrayAssign(op: ArrayAssign): T
           fun visitIfOp(op: IfOp): T
           // ... all 24
       }
       ```

    5. **Create ExprVisitorI.kt** with 9 methods (visitLiteral, visitStringLiteral, visitVarRef, visitBinaryExpr, visitUnaryExpr, visitCallExpr, visitTernaryExpr, visitArrayAccessExpr, visitPropertyAccessExpr).

    6. **Create SystemIRVisitorI.kt** with 6 methods (visitDialogSystem, visitSoundSystem, visitSaveSystem, visitExplorationSystem, visitCameraSystem, visitGenericSystem).

    7. **IMPORTANT:** The visitor interface names use the `I` suffix (`ScriptOpVisitorI`) to avoid collision with the existing `ScriptOpVisitor` object in the backend. The `I` suffix is a common Kotlin/Java convention for interfaces that have an implementation counterpart.

    8. **Do NOT create abstract base classes yet** — that would be scope creep. The visitor interfaces are sufficient for this phase.
  </action>
  <verify>
    Run `./gradlew :gbkt-core:compileKotlin` — must compile without errors. The unsealing will cause `when` expressions in other modules to emit warnings about non-exhaustive matching but should not cause errors if they have `else` branches.
  </verify>
  <done>
    ScriptOp, Expr, SystemIR are `interface` (not `sealed interface`). Each subtype has an `accept()` method. Three visitor interfaces exist in the ir/v2/ package.
  </done>
</task>
