## Decisions Made

- v1 engine packages stay in gbkt-core: Moving entity/scene/graphics to gbkt-engine would require gbkt-engine to depend on gbkt-core (for v1 sealed IR), making gbkt-core → gbkt-engine AND gbkt-engine → gbkt-core a circular dependency. Plan explicitly states "do NOT force the split if it creates circular dependencies."
- Suggestions.kt moved (not copied) to gbkt-ir: The class has zero external deps and is used by both gbkt-lang (RefRegistry) and gbkt-core (Validation.kt, IRReferenceValidation.kt). Moving it to gbkt-ir eliminates the duplicate class problem while letting both get it transitively.
- gbkt-engine starts empty: No v2 engine constructs exist yet. Future phases will populate this module as the v2 migration progresses (actors, scene management, input, graphics).
