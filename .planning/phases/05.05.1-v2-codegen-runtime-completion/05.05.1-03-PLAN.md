  <name>Task 1: Extend ActorVisitor and GBDKPipelineV2 for sprite rendering</name>
  <files>

  <action>
    1. **Extend ActorVisitor** with new methods:

       `generateSpriteDataLoad(actor: ActorIR, tileDataArrayName: String, startTile: Int): List<CStatement>`:
       - Computes `tilesWide = (sprite.size.width + 7) / 8`, `tilesHigh = (sprite.size.height + 7) / 8`, `totalTiles = tilesWide * tilesHigh`
       - Emits `CExprStatement(CCall("set_sprite_data", listOf(CLiteral(startTile), CLiteral(totalTiles), CVar(tileDataArrayName))))`
       - Returns empty list if actor has no sprite

       `generateOAMInit(actor: ActorIR, oamSlotStart: Int, tileStart: Int): List<CStatement>`:
       - For each OAM slot in the actor's metasprite grid (row 0..tilesHigh-1, col 0..tilesWide-1):
         - `set_sprite_tile(slot, tileStart + tileIndex)` to bind OAM slot to tile
         - `move_sprite(slot, _actorId_x + 8 + col*8, _actorId_y + 16 + row*8)` for initial position
       - Uses `actor.oamSlot?.slot ?: oamSlotStart` for fallback when analysis hasn't run (per pitfall 1 in RESEARCH.md)

       `generateUpdateSprites(actors: List<ActorIR>): CFunction`:
       - Builds the `update_sprites()` function
       - Iterates all actors with sprites
       - For each OAM slot in each actor's metasprite grid:
         - `move_sprite(slot, _actorId_x + 8 + col*8, _actorId_y + 16 + row*8)`
       - **CRITICAL:** GBDK hardware coordinate offset is +8 for x, +16 for y. Position (0,0) in game logic maps to (8,16) in OAM hardware.
       - Returns `CFunction(name="update_sprites", returnType=CVoid, body=statements, sectionComment="Sprite OAM sync (called every frame)")`

    2. **Update GBDKPipelineV2.buildHomeFile():**

       a. **Add `#include` directives** for sprite asset headers. For each actor with a sprite, add:
          `CRawCode("#include \"sprites/${actor.sprite.asset.path}.h\"")` to the file's includes section.
          Use the asset path from `actor.sprite.asset` (AssetRef). If no asset path is available (inline sprites), generate tile data as `const unsigned char` C arrays directly.

       b. **Replace `buildSpriteHelperStubs()` with `buildSpriteHelperFunctions()`:**
          - `hide_sprites_range(from, to)`: Loop from `from` to `to`, call `move_sprite(i, 0, 0)` for each (moves sprite off-screen; GBDK has no hide_sprite API)
          - `show_sprites_range(from, to)`: This is a no-op stub — sprites are shown by moving them to visible positions. Keep the function signature for DSL compatibility but make the body a comment explaining this.

       c. **Add `update_sprites()` to HOME bank** by calling `ActorVisitor.generateUpdateSprites(gameIR.actors)` and adding the result to the home file's functions list.

       d. **Add sprite initialization to `buildMainFunction()`:**
          - After `DISPLAY_ON;` add `SHOW_SPRITES;` to enable OAM layer
          - Before the game loop, add sprite data loading calls (`set_sprite_data()`)
          - Add `update_sprites()` call inside the game loop, after `update_joypad()` and scene frame dispatch, before `wait_vbl_done()`

       e. **Add OAM init calls to scene enter functions:**
          - In `SceneVisitor.visit()`, after the existing enter body, add `set_sprite_tile()` and initial `move_sprite()` calls from `ActorVisitor.generateOAMInit()`
          - These should only be added if the scene has actors referenced in `scene.actorIds`

    3. **Add forward declarations to game.h:**
       - `update_sprites()` prototype
       - `hide_sprites_range(UINT8 from, UINT8 to)` prototype
       - `show_sprites_range(UINT8 from, UINT8 to)` prototype
