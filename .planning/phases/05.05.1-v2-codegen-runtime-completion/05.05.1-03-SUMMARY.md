## Decisions Made

- **CLiteral 'u' suffix:** The CEmitter emits `CLiteral(n)` as `"${n}u"` for non-negative values.
  All test assertions must use `move_sprite(0u, ...)` not `move_sprite(0, ...)`.
  This is the existing CEmitter convention — not changed.

- **hide_sprites_range uses CRawCode:** The loop body uses `CRawCode("UINT8 i; for (i = from; i < to; i++) { move_sprite(i, 0, 0); }")` rather than typed `CFor`, because a typed for loop with `CVar("i")` would require forward declaration of `i` before the loop (C89 GBDK compatibility). CRawCode avoids the issue cleanly.

- **show_sprites_range is a no-op:** Sprites become visible by moving them to valid on-screen positions via `update_sprites()`. The function body has a comment explaining this and is kept for DSL compatibility (`screen.showSprites()` DSL call emits `show_sprites_range()`).

- **Sequential VRAM tile assignment:** Tile slots start at 0 and increment by each actor's tile count. No dependency on the analysis pass's VRAM layout — avoids coupling to optional analysis output while still generating correct set_sprite_data() calls.
