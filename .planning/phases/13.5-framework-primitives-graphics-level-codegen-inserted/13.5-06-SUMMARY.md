# Phase 13.5 Plan 06: PlatformerTemplate + LevelCardSceneBuilder Migration Summary

**One-liner:** Eliminated all cEmit escape hatches and zone-as-screen abuse from the platformer carrier by migrating to typed `screen(asset(...))` + `bindCurrentLevel()` primitives, including adding `LevelCardSceneBuilder.screen()` forwarding method and updating JVM regression guards.

## What Was Built

**Task 1 (commit 2327e876):** Refactored `LevelCardSceneBuilder.materialize()` to:
- Remove the entire synthesized `enter { }` block with 5 cEmit calls (hide_sprites, move_bkg, fill_bkg_rect, centered tile load, DISPLAY_ON) — these are now handled by `screen()`'s screenMode superset in SceneVisitor
- Replace `cEmit("setup_current_level();")` in the Start-press handler with `bindCurrentLevel()` (typed BindCurrentLevel IR node, Phase 13.5 Req #17)
- Remove `cardZoneRef` field and `zone(ZoneRef)` method from the builder (the old zone-capture path)
- Remove unused `import io.github.gbkt.core.dsl.ZoneRef`

**Task 2 (commit f43ba672):** Four file changes:

- `PlatformerExtensions.kt`: Added `LevelCardSceneBuilder.screen(assetRef: AssetRef)` forwarding method + `import io.github.gbkt.core.ir.AssetRef` (the IR-layer AssetRef, not assets layer)
- `LevelCardSceneEmissionTest.kt`: Updated `buildLevelCardSceneWithZoneDsl()` fixture to use `screen(asset("res/graphics/nextlevel.png"))` on `levelCardScene`; added Test 10 asserting screenMode superset in `nextLevelScene_enter`
- `LevelCardSceneBuilderTest.kt`: Updated Test 2 from `RawOp("setup_current_level();")` assertion to `BindCurrentLevel` typed IR node assertion (Rule 1 fix — test was checking stale behavior)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking Issue] Missing LevelCardSceneBuilder.screen() forwarding method**

- **Found during:** Task 2 implementation
- **Issue:** Plan action specified `levelCardScene { screen(asset(...)) }` direct DSL usage, but `LevelCardSceneBuilder` had no `screen()` method — the lambda receiver is `LevelCardSceneBuilder`, not `SceneBuilder`. Without a forwarding method, the call would not compile.
- **Fix:** Added `fun screen(assetRef: AssetRef)` to `LevelCardSceneBuilder` that captures via `sceneBuilderBlocks += { this.screen(captured) }`. Also added `import io.github.gbkt.core.ir.AssetRef` (the IR-layer `AssetRef`, not `io.github.gbkt.core.assets.AssetRef` which would cause a type mismatch with `SceneBuilder.screen()`).
- **Files modified:** `PlatformerExtensions.kt`
- **Commit:** f43ba672

**2. [Rule 1 - Bug] LevelCardSceneBuilderTest Test 2 checked for RawOp (stale after Task 1)**

- **Found during:** Task 2 test run (`gbkt-genre-platformer:test`)
- **Issue:** `LevelCardSceneBuilderTest` Test 2 was asserting `RawOp("setup_current_level();")` in the IfOp then-branch, but Task 1 migrated `materialize()` to emit `bindCurrentLevel()` (BindCurrentLevel IR node), making Test 2 fail.
- **Fix:** Updated Test 2 to assert `BindCurrentLevel` typed IR node; renamed the test to `levelCardScene frame emits bindCurrentLevel then navigate to gameplay (Phase 13_5 Req17)`.
- **Files modified:** `LevelCardSceneBuilderTest.kt`
- **Commit:** f43ba672

### Expected Deviations

The plan acceptance criterion assumed only 1 game-map zone would remain (`world1Area1Zone`), but the platformer template actually has 3 game-map zones: `world1Area1Zone`, `world1Area2Zone`, `world2Area1Zone`. This is correct behavior — all 3 game-map zones are legitimate and must stay.
