**Gathered:** 2026-06-04

<domain>
## Phase Boundary

The last and widest-blast-radius slice of the Phase-13 umbrella. Eliminate the three
highest-blast-radius **codegen workarounds** from the reference ports by adding three
typed framework primitives, then migrate the two carrier examples so they carry **zero
workarounds** with generated C *functionally equivalent* and ROM bytes *same-or-smaller*:

- **Req #15** — auto-emit `${scene.id}_exit` BANKED functions for cross-bank scenes,
  removing the empty `exit { hideSprites() }` codegen trick (`Banks.kt:96`).
- **Req #17** — typed `bindCurrentLevel()` scene-enter primitive replacing the
  `cEmit("setup_current_level();")` raw-C escape hatch (`PlatformerTemplate.kt:434` +
  the genre `levelCardScene` helper's Start-press path).
- **Req #18** — first-class `screen()` static full-screen image primitive replacing the
  zone-as-screen abuse for BOTH the title screen and the inter-level NextLevel card.

Scope is bounded to **`Banks.kt`** (Req #15) and **`PlatformerTemplate.kt` + the
`levelCardScene` genre helper** (Req #17 + #18). The other 6 active examples (pong,
breakout, simple-physics, metasprites, metasprites-stress, racer) carry none of these
patterns — they only appear in the regression sweep.

<decisions>
## Implementation Decisions

### Naming (both pairs were interchangeable in SPEC/ROADMAP — now canonical)

- **D-01: Req #18 primitive is named `screen()`** (NOT `image()`, NOT a `screen()`+`image()`
  alias pair). Matches ROADMAP #18's lead phrasing; emphasizes the full-screen-surface
  intent (the title + card are literally screens) and avoids the conceptual collision with
  sprites/metasprites that `image()` would invite. No alias — consistent with the 13.x
  one-clean-surface / no-redundant-name policy.
- **D-02: Req #17 primitive is named `bindCurrentLevel()`** (NOT `loadLevel()`, NOT
  `loadCurrentLevel()`). Parameterless; binds the active/current level's tileset+tilemap
  into VRAM. SPEC Req #17's lead name; `bind` signals the VRAM-binding semantics and
  `current` matches the `setup_current_level()` C naming. `loadLevel()` was rejected because
  it reads as if it takes a level argument (`loadLevel(2)`) when the call is
  parameterless/current.

### Req #18 — `screen()` API shape & asset pipeline

- **D-03: `screen()` is asset-direct — `screen(asset("graphics/title-screen.png"))` called
  inside a scene's `enter { }`.** No `by zone` / `by screen` declaration, no explicit
  `size(...)`. Dims are **auto-derived from the PNG at build time** in a gradle task
  (preserving the DSL-never-touches-filesystem boundary, 13.4 D-01). This kills the explicit
  `size(20, 9)` workaround the SPEC calls out. A `by screen` ref-form delegate was rejected
  (heavier declaration+registry for a once-per-surface use; neither carrier reuses a screen).
- **D-04: `screen()` reuses the existing zone tileset pipeline.** `screen(asset(...))`
  lowers to an **internal zone-equivalent** (an inferred-ID zone-like construct, tileset =
  the asset) so `ConvertZoneTilesetsTask` — which already reads the PNG via ImageIO and
  already emits `_zone_<id>_tileset` / `_zone_<id>_tilemap` / `_..._PALETTE_COUNT` /
  `_..._palettes` symbols — processes it unchanged. The title + card already ride this exact
  pipeline today (as the zone-as-screen abuse), so reuse is the lowest-risk path to
  byte-equivalence. A new dedicated `ConvertScreensTask` + `_screen_<id>_*` symbol family
  was rejected (new task + new symbol naming + new asset-discovery wiring = more surface,
  higher regression risk, harder same-or-smaller bytes).
  - **Researcher/planner integration item:** nail down how `screen(asset)` at scene-enter
    **synthesizes the internal zone's ID** and how the gradle task's asset-discovery picks
    it up (today discovery keys on declared zones in `game_metadata.json`). The inferred-ID
    construct must land in the same metadata channel the task already consumes.

### Req #18 — `screen()` placement / visual parity

- **D-05: `screen()` auto-centers ALWAYS (superset path).** It emits the full
  sequence — hide sprites + clear BG + center-place the tilemap from its derived dims
  (DEVICE_SCREEN-based centering, exactly what `levelCardScene` does today). A full 20×18
  image centers to (0,0) trivially; a 20×9 banner centers vertically. ONE code path serves
  BOTH the title and the NextLevel card. This **absorbs the card's manual `cEmit` ceremony**
  (hide-sprites + `fill_bkg_rect` clear + centered-draw) into the primitive — the
  "framework owes the author a primitive" thesis. Rejected: draw-at-(0,0)-and-require-
  full-screen-art (would force re-authoring/padding the 20×9 banners to 20×18 PNGs, changing
  the assets and risking the card no longer matching pre-migration).
- **D-06: `screen()` resets sprite + scroll state on enter** (hide all sprites +
  `move_bkg(0, 0)`) as part of the primitive — a clean static-surface slate. Matches what
  titleScene/levelCardScene do today and prevents a previous scene's sprites/scroll leaking
  onto the static image. SPEC #18's "static full-screen image with no collision/scroll/spawn
  semantics" implies this clean slate. Rejected: image-only (re-introduces the
  hideSprites/scroll-reset ceremony the migration is deleting; risks sprite bleed-through).
  - **Verification item (researcher):** the title currently renders via a plain
    `zone(titleZone)` at (0,0) **without** the clear/center path; `screen()`'s superset adds
    a few ops to title-enter. SPEC allows *functionally-equivalent + same-or-smaller bytes*
    (NOT byte-identical), so confirm the migrated title-enter ROM stays **same-or-smaller**
    and the title still renders identically (MCP screenshot).

### Req #15 — auto-emit `*_exit` BANKED predicate

- **D-07: Auto-emit an empty `${scene.id}_exit` BANKED function ONLY when
  `scene.bankSlot?.bank != null && scene.bankSlot.bank > 0`** (genuinely assigned a non-HOME
  bank). HOME-bank (bank 0) AND null-bankSlot scenes get **nothing new**. This satisfies the
  "no growth for single-bank" acceptance gate *by construction* — pong/breakout (HOME)
  stay untouched while banks' `play` (bank 1+, assigned by `BankingAnalysisPass` FFD) keeps
  its `play_exit`. Rejected: reusing the broader `sceneBanked` flag (which is `true` for
  null-bankSlot via the backward-compat default) — that risks pong/breakout gaining a new
  `*_exit` and failing the single-bank gate if their scenes carry a null bankSlot.
  - **Verification item (researcher):** confirm pong/breakout scenes' actual `bankSlot`
    values, and confirm no active example relies on an auto-`*_exit` for a null-bankSlot
    (BANKED-by-default but not genuinely bank-assigned) scene. The bank>0-only predicate
    intentionally does NOT emit for that ambiguous case.
  - **Hook point:** `SceneVisitor.kt:367` — drop the `scene.exitOps.isNotEmpty()`-only guard
    and OR-in the auto-synthesis path gated on the D-07 predicate; the emitted function
    mirrors the existing enter/frame BANKED structure (`isBanked = sceneBanked`,
    `bank = sceneBank`). Verified by INV-1 (banked enter/frame/exit triplet, Plan 11-07).

### Req #17 — `bindCurrentLevel()` IR shape

- **D-08: `bindCurrentLevel()` is a dedicated `BindCurrentLevel` IR ScriptOp node** (mirrors
  `ScreenClear`), with a new visitor method emitting `CCall("setup_current_level", [])`.
  Fully typed, visitor-dispatched, no raw string, no escape-hatch warning surface. Rejected:
  a marked/whitelisted `RawOp` (still a string under the hood, fragile, against the SPEC's
  "typed, no escape hatch" intent). The same typed primitive serves both call sites: the
  `gameplayScene.enter{}` bind AND the NextLevel card's Start-press path (currently
  `PlatformerExtensions.kt:914`'s `cEmit("setup_current_level();")`).
  - **Blueprint:** `ScreenClear` (IR node in `gbkt-ir/.../ir/ScriptOp.kt`; DSL `clear()` in
    `ScriptBuilder.kt:483`; visitor `visitScreenClear` in `ScriptOpVisitor.kt:959`). The new
    node lowers to a named `setup_current_level()` call (generated as a HOME-bank NONBANKED
    function by `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded`, gated on
    `gameUsesTilemapCollision`). No build-time stderr WARNING is emitted (the typed path
    bypasses any `cEmit`/raw-C deviation signal).

### Migration / verification policy (carried from 13.1/13.2/13.3/13.4)

- **D-09: Clean `:buildRom` smoke is mandatory** for `banks` + `platformer-template`, plus
  the full 7-target regression sweep (pong, breakout, simple-physics, metasprites,
  metasprites-stress, banks, racer) — every target `buildRom` EXIT 0 with same-or-smaller
  byte sizes (`feedback_rom_build_smoke_test_for_codegen_phases`: JVM tests can't see
  staleness in `build/gbkt/generated/`). **Pong toolchain non-determinism is a known
  PASS\*** (generated C unchanged; `project_pong_toolchain_nondeterminism` — do NOT
  re-investigate).
- **D-10: Equivalence bar is functional, NOT byte-identical.** Generated C must be
  *functionally equivalent* and ROM byte size *same-or-smaller* — incidental reshaping
  (reordered emits, renamed temporaries, the screen()/bindCurrentLevel() superset ops) is
  permitted, validated by runtime behavior + ROM size, not by an empty `diff`.
- **D-11: MCP runtime visual evidence is binding** for the Req #18 + #17 surfaces (title,
  gameplay-level, NextLevel-card) per the CLAUDE.md Visual Evidence Rule — migrated-ROM
  screenshots MUST match the pre-migration ROM. Capture a pre-migration baseline BEFORE
  refactoring.
- **D-12: New primitives documented in `DSL_REFERENCE.md`** with worked examples for
  `screen(asset(...))`, `bindCurrentLevel()`, and the auto-`*_exit` behavior.
- **D-13: Must NOT revert prior fixes / regress 13.4 outcomes** — preserve the 13.3-22/24
  sprite-palette ascending-ramp polarity and 12.9 D2a `-keep_palette_order`; keep
  `_zone_world1Area1Zone_tilemap` at [1920]/WIDTH 60 and the RIGHT+A jump-traversal guard
  GREEN (`learning_platformer_traversal_needs_jumps`).

### Claude's Discretion / researcher-verify
- **D-04** — exact synthesis + discovery mechanism for `screen()`'s internal zone ID
  (how the inferred-ID construct reaches `game_metadata.json` for `ConvertZoneTilesetsTask`).
- **D-06 / D-07** — the two verification items above (title-enter same-or-smaller bytes;
  pong/breakout/null-bankSlot `bankSlot` audit) — researcher enumerates before planning.
- **D-08** — exact placement of the `BindCurrentLevel` node + visitor wiring and whether the
  card Start-press path migrates the genre helper internals in the same plan as the example.
- Plan-by-plan batching of the migration (small plans, each GREEN —
  `feedback_many_small_plans_terminal_subphase`; this is the terminal sub-phase of the 13.x
  family and must CLOSE its cluster, no 13.5.1 follow-ups).

## Existing Code Insights

### Reusable Assets
- **`SceneVisitor` zone-load prepend** (`SceneVisitor.kt:170–342`) already emits the exact
  full-screen-image C (`set_bkg_data` + `_bkg_tiles_load_banked` + GBC `set_bkg_palette` +
  `DISPLAY_ON`) — `screen()` reuses it (D-04). The card's centered-draw + clear logic
  (`LevelCardSceneBuilder.materialize`) is the superset `screen()` adopts (D-05).
- **`ScreenClear` IR node + `visitScreenClear`** — the structured, context-aware
  ScriptOp+visitor blueprint to copy for `BindCurrentLevel` (D-08).
- **`setup_current_level()` already generated** by `GBDKPipelineV2`
  (`buildSetupCurrentLevelFunctionIfNeeded`, gated on `gameUsesTilemapCollision`) —
  `bindCurrentLevel()` just emits a typed `CCall` to it; no new C function needed (D-08).
- **`sceneBank`/`sceneBanked`** already computed at the SceneVisitor emit point
  (`:101–105`) — the bank>0 predicate (D-07) needs no new analysis, just reads
  `scene.bankSlot.bank`.
- **`ConvertZoneTilesetsTask` already reads zone PNGs + emits the symbol family** — screen()
  hooks into an existing read; no new file-IO machinery (D-04).

### Established Patterns
- **DSL never touches the filesystem** — PNG-dim derivation defers to the gradle task
  (13.4 D-01); D-03 preserves this for `screen()`'s auto-size.
- **Structured ScriptOp over RawOp** for typed primitives — `ScreenClear` (not a `RawOp`)
  is the precedent D-08 follows; raw-C stays the escape hatch, not the primitive's lowering.
- **Additive primitives, escape hatches survive** — unlike 13.1/13.3/13.4's hard-replace,
  13.5's `cEmit`/`zone{}` stay valid (13.3 D-04 keep-`frame{}` precedent); examples just
  stop using them.
- **Codegen-shape change is acceptable when functionally equivalent + smaller** (13.3 D-03)
  — D-10's bar; the screen()/bindCurrentLevel superset ops reshape C without breaking the
  same-or-smaller-bytes constraint.

### Integration Points
- DSL (`screen(asset)`, `bindCurrentLevel()`, auto-`*_exit`) → IR (`BindCurrentLevel` node;
  internal zone-equivalent for `screen()`; `bankSlot.bank` read for `*_exit`) →
  `SceneVisitor` / `ScriptOpVisitor` / `GBDKPipelineV2` codegen → `GenerateCTask`
  (`game_metadata.json` carries screen()'s synthesized-ID zone) → `ConvertZoneTilesetsTask`
  (PNG read + symbol emission) → migrated `Banks.kt` + `PlatformerTemplate.kt` +
  `PlatformerExtensions.kt` → regression `:buildRom` sweep (banks + platformer-template
  mandatory) → MCP visual evidence (title / gameplay-level / NextLevel-card).
- **Build-graph ordering** mirrors 13.3 D-02: `generateC` (JVM) does not need the PNG; only
  `ConvertZoneTilesetsTask` (after generateC) reads it. The cross-task contract is the
  `game_metadata.json` zone entry for screen()'s synthesized construct.

  the user chose the **superset auto-center + reset** behavior so a single clean call covers
  every static-image surface, absorbing the card's hand-rolled `cEmit` ceremony.
