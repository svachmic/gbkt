### Task 2 — Capture pre-migration MCP visual-parity oracles (checkpoint: human-verify, blocking)

**Traversal recipe (recorded for the terminal regression plan 13.5-08 to reuse):**
The NextLevel card is reachable but requires the PLAYBOOK.md recipe, not naive held-RIGHT:
1. Start with `gbcMode=true` AND the `.noi` symFile (`platformer-template.noi`) so player/camera
   variables resolve — the ROM is GBC-target and palette/physics behave correctly under GBC.
2. Let the title fully initialize before pressing START (a START at frame 0 is swallowed).
3. Jump is **rising-edge** `button_pressed(A|UP)` while `grounded` — hold A across frames fires
   only one jump. Clear each obstacle with a fresh not-held→held A transition, then hold RIGHT
   to carry forward while airborne.
4. Track real progress via `map_pos_x` (monotonic tile-scroll, 0 → ~47 across the 60-tile level)
   and the `next_level`/`current_scene` variables — NOT screen-X (the camera centers the player
   at screen-X≈68) and NOT the `playerX` raw value (reads non-monotonically).
5. Level 1 has a 4-tile stacked-crate wall mid-level and a crate cluster near the end; both need
   a jump. The level-end trigger flips `current_scene` 1→2 and `next_level` 0→1 (the NextLevel card).

This corroborates `learning_platformer_traversal_needs_jumps`: held-RIGHT-only stalls at the
designed obstacle; jumps are required.
