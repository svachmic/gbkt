## Primitive naming

### Req #18 — screen() vs image()

| Option | Description | Selected |
|--------|-------------|----------|
| screen() | ROADMAP #18's lead name; emphasizes full-screen surface | ✓ |

**Notes:** Matches ROADMAP canonical phrasing; the title/card are literally screens.

### Req #17 — bindCurrentLevel() vs loadLevel() / loadCurrentLevel()

| Option | Description | Selected |

## screen() API shape

### How screen() takes its image

| Option | Description | Selected |
|--------|-------------|----------|
| Asset-direct: screen(asset(...)) | No declaration, no size(); dims auto-derived from PNG at build time | ✓ |
| Ref form: screen(screenRef) | `by screen { }` delegate + registry; heavier than the once-per-surface need | |
| Both forms | Two surfaces to maintain; against one-clean-surface policy | |

**User's choice:** Asset-direct `screen(asset(...))`
**Notes:** Kills the explicit size(20,9) workaround; DSL-no-filesystem preserved (derive in gradle task).

### Where screen()'s PNG gets processed

| Option | Description | Selected |
|--------|-------------|----------|
| Reuse the zone tileset pipeline | Lowers to internal zone-equivalent; ConvertZoneTilesetsTask unchanged | ✓ |
| New dedicated screen pipeline | New ConvertScreensTask + _screen_<id>_* symbols; more surface, higher risk | |

**User's choice:** Reuse the zone tileset pipeline
**Notes:** Title/card already ride this pipeline as the zone-as-screen abuse; lowest-risk path to byte-equivalence. Researcher to resolve the internal-zone-ID synthesis + asset-discovery wiring.

## screen() placement/parity

### How one screen() serves both title + card with pixel-parity

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-center always | Superset: hide sprites + clear + center-place from derived dims; reproduces card path | ✓ |
| Draw at (0,0), require full-screen art | Simpler codegen but would force re-authoring 20×9 banners to 20×18 | |
| You decide (planner) | Lock the parity requirement, let planner pick | |

**User's choice:** Auto-center always
**Notes:** A full 20×18 image centers to (0,0); a 20×9 banner centers vertically. Absorbs the card's manual cEmit ceremony into the primitive.

### Should screen() reset sprite + scroll state on enter?

| Option | Description | Selected |
|--------|-------------|----------|
| Yes — reset sprites + scroll | hide sprites + move_bkg(0,0); clean static-surface slate | ✓ |
| No — image only | Author resets explicitly; re-introduces deleted ceremony, risks sprite bleed-through | |

**User's choice:** Yes — reset sprites + scroll
**Notes:** SPEC #18 "no collision/scroll/spawn semantics" implies a clean slate.
