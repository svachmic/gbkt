# Phase 13.5: Code Review Report

**Reviewed:** 2026-06-05
**Depth:** standard
**Files Reviewed:** 28
**Status:** issues_found

## Summary

Phase 13.5 delivered three new framework primitives: `BindCurrentLevel` typed ScriptOp (Req #17), `screen(asset(...))` static full-screen image primitive (Req #18), and auto-synthesized empty `${scene.id}_exit BANKED` stubs for MBC games (Req #15). Supporting changes include the `LevelCardSceneBuilder.screen()` forwarding method, `PlatformerTemplate.kt` migration onto the new surfaces, `Banks.kt` removal of the now-redundant manual exit block, and a Gradle task-ordering fix in `GbktPlugin.kt`.

The implementation is architecturally sound and follows established patterns. Test coverage is strong: brace-walk extraction is used consistently, evidence-before-assert convention is respected, and the no-growth gates for ROM_ONLY games are properly exercised. Two critical findings were identified: `BindCurrentLevel` is entirely absent from `GameIRSerializer.serializeOp()`, causing silent data loss on any game that uses `bindCurrentLevel()`; and a naming-convention filter in `buildSetupCurrentLevelFunctionIfNeeded` is the only thing preventing `screen()`-synthesized zones from appearing in `setup_current_level()`, creating a correctness failure for non-"title"/"nextlevel" scene IDs. Two warnings relate to a zone registration side-effect occurring before a guard check in `SceneBuilder.screen()`, and a missing null-guard in `SceneVisitor`'s screenMode branch. Two informational items cover a stale visitor count KDoc and a redundant local variable.

## Critical Issues

### CR-01: `BindCurrentLevel` missing from `GameIRSerializer.serializeOp()` — RESOLVED (8cd7e35f)

**File:** `gbkt-ir/src/main/kotlin/io/github/gbkt/core/ir/GameIRSerializer.kt`
**Issue:** The `serializeOp()` when-expression has no `is BindCurrentLevel` branch. Any game that calls `bindCurrentLevel()` will silently fall through to the `else` handler which emits a type-discriminator with the class name instead of a proper serialized form, and on deserialization the op is reconstructed as a `RawOp("BindCurrentLevel")` placeholder with a `System.err` warning. This is data loss on the serialization round-trip. The bug is confirmed: `grep -n "BindCurrentLevel" GameIRSerializer.kt` returns no results. Every game using the new Req #17 primitive — including the migrated `PlatformerTemplate.kt` — will silently lose the `bindCurrentLevel()` op if the game IR is ever serialized and deserialized (e.g., for caching, incremental builds, or source map correlation). The `LevelCardSceneBuilderTest` and `BindCurrentLevelEmissionTest` do not exercise the serializer path, so this goes undetected by existing tests.

**Fix:**
```kotlin
// In serializeOp(), add a case before the else branch:
is BindCurrentLevel -> {
    val json = JSONObject()
    json.put("type", "BindCurrentLevel")
    op.sourceLocation?.let { json.put("sourceLocation", serializeSourceLocation(it)) }
    json
}
```

Additionally, add a deserialization case in `deserializeOp()` (wherever `"BindCurrentLevel"` type string is mapped back):
```kotlin
"BindCurrentLevel" -> BindCurrentLevel(
    sourceLocation = json.optJSONObject("sourceLocation")?.let { deserializeSourceLocation(it) }
)
```

### CR-02: `buildSetupCurrentLevelFunctionIfNeeded` naming-convention filter breaks for non-standard scene IDs used with `screen()` — RESOLVED (f3fd9f8f)

**File:** `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/GBDKPipelineV2.kt`
**Issue:** The filter that excludes synthetic `_screen_*` zones from the `setup_current_level()` switch relies exclusively on a string-contains heuristic:

```kotlin
val gameplayZones = gameIR.zones.filter { zone ->
    val idLower = zone.id.lowercase()
    !idLower.contains("title") &&
        !idLower.contains("nextlevel") &&
        !idLower.contains("next_level")
}
```

This correctly handles `_screen_title` (contains "title") and `_screen_nextLevelScene` (lowercase contains "nextlevel"). However, if a user calls `screen()` on any other scene — for example `scene("intro")`, `scene("credits")`, `scene("loading")`, `scene("chapter1")` — the synthetic zone ID `_screen_intro` does NOT contain any of the filtered strings. The zone therefore appears as a case branch in `setup_current_level()`, where it will attempt to spawn the player from a non-gameplay screen zone, corrupting runtime state. The real discriminator is already present on `ZoneIR`: `screenMode = true`. The filter should use it.

**Fix:**
```kotlin
// Replace the name-heuristic filter with the semantic field that already exists:
val gameplayZones = gameIR.zones.filter { zone ->
    !zone.screenMode  // screenMode=true zones are synthetic screen() zones, never gameplay
}
```

This is a zero-ambiguity predicate that also future-proofs any new `screenMode` use cases.

## Warnings

### WR-01: `SceneBuilder.screen()` registers the synthetic zone before the guard check fires — RESOLVED (45bea8a2)

**File:** `gbkt-lang/src/main/kotlin/io/github/gbkt/core/dsl/SceneBuilder.kt`
**Issue:** The method body calls `GameBuilderContext.current?.registerZone(syntheticZone)` and then, several lines later, calls `require(zoneRefs.isEmpty())`. If `screen()` is called twice on the same scene, the second synthetic zone is registered into `GameIR.zones` before the `require` throws. Kotlin exceptions stop further processing, but the first call's zone registration side-effect has already committed an orphaned zone entry to the in-memory IR. While this is caught at DSL record-time and prevents compilation, the orphaned zone entry in `gameIR.zones` will be present in any partial-build diagnostics or serializer output that runs in an error handler, potentially causing confusion.

**Fix:** Invert the order — validate first, register second:
```kotlin
fun screen(assetRef: AssetRef) {
    val syntheticId = "_screen_${id}"
    require(zoneRefs.isEmpty()) {
        "scene '$id' already binds a zone or screen; multi-zone/screen-per-scene deferred to Phase 13"
    }
    val syntheticZone = ZoneIR(
        id = syntheticId, name = syntheticId,
        tilesetPath = assetRef.path, screenMode = true,
    )
    GameBuilderContext.current?.registerZone(syntheticZone)
        ?: error("screen() must be called inside a game { } block")
    zoneRefs += syntheticId
}
```

### WR-02: `SceneVisitor` screenMode branch assumes `zone.tilesetPath != null` without a guard — RESOLVED (5033e348)

**File:** `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/visitor/SceneVisitor.kt`
**Issue:** The `when { zone.screenMode -> { ... } }` branch directly constructs C symbol references using `_zone_${zoneSanitized}_tileset`, `_zone_${zoneSanitized}_tilemap_WIDTH`, etc., without verifying that `zone.tilesetPath != null`. The KDoc comment on `ZoneIR.screenMode` notes "guaranteed by `SceneBuilder.screen()` DSL" but the visitor itself has no enforcement. A manually constructed `ZoneIR(screenMode = true, tilesetPath = null)` — which is a valid Kotlin construction since `tilesetPath` has a nullable type — would generate C code referencing undefined symbols, producing a link-time error with no diagnostic pointing to the IR-level mismatch. This is especially relevant given that `ZoneIR` is a data class (copyable) and `screenMode` is a plain `Boolean` field that could be set to `true` programmatically.

**Fix:** Add a precondition check at the entry of the screenMode branch:
```kotlin
zone.screenMode -> {
    require(zone.tilesetPath != null) {
        "Zone '${zone.id}' has screenMode=true but tilesetPath is null. " +
        "screen() always sets tilesetPath; do not set screenMode=true on zones without an asset."
    }
    listOf(
        CRawCode("hide_sprites_range(0u, MAX_HARDWARE_SPRITES);"),
        // ... rest of superset
    )
}
```

### IN-02: Redundant local variable in `LevelCardSceneBuilder.screen()` — RESOLVED (6057698d)

**File:** `gbkt-genre-platformer/src/main/kotlin/io/github/gbkt/genre/platformer/dsl/PlatformerExtensions.kt`
**Issue:** The `screen()` forwarding method captures the parameter into a redundant `val captured` before using it in the lambda:
```kotlin
fun screen(assetRef: AssetRef) {
    val captured = assetRef   // <- redundant; assetRef is already captured by the lambda
    sceneBuilderBlocks += { this.screen(captured) }
}
```
Kotlin closures capture variables by reference from the enclosing scope; `assetRef` is already immutable (it's a `val` parameter) and can be captured directly. The `captured` alias adds no semantic value and was presumably added out of caution when porting from a mutable-capture scenario.

**Fix:**
```kotlin
fun screen(assetRef: AssetRef) {
    sceneBuilderBlocks += { this.screen(assetRef) }
}
```

## Overall Assessment

Phase 13.5 is a well-structured implementation that correctly separates the three new primitives into typed IR nodes, DSL builders, and codegen visitor branches. The test suite is solid: brace-walk extraction is used throughout, evidence-before-assert is respected, no-growth gates are present for ROM_ONLY games, and the negative test (`ScreenPrimitiveEmissionTest` Test 2) correctly acknowledges the naming-convention assumption (A2) it is built on. The critical findings are both in the same cluster — `GameIRSerializer` was not updated for `BindCurrentLevel` (a gap that is invisible to compile-time checking and easily missed when visitor interfaces don't require serializer parity), and the screenMode exclusion from `setup_current_level()` relies on a heuristic that is brittle to scene naming. Both are fixable without architectural changes. The warnings are defensive improvements that harden against programmatic misuse of `ZoneIR.screenMode`. None of the test files contain tautological assertions or missing coverage for the scenarios they claim to test.
