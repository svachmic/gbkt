# Phase 13.5: framework primitives — graphics & level codegen — Specification

**Created:** 2026-06-04
**Ambiguity score:** 0.173 (gate: ≤ 0.20)
**Requirements:** 3 locked

## Goal

Eliminate the three highest-blast-radius codegen workarounds from the reference ports — the empty-`exit{}` codegen trick (Banks.kt), the `cEmit("setup_current_level();")` raw-C escape hatch (platformer-template), and the zone-as-static-screen abuse (platformer-template title + NextLevel card) — by adding three typed framework primitives (Req #15 auto-emitted `*_exit`, Req #17 `bindCurrentLevel()`, Req #18 `screen()`), such that the migrated examples carry zero workarounds and the generated C and ROM behavior stay functionally equivalent (same-or-smaller bytes).

## Background

Phase 13.5 is the last and widest-blast-radius slice of the Phase 13 umbrella (Req #1–#18). Sub-phases 13.1–13.4 are COMPLETE; 13.5 owns Req #15, #17, #18 — the three codegen-touching gaps deferred to last because each changes the C-emission shape. Grounded current state from the codebase scout:

- **Req #15 — empty `exit{}` trick** is carried by exactly one active example: `gbkt-examples/banks/.../Banks.kt:96` declares `exit { hideSprites() }` on the `play` scene. The accompanying comment (Banks.kt:82–85) states it is "intentionally declared so the bank1.c emission of `play_exit` exists and carries the `BANKED` keyword. Without an explicit `exit { }` block, scene codegen does NOT emit a `*_exit` function." The codegen confirms this: `SceneVisitor.kt:367` only emits a `${scene.id}_exit` `CFunction` when `scene.exitOps.isNotEmpty()`. INV-1 (Plan 11-07) verifies the full enter/frame/exit BANKED triplet for the multi-bank trampoline target.
- **Req #17 — `cEmit` escape hatch** is carried by exactly one active example: `gbkt-examples/platformer-template/.../PlatformerTemplate.kt:434` ships `cEmit("setup_current_level();")` in the `gameplayScene.enter{}` block. The file's own comment (lines 423–426) documents the stderr WARNING this emits as "the expected signal documenting this deviation," tracked as future framework-shaping cleanup (D-20 routing). `cEmit`/raw-C is a general-purpose escape hatch in the DSL.
- **Req #18 — zone-as-screen abuse** is carried by exactly one active example: `PlatformerTemplate.kt` models BOTH static full-screen pictures as zones — `titleZone` (lines 314–317, `tileset(asset("graphics/title-screen.png"))` + `size(20, 9)`) and `nextLevelZone` (318–321) — bound into `titleScene` (line 389, `zone(titleZone)`) and into the `nextLevelScene by levelCardScene { zone(nextLevelZone) … }` helper (lines 466–476). A ~20-line comment block (284–313) explains why this works (the PNG carries both tileset pixels and the tile-index map through the zone-tilemap pipeline) and notes the explicit `size(20, 9)` workaround "is removed when these migrate to `screen()` in Phase 13.5."
- **No existing primitive:** there is no `screen()`/`image()`/`bindCurrentLevel()`/`loadLevel()` surface in `gbkt-lang`, `gbkt-ir`, or `gbkt-engine` today. The other 6 active examples (pong, breakout, simple-physics, metasprites, metasprites-stress, racer) use none of these three patterns — so migration scope is bounded to **Banks.kt** (Req #15) and **platformer-template** (Req #17 + #18).

## Requirements

1. **Auto-emit `*_exit` BANKED functions for cross-bank scenes (Req #15)**: The framework emits a `${scene.id}_exit` BANKED function for cross-bank scenes without requiring the author to declare a non-empty `exit { }` block solely as a codegen trick.
   - Current: `SceneVisitor.kt:367` emits `${scene.id}_exit` only when `scene.exitOps.isNotEmpty()`. `Banks.kt:96` ships `exit { hideSprites() }` purely to force `play_exit` BANKED emission; removing it today would drop the function and fail INV-1.
   - Target: After removing the manual `exit { hideSprites() }` from `Banks.kt`, the `play_exit` BANKED function is still emitted into `bank1.c` (auto-synthesised for the cross-bank scene), preserving the enter/frame/exit BANKED triplet. Single-bank (HOME) scenes do NOT gain a new `*_exit` function (no C growth for non-banked games).
   - Acceptance: `Banks.kt` contains zero empty/trick `exit { }` blocks; clean `:gbkt-examples:banks:buildRom` EXIT 0; the generated `bank1.c` still contains a `BANKED`-qualified `play_exit` function (INV-1 / banked-triplet guard GREEN); single-bank examples (pong, breakout) show no new `*_exit` function in their generated C (no shape growth, byte size same-or-smaller).

2. **Typed `bindCurrentLevel()` scene-enter primitive (Req #17)**: A typed DSL call replaces the `cEmit("setup_current_level();")` raw-C escape hatch for loading the active level's tileset+tilemap into VRAM before the first gameplay frame.
   - Current: `PlatformerTemplate.kt:434` uses `cEmit("setup_current_level();")` in `gameplayScene.enter{}`, emitting a build-time stderr WARNING.
   - Target: `gameplayScene.enter{}` calls a typed `bindCurrentLevel()` (parameterless, binds the active/current level — matching `setup_current_level()` semantics) that lowers to the same `setup_current_level();` C call with no escape hatch and no build WARNING. The same typed primitive (or its equivalent) covers the level-bind on the NextLevel card's Start-press path currently served by `setup_current_level()`.
   - Acceptance: `PlatformerTemplate.kt` contains zero `cEmit(...)`/raw-C calls; a clean `:gbkt-examples:platformer-template:buildRom` produces ZERO `cEmit`/`setup_current_level`-deviation stderr WARNINGs; the generated gameplay-enter (and card Start-press) C still performs the `setup_current_level()` level-bind (functionally equivalent — verified by ROM runtime, byte size same-or-smaller).

3. **Static full-screen image primitive `screen()` (Req #18)**: A first-class `screen()` (a.k.a. `image()`) primitive renders a full-screen static background image with no collision/scroll/spawn semantics, usable from a scene's `enter{}`, replacing the zone-as-screen abuse for BOTH the title screen and the inter-level NextLevel card.
   - Current: `titleZone` + `nextLevelZone` are `zone { tileset(asset(...)); size(20, 9) }` declarations bound via `zone(titleZone)` (title scene) and `zone(nextLevelZone)` (inside `levelCardScene`). A ~20-line comment block explains the abuse; an explicit `size(20, 9)` workaround is required.
   - Target: Both static pictures use `screen(asset("graphics/title-screen.png"))` / `screen(asset("graphics/next-level.png"))` — no `zone { }`, no explicit `size(...)`, no explanatory comment block. The `levelCardScene` card path is refactored onto `screen()`. Title and NextLevel card render identically to the pre-migration ROM.
   - Acceptance: `PlatformerTemplate.kt` contains zero `zone { }` declarations used as static screens (titleZone/nextLevelZone removed or converted to `screen()`); the zone-as-screen explanatory comment block is gone; MCP runtime screenshots of the title screen and the NextLevel card from the migrated ROM match the pre-migration ROM (Visual Evidence Rule); ROM byte size same-or-smaller.

## Boundaries

**In scope:**
- New typed DSL/IR/codegen primitive for auto-emitted `*_exit` BANKED functions on cross-bank scenes (Req #15).
- New typed `bindCurrentLevel()` scene-enter DSL/IR/codegen primitive that lowers to `setup_current_level()` (Req #17).
- New first-class `screen()`/`image()` DSL/IR/codegen primitive for static full-screen background images (Req #18).
- Migration of the two carrier examples: `Banks.kt` (Req #15) and `platformer-template/PlatformerTemplate.kt` (Req #17 + #18), including refactoring the `levelCardScene` card path onto `screen()`.
- Documentation of the three new primitives in `DSL_REFERENCE.md` with worked examples.
- Regression sweep across pong, breakout, simple-physics, metasprites, metasprites-stress, banks, racer.
- MCP runtime visual evidence for the title + gameplay-level + NextLevel-card surfaces.

**Out of scope:**
- Hard-removal / hard-deprecation of `cEmit`/raw-C — it stays as a documented general escape hatch (examples merely stop using it). Reason: `cEmit` is a deliberate escape valve, not a workaround to delete.
- Actively preventing or hard-deprecating `zone { }` for real maps — `zone { }` stays valid for scrollable game maps; only the static-screen *abuse* is removed from examples. Reason: zones remain the correct primitive for collision/scroll/spawn maps.
- Migrating examples that do not carry these three patterns (pong, breakout, simple-physics, metasprites, metasprites-stress, racer have no exit-trick / cEmit / zone-as-screen). Reason: nothing to migrate — they only appear in the regression sweep.
- The Tier-3 deferred candidates (typed `bgFill()`, scoped state vars, `Facing` enum, `ZoneKind`, etc.) — explicitly deferred per the Phase 13 umbrella. Reason: not surfaced by these three reqs.
- The Phase 13.7 platformer color-polarity defect and the Phase 13.6 sprite-tRNS work — separate phases. Reason: orthogonal defect classes; 13.5 must not revert the 13.3-22/24 ascending-ramp fix or 12.9 `-keep_palette_order`.
- Forcing PlatformerTemplate.kt ≤180 / Banks.kt ≤50 as a hard fail. Reason: per interview, the structural "zero workaround" gates are binding; line counts are a strong target tracked as advisory.

## Constraints

- **Equivalence bar:** the migrations are refactors — generated C must be *functionally equivalent* and ROM byte size *same-or-smaller* (NOT necessarily byte-identical; incidental C reshaping such as reordered emits or renamed temporaries is permitted, validated by runtime behavior + ROM size, not by an empty `diff`).
- **Req #15 must not grow C for single-bank scenes** — auto-`*_exit` applies only to cross-bank scenes; non-banked games' generated C and ROM size must not increase.
- **No new build-time stderr WARNINGs** shipped by any migrated example.
- **Must build clean against GBDK** — every regression-sweep target ROM builds GREEN (`buildRom` EXIT 0) with same-or-smaller byte sizes; pong toolchain non-determinism is a known PASS\* (generated C unchanged).
- **MCP `gbkt-emulator` must be live** for the Req #18 + #17 visual evidence capture (title / gameplay-level / NextLevel-card).
- Must NOT revert prior fixes: 13.3-22/24 sprite-palette ascending-ramp polarity and 12.9 D2a `-keep_palette_order`.
- Must NOT regress the 13.4 outcomes: `_zone_world1Area1Zone_tilemap` stays [1920]/WIDTH 60; the RIGHT+A jump-traversal guard stays GREEN.
