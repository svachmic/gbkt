### Why this isolation result is exactly what RESEARCH §regression-sensitivity predicted

Plan 12.1-11 modifies `buildSetupCurrentLevelFunctionIfNeeded` in `GBDKPipelineV2.kt`. The function is gated at its entry on `gameUsesTilemapCollision(gameIR) == true` and returns `null` otherwise. For each of the 6 sweep ROMs:

| ROM | Has `tilemapCollision { }` system? | `gameUsesTilemapCollision`? | `setup_current_level` emitted? |
|-----|-----------------------------------|------------------------------|--------------------------------|
| banks              | No | false | No |
| pong               | No | false | No |
| breakout           | No | false | No |
| simple-physics     | No | false | No |
| metasprites        | No | false | No |
| metasprites-stress | No | false | No |

ALL 6 hit the early `null` return, so the body change (`BANK(_zone_<id>_tilemap)` → literal-bank substitution from `bankAllocation`) cannot reach any of these ROMs' codegen output. Plan 12.1-12's changes are scoped to a test file + a docstring + a visibility widening (`private` → `internal`) — none of which alter production codegen behavior. The byte-identical result is therefore not a coincidence but the structurally guaranteed outcome.

### gbkt-build.properties timestamp drift

The 5-line raw diff per ROM is entirely the timestamp:

- Baseline `gbkt-build.properties` was written `2026-05-22 16:15:xx CEST` (the moment the /tmp/12.1-13-baseline-checkout buildRom ran).
- Current `gbkt-build.properties` was written `2026-05-22 16:14:31 CEST` (the moment the executor's buildRom ran — interestingly, EARLIER than the baseline because Task 1 ran before Task 2's baseline-recapture).

The build-timestamp drift is the OS clock's wall-time signature and not a codegen contract; it is filtered from the regression-sweep methodology per Plan 12.1-09 §"Generated-C Diff" precedent.
