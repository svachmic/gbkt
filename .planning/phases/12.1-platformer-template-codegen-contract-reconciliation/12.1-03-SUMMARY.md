**`ConvertZoneTilesetsTask.synthesizeHeader` emits `#define _zone_<id>_tilemap_WIDTH/HEIGHT` macros and `GBDKPipelineV2.buildHomeFile` includes the corresponding tileset.h files into main.c, closing Defect 3 of Phase 12 first-buildrom (zero remaining `_zone_<id>_tilemap_WIDTH`/`_HEIGHT` SDCC error-20 instances against platformer-template).**

- **`synthesizeHeader` emits two new `#define` lines** for every zone tileset.h — WIDTH and HEIGHT both sourced from the existing `screenMapWidth` / `screenMapHeight` parameters. Signature unchanged. Header is the single source of truth.

## Decisions Made

- **Option (a) chosen for Defect 3 per SPEC.md Requirement 2:** emit defines via tileset.h rather than literal substitution at codegen time. Rationale: keeps symbol provenance debuggable; matches the existing `_tileset_count` convention sharing the same sanitized prefix; lower blast radius (one place, additive only).
- **Did NOT modify `setup_current_level` codegen:** leaves the `_zone_<id>_tilemap_WIDTH` / `_HEIGHT` references intact; the preprocessor expansion now resolves them transparently.
- **Did NOT extend `synthesizeHeader` signature:** dimensions already pass through as `screenMapWidth` / `screenMapHeight` parameters from the calling `convertOneTileset`.
- **Co-located defines with the matching extern declaration** (not with `_tileset_count`) — logical grouping by entity (`_tilemap` vs `_tileset`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking issue] Wired per-zone `#include "_zone_<id>_tileset.h"` into `main.c` via `GBDKPipelineV2.buildHomeFile`**

- **Found during:** Task 1 verification (the `:compileRom` acceptance check)
- **Issue:** With the new `#define` lines emitted in `_zone_<id>_tileset.h`, `:compileRom` still reported 9 Defect-3-class `error 20: Undefined identifier '_zone_<id>_tilemap_WIDTH'` / `_HEIGHT` instances. Root cause: main.c (where `setup_current_level` lives) was not `#include`ing the zone tileset.h headers, so the new preprocessor macros were invisible to SDCC at compile time. Only bank1.c included them (via the existing `zoneTilesetIncludes` block in `buildSceneFile`).
- **Fix:** Mirrored the existing `buildSceneFile`'s `zoneTilesetIncludes` pattern inside `buildHomeFile`: built a `homeZoneTilesetIncludes` list of `\"_zone_${sanitized}_tileset.h\"` strings (one per zone with a non-null `tilesetPath`, `distinct()`-ed) and appended it to `allIncludes`. Header guards make duplicates safe.
- **Files modified:** `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/GBDKPipelineV2.kt`
- **Why Rule 3, not Rule 4:** Plan 12.1-01's SUMMARY explicitly named this header-wiring as Plan 12.1-03's territory in its decisions list ("Did not extend scope to chase the chained `_zone_<id>_tilemap` extern-visibility issue in main.c — that is Plan 12.1-03's header-wiring territory"). The change is strictly additive, mirrors an established pattern in the same file, has zero impact on examples without zone tilesetPath, and is necessary to satisfy this plan's stated acceptance criterion ("zero `_zone_<id>_tilemap_WIDTH/_HEIGHT` SDCC error-20 instances").
- **Verification:** Defect-3 error count dropped from 9 → 0; regression sweep across 5 existing example ROMs clean; both `:gbkt-gradle-plugin:test` and `:gbkt-backend-gbdk:test` GREEN.
- **Committed in:** `0d097054` (Task 1 GREEN commit; bundled with synthesizeHeader change because the two changes are joint-necessary to satisfy the acceptance criterion).
