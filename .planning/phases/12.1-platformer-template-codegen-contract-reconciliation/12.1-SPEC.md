# Phase 12.1: platformer-template-codegen-contract-reconciliation — Specification

**Created:** 2026-05-22
**Ambiguity score:** 0.14 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

`./gradlew :gbkt-examples:platformer-template:buildRom` exits 0, producing `platformer-template.gb` plus a `.noi` with every bank ≤ 16 384 bytes, by reconciling four named codegen-symbol-contract defects (Defect 2–5 from `.planning/phases/12-port-platformer-template-gbdk-example-to-gbkt/evidence/first-buildrom.md`) without breaking any existing example ROM (banks, pong, breakout, simple-physics, metasprites).

## Background

Phase 12 Plan 12-18 ran the first `:buildRom` against the new `platformer-template` example. `:processAssets`, `:generateC`, `:convertSprites`, `:convertZoneTilesets`, and `:copyResources` ran GREEN — but `:compileRom` failed with **51 SDCC error-20 (undefined identifier)** errors in `main.c` + `bank1.c`. Plan 12-18 inline-fixed Defect 1 (asset path duplication, commit `4830d69c`) and escalated Defects 2–5 to this subphase per `feedback_route_to_proper_phase_when_blast_radius_is_wide.md` — they span three codegen visitors (`GBDKPipelineV2`, `PlatformerVisitor`, `MetaspriteVisitor`) plus one Gradle task (`ConvertZoneTilesetsTask`) and require contract-changing decisions. The merged tree currently has Phase 12 plans 12-01..12-17 + 12-09b complete (commit `40d9f074`) plus the 12-18 partial inline-fix (commit `fb4c6037`); the platformer-template subproject compiles and `generateC` is GREEN, but `compileRom` fails.

Phase 12.1 is **terminal** per `feedback_many_small_plans_terminal_subphase.md`: it must close the defect cluster completely. There is no Phase 12.1.1 — surplus defects discovered here must be absorbed inline up to a reasonable bound, otherwise routed to Phase 13.

## Requirements

1. **Defect 2 — `BANK()` macro on HOME-bank tilemap arrays**: `BANK(_zone_<id>_tilemap)` expansion `__bank__zone_<id>_tilemap` must resolve at SDCC link time for all five Phase 12 zones (world1Area1, world1Area2, world2Area1, title, nextLevel).
   - Current: `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded` emits `_current_area_bank = BANK(_zone_<id>_tilemap);` in `setup_current_level`'s per-case body, but `ConvertZoneTilesetsTask` writes `_zone_<id>_tilemap.c` into the HOME bank and SDCC only synthesizes `__bank_<sym>` for arrays in non-HOME banks (via `#pragma bank <N>` or banked file naming). All three gameplay zones report `error 20: Undefined identifier '__bank__zone_<id>_tilemap'`.
   - Target: Either (a) `setup_current_level` substitutes literal `1u` (HOME bank) for HOME-bank tilemap arrays, OR (b) `ConvertZoneTilesetsTask` moves tilemap arrays to a non-HOME bank with a `#pragma bank <N>` annotation, OR (c) `ConvertZoneTilesetsTask` emits an explicit `#define _zone_<id>_tilemap_BANK <N>` symbol that the pipeline reads. The chosen option must keep banks/pong/breakout regression-clean.
   - Acceptance: `grep -c '__bank__zone_world1Area1Zone_tilemap' build/gbkt/output/platformer-template.map` returns ≥ 1 (symbol resolved) **OR** the generated `setup_current_level` body contains no `BANK(_zone_<id>_tilemap)` reference (substitution path); `:gbkt-examples:platformer-template:compileRom` no longer emits any Defect 2 error 20.

2. **Defect 3 — Tilemap WIDTH / HEIGHT symbols never declared**: References to `_zone_<id>_tilemap_WIDTH` and `_zone_<id>_tilemap_HEIGHT` in `setup_current_level` must resolve for all three gameplay zones.
   - Current: `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded` references these symbols speculatively, but no producer exists in the codegen pipeline. `_zone_<id>_tileset.h` headers emitted by `ConvertZoneTilesetsTask` do not contain `WIDTH` / `HEIGHT` constants. `error 20: Undefined identifier '_zone_world1Area1Zone_tilemap_WIDTH'` fires 6 times (3 zones × 2 dimensions).
   - Target: Either (a) `ConvertZoneTilesetsTask` emits `#define _zone_<id>_tilemap_WIDTH <N>` and `#define _zone_<id>_tilemap_HEIGHT <M>` into the corresponding `_zone_<id>_tileset.h`, where `<N>` and `<M>` are the tilemap pixel-grid dimensions from the source PNG, OR (b) the pipeline reads `mapWidth` / `mapHeight` from `game_metadata.json` at codegen time and substitutes literal values into the per-case body.
   - Acceptance: For each gameplay zone (world1Area1, world1Area2, world2Area1), `grep -c '_zone_<id>_tilemap_WIDTH' build/gbkt/generated/_zone_<id>_tileset.h` ≥ 1 (define path) **OR** the generated `setup_current_level` body contains no `_zone_<id>_tilemap_WIDTH` reference (substitution path); `:compileRom` emits no Defect 3 error 20.

3. **Defect 4 — `_player_x` / `_player_y` / `_player_vx` / `_player_vy` / `_grounded` undefined**: The five symbols referenced by the tilemap-physics branch of `PlatformerVisitor` must resolve.
   - Current: `PlatformerVisitor.buildTilemapPhysicsUpdateFunction` (Plans 12-11/12-13) references `_player_x`, `_player_y`, `_player_vx`, `_player_vy`, `_grounded` (no prefix on position, `_player_` on velocity, bare `_grounded`). The `game.h` actor-extern path declares `_plat_vx`, `_plat_vy`, `_plat_grounded`, `_plat_coyote_timer`, `_plat_jump_buffer`, `_jump_increase_timer` (different prefix). Neither path declares `_player_x` / `_player_y`. The example DSL `PlatformerTemplate.kt` omits a `val player by actor { position(...); hitbox(...) }` declaration (Plan 12-16 SUMMARY §Known Stubs). 22 `error 20` instances across `main.c` lines 312-368.
   - Target: Reconcile the two naming conventions to a single source of truth. Either (a) rewrite `PlatformerVisitor`'s tilemap-physics path to use the `_plat_*` prefix (matching the existing actor-extern contract), OR (b) declare the five `_player_*` / `_grounded` symbols at the pipeline level via a new `buildTilemapPhysicsGlobals` (mirroring Plan 12-08's `buildTilemapCollisionGlobals`), OR (c) require a user-DSL `val player by actor { position(x, y); hitbox(0, 0, 8, 24) }` declaration that emits the `_player_*` globals via the existing actor-property delegate path. Whichever path is chosen, the example `PlatformerTemplate.kt` must declare a player actor with position + hitbox if the chosen path requires it.
   - Acceptance: `:compileRom` emits zero Defect 4 errors (no `_player_x`, `_player_y`, `_player_vx`, `_player_vy`, `_grounded` undefined-identifier errors); the resolution path is documented in a new JVM emission-invariant test added in 12.1 (analogous to `TilemapCollisionEmissionTest`).

4. **Defect 5 — `_posX` / `_posY` undefined (metasprite render in `bank1.c`)**: `MetaspriteVisitor.moveMetasprite` lowering must reference symbols that exist.
   - Current: `MetaspriteVisitor` lowers `moveMetasprite(player)` to `move_metasprite_ex(...DEVICE_SPRITE_PX_OFFSET_X + (_posX >> 4), DEVICE_SPRITE_PX_OFFSET_Y + (_posY >> 4))`. `_posX` / `_posY` are magic names not declared by any pipeline component or DSL builder. Pre-existing visitor expectation appears to assume an actor-positioning contract that does not fire when no actor is bound. 4 `error 20` instances at `bank1.c` lines 52-68.
   - Target: Either (a) rewrite `MetaspriteVisitor` to read the bound actor's position-property convention (`_<actorName>_x` / `_<actorName>_y` — which becomes `_player_x` / `_player_y` once Defect 4 lands), OR (b) declare `_posX` / `_posY` as pipeline-emitted globals when an unbound metasprite is detected. Option (a) is preferred because it composes with Defect 4's actor-declared player; option (b) is a fallback if the visitor cannot statically resolve the bound actor name.
   - Acceptance: `:compileRom` emits zero Defect 5 errors (no `_posX`, `_posY` undefined-identifier errors); generated `bank1.c` references either `_player_x`/`_player_y` (option a) or declared `_posX`/`_posY` globals (option b).

5. **Regression guard — existing example ROMs unchanged**: All currently-shipping example ROMs must continue to build GREEN with byte-identical (or near-byte-identical) generated C.
   - Current: banks, pong, breakout, simple-physics, metasprites all build GREEN at the pre-12.1 baseline (commit `fb4c6037`).
   - Target: After 12.1's codegen-contract changes land, each of the 5 example ROMs continues to build GREEN; any diff in their generated `main.c` / `bank<N>.c` is either zero (preferred) or documented in 12.1's terminal-plan SUMMARY.md as an expected consequence of the contract change.
   - Acceptance: `./gradlew :gbkt-examples:banks:buildRom :gbkt-examples:pong:buildRom :gbkt-examples:breakout:buildRom :gbkt-examples:simple-physics:buildRom :gbkt-examples:metasprites:buildRom` all exit 0; `git diff` against the pre-12.1 baseline for `gbkt-examples/<game>/build/gbkt/generated/*.c` is either empty or has an entry in the 12.1 SUMMARY explaining each non-empty diff.

6. **Terminal — platformer-template ROM produced with valid bank layout**: The first-buildRom milestone (deferred from 12-18) closes successfully.
   - Current: No `build/gbkt/output/platformer-template.gb` exists. No `.noi` produced (compileRom fails before link step).
   - Target: A GREEN `:gbkt-examples:platformer-template:buildRom` invocation produces both `platformer-template.gb` (any size) and `platformer-template.noi`; every `DEF l__CODE_<N>` byte size in the `.noi` is ≤ 16 384 (Phase 11 D-15 hard cap, carry-forward per Phase 12 D-17).
   - Acceptance: `test -f gbkt-examples/platformer-template/build/gbkt/output/platformer-template.gb` exits 0; `test -f gbkt-examples/platformer-template/build/gbkt/output/platformer-template.noi` exits 0; `awk '/^DEF l__CODE/ { n=strtonum($NF); if (n > 16384) { print "OVERFLOW " $0; e=1 } } END { exit e }'` on the `.noi` exits 0.

## Boundaries

**In scope:**
- Reconciling Defects 2-5 from `evidence/first-buildrom.md` so `:buildRom` is GREEN.
- One JVM emission-invariant test per defect that locks the chosen contract (mirroring the per-function awk brace-walk pattern from Plan 12-09).
- Regression sweep across the 5 currently-shipping example ROMs.
- Any minimal DSL-side change required by the chosen defect-resolution path (e.g., adding `val player by actor { ... }` to `PlatformerTemplate.kt` if option (c) of Defect 4 is chosen).
- The terminal `:buildRom` smoke per `feedback_rom_build_smoke_test_for_codegen_phases.md` and `feedback_many_small_plans_terminal_subphase.md`.

**Out of scope:**
- Phase 12 Wave 12+ work (UAT anchors 12-19..23, oracle artifact 12-24, retire-old-example 12-25, regression sweep 12-26, admin close 12-27) — Phase 12 resumes after 12.1 ships.
- New framework primitives surfaced by these defects (e.g., a typed `Cartridge` enum, structured actor-position-property naming convention) — those route to Phase 13's rolling collector per the existing Phase 13 trigger mechanism.
- Visual / UAT correctness — 12.1 ships when `:buildRom` is GREEN, not when the ROM gameplay is correct. Anchor verification happens in Phase 12 Waves 12-14.
- Cross-genre adoption of any reconciliation pattern (e.g., applying the same `_<actorName>_x/_y` lookup to RPG / shmup actors) — 12.1 fixes the contract; broader rollout is Phase 13 territory.
- Any 12.1.1 or 12.2 follow-up — terminal subphase per `feedback_many_small_plans_terminal_subphase.md`. If a defect surfaced in 12.1 cannot be absorbed inline, it routes to Phase 13.

## Constraints

- **Gate-predicate invariance**: Each codegen change must remain gated by the same predicate (`gameUsesTilemapCollision == true` for tilemap-physics path; equivalent gates elsewhere) so non-tilemap games stay byte-identical. The regression sweep in Requirement 5 is the explicit check.
- **Per-bank size**: Every ROM bank in the produced `.noi` must remain ≤ 16 384 bytes (Phase 11 D-15, Phase 12 D-17).
- **No new public DSL surface unless strictly required by a defect's resolution path**: Defect 4 may force adding `val player by actor { ... }` to the example DSL (which uses existing primitives), but creating new keywords / delegates is out of scope.
- **Terminal**: 12.1 must close the defect cluster completely — `feedback_many_small_plans_terminal_subphase.md`. The plan list ends with a buildRom-smoke plan that exits 0.
- **No magic strings**: Per `feedback_no_magic_strings.md`, any new DSL surface must reflect names from property delegates / lambda params — no string-typed identifiers.
