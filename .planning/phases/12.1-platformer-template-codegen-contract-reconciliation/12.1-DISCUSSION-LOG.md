## Defect 2 — BANK() macro path

| Option | Description | Selected |
|--------|-------------|----------|
| (a) Codegen literal `1u` for HOME tilemaps | GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded emits `_current_area_bank = 1u;` instead of `BANK(_zone_<id>_tilemap)`. Smallest blast radius — single visitor method. Locks the assumption that tilemaps are HOME-resident. | |
| (b) Move tilemaps to non-HOME bank | ConvertZoneTilesetsTask emits `#pragma bank N` at the top of each `_zone_<id>_tilemap.c`. BANK(...) resolves naturally via SDCC. Bigger blast radius — touches ConvertZoneTilesetsTask + BankingAnalysisPass + may shuffle bank layout for existing examples (regression risk). | ✓ |
| (c) Emit explicit `_BANK` `#define` | ConvertZoneTilesetsTask writes `#define _zone_<id>_tilemap_BANK <N>` into tileset.h. Pipeline emits `_current_area_bank = _zone_<id>_tilemap_BANK;`. Adds one symbol per tilemap; keeps placement flexible; symmetric with Defect 3's #define approach. | |

**User's choice:** initially "I want the correct solution, not one that is the easiest. But I am unable to judge which one it is." → after Claude's architectural reasoning, locked option (b).

**Notes:**
- Claude advised (b) because (a) locks tilemap data into HOME bank forever; HOME is ~16 KB shared with main loop / scene dispatch / all helpers; Phase 12 has 5 zone tilemaps and risks blowing the 16 KB-per-bank cap (Phase 11 D-15) that Requirement 6 verifies.
- (a) also makes the existing `SWITCH_ROM(_current_area_bank)` machinery (Plan 07.4-30) vestigial — always switches to bank 1, which is a no-op when already there. Vestigial code is a smell.
- (c) parallels SDCC's native `__bank_<sym>` with a manual define — redundant when (b) does the job natively.
- (b) activates the existing SWITCH_ROM wrapper for its intended purpose and matches the established dungeon-zone pattern (`zone_bank2.c` with bank-2 tilemap arrays).

## Defect 3 — WIDTH/HEIGHT symbol source

| Option | Description | Selected |
|--------|-------------|----------|
| (a) `#define` in tileset.h via ConvertZoneTilesetsTask | Task emits `#define _zone_<id>_tilemap_WIDTH <N>` + `_HEIGHT <M>` into `_zone_<id>_tileset.h` alongside the `#pragma bank` from Defect 2. Symbolic, debuggable, same task as Defect 2. | ✓ |
| (b) Literal substitution from game_metadata.json | GBDKPipelineV2 reads mapWidth/mapHeight from `game_metadata.json` and substitutes literal values into the per-case body. Creates a metadata→codegen data-flow loop the pipeline currently doesn't have. | |
| Push back — reason for concern | (offered as escape) | |

**User's choice:** option (a).

**Notes:**
- (a) keeps the contract symbolic and debuggable; a developer inspecting `_zone_world1Area1Zone_tileset.h` sees `#define _zone_world1Area1Zone_tilemap_WIDTH 32` with full provenance.
- (a) composes naturally with D-01 (Defect 2): both contracts owned by ConvertZoneTilesetsTask, both verified by the same pair of fix-then-test plans.
- (b) was rejected because `game_metadata.json` is currently pipeline OUTPUT, not input; routing back into `GBDKPipelineV2` would create a new ordering constraint.

## Defects 4 + 5 — Player position symbol convention (COUPLED)

| Option | Description | Selected |
|--------|-------------|----------|
| (i) `val player by actor { position(); hitbox() }` | Matches Phase 12 D-12b's hitbox-driven probe intent. Actor-property delegate emits `_player_x`/`_y`. Requires verifying actor + standalone metasprite descriptor coexist on the same logical entity; may need codegen wiring for actor.metasprite vs actor.sprite. | |
| (ii) `var playerX by i16Var(...)` + metasprite `pos(playerX, playerY)` | DSL declares position vars + binds metasprite via existing `pos(varRef)` API. PlatformerVisitor rewrites physics path to read/write the user's property names. `tilemapCollision` gets explicit `position(varRef, varRef) + hitbox(...)` configuration. No actor required. | ✓ |
| (iii) Pipeline-emitted `_plat_x`/`_y` globals | PlatformerVisitor.buildTilemapCollisionGlobals declares `_plat_x`/`_y` alongside `_plat_vx`/`_vy`. Physics-update renamed to `_plat_*`. User-DSL has no handle on player position from scene scripts. Forces magic binding from metasprite to pipeline globals. | |
| Other — I'll explain | (offered as escape) | |

**User's choice:** option (ii).

**Notes:**
- (ii) uses the documented `pos(varRef)` API (MetaspriteBuilder.kt:140-145) as intended — the metasprite IR's `posXVarName` / `posYVarName` fields already propagate to MetaspriteVisitor's emission.
- (ii) lets the user own player state via their own property delegate, matching `feedback_no_magic_strings.md` and the declarative-over-imperative core principle.
- (iii) was rejected because it hides player position from user DSL — user can't write `playerX set 80` from a scene script — and forces a magic binding from metasprite to pipeline-emitted globals.
- (i) was rejected because actor + metasprite composition is unverified — actor uses sprite slot; metasprite uses descriptor render; the two don't naturally converge. Would force additional codegen wiring not required by (ii).
- The 5-point bounding-box probe (Phase 12 D-12b "auto-derived from actor hitbox") becomes explicit `tilemapCollision { position(playerX, playerY); hitbox(0, 0, 8, 24) }` configuration — more explicit than implicit actor-derivation; easier to test.
