## Defect 6 — `BANK()` macro vs. data-array `#pragma bank` mismatch

### Symptom

```
gbkt-examples/platformer-template/build/gbkt/generated/main.c:146: error 20: Undefined identifier '__bank__zone_world1Area1Zone_tilemap'
gbkt-examples/platformer-template/build/gbkt/generated/main.c:159: error 20: Undefined identifier '__bank__zone_world1Area2Zone_tilemap'
gbkt-examples/platformer-template/build/gbkt/generated/main.c:172: error 20: Undefined identifier '__bank__zone_world2Area1Zone_tilemap'
```

Three instances — one per gameplay zone (`world1Area1Zone`, `world1Area2Zone`, `world2Area1Zone`). `titleZone` and `nextLevelZone` are not referenced from `setup_current_level` and so do not error.

### Evidence — SDCC does not synthesize `__bank_<sym>` for data arrays

Manual compile of `gbkt-examples/platformer-template/build/gbkt/generated/_zone_world1Area1Zone_tilemap.c` with `lcc -c -Wa-l`:

```
.module _zone_world1Area1Zone_tilemap
;--------------------------------------------------------
; Public variables in this module
;--------------------------------------------------------
	.globl __zone_world1Area1Zone_tilemap     ; ← data symbol, single underscore prefix
;--------------------------------------------------------
...
	.area _CODE_2                              ; ← #pragma bank 2 took effect (placed in bank 2)
	.area _CODE_2
__zone_world1Area1Zone_tilemap:
	.db #0x00	; 0
	.db #0x01	; 1
	...
```

The symbol table emits only `__zone_world1Area1Zone_tilemap` (the data symbol). There is no `__bank__zone_world1Area1Zone_tilemap` symbol — SDCC does **not** auto-synthesize the bank-tracking symbol for `const uint8_t[]` arrays from `#pragma bank N` alone. The synthesis only fires for **banked function definitions** (where the linker needs to know the bank to install the trampoline).

### Why Banks works and platformer-template doesn't

`gbkt-examples/banks/build/gbkt/generated/bank1.c` line 23:

```c
_bkg_tiles_load_banked(2u, 0u, 0u, 20u, 18u, _zone_play_zone_tilemap);
```

The bank number `2u` is passed as a literal (sourced from `BankingAnalysisPass` allocation in the in-memory IR — banks's `_zone_play_zone_tileset` has its bank known at codegen-time before the data array is generated). No `BANK()` macro is used.

Platformer-template's `setup_current_level` (main.c lines 146, 159, 172) uses:

```c
_current_area_bank = BANK(_zone_world1Area1Zone_tilemap);
```

The `BANK()` macro expands to `__bank__zone_world1Area1Zone_tilemap` at preprocessor time, which is then resolved at link time. For functions, GBDK's lcc/sdldgb pipeline synthesizes the `__bank_<func>` symbol for banked function definitions. For data arrays, **no such synthesis exists** in SDCC/GBDK.

### Why Plan 12.1-01's option (b) doesn't close Defect 2 fully

SPEC §Defect 2 §Target offered three options:
- (a) Substitute literal `1u` (HOME bank) — rejected because tilemap data exceeds HOME budget.
- (b) `#pragma bank N` annotation — **chosen** per D-01.
- (c) Explicit `#define _zone_<id>_tilemap_BANK <N>` symbol that the pipeline reads — rejected.

Option (b) was selected on the assumption that `#pragma bank N` would cause SDCC to synthesize `__bank_<sym>` for the data array, so `BANK(_zone_<id>_tilemap)` would resolve at link. **This assumption is incorrect for data arrays.** Plan 12.1-02's test only locks the *emission* of `#pragma bank N` — it does not lock the resolution of `__bank_<sym>` at link time (because JVM-tier tests cannot observe SDCC's symbol-synthesis behavior).

The correct closure for Defect 2 in the presence of data-array references is one of:

- **(c-prime) Pipeline-reads-bank substitution.** Rewrite `buildSetupCurrentLevelFunctionIfNeeded` to read `bankAllocation[zoneId]` (already available — it's an internal map on the pipeline) and emit the literal bank number `Nu` instead of `BANK(_zone_<id>_tilemap)`. The `_current_area_bank = 2u;` form has no `__bank_` symbol dependency. This is **the same shape banks already uses** for `_bkg_tiles_load_banked`'s first arg.
- **(d) Manual `__bank_<sym>` assembly emission.** Emit an inline assembly directive `__bank__zone_<id>_tilemap = N` inside `_zone_<id>_tilemap.c`, mimicking what SDCC does for banked functions. This is the more general fix (preserves the `BANK()` macro abstraction in user code) but requires inline-asm or `#define __bank_<sym> N` machinery that is more invasive than (c-prime).
- **(e) Hybrid: pipeline-substitute at the call site, keep the macro for documentation.** Emit `_current_area_bank = 2u; /* was BANK(_zone_<id>_tilemap) */`. This is the lowest-risk surgical fix.

### Recommended path (for the human approver)

Option **(c-prime)** is recommended: rewrite `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded` to substitute the literal bank from `bankAllocation` map. This:

- mirrors the working pattern in `bank1.c` (`_bkg_tiles_load_banked(2u, ...)`).
- requires a single visitor change (the pipeline already has the `bankAllocation` map available).
- preserves the option-(b) `#pragma bank N` emission (still needed so the data actually lands in bank N).
- is testable via a JVM-tier emission-invariant test in `GBDKPipelineV2Test` (locks `_current_area_bank = 2u` shape).
- closes the visual hole: future per-zone bank-allocation changes flow through one source of truth (the BankingAnalysisPass / `allocateZoneBanks` result).
