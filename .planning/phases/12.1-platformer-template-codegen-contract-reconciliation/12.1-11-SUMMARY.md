# Phase 12.1 Plan 11: Substitute literal bank in setup_current_level (Defect 6 fix, option c-prime) Summary

Rewrote `GBDKPipelineV2.buildSetupCurrentLevelFunctionIfNeeded` to emit
`_current_area_bank = <N>u;` (literal bank number from the in-memory
`bankAllocation` map) instead of `_current_area_bank = BANK(_zone_<id>_tilemap);`
— closing Defect 6 by eliminating the SDCC link-time dependency on the
never-synthesized `__bank__zone_<id>_tilemap` symbol while preserving
Plan 12.1-01's `#pragma bank N` data placement.

## What this plan changed

### `gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/GBDKPipelineV2.kt`

| Line range | Change |
|---|---|
| 2291–2294 | Function signature changed from `buildSetupCurrentLevelFunctionIfNeeded(gameIR: GameIR): String?` to `buildSetupCurrentLevelFunctionIfNeeded(gameIR: GameIR, bankAllocation: Map<String, Int>): String?` |
| 2303–2318 | Inserted bank resolution: `val bank = bankAllocation[zone.id] ?: 1` plus a `bankFallbackComment` that emits `/* fallback: bankAllocation missing zoneId; safe HOME-adjacent */` only when the lookup misses. Preceded by an 8-line Kotlin comment explaining the option c-prime rationale (SDCC does not synthesize `__bank_<sym>` for data arrays under `#pragma bank N`, only for banked function defs) |
| 2332 | Per-case body emission changed from `_current_area_bank = BANK(_zone_${zoneSanitized}_tilemap);` to `_current_area_bank = ${bank}u;${bankFallbackComment}  // Defect-6 fix: literal bank from bankAllocation (option c-prime)` |
| 1128 | Call site updated: `buildSetupCurrentLevelFunctionIfNeeded(gameIR)` → `buildSetupCurrentLevelFunctionIfNeeded(gameIR, bankAllocation)`. `bankAllocation` was already in scope as a parameter of the enclosing `buildHomeFile(gameIR, bankAllocation)` function (line 834). |

The other 5 per-case body lines (`_current_level_map`, `_current_level_width_in_tiles`,
`_current_level_height`, `_current_level_width`, `_current_level_non_solid_tile_count`,
`break;`) are UNCHANGED — they reference data symbols (`_zone_<id>_tilemap`,
`..._tilemap_WIDTH`, `..._tilemap_HEIGHT`) that SDCC DOES resolve at link time via
the `extern` declarations Plan 12.1-03 contract emits in tileset headers.
