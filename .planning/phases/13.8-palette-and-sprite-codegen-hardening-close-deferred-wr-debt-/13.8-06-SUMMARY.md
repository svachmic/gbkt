# Phase 13.8 Plan 06: Zone Bank Single-Source Field (Req 6) Summary

SceneIR gains `allocatedZoneBank: Int? = null` as a pipeline-transient annotation populated by
`buildCFiles` after `allocateZoneBanks()` returns, consumed by `SceneVisitor` as the authoritative
bank source. D-03 zero-delta preserved — platformer-template generated C is byte-identical.

## One-liner

`SceneIR.allocatedZoneBank: Int? = null` threaded from `allocateZoneBanks` through `buildCFiles`
into `SceneVisitor` — single-source IR-level bank truth (D-01 field-over-lookup, Req 6).

### Task 2: Pipeline population + SceneVisitor field read (Req 6)

**GBDKPipelineV2.kt:**
```kotlin
// After allocateZoneBanks(gameIR) in buildCFiles:
val gameIRWithBanks = if (bankAllocation.isNotEmpty() && gameIR.zones.isNotEmpty()) {
    val scenesWithBanks = gameIR.scenes.map { scene ->
        val zoneBank = scene.zoneRefs.firstNotNullOfOrNull { bankAllocation[it] }
        if (zoneBank != null) scene.copy(allocatedZoneBank = zoneBank) else scene
    }
    gameIR.copy(scenes = scenesWithBanks)
} else {
    gameIR
}
// All sub-calls now use gameIRWithBanks (homeFile, sceneFile, headerFile, tilemapBankFiles)
```

    scene.allocatedZoneBank           // D-01: single-source field (populated by pipeline)

## Decisions Made

1. **D-01 field-over-lookup**: `allocatedZoneBank` as explicit IR field over a direct
   `zoneBankAllocation` map lookup at SceneVisitor time. Provides structural single-source
   guarantee: the field IS the bank authority, map lookup is a fallback.

2. **SceneVisitor fallback retained**: `scene.allocatedZoneBank ?: zoneBankAllocation[zoneId] ?: error(...)`
   keeps backward compatibility for test fixtures and multi-zone scenes that populate `zoneRefs`
   with multiple IDs (the field stores the first zone's bank).

3. **NOT serialized**: Pipeline-transient field, recomputed each codegen run. Same treatment as
   `bankSlot`/`vramRange`/`oamSlot` (all three are serialized in `GameIRSerializer`, but
   `allocatedZoneBank` differs — it is purely a pipeline-internal propagation channel, not a
   user-authored annotation). See RESEARCH Open Question 3 + Assumption A2.

4. **gameIRWithBanks flows to all sub-calls**: `buildHomeFile`, `buildSceneFile`, `buildHeaderFile`,
   and `buildTilemapBankFiles` all receive the enriched `gameIRWithBanks` for consistency.
   This is a structural improvement: if any future pipeline stage also reads `allocatedZoneBank`,
   it will receive the populated value without additional wiring.
