<objective>
Eliminate two architectural latents in `GBDKPipelineV2` that share a single `MetaspriteIR` IR-field change (D-02 diagnose-first; RESEARCH recommends Option B over Option A): Req 5 derives the `set_sprite_palette` OBJ slot from each metasprite's declared sub-palette instead of list position (12.9 WR-05), and Req 4 makes the asset-driven OBJ upload suppression scene-scoped instead of game-global (13.7 WR-05). Behind the zero-delta byte-identity gate (D-03).

Purpose: Currently `mapIndexed { slot, ms -> set_sprite_palette(${slot}u, ...) }` binds slot to list order, and `hasSpritePalette = gameIR.palettes.any { SPRITE }` is game-global — any single `spritePalette{}` anywhere suppresses asset-driven OBJ auto-upload game-wide. Both break silently for multi-scene / multi-metasprite games. The fields default to null → list-index / game-global fallback, preserving byte-identity for the two shipped shapes.
Output: `MetaspriteIR.initialSubPaletteSlot` + `MetaspriteIR.sceneId`; pipeline reads both; the two Wave 0 RED tests GREEN; byte-identity oracles GREEN.
</objective>
