# Phase 13.8: palette and sprite codegen hardening — close deferred WR debt — Specification

**Created:** 2026-06-06
**Ambiguity score:** 0.19 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

Close the full cluster of deferred code-review warnings carried out of Phases 12.9 and 13.7 — revive the dead BG palette-polarity guard (rank per GBC sub-palette), consolidate the duplicated palette/RGB conversion into a single `PngUtils` source on a consistent quantization grid, and architecturally eliminate the palette-slot / bank-literal latents (scene-scoped sprite-palette suppression, slot derived from declared sub-palette, allocated zone bank threaded through `SceneIR`) — with zero visual regression to the shipped platformer-template and metasprites ROMs.

## Background

Phases 12.9 (palette-inversion asset pipeline) and 13.7 (platformer color polarity) both shipped working visual fixes but closed with documented code-review debt that was deferred rather than fixed. `12.9-REVIEW.md` left WR-04/WR-05 `UNCHANGED` at close; `13.7-REVIEW.md` raised WR-01/02/03/04/05 + IN-01/02/03. The v1.0 milestone was prematurely flagged `milestone_complete` despite this debt and has been REOPENED to absorb this phase. None of these items causes a *current* visible defect — the platformer (BG sky light, player body light) and metasprites (solid elephant outline) render correctly after 13.7. The risk is structural: a guard that cannot fire, duplicated logic that will drift, and latent palette/bank coupling that breaks silently the moment a multi-scene or multi-metasprite game is built.

Grounded current state (verified in source):
- `PngUtils.checkPalettePolarity` (`gbkt-gradle-plugin/.../PngUtils.kt:249-307`) ranks all 16 PLTE entries as one flat Spearman series; `world1-tileset.png` has 12/16 zero-padded entries → tied averaged ranks make a strict −1.0 mathematically unreachable → the advertised BG regression guard is dead for the one shipped BG asset. The flat ranking also crosses the four independent 4-entry GBC sub-palette boundaries (WR-02).
- Palette-parse + RGB8→RGB555 packing is duplicated near-verbatim across `ConvertSpritesTask` (`parseSpriteRgb555Values`) and `ConvertZoneTilesetsTask` (`parsePaletteRgb555Values` + `parseRgb8OrIntValues`), violating the `PngUtils` single-source charter (WR-03). The two copies already diverge in empty-result handling (IN-02). The packing truncates (`r5 = r8 * 31 / 255`) while `checkPalettePolarity` ranks the source on exact 8-bit values — an apples-to-oranges luminance grid that can flip ranks near ties (13.7 WR-04).
- `GBDKPipelineV2.kt:5022-5074` gates the asset-driven OBJ upload on the game-global predicate `gameIR.palettes.any { it.type == PaletteType.SPRITE }` (`hasSpritePalette`), and `set_sprite_palette(${slot}u, ...)` assigns OBJ slot = position in `gameIR.metasprites` with no binding to each metasprite's declared sub-palette (13.7 WR-05 + 12.9 WR-05).
- `PlatformerExtensions.kt:889-896` hardcodes `_bkg_tiles_load_banked(2u, ...)`, duplicating the SceneVisitor's bank literal for the same zone; if `BankingAnalysisPass` repacks the tilemap the two literals diverge silently (12.9 WR-04).
- A visitor-count KDoc is stale (says 37; actual 54) (13.5 trivial).

This phase was routed through the proper spec→discuss→plan chain per the wide-blast-radius rule (shared `PngUtils` comparator + both convert tasks + the new IR-layer `SceneIR` change).

## Requirements

1. **Per-sub-palette polarity guard (revives dead BG guard)**: `checkPalettePolarity` ranks luminance per 4-entry GBC sub-palette group, not over the flat 16-entry array.
   - Current: Flat 16-entry Spearman ranking; 12 zero-padded tied entries on `world1-tileset.png` make strict −1.0 unreachable → guard returns `false` even for a truly inverted first-four colors. Crosses sub-palette boundaries.
   - Target: Comparator evaluates inversion independently per 4-entry sub-palette (taking or inferring the stride), skipping all-equal-luminance degenerate groups; returns `true` if any meaningful sub-palette is a strict reversal.
   - Acceptance: A RED→GREEN unit test constructs a synthetic 16-entry palette whose first 4-entry sub-palette is a strict luminance reversal with the remaining 12 entries zero-padded, and asserts the comparator now returns `true` (it returns `false` under the flat ranking). A second test asserts a correctly-ordered 4×4 palette returns `false`.

2. **Single-source palette/RGB conversion in PngUtils (WR-03 + IN-02)**: The `palette_color_t` parse and RGB8→RGB555 packing live in one `PngUtils` function; both convert tasks delegate.
   - Current: `parseSpriteRgb555Values` (ConvertSpritesTask) and `parsePaletteRgb555Values` + `parseRgb8OrIntValues` (ConvertZoneTilesetsTask) duplicate the regex parse, RGB8 loop, packing, and decimal/hex fallback verbatim; empty-result handling diverges (one returns empty list, the other coerces to null).
   - Target: A single `internal fun` in `PngUtils.kt` (e.g. `parsePaletteRgb555Values(file, symbol): List<Int>?`) plus the RGB8→RGB555 helper; both tasks call it; empty result consistently coerces to `null`.
   - Acceptance: `grep` shows the parse/packing regex and the `* 31 / 255` packing appear exactly once in the codebase (in `PngUtils.kt`) and zero times in either convert task body. Existing zone-tileset and sprite conversion tests remain GREEN (delegation is behavior-preserving for the shipped assets).

3. **Consistent luminance quantization grid (13.7 WR-04, folded into WR-03)**: The polarity comparator computes source and emitted luminance on the same RGB555 5-bit grid.
   - Current: Emitted side is truncated to RGB555 and back; source side uses exact 8-bit PLTE values → two series on different quantization grids → rank flips near luminance ties (false pos/neg).
   - Target: Quantize the source PLTE to RGB555 (`to5(c) = (c * 31 / 255) * 255 / 31`) before computing source luminance, so both series live on the 5-bit grid the hardware displays; the shared helper from Req 2 is the single conversion path.
   - Acceptance: A RED→GREEN unit test with two source colors that differ in 8-bit luminance but collapse to equal RGB555 luminance asserts the comparator treats them as tied (no spurious inversion) — proving both sides quantize identically.

4. **Scene-scoped sprite-palette suppression (architectural; 13.7 WR-05)**: The asset-driven OBJ upload suppression is decided at scene scope, not game-global.
   - Current: `hasSpritePalette = gameIR.palettes.any { it.type == PaletteType.SPRITE }` is game-global; any single `spritePalette{}` anywhere suppresses asset-driven OBJ auto-upload game-wide.
   - Target: Suppression is determined by whether the scene that owns the metasprite is the OBJ-palette authority (scene-scoped predicate), so a non-owning `spritePalette{}` declared elsewhere does NOT suppress an asset-driven metasprite's upload.
   - Acceptance: A RED→GREEN JVM codegen-shape test builds a synthetic multi-scene `GameIR` where a `spritePalette{}` is declared for a non-owning scene and an asset-driven metasprite lives in another scene; asserts the generated C still emits the asset-driven `set_sprite_palette` upload (not suppressed). The two shipped shapes (platformer = no spritePalette; metasprites = has spritePalette) keep their current generated-C output (byte-identity oracle GREEN).

5. **Slot derived from declared sub-palette (architectural; 12.9 WR-05)**: The `set_sprite_palette` OBJ slot is derived from each metasprite's declared sub-palette, not its list position.
   - Current: `mapIndexed { slot, ms -> set_sprite_palette(${slot}u, 1u, ...) }` uses list-order index; no binding to the metasprite's OAM `subPalette` attribute / `_<id>_subPalette` variable.
   - Target: The upload slot is sourced from the metasprite's declared sub-palette so the upload slot and the draw-path sub-palette reference always agree, regardless of list order.
   - Acceptance: A RED→GREEN JVM codegen-shape test builds a `GameIR` with ≥2 metasprites whose declared sub-palettes are NOT in list order and asserts each emitted `set_sprite_palette(slot, ...)` slot matches the metasprite's declared sub-palette (not its index). Single-metasprite shipped case keeps current output (byte-identity GREEN).

6. **Allocated zone bank threaded through SceneIR (architectural; 12.9 WR-04)**: The card-scene tilemap re-place sources its bank from the zone's allocated bank, eliminating the hardcoded `2u` dual-literal.
   - Current: `PlatformerExtensions.kt` hardcodes `_bkg_tiles_load_banked(2u, ...)`, duplicating the SceneVisitor literal; diverges silently if `BankingAnalysisPass` repacks.
   - Target: The allocated zone bank is carried via `SceneIR` metadata (or a bank-allocation lookup) to both emission sites so a single source of truth drives both literals; no hardcoded `2u`.
   - Acceptance: A RED→GREEN JVM test asserts the card-scene tilemap-place bank literal equals the SceneVisitor's bank literal for the same zone, sourced from `allocateZoneBanks` (changing the allocated bank in the fixture changes BOTH literals together). `grep` shows no hardcoded `2u` bank literal remains at `PlatformerExtensions.kt` for this re-place.

7. **Advisory cleanups (IN-01/02/03 + 13.5 KDoc)**: Fold the minor consistency and portability items into the relevant fixes.
   - Current: IN-03 test hardcodes an absolute `elephant.png` path (silently skips off the author's machine → zero CI coverage for the OBJ non-fatal path); IN-01 comparator exposes a `0.0` sentinel via full `spearmanCorrelation`; IN-02 empty→null divergence; the 13.5 visitor-count KDoc says 37 (actual 54).
   - Target: IN-03 test uses a walk-up search (mirroring `findPlatformerTemplatePng`) so it runs in CI; IN-01 narrowed to a boolean helper OR documented sentinel; IN-02 resolved by the Req-2 shared helper; the visitor-count KDoc corrected to 54.
   - Acceptance: The polarity warning test no longer contains an absolute filesystem path and exercises the OBJ path in a clean checkout (no skip-guard short-circuit when run from repo root). The visitor-count KDoc reads 54.

8. **No-regression + visual binding gate**: All shipped behavior is preserved and confirmed visually.
   - Current: Phase 13.7 shipped correct BG/OBJ polarity; 13.3-22/24 ascending-ramp sprite polarity and 12.9 D2a `-keep_palette_order` are in place; byte-identity oracles exist for metasprites/metasprites-stress.
   - Target: No regression of 13.3-22/24, 12.9 D2a, or 13.7's BG/OBJ polarity fixes; shipped ROM output for platformer-template and metasprites is unchanged.
   - Acceptance: 7-target `:buildRom` sweep EXIT 0 (pong PASS\* per known toolchain non-determinism); byte-identity oracles (`:gbkt-examples:metasprites:test`, `:gbkt-examples:metasprites-stress:test`) GREEN; existing 13.7 polarity guard/emission tests GREEN; binding MCP GBC reshoot of platformer-template (GBC mode + `.noi` symFile per platformer-MCP-needs-GBC-mode) and metasprites confirms zero visual regression with user sign-off.

## Boundaries

**In scope:**
- `PngUtils.checkPalettePolarity` per-sub-palette ranking rewrite (WR-01 + WR-02)
- Single-source palette/RGB555 parse+pack helper in `PngUtils` with consistent empty→null handling; both convert tasks delegate (WR-03 + IN-02)
- Consistent RGB555 luminance quantization on both comparator sides (13.7 WR-04)
- Scene-scoped sprite-palette suppression predicate (13.7 WR-05) — architectural
- `set_sprite_palette` slot derived from declared sub-palette (12.9 WR-05) — architectural
- Allocated zone bank threaded through `SceneIR` to the card-scene tilemap re-place (12.9 WR-04) — architectural, touches the IR layer
- Advisory cleanups: IN-03 portable test path, IN-01 sentinel narrowing/doc, IN-02 (absorbed by WR-03), 13.5 visitor-count KDoc
- RED→GREEN test per fix; JVM codegen-shape tests for the architectural latents (synthetic multi-scene/multi-metasprite `GameIR`, no new buildable example)
- 7-target buildRom sweep + byte-identity oracles + binding MCP visual reshoot (platformer + metasprites)

**Out of scope:**
- Any net-new DSL feature or runtime behavior — this is debt closure, not feature work
- A new example/fixture game in `gbkt-examples` — latent contracts are proved by JVM codegen-shape tests against synthetic `GameIR`, not a maintained buildable example
- Changing the shipped visual output of platformer-template or metasprites — the visual gate proves output is *unchanged*
- Reverting or re-tuning the 13.3-22/24 ascending-ramp polarity fix, 12.9 D2a `-keep_palette_order`, or 13.7's BG/OBJ polarity byte order — explicit no-regress constraints
- Other genres' palette/bank paths (puzzle, sport, rpg) beyond what the shared `PngUtils`/`SceneIR` change naturally touches — not part of this debt cluster
- Multi-language / localization, banking strategy redesign, asset-optimization passes — unrelated subsystems

## Constraints

- **No-regress set (hard):** must not change generated C for platformer-template or metasprites in a way that alters 13.3-22/24, 12.9 D2a, or 13.7 BG/OBJ polarity. Byte-identity oracles are the tripwire.
- **Wide blast radius:** the architectural latent fixes reach the IR layer (`SceneIR` metadata) and the GBDK pipeline + platformer genre extension — diagnose/plan must account for cross-module change (gbkt-ir → gbkt-backend-gbdk → gbkt-genre-platformer).
- **Diagnose-first** for the architectural latents (per `feedback_dont_pay_to_confirm_obvious` / `feedback_route_to_proper_phase_when_blast_radius_is_wide`): plan must ground the `SceneIR`/sub-palette/scene-scope changes in a read of the actual IR + pipeline before committing the edit.
- **No magic strings** (Project Rule #1): any new DSL/IR surface must reflect delegate/lambda names, never duplicate as String params.
- **buildRom smoke gate:** because this touches `PngUtils`/convert tasks/`GBDKPipelineV2`/`SceneIR`, the verifier MUST run a clean `:buildRom` sweep — JVM tests cannot see staleness in `build/gbkt/generated/`.
- **MCP GBC mode:** the binding reshoot must use `emulator_start` with `gbcMode=true` + `.noi` symFile (per `learning_platformer_mcp_needs_gbc_mode`); DMG captures read falsely green-tinted.
- **Terminal subphase:** close within 13.8 (gap plans flex to 13.8-NN); NO Phase 13.8.1. Resume target after close is PARENT Phase 13 (cross-check ROADMAP, not auto-advance).
- Pong rebuild hashes non-deterministically (`project_pong_toolchain_nondeterminism`) — flag PASS\* in the sweep, do not re-investigate.
