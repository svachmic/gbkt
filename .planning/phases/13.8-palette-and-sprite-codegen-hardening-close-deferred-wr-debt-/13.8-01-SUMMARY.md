### Task 2: Per-Sub-Palette Spearman Ranking (Req 1 GREEN)

Rewrote `checkPalettePolarity` in `PngUtils.kt`:

**Before (flat 16-entry):**
```kotlin
val sourceRanks = spearmanRanks(sourceLum)  // over all 16 entries
val emittedRanks = spearmanRanks(emittedLum)
spearmanCorrelation(sourceRanks, emittedRanks) < -1.0 + SPEARMAN_EPSILON
```

**After (per-4-entry sub-palette):**
```kotlin
if (n % subPaletteSize != 0) return false
(0 until n step subPaletteSize).any { base ->
    val srcGroup = sourceLum.subList(base, base + subPaletteSize)
    val emGroup  = emittedLum.subList(base, base + subPaletteSize)
    if (maxLum - minLum < SPEARMAN_EPSILON) return@any false  // skip degenerate
    spearmanCorrelation(spearmanRanks(srcGroup), spearmanRanks(emGroup)) < -1.0 + SPEARMAN_EPSILON
}
```

**Why this was dead:** With 12 zero-padded trailing entries, the flat Spearman ranking creates a mass-tie at zero luminance. The tied entries receive averaged ranks that push the maximum achievable correlation above -1.0 + EPSILON, making the strict inversion threshold mathematically unreachable for shipped assets like `world1-tileset.png`.

## Decisions Made

1. **Per-sub-palette loop uses `subPaletteSize = 4`** — hardcoded in the function body, not a parameter. GBC sub-palettes are always 4 entries; a parameter would invite misuse.
2. **Req 3 RGB555 quantization deferred** — The `to5()` source-side quantization (Req 3) is intentionally NOT included in this plan. Task 2 explicitly notes "pending 13.8-02" in a comment, keeping the Req 3 RED test `@Disabled` with the correct plan citation.
3. **`@kotlin.test.Ignore` in backend-gbdk** — `gbkt-backend-gbdk` uses `kotlin("test")` without JUnit5 on the classpath. Using `@org.junit.jupiter.api.Disabled` caused compile errors (`Unresolved reference 'jupiter'`). Fixed by using `@kotlin.test.Ignore` instead.
