## Decisions Made

1. **W1: IOException only** — The only legitimate I/O failure mode in `countUsedVisibleColors` is an unreadable PNG file (IOException). Once `ImageIO.read` succeeds and returns a non-null image, all subsequent raster scan operations are in-memory JVM operations. An `ArrayIndexOutOfBoundsException` in the scan loop would indicate a logic error in the bounds-check predicate, not an I/O failure — swallowing it to `0` would make `usedVisibleCount <= 3` true and silently pass the overflow guard.

2. **W2: caller-supplied stemName** — `ConvertSpritesTask` already computes `stemName` from the include path (line 281-282) as the canonical sprite id. Passing it explicitly to `prePermuteIndexedPng` keeps the collision-free naming at the call site where the id is derived, without requiring PngUtils to know about the include-path convention.

3. **W3: temporaryDir over sprites/tmp in @OutputDirectory** — Gradle's `@CacheableTask` fingerprints the `@OutputDirectory` tree. An undeclared file (temp PNG) inside that tree would cause the fingerprint to differ between a cached and a fresh run, breaking the reproducibility guarantee that the 13.6-07 byte-identity oracle proves. `Task.getTemporaryDir()` is explicitly excluded from output tracking by Gradle.

4. **W2+W3 coupled** — Per Pitfall 4 in the RESEARCH.md: relocating the directory alone still allows name collisions (old name = `gbkt_permuted_idle.png` for both `player/idle.png` and `enemy/idle.png`), and fixing the name alone doesn't remove undeclared files from `@OutputDirectory`. Both changes land in a single commit.
