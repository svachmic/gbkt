# Phase 13.8 Plan 02: Parse Consolidation + RGB555 Quantization Summary

Palette parse/pack consolidated to one PngUtils helper (Req 2, WR-03, IN-02); RGB555
source-side quantization in checkPalettePolarity (Req 3, WR-04) turns the @Disabled test GREEN.

## One-liner

quantization aligns both comparator sides on the 5-bit RGB555 grid the hardware displays.

### Task 2: Consistent RGB555 luminance quantization on the source side (Req 3 — TDD GREEN)

Applied `to5(c) = (c * 31 / 255) * 255 / 31` source-side quantization in `checkPalettePolarity`.

**Before (Phase 13.8-01 state):**
```kotlin
// Source used raw 8-bit PLTE values
val sourceLum = (0 until n).map { i ->
    0.299 * (srcReds[i].toInt() and 0xFF) +
        0.587 * (srcGreens[i].toInt() and 0xFF) +
        0.114 * (srcBlues[i].toInt() and 0xFF)
}
```

**After:**
```kotlin
// Both sides on the same RGB555 5-bit grid (Req 3)
fun to5(c: Int): Int = (c * 31 / 255) * 255 / 31
val sourceLum = (0 until n).map { i ->
    0.299 * to5(srcReds[i].toInt() and 0xFF) +
        0.587 * to5(srcGreens[i].toInt() and 0xFF) +
        0.114 * to5(srcBlues[i].toInt() and 0xFF)
}
```

**Why this matters:**
The emitted side already decodes RGB555 back to 8-bit via `r5*255/31`. Without source-side
quantization, two source PLTE colors like RGB(100,100,100) and RGB(103,103,103) have distinct
8-bit luminance (100 vs 103) but collapse to the same RGB555 value `(12,12,12)`. The old code
would rank them distinctly → a strict reversal was possible even when hardware shows identical
brightness → potential spurious inversion flag.

With `to5()`: both collapse to `(12*255/31) ≈ 98.7` → same luminance → tied ranks → strict
-1.0 is unreachable → `checkPalettePolarity` returns `false` (correct: no inversion perceived
by the hardware). This is the Pitfall 3 / Req 3 scenario described in 13.8-RESEARCH.md.

## Decisions Made

1. **`parsePaletteRgb555Values` as package-level `internal fun`** — both tasks are in the
   same `io.github.gbkt.gradle.tasks` package; no qualified name or object wrapper needed.
   Keeps the same accessibility model as other PngUtils helpers (`isIndexedPngShared`,
   `getTransparentIndexShared`, `checkPalettePolarity`).

2. **`to5()` as a local fun inside `checkPalettePolarity`** — co-located with its only use
   site (the source-luminance computation). A package-level `to5` would be exposed as an API
   surface with no other consumers; keeping it local prevents misapplication.

3. **Test rename is `parsePaletteRgb555Values` everywhere** — the old `parseSpriteRgb555Values`
   name was an OBJ-specific misnomer; the helper is format-agnostic (same regex + packing for
   BG and OBJ paths). Rename aligns the test with the consolidated name.
