# Phase 13.8: palette and sprite codegen hardening — close deferred WR debt - Context

**Gathered:** 2026-06-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Debt closure across the palette/sprite codegen path. Revive the dead BG palette-polarity
guard (rank per 4-entry GBC sub-palette), consolidate the duplicated palette/RGB conversion
into a single `PngUtils` source on a consistent RGB555 quantization grid, and architecturally
eliminate the palette-slot / bank-literal latents (scene-scoped sprite-palette suppression,
slot derived from declared sub-palette, allocated zone bank threaded through `SceneIR`) — with
**zero visual regression** to the shipped platformer-template and metasprites ROMs.

Not feature work — no net-new DSL/runtime behavior, no new buildable example. Latent contracts
are proved by JVM codegen-shape tests against synthetic `GameIR`.

</domain>

<decisions>
## Implementation Decisions

### IR bank-threading mechanism (Req 6)
- **D-01:** Thread the allocated zone bank via a **new explicit field on `SceneIR`**, populated by
  `BankingAnalysisPass` / `allocateZoneBanks`. Both emission sites (SceneVisitor literal + the
  card-scene tilemap re-place in `PlatformerExtensions.kt`) read it. Chosen over a shared lookup
  function for the stronger structural single-source guarantee — a field can't be "forgotten" the
  way a lookup call can.
- **D-02:** Diagnose-first still applies. The researcher/planner MUST read the actual `SceneIR`
  definition + `BankingAnalysisPass`/`allocateZoneBanks` wiring and confirm the field placement
  fits the existing IR pattern (constructor ripple, defaults, test fixtures) before committing the
  edit. The field is the chosen direction, not a blind mandate.

### No-regression gate posture (Req 8)
- **D-03:** **Zero-delta required.** ANY generated-C delta for platformer-template or metasprites is
  a regression that blocks the phase. The architectural refactors (Req 4/5/6) MUST produce
  byte-identical output for the two shipped shapes. The byte-identity oracle stays the hard
  automated tripwire; MCP GBC visual reshoot confirms. No re-pin-after-review escape hatch.
- **D-04:** Byte-identity baselines are current (re-pinned in 13.6-07 commit `8d956ba9`, now carry
  `-keep_palette_order`) — the oracle is trustworthy as-is. No baseline regeneration is in scope;
  if the refactor forces a baseline change, that signals a regression to investigate, not a re-pin.

### Opportunistic hardening scope (folded into Req 2)
- **D-05:** Fold **all three** deferred 13.6-07 PngUtils/ConvertSprites hardening items into this
  pass, since Req 2 is already rewriting `PngUtils`:
  - **W1** — narrow the over-broad `catch (_: Exception) { 0 }` in `countUsedVisibleColors`
    (`PngUtils.kt`) to `IOException`, so a scan-loop logic error propagates instead of silently
    bypassing the REQ-5 OBJ-palette overflow guard. (Natural fold — same file as Req 2.)
  - **W2** — key the deterministic permuted temp name on sprite id/`stemName`, not
    `file.nameWithoutExtension` (`ConvertSpritesTask.kt` + `prePermuteIndexedPng`), eliminating the
    latent same-basename-different-subdir collision.
  - **W3** — move `sprites/tmp` out of the task `@OutputDirectory` to `getTemporaryDir()`
    (`ConvertSpritesTask.kt:358`), so undeclared temp files stop polluting the build-cache fingerprint.

### Plan slicing / sequencing
- **D-06:** **Risk-ascending.** Slice the 8 reqs so pure-function fixes land first (Req 1
  per-sub-palette comparator, Req 2/3 PngUtils consolidation + RGB555 quantization, Req 7 cleanups +
  folded W1/W2/W3) — contained, no IR ripple — then the IR-layer architectural latents (Req 4
  scene-scope suppression, Req 5 slot-from-sub-palette, Req 6 SceneIR bank field) behind the
  zero-delta byte-identity gate. Final plan: Req 8 (7-target buildRom sweep + oracles + binding MCP
  GBC reshoot + user sign-off). Many small plans per the project's plan-granularity preference.

### Claude's Discretion

  dependencies + diagnose-first research).
- Test source-set placement for the synthetic-`GameIR` codegen-shape tests (per existing JVM-tier
  test conventions).

### Folded Todos
- **`13.6-07-convertsprites-hardening-followups`** — three deferred code-review warnings (W1 narrow
  catch, W2 temp-name keying, W3 temp-dir relocation) from the 13.6-07 gap closure. Originally
  parked as robustness/latent-hazard follow-ups. Folded here because Req 2 rewrites the same
  `PngUtils`/`ConvertSpritesTask` surface — see D-05.

<specifics>
## Specific Ideas

- Strong preference for a **field over a lookup** for Req 6 specifically because "a function call both
  sites must remember to use" is exactly the WR-04 failure mode being closed — the structural fix
  should make divergence impossible, not merely conventional.
- The zero-delta stance is deliberate quality posture: if a "behavior-preserving" refactor changes
  generated C, that is a finding to investigate, not paperwork to re-pin.

</specifics>
