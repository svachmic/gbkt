# Phase 10.1 Plan 20: Fix DEF-10.1-13-C Bootstrap-Order Mismatch — Summary

**Closed DEF-10.1-13-C at the codegen level by applying Plan 10.1-19's named cause (bootstrap-order mismatch in `GBDKPipelineV2.buildMainFunction`).** The four `set_sprite_palette()` writes are now emitted in `main()` BEFORE `DISPLAY_ON`, mirroring the GBDK reference's 9-step bootstrap sequence. The first PPU frame on GBC now composites with palette RAM in its final state instead of the post-`cgb_compatibility()` zero state that produced the all-black sprite render.

## What Changed

### `GBDKPipelineV2.buildMainFunction` — bootstrap-order refactor

**Pre-Plan-20 bootstrap (broken — GAP-1, GAP-2, GAP-3 from Plan 19 finding):**

```c
void main(void) {
    cgb_compatibility();
    NR52_REG = 128u; NR50_REG = 119u; NR51_REG = 255u;
    SPRITES_8x8;
    DISPLAY_ON;                       // ← LCD ON HERE
    SHOW_BKG;                          //   ↘ LCDC bits set AFTER LCD on
    SHOW_SPRITES;                      //   ↗
    set_sprite_data(0u, 48u, ...);    //   ↘ VRAM writes AFTER LCD on
    play_enter();                      //   ↘ palette writes deferred to play_enter — runs AFTER DISPLAY_ON
    while (1) { ... }
}
```

**Post-Plan-20 bootstrap (reference-aligned):**

```c
void main(void) {
    DISPLAY_OFF;                                  // NEW — GAP-1 fix
    cgb_compatibility();
    set_sprite_palette(0u, 1u, gray_pal);         // NEW — hoisted from play_enter (GAP-2 fix)
    set_sprite_palette(1u, 1u, pink_pal);
    set_sprite_palette(2u, 1u, cyan_pal);
    set_sprite_palette(3u, 1u, green_pal);
    NR52_REG = 128u; NR50_REG = 119u; NR51_REG = 255u;
    set_sprite_data(0u, 48u, elephant_tiles);     // moved BEFORE DISPLAY_ON
    SHOW_BKG;                                      // moved BEFORE DISPLAY_ON (GAP-3 fix)
    SHOW_SPRITES;                                  // moved BEFORE DISPLAY_ON
    SPRITES_8x8;                                   // (already conditional; now positioned just before DISPLAY_ON)
    DISPLAY_ON;                                    // LAST bootstrap macro per reference (GAP-3 fix)
    play_enter();                                  // unchanged — palette ops re-run idempotently here
    while (1) { ... }
}
```

This matches `gbdk/examples/cross-platform/metasprites/src/metasprites.c:160-194` step-by-step.

### `SpriteRenderingTest.test show sprites in main` — assertion inversion

The prior assertion was:

## Deviations from Plan

### Rule 1 — Bug fix (test was locking the defect)

**1. [Rule 1 - Bug] Inverted `SpriteRenderingTest.test show sprites in main` assertion**

- **Found during:** Pre-edit reconnaissance — grepping the test suite for `SHOW_SPRITES`/`DISPLAY_ON` ordering assertions before applying the fix
- **Issue:** Test asserted `showSpritesIdx > displayOnIdx` (SHOW_SPRITES AFTER DISPLAY_ON). This is directly inverse to Plan 19's named GAP-3 and to GBDK reference `metasprites.c:186-194`. The test was locking the bootstrap-order defect itself as the contract.
- **Fix:** Inverted assertion direction (`showSpritesIdx < displayOnIdx`), updated comment block to reference Plan 19 finding and metasprites.c line range. New assertion now LOCKS the fix.
- **Files modified:** `gbkt-backend-gbdk/src/test/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/SpriteRenderingTest.kt`
- **Commit:** 7b86049f (combined with primary fix — both belong to the same atomic "correct bootstrap order" change)

### Scope decisions (NOT deviations — explicit minimal-scope choices)

**1. Did NOT hoist `bgFillCheckerboard` (RawOp wrapping fill_bkg_rect + set_bkg_data)**

The Plan 19 finding's Option A mentions `bgFillCheckerboard` hoisting as part of the fix. However:
- The DV3GbcPaletteWriteDiagnosticTest tests gate ONLY palette + LCDC order; they do not require bgFillCheckerboard hoisting
- Hoisting RawOps by string content (matching `fill_bkg_rect`/`set_bkg_data`) is fragile (any future RawOp shape change breaks the detector)
- BgCheckerboardEmissionTest asserts `play_enter()` body contains these calls — hoisting would break that contract
- BG VRAM writes complete safely under vblank stalls; sprite palette RAM is the critical first-frame path (it's a 32-byte burst written via OCPS/OCPD register pair, which the GBC PPU lockouts unless LCD is off — palette is the dominant cause)
- Per D-05 ("ONLY this bootstrap-order fix"), staying minimal is preferred

**2. Did NOT modify `SceneVisitor`**

The Plan 19 finding's Option A proposed a SceneVisitor change to skip hoisted ops in the start scene's enter. The duplication-not-relocation approach (palette ops emitted both in main and in {start}_enter) sidesteps this entirely:
- Preserves `SpritePaletteSlotEmissionTest` (which asserts palettes appear in `play_enter()` body)
- Preserves multi-scene navigate-back semantics (re-entering start scene re-applies palette)
- Palette writes are idempotent — duplication is runtime-neutral
- SceneVisitor untouched = zero risk of regression on non-start scenes' enter handlers
