# Phase 10.1 Plan 04: Add Subpalette/Flip Global Sync in Metasprite Frame Switch — Summary

Three-line emission inside `MetaspriteVisitor.generateMetaspriteFrameSwitch` writes
`_<id>_subPalette`, `_<id>_flipX`, and `_<id>_flipY` globals each frame so MCP
sym-file reads reflect runtime `_rot` state — closes D-V3 (SEED-006) and IN-01.

## What Was Built

**Bug closed (D-V3 + IN-01 simultaneously):** `MetaspriteVisitor.generateMetaspriteFrameSwitch`
now emits 3 assignment lines immediately after the existing
`uint8_t subpal = _rot >> 2;` local computation:

```c
uint8_t subpal = _rot >> 2;
_elephant_subPalette = subpal;             // D-V3 (SEED-006)
_elephant_flipX = (_rot & 0x3u) >> 0u;     // D-12 (IN-01)
_elephant_flipY = (_rot & 0x3u) >> 1u;     // D-12 (IN-01)
```

The `_<id>_subPalette` / `_<id>_flipX` / `_<id>_flipY` globals already existed
(declared in `GBDKPipelineV2.kt:790-797` from Phase 10) but were never written
from `play_frame()`. MCP sym-file reads returned the stale initial value
regardless of how many A presses cycled `_rot`.

The 3 new lines are namespaced by `metasprite.id` (Kotlin string template) so
the emission stays multi-metasprite-safe.

**Test coverage added:** `Seed006SubPaletteSyncTest` (3 tests):

1. `frame_switch_emits_subPalette_assignment` — asserts `_elephant_subPalette = subpal;` (D-V3).
2. `frame_switch_emits_flipX_and_flipY_assignments` — asserts both flip-axis assignments (IN-01).
3. `frame_switch_preserves_existing_subpal_computation` — regression guard: `uint8_t subpal = _rot >> 2;` local remains.
