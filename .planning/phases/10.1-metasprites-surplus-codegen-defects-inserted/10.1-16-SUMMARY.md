## Decisions Made

(See `key-decisions` frontmatter for the full list — paraphrased here for narrative continuity.)

1. **Comment-marker plumbing for IR → asset-pipeline (Task 4).** Reused Plan 11's structural-signal pattern (`sprite_<stem>_frames` in main.c). MetaspriteVisitor emits `/* gbkt:mirror-dedup:<id> */`, ConvertSpritesTask greps with stem-boundary regex. Avoids threading a SetProperty<Boolean> through GbktPlugin/GenerateCTask — same minimal-blast-radius discipline as Plan 11.
2. **Marker format `gbkt:<feature>:<id>` with `gbkt:` namespace prefix** so the sentinel cannot be confused with anything else emitted in the C source. The `<id>` suffix lets per-metasprite scoping (a multi-metasprite game can opt SOME sprites in while keeping `-noflip` on others — the regex matches one specific stem).
3. **Layer Task 1 and Task 4 in sequence (not fused).** Task 1's commit closes DEF-10.1-13-A unconditionally on its own (the named cause from Plan 15). Task 4 layers the DSL opt-in as a follow-on capability. The git log audit shows defect closure as the primary intent and the DSL escape-hatch as a secondary feature — the right narrative for future readers.
4. **MetaspriteVisitor edit is confined to one if-block.** Task 4 modifies `generateMetaspriteDescriptor` only — no signature changes, no behavior changes for the no-opt-in case. Disjoint from Plan 20's GBDKPipelineV2/SceneVisitor scope in the same `gbkt-backend-gbdk` module, no merge-conflict risk.
5. **Stem-boundary regex `\\bgbkt:mirror-dedup:<stem>\\b` mirrors Plan 11's safety verbatim.** Three assertions in ConvertSpritesTaskMirrorDedupOptInTest's `mirror_dedup_marker_does_not_false_positive_on_prefix_stem`: stem present → opt-in; prefix stem absent → no opt-in; unrelated stem absent → no opt-in.
