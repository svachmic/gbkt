## Conclusion

DSL transcription is **CORRECT against the reference**: per-frame counts match
exactly (31 + 33 + 33 + 32 + 32 = 161 in both the DSL and the reference
METASPR_ITEM table). Spot-checks of dx/dy/baseId on multiple entries also match
after the documented `(dy, dx, dtile) -> (x=dx, y=dy, baseId=dtile)` arg swap.

BUT the DSL was transcribed from the reference's `-noflip` ID space (0..47). The
port's actual png2asset invocation (no `-noflip`) emits tile IDs 0..44 only,
renumbered. So DSL baseIds 45, 46, 47 reference NO BYTES in the port's
elephant_tiles[720] array -- garbage pixel reads.

Hypothesis #3 (DSL transcription error) is REJECTED in the narrow sense
(the indices are correct against the reference's id space) but ACTIVE in the
broader sense: the DSL and the asset-pipeline disagree on which id space they
speak. The fix is to make the asset pipeline match the DSL's id space (= add
`-noflip` to the png2asset invocation), NOT to renumber the DSL.
