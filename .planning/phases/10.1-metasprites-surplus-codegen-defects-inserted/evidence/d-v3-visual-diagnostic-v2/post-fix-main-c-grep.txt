# Findings

1. **Bootstrap order (lines 208-222) is REFERENCE-ALIGNED** per Plan 20 fix:
   - DISPLAY_OFF (line 209) is first
   - cgb_compatibility() (line 210) is second
   - 4× set_sprite_palette (lines 211-214) BEFORE DISPLAY_ON ✓
   - SHOW_BKG / SHOW_SPRITES / SPRITES_8x8 / DISPLAY_ON (lines 219-222) in correct order
   - Sprite tile data (line 218) loaded BEFORE DISPLAY_ON

2. **MISSING: `set_bkg_palette()` is NEVER called** for any of the 8 GBC BG palette slots.
   The only BG-palette state the GBC PPU sees is whatever `cgb_compatibility()` writes —
   which per `<gb/cgb.h>` docs (set_default_palette obsolete-redirect) only sets
   BG palette slot 0 to DMG-default (white/lt-gray/dk-gray/black).

3. **MISSING: GBC BG attribute byte for tiles is never initialized.** On GBC, each BG tile
   in the tilemap also has a per-tile attribute byte in VRAM bank 1 (bits 0-2 select BG
   palette 0-7). After cgb_compatibility() these bytes default to 0 (palette slot 0).
   fill_bkg_rect (line 247) writes ONLY to VRAM bank 0 (tile index). Bank-1 attribute
   bytes are left at whatever the GBC firmware/cgb_compatibility() initialized them to.

4. **The 4 set_sprite_palette() calls are DUPLICATED in play_enter()** (lines 239-242)
   per Plan 20's "duplication-not-relocation" decision. This is intentional and idempotent.

5. **`move_metasprite_*` calls pass `subpal` (rot>>2) as `base_prop` (3rd positional
   arg)** at lines 302, 307, 312, 317. Per gb/metasprites.h docs, this overwrites each
   OAM entry's attribute byte. So OAM bits[2:0] = subpal at runtime — selecting sprite
   palette slot 0..3 dynamically. Hypothesis 2 (OAM attribute hardcoded to S_PAL(0))
   is **FALSIFIED**.

6. **Descriptor table `metasprite_t` entries use 3-field initializers** `{dy, dx, dtile}`
   (omitting 4th `props` field — C zero-fills). This is irrelevant because runtime
   `move_metasprite_*` OVERWRITES OAM properties with `base_prop` per the header docs.
   Hypothesis 3 (descriptor needs per-frame regen) is **FALSIFIED**.
