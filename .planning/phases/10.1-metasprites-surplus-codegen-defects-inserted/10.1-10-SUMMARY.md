## Decisions Made

- **Reported RESEARCH's prediction surprise honestly in the finding markdown.** RESEARCH §D-V1 Diagnostic Recipe (lines 765-767) predicted with HIGH confidence that hypothesis #1 (byte ordering) would be REJECTED because both pipelines were assumed to use the same `png2asset -spr8x8` toolchain. The evidence captured by Task 1-2 shows that assumption was wrong — port uses `-spr8x16` (per `ConvertSpritesTask.determineSpriteMode` line 236 defaulting PNG height ≥ 16 to 8x16). The finding markdown explicitly contradicts the prior prediction rather than silently working around it, preserving an honest audit trail.
- **Kept the named root cause SINGULAR per D-05** even though the fix requires touching two pipeline layers. The single root is the missing 8x8-vs-8x16 contract across the asset pipeline and the runtime emission; the two edits are joint, not independent. Naming two roots would have invited defensive parallel fixes (the D-05 anti-pattern).
- **RED test scope is intentionally narrow.** It locks only the runtime-side fix (Edit 2). The asset-pipeline-side fix (Edit 1) needs a separate test which Plan 11 must add when it lands the fix. Splitting the RED locks prevents Plan 11 from accidentally closing only one half of the contract gap and leaving the other regressing later.

Not a bug per se — `convertSprites` is a separate Gradle task, but RESEARCH §D-V1 step 1-2 (line 741-754) only mentioned `generateC` + `xxd`, so the recipe needs `convertSprites` between steps 1 and 2 for future runs.

- **Bash heredoc redirects via the Bash tool silently truncated multi-step output blocks.** Two attempts to write `sprite-mode-init-grep.txt` via `{ … } > "$OUT"` block scripts produced partial files (only the first echo + grep landed). Worked around by switching to the `Write` tool with the pre-captured grep output. Not a project issue, but a worktree/Bash-tool quirk worth flagging if reproducible.
