# Phase 10.1 Plan 02: D-V2 (checker byte literal) + WR-03 (tile() int8_t guards) Summary

**MetaspriteBuilder.kt bgFillCheckerboard() now emits a true 4x4 checker byte literal (0xF0 × 4 / 0x0F × 4 × 2 rows) instead of the diagonal-stripe pattern, and MetaspriteFrameBuilder.tile(x, y, baseId) now rejects x/y outside int8_t range (-128..127) at DSL build time via require() guards.**

## Accomplishments

- D-V2 (SEED-005) closed: `bgFillCheckerboard()` emits the true checker literal `0xF0,0xF0,0xF0,0xF0,0x0F,0x0F,0x0F,0x0F` × 2 rows. The helper name now matches what it visually emits — a true 4x4 checker square pattern when tiled by `fill_bkg_rect`, not parallel diagonal stripes.
- WR-03 closed: `MetaspriteFrameBuilder.tile(x, y, baseId)` rejects out-of-range x or y with an actionable `IllegalArgumentException` message that names the offending axis and the `-128..127` range. Boundary values -128 and 127 are accepted (closed range).
- Two TDD test files added that lock both behaviors against future regression: Seed005CheckerboardBytePatternTest (2 tests — positive checker-row shape + negative diagonal-stripe forbidden token) and MetaspriteBuilderTileRangeTest (3 tests — x-reject + y-reject + boundary-accept).
- Full `:gbkt-lang:test` GREEN end-to-end (no regression in MetaspriteBuilderTest, MetaspriteIRTest, or any other gbkt-lang test).

## Decisions Made

- **D-V2 byte literal direction (D-12b Option A):** Followed PATTERNS.md / RESEARCH.md guidance — replace the literal in place rather than renaming the helper. Rationale: keeps the public DSL surface stable (no caller updates) and makes the helper name honest.
- **KDoc rewrite to honor file-level grep gate:** The original KDoc draft (Task 3 first attempt) quoted the diagonal sequence `0x80,0x80,0x40,0x40` verbatim to explain the historical deviation. This violated the plan's `grep -c "0x80,0x80,0x40,0x40" = 0` acceptance gate. Resolved by rephrasing the KDoc to describe the deviation without quoting the byte sequence — the Seed005 negative-pattern test still locks the emitted-code shape, and the file-level gate is honest. No deviation rule invoked; this was a normal in-task tightening to honor the explicit acceptance criterion.
- **WR-03 message phrasing:** Both `require()` guards use the message format `"metasprite tile {x|y} must be int8_t-representable (-128..127), got $value"`. Includes both `"int8_t"` and `"-128..127"` tokens to give the user a vocabulary they can match against either the C type or the numeric range.
