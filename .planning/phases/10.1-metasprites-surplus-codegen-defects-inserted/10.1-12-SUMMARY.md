## Deviations from Plan

### In-wave D-03b absorption (Tasks 3a + 3b)

**The plan declared 3 tasks; I committed 5.** Tasks 3a and 3b are an in-wave D-03b absorption authorized explicitly by the plan's Task 3 failure protocol:

> "If build FAILS: this is the binding integration evidence that one of Plans 05-09 has a defect that JVM tests missed. ... In failure case: STOP the plan; trace which JVM test should have caught this; absorb fix as a split-plan within current wave (D-03b escape valve) — do NOT defer to Phase 10.1.1."

The first `:metasprites-stress:buildRom` attempt failed with SDCC `error 20: Undefined identifier 'elephantPosX'` (and 7 other binder-supplied names) in `bank1.c`. Diagnosis: `ScriptOpVisitor.visitMoveMetasprite` passed `op.posXVar` (the raw user-declared variable name from `AssignableVar.name`, e.g. `"elephantPosX"`) UNCHANGED to `MetaspriteVisitor.generateMetaspriteFrameSwitch`, while every other user-declared global in main.c emits with the `_` prefix (`INT16 _elephantPosX = 1280u;`).

**This is exactly the wiring-layer gap that the plan was designed to surface.** No JVM test in Plans 03–11 covered it because:

- `Seed010NamespaceTest` passes pre-prefixed names (`"_elephant_posX"`) directly to `MetaspriteVisitor.generateMetaspriteFrameSwitch` — locks the visitor BODY contract, not the wiring layer's prefix obligation.
- `ScriptOpVisitorMoveMetaspriteTest` Tests 1–3 declare metasprites with NO binders bound, so `op.posXVar` etc. are null and the canonical `"_posX"` fallback kicks in — never exercises the non-null binder path.

The in-wave absorption follows the plan-authorized D-03b discipline: TDD RED (Task 3a, commit `aad05913` — new TEST 4 in ScriptOpVisitorMoveMetaspriteTest exercising the full DSL→IR→visitor→emitted-C path with binders bound; fails for documented reason), then GREEN (Task 3b, commit `3d44c8db` — one-line fix at the visitor wiring boundary), then re-run buildRom (Task 3c, commit `68c543e8` — clean log captured). No new phase needed.
