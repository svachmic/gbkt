metasprites port — four **visual parity** defects (D-V1, D-V2, D-V3, D-extra) and four

## Implementation Decisions

### Phase shape & scope cap (overarching)

- **D-01: Hard scope cap = 8 seeded defects + 3 absorbed review warnings + 1 synthetic
  verification game + 1 re-shoot of Phase 10 UAT screenshots.** No new DSL surface beyond
  the IR-level `MoveMetasprite` var-ref change (D-13). No new metasprite behaviors. No
  4th UAT anchor.
- **D-02: Plans grouped by FILE AFFINITY, not by visual-vs-latent cluster.** Visual fixes
  and latent fixes touch the same files (`MetaspriteVisitor.kt`, `GBDKPipelineV2.kt`),
  so grouping by file minimizes merge friction and per-plan blast radius. Suggested
  groupings (planner refines):
  1. `GameBuilder.kt` palette slot fix (D-extra / SEED-007) — standalone
  2. `MetaspriteBuilder.kt` cluster — D-V2 byte literal (SEED-005) + WR-03 int8_t range
     validation (absorbed)
  3. `MetaspriteVisitor.kt` cluster — D-V3 + IN-01 (SEED-006 "both" option) assignment
     emission + CR-03 (SEED-010) symbol namespacing + WR-01 (absorbed) IR-level var-ref
     fields + WR-05 (SEED-011) hiwater hoist
  4. `GBDKPipelineV2.kt` cluster — CR-01 (SEED-008) `VramAllocator` class + CR-02
     (SEED-009) per-bank metasprites.h include + WR-02 (absorbed) extern declaration
  5. D-V1 (SEED-004) — diagnostic plan first (hex-dump + 8x8/8x16 mode check), then fix plan
  6. Synthetic test example game (`metasprites-stress/` or similar)
  7. Re-shoot Phase 10 UAT (3 behaviors) into Phase 10's evidence/ directory
- **D-03: Plan-sizing inherits Phase 10 D-14 — RE-EMPHASIZED by user 2026-05-18.**
  Many small plans over few large. **The user explicitly stated (twice now — Phase 10
  and Phase 10.1) that compression-to-look-efficient is the wrong tradeoff.** Concrete
  rules:
  - ≤2 distinct concerns per plan; if a plan paragraph says "and also" twice, split.
  - If a plan touches >1 IR node + >1 visitor + >1 test file, split.
  - Expected plan count: ~12–16 plans given the scope (1 plan per defect + WR-03
    bundled with D-V2 + D-V1 split into diagnostic+fix + synthetic game build + per-
    behavior re-shoot + verification gate + phase close).
  - Plan-checker MUST flag any plan count under 12 as a sizing concern, not an
    efficiency win.
- **D-03b: Phase 10.1 MUST be the TERMINAL closer for the metasprites defect cluster
  — no Phase 10.1.1 / 10.2 / 10.3.** User explicit constraint 2026-05-18: this
  subphase is final. The planner must size plans small enough that surplus discoveries
  during execution can be ABSORBED within the existing plan budget (split a plan, add
  a plan in a wave, restructure the wave graph), NOT escalated to a new follow-up
  subphase. Acceptable escape valves at execution time:
  1. **Split a stalling plan** into 2–3 smaller plans within the same wave (preferred).
  2. **Insert a new plan** between waves if a discovery surfaces a blocking dependency
     not foreseen at planning time.
  3. **Seed for a LATER phase** (Phase 11/12/13) ONLY if the discovery is genuinely
     outside the 8-defect + 3-absorbed-warning cluster (e.g., a brand-new codegen bug
     in a different file). Surplus discoveries WITHIN the cluster must be absorbed.
  Unacceptable escape valves: defer-to-Phase-10.1.1, defer-to-Phase-10.2, "ship the
  rest and seed". The phase ships ONLY when all 8 seeds + 3 absorbed warnings are
  closed AND both ROMs build cleanly AND visual SCs are re-shot.

### Fix-route selections for ambiguous seeds

- **D-08: SEED-008 (CR-01 VRAM collision) — Route B: `VramAllocator` class.** OVERRIDE
  of the seed's recommended Route A (inline shared allocator). Rationale: Phase 11
  (banks) is likely to need per-scene/per-bank VRAM allocation (not a single monotonic
  global counter), and standing up the allocator class now is cheaper than retrofitting
  it later. Cost: ~1 extra plan vs Route A. Architecture: data class held on pipeline
  context; `allocator.reserve(tileCount): Int` is the only public surface; lives in
  `gbkt-backend-gbdk` (NOT a public API exposed to user code). The Phase 10.1 fix
  delivers the per-build singleton variant; the per-scene variant is a Phase 11 concern.
- **D-09: SEED-009 (CR-02 missing header in bank1.c) — Route A: per-bank scan +
  conditional include.** Seed-recommended. `buildBankHeaders` checks
  `bankIR.scenes.any { it.frameOps.any { it is MoveMetasprite } }`; only banks that
  actually need it get `<gbdk/metasprites.h>`. Pattern matches existing
  per-bank-condition logic. The synthetic test ROM (D-06) exercises this path.
- **D-10: SEED-010 (CR-03 + WR-01 long-term) — Option (b): IR-level var-ref fields on
  `MoveMetasprite`.** SCOPED EXCEPTION to the "no new DSL features" cap (see D-13 for
  the justification line). Add `posXVar: VarRef`, `posYVar: VarRef`, `idxVar: VarRef`,
  `rotVar: VarRef` fields to `MoveMetasprite` IR node. DSL `moveMetasprite(elephant)`
  resolves these from metasprite-scope variable declarations (or accepts optional
  overrides). Visitor emits the actual variable names — no more hardcoded `_rot` /
  `_idx`. CLOSES BOTH CR-03 (per-metasprite namespace) AND WR-01 (var contract)
  honestly. The synthetic test ROM (D-06) exercises this with two metasprites that
  declare distinct rot/idx vars.
- **D-11: SEED-011 (WR-05 hiwater reset) — Route A: frame-scope hiwater hoist.**
  Seed-recommended. Emit `uint8_t hiwater = 0u;` ONCE at frame{} prelude; each
  `moveMetasprite()` only contributes `hiwater += move_metasprite_*(...)`;
  `hide_sprites_range(hiwater, MAX_HARDWARE_SPRITES)` ONCE at frame postlude. Requires
  scene visitor to support frame_prelude/postlude emission hooks (research must confirm
  this hook exists or is small to add). The synthetic test ROM (D-06) exercises this
  with two metasprites moved per frame.
- **D-12: SEED-006 (D-V3 stale sub-palette global) — "Both" option: emit assignment AND
  apply same fix to `_<id>_flipX` / `_<id>_flipY` (closes IN-01).** Apply the same
  assignment-in-frame fix to all three accessor globals. Pro: closes IN-01 (dead
  flipX/flipY API) at zero extra cost; consistent semantics across all three
  accessors; MCP debugging surface stays useful.
- **D-12b: SEED-005 (D-V2 diagonal stripes) — Option A: in-place byte-literal fix.**
  Replace diagonal byte literal with reference's `0xF0,0xF0,0xF0,0xF0,0x0F,0x0F,0x0F,0x0F`
  pattern. Helper keeps the name `bgFillCheckerboard()`. Add JVM-tier test asserting
  emitted byte literal matches the checker pattern so this can't regress silently.

### Scoped exceptions to the "no new DSL features" cap

- **D-13: IR-level `MoveMetasprite` var-ref fields (D-10) are a SCOPED EXCEPTION to
  the ROADMAP's "Hard scope cap: eight seeded defects only. No new DSL features" line.**
  Justification: CR-03 (per-metasprite symbol namespacing) cannot be honestly closed
  without an IR change. Option (a) — auto-namespace using the same hardcoded names —
  papers over WR-01 by changing `_idx` → `_elephant_idx` in codegen but leaves the
  emitter still hardcoding ONE name (just a renamed one). Option (c) — punt — means
  the synthetic test ROM (D-06) cannot build because the two metasprites would compete
  for the same `_rot` / `_idx` globals. The IR-field fix is the smallest change that
  makes CR-03 + WR-01 + the verification ROM honest. The change is bounded: 4 fields
  on `MoveMetasprite`, optional override in DSL, visitor reads from fields instead of
  string-literals.
- **D-13b: VramAllocator class (D-08) is NOT a scope expansion.** It is an internal
  codegen class in `gbkt-backend-gbdk` with no DSL exposure. ROADMAP cap forbids "new
  DSL features", not internal refactors. The user picked Route B with the explicit
  intent of getting cleaner foundation for Phase 11.

- **D-17: WR-04 / IN-02 / IN-03 are NOT absorbed.** None block Phase 11/12. Seed if
  they bite later. IN-01 IS absorbed via SEED-006 "both" option (D-12).

### Verification methodology (inherited from Phase 10)

  expected emission shape — e.g., WR-05 hiwater test must assert `hide_sprites_range`
  appears exactly ONCE inside the frame function body, not just in the file.

### Claude's Discretion

- **Wave structure:** Planner decides wave dependencies. Expected rough shape: Wave 1
  = file-affinity refactors (parallel — GameBuilder, MetaspriteBuilder, two separate
  MetaspriteVisitor plans, GBDKPipelineV2 plans), Wave 2 = D-V1 diagnostic, Wave 3 =
  D-V1 fix, Wave 4 = synthetic test ROM (`metasprites-stress`), Wave 5 = re-shoot
  Phase 10 UAT, Wave 6 = phase close + verification.
- **Synthetic test ROM name:** `metasprites-stress` is the working name; planner may
  pick a more descriptive one (e.g., `metasprites-multi`) if it clarifies intent.
- **DSL surface for IR-field var-refs (D-10):** Two candidate shapes —
  (a) implicit (metasprite scope declares `var idx by u8Var()` and the IR captures
  refs by scope walk), or
  (b) explicit override (`moveMetasprite(elephant, idx = elephantIdx, rot = elephantRot)`
  takes optional `VarRef` params).
  Planner picks based on what reads cleanly in the synthetic test ROM with two
  metasprites. Prefer (a) if it scope-walks cleanly; fall back to (b) if scope walking
  is messy.
- **VramAllocator API surface (D-08):** Internal to `gbkt-backend-gbdk`; planner picks
  the minimal API. Suggested: `class VramAllocator { fun reserve(tileCount: Int): Int }`
  with a per-pipeline-invocation instance. No persistence across builds.
- **Per-plan test naming:** Inherit Phase 10 pattern — one JVM-tier test per defect
  matching SEED ID (`Seed008VramCollisionTest`, `Seed010NamespaceTest`, etc.) for
  traceability.
