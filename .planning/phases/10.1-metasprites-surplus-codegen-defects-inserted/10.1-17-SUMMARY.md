# Phase 10.1 Plan 17: D-V2 Visual Diagnostic — DEF-10.1-13-B Root Cause Named, Paused at Human-Verify Checkpoint

**Diagnosed why the BG checker visibly renders as "rectangles, slightly wider than taller" instead of squares: Plan 10.1-02's byte literal alternates `0xF0`/`0x0F` every 2 tile rows (period = 4 bytes) when it must alternate every 4 tile rows (period = 8 bytes) to produce true 4×4-pixel square cells. Per-tile rendering of the current literal is 4 pixels wide × 2 pixels tall — matching the user-verified screenshot at `behavior1-animation-advance.png` exactly. Plan 10.1-18 fix is a 1-edit literal swap in `MetaspriteBuilder.kt`: 8× `0xF0` followed by 8× `0x0F`. RED `DV2BgAspectDiagnosticTest` committed at `c49b9991` — it asserts the corrected structural invariant and flips GREEN once Plan 18 lands.**

## Accomplishments

- **Named the root cause** for DEF-10.1-13-B: byte-literal alternation period is 2 tile rows (= 4 bytes) when it must be 4 tile rows (= 8 bytes). The bytes themselves encode 4w×2h rectangles; this is NOT an emulator artifact, NOT a perceptual issue.
- **Specified the Plan 18 fix shape** as a 1-edit literal swap (`0xF0,0xF0,0xF0,0xF0,0x0F,0x0F,0x0F,0x0F,…` → `0xF0,0xF0,0xF0,0xF0,0xF0,0xF0,0xF0,0xF0,0x0F,…`) with explicit guidance on updating Seed005's locked substring and an explicit "do NOT rename the helper" recommendation.
- **Committed a RED `DV2BgAspectDiagnosticTest`** (3 @Tests) that asserts the corrected structural invariant. Verified RED via `./gradlew :gbkt-lang:test --tests "*DV2BgAspectDiagnosticTest*"` — 2 of 3 fail for the right reason on `HEAD`, 1 passes (the F0/0F count sanity, which is shared between wrong/correct literals).
- **3 evidence files** dumped into `evidence/d-v2-visual-diagnostic/` per the plan's `files_modified` spec — including a full DSL → generated-C → VRAM → screen reconciliation table.
- **Documented the test-authoring failure mode** that allowed Plan 10.1-02 to ship the wrong literal under a GREEN test: the asserted substring `0xF0,0xF0,0xF0,0xF0,0x0F,0x0F,0x0F,0x0F` is correct as a per-half description but wrong as a per-row repeating unit, and the substring assertion masked the per-row period error. This is exactly the failure mode `feedback_visual_evidence_for_visual_truths.md` warned about — codegen-shape tests are necessary but never sufficient for visual truths.

## Decisions Made

1. **Did NOT attempt a runtime VRAM read** at `0x8000..0x800F`. Executor has no `mcp__gbkt-emulator__*` tools in its registry (same upstream constraint that drove Plan 10.1-13's `human-action` checkpoint). The chain DSL → generated C → `set_bkg_data` → VRAM is a verbatim memcpy with zero transformation, and the user-verified screenshot anchors the on-screen end of the chain to reality. Adding a runtime read would be belt-and-suspenders; documented as an optional polish task in `bg-tile-byte-layout.txt` and `d-v2-visual-finding.md` for the orchestrator to add post-checkpoint via `/gbkt-play-game metasprites` if desired.
2. **DV2BgAspectDiagnosticTest is a NEW test file, NOT an edit to Seed005.** Plan 18 will edit Seed005 to lock the new substring; the new diagnostic test serves a different purpose (semantic invariant about checker-cell aspect ratio) and should stay independent. This gives belt-and-suspenders coverage post-Plan-18: Seed005 locks the exact emitted substring; DV2Aspect locks the structural invariant that justifies why the substring is what it is.
3. **Did NOT recommend renaming the helper to `bgFill4x4Checkerboard()`** in the Plan 18 fix shape. The current name is honest once the literal is corrected. The rename would churn call sites in `gbkt-examples/metasprites/src/.../Metasprites.kt` for no semantic gain.
4. **Did NOT pre-execute Task 4 (checkpoint).** Per executor protocol `<checkpoint_protocol>`, `checkpoint:human-verify` STOPS execution and returns structured state — this plan is `autonomous: false` so even the auto-mode escape hatch doesn't apply.
