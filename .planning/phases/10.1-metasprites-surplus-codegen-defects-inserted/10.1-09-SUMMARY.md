# Phase 10.1 Plan 09: Frame-scope hiwater wrap (WR-05 / SEED-011) Summary

**`MetaspriteVisitor.generateMetaspriteFrameSwitch` no longer emits the wrapping `uint8_t hiwater = 0u;` declaration NOR the trailing `hide_sprites_range(hiwater, MAX_HARDWARE_SPRITES);` call — a new `GBDKPipelineV2.wrapFrameWithMetaspriteHiwater` helper hoists both to the scene frame function's prelude/postlude, ensuring EXACTLY-ONE hiwater init + EXACTLY-ONE hide_sprites_range per frame regardless of how many `moveMetasprite()` ops the scene contains. Closes WR-05 / SEED-011 (multi-metasprite-per-frame OAM collision); Phase 12 (platformer_template) prerequisite unblocked.**

- **Closed WR-05 / SEED-011.** A scene that calls `moveMetasprite()` multiple times per frame no longer suffers OAM collision. Pre-fix the per-call switch block emitted `uint8_t hiwater = 0u;` (RESETTING the slot counter) AND `hide_sprites_range(hiwater, MAX_HARDWARE_SPRITES);` (HIDING the prior metasprite's slots) for each call. Post-fix one hiwater declaration serves the entire frame; one tail cleanup runs once per frame.

The downstream chain now receives `functionsWithHiwater` so the prelude/postlude land AT the frame body boundary (before update_movement/update_animation prepend; before genre frame ops; before tileset guards).
