<objective>
Close DEF-10.1-13-A by applying the named root cause from Plan 10.1-15: ConvertSpritesTask omits `-noflip` when invoking png2asset for metasprite-bound PNGs. Without `-noflip`, png2asset detects mirror tile pairs and dedups to 45 unique tiles + emits `S_FLIPX` METASPR attrs; DSL was hand-transcribed from reference's `-noflip` id space (0..47), so DSL `tile()` baseIds 45/46/47 dereference past `elephant_tiles[720]` end → garbage pixels.

Per the D-05 discipline established by Plans 10/11: fix ONLY the named cause (Edit 1 below).

Per user decision at 10.1-15 checkpoint: ADD a per-metasprite DSL opt-in (`mirrorDedup()`) so games can intentionally allow mirror dedup for legitimate cases (Edit 2 below).

**Edit 1 (named cause, default behavior):** In `ConvertSpritesTask.convertSprite()` after `args.add("-spr8x8")`, add `if (isMetaspriteBound(includePath, mainCContent) && !ms.mirrorDedup) args.add("-noflip")`. Default keeps metasprites visually correct.

**Edit 2 (DSL opt-in, per user):** Add `MetaspriteBuilder.mirrorDedup()` builder method → `MetaspriteIR.mirrorDedup: Boolean` field (default false) → ConvertSpritesTask reads the metasprite metadata (via the existing `isMetaspriteBound` plumbing or new SetProperty input) to gate the -noflip arg.

Output: 4 source edits (ConvertSpritesTask, MetaspriteBuilder, MetaspriteIR, isMetaspriteBound metadata plumbing) + 3 tests (DV1VisualDiagnosticTest RED→GREEN, MetaspriteBuilderMirrorDedupTest NEW, ConvertSpritesTaskMirrorDedupOptInTest NEW) + ROM-build smoke test + orchestrator-driven visual re-shoot.
</objective>
