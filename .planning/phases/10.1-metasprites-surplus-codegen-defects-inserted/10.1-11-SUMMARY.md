## Decisions Made

(See `key-decisions` frontmatter for the full list — copied here for narrative continuity.)

1. **Option A (narrow, metasprite-aware) over Option B (broad default flip).** Option A blast radius is one file with zero plumbing changes. The structural signal `sprite_<stem>_frames` in main.c is emitted unconditionally by MetaspriteCodegen — reliable, zero-cost detection.
2. **Self-contained detection via main.c grep**, not a SetProperty<String> threaded from GenerateCTask. Cost is negligible (one file read + one regex match per convertSprites invocation). Keeps Option A's promise of minimal architectural disruption.
3. **Removed the dead `private fun determineSpriteMode(pngFile)`** after wiring `resolveSpriteMode` through `convertSprite()`. Eliminates the regression risk of someone calling the old function. The companion-object `resolveSpriteMode` preserves the legacy heuristic verbatim for non-metasprite sprites.
4. **Word-boundary anchored regex `\bsprite_<stem>_frames\b`** to prevent stem-prefix false positives (e.g., `sprites/elepha.h` matching `sprite_elephant_frames`). Locked by `isMetaspriteBound_detects_descriptor_reference_for_matching_stem`.
5. **TDD RED-phase production stub pattern** for Task 3: companion-object stub returns `false` from `isMetaspriteBound` so the test compiles + fails RED for the documented reason (`SPR8x8 expected, SPR8x16 actual`). Task 4 replaces the stub body with the real regex — the test flips GREEN.

### Architectural pivots

**Option A implementation surface (in-scope refinement, not a deviation).** The plan's `<interfaces>` Edit 1 sketch suggested two possible Option A wiring patterns:

1. Thread a `SetProperty<String>` from GenerateCTask metadata into ConvertSpritesTask, populated in `GbktPlugin.afterEvaluate`.
2. Override `determineSpriteMode` to check the metasprite-bound set first, otherwise fall through to height heuristic.

I picked a **third Option A wiring** that the plan did not enumerate but is within Option A's scope: **detect metasprite-bound headers by scanning main.c for `sprite_<stem>_frames` references** (the MetaspriteCodegen-emitted descriptor table). This is more minimal than either listed approach — it requires zero changes to GbktPlugin or GenerateCTask, only ConvertSpritesTask itself.

Why this is in-scope and not a deviation: the plan's Option A definition is "thread metasprite-bound asset paths from the generated metasprite header set into ConvertSpritesTask." The "generated metasprite header set" can be derived (a) from GameIR via a property, (b) from `<gbdk/metasprites.h>` + include lists, or (c) from `sprite_<stem>_frames` descriptor references — all are structural signals from the same MetaspriteCodegen output. The plan's hint to check "whether `GBDKPipelineV2.buildMetadataFile` or the metasprite header generator already exposes this list" was a search-for-the-cheapest-seam, and the descriptor table is cheaper than any of them.

**Total deviations:** 0 (one architectural refinement chose the cheapest of three Option A wirings, all within plan-authorized scope)
