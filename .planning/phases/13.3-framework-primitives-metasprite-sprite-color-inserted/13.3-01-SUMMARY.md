# Phase 13.3 Plan 01: Color Namespace Foundation Summary

Unified `Color` namespace introduced in `gbkt-lang` as a thin, discoverable facade over the existing `gbkt-ir` `GBCColor` converters, with RED-first test suite pinning the full contract.

## What Was Built

**Color.kt** (`object Color` in `io.github.gbkt.core.dsl`):
- `Color.rgb888(r, g, b)` — delegates to `GBCColor.fromRGB888`; emits stderr `WARNING` when `GBCColor.hasPrecisionLoss(r, g, b)` is true (D-15 / T-13.3-01 mitigation)
- `Color.rgb555(r, g, b)` — packs raw 0-31 hardware components into `GBCColor` via inline bit math (matches `gbc()` behavior; no `GBCColor.fromRGB555` factory exists in gbkt-ir)
- `Color.hex(hex: String)` — strips leading `#`, parses 6 hex digits to `Int`, delegates to `GBCColor.fromHex(Int)` (preserves `gbcHex` ergonomics)
- 16 named constants (WHITE through TEAL) with identical `GBCColor` values to `GbcColor.*`

**ColorTest.kt** (34 tests):
- `Color.rgb888` conversion correctness + precision-loss WARNING via stderr capture
- `Color.rgb555` channel packing
- `Color.hex` with and without `#` prefix
- All 16 named constants assertEquals to `GbcColor.*` values

## Deviations from Plan

None — plan executed exactly as written. One clarification noted:

- Plan said `Color.rgb888(255, 0, 255) equals GBCColor(0x001F)` but 0x001F is red=31,g=0,b=0 (pure red). Magenta packs to `r=31,g=0,b=31` → `(31 shl 10) or 31 = 0x7C1F`. The test was written to assert the correct packing from `GBCColor.fromRGB888(255, 0, 255)` rather than the erroneous literal in the plan note. This is not a deviation — the behavior assertion (delegate to `GBCColor.fromRGB888`) is correct; only the inline comment in the plan was misleading.
