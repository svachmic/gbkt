# Phase 13.3 Plan 14: Asset-Driven Metasprite set_sprite_data Gap Closure Summary

**One-liner:** Restores dropped set_sprite_data() VRAM tile load for Path A metasprites using png2asset deduped tile-count macros and CRawCode macro-chained start expressions.

## What Was Built

Gap closure for 13.3-13: the Path A asset-driven metasprite migration dropped the `set_sprite_data()` VRAM tile load. The elephant OAM pointed at unloaded VRAM tiles → invisible elephant on bgFillCheckerboard background (Visual Evidence Rule violation).

### Root Cause

`MetaspriteVisitor.tileCountForMetasprite(ms)` returns `null` when `ms.frames.flatMap{it.tiles}` is empty. Asset-driven (Path A) metasprites have frames with NO DSL tiles (tiles come from png2asset's `<id>_tiles[]`), so `tileCountForMetasprite` returns null. `GBDKPipelineV2.buildAllSpriteDataLoadStatements()` skipped these via `?: continue` — emitting NO `set_sprite_data`.

### Fix Applied

**Task 1 (RED):** `MetaspriteAssetTileLoadEmissionTest` — 4 tests, 3 fail RED initially:
- Asserts `set_sprite_data(` present in main.c for Path A metasprite
- Asserts `sprites_elephant_tiles_count` macro used (not integer)
- Asserts two metasprites chain their starts via count macros
- Regression guard: Path B (procedural) uses integer count unchanged

**Task 2 (ConvertSpritesTask):** Added `parseTileCount()` — parses `<stemName>_tiles[LEN]` from png2asset output, computes `N = LEN / 16` (16 bytes per 8×8 2bpp tile). `generateSpriteHeader()` now emits for metasprite entries:
```c
/* Actual deduped tile count from png2asset output (array length / 16) */
#define sprites_elephant_tiles_count 44u
```
Actor sprite headers unchanged (no count macro).

**Task 3 (GREEN):** `GBDKPipelineV2.buildAllSpriteDataLoadStatements()` updated:
- Asset-driven metasprites (spritePath != null): emit `CRawCode` with macro count
- Start chaining: `base = allocator.tilesUsed` after actor reserves; subsequent metasprites chain cumulative `sprites_<prior>_tiles_count` in a C expression string
- Path B (escape-hatch D-04, spritePath null): integer path unchanged — byte-identical

Generated metasprites main.c:
```c
set_sprite_data(0u, sprites_elephant_tiles_count, sprites_elephant_tiles);
```

Generated metasprites-stress main.c (actor + 2 metasprites):
```c
set_sprite_data(0u, 2u, sprites_player_tiles);
set_sprite_data(2u, sprites_elephant_tiles_count, sprites_elephant_tiles);
set_sprite_data(2u + sprites_elephant_tiles_count, sprites_tiger_tiles_count, sprites_tiger_tiles);
```

**Task 4 (Baselines + ROM):** Both baselines (`elephant.c.baseline`, `tiger.c.baseline`) are unchanged — they track png2asset `.c` output which our fix does not alter (only `.h` changes). Both buildRom EXIT 0.
