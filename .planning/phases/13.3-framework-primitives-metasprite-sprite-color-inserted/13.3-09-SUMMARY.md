# Phase 13.3 Plan 09: Metasprites Headline Migration Summary

Asset-driven elephant declaration in 102 lines using `sprite(asset("sprites/elephant.png"))+frames(5)` and `Color.rgb555()` palette colors — the Phase 13.3 ROADMAP headline SC delivered.

## What Was Built

**Task 1 — Migrate Metasprites.kt (403 → 102 lines)**

The elephant metasprite was fully migrated from the hand-transcribed `frame { tile(relX, relY, tileId) }` approach to the asset-driven path:

- **Before:** 5 `frame {}` blocks × 31-33 `tile()` calls = 175+ lines of tile transcription + a `baseId` assignment + PHASE-13 stale comments + 16 `gbc()` palette calls
- **After:** Single `sprite(asset("sprites/elephant.png")) { mode(SPR8x8); pivot(0,0); frameSize(64,48) }` block + `frames(5)` declaration = 7 lines

All 16 `gbc(r, g, b)` calls were migrated to `Color.rgb555(r, g, b)`. The values were already in 5-bit native hardware format (0-31 range), so no precision loss occurred. `Color.rgb555()` provides range-checked construction with no precision-warning path triggered.

The stale PHASE-13 TODO comments for items 1 and 2 (sprite() missing / slot assignment) were removed. CLAUDE.md was updated to mark item 1 RESOLVED (sprite() implemented in Plans 13.3-05/06) and note item 2 still deferred to Plan 18.

Final line count: **102 lines** (target: ≤150).

**Task 2 — Re-pin MetaspriteIRTest (18 tests, all GREEN)**

The test was rewritten to assert the asset-driven IR shape:
- `frames.isEmpty()` — D-08 mutual exclusion: asset-driven path produces no procedural tile descriptors
- `spritePath == "sprites/elephant.png"` — asset binding captured in IR
- `frameCount == 5` — author-declared count for build-time cross-validation against png2asset
- Cutting flags: `spriteMode==SPR8x8`, `frameWidth==64`, `frameHeight==48`, `pivotX==0`, `pivotY==0`

All palette, variable, scene, and GBC target assertions preserved.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `every.frame {}` does not exist in SceneBuilder DSL**

- **Found during:** Task 1 — `./gradlew compileKotlin` failed with "Unresolved reference 'every'"
- **Issue:** The plan assumed `every.frame {}` could avoid the `\bframe\s*\{` regex match in the automated verify check. However, `every.frame` is not a SceneBuilder DSL member — the correct form is `frame {}`.
- **Fix:** Reverted `every.frame {` back to `frame {` for the scene's game loop lifecycle block.
- **Impact on automated verify:** The plan's automated verify check `! grep -qE '\bframe\s*\{|gbc\('` has a false positive: `\bframe\s*\{` matches the scene's lifecycle `frame {`, not just metasprite transcription blocks. The acceptance criteria (human-readable) is fully met — zero metasprite `frame { tile() }` transcription blocks exist. The automated check regex is overabroad; this is a plan defect. The spirit of the check is satisfied.
- **Files modified:** `Metasprites.kt`
