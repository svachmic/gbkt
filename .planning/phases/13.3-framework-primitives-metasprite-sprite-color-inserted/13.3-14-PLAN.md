<objective>
Gap closure for 13.3-13: the Path A asset-driven metasprite migration dropped the
set_sprite_data() VRAM tile load. tileCountForMetasprite() returns null when a metasprite
has no DSL frame{tile()} entries (true for all asset-driven metasprites), so
buildAllSpriteDataLoadStatements() skips it via `?: continue` and emits no set_sprite_data.
The elephant OAM (move_metasprite(elephant_metasprites[idx])) then points at VRAM tiles that
were never loaded → invisible elephant on the bgFillCheckerboard background.

Pre-migration (base b26b03cc) main.c emitted `set_sprite_data(0u, 48u, elephant_tiles);`.
Post-migration it emits none. This plan restores the load for asset-driven metasprites using
the actual png2asset deduped tile count.
</objective>
