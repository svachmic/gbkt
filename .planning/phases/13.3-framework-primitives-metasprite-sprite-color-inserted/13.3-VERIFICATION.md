Three distinct divergences were diagnosed (13.3-15) and addressed across the 13.3-15..19 gap cluster.
All share the SAME `move_metasprite(80, 72)` anchor in pre and post — the divergence is in the png2asset
descriptor / palette pipeline, not game logic:

1. **Position (pivot). — RESOLVED (13.3-16).** Root cause: DSL `pivot(0, 0)` → png2asset `-px 0 -py 0`
   (top-left), shifting the elephant +32,+24 to the bottom-right. Fix: `pivot(32, 24)` (frame center) so
   png2asset emits `-px 32 -py 24`; ConvertSpritesPivotArgsTest locks the token emission; elephant.c
   baseline re-pinned. The 13.3-19 reshoot confirms the elephant is now CENTERED (user: "At least its
   centered"). ✓ closed under binding sign-off.

2. **Color (sub-palette). — STILL OPEN (residual shifted after 13.3-20).** 13.3-15 diagnosed a
   slot-collision: `buildMetaspriteSpritePaletteStatements` emitted `set_sprite_palette(0u,1u,elephant_palettes)`,
   later overwritten by `play_enter()`, leaving OBJ slot 1 = pink; the png2asset descriptor bakes `S_PAL(1)`
   into 52/149 OAM entries. The diagnostic named TWO required actions: (a) suppress the `elephant_palettes`
   upload — DONE in 13.3-17 (Direction B; `main.c` `elephant_palettes` count now 0) — AND (b) remap the
   `S_PAL(1)` descriptor entries to `S_PAL(0)` for the fully-gray render — **DONE in 13.3-20** (deterministic
   `remapMetaspriteSubPalette` post-process in `ConvertSpritesTask.convertSprite()`, gated on
   `isMetaspriteEntry`; generated `elephant.c` now 0 `S_PAL(1)` / 149 `S_PAL(0)`, baselines re-pinned,
   RED→GREEN `MetaspriteSubPaletteRemapTest`). The pink-from-slot-1 overlay is GONE.

   **A NEW/distinct residual surfaced on the 13.3-20 reshoot — now ALSO CLOSED (13.3-21..23).** With every
   OAM entry on OBJ slot 0 (`gray_pal`), the elephant's palette VALUES read inverted (binding verdict
   13.3-20, verbatim: "I think the colors on the elephant are either inverted or somehow wrongly set.
   Probably Color refactor broke it.").

   **13.3-21 DIAGNOSE — root cause (b) palette-INDEX-POLARITY (the Color-refactor suspect was FALSIFIED).**
   `gbc(r,g,b)=(b<<10)|(g<<5)|r` and `Color.rgb555(r,g,b)=r|(g<<5)|(b<<10)` are the SAME bit layout →
   byte-neutral; `gray_pal == {0x7FFF,0x56B5,0x294A,0x0000}` matched the gbdk oracle. The real defect: the
   `gray` `spritePalette` was authored DMG-descending (color0=lightest) while png2asset baked the elephant
   tile 2bpp indices in ASCENDING luminance from the source PNG PLTE (index3 = the lightest body colour,
   29.2% of pixels). At runtime index3 → `gray_pal[3]=0x0000` BLACK → full body inversion. Live MCP probe
   (`evidence/13.3-21-color-probe.png`) + 2bpp frequency decode confirmed.

   **13.3-22 FIX — reverse the gray ramp to ascending luminance.** `gray` reordered
   `color0(0,0,0)..color3(31,31,31)` → `gray_pal == {0x0000,0x294A,0x56B5,0x7FFF}`, so the index-3 body
   lands light. RED→GREEN `MetaspritesGrayPaletteEmissionTest` (token ORDER), byte-identity oracles GREEN
   (palette-literal-only; descriptor untouched; 13.3-20 all-S_PAL(0) remap preserved), D-17 7-target sweep
   EXIT 0.

   **13.3-23 RE-BIND — APPROVED.** The clean-rebuilt rot=0 reshoot (`evidence/13.3-23-elephant-color.png`)
   renders a correct, non-inverted, light-bodied gray elephant (darker legs/shading, zero pink). User
   binding verdict: **APPROVED.** ✓ COLOR axis CLOSED.

3. **Composition (dedup). — ACCEPTED on record (13.3-18).** Pre = 31 OAM entries, post = 29; the diff is
