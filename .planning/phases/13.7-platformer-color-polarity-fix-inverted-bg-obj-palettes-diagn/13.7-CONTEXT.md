<decisions>
## Implementation Decisions

### Diagnose→fix sequencing
- **D-01:** **Unified diagnostic wave first.** One diagnostic plan reads BOTH the BG and OBJ
  palette codegen paths, establishes the compiled GBDK reference ONCE (compile + run the
  `platformer_template` Makefile in GBC mode), and writes ONE DIAGNOSTIC artifact recording
  each pipeline's root cause — `inverted + fix-needed` OR `already-correct (with evidence)`.
  Fix wave(s) follow per CONFIRMED root cause. Reference built once, shared diagnostic format,
  clean diagnose-first gate.
- **D-01b (no-pay-to-confirm-the-obvious):** The diagnostic's codegen-read IS the gate. If a
  pipeline's root cause is proven inverted in the diagnostic, the fix proceeds directly in the
  fix wave — do NOT structure a separate plan around "try a cheap fix and let a binding gate
  catch the failure." The diagnostic locks the cause; the fix acts on it. (See
  `feedback_dont_pay_to_confirm_obvious`.)

### Inverted-polarity detection mechanic
- **D-02:** **Single shared luminance-order comparator in `PngUtils`** (alongside
  `isIndexedPngShared`). It is the ONE source of truth consumed by all three: the build
  WARNING (Req 4), the diagnostic artifact (Req 1/2), and the emission tests (Req 3).
- **D-02b:** Baseline for "inverted" = the **source PNG's own PLTE luminance ranking**.
  "Inverted" = the emitted RGB555 palette sequence is the monotonic reverse of that ranking.
  Self-contained — no build-time dependency on the external compiled GBDK reference (that
  reference is for the human visual sign-off, not for the build-time warning). Matches the
  SPEC wording ("inverted vs the source PNG PLTE") and the DRY `*Shared` precedent.
- **D-02c (deferred to research):** The exact reversal predicate (strict full-reversal vs
  negative rank-correlation / Spearman) is a research call — pick the one that cleanly
  distinguishes the real inversion from benign reorderings without false positives.

### Emission-test homes
- **D-03:** **Two-level, both in `gbkt-gradle-plugin`** (run via `./gradlew pluginTest`, NOT
  `:gbkt-gradle-plugin:test` — see root CLAUDE.md):
  1. **PngUtils comparator/permute UNIT tests** on fixture PNGs — RED on an inverted source,
     GREEN on the corrected order — covering the shared mechanic for BOTH BG and OBJ.
  2. **One C-shape assertion per CHANGED pipeline** on the real platformer asset's emitted
     palette array byte order (`_zone_*_tileset_palettes[]` for BG; `<stem>_palettes[]` for OBJ).
- **D-03b:** No emission test lands in the backend module (`GBDKPipelineV2`): the palette BYTE
  ORDER originates in the gradle-plugin convert tasks (png2asset-emitted `.c`); the backend's
  `buildMetaspriteSpritePaletteStatements` only wires the `set_sprite_palette()` CALL, not the
  bytes. (Confirmed during scout.)

### Fix locus / mechanism
- **D-04:** **Defer the fix layer/mechanism to the diagnostic + research.** Do NOT lock it now.
  The unified diagnostic must isolate WHERE the inversion enters before any code change —
  candidate loci to probe (in order of evidence weight): the 13.3 Color-namespace migration
  (`gbc()`/`Color`/`gbcHex()` emission), the png2asset PLTE-order path
  (`-keep_palette_order` × `isIndexedPng()`), or the RGB555 bit-layout/emission. The fix lands
  at whichever proven root cause, at the framework source. Mirrors 13.6's deferred-mechanism
  approach and honors the SPEC's diagnose-first / no-blind-remap constraint.
- **D-04b (open hypothesis tension — must be resolved by the diagnostic):** The SPEC names the
  13.3 Color refactor as prime suspect, BUT the platformer BG and player palettes are
  png2asset-derived from indexed PNGs via `-keep_palette_order` — a path the DSL `Color`
  migration would not obviously touch. The diagnostic MUST reconcile these two hypotheses
  (DSL-Color-emission vs PNG-PLTE-order) with codegen-read evidence before the fix is chosen.

### Claude's Discretion
- Exact reversal predicate for the comparator (D-02c) — research.
- Whether BG and OBJ fixes share a single corrective code path or need separate ones — falls
  out of the diagnostic (if both prove to be the same root cause, one fix; if divergent, two).
- Fixture-PNG design for the RED→GREEN unit tests (synthesized inverted PLTE vs a copy of the
  real asset) — planner's call, provided RED is genuinely red at the pre-fix commit.

</decisions>
