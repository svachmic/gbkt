# Phase 13.7 Plan 03: Asset-Driven OBJ Palette Upload Fix Summary

Fixed the CONFIRMED OBJ root cause (D-04, Req-2): emit `set_sprite_palette` for asset-driven
metasprites (spritePath != null) when the game has no `spritePalette{}` declaration — closes
the platformer player dark-body/light-halo inversion.

## Task 1: RED+GREEN — asset-driven set_sprite_palette fallback in GBDKPipelineV2

**RED commit:** `96ae1f09` — `PlatformerObjPaletteUploadTest.kt` written with 5 behaviors.
Tests 1, 4, 5 fail RED (the fix does not exist yet). Tests 2, 3 pass (Direction B + DMG gate
already correct pre-fix).

**GREEN commit:** `7a074a29` — additive fallback arm in `buildMetaspriteSpritePaletteStatements`.

### Implementation

Added `import io.github.gbkt.core.ir.PaletteType` and the following arm AFTER the existing
procedural arm in `GBDKPipelineV2.buildMetaspriteSpritePaletteStatements`:

```kotlin
val hasSpritePalette = gameIR.palettes.any { it.type == PaletteType.SPRITE }
val assetDrivenStatements = if (!hasSpritePalette) {
    val proceduralCount = proceduralMetasprites.size
    val assetDrivenMetasprites = gameIR.metasprites.filter { it.spritePath != null }
    assetDrivenMetasprites.mapIndexed { idx, ms ->
        CRawCode("set_sprite_palette(${proceduralCount + idx}u, 1u, ${ms.id}_palettes);")
    }
} else {
    emptyList()
}
return proceduralStatements + assetDrivenStatements
```

The procedural arm itself is byte-unchanged; only its local variable name was changed from
a direct `return` to `val proceduralStatements =` to allow combining both results.

### Emitted palette symbol stem

Confirmed: `${ms.id}_palettes` → for `id="player"` → `player_palettes`.

Evidence: `gbkt-examples/platformer-template/build/gbkt/generated/sprites/player.c` line 12:
```c
const palette_color_t player_palettes[4] = {
```

The fix emits: `set_sprite_palette(0u, 1u, player_palettes);` — exactly what the GBDK reference
emits at `player.c:85` (`set_sprite_palette(baseProp, 1, PlayerCharacterSprites_palettes)`).

### MetaspriteSubPaletteEmissionTest update

The existing `buildGame` helper created a game with `palettes = emptyList()`. After the fix,
such a game (no `GBCPalette(type=SPRITE)`) would trigger the new fallback arm, causing the
asset-driven elephant to EMIT `set_sprite_palette` — breaking Tests 1, 2, 4.

Fix: added `graySpritePalette()` helper and updated `buildGame` to include
`palettes = listOf(graySpritePalette())`. This correctly models the metasprites-example shape
(game HAS an explicit `spritePalette{}`) — Direction B suppression applies, tests remain valid.
