<objective>
Fix the CONFIRMED OBJ root cause (Req 2): emit `set_sprite_palette` for asset-driven
metasprites that lack any game-level `spritePalette{}` declaration, so the platformer player
renders under its png2asset-derived palette instead of the GBC `cgb_compatibility()` descending
default (which produced the dark-body / light-halo inversion). Fix lands at the proven framework
locus `GBDKPipelineV2.buildMetaspriteSpritePaletteStatements` (D-04) — NOT in the example DSL.

Purpose: 13.3-17 Direction B deliberately excluded ALL asset-driven metasprites from auto
upload to avoid triple-slot collision when a `spritePalette{}` is present. The fix is ADDITIVE:
only the asset-driven metasprites with NO `spritePalette{}` anywhere (game has no
`GBCPalette(type=SPRITE)`) get the automatic upload. Per the phase planning guidance, the OBJ
fix's RED->GREEN emission test lives WITH this change in the backend module (the explicit
exception to D-03b, which constrains only palette-BYTE-ORDER tests — this test asserts the
`set_sprite_palette` CALL is now emitted, not byte order).
Output: the fallback arm + `PlatformerObjPaletteUploadTest.kt`.
</objective>
