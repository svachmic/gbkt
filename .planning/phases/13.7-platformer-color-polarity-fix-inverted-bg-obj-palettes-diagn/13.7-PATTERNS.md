```kotlin
internal fun countUsedVisibleColors(file: File, transparentIdx: Int): Int {
    return try {
        val img = ImageIO.read(file) ?: return 0
        val cm = img.colorModel as? IndexColorModel ?: return 0
        val raster = img.raster
        val pixelCounts = IntArray(cm.mapSize)
        for (y in 0 until img.height) {
            for (x in 0 until img.width) {
                val idx = raster.getSample(x, y, 0)
                if (idx in pixelCounts.indices) pixelCounts[idx]++
            }
        }
        pixelCounts.indices.count { it != transparentIdx && pixelCounts[it] > 0 }
    } catch (_: Exception) {
        0
    }
}
```

**New function to add — `checkPalettePolarity`:**
- Signature: `internal fun checkPalettePolarity(sourcePng: File, emittedRgb555Values: List<Int>): Boolean`
  - Returns `true` if Spearman rank correlation between source PLTE luminances and emitted RGB555 luminances equals -1.0 (strict full reversal = inverted).
  - Returns `false` for degenerate input (n < 2, all-equal lum).
- Companion private helpers: `internal fun spearmanRanks(values: List<Double>): List<Double>` and `internal fun spearmanCorrelation(ranksX: List<Double>, ranksY: List<Double>): Double` — same `internal` file-scope visibility pattern.
- RGB555 layout confirmed from `CoreTypes.kt`: `rgb555 = (b5 shl 10) or (g5 shl 5) or r5` — decompose as `r5 = rgb555 and 0x1F`, `g5 = (rgb555 shr 5) and 0x1F`, `b5 = (rgb555 shr 10) and 0x1F`.
- Luminance formula: Rec.601 `lum = 0.299 * r8 + 0.587 * g8 + 0.114 * b8` where `r8 = r5 * 255 / 31`.
- Caller in convert tasks parses the emitted `palette_color_t` array with `parsePaletteArrayDim` regex and passes the RGB555 values separately — do NOT read the .c file inside `checkPalettePolarity` to preserve testability.

```kotlin
    val sigIdx = source.indexOf(signature)
    if (sigIdx == -1) return null

    if (openIdx == -1) return null

    }
```

## Implementation Notes for Open Questions

### A2: How `spritePalette{}` is represented in `GameIR`

From reading `CoreTypes.kt` lines 326-343 and `GBDKPipelineV2.kt` lines 1179, 2970-2971:
- `spritePalette{}` DSL produces `GBCPalette(type = PaletteType.SPRITE, ...)` entries
- These are stored in `GameIR.palettes: List<GBCPalette>` (NOT inside SceneIR)
- Check for "no scene spritePalette{}" = `gameIR.palettes.none { it.type == PaletteType.SPRITE }`
- PaletteType enum is in `CoreTypes.kt` line 90: `enum class PaletteType { SPRITE, BACKGROUND }`
- Implication: the fix in `buildMetaspriteSpritePaletteStatements` should filter asset-driven metasprites where the entire game has no `GBCPalette(type = SPRITE)` — not per-scene but game-level.

### Slot numbering for asset-driven fallback

- Procedural metasprites claim OBJ palette slots 0..N-1 (mapIndexed { slot, ms -> slot })
- Asset-driven fallback must start at `proceduralMetasprites.size` to avoid collision
- For platformer-template specifically: zero procedural metasprites → asset-driven starts at slot 0
- Verify: `gameIR.metasprites.count { it.spritePath == null }` before assigning asset-driven slots
