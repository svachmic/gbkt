# Phase 13.7 Plan 05: Palette Polarity WARNING Wired into BG+OBJ Convert Tasks

Non-fatal build-time WARNING detecting luminance-order inversion wired into both
convert task pipelines using the shared `checkPalettePolarity` comparator from Plan 02.

## What Was Built

**Task 1 — BG WARNING (ConvertZoneTilesetsTask) + OBJ WARNING (ConvertSpritesTask):**

`ConvertZoneTilesetsTask.convertOneTileset` now calls `parsePaletteRgb555Values` (new
private helper) after the png2asset success + non-empty-outputC guards and before
`parsePaletteArrayDim`, gated on `isIndexedPng(pngFile)`. If `checkPalettePolarity`
returns true, `logger.warn` emits an ASCII-only message naming the offending PNG.

`ConvertSpritesTask.convertSprite` now calls `parseSpriteRgb555Values` (new internal
function) after `remapMetaspriteSubPalette` and before `injectBankPragma`, gated on
`isIndexedPngShared(pngFile)`. Same `logger.warn` shape. The existing D-06 transparent-
index warn is preserved unchanged (additive second warning).

Both warnings: no `throw`, no error state, build exits 0. WR-05 compliant (ASCII-only).

**Key implementation detail — RGB8 macro parsing:**
Real png2asset output uses `RGB8(r,g,b)` GBDK macros in palette arrays, not raw integers.
Both `parsePaletteRgb555Values` and `parseSpriteRgb555Values` detect `RGB8(r,g,b)` entries
first (via Regex) and convert to RGB555 using `(r*31/255) | ((g*31/255)<<5) | ((b*31/255)<<10)`,
then fall back to raw integer parsing for synthetic/test fixtures.

**Task 2 — PalettePolarityWarningTest.kt (8 tests, all GREEN):**

| Test | What it covers |
|------|----------------|
| 1 | `parseSpriteRgb555Values` parses RGB8-format BG palette array |
| 2 | `parseSpriteRgb555Values` parses RGB8-format sprite palette array |
| 3 | BG inverted fixture → `checkPalettePolarity` true → one warn would be emitted |
| 4 | BG corrected fixture → `checkPalettePolarity` false → zero warns |
| 5 | OBJ inverted fixture → `checkPalettePolarity` true → one warn would be emitted |
| 6 | OBJ corrected fixture → `checkPalettePolarity` false → zero warns |
| 7 | `ConvertZoneTilesetsTask` does not throw on inverted palette (skip-guarded) |
| 8 | `ConvertSpritesTask` does not throw on inverted palette (skip-guarded) |

Tests 3-6 prove the "exactly one warn per inverted asset / zero on corrected" contract
at the logic level (checkPalettePolarity return value = warn trigger). Tests 7-8 prove
the non-fatal contract at the task execution level.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] RGB8 macro parsing required for real png2asset output**
- **Found during:** Task 1 implementation
- **Issue:** Initial `parsePaletteRgb555Values` and `parseSpriteRgb555Values` split by
  comma and called `toIntOrNull()`, which cannot parse `RGB8(r,g,b)` macro entries.
  Real png2asset output (e.g. `_zone_world1Area1Zone_tileset.c`) uses
  `RGB8(  8, 24, 32), RGB8(224,248,207), ...` format, not raw integers. This caused
  `parseSpriteRgb555Values` to return `null` for all real assets, meaning the WARNING
  would never fire. Test 1 caught this: `parseSpriteRgb555Values must parse a palette_color_t
  array ==> expected: not <null>`.
- **Fix:** Both parsers first scan for `RGB8(r,g,b)` matches via Regex and convert to
  RGB555 using the GBDK formula. Fall back to raw integer parsing (decimal + 0x-hex) for
  synthetic fixtures. Tests updated to use RGB8 format matching real png2asset output.
- **Files modified:** `ConvertZoneTilesetsTask.kt`, `ConvertSpritesTask.kt`,
  `PalettePolarityWarningTest.kt`
- **Commit:** `2142b5d1`
