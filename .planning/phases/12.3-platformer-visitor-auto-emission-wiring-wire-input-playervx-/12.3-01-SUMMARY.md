# Phase 12.3 Plan 01: PlatformerInput DSL Substrate Summary

**One-liner:** `platformerInput { }` DSL builder + ZoneBuilder extension + per-zone override payload — Wave 2 prerequisite that exposes `GenericSystem(type="platformer_input")` for PlatformerVisitor input/walk-cycle emission and `ZoneIR.platformerInputOverride` for per-level tuning.

## Result

R1 ACCEPTANCE — `platformerInput { walkSpeed(N); friction(F); airFriction(F); walkFrameCount(W); cyclePeriod(P); walkFrameIdx(AssignableVar); threeFrameCounter(AssignableVar) }` compiles at game-level (registers a `GenericSystem`) and zone-level (writes only explicitly-set numeric fields into `ZoneIR.platformerInputOverride`, with binders intentionally absent). PlatformerInputDslTest 3/3 GREEN; full `:gbkt-genre-platformer:test` suite GREEN; `:gbkt-ir:test` GREEN; `:gbkt-lang:compileKotlin` exit 0.

## Deviations from Plan

**Single auto-fix (Rule 3 — blocking issue):**

1. **[Rule 3 — Test stuck on `build()` validation]** Test 1 originally called `gb.build()` to extract the `GenericSystem`, which fired the `DSLValidationError: No start scene set` gate.
   - **Found during:** Task 2 first GREEN attempt.

   - **Files modified:** PlatformerInputDslTest.kt only.
   - **Commit:** 38fb2ed5 (Task 2 commit — fix was applied during initial test authoring, before the commit).
