# Phase 12.3: PlatformerVisitor Auto-Emission Wiring — Specification

**Created:** 2026-05-23
**Ambiguity score:** 0.16 (gate: ≤ 0.20)
**Requirements:** 7 locked

## Goal

PlatformerVisitor + MetaspriteVisitor + PlatformerPhysicsBuilder are extended so a platformer-physics zone with a player metasprite renders a fully-playable platformer (input → velocity, camera tracking, screen-relative metasprite render, walk-frame cycling) WITHOUT any inline `cEmit(...)` workarounds in user DSL. The 3 inline cEmits added in Plan 12-21 are removed, Phase 12 Plan 12-22 (Anchor 4) closes GREEN, and Anchors 1–3 are re-shot from the cleaned-up ROM to confirm no visual regression.

## Background

Phase 12 Wave 13 surfaced 4 PlatformerVisitor auto-emission gaps when running UAT against the platformer-template port:

1. **Input → velocity gap:** `platformer_physics_update()` (PlatformerVisitor lines ~221+, see `gbkt-genre-platformer/src/main/kotlin/io/github/gbkt/genre/platformer/codegen/PlatformerVisitor.kt:492` `buildTilemapPhysicsUpdateFunction`) reads `_playerVx` for horizontal collision + integrates `_playerX += _playerVx >> 4` but **nothing sets `_playerVx` from dpad input**. Reference GBDK `player.c` sets `playerXVelocity = ±moveSpeed` on RIGHT/LEFT held with ground-friction deceleration on release.

2. **camera_update call-site gap:** `platformer_camera_update()` is emitted in main.c:437 (PlatformerVisitor `buildTilemapCameraUpdateFunction`, line 1312) but **no call site invokes it**. Without the call, `move_bkg()` never fires (no visual scroll), `_map_pos_x` stays at 0, and column-scroll redraw never triggers.

3. **Metasprite camera-offset gap:** MetaspriteVisitor (`gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/visitor/MetaspriteVisitor.kt:267-273`) emits `move_metasprite_*(... DEVICE_SPRITE_PX_OFFSET_X + ($posXVar >> 4), ...)` using ABSOLUTE world position. When the bg scrolls via `move_bkg`, the player metasprite drifts off-screen because no camera offset is applied to the sprite layer.

4. **walkFrameIdx cycle gap:** `_walkFrameIdx` is declared in DSL (`PlatformerTemplate.kt:118`) and READ by the metasprite render switch (`bank1.c:65,70,75,80`) but **nothing increments it**. DSL comments at lines 109-113 describe the expected `threeFrameCounter → walkFrameIdx` cycle pattern (mirroring reference `player.c:130-145`) but no code implements it.

Plan 12-21 inline-fixed gaps 1/2/3 via `cEmit(...)` workarounds in `PlatformerTemplate.kt:402-453`. Plan 12-22 hit gap #4 and triggered the 4-gap escalation threshold per memory rule `feedback_route_to_proper_phase_when_blast_radius_is_wide`. Comprehensive catalog: `.planning/seeds/SEED-PHASE-12-PLATFORMER-VISITOR-AUTO-EMISSION-GAPS.md`. Block evidence: `.planning/phases/12-port-platformer-template-gbdk-example-to-gbkt/evidence/anchor-4-blocked-walkframeidx-never-incremented.md`.

`playerVx` is currently `i8Var` (INT8, max 127); the reference uses INT16 `moveSpeed = 0x80 = 128`, so realistic platformer feel requires widening to `i16Var`.

## Requirements

1. **`platformerInput { }` DSL surface on `ZoneBuilder`**: New extension exposing walkSpeed + friction configuration.
   - Current: No `platformerInput { }` block exists. `gbkt-genre-platformer/src/main/kotlin/io/github/gbkt/genre/platformer/dsl/PlatformerExtensions.kt` has `platformerPhysics { }` and `platformerCamera { }` but no input config.
   - Target: New `platformerInput { walkSpeed(N); friction(F) }` extension on `ZoneBuilder` (sibling of `platformerPhysics`/`platformerCamera`). Lowered via the same `setPlatformerInputOverride(Map<String,Any>)` pattern Plan 12-06 established for physics overrides. Defaults: walkSpeed=128 (INT16), friction=8 (per-frame velocity damping toward 0).
   - Acceptance: A unit test in `gbkt-genre-platformer/src/test/kotlin/.../dsl/` declares `zone("test") { platformerInput { walkSpeed(64) } }` and verifies the override is stored in the zone's input-override map. Default values are exposed via `PlatformerInputConfig` data class.

2. **Auto-emit dpad → playerVx in PlatformerVisitor (gap #1)**: When a zone is bound to platformer-physics, PlatformerVisitor emits dpad-held → playerVx velocity wiring with friction-based deceleration on release.
   - Current: PlatformerVisitor `buildTilemapPhysicsUpdateFunction` does not emit any input → velocity code. `_playerVx` is only zeroed by collision.
   - Target: PlatformerVisitor appends to the gameplay zone's `frame { }` codegen output: `if (button_held(J_RIGHT)) _playerVx = walkSpeed; else if (button_held(J_LEFT)) _playerVx = -walkSpeed; else if (_playerVx > 0) _playerVx -= friction (clamp at 0); else if (_playerVx < 0) _playerVx += friction (clamp at 0);` — values from `PlatformerInputConfig` defaults or override.
   - Acceptance: JVM-tier emission invariant test (per-function awk brace-walk) at `gbkt-genre-platformer/src/test/kotlin/.../codegen/PlatformerInputEmissionTest.kt` locks the emitted shape. Runtime: when ROM rebuilt without the Plan 12-21 inline cEmit, anchor 3 still passes (`_camera_x > 0` after 150-frame RIGHT hold).

3. **Auto-call `platformer_camera_update()` in PlatformerVisitor (gap #2)**: PlatformerVisitor emits a call to the camera-update function from each gameplay zone's `frame { }` codegen output, after physics_update.
   - Current: `platformer_camera_update()` function body is emitted but no call site exists anywhere.
   - Target: PlatformerVisitor `buildTilemapCameraUpdateFunction` ALSO appends `platformer_camera_update();` to the zone-frame BodyExtension list (analogous to the physics_update call wiring). Order: physics_update → input → camera_update → metasprite render.
   - Acceptance: Per-function awk brace-walk emission test at `PlatformerCameraCallSiteEmissionTest.kt` verifies the `platformer_camera_update();` line appears in `gameplay_frame(void) BANKED { ... }` between `platformer_physics_update();` and the first `move_metasprite_*` call. Runtime: without inline cEmit, anchor 3 still passes (`_map_pos_x > 0`).

4. **MetaspriteVisitor camera-offset render in tilemap-camera mode (gap #3)**: MetaspriteVisitor emits screen-relative metasprite X coordinates when the parent zone uses tilemap-camera mode.
   - Current: MetaspriteVisitor lowers to `DEVICE_SPRITE_PX_OFFSET_X + ($posXVar >> 4)` unconditionally — absolute world position.
   - Target: When the binding zone's camera config is `tilemap-camera` (Plan 12-10/12-11 mode), emit `DEVICE_SPRITE_PX_OFFSET_X + (UINT8)(((INT16)($posXVar >> 4)) - (INT16)_camera_x)` instead. Y stays world-coordinate (no vertical camera). The mode flag is passed into `lowerMoveMetasprite` as a new parameter (e.g., `cameraOffsetX: String? = null`); when null, current behavior preserved (back-compat for non-platformer games).
   - Acceptance: Per-function awk brace-walk emission test at `MetaspriteCameraOffsetEmissionTest.kt` verifies the screen-relative formula in `gameplay_frame` when the test fixture's player metasprite is bound under tilemap-camera; verifies absolute formula in a non-platformer fixture (back-compat). Runtime: anchor 3 visual shows player at consistent screen X across 01-initial and 02-scrolled.

5. **Auto-emit walkFrameIdx cycle in PlatformerVisitor (gap #4)**: When a zone is bound to platformer-physics AND has a multi-frame player metasprite, PlatformerVisitor emits the threeFrameCounter→walkFrameIdx cycle.
   - Current: `_walkFrameIdx` declared + read by metasprite render switch, but no code increments it. `_threeFrameCounter` is also declared but never written.
   - Target: PlatformerVisitor appends to gameplay zone's `frame { }`: `if (_playerVx != 0) { _threeFrameCounter++; if (_threeFrameCounter >= N) { _threeFrameCounter = 0; _walkFrameIdx++; if (_walkFrameIdx >= W) _walkFrameIdx = 0; } } else { _walkFrameIdx = 0; _threeFrameCounter = 0; }` — where N=6 (default cycle period from reference), W=3 (number of walk frames; configurable via the new `platformerInput { walkFrameCount(W); cyclePeriod(N) }` setters). Defaults match reference player.c.
   - Acceptance: Per-function awk brace-walk emission test at `PlatformerWalkCycleEmissionTest.kt` locks the shape. Runtime: anchor 4 test (Plan 12-22) — `walkFrameIdx` takes ≥ 2 distinct values across 3 captures while RIGHT is held; `walkFrameIdx == 0` after release.

6. **Widen `playerVx` to `i16Var` in `PlatformerTemplate.kt`**: Player horizontal velocity uses INT16 to support reference-equivalent walking speed.
   - Current: `var playerVx by i8Var(0)` at `PlatformerTemplate.kt:152` (INT8, max 127). Generated as `INT8 _playerVx`.
   - Target: `var playerVx by i16Var(0)` (INT16, ~±32767 range). Generated as `INT16 _playerVx`. PlatformerVisitor `buildTilemapPhysicsUpdateFunction` integration `_playerX += _playerVx >> 4` already works with INT16 (Kotlin codegen emits compatible C). Verify no integer-promotion warnings from gbdk lcc on the ROM build.
   - Acceptance: `_playerVx` declaration in generated main.c is `INT16 _playerVx`. ROM builds clean with 0 errors / 0 new warnings. Reference walkSpeed value (128) compiles and runs correctly (gap #2 acceptance also passes with walkSpeed=128 default).

7. **Remove 3 inline cEmits from `PlatformerTemplate.kt` + re-shoot Anchors 1–3 (cleanup + regression check)**: The Plan 12-21 inline workarounds are removed; UAT anchors 1, 2, 3 are re-run from the cleaned-up ROM.
   - Current: `PlatformerTemplate.kt:402-453` contains 3 cEmit-based inline fixes (dpad→playerVx clauses, `cEmit("platformer_camera_update();")`, cEmit-fudge save/restore around moveMetasprite).
   - Target: All 3 inline blocks removed. `gameplay` scene's `frame { }` block contains only the original facingRot clauses + `moveMetasprite(player)`. Anchor 1 (12-19), Anchor 2 (12-20), Anchor 3 (12-21) re-shot with fresh PNGs. Human-verify gates re-run.
   - Acceptance: `grep -c "cEmit" PlatformerTemplate.kt` returns 1 (only `cEmit("setup_current_level();")` remains, since that's a separate D-20 follow-up not covered by this phase). All 4 anchor tests pass. User-verify APPROVE on re-shot 01-title.png, 02-gameplay.png (anchor 1); 01-grounded/02-mid-jump/03-landed (anchor 2); 01-initial/02-scrolled (anchor 3); 01-walk-frame-0/01/02/04-facing-left (anchor 4).

## Constraints

- **Backwards-compat with existing platformer-template DSL:** Removing the inline cEmits MUST NOT change the gameplay behavior — the new auto-emission must produce equivalent runtime output (modulo cEmit ordering quirks).
- **MetaspriteVisitor back-compat:** Non-platformer games (pong, breakout, banks, metasprites) call `lowerMoveMetasprite` without camera-offset context. The new `cameraOffsetX` parameter defaults to null → existing emission shape preserved → all existing emission tests still pass without modification.
- **No new C standard library dependencies:** Use only `button_held(J_*)` (already used), arithmetic / shift / comparison (already used), `move_bkg()` (already called from camera_update). No new GBDK functions.
- **ROM size:** Adding ~20 lines to `gameplay_frame` (bank 1) should fit. If bank 1 overflows, the framework's banking-analysis pass should re-allocate automatically; no manual intervention.
- **JVM test suite:** All existing emission invariant tests (12-09, 12-12, 12-14, 12-09b) MUST still pass. New tests are ADDED, not modifications of existing tests.
