# Phase 12.3 Plan 04: PlatformerVisitor visitCamera frameOps Splice Summary

**One-liner:** PlatformerVisitor.visitCamera now returns a `frameOps` splice carrying `RawOp("platformer_camera_update();")` for the gameplay scene id whenever the triple-condition gate (`gameUsesTilemapCollision && ScrollDirection.HORIZONTAL && CameraScrollMode.SMOOTH_FOLLOW`) holds. Wires gap #2 — the `platformer_camera_update()` function (already emitted by `buildTilemapCameraUpdateFunction` since Plan 12-10) finally gets CALLED each frame, replacing the inline `cEmit("platformer_camera_update();")` at PlatformerTemplate.kt:430 (cleanup ships in Plan 12.3-12).

## Result

**R3 CODEGEN ACCEPTANCE** (acceptance test ships in Plan 12.3-05): `visitCamera` emits a `frameOps` map keyed by the gameplay scene id, with a single-element list containing `RawOp("platformer_camera_update();")`. When the triple-gate fails (rect-physics game, vertical-only camera, or screen-lock camera), `frameOps = emptyMap()` — no `platformer_camera_update();` line appears in any scene frame body, preserving back-compat for non-platformer-camera games (existing JumpHold / TilemapCollision / HorizontalScroll / Defect4SymbolRewrite emission test fixtures stay byte-identical). Existing `varDecls` + `functions` outputs of `visitCamera` are UNCHANGED — the splice is purely additive on the `frameOps` field.

## Source Changes

### gbkt-genre-platformer/.../codegen/PlatformerVisitor.kt (modified — 1 file, 48 lines added)

Single additive edit (no existing lines removed; the only diff is the new gameplaySceneId/frameOps block + the GenreVisitorResult constructor call updated to include `frameOps = frameOps` and use fully named args).

**Edit — Inside `visitCamera`, just BEFORE the existing `return GenreVisitorResult(...)` at original line 1328:**

1. **gameplaySceneId discovery** (copied verbatim from `visitPhysics` at PlatformerVisitor.kt:186-197):
   ```kotlin
   val physicsActorIds =
       gameIR.actors
           .filter { it.movementConfig?.style == MovementStyle.PHYSICS }
           .map { it.id }
           .toSet()
   val gameplaySceneId: String? =
       gameIR.scenes
           .firstOrNull { scene -> scene.actorIds.any { id -> id in physicsActorIds } }
           ?.id
           ?: findFirstNavigateTarget(gameIR)
           ?: gameIR.startScene
           ?: gameIR.scenes.firstOrNull()?.id
   ```

2. **frameOps map computed with the triple-condition gate:**
   ```kotlin
   val frameOps: Map<String, List<ScriptOp>> =
       if (gameplaySceneId != null &&
           gameUsesTilemapCollision(gameIR) &&
           cameraConfig.scrollDirections == ScrollDirection.HORIZONTAL &&
           cameraConfig.mode == CameraScrollMode.SMOOTH_FOLLOW
       ) {
           mapOf(gameplaySceneId to listOf(RawOp("platformer_camera_update();")))
       } else {
           emptyMap()
       }
   ```

3. **Return statement** updated from `return GenreVisitorResult(functions = functions, varDecls = varDecls)` to:
   ```kotlin
   return GenreVisitorResult(
       functions = functions,
       varDecls = varDecls,
       frameOps = frameOps,
   )
   ```

Triple-gate equivalence with the existing `buildTilemapCameraUpdateFunction` trigger (PlatformerVisitor.kt:1406-1408):

| Condition | Function-body gate (line 1406) | Call-site gate (this plan) | Lockstep? |
|-----------|--------------------------------|----------------------------|-----------|
| 1 | `gameUsesTilemapCollision(gameIR)` | `gameUsesTilemapCollision(gameIR)` | ✓ |
| 2 | `cfg.scrollDirections == ScrollDirection.HORIZONTAL` | `cameraConfig.scrollDirections == ScrollDirection.HORIZONTAL` | ✓ (`cameraConfig` is the visitCamera-local alias of `cfg`) |

When all 3 conditions are true: the function body emits via `buildTilemapCameraUpdateFunction` AND the call is spliced into the gameplay scene's frame body. When any condition is false: neither emission fires (no orphan function, no orphan call).
