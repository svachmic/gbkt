**Edit A — New `gameUsesPlatformerInput(gameIR): Boolean` predicate** (inserted at line 1363, immediately AFTER `gameUsesTilemapCollision`):

```kotlin
private fun gameUsesPlatformerInput(gameIR: GameIR): Boolean {
    val systemPresent =
        gameIR.systems.filterIsInstance<GenericSystem>().any { sys ->
            (sys.config["type"] as? String) == "platformer_input"
        }
    if (systemPresent) return true
    return gameIR.zones.any { zone -> zone.platformerInputOverride != null }
}
```

KDoc cross-references `gameUsesTilemapCollision` for shape parity. Both paths:
- **Path A** — `platformer_input` GenericSystem present (game-level registration via `GameBuilder.platformerInput { ... }` extension from Plan 12.3-01).
- **Path B** — any zone has `platformerInputOverride` non-null (per-zone numeric shadow via `ZoneBuilder.platformerInput { ... }`).

**Edit B — New `piSystem` config-read block in `buildTilemapPhysicsUpdateFunction`** (inserted at line 560, immediately AFTER the existing `tcSystem` / vxSym / groundedSym resolution at lines 549-558):

```kotlin
val piSystem =
    gameIR.systems.filterIsInstance<GenericSystem>().firstOrNull { sys ->
        (sys.config["type"] as? String) == "platformer_input"
    }
val walkSpeed: Int = (piSystem?.config?.get("walkSpeed") as? Int) ?: 128

```

Hardcoded fallbacks (128/8/0) mirror the `PlatformerInputConfig` defaults from Plan 12.3-01 (D-01a). When `gameUsesPlatformerInput == false`, the gate (Edit C) is OFF and these values are never consumed — the fallbacks exist for shape symmetry with the `tcSystem` block at lines 553-558.

**Edit C — New section 0 inside the `body = buildList<CStatement> { ... }` block** (inserted at line 579, AS THE FIRST `add(...)` statement — BEFORE the existing position-read at original line 561). Gated on `gameUsesPlatformerInput(gameIR)`.

Emission shape (matches RESEARCH §"Code Examples / Input → playerVx"):

```c
if (button_held(J_RIGHT)) {
    _playerVx = 128;            // walkSpeed — CIntLiteral (signed RHS)
} else if (button_held(J_LEFT)) {
    _playerVx = -128;           // CIntLiteral (signed RHS)
} else {
    UINT8 f = _grounded ? 8u : 0u;                          // friction vs airFriction
    if (_playerVx > 0) {                                    // CIntLiteral(0)
        _playerVx = (_playerVx > f) ? (_playerVx - f) : 0;
    } else if (_playerVx < 0) {                             // CIntLiteral(0)
        _playerVx = (_playerVx < -((INT16)f)) ? (_playerVx + f) : 0;
    }
}
```

Codegen idiom (recorded in commit body for Plan 12.3-08 to inherit):
- Typed C-AST `CIf` with `thenBody`/`elseBody` for control flow.
- `CCall("button_held", listOf(CVar("J_RIGHT")))` for the input poll calls.
- `CBinaryExpr(CVar(vxSym), "=", CIntLiteral(walkSpeed))` for velocity assignments — `CIntLiteral` is the signed-RHS form, no `u` suffix.
- `CBinaryExpr(CVar(vxSym), ">", CIntLiteral(0))` / `..., "<", CIntLiteral(0))` for signed comparisons — **Phase 07.9 / L-5.1 discipline** — NEVER `CLiteral(0)`.
- `CVarDecl(name = "f", type = CU8, initializer = CRawExpr(...))` for the UINT8 friction local — the `${friction}u` suffix in the ternary RHS is correct because UINT8 is unsigned context.
- `CRawExpr` for the cast-heavy ternary assignment RHS expressions `(_playerVx > f) ? (_playerVx - f) : 0` and `(_playerVx < -((INT16)f)) ? (_playerVx + f) : 0`. CRawExpr is the cleanest representation here and matches the file's existing convention for cast-heavy expressions (compare with `_jump_increase_timer` decrement at lines 762, 763 which also uses `CRawExpr`).

D-05 emission order locked: `add(...)` for section 0 happens BEFORE the existing section-1 `Sub-pixel position read` — the input set lands first in the `body` list, the position read second, AABB probes third, etc. The emission order is settled at function-build time (not at frameOps splice time), so even if the pipeline merges visitors in a different order, this plan's input wiring runs FIRST inside the physics function.

L-5.4 (walk-cycle) is OUT OF SCOPE — that's Plan 12.3-08. No `_walkFrameIdx` references emitted by this plan.
