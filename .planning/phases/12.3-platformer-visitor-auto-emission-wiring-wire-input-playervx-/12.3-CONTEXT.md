## Implementation Decisions

### DSL surface — `platformerInput { }` placement

- **D-01: Mirror `platformerPhysics` — `GameBuilder.platformerInput { }` sets game-level defaults; `ZoneBuilder.platformerInput { }` shadows specific fields per-zone.** The SPEC req 1 wording ("extension on ZoneBuilder") is INTERPRETED to mean per-zone override surface; game-level defaults need a corresponding `GameBuilder.platformerInput { }` for symmetry with `platformerPhysics`. Lowered via the same `OverrideTrackingBuilder` pattern Plan 12-06 / 12-07 established for physics overrides (record which fields were explicitly set; unset fields fall through to defaults at codegen time). Storage:
  - Game-level: `GenericSystem(type="platformer_input", config={ walkSpeed, friction, airFriction, walkFrameCount, cyclePeriod })` registered via `GameBuilder.platformerInput`.
  - Per-zone: opaque `ZoneIR.platformerInputOverride: Map<String, Any>?` payload (analogous to `platformerPhysicsOverride` — keeps `gbkt-ir` a leaf module).
  - Defaults baked into `PlatformerInputConfig` data class.
  - Field-shadowing semantics identical to `platformerPhysicsOverride` (fields SET in zone block land in override map; fields NOT SET fall through to game-level config at codegen time).
- **D-01a: Defaults locked per SPEC + Area 2a airFriction addition.** `walkSpeed=128` (INT16, 8 sub-pixel/frame = 0.5 px/frame), `friction=8` (decelerate over ~16 frames), **`airFriction=0` (no air friction by default — see D-02)**, `walkFrameCount=3` (frames 0/1/2 cycle), `cyclePeriod=6` (advance walk frame every 6 game frames). Reference `player.c` values. Future platformer ports inherit these defaults; per-zone override is the tuning surface.

### Walk-cycle variable ownership

- **D-03: Keep `walkFrameIdx` + `threeFrameCounter` user-declared in DSL (`PlatformerTemplate.kt:118-119` stay).** PlatformerVisitor reads the variable names via a NEW BINDER on `platformerInput { }` builder:
  ```kotlin
  platformerInput {
      walkFrameIdx(walkFrameIdx)       // AssignableVar binder — captures name from delegate
      threeFrameCounter(threeFrameCounter)
      // walkSpeed, friction etc. omitted → use defaults
  }
  ```
  Rationale: (a) MetaspriteVisitor frame-switch already reads `_walkFrameIdx` via `idx(walkFrameIdx)` binding (`PlatformerTemplate.kt:302`) — if we auto-emit, we re-introduce magic-string `_walkFrameIdx` which violates `feedback_no_magic_strings.md`. (b) The Phase 12.1 `tilemapCollision { position(playerX, playerY); velocity(playerVx, playerVy); grounded(grounded) }` precedent established `AssignableVar`-based name-capture as the canonical no-magic-strings pattern; reusing it here is consistent. (c) Visitor reads `genericSystem.config["walkFrameIdxVar"] as? String` and `config["threeFrameCounterVar"] as? String`, prefixes with `_`, and emits the cycle body. Fallback shape (when binders unset): visitor SKIPS emitting the walk-cycle block — no magic-string emission and no silent default.

### Input → velocity emission

- **D-04: Friction is configurable via `platformerInput { friction(F); airFriction(F) }`.** Two distinct setters; air-vs-ground friction is gated by reading the `_grounded` symbol resolved from the existing `tilemapCollision { grounded(grounded) }` binder. Emission shape:
  ```c
  // Auto-emitted by PlatformerVisitor in gameplay zone's frame{} (BEFORE physics_update)
  if (button_held(J_RIGHT)) _playerVx = walkSpeed;
  else if (button_held(J_LEFT)) _playerVx = -walkSpeed;
  else {
      uint8_t f = _grounded ? friction : airFriction;
      if (_playerVx > 0) _playerVx = (_playerVx > f) ? _playerVx - f : 0;
      else if (_playerVx < 0) _playerVx = (_playerVx < -f) ? _playerVx + f : 0;
  }
  ```
  Defaults `friction=8`, `airFriction=0` mirror reference `player.c` lines 268-289 (ground-friction-only behavior). User can override per-game or per-zone.

- **D-05: Emission order = `input → physics_update → camera_update → metasprite render` (DIVERGES from SPEC req 3 wording).** SPEC req 3 says "Order: physics_update → input → camera_update → metasprite render". Discussion locks **input-first** instead:
  - Input sets `_playerVx` BEFORE physics_update integrates `_playerX += _playerVx >> 4` on the same frame.
  - Zero-frame input lag (mirrors reference player.c's poll-joypad-then-update-player order).
  - Matches the 12-21 inline cEmit ordering that produced GREEN anchor 3 — keeps post-cleanup runtime behavior identical to the working inline version.
  - **Downstream agents (researcher + planner): treat SPEC req 3's "physics_update → input" as a wording typo; emit `input → physics_update`.**
  - `_grounded` referenced in D-04's friction expression reads LAST frame's physics state (since physics hasn't run yet) — acceptable per standard platformer convention.
