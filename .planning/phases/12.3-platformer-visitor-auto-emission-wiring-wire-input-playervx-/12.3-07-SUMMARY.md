# Phase 12.3 Plan 07: MetaspriteCameraOffset JVM-Tier Acceptance Test Summary

JVM-tier per-function awk brace-walk emission test locking Plan 12.3-06's
`cameraOffsetX` parameter — positive case asserts the `_camera_x`
screen-relative formula emits when reflective gates fire; negative case
asserts the absolute formula emits + no `_camera_x` leak when the GameIR has
no platformer systems (D-08 back-compat).

## What Shipped

### `MetaspriteCameraOffsetEmissionTest.kt`

New test file in `gbkt-backend-gbdk/src/test/kotlin/.../visitor/` (owner-module
convention per Plan 12.3-07 PLAN.md `files_modified` and CONTEXT.md §test
files). Two `@Test` methods:

#### `positive_tilemapCamera_emits_screen_relative_X_formula`

Builds a GameIR fixture carrying:

- a `platformer_physics` GenericSystem with `physicsConfig` = local
  `FakePhysicsConfig(solidThreshold = 17)` → Plan 12.3-06 reflective Path A
  fires
- a `platformer_camera` GenericSystem with `cameraConfig` = local
  `FakeCameraConfig(mode = SMOOTH_FOLLOW, scrollDirections = HORIZONTAL)` →
  step 2 fires
- a `player` metasprite with `posXVar="playerX"` binder
- a `gameplay` scene whose `frameOps` runs `MoveMetasprite("player",
  posXVar="playerX", ...)`

Pipeline output's `gameplay_frame` body is extracted via brace-walk from
`bank1.c` (with fallback to `main.c` if the single-scene fast-path folded
the scene into HOME). The extracted body is persisted to
`evidence/tier1-shape/gameplay_frame_metasprite_positive.c` BEFORE
assertions fire.

Assertions:

1. `frameBody.contains("_camera_x")` — primary binding token (unique to
   screen-relative branch). PASS — 4 occurrences (one per flip-variant case
   branch).
2. `frameBody.contains("(INT16)")` — secondary cast marker for the screen-
   relative subtraction. PASS — L-12.2 noted that this assertion may need
   loosening if Plan 12.3-15 ROM smoke trips SDCC warnings 158/207 and the
   codegen drops the explicit casts.

#### `negative_back_compat_no_camera_offset_for_non_platformer_fixture`

Builds a minimal GameIR with:

- a single `elephant` metasprite (no binders → falls back to canonical
  `_posX`/`_posY`/`_idx`/`_rot` globals)
- a `gameplay` scene whose `frameOps` runs `MoveMetasprite("elephant")`
- **no** platformer systems (no `platformer_physics`, no
  `platformer_camera`, no `tilemap_collision`)

`derivePlatformerCameraOffsetX` returns `null` on step 1's first guard →
`MetaspriteVisitor.generateMetaspriteFrameSwitch` receives `cameraOffsetX =
null` → absolute formula emitted byte-identically. The extracted
`gameplay_frame` body is persisted to
`evidence/tier1-shape/gameplay_frame_metasprite_negative.c`.

Assertions:

1. `frameBody.contains(">> 4)")` — absolute-formula right-shift sanity
   check. PASS.
2. `assertFalse(frameBody.contains("_camera_x"))` — load-bearing D-08
   back-compat lock. PASS — 0 occurrences. A failure here would mean
   `_camera_x` leaked into a non-platformer fixture's emission and would
   break every non-platformer ROM (pong / breakout / banks / metasprites)
   at SDCC link time with `Undefined identifier '_camera_x'`.

## Deviations from Plan

None. The plan executed exactly as written, with one stylistic adjustment
explicitly anticipated by Plan 12.3-07's `<read_first>` guidance:

- **Bank1.c → main.c fallback in the extraction helper.** Plan 12.3-07's
  Task 1 action step 5 specified the positive case extracts `gameplay_frame`
  from `bank1.c`. For small single-scene fixtures, `BankingAnalysisPass`'s
  single-scene fast-path folds the scene functions into HOME (`main.c`) and
  omits `bank1.c` (per Phase 10.1 `MetaspriteEmissionTest.playFrameBody`'s
  inline note). The helper `extractGameplayFrame(output)` tries `bank1.c`
  first then falls back to `main.c`, mirroring the established Phase 10.1
  pattern. Both fixtures land in `bank1.c` per the actual run (verified via
  evidence file content), so the fallback is defensive but not triggered;
  the symmetric structure is preserved for future fixture variants.

## Plan 12.3-06 cameraOffsetX Parameter Threading — Locked

The contract Plan 12.3-06 shipped:

```
ScriptOpVisitor.visitMoveMetasprite
    → reads gameIRContext ThreadLocal
    → invokes derivePlatformerCameraOffsetX(gameIR) [reflection-based]
    → threads cameraOffsetX = null | "_camera_x" as 5th arg to
        MetaspriteVisitor.generateMetaspriteFrameSwitch
    → xExpr resolves to absolute or screen-relative formula
```

is now JVM-tier verified at BOTH branches of the conditional. A regression
that:

- mistypes a reflection field name (e.g. `solidThreshold` → `solidThresh`)
  → positive test RED (the gates miss; emission falls back to absolute)
- defaults `cameraOffsetX` to `"_camera_x"` instead of `null` → negative
  test RED (`_camera_x` leaks)
- drops the `cameraOffsetX != null` branch in `MetaspriteVisitor`'s
  `xExpr` → positive test RED (`_camera_x` doesn't appear)
- drops the `(INT16)` cast wrapping → positive test secondary marker RED
  (loosening flagged for Plan 12.3-15 ROM smoke)

is caught at JVM tier BEFORE the ROM smoke / UAT layers.
