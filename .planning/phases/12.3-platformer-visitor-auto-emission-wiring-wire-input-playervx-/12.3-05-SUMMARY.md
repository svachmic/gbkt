# Phase 12.3 Plan 05: PlatformerCameraCallSiteEmissionTest Summary

**One-liner:** Locks R3 acceptance for Plan 12.3-04's `visitCamera` frameOps splice — a JVM-tier per-function awk brace-walk emission test that extracts the gameplay scene's frame body from `bank1.c`, asserts `platformer_camera_update();` is present AND appears AFTER `platformer_physics_update();` in the positive fixture, and asserts back-compat omission (no camera_update call) when `gameUsesTilemapCollision()` returns false. Evidence artifacts captured at `evidence/tier1-shape/gameplay_frame_camera_{positive,negative}.c`.

## Result

**R3 ACCEPTANCE LOCKED.** `PlatformerCameraCallSiteEmissionTest` (2/2 GREEN, 0.007s on JVM) now guards Plan 12.3-04's emission contract against silent regression. The test exercises both branches of the visitCamera triple-gate:

- **Positive fixture** (`solidThreshold = 17`, `HORIZONTAL`, `SMOOTH_FOLLOW`) — gate fires, splice lands in `gameplay_frame`, `cameraIdx > physicsIdx` confirms D-05 emission order.
- **Negative fixture** (`solidThreshold = null`) — gate's first condition fails, `platformer_camera_update();` is absent from `gameplay_frame`.

The full `:gbkt-genre-platformer:test` suite (13+ tests including JumpHoldEmissionTest, HorizontalScrollEmissionTest, TilemapCollisionEmissionTest, Defect4SymbolRewriteEmissionTest, PlatformerPhysicsBuilderTest, PlatformerInputDslTest, etc.) stays GREEN — no regression in adjacent tests.

## Source Changes

### gbkt-genre-platformer/src/test/kotlin/.../codegen/PlatformerCameraCallSiteEmissionTest.kt (created — 1 file, 277 lines)

Single Kotlin test class with 2 `@Test` methods following the sibling-test contract from `JumpHoldEmissionTest.kt` and `HorizontalScrollEmissionTest.kt`:

1. **`extractFunctionBody(cSource, prefix)`** — verbatim copy of the brace-walk helper from `JumpHoldEmissionTest.kt:114-134` and `HorizontalScrollEmissionTest.kt:116-136`. Anchors on `lines.indexOfFirst { it.startsWith(prefix) }` (column-zero match — Kotlin counterpart of `awk '/^prefix/'`) and walks `{` / `}` depth until depth returns to zero. The Kotlin-side mirror of CLAUDE.md §"Scope-level grep gates" → per-function awk brace-walk.

2. **`buildPlatformerGameIR(solidThreshold)`** — fixture builder. Constructs a `GameIR` with:
   - `platformer_physics` `GenericSystem` (configurable `solidThreshold`)
   - `platformer_camera` `GenericSystem` with `HORIZONTAL` + `SMOOTH_FOLLOW` (the visitCamera gate's required conditions 2 + 3)
   - `gameplay` scene with `frameOps = listOf(RawOp("// gameplay-frame-anchor"))` — sentinel keeps the function emitted
   - `startScene = "gameplay"` — third-tier fallback in visitCamera's gameplaySceneId discovery chain resolves to "gameplay"
   - Systems declared in order [physics, camera] — `collectGenreFrameOps` iterates `gameIR.systems` in declaration order, so the accumulator yields `[physics_update; camera_update]` for the gameplay scene

3. **`positive_gameplay_frame_contains_camera_update_after_physics`** — asserts:
   - `frameBody.contains("platformer_camera_update();")` — splice landed
   - `frameBody.contains("platformer_physics_update();")` — visitPhysics splice still fires (regression guard for Plan 12-13)
   - `cameraIdx > physicsIdx` — D-05 emission order lock
   - Evidence written to `gameplay_frame_camera_positive.c` BEFORE any assertion fires

4. **`negative_back_compat_no_camera_call_when_no_tilemap_collision`** — asserts:
   - `frameBody.isNotEmpty()` — scene-frame function still emitted (sentinel keeps it alive)
   - `!frameBody.contains("platformer_camera_update();")` — splice gated OFF
   - Evidence written to `gameplay_frame_camera_negative.c` BEFORE any assertion fires

## Deviations from Plan

None — plan executed exactly as written. The single-task plan structure matched the work exactly: one test file, two test methods, two evidence files, one commit.

The plan's optional alternative ("Visitor-isolation pattern — call `visitCamera(config, gameIR)` directly on a fixture IR and assert `result.frameOps[gameplaySceneId]` contains `RawOp(\"platformer_camera_update();\")`") was NOT taken. Rationale: the plan §objective explicitly mandates per-function awk brace-walk extraction from `bank1.c`, NOT visitor-isolation. The chosen approach matches CLAUDE.md §"Scope-level grep gates" — extracting the body and grepping WITHIN scope — which is what the plan's authority cites. Visitor-isolation would lock the splice at the IR level but would NOT catch a regression where the splice is emitted correctly but `addGenreFrameOps` fails to land it in the right function (e.g. if `addGenreFrameOps`'s `fn.name == "${sceneId}_frame"` check broke). The awk brace-walk approach locks BOTH layers.

## Unblocks

- **Plan 12.3-12** — PlatformerTemplate.kt cleanup. Once the inline `cEmit("platformer_camera_update();")` at PlatformerTemplate.kt:430 is removed, this test stays GREEN because it isolates the VISITOR splice (the user-DSL inline cEmit and the visitor frameOps splice produce textually identical output; removing the inline cEmit leaves the visitor splice as the sole source). The test does NOT depend on the inline cEmit being present.
- **Any future plan modifying PlatformerVisitor.visitCamera** — this test is the binding contract for R3. A regression in:
  - The triple-gate condition (e.g. dropping the `gameUsesTilemapCollision` check) → would leak the splice into the negative fixture → fails the negative assertion
  - The RawOp content (e.g. typo `platformer_camera_update();` → `platformer_camra_update();`) → fails the positive splice-present assertion
  - The gameplaySceneId discovery (e.g. always returning null) → splice goes to no scene → fails the positive splice-present assertion
  - The collectGenreFrameOps iteration order (e.g. processing camera before physics) → swaps the indices → fails the order assertion
  - The addGenreFrameOps prepend semantics (e.g. switching to append) → moves cameraIdx to the END of the body — still satisfies `cameraIdx > physicsIdx` (physics is also at the front of the original-body-prepend list), so this specific test would NOT catch an append-vs-prepend regression on its own. Plan 12.3-15's full back-compat regression sweep is the appropriate guard there.
