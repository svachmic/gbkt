# Phase 12.3 Plan 06: MetaspriteVisitor cameraOffsetX wiring Summary

Wired gap #3 — MetaspriteVisitor.generateMetaspriteFrameSwitch now emits screen-relative metasprite X coordinates when the parent zone uses tilemap-camera mode, threaded via a reflection-based predicate on ScriptOpVisitor that never imports gbkt-genre-platformer (layering invariant locked).

## What Shipped

### MetaspriteVisitor.kt — additive cameraOffsetX parameter

`generateMetaspriteFrameSwitch` accepts a new 5th optional parameter `cameraOffsetX: String? = null` (positional after `rotVar`). Inside the function body, an `xExpr` string is computed once before the StringBuilder switch block:

- `cameraOffsetX == null` (default) → `DEVICE_SPRITE_PX_OFFSET_X + ($posXVar >> 4)` — **byte-identical** to pre-Phase-12.3 emission (D-08 back-compat)
- `cameraOffsetX != null` → `DEVICE_SPRITE_PX_OFFSET_X + (UINT8)(((INT16)($posXVar >> 4)) - (INT16)$cameraOffsetX)` — screen-relative formula

A sibling `yExpr` is extracted in parallel (Y emission unchanged across all paths — no vertical camera in Phase 12). All 4 case branches (case 1 / case 2 / case 3 / default) now reference `$xExpr` and `$yExpr` rather than hardcoded inline strings — substitution is uniform across flip variants (L-6.3).

The leading-whitespace padding in each branch was preserved exactly (46 spaces for `move_metasprite_flipy/flipxy/flipx`, 42 spaces for `move_metasprite_ex`) so the byte-for-byte emission is identical when `cameraOffsetX == null`.

KDoc updated with `@param cameraOffsetX` documenting the contract.

### ScriptOpVisitor.kt — derivePlatformerCameraOffsetX reflection helper

Added a private `derivePlatformerCameraOffsetX(gameIR: GameIR): String?` method on the `ScriptOpVisitor` object that mirrors the canonical `GBDKPipelineV2.gameUsesTilemapCollision` reflection pattern (lines 2031-2082) verbatim plus an additional sibling reflection read on `platformer_camera`'s `cameraConfig`:

- **Step 1 (tilemap-collision detection):** Returns null unless any of these fire:
  - Path A: a `platformer_physics` GenericSystem with non-null `physicsConfig.solidThreshold` via `javaClass.getDeclaredField`
  - Path B: any `zone.platformerPhysicsOverride?.containsKey("solidThreshold")`
  - Path C: an explicit `tilemap_collision` GenericSystem is present
- **Step 2 (platformer-camera detection):** Returns null unless a `platformer_camera` GenericSystem's `cameraConfig` has both `mode.name == "SMOOTH_FOLLOW"` and `scrollDirections.name == "HORIZONTAL"` via reflection on Enum.name

Returns `"_camera_x"` when both steps pass; null otherwise. `visitMoveMetasprite` reads the `gameIRContext` ThreadLocal, invokes the helper, and threads the result as the 5th named arg `cameraOffsetX` to `MetaspriteVisitor.generateMetaspriteFrameSwitch`.

Reflection on opaque `Any` config objects is the only viable access pattern — mirrored verbatim from the existing GBDKPipelineV2 precedent.
