# Phase 12.3 Plan 08: PlatformerVisitor Walk-Cycle Emission Summary

**One-liner:** PlatformerVisitor now auto-emits the 3-frame walk-cycle counter → walkFrameIdx advance inside `buildTilemapPhysicsUpdateFunction` — gated on BOTH `walkFrameIdxVar` AND `threeFrameCounterVar` AssignableVar binders being set in the `platformer_input` GenericSystem config (D-03 skip-when-unset contract). Closes gap #4: `_walkFrameIdx` finally cycles 0→1→2→0 during horizontal motion, unblocking the metasprite render switch and anchor 4 (UAT walk-frame visual).

## Result

**R5 CODEGEN ACCEPTANCE** — when `gameUsesPlatformerInput(gameIR) == true` AND BOTH AssignableVar binders are non-null in the platformer_input GenericSystem config, the emitted `void platformer_physics_update(void)` function body contains a new section 0b emission immediately after Plan 12.3-02's section 0 input wiring and immediately before section 1's sub-pixel position read. The emission shape:

```c
// Phase 12.3 — Walk-cycle (3-frame counter → frame-index advance)
if (<vxSym> != 0) {                                 // CIntLiteral(0) — signed-RHS discipline
    <tfcSym>++;
    if (<tfcSym> >= 6u) {                            // CLiteral(cyclePeriod) — UINT8 RHS
        <tfcSym> = 0u;
        <wfiSym>++;
        if (<wfiSym> >= 3u) {                        // CLiteral(walkFrameCount) — UINT8 RHS
            <wfiSym> = 0u;
        }
    }
} else {
    <wfiSym> = 0u;
    <tfcSym> = 0u;
}
```

Where `<vxSym>` resolves from `tilemap_collision.config["vxVar"]` (e.g. `_playerVx`), `<tfcSym>` = `_${threeFrameCounterVar}` (e.g. `_threeFrameCounter`), and `<wfiSym>` = `_${walkFrameIdxVar}` (e.g. `_walkFrameIdx`) — names come from the AssignableVar binders captured in Plan 12.3-01's builder, NEVER from hardcoded magic strings (D-03 / L-5.4 / feedback_no_magic_strings.md). Acceptance test ships in Plan 12.3-09 (Wave 4).

All 37 existing `:gbkt-genre-platformer` tests stay GREEN — their fixtures do not register a `platformer_input` GenericSystem, so `gameUsesPlatformerInput` returns false and the walk-cycle block is gated OFF (byte-identical emission to the pre-plan baseline).

Emission shape — typed C-AST `CIfStatement` matching the codegen idiom Plan 12.3-02 recorded in commit `1bd800e3`'s body:

```kotlin
CIf(
    condition = CBinaryExpr(CVar(vxSym), "!=", CIntLiteral(0)),  // signed RHS
    thenBody = listOf(
        CExprStatement(CUnaryExpr("++", CVar(tfcSym))),          // tfc++
        CIf(
            condition = CBinaryExpr(CVar(tfcSym), ">=", CLiteral(cyclePeriod)),  // UINT8 RHS — `u` suffix
            thenBody = listOf(
                CExprStatement(CBinaryExpr(CVar(tfcSym), "=", CLiteral(0))),     // tfc = 0u
                CExprStatement(CUnaryExpr("++", CVar(wfiSym))),                  // wfi++
                CIf(
                    condition = CBinaryExpr(CVar(wfiSym), ">=", CLiteral(walkFrameCount)),
                    thenBody = listOf(
                        CExprStatement(CBinaryExpr(CVar(wfiSym), "=", CLiteral(0)))  // wfi = 0u
                    ),
                ),
            ),
        ),
    ),
    elseBody = listOf(
        CExprStatement(CBinaryExpr(CVar(wfiSym), "=", CLiteral(0))),   // wfi = 0u (no motion → reset)
        CExprStatement(CBinaryExpr(CVar(tfcSym), "=", CLiteral(0))),   // tfc = 0u (no motion → reset)
    ),
)
```

Codegen idiom inherited from Plan 12.3-02 (recorded in `1bd800e3` body):
- Typed C-AST `CIf` with `thenBody`/`elseBody` lists for control flow.
- `CBinaryExpr` for assignments (`= value`) and comparisons (`!= 0`, `>= N`).
- `CUnaryExpr("++", CVar(...))` for in-place increments — mirrors the `--_jump_increase_timer` decrement pattern at section 5b lines 878-880 (CUnaryExpr supports prefix `++`/`--`/`!`/`-`/`~` per CExpr.kt L60).
- `CIntLiteral(0)` for the signed `!= 0` RHS — preserves the Phase 07.9 / L-5.1 / L-13.2 discipline that vxSym comparisons MUST use signed-safe literals.
- `CLiteral(N)` for the unsigned counter/index `>=` RHS and the `= 0u` reset assignments — UINT8 context, `u` suffix is correct (Phase 07.9 default for non-signed-comparison sites).
- **NO `CRawExpr`** needed — the walk-cycle body has no cast-heavy expressions. Contrast with Plan 12.3-02's friction branch which DID need `CRawExpr` for `-((INT16)f)` because Kotlin-side typed builders cannot represent the INT16 cast cleanly. The walk-cycle is purely UINT8 increments + signed-zero compare → fully typed-AST representable.

D-05 emission order: this block lives AFTER Plan 12.3-02's section 0 input emission (so `_<vxSym>` reflects this frame's just-set velocity — motion-this-frame produces frame-advance-this-frame, no off-by-one lag) and BEFORE section 1's sub-pixel position read (so the visual frame index is in lock-step with the velocity that drives this frame's integration).
