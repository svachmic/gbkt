# Plan 07.2-01 Summary: Pong & Breakout UAT

## What Was Built

Interactive MCP-driven play-test sessions for Pong and Breakout — the two simplest example games. Established the UAT workflow pattern and caught one visual bug.

## Key Outcomes

### Pong — PASS
- All 11 playbook sections verified: title, gameplay, paddle movement, AI tracking, ball physics, scoring, game over, title loop
- 3 golden screenshots captured
- **Bug found and fixed inline:** paddle1 was asymmetrically positioned (18px from left vs 2px from right). Fixed by changing position(16,64) → position(0,64) with adjusted collision zone [2,8) and scoring threshold <2.

### Breakout — PASS
- All gameplay mechanics verified: brick breaking, scoring (+10/brick), lives system, HUD, both terminal states (gameover at lives=0, win at bricksLeft=0)
- 3 golden screenshots captured
- **Critical bug found and fixed:** `HudVisitor` emitted `SHOW_WIN` without `move_win()` for top-anchored HUDs, causing the window layer to cover the entire screen and hide all BG content (bricks, text). Fixed by adding `effectiveRenderOnWindow()` that auto-selects BG rendering for top-half HUDs. Affects Breakout, Dungeon, and Explorer.

## Inline Fix

**Pong paddle symmetry fix:**
- `PongV2.kt`: position(16,64) → position(0,64), collision [4,20) → [2,8), scoring <4 → <2
- `PongIRTest.kt`: Updated position assertion
- `PLAYBOOK.md` + `CLAUDE.md`: Updated documentation
- All tests pass after fix

## Phase 08 Requirement Added

During UAT, identified opportunity for platform-aware screen constants (QUAL-03). Added to Phase 08 roadmap — `screen.width`, `screen.height`, `screen.bounds` derived from TargetProfile to eliminate magic pixel numbers.
