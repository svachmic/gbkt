Run an interactive MCP play-test session for Pong. This is the first and simplest game — use it to validate the full UAT workflow.

**Pre-session setup:**
```bash
mkdir -p gbkt-examples/pong/src/test/resources/golden
./gradlew :gbkt-mcp-server:shadowJar
```

**Session flow (one conversation, user watches):**

1. **Boot and load context:**
   - `emulator_start(game = "pong")`
   - `emulator_get_playbook()` — read the Pong playbook
   - `emulator_describe_game()` — load metadata (scenes, variables, actors)
   - `emulator_step(frames = 120)` — let game boot to title

2. **Title screen verification:**
   - `emulator_assert` checks: `scene_is: "title"`, `text_on_screen: "PONG"`
   - `emulator_screenshot(label = "pong-title")` — golden screenshot #1
   - `emulator_save_state(label = "title")` — bookmark
   - Report to user: scene name, visible text, sprite count

3. **Title to gameplay transition:**
   - `emulator_press(button = "start")`
   - `emulator_wait_for_scene(scene = "game", maxFrames = 120)`
   - `emulator_assert` checks: `scene_is: "game"`, `variable_equals: p1Score=0`, `variable_equals: p2Score=0`, `actor_visible: "ball"`, `sprite_count: 5`
   - `emulator_save_state(label = "gameplay-start")`
   - `emulator_screenshot(label = "pong-gameplay")` — golden screenshot #2

4. **Gameplay mechanics verification:**
   - Hold UP for 30 frames: `emulator_press(button = "up", frames = 30)` — verify paddle1 moves
   - Hold DOWN for 30 frames: verify paddle1 moves other direction
   - `emulator_step(frames = 120)` — let ball bounce, verify ballDx/ballDy change signs
   - Read `ballDx` and `ballDy` via `emulator_read_variable` — confirm INT8 values (e.g., -1, not 255)
   - Read AI paddle position — verify paddle2.y tracks ball.y

5. **Score and game over:**
   - Use `emulator_write_variable(name = "p1Score", value = 4)` to set score near game-over threshold
   - Advance frames until a point scores: `emulator_step(frames = 600)`
   - Check if `p1Score` reached 5 and triggered gameover scene
   - If not, continue stepping or write variable directly to 5
   - `emulator_wait_for_scene(scene = "gameover", maxFrames = 300)`
   - `emulator_assert`: `scene_is: "gameover"`, `text_on_screen: "GAME OVER"`
   - `emulator_screenshot(label = "pong-gameover")` — golden screenshot #3

6. **Game over to title loop:**
   - `emulator_press(button = "start")` from gameover
   - `emulator_wait_for_scene(scene = "title", maxFrames = 120)`
   - Verify game restarted cleanly

7. **Move golden screenshots:**
   ```bash
   cp build/gbkt/screenshots/pong-title-*.png gbkt-examples/pong/src/test/resources/golden/pong-title.png
   cp build/gbkt/screenshots/pong-gameplay-*.png gbkt-examples/pong/src/test/resources/golden/pong-gameplay.png
   cp build/gbkt/screenshots/pong-gameover-*.png gbkt-examples/pong/src/test/resources/golden/pong-gameover.png
   ```

8. **Write UAT report:** Create `.planning/phases/07.2-interactive-game-uat/UAT-pong.md` with structured sign-off report covering each playbook section, variable assertions, golden screenshot list, bugs found (if any), and user sign-off placeholder.

9. **Bug handling:** If ANY assertion fails or unexpected behavior occurs:
   - Stop play-testing
   - Diagnose the root cause (check generated C, IR, codegen visitors)
   - Fix the framework bug (NOT a game-specific workaround)
   - Add a regression test
   - Atomic commit: `fix(codegen): <description>`
   - Run `./gradlew test` to verify no regressions
   - Resume play-testing from last save state

10. `emulator_stop()` — end session

**Known Pong quirks from RESEARCH.md:**
- Ball clipping at screen edge at high speeds
- AI paddle center-tracking: `paddle2.y + 8` vs `ball.y`
- Score format string has specific spacing: `"P1:%d    P2:%d"` (4 spaces)
- Sprite count in gameplay: 5 (paddle1=2 tiles, paddle2=2 tiles, ball=1)

**Pong variables:** `p1Score` (UINT8), `p2Score` (UINT8), `ballDx` (INT8), `ballDy` (INT8)
**Pong scenes:** `title` -> `game` -> `gameover` -> `title`
