# Phase 5.05: V2 Source Map Implementation - Context

**Gathered:** 2026-02-19
**Status:** Ready for planning

<domain>
## Phase Boundary

The v2 pipeline (GBDKPipelineV2) generates source maps that map generated C lines back to Kotlin DSL source file:line. lcc compilation errors display DSL locations instead of C locations. The existing v1 SourceMapLoader, ErrorEnhancer, and IntelliJ plugin infrastructure are refactored to the new v2 format — no backward compatibility with v1 format needed (no legacy users).

</domain>

<decisions>
## Implementation Decisions

### Mapping Coverage
- Map every generated C line where feasible — not just "interesting" constructs
- Statement-level granularity inside scene lifecycle blocks: each C statement maps to the specific DSL line that produced it (e.g., `player.x += 2` in DSL → the corresponding C assignment line)
- Boilerplate lines with no DSL origin: Claude's discretion on handling

### Source Location Capture
- DSL builders record caller's file:line at construction time via stack trace inspection (Thread.currentThread().stackTrace)
- Every IR node type carries a SourceLocation field (GameIR, SceneIR, ActorIR, SystemIR, ScriptOp, Expr — all of them)
- Compound expressions: Claude's discretion on outermost vs innermost mapping

### Error Presentation
- Show DSL source line alongside lcc errors (Rust-style: `MyGame.kt:42 | player.x += 2`)
- Show both C file location AND Kotlin DSL location per error (two lines: original C + mapped DSL)
- Unmapped errors (boilerplate): show C location + note "(no DSL mapping — generated scaffolding)"
- Group related errors by DSL line — if multiple C errors trace to the same DSL line, show once with all errors listed underneath

### Multi-File Map Strategy
- One .gbkt.map per C file (industry standard: matches Kotlin/JS and transpiler conventions)
- main.c → main.c.gbkt.map, bank1.c → bank1.c.gbkt.map
- Keep .gbkt.map extension (avoids conflicts with GBDK's own .map debug files)
- Use improved v2 JSON format with additional fields (IR node type, bank number); update all parsers — no v1 format support needed
- game.h source map: Claude's discretion

### IntelliJ Plugin Integration
- Combined view for multi-file output — merge all generated C files into one scrollable preview with source map navigation across all files
- Bidirectional navigation: click DSL → highlights C, click C → navigates to DSL
- Auto-refresh via file watcher when .gbkt.map files change after generateC runs
- No v1/v2 distinction — refactor everything to new v2 format only

### Claude's Discretion
- Boilerplate line handling in source map (map to game{} block vs leave unmapped)
- Symbol name and DSL snippet population strategy
- Compound expression mapping direction (outermost vs innermost)
- Whether game.h gets its own source map

</decisions>

<specifics>
## Specific Ideas

- Error output should feel like Rust's compiler — show the DSL source line with the error context
- Follow Kotlin/JS source map conventions (one map per output file)
- No backward compatibility constraints — this is a greenfield refactor of all source map infrastructure to v2 format

</specifics>
