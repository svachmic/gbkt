## Decisions Made

- Regex-based JSON parsing in `GbktCodegenService` instead of `org.json` — the Gradle plugin has `org.json` on its classpath but the IntelliJ plugin does not; the v2 format is simple enough for reliable regex extraction without external dependencies
- `ErrorEnhancer.enhanceErrors()` (single-map) now delegates to `enhanceErrorsMultiFile()` with a single-entry map — zero breaking changes to existing callers, no duplication of logic
- Legacy `parseSourceMapLine()` and all colon-format parsing removed from `GbktCodegenService` per locked decision ("No v1/v2 distinction — refactor everything to new v2 format only")
- `fileLineOffsets` maps cFile to the 1-based first content line within the combined document — `scrollToMatchingCLine` converts `fileOffset + cLine - 2` to 0-based editor position
