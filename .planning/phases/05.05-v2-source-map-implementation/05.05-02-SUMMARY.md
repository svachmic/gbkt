# Phase 5.05 Plan 02: Pipeline Plumbing — CEmitter Line Tracking + .gbkt.map File Writing Summary

**Line-tracking CEmitter with SourceMapCollector integration, PipelineV2Output carrying per-file v2 JSON source maps, and executeV2Path writing .gbkt.map files for all three example games**

## Performance

- **Duration:** 5 min
- **Started:** 2026-02-19T20:55:49Z
- **Completed:** 2026-02-19T21:00:00Z
- **Tasks:** 2
- **Files modified:** 8 (7 modified + 1 test updated for API change)

## Accomplishments

- Added `LineTrackingBuilder` private class to `CEmitter` that wraps `StringBuilder` with a line counter, enabling `CEmitter.emit(file, collector)` to record (cLine, sourceLocation, irNodeType) per statement without threading state through every emit method
- Changed `GBDKPipelineV2.generate()` from returning `Map<String, String>` to returning `PipelineV2Output(files, sourceMaps)` with v2 JSON source maps (version "2.0", bankNumber, irNodeType) per non-header C file
- Updated `GeneratedFile` with `sourceMapJson` field and `GenerationResultWrapper.getSourceMapJsonForFile()` via reflection with v1 backward-compat; `executeV2Path` now writes `.gbkt.map` files and the WARNING about missing source maps is removed
- All three example games (Pong, Breakout, Explorer) produce `main.c.gbkt.map` and `bank1.c.gbkt.map` with non-empty mappings (pong: 51 mappings in bank1.c, breakout: 68, explorer: 50)

## Files Created/Modified

- `gbkt-backend-gbdk/.../codegen/emit/CEmitter.kt` - Added `LineTrackingBuilder` private class + optional `collector` param on `emit()`; `emitStatement()` calls `ltb.recordMapping()` before each statement
- `gbkt-backend-gbdk/.../codegen/pipeline/GBDKPipelineV2.kt` - Added `PipelineV2Output` data class; `generate()` now returns `PipelineV2Output` with both C content and source map JSON per non-header file; added `buildSourceMapJson()` helper
- `gbkt-backend-gbdk/.../GBDKBackend.kt` - `generateV2()` uses `output.files` and `output.sourceMaps` to populate `GeneratedFile.sourceMapJson`
- `gbkt-backend-api/.../GenerationResult.kt` - `GeneratedFile` gains `sourceMapJson: String? = null` field
- `gbkt-core/.../SourceMap.kt` - `SourceMap` gains `bankNumber: Int? = null`; `SourceMapping` gains `irNodeType: String? = null`; `toJson()` emits both when present; `SourceMapBuilder` gains `version` and `bankNumber` constructor params
- `gbkt-gradle-plugin/.../BackendReflection.kt` - `GenerationResultWrapper.getSourceMapJsonForFile()` extracts per-file source map JSON via reflection with `NoSuchMethodException` backward-compat
- `gbkt-gradle-plugin/.../GenerateCTask.kt` - `executeV2Path()` writes `$filename.gbkt.map` for each file with non-null source map JSON; removed two WARNING lines about source maps not available
- `gbkt-backend-gbdk/.../PongPipelineTest.kt` - Updated `output` to use `pipelineOutput.files`; added Test 18 (source maps for main.c and bank1.c) and Test 19 (version 2.0 format)

## Decisions Made

- `LineTrackingBuilder` is a private inner class within `CEmitter` — no mutable state on the `CEmitter object`; all state created per `emit()` call per the architectural constraint documented in the plan
- Header files (game.h) excluded from source map output — they contain only extern declarations and forward prototypes, not DSL-originated `CStatement` nodes; `buildHeaderFile()` result goes through `CEmitter.emit(cFile)` without a collector
- `SourceMapBuilder` constructor extended with `version` and `bankNumber` defaulting to "1.0" and null — fully backward-compatible with existing v1 call sites in `SourceMapBuilder.build()`
