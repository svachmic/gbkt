# Phase 06.2 Plan 04: HUD Codegen Summary

**HUD system codegen with change-detection rendering, fill bars (fillTile/emptyTile), numeric displays, icon counters, anchor positioning, background-layer rendering path, and 20-test HudCodegenTest**

## Performance

- **Duration:** 15 min
- **Completed:** 2026-02-22
- **Tasks:** 2
- **Files modified:** 3 (2 source files + 1 new test file)

## Accomplishments
- `buildHudFunctions()` generates `update_hud_<id>()`, `show_hud_<id>()`, `hide_hud_<id>()` for all HUD panels
- Change detection via `_hud_<id>_<elem>_prev` globals (0xFF sentinel = force first-frame full redraw)
- HudBar: CFor loop 0..width with `set_win_tiles`/`set_bkg_tiles` using `fillTile`/`emptyTile` from IR fields
- HudNumber: label via `_win_print_at` + 3-digit decimal via `_hud_print_u8` digit-extraction helper
- HudIcons: CFor loop 0..maxValue with FULL_AND_EMPTY (full icon + empty icon) or FILLED_ONLY (full + space tile) modes
- Anchor positioning: resolves all 9 anchor values plus tileX/tileY override to tile coordinates
- `addHudUpdateCalls()` prepends `update_hud_<id>()` calls to scene frame functions (mirrors movement/animation injection)
- Background layer path: `renderOnWindow=false` uses `set_bkg_tiles`/`_bkg_print_at`/`_bkg_clear_region`; no SHOW_WIN/HIDE_WIN
- `GBDKSystemVisitor.visitDialogSystem()` updated with extended config documentation; `_dialog_default_speed`/`_dialog_default_border` globals generated via `buildSystemGlobalVars`
- HudCodegenTest: 20 unit tests covering all element types, change detection, anchors, window/background layer selection

## Decisions Made
- HUD tile index constants stored as `const UINT8` globals: `_hud_fill_tile_<id>`, `_hud_empty_tile_<id>`, `_hud_full_icon_<id>`, `_hud_empty_icon_<id>` — C89 requires lvalue for the address-of operator used in `set_win_tiles` calls
- `_bkg_print_at`/`_bkg_clear_region` helpers generated only when `gameIR.huds.any { !it.renderOnWindow }` — avoids dead code for window-only games
- `_hud_space_tile` (value 0) generated only when FILLED_ONLY icon mode is used — avoids 1-byte constant overhead
- `_dialog_default_speed`/`_dialog_default_border` emitted via `buildSystemGlobalVars` (not visitor return) — consistent with CameraSystem/ExplorationSystem pattern where system globals are separate from system functions

## Deviations from Plan

None — plan executed exactly as written.

## Issues Encountered
- **Cross-module smart cast for `HudBar.maxVariable`**: Captured into local `val barMaxVariable: String?` before use in `CVar()` constructor — required because Kotlin cannot smart-cast public API properties from different modules (standard project pattern per multiple STATE.md decisions)
- **Test 18 (HUD update call injection)**: Initial test used `frameOps = listOf()` (empty), which doesn't generate a frame function. Fixed to use `frameOps = listOf(NavigateTo("gameplay"))` so the scene frame function exists for injection to apply.
