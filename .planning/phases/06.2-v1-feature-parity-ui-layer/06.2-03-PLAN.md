  <name>Task 1: Rewrite menu codegen with layout-aware cursor, parent/child stack, SFX hooks, and settings controls</name>
  <files>
    gbkt-backend-gbdk/src/main/kotlin/io/github/gbkt/backend/gbdk/codegen/pipeline/GBDKPipelineV2.kt

  <action>
  **Use Serena MCP tools** for code exploration and editing.

  **Replace `buildMenuHelpers(gameIR)` and `buildMenuFunction(menu: ShowMenu)`** with:

  **`buildMenuFunctions(gameIR: GameIR): List<CFunction>`** — iterates `gameIR.menus` and generates per-menu C functions using `MenuDef` IR (not the old `ShowMenu` ScriptOp).

  For each `MenuDef`, generate `show_menu_<id>()` function:

  **1. Initialization:**
  - C89 local vars first: `CVarDecl("sel", CU8, CLiteral(0))`, `CVarDecl("joy", CU8, CLiteral(0))`
  - For GRID layout, add `CVarDecl("col", CU8, CLiteral(0))`, `CVarDecl("row", CU8, CLiteral(0))`
  - Position window: `CCall("move_win", [CLiteral(7), CLiteral(menuDef.y * 8)])` when renderOnWindow=true
  - Show window: `CRawCode("SHOW_WIN;")` when renderOnWindow=true
  - Draw menu items using `_win_print_at` for window layer. For background layer (renderOnWindow=false), use `gotoxy()/printf()` — this is the only acceptable case for gotoxy.

  **2. Layout-aware item rendering:**
  - **VERTICAL**: Items stacked vertically, one per row. Cursor at column 0 of selected row.
  - **HORIZONTAL**: Items side by side in a single row. Cursor tracks current column.
  - **GRID**: Items arranged in `columns` columns. Cursor tracks both row and column. Position = row * columns + col.

  **3. Input loop (CWhile with CLiteral(1)):**
  - Draw cursor at current selection position via `_win_print_at` (window) or `gotoxy/printf` (background)
  - `wait_vbl_done()` per frame
  - Read joypad

  Layout-dependent navigation:
  - **VERTICAL**: J_UP decrements sel (bounds check), J_DOWN increments sel
  - **HORIZONTAL**: J_LEFT decrements sel, J_RIGHT increments sel
  - **GRID**: J_UP/J_DOWN navigates rows (sel -= columns / sel += columns), J_LEFT/J_RIGHT navigates columns (sel -= 1 / sel += 1) with wrapping within row

  - **J_A**: Select — store selection, break from loop. If SFX `sfxOnSelect` configured, emit `CCall("play_sfx_<sfxOnSelect>", [])` before break.
  - **J_B**: Cancel — if `parentId != null`, emit `CRawCode("HIDE_WIN;")` then `CCall("show_menu_<parentId>", [])` then `CReturn`. If no parent, optionally break with cancel value (0xFF). If SFX `sfxOnCancel` configured, emit sound call.
  - **Movement SFX**: If `sfxOnMove` configured, emit sound call when cursor moves.

  **4. Cursor rendering (two modes — text cursor AND sprite cursor, both fully implemented):**

  **Text cursor** (when `cursorSprite == null`, default):
  - Erase old cursor: write space tile at old cursor position via `_win_print_at(oldCursorX, oldCursorY, " ", 1)` (window layer) or `gotoxy(oldCursorX, oldCursorY); printf(" ")` (background layer)
  - Draw new cursor: write `cursorChar` at new cursor position via `_win_print_at(cursorX, cursorY, cursorChar, 1)` (window) or `gotoxy/printf` (background)

  **Sprite cursor** (when `cursorSprite != null`):
  - On menu open: load the cursor sprite tile into a dedicated sprite slot. Use `set_sprite_tile(MENU_CURSOR_SPRITE_ID, cursorSprite_tile)` where `MENU_CURSOR_SPRITE_ID` is a reserved sprite slot (e.g., sprite slot 38, distinct from the portrait sprite slot 39). Generate a `#define MENU_CURSOR_SPRITE_ID 38` in the output.
  - Position sprite at the current selection: `move_sprite(MENU_CURSOR_SPRITE_ID, cursorPixelX, cursorPixelY)` where `cursorPixelX = (menuDef.x + textStartX) * 8 + 8` and `cursorPixelY = (menuDef.y + sel * rowHeight) * 8 + 16` (the +8/+16 are OAM offsets required by GBDK sprite positioning).
  - On cursor move (J_UP/J_DOWN/J_LEFT/J_RIGHT): recalculate pixel position and call `move_sprite(MENU_CURSOR_SPRITE_ID, newPixelX, newPixelY)` to reposition the sprite. No need to erase old position — sprites are hardware-managed.
  - On menu close: hide the sprite cursor by moving it off-screen: `move_sprite(MENU_CURSOR_SPRITE_ID, 0, 0)`.
  - For GRID layout: pixel position accounts for both row and column: `cursorPixelX = (menuDef.x + col * columnWidth) * 8 + 8`, `cursorPixelY = (menuDef.y + row * rowHeight) * 8 + 16`.
  - For HORIZONTAL layout: `cursorPixelX = (menuDef.x + sel * itemWidth) * 8 + 8`, `cursorPixelY = menuDef.y * 8 + 16`.
  - Do NOT write any tile data for the cursor position when using sprite cursor — the sprite overlay handles it.

  **5. Settings controls:**
  - **Toggle items**: On A-press, toggle the bound variable (XOR with 1), redraw item label with [ON]/[OFF] suffix
  - **Slider items**: On LEFT/RIGHT, decrement/increment variable (clamped to min/max by step), redraw value
  - **Option items**: On LEFT/RIGHT, cycle through choices, update variable and redraw

  For settings controls, generate inline CIf branches within the A-button handler checking which item is selected.

  **6. Scroll behavior:**
  - **AUTO_SCROLL**: If total items > visible height, scroll offset tracks current selection. Show scroll indicator (arrow tiles) at top/bottom.
  - **PAGE_BASED**: Selection wraps within page. Page flips on boundary crossing. All items on page redrawn.
  - Both scroll modes use a `CVarDecl("scroll_offset", CU8, CLiteral(0))` and adjust item rendering Y coordinates.

  **7. Dynamic data binding (itemsFrom):**
  If `menuDef.dataSource` is non-null, generate dynamic population logic instead of static item labels:
  - For `InventoryDataSource(inventoryId)`: Generate a CFor loop iterating `_inventory_<id>_slots` array. For each non-empty slot, render the item name from a lookup table. The menu item count equals the number of occupied slots (tracked via `_inventory_<id>_count`). Selection maps to inventory slot index.
  - For `ArrayDataSource(arrayId)`: Generate a CFor loop iterating the array. Each element value maps to a label via a generated string table. Selection maps to array index.
  - Dynamic menus still support all layout modes (VERTICAL, HORIZONTAL, GRID) — the rendering loop is layout-aware.
  - When `dataSource` is set, `items` from the static MenuItemDef list serve as fallback/template items only (e.g., a "Cancel" option at the end).

  **8. Return value:**
  - Function returns UINT8 (selected index) via `CReturn(selVar)`
  - Store in global `_menu_result` for ScriptOpVisitor dispatch

  **Wire into pipeline**: In `buildHomeFile()`, replace the old `buildMenuHelpers(gameIR)` call with `buildMenuFunctions(gameIR)`.

  Also remove `collectUniqueMenus()` helper since we no longer scan ScriptOps for ShowMenu — we use `gameIR.menus` directly.
