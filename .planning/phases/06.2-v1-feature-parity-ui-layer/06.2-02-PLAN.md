  **Replace `buildDialogHelpers()`** with a new `buildDialogFunctions(gameIR: GameIR): List<CFunction>` method that iterates over `gameIR.dialogs` and generates per-dialog C functions.

  For each `DialogDef`, generate:

  **`show_dialog_<id>()` function** (HOME bank):
  1. Position window: `CCall("move_win", [CLiteral(7), CLiteral(def.boxY * 8)])` — 7px left offset is GBDK hardware convention
  2. Show window: `CRawCode("SHOW_WIN;")` — approved CRawCode exception (GBDK hardware macro)
  3. **Border drawing** (before any text rendering):
     - **NONE**: Skip border drawing entirely — text uses the full box area.
     - **SINGLE**: Draw single-line border tiles around the dialog box using `set_win_tiles`. Tiles: top-left corner (0xDA), top-right (0xBF), bottom-left (0xC0), bottom-right (0xD9), horizontal (0xC4), vertical (0xB3) — standard GBDK font code page 437 box-drawing characters. Use CFor loop for horizontal edges (top row, bottom row) and vertical edges (left column, right column). Inset the text area by 1 tile on each side.
     - **DOUBLE**: Same pattern with double-line tile variants: TL (0xC9), TR (0xBB), BL (0xC8), BR (0xBC), H (0xCD), V (0xBA).
     - **CUSTOM**: Read 8 tile indices from `dialogDef.customBorderTiles` (TL, TR, BL, BR, H-top, H-bottom, V-left, V-right) and use `set_win_tiles` with those indices. If `customBorderTiles` is null, fall back to SINGLE border tiles.
     - After border drawing, compute the text area inset: textStartX = (border == NONE ? 0 : 1), textStartY = (border == NONE ? 0 : 1), textWidth = boxWidth - (border == NONE ? 0 : 2), textHeight = boxHeight - (border == NONE ? 0 : 2).
  4. **Portrait sprite rendering** (when `portrait != null`):
     - Use `set_sprite_tile(PORTRAIT_SPRITE_ID, portrait_tile)` to load the portrait tile into a dedicated sprite slot (e.g., sprite slot 39, which is reserved for UI use).
     - Position the portrait at the dialog box corner: `move_sprite(PORTRAIT_SPRITE_ID, (boxX + textStartX) * 8 + 8, (boxY + textStartY) * 8 + 16)` — the +8/+16 are OAM offsets required by GBDK sprite positioning.
     - Offset textStartX by the portrait width in tiles (typically 2 tiles = 16px) so text doesn't overlap the portrait: `textStartX += 2; textWidth -= 2`.
     - On dialog dismiss (step 8), hide the portrait sprite: `move_sprite(PORTRAIT_SPRITE_ID, 0, 0)`.
  5. If `speaker != null`: write speaker name as first line of the text area via `_win_print_at(textStartX, textStartY, speaker, speakerLen)`, then increment textStartY by 1 to leave room for the name line. Decrement textHeight by 1.
  6. **Typewriter effect with auto-pagination**: Generate the typewriter rendering with automatic page breaks for long text.
     - Outer pagination loop (`CWhile`): Tracks `_dialog_page_offset` — the character index into the full message where the current page starts. Loop continues while `_dialog_page_offset < msg_len`.
     - Clear the text area at the start of each page (except the first): `_win_clear_region(textStartX, textStartY, textWidth, textHeight)`.
     - Inner typewriter loop (`CFor i = 0; i < textWidth * textHeight && (_dialog_page_offset + i) < msg_len; i++`): Places characters one at a time at `set_win_tiles(textStartX + (i % textWidth), textStartY + (i / textWidth), 1, 1, &msg[_dialog_page_offset + i])`. Insert `delay_frames(textSpeed)` between characters for the typewriter speed.
     - After the inner loop completes (page filled or message ends), advance `_dialog_page_offset += textWidth * textHeight`.
     - **A-button wait after each page**: Two CWhile loops — first waits for A press `CWhile(CRawExpr("!(joypad() & J_A)"), [wait_vbl_done()])`, second waits for A release `CWhile(CBinaryExpr(CCall("joypad"), "&", CVar("J_A")), [wait_vbl_done()])`.
     - The pagination loop naturally terminates when all text has been displayed and the player presses A on the last page.
     - This handles explicit page breaks (separate `say()` calls) automatically — each `say()` generates its own `show_dialog_<id>()` call.
  7. **FontMode rendering path**: The typewriter inner loop and text helpers use the dialog's fontMode to select the rendering function:
     - **FIXED_WIDTH**: Use `_win_print_at(x, y, str, len)` — one character per tile, standard tile-based rendering.
     - **VARIABLE_WIDTH**: Use `_vwf_print_at(x, y, str, len)` — VWF helper that renders characters at pixel precision within tiles (see VWF helper generation below).
  8. Hide window: `CRawCode("HIDE_WIN;")` — approved CRawCode exception. If portrait was shown, hide it: `move_sprite(PORTRAIT_SPRITE_ID, 0, 0)`.

  For `DialogSay` with variable interpolation (mixed segments):
  - Generate helper that writes each segment: string literals directly, Expr segments via value-to-string conversion (use `printf`-style formatting on window layer). For simplicity, use a `_win_print_at(x, y, str)` helper wrapper or `set_win_tiles` with a character buffer.
  - IMPORTANT: Do NOT use `gotoxy()`/`printf()` for dialog text rendering — these write to the background tile layer. All text goes through window layer functions.

  For `DialogChoice`:

  **Also generate a `_win_print_at(x, y, str, len)` helper function** in HOME bank that writes a string to the window layer tile-by-tile using `set_win_tiles`. This helper replaces `gotoxy()/printf()` for all window-layer text output. Pattern:
  ```c
  void _win_print_at(UINT8 x, UINT8 y, const char* str, UINT8 len) {
      UINT8 i;
      for (i = 0; i < len; i++) {
          set_win_tiles(x + i, y, 1, 1, (unsigned char*)&str[i]);
      }
  }
  ```

  **Generate `_vwf_print_at(x, y, str, len)` helper function** (HOME bank) for variable-width font rendering. VWF on Game Boy works by:
  - Maintaining a `pixel_x` position (sub-tile precision, 0-7 within the current tile).
  - For each character in `str`: look up the character's width from a `_vwf_char_widths[]` const array (each entry is the pixel width of that ASCII character, typically 3-8 pixels). Draw the character bitmap shifted right by `pixel_x % 8` bits into the current tile. If the shifted bitmap overflows into the next tile, write the overflow into that adjacent tile using OR-based composition. Advance `pixel_x += char_width`. When `pixel_x >= (x_start + available_width) * 8`, stop (line overflow).
  - The composed tiles are written to window VRAM via `set_win_tiles`. This requires a small tile buffer (e.g., `_vwf_tile_buf[20]` — one row of tiles) that accumulates the composed pixel data before flushing.
  - The `_vwf_char_widths[]` array defaults to a built-in proportional width table for GBDK's standard font (e.g., 'W'=6, 'i'=2, 'm'=6, space=3). Users can override via a custom font asset.
  - Pattern for the helper:
  ```c
  void _vwf_print_at(UINT8 x, UINT8 y, const char* str, UINT8 len) {
      UINT8 i, px = 0, tile_x = x;
      UINT8 tile_buf[8] = {0,0,0,0,0,0,0,0};
      for (i = 0; i < len; i++) {
          UINT8 ch = str[i];
          UINT8 w = _vwf_char_widths[ch];
          // shift character bitmap by (px % 8) and OR into tile_buf
          // when px crosses tile boundary, flush tile_buf to set_win_tiles and advance tile_x
          px += w;
      }
      // flush remaining tile_buf
      set_win_tiles(tile_x, y, 1, 1, tile_buf);
  }
  ```
  - The `FontMode` field on `DialogDef` and text ScriptOps (PrintAt, PrintCentered, PrintAligned) determines which helper is called: `FIXED_WIDTH` -> `_win_print_at`, `VARIABLE_WIDTH` -> `_vwf_print_at`.

  **Generate `_win_clear_region(x, y, w, h)` helper** for clearing window regions.

  **Generate `_screen_fill(tile)` helper** for filling the entire screen (20x18 tiles) with a given tile index using nested CFor loops and `set_win_tiles`. This is used by the `ScreenFill` ScriptOp (the DSL's `screen.fill(tile)`).
