# Phase 06.2: V1 Feature Parity Port — UI Layer - Context

**Gathered:** 2026-02-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Port V1 UI subsystems to V2 pipeline: dialog boxes with text rendering, choice menus, status bars, HUD elements, and screen text helpers. Full V2 DSL style with typed builders, new IR nodes, and typed C AST codegen. Old V1 IR nodes (ShowDialog, ShowMenu) are replaced entirely — clean break, no deprecated wrappers.

</domain>

<decisions>
## Implementation Decisions

### Dialog DSL Design
- Both dialog patterns: quick inline `say("text")` for one-liners AND named `dialog("elder") { ... }` builder for RPG/adventure use
- Configurable text speed per dialog (`textSpeed` property) — different NPCs can talk at different speeds
- Variable interpolation via vararg mixing: `say("That'll be ", price, " gold.")` — type-safe, preserves Expr boundary
- Dialog choices use lambda-per-option pattern (no index matching): `elder.choice { option("Accept") { scene(quest) }; option("Decline") { scene(village) } }`
- Choice option labels must be i18n-aware — candidates for PO file localization, no magic strings
- Auto-paginate long text by default, but also allow explicit page breaks via separate `say()` calls
- Speaker name display AND optional portrait sprite reference in dialog box
- All four border styles ported: NONE, SINGLE, DOUBLE, CUSTOM
- A button only for dialog dismiss — no auto-timer (player must press A to advance after typewriter completes)

### Menu / Choice System
- All three layouts ported: VERTICAL, HORIZONTAL, GRID
- Settings menu controls in scope: toggle, slider, option — full parity
- Full parent/child submenu stack — `parent = mainMenu` for auto-back on B, `open(childMenu)` pushes, `close()` pops
- Menu rendering layer configurable per menu — window layer default, background layer option
- Grid menus support dynamic data binding via `itemsFrom(inventory)` — auto-populates from data source
- Cursor supports both text character (`cursor = ">"`) and optional sprite cursor (animated hand/arrow)
- Scroll behavior configurable: auto-scroll with indicator (default) OR page-based — developer chooses
- Optional SFX hooks per menu: onMove, onSelect, onCancel sound configuration
- Generic enough that BattleMenu (phase 06.5) will be a configuration of this menu system, not a separate system

### Status Bar / HUD
- Full HUD toolkit: fill bars, numeric displays ("HP: 45/100"), and icon-based counters (hearts, stars)
- Positioning supports both: anchor shortcuts (Anchor.TOP_LEFT, Anchor.BOTTOM) for common placements AND tile coords for precise control
- On-change update strategy — HUD redraws only when bound value changes, not every frame
- Rendering layer configurable — window layer default, background layer option
- HUD panel groups: `hud("stats") { bar("hp"); number("score"); icons("lives") }` — show/hide as a unit
- Animated bar fill — smooth decrease/increase over configurable number of frames
- Icon counters configurable: full+empty icons (Zelda-style) OR filled-only — developer decides
- Bar colors: pattern-based fill tiles (DMG compatible) + optional GBC palette enhancement
- Numeric displays with label+value formatting: `number("score") { label("Score: "); value(score); format("%04d") }`

### Text Rendering & Screen Operations
- Both variable-width and fixed-width font support (fixed-width tile-based default, optional VWF for GBC)
- Full text helper set: printAt(x,y), printCentered, printAligned(RIGHT), etc.
- Screen operations included: clear(), fill(tile), clearRegion(x,y,w,h) as part of UI toolkit

### V1 Parity Strategy
- New dialog IR node hierarchy (DialogShow, DialogSay, DialogChoice) — replaces old ShowDialog entirely
- New menu IR nodes matching V2 DSL — old ShowMenu replaced entirely
- Complete text rendering codegen rewrite from scratch — typed C AST, no legacy string emission
- Clean break from V1 — old DSL functions removed, no deprecated wrappers, forces migration

### Claude's Discretion
- Exact IR node structure for dialog/menu/HUD hierarchies
- C AST patterns for window-layer rendering
- Text rendering implementation details (typewriter state machine, VWF algorithm)
- Internal HUD change-detection mechanism
- Bar animation frame timing

</decisions>

<specifics>
## Specific Ideas

- Dialog choice pattern should feel like Compose-style lambdas: `option("Accept") { scene(quest) }` — clean, no index matching
- Menu system should be generic enough to serve as foundation for BattleMenu in phase 06.5 (RPG commands are just menu items with battle-specific callbacks)
- HUD panel grouping enables show/hide of entire stat displays as a unit (e.g., hide battle HUD when returning to exploration)
- Icon counter display mode (full+empty vs filled-only) should be a per-counter configuration

</specifics>
