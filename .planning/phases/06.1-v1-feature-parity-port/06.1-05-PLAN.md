    1. In GBDKSystemVisitor.kt, implement `visitPathfindingSystem(system)`:
       Generate A* infrastructure as C functions with typed C AST. This is the most complex codegen in Phase 06.1.

       Generate data structures:
       - `_pf_open[maxOpenNodes * 4]` (UINT8 array: each node = x, y, g_cost, f_cost — 4 bytes per node)
       - `_pf_open_count` (UINT8) — current open list size
       - `_pf_closed[mapSize / 8 + 1]` (UINT8 array) — bit-packed closed set (1 bit per tile)
       - `_pf_path_x[maxPathLength]`, `_pf_path_y[maxPathLength]` (UINT8 arrays) — result path
       - `_pf_path_length` (UINT8) — result path length

       Generate helper functions:
       a. `pf_is_closed(x, y)` — check bit in closed set: `return _pf_closed[(y * mapWidth + x) >> 3] & (1 << ((y * mapWidth + x) & 7))`
       b. `pf_set_closed(x, y)` — set bit: `_pf_closed[(y * mapWidth + x) >> 3] |= (1 << ((y * mapWidth + x) & 7))`
       c. `pf_find_path(startX, startY, endX, endY)` — iterative A* using typed C AST:
          - Initialize: clear closed set, add start to open list
          - While loop (not recursive — critical for Game Boy stack): CWhile(CBinaryExpr(CVar("_pf_open_count"), ">", CLiteral(0)))
          - Find lowest f_cost in open list (linear scan — OK for small lists)
          - Check if at target → reconstruct path
          - Expand 4 neighbors (UP, DOWN, LEFT, RIGHT), check walkability via collision data
          - Add valid neighbors to open list
          - Use Manhattan distance heuristic: `abs(nx - endX) + abs(ny - endY)`
       d. `pf_step_toward(actorIdx)` — read next waypoint from path, move actor one step

       WRAM budget: For default 32x32 map (mapWidth=32, mapHeight=32): open list = 32*4 = 128 bytes, closed set = mapWidth*mapHeight/8 = 128 bytes, path = 32*2 = 64 bytes. Total ~320 bytes. Acceptable. Closed set size is computed from `mapWidth * mapHeight / 8 + 1`.

       Use typed CFor, CWhile, CIf, CBinaryExpr throughout. CRawExpr acceptable only for bit manipulation expressions if they are complex. The A* loop body will be large — this is expected and documented in detekt.yml exclusions for codegen.

       **Scene collision integration:** The A* walkability check needs access to the current scene's collision function. GBDKPipelineV2 already generates a `_map_collision_{sceneId}(x, y)` function for each scene with collision data. The pathfinder should use a global function pointer `_pf_collision_fn` (set during scene enter) so A* can call the correct collision function for the current scene. Generate:
       - `UINT8 (*_pf_collision_fn)(UINT8 x, UINT8 y) = 0;` — global function pointer
       - In each scene enter that uses pathfinding: `_pf_collision_fn = &_map_collision_{sceneId};`
       - In `pf_find_path` neighbor expansion: `if (_pf_collision_fn && _pf_collision_fn(nx, ny)) continue;` — skip impassable tiles

    2. In ScriptOpVisitor.kt:
