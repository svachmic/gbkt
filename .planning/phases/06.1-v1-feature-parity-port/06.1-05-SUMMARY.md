# Phase 06.1 Plan 05: NPC Pathfinding System Summary

**One-liner:** Grid-based iterative A* pathfinding with bit-packed closed set, waypoint patrol routes, and `pf_find_path`/`pf_step_toward` codegen for GBDK NPC navigation.

## What Was Built

### Task 1: PathfindingSystem IR, waypoint/follow on ActorIR, and DSL builders (57c6d93)

Added complete IR layer for NPC pathfinding:

**New IR types:**
- `PathfindingSystem` — new `SystemIR` subtype with `gridSize`, `mapWidth`, `mapHeight`, `maxOpenNodes`, `maxPathLength` config fields. Dispatches via `accept(visitor)` to `visitPathfindingSystem`.
- `WaypointRoute` — data class in `CoreTypes.kt` with `points: List<Pair<Int, Int>>` and `loop: Boolean`.
- `PathfindStep` — new `ScriptOp` with `npcActorId` and `targetActorId`, emits one-step A* pathfinding.
- `WaypointStep` — new `ScriptOp` with `npcActorId`, emits one-step waypoint patrol advancement.

**ActorIR extensions:**
- `waypointRoute: WaypointRoute? = null` — NPC patrol route definition
- `followTargetId: String? = null` — actor ID to chase (for A* follow behavior)

**Visitor interface extensions:**
- `SystemIRVisitorI.visitPathfindingSystem(system: PathfindingSystem): T`
- `ScriptOpVisitorI.visitPathfindStep(op: PathfindStep): T`
- `ScriptOpVisitorI.visitWaypointStep(op: WaypointStep): T`

**DSL builders:**
- `PathfindingBuilder` with `gridSize()`, `mapSize()`, `maxOpenNodes()`, `maxPathLength()` methods
- `GameBuilder.pathfinding()` method registers PathfindingSystem
- `ActorBuilder.waypoints(loop, block)` with `WaypointBuilder` (adds `point(x, y)`)
- `ActorBuilder.followTarget(actor: ActorRef)` sets follow target ID
- `ScriptBuilder.pathfindStep(npc, target)` and `waypointStep(npc)` methods

**Tests updated:** `IRHierarchyTest.kt` — `ScriptOpDescriber` and `SystemDescriber` have `visitPathfindStep`, `visitWaypointStep`, `visitPathfindingSystem` implementations.

### Task 2: Pathfinding codegen (iterative A*) + waypoint codegen + unit tests (75f9d36)

**`GBDKSystemVisitor.visitPathfindingSystem`** generates 4 functions:

1. `pf_is_closed(x, y)` — bit-test the closed set:
   ```c
   UINT8 idx = y * mapWidth + x;
   return _pf_closed[idx >> 3] & (1 << (idx & 7));
   ```

2. `pf_set_closed(x, y)` — bit-set the closed set:
   ```c
   UINT8 idx = y * mapWidth + x;
   _pf_closed[idx >> 3] |= (1 << (idx & 7));
   ```

3. `pf_find_path(startX, startY, endX, endY)` — iterative A* with `CWhile`:
   - Clears closed set and path on entry
   - Adds start node to open list
   - `while (_pf_open_count > 0)`: finds lowest f_cost, extracts best node, expands 4 neighbors (UP/DOWN/LEFT/RIGHT), checks closed set and collision, adds valid neighbors
   - Records first step direction in `_pf_path_x[0]`, `_pf_path_y[0]`
   - Uses Manhattan distance heuristic

4. `pf_step_toward(npc_x, npc_y)` — moves NPC one tile toward `_pf_path_x[0]`:
   - If `_pf_path_length == 0`: return early
   - Increments/decrements npc_x or npc_y by 1 toward target tile

**`GBDKSystemVisitor.buildPathfindingGlobals`** — companion object function generating global arrays:
- `_pf_open[maxOpenNodes*4]` — UINT8 open list (4 bytes/node: x, y, g, f)
- `_pf_open_count` — current open list size
- `_pf_closed[mapWidth*mapHeight/8+1]` — bit-packed closed set
- `_pf_path_x[maxPathLength]`, `_pf_path_y[maxPathLength]` — result path
- `_pf_path_length` — result path length
- `_pf_collision_fn` — simplified stub (UINT8=0); full fn-pointer wiring deferred

**`ScriptOpVisitor.visitPathfindStep`** — real implementation:
```kotlin
CBlock(listOf(
    CCall("pf_find_path", [npc_x/PF_GRID_SIZE, npc_y/PF_GRID_SIZE, target_x/PF_GRID_SIZE, target_y/PF_GRID_SIZE]),
    CCall("pf_step_toward", [_npcId_x, _npcId_y]),
))
```

**`ScriptOpVisitor.visitWaypointStep`** — real implementation:
```kotlin
CBlock(listOf(
    CCall("pf_step_toward", [_npcId_wp_x[idx], _npcId_wp_y[idx]]),
    CIf(arrival_check, [advance idx with CTernary wrap]),
))
```

**`GBDKPipelineV2`** wiring:
- `buildSystemGlobalVars`: handles `PathfindingSystem` → calls `GBDKSystemVisitor.buildPathfindingGlobals(system)`
- `pathfindingDefines`: emits `#define PF_GRID_SIZE <n>` from `PathfindingSystem.gridSize`
- `PathfindingSystem` import added

**PathfindingCodegenTest.kt** — 6 tests:
1. `pathfinding system generates A* infrastructure arrays` — validates _pf_open[128], _pf_closed[129], _pf_path_x[32]
2. `pathfinding generates iterative while loop not recursion` — verifies CWhile present, no recursive CCall
3. `pathfinding closed set uses bit-packing with shift and mask` — verifies >> and & in pf_is_closed, |= in pf_set_closed
4. `pathfindStep generates pf_find_path and pf_step_toward calls` — verifies call sequence and PF_GRID_SIZE usage
5. `waypointStep generates waypoint movement and index advancement` — verifies pf_step_toward, _guard_wp_idx, _guard_wp_count
6. `pathfinding with small open list generates correct array sizes` — maxOpenNodes=16 → _pf_open[64], _pf_closed[33]

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing] KDoc comment misplacement in GBDKSystemVisitor**
- **Found during:** Task 2 review
- **Issue:** KDoc comment for `buildPathfindingGlobals` was placed outside the companion object (between the class body and the companion object opening brace), so it would not attach to the function.
- **Fix:** Moved the KDoc inside the companion object, directly above `buildPathfindingGlobals`. Added section comment for the companion object block.
- **Files modified:** GBDKSystemVisitor.kt
- **Commit:** 75f9d36

**2. [Rule 2 - Missing] ScriptOpVisitor missing CRawExpr import**
- **Found during:** Task 2
- **Issue:** WaypointStep implementation uses `CRawExpr` for abs() expressions but the import was missing from ScriptOpVisitor.kt.
- **Fix:** Added `import io.github.gbkt.backend.gbdk.codegen.ast.CRawExpr` to the import block.
- **Files modified:** ScriptOpVisitor.kt
- **Commit:** 75f9d36

**3. [Rule 1 - Simplification] _pf_collision_fn stored as UINT8=0 (not full fn pointer)**
- **Found during:** Task 2
- **Issue:** The plan specified `UINT8 (*_pf_collision_fn)(UINT8 x, UINT8 y) = 0;` as a typed function pointer, but the typed C AST (`CVarDecl`) doesn't have a function pointer type node. Emitting it as a typed CVarDecl is not possible without a new `CFunctionPointerType` AST node.
- **Fix:** Stored as `CVarDecl("_pf_collision_fn", CU8, CLiteral(0))` — a simplified stub. The pf_find_path body uses `CRawCode("if (_pf_collision_fn && _pf_collision_fn(nx, ny)) continue;")` which will compile when the variable is promoted to a real fn pointer in a future phase.
- **Impact:** The A* walkability check is present as raw C in the CWhile body but won't function at runtime until the fn pointer type is properly generated.
- **Files modified:** GBDKSystemVisitor.kt
- **Commit:** 57c6d93
