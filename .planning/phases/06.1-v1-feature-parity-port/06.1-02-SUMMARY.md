## Decisions Made

- GameBuilderContext uses a separate `transientHolder: ThreadLocal<MutableSet<String>>` rather than adding a field to the GameBuilder itself — keeps transient tracking orthogonal to builder state, mirrors the holder pattern
- SaveDataBuilder uses `fun slots(n)` / `fun checksum()` / `fun version(n)` methods instead of `var` properties — consistent with CameraBuilder/ExplorationBuilder V2 DSL style
- `CRawExpr` for volatile pointer cast — acceptable per plan spec ("CRawExpr is acceptable for type casts/GBDK-specific expressions per existing pattern")
- Sentinel value 0xAB (= 171 decimal); CLiteral(0xAB) emits `171u` — tests check for `"171"` OR `"0xAB"` for robustness across emitter conventions
