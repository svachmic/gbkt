# Phase 06.1 Plan 03: Movement and Animation Codegen Summary

**One-liner:** Per-actor movement (GRID/SMOOTH) and animation state machine codegen with CSwitch dispatch, condition-based auto-transitions, and typed C AST replacing CRawCode in visitAnimateOp.

## What Was Built

### Task 1: IR Types and DSL Extensions (commit 7b509e9)

**New IR types in `CoreTypes.kt`:**
- `MovementStyle` enum: `GRID`, `SMOOTH`, `PHYSICS`
- `MovementConfig(style, speed, tileSize)` — per-actor movement configuration
- `AnimationStateDef(name, startFrame, endFrame, speed, loop, transitions)` — animation state definition
- `AnimTransition(fromState, toState, condition: Expr?)` — condition-based auto-transition

**`ActorIR.kt` — three new optional fields (backward-compatible defaults):**
```kotlin
val movementConfig: MovementConfig? = null
val animationStates: List<AnimationStateDef> = emptyList()
val frameSpeed: Int? = null
```

**New `SetAnimationState` ScriptOp** with `visitSetAnimationState` dispatch method in `ScriptOpVisitorI`.

**`ActorBuilder.kt` DSL extensions:**
```kotlin
actor {
    movement { style(MovementStyle.SMOOTH); speed(2) }
    animationStates {
        state("idle") { frames(0..3); speed(8) }
        state("walk") { frames(4..7); speed(4) }
        transition("idle" to "walk") { dpad.any }
    }
    frameSpeed(8)  // simple animation, no state machine
}
```

**`ScriptBuilder.kt`:** `setAnimationState(actor, "walk")` emits `SetAnimationState` op.

### Task 2: Codegen Implementation (commit d4625d1)

**`ActorVisitor.kt` — new codegen methods:**
- `generateMovementFunction(actor)` — produces `update_movement_{id}()` for GRID (bounded dpad) and SMOOTH (pixel-level) modes
- `generateAnimationFunction(actor, exprVisitor)` — delegates to `generateSimpleAnimationFunction()` (frameSpeed path) or `generateStateMachineFunction()` (animationStates path)
- `generateAnimationVars(actor)` — state/frame/counter global vars for state machine actors
- `generateSimpleAnimationVars(actor)` — frame/counter vars for simple animation actors
- `generateAnimationDefines(actor)` — `#define ANIM_{ACTORID}_{STATENAME} N` constants

**GRID movement pattern (typed C AST, no CRawCode):**
```c
void update_movement_player(void) {
    if (dpad_held(J_UP) && _player_y > 0) { _player_y -= 8; }
    if (dpad_held(J_DOWN) && _player_y < 136) { _player_y += 8; }
    if (dpad_held(J_LEFT) && _player_x > 0) { _player_x -= 8; }
    if (dpad_held(J_RIGHT) && _player_x < 152) { _player_x += 8; }
}
```

**Animation state machine pattern:**
```c
#define ANIM_PLAYER_IDLE 0
#define ANIM_PLAYER_WALK 1

UINT8 _player_anim_state = 0;
UINT8 _player_anim_frame = 0;
UINT8 _player_anim_counter = 0;

void update_animation_player(void) {
    switch (_player_anim_state) {
        case ANIM_PLAYER_IDLE:
            _player_anim_counter++;
            if (_player_anim_counter >= 8) {
                _player_anim_counter = 0;
                _player_anim_frame++;
                if (_player_anim_frame > 3) { _player_anim_frame = 0; }
            }
            if (joypad() & (J_LEFT | J_RIGHT | J_UP | J_DOWN)) {
                _player_anim_state = ANIM_PLAYER_WALK;
                _player_anim_frame = 0;
                _player_anim_counter = 0;
            }
            break;
        // ...
    }
}
```

**`ScriptOpVisitor.kt` changes:**
- `visitAnimateOp` refactored from `CRawCode` to typed C AST (CUnaryExpr, CIf, CBinaryExpr, CLiteral)
- `visitSetAnimationState` implemented: state assignment + frame/counter reset as CBlock with 3 statements

**`GBDKPipelineV2.kt` wiring:**
- `animationVars` + `animationDefines` injected into `main.c` home file
- `movementFunctions` + `animationFunctions` added to main.c function list
- `addMovementAndAnimationCalls()` prepends `update_movement_{id}()` and `update_animation_{id}()` calls to each scene's frame function — ensuring movement/animation runs before user script logic each frame

**Test file: `MovementAnimationCodegenTest.kt` — 12 tests:**
1. Grid movement generates dpad_held checks with boundary conditions
2. Smooth movement generates simple dpad_held checks without bounds
3. Simple animation generates typed frame counter with CUnaryExpr and CIf
4. State machine generates ANIM_* #define constants (3 states = 3 defines)
5. State machine generates CSwitch with one case per state
6. visitSetAnimationState generates state/frame/counter reset block
7. Transition condition generates CIf inside switch case body
8. Actor without movementConfig generates no movement function
9. PHYSICS style generates no movement function (deferred)
10. generateAnimationVars returns 3 vars for state machine actor
11. generateSimpleAnimationVars returns 2 vars for frameSpeed actor
12. Plain actor produces no animation vars from either helper

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Cross-module smart cast compilation error in GBDKPipelineV2**
- **Found during:** Task 2 implementation
- **Issue:** `actor.movementConfig != null && actor.movementConfig.style != MovementStyle.PHYSICS` caused "Smart cast to 'MovementConfig' is impossible" — Kotlin cannot smart-cast public API properties from different modules (gbkt-ir is a separate module from gbkt-backend-gbdk)
- **Fix:** Captured in local variable: `val mc = actor.movementConfig; if (mc != null && mc.style != ...)`
- **Files modified:** `GBDKPipelineV2.kt`
- **Commit:** d4625d1 (combined with other Task 2 changes)

**2. [Rule 1 - Bug] BinaryExpr constructor argument order in test**
- **Found during:** Task 2 test compilation
- **Issue:** Test used `BinaryExpr(VarRef(...), Literal(1), BinaryOp.GTE)` but constructor is `(left, op, right)` — Literal and BinaryOp were swapped
- **Fix:** Corrected to `BinaryExpr(VarRef(...), BinaryOp.GTE, Literal(1))`
- **Files modified:** `MovementAnimationCodegenTest.kt`
- **Commit:** d4625d1

**3. [Rule 1 - Bug] Boundary constant in test assertion**
- **Found during:** Task 2 test execution (1 failing test)
- **Issue:** Test asserted emitted code contains "144" but `generateMovementFunction()` computes `CLiteral(144 - speed)` = `CLiteral(136)` at compile time (speed=8)
- **Fix:** Updated assertion to check for "136" (144 - 8) and "152" (160 - 8)
- **Files modified:** `MovementAnimationCodegenTest.kt`
- **Commit:** d4625d1

### Scope Boundary Notes

The plan mentioned also replacing CRawCode in `hide_sprites_range` / `show_sprites_range` with typed CFor + CCall. This was not done — those functions use GBDK-specific UINT8 loop variable declarations that require C89 compatibility (`UINT8 i; for (...)`), which cannot be expressed as a typed CFor without introducing a new C AST node type. This is a pre-existing pattern and out of scope for this plan. Logged as deferred.
