# Phase 06.10: V1 Feature Parity Port — Example Games - Context

**Gathered:** 2026-02-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Update all 3 existing example games (Pong, Breakout, Explorer) to final V2 DSL syntax and add 5 new genre example games (Platformer, RPG-lite, Dungeon Crawler, Shoot-em-up, Top-down Racer). Each example must be a self-contained, working mini-game that showcases specific gbkt V2 features. All deferred gaps from Phases 06.6-06.9 are now closed, so examples can exercise the full framework.

Scope expanded from original roadmap (which specified 1 new platformer) to include genre showcase examples.

</domain>

<decisions>
## Implementation Decisions

### Example Update Scope (Pong, Breakout, Explorer)
- Functionally equivalent to GBDK-2020 sample projects — same game mechanics, not pixel-perfect
- Match GBDK sample gameplay using gbkt V2 DSL idioms (not transliterated C logic)
- Explorer reference is the existing gbkt V1 Explorer; port to V2 with RPG/world/exploration features
- Clean removal of all deprecated V1 APIs — no migration comments
- Comprehensive SimulationContext tests for each example covering key game mechanics
- Working ROMs if GBDK is available; CI tests don't require GBDK toolchain

### New Platformer
- Purpose: Physics showcase — demonstrate gravity, jumping, tile collision
- Complexity: Minimal — player + platforms + gravity + jump only (no enemies, no collectibles)
- Must use entity/movement system (MovementController, GravityComponent) from Phase 06.7
- Both DMG and GBC variants (two build targets or two separate example modules)

### New Genre Examples (RPG-lite, Dungeon Crawler, Shoot-em-up, Top-down Racer)
- Each is a 2-3 scene mini-game (~150-250 lines DSL) that feels like a real (tiny) game
- Genre-appropriate scene flow per game (not forced title/gameplay/game-over template)
- RPG-lite: Town + dungeon + battle — showcases character, monster, ability, battle, inventory, floor DSL
- Dungeon Crawler: Grid-based exploration — showcases torch gauge, encounters, keys/doors, exploration package
- Shoot-em-up: Vertical scrolling, enemy waves, projectiles — showcases entity system + collision in action context
- Top-down Racer: Overhead view, car on scrolling track — showcases smooth movement, camera follow, tilemap scrolling
- Mix of DMG and GBC targets across genre examples

### V2 Feature Distribution (Tiered by Complexity)
- Pong: Basics (delegate vars, typed input API, scenes)
- Breakout: Arrays, collision detection, compound operators
- Platformer: Physics, entity/movement system, GravityComponent
- RPG-lite: Full RPG package (character, monster, ability, battle, inventory, floor)
- Dungeon Crawler: Exploration package (gauges, keys, grid movement, encounters)
- Shoot-em-up: Entity system, collision, action-oriented movement
- Top-down Racer: Camera follow, tilemap scrolling, smooth movement
- Explorer: Full showcase (RPG + world + exploration + save/load — the advanced reference)

### Audio
- All examples get at least basic sound effects — audio is fundamental to games
- Uses audio system from Phase 06.6

### Localization
- Explorer and RPG-lite demonstrate .po file localization
- Other examples skip localization (not enough text to justify it)

### Save System
- Explorer only — other examples are too simple for save/load

### Assets and Art
- Each example self-contained with its own sprite/tile assets (no shared asset sets)
- Art quality matches GBDK-2020 sample quality level (clean programmer art, not placeholder but not polished)

### Project Structure
- All examples follow `gbkt-examples/{game-name}/` convention (existing pattern)
- Consistent `build.gradle.kts` template across all examples — only game-specific config differs (name, GBC flag)

### Documentation
- Explicit learning progression: Pong(beginner) -> Breakout -> Platformer -> genre games -> Explorer(advanced)
- Per-example README.md (user guide): what the game is, how to play, V2 features showcased
- Per-example CLAUDE.md (dev guide): build commands, code structure, DSL patterns used, how to modify
- Top-level gbkt-examples/README.md: index of all examples with ASCII art mockups, guide table ("Want to build X? Start with Y")
- Top-level gbkt-examples/CLAUDE.md: development guide for working with examples
- Inline comments: key concepts only (~10-15 per example), not tutorial-style
- Each README includes "Features Demonstrated" section listing V2 features used

### Claude's Discretion
- Exact DMG vs GBC assignment per genre example
- Scene flow details for each genre example
- Specific sound effects and when they play
- Exact tile/sprite sizes and layouts
- How to structure the platformer DMG/GBC variants (two modules vs build flag)
- ASCII art style for the top-level README

</decisions>
