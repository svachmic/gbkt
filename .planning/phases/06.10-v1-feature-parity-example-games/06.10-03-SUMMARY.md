# Phase 06.10 Plan 03: RPG-lite Game Definition Summary

**One-liner:** 258-line mini-RPG using character/monster/simpleBattle DSL with en.po localization covering 25 strings across 5 namespaces.

## Summary

Created the RPG Lite example game (`RpgLite.kt`) showcasing the `gbkt-genre-rpg` package alongside the v2 core DSL. Added `en.po` localization for all game strings grouped by context namespace.

## Changes

### RpgLite.kt (258 lines)

- `MBC5_RAM_BATTERY` cartridge, 4 ROM banks, 1 RAM bank
- **4 variables:** `hp` (u8, 30), `gold` (u8, 0), `dungeonLevel` (u8, 1), `stepCount` (u8, 0)
- **4 sound effects:** `hitSfx` (HIT), `coinSfx` (COIN), `winSfx` (WIN), `loseSfx` (EXPLODE)
- **1 actor:** `heroActor` — position(80, 72), sprite `sprites/hero.png`, size(8, 16)
- **2 characters:** `hero` (HP 30, ATK 8, DEF 5, AGL 10)
- **2 monsters:** `slime` (HP 12, ATK 4, DEF 2, AGL 8, EXP 5), `bat` (HP 8, ATK 6, DEF 1, AGL 15, EXP 3)
- **1 battle system:** `simpleBattle("combat")` with party(hero), two encounter groups, onVictory/onDefeat
- **4 scenes:** title, town, dungeon, gameover
  - title: reset state, navigate to town on START
  - town: heal with gold, enter dungeon with A
  - dungeon: 4-directional movement, step-based random encounters (every 60 steps), battleUpdate("combat"), exit deeper logic
  - gameover: show HP/gold stats, navigate to title via titleRef
- Forward-declared `titleRef` and `gameoverRef` for circular navigation

### en.po (25 msgid entries)

Namespaces: `ui` (9 strings), `hud` (2 strings), `combat` (5 strings), `gameplay` (4 strings), `character` (3 names)

## Deviations from Plan

### Auto-fixed Issues

None - plan executed exactly as specified, with one minor adaptation:

**Navigate string in simpleBattle onVictory:** The `onVictory {}` block in `simpleBattle` uses `navigate("dungeon")` (string) rather than a SceneRef because the combat system callback executes in the context of a `ScriptBuilder`, not the `GameBuilder` scene scope. This is the same pattern used in `ExplorerV2.kt` (`navigate("gameplay")` in the onVictory block). The `gameoverRef` forward-declaration IS used for `onDefeat` where the gameover scene is defined after the battle system.
