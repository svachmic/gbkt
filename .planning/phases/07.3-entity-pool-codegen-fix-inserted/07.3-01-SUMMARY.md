## Accomplishments

- Fixed Bug 1: `buildActorPoolStateVars()` now generates `_pool_x[N]`, `_pool_y[N]`, `_pool_oam[N]` alongside `_pool_active[N]`. The `oam_base` scalar is completely removed.
- Fixed Bug 2: `pool_spawn()` allocates OAM slots dynamically via `spawn_actor()` and stores per-instance state; `pool_destroy()` returns slots via `destroy_actor()` and clears `oam[i]=0xFF`.
- Fixed Bug 3: `pool_init()` zeroes active bitmap AND sets all oam entries to 0xFF sentinel; `main()` calls `pool_<id>_init()` before the start-scene enter call.
- Fixed Bug 5: Pool template actors are excluded from `update_sprites()` (no `move_sprite` calls for template actors) and excluded from static OAM init (`set_sprite_tile`/`move_sprite` not emitted). VRAM tile data (`set_sprite_data`) is still loaded for template actors so pool instances can reference the tiles.

## Decisions Made

- `pool_destroy(i)` takes pool index (not OAM slot) - internally reads `_pool_oam[i]` to call `destroy_actor()`. This keeps the API surface at pool-level abstraction.
- `spawn_actor(0)` is called with dummy argument 0 — the actor_id parameter is unused in the current `spawn_actor` implementation (it just pops from the free stack).
- Template actors are still counted in VRAM tile allocation (`buildSpriteDataLoadStatements` unchanged) but skipped in static OAM slot assignment.
