    **Pool-template collision detection in ScriptOpVisitor:**
    The fix needs to happen at the `Conditional` (whenever) level, not just the `Collision` expression level, because the whole conditional needs to be wrapped in loops.

    In `ScriptOpVisitor.visitConditional()` (or wherever `whenever` is compiled), before generating the standard `if (condition) { body }`:
    1. Check if the condition contains a `Collision` expression where one or both operands are pool template actors.
    2. Need access to the set of pool template actor IDs (from `gameIR.actorPools.map { it.actorTemplateId }.toSet()`) — use the GameIR ThreadLocal set up in Task 1.
    3. Determine the case:

    **Case A: Both actors are pool templates (e.g., bullet.collides(enemy)):**
    Generate nested loops:
    ```c
    {
        UINT8 _pool_bi;
        for (_pool_bi = 0u; _pool_bi < bulletPool_maxSize; _pool_bi++) {
            if (_pool_bulletPool_active[_pool_bi]) {
                UINT8 _pool_ei;
                for (_pool_ei = 0u; _pool_ei < enemyPool_maxSize; _pool_ei++) {
                    if (_pool_enemyPool_active[_pool_ei]) {
                        if (/* AABB using _pool_bulletPool_x[_pool_bi] vs _pool_enemyPool_x[_pool_ei] */) {
                            // body ops (with both pool contexts active for destroy resolution)
                        }
                    }
                }
            }
        }
    }
    ```

    For AABB calculation, use per-instance arrays. The hitbox dimensions come from the template actor's sprite hitbox (same as currently used for scalar AABB).

    For body ops, both pools need context. The outer loop's pool context is for actorA, the inner loop's pool context is for actorB. Body ops like `destroy(bulletPool, ...)` need to resolve to the outer loop's slot var, and `destroy(enemyPool, ...)` to the inner loop's slot var.

    Implementation approach: Generate unique slot variable names per pool to avoid collisions. E.g., `_pool_bi` for bulletPool and `_pool_ei` for enemyPool. The slot var names can be derived from the poolId: `_pool_${poolId.take(2)}i` or similar.

    For body compilation, set a dual pool context (or compile body ops with knowledge of both active pools). The body ops from the shmup are:
    ```kotlin
    whenever(bullet.collides(enemy)) {
        score += 10           // normal var, no pool context needed
        playSound(explodeSfx) // no pool context needed
    }
    ```
    These body ops don't reference pool template actor properties directly, so they don't need pool context redirection. But `destroy()` calls within the body would need the correct slot var. Since the shmup collision body doesn't call destroy on either pool entity (it just scores), the body compilation can use no pool context for now. If future games need to destroy both colliding entities inside the collision body, the pool collision context would need to provide both slot vars. For now, implement the common case.

    **Case B: One actor is a pool template, the other is not (e.g., enemy.collides(player)):**
    Generate a single forEachActive loop for the pool template actor:
    ```c
    {
        UINT8 _pool_ei;
        for (_pool_ei = 0u; _pool_ei < enemyPool_maxSize; _pool_ei++) {
            if (_pool_enemyPool_active[_pool_ei]) {
                if (/* AABB using _pool_enemyPool_x[_pool_ei] vs _player_x */) {
                    // body ops (with single pool context for the pool actor)
                }
            }
        }
    }
    ```

    **Case C: Neither actor is a pool template:**
    Keep current behavior — single AABB check. No change.

    **Resolving pool from template actor ID:**
    Given an actor ID (e.g., "bullet"), look up which pool uses it as `actorTemplateId`:
    ```kotlin
    val pool = gameIR.actorPools.find { it.actorTemplateId == actorId }
    ```
    This gives the poolId and maxSize needed for loop generation.

    **AABB dimensions:**
    The hitbox comes from the `Collision` expression's hitboxA/hitboxB fields (or from the template actor's sprite hitbox). Use the same hitbox dimensions as the current scalar AABB check, but substitute per-instance array accesses for position variables.
