## Accomplishments

- Fixed Bug 4: `forEachActive` body ops on template actor properties now redirect to per-instance arrays. `bullet.y -= 4` inside a pool body emits `_pool_bulletPool_y[_bi] -= 4u` instead of `_bullet_y -= 4u`. Redirection covers both `Assign` target names and `PropertyAccessExpr` in `ExprVisitor`.
- Fixed Bug 6: `visitPoolForEachActive` emits `move_sprite(_pool_<id>_oam[slot], _pool_<id>_x[slot] + 8u, _pool_<id>_y[slot] + 16u)` after body ops inside the active-guard `if`. Multi-tile support generates one `move_sprite` per OAM tile entry with proper column/row pixel offsets.
- Fixed Bug 7: `visitIfOp` detects `collides()` expressions where one or both actors are pool templates, synthesizing nested `forEachActive` loops with per-instance AABB checks instead of the single scalar AABB check. Three cases handled:
  - **Case A** (both pool templates): two nested for-loops, both AABB sides use `_pool_<id>_x[slot]`
  - **Case B** (one pool template): one for-loop, pool side uses array, non-pool side uses scalar `_<id>_x`
  - **Case C** (neither is pool template): unchanged existing single AABB check (no regression)
- Pool context is thread-safe via `ThreadLocal<PoolCodegenContext?>` with `try/finally` cleanup — ensured pool context never leaks between body compilation calls.
- Added `setGameIR(GameIR)` to `ScriptOpVisitor` for pipeline-level GameIR injection, enabling pool/actor metadata lookup without requiring GameIR to be passed to every `visit()` call.

## Decisions Made

- `ExprVisitor.visitPropertyAccessExpr` reads `ScriptOpVisitor.activePoolContext` directly since both classes are in the same package and `activePoolContext` is `internal`. This avoids adding a constructor parameter to `ExprVisitor` and keeps the existing `SceneVisitor.visit()` call site unchanged.
- Slot variable names for nested collision loops use `_pool_<poolId.take(1)>i` to generate distinct names (`_pool_bi`, `_pool_ei`) without requiring the developer to specify them.
- `buildDisplaySyncStatements` uses GBDK hardware offsets: x+8 and y+16 for the first tile, with additional +8 per column/row for multi-tile sprites (standard GBDK viewport adjustment).
