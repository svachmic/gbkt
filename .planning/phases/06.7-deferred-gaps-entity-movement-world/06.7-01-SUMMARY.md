**Actor pool IR with OAM slot lifecycle (init/spawn/destroy), DSL delegate pattern, GBDK codegen, and interpreter stubs for bullet/particle/brick entity pools**

## Accomplishments

- Complete actor pool IR: `ActorPoolIR`, `ActorPoolConfig`, `PoolOverflowStrategy` types with `GameIR.actorPools` field
- Two new ScriptOps `PoolSpawnActor`/`PoolDestroyActor` with full visitor dispatch across all implementing classes
- DSL delegate `val bullets by pool(bullet, max = 8)` pattern with `spawn(pool, x, y)` and `destroy(pool, slot)` ScriptBuilder extensions
- GBDK codegen generating `pool_<id>_init()`, `pool_<id>_spawn(x,y)`, `pool_<id>_destroy(slot)` C functions per pool
- Both overflow strategies: SILENT_NOOP returns 0xFF sentinel, RECYCLE_OLDEST uses round-robin recycling with static oldest counter
- ScriptOpInterpreter pool state tracking for JVM simulation testing

## Decisions Made

- Pool codegen functions placed in `GBDKSystemVisitor.companion object` (static builders) because pools are `GameIR`-level declarations, not `SystemIR`-level — no visitor override needed
- `CRawExpr("0xFF")` used for invalid-slot sentinel instead of `CLiteral(0xFF)` — `CLiteral` emits `255u` which breaks idiomatic GBDK code and test assertions
- RECYCLE_OLDEST uses a `static UINT8 _pool_<id>_oldest` counter with modulo wrap — minimal ROM footprint
- IR tests in `gbkt-ir`, codegen tests in `gbkt-backend-gbdk` (matching module boundaries)
