  <action>
    **Step 1: Read game source files** to understand mechanics:
    - Read PongV2.kt for: paddle movement, ball physics, scoring, scene transitions, game over conditions
    - Read BreakoutV2.kt for: brick layout, ball bounce, paddle control, scoring, scene transitions

    **Step 2: Create UAT checklists** for each game. Format:

    ```markdown
    # UAT: Pong
    | # | Scenario | Expected | Coffee-GB | mGBA | Attempt | Notes |
    |---|----------|----------|-----------|------|---------|-------|
    | 1 | Title screen displays | "PONG" text, "Press START" prompt | | | | |
    | 2 | Start button begins game | Scene transitions to gameplay | | | | |
    ...
    ```

    **Pong scenarios must include:**
    - Title screen display and START button
    - Left paddle moves with D-pad (up/down)
    - Right paddle (AI) tracks ball
    - Ball bounces off top/bottom walls
    - Ball bounces off paddles
    - Score increments when ball passes a paddle
    - Score display updates correctly
    - Game over / win conditions trigger
    - Restart from game over
    - Edge case: ball at screen corners
    - Edge case: paddle at screen edges (can't go off-screen)

    **Breakout scenarios must include:**
    - Title screen and START
    - Paddle moves left/right with D-pad
    - Ball launches from paddle
    - Ball bounces off walls (top, left, right)
    - Ball bounces off paddle
    - Bricks break on ball contact
    - Score increments per brick
    - All bricks cleared triggers win/level complete
    - Ball falls below paddle triggers life loss
    - Lives display updates
    - Game over at zero lives
    - Edge case: ball at corners
    - Edge case: paddle at screen edges

    **Step 3: Create headless smoke tests** for each game:
    - Build ROM first via `./gradlew :{game}:buildRom`
    - Use AgentDebugSession to: start ROM, run 600 frames, capture screenshot, check no ERROR log entries
    - For Pong: run 300 frames, read "score" variable, verify it's defined (>= 0)
    - For Breakout: run 300 frames, read "score" variable, verify it's defined
    - These tests go in the example game's test directory
    - Use JUnit Jupiter (@Test annotation) with kotlin.test assertions
    - Tests should be skipped if ROM doesn't exist (conditional on buildRom having run)

    **Step 4: Run headless tests** — `./gradlew :pong:test :breakout:test`
    Fix any issues found in headless tests inline (framework fixes, not game-specific workarounds).
