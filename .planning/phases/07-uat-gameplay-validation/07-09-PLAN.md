<task type="auto">
  <name>Task 1: Create comprehensive UAT_GUIDE.md</name>
  <files>context/UAT_GUIDE.md</files>
  <action>
    Create `context/UAT_GUIDE.md` with the following sections. Pull real examples from the SUMMARY files of Plans 05-08 (actual bugs found and fixed during UAT).

    **Required sections (from CONTEXT.md decisions):**

    1. **Overview** — What UAT is, why it matters, the dual-emulator (Coffee-GB + mGBA) validation approach

    2. **Writing UAT Checklists** — Format standard for future games:
       - Table format with columns: #, Scenario, Expected, Coffee-GB, mGBA, Attempt, Notes
       - How to write good scenarios (specific, observable, testable)
       - Happy path vs edge cases
       - Expected "feel" descriptions
       - Iteration tracking (attempt 1: fail, attempt 2: pass after fix)

    3. **Running Games** — How to build and run in both emulators:
       - `./gradlew :{game}:buildRom` then open in mGBA
       - `./gradlew :{game}:runEmulator` for embedded Coffee-GB
       - `./gradlew :{game}:debugEmulator` for full debug tooling

    4. **Agent Debugging Toolkit** — How to use each tool:
       - `./gradlew captureScreenshot` — options, output format
       - `./gradlew runScript` — script file format, examples
       - `./gradlew readVariable` — variable naming, .sym resolution
       - `./gradlew saveState` / `loadState` — checkpoint/restore workflow
       - `./gradlew diffScreenshots` — visual regression testing
       - AgentDebugSession programmatic API for custom test scripts

    5. **Debug Logs** — How to use EMU_printf with source map correlation:
       - EMU_printf trap mechanism (ld d,d detection)
       - DebugLogEntry structure (level, timestamp, kotlin source)
       - Source map resolution: C line -> Kotlin DSL file:line
       - Filtering by log level (GAME, EMU, WARN, ERROR)

    6. **Source Maps** — How to trace issues to DSL code:
       - .gbkt.map file format
       - .sym file for variable address resolution
       - .noi file for function symbols
       - Workflow: mGBA error -> C line -> source map -> Kotlin DSL source

    7. **Troubleshooting** — Symptom -> Cause -> Fix tables:
       - Bank overflow errors
       - Sprite glitches (OAM corruption, wrong position)
       - Sound issues
       - Text rendering corruption (window layer vs background)
       - Collision not registering
       - Scene transition freezes
       - Variable not updating
       - Save/load corruption

    8. **Real Debugging Walkthroughs** — 2-3 actual bugs from this phase:
       - Pull from SUMMARY files: what the symptom was, how it was diagnosed, what the fix was
       - Include actual log output, source map traces, and code changes
       - Show the full workflow: observe symptom -> read debug log -> correlate via source map -> identify root cause -> fix -> verify

    9. **Bug Handling Protocol** — The process for fixing UAT bugs:
       - Fix inline immediately, no log-and-defer
       - Generic framework fixes only
       - One atomic commit per bug
       - Always add regression test
       - Retest affected games
       - `./gradlew build` as gate

    10. **Per-Game UAT Checklist Index** — Links to all UAT-{game}.md files

    Target: 200+ lines, comprehensive but practical. Written for both humans and Claude agents.
