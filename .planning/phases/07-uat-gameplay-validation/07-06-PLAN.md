  <action>
    **Step 1: Read game source files** to understand each game's mechanics.

    **Step 2: Create UAT checklists** using the same format as Plan 05.

    **Platformer scenarios must include:**
    - Title screen and START
    - Player moves left/right with D-pad
    - Gravity pulls player down when not on platform
    - Jump (A or UP) lifts player
    - Landing on platforms stops fall
    - Falling off screen triggers death/respawn
    - Platform collision is accurate (no clipping through)
    - Scene transitions work
    - Edge case: jumping at screen ceiling
    - Edge case: walking to screen edges

    **Shmup scenarios must include:**
    - Title screen and START
    - Player ship moves with D-pad (all 4 directions)
    - A button fires bullets
    - Bullets move upward and despawn off-screen
    - Enemies spawn at top and move downward
    - Bullet-enemy collision destroys enemy
    - Enemy-player collision damages player
    - Score increments on enemy kill
    - Entity pool handles spawning/despawning (no sprite corruption)
    - Edge case: rapid fire (many bullets)
    - Edge case: many enemies on screen

    **Racer scenarios must include:**
    - Title screen and START
    - Vehicle moves left/right with D-pad
    - Track scrolls vertically
    - Obstacles appear and scroll toward player
    - Collision with obstacles registers
    - Score/distance increments
    - Speed increases over time (if applicable)
    - Edge case: vehicle at screen edges

    **Step 3: Create headless smoke tests** for each game:
    - Build ROMs, run 600 frames via AgentDebugSession, check no ERROR logs
    - Capture screenshot at frame 300 for visual baseline

    **Step 4: Run tests and fix issues inline.**

    **Bug handling per CONTEXT.md policy:**
    - Fix inline immediately, generic framework fixes only
    - One atomic commit per bug with regression test
    - `./gradlew build` must pass after each fix
    - Retest all previously-validated games (Pong, Breakout) after framework fixes
  </action>
