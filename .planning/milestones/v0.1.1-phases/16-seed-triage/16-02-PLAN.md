<objective>
Run the one-time shared substrate pass (D-13): a single serial Gradle invocation that cleans and builds all 7 example ROMs, then runs the full JVM suite and the plugin-validation tests, pins the HEAD SHA (D-14), and rebuilds the MCP shadow JAR that the substrate clean wipes. Purpose: One authoritative, SHA-attributable build/test substrate eliminates parallel-Gradle daemon collisions (the project's hardest landmine) and guarantees every per-seed disposition is grounded in the same commit's artifacts.
Output: substrate-sha.txt, substrate-buildrom-report.txt, substrate-test-report.txt, plugin-validate-report.txt, rebuilt MCP shadow JAR, and the build/gbkt artifacts under each example.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build toolchain → evidence substrate | All downstream dispositions trust that these artifacts came from the pinned HEAD; a wrong-SHA or corrupted build invalidates every cluster verdict |
| Gradle daemon → parallel invocations | Concurrent `clean` invocations corrupt build artifacts (Kotlin daemon collision) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-03 | Tampering | substrate build artifacts | mitigate | Single serial `./gradlew` invocation (D-13); `./gradlew --stop` + retry on failure; never parallel clean |
| T-16-04 | Repudiation | evidence-to-commit attribution | mitigate | `git rev-parse HEAD` pinned to substrate-sha.txt (D-14) before the build; all evidence attributed to that SHA |
| T-16-05 | Denial of Service | MCP shadow JAR wiped by clean | mitigate | Rebuild `:gbkt-mcp-server:shadowJar` immediately post-substrate so the visual plan can connect |
| T-16-SC | Tampering | npm/pip/cargo installs | accept | No package installs; Gradle uses the pinned version catalog already in-tree |
</threat_model>
